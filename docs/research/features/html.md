### 2026-09-30: 2026-09-30-static-preview-decoration-cost-review

[Immutable record](../review-records/2026-09-30-static-preview-decoration-cost-review.json) — review; pursue; observation stale.

Pursue owner fixes and defer skipping unchanged blocks. The decoration cost came from sources reading everywhere and from a wrapper that trapped every property access, not from the live contract. Code highlighting now reads once per code block; the wrapper resolves its context once per view; document views find highlighting by block identity without indexing each document; previews render with useDeferredValue; and the registry previews render only when their document changes. On the final tree, React time per stream fell 48-55% at 10 KB and 73-74% at 50 KB against S5 snapshot w, and static source reads are 8-21% of React time. The browser still shows a pass over every top-level block, 1.7-3.8 ms per commit at 50 KB. Per-block caching and chunking are one decision, deferred until every source reads within its entry (the AI end marker reads the whole document) and static renders can see a version of observed state. The document views and block reuse reviewed on 2026-09-29 stand.

Question: Which schema and renderer contracts should HTML ingress and static output share, and which interactive dependencies can be removed?

- Per-block decoration caching behind a source declaration such as decorate.readsDocument. Defer: the per-block pass costs 1.7-3.8 ms per commit at 50 KB while every commit stays within the 32 ms cadence. A correct cache also needs sources that read only their entry and a version of observed state, and the AI end marker reads the whole document.
- Chunked rendering, as Slate does for large documents. Defer, as part of the same decision: skipping an unchanged chunk is correct only under the same two conditions, it would save about 2-4 ms per commit at 50 KB, and it does not reduce style, layout or paint, which now grow more with size.
- Memoize EditorStatic itself. Stop: re-rendering it is how a consumer refreshes decorations that read other state; consumers that re-render for unrelated state memoize the element on their document.
- Delete static decorations and bake code tokens into the document at parse time, as HTML-producing Markdown renderers do. Stop: highlighting is paint, not content; baking it in forks static output from the live editor and bloats stored documents.
- Keep per-text code highlighting with a text-level cache. Stop: the highlighter decorates a code block, and the live contract already re-reads an element whose text changed.
- Throttle publications instead of deferring the render. Stop: a fixed interval idles a fast machine and still saturates a slow one; useDeferredValue adapts to the render's actual cost.

### 2026-09-30: 2026-09-30-static-preview-proportional-cost-execution

[Immutable record](../review-records/2026-09-30-static-preview-proportional-cost-execution.json) — execution; completed; observation stale.

Streamed previews now cost work in proportion to the change. Code highlighting reads each code block once and reuses unchanged blocks by identity, without indexing each rendered document; the Plate decoration wrapper resolves its plugin context once per view; the static renderer reads a block's sources once and compares decorations by identity first; Plite's cloneValue returns primitives as they are.
