Question: Which focus and navigation guarantees must hold for voids, owned controls, inactive editors and read-only views?

- Keep/configure: existing local effects, view-derived focus and optional Tabbable policy fit distinct jobs.
- Change API: no observed recurring coordination requires a new public accessibility surface.
- Add primitive: a unified focus/announcement manager adds no independent capability.
- Delete/merge/inline: deleting Tabbable for native Tab loses editor/text traversal policy; inlining moves the same job rather than eliminating it.
- Move ownership: app wording and kit exclusions stay above Plite; exact-view focus and local effect delivery remain with their lifecycle owners.
- Replace architecture: one global accessibility store conflates independent documents and provider/view lifetimes; merging announcements with navigation does not remove necessary work.

Proof limits: No test, browser or assistive-technology session run. Assertions inspected do not prove speech output or full Tab/iframe/shadow-root behavior; Tabbable ambient document access is an explicit environment limit. No global announcement deduplication or changed runtime accepted.
