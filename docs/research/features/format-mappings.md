Question: Which schema-bound construction and property contracts should HTML, Markdown and plain-text feature mappings share without erasing their format semantics?

- Keep the selected CommonMark plus registered-tag parser and finish current repairs: retain. There is no new grammar requirement or contradictory recognizer evidence that pays for another broad GitHub search.
- Keep all mapping construction handwritten: loses for simple bound tags and scalar marks, where repeated schema identity, attributes and recursive child handling are owned by the compiler already. Keep callbacks for real format-specific transforms.
- Proposed explicit declaration such as defineFormats({ markdown: { tag: type, properties: ["width"] } }): pursue as a design candidate. Existing Markdown compiler can own node construction, declared attribute conversion and schema-directed child traversal; exact syntax and whether an explicit property selection or another bounded policy wins remain open.
- Derive mark/element call shapes from the schema binding and remove redundant role declarations; compare a shared format-neutral property-value contract privately. This may delete more author work than a helper returning the same verbose mapping, without introducing another plugin or namespace.
- Automatically convert every schema type/property to a tag and reuse those tags as HTML: reject. Schema identity/validation does not specify a useful HTML representation, raw attributes versus properties, metadata inclusion, URL aliases, captions, generated IDs or atom text. The existing ElementId metadata/copy law and media URL/caption consumers are concrete counterexamples.
- Route all Markdown tags and raw HTML through the HTML parser: do not adopt wholesale. It would couple a pure syntax path to DOM semantics and conflict with the retained registered-tag dialect; consider a targeted adapter only for a named raw-HTML user job.
- Merge HTML, Markdown, plain text, DOCX and static rendering into one codec or public AST/result: reject. Plain-text projection, semantic interchange, visual rendering and package artifacts have different directions, syntax and lifecycle. Reuse only proven private mechanics at Plate; Plite retains schema/model law.
- Prior art supports explicit reuse rather than schema-wide automatic exposure: ProseMirror parser state constructs nodes at close; Tiptap exposes opt-in Pandoc block/atom Markdown spec factories and Audio supplies allowedAttributes. These are analogues, not the same registered-tag grammar or proof that Plate is the best editor. Tiptap returns an empty string for an unknown renderer; ProseMirror throws by default. Preserve Plate structured refusals instead of copying either failure contract.
- Next owner: $task design plan format-mappings: simplify schema-bound HTML and Markdown authoring, remove repeated construction and traversal, and preserve explicit format semantics. Begin by proving representative tag/property cases and the strongest counterexamples before choosing a generic declaration.
