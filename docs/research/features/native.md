### 2026-09-12: 2026-09-12-native-input-authority

[Immutable record](../review-records/2026-09-12-native-input-authority.json) — review; stop; observation stale.

Keep shared DOMInputRuntime arbitration, private React/Android executors and canonical transaction convergence. Absorbing controller/router/kernel files removes forwarding but establishes no material ownership gain.

Question: Which owner should reconcile browser input, IME, DOM mutations and document changes without competing write paths?

- Keep/configure: automatic semantic eligibility and renderer capability already avoid app-authored input-safety flags.
- Change API: no recurring caller coordination establishes a missing public input contract.
- Add primitive: another input authority or generic reconciliation protocol duplicates current jobs.
- Delete/merge/inline: absorbing router/controller/kernel orchestration into DOMInputRuntime would mainly remove forwarding; no independent duplicate canonical authority was demonstrated.
- Move ownership: canonical commits remain in core, event ordering/composition grouping in mounted input lifecycle, and renderer safety with renderers.
- Replace architecture: uniform model-only editing still needs IME/Android reconciliation; uniform DOM-owned editing cannot replace command semantics or arbitrary renderer safety.

Proof limits: Read-only source and contract inspection; no tests, browser, device or scale experiment run. Synthetic desktop composition coverage is not mobile IME proof. Double insertion, pending-input loss, split undo and repair-during-composition remain regression risks for any future replacement.
