Pursue one private Plite document-shape validation owner across construction, schema assertion and replacement; retain the JSON tree and separate runtime, persisted and schema identities.

Question: What is the smallest schema-valid document and identity contract that all editors and codecs must preserve?

- Keep/configure the current model: retain the core tree and identity boundaries, but configuration cannot repair the false assertion contract.
- Change the existing owner: selected. Reuse one private Plite base-document validation path before entry-specific fitting or full schema assertion, preserving the public calls.
- Add a public validated Document wrapper or parser family: rejected; it adds caller conversion and concepts while the existing assertion and JSON contracts already express the job.
- Delete/merge: delete duplicate base-shape admission rules. Reject one universal persisted ID because text/element live keys, optional persistent element IDs and schema fingerprints have distinct lifetimes.
- Move validation into Plate or codecs: rejected; raw and other ingress paths remain unsound. Keep product root defaults and migrations in Plate/application owners.
- Replace the AST with classes or an ID-indexed public store: rejected for this question; no source-backed current benefit earns the additional representation and runtime machinery.

Proof limits: 46 existing tests passed in five source-first package files. A separate 16-row, four-operation-per-row public-API probe reproduced 12 malformed-container cases in raw and closed-schema editors: assertDocument accepts, construction rejects, direct and persisted replacement accept and discard the malformed field. Valid-document and invalid-node controls behave consistently. No fix, browser/device proof, full static typecheck, packed artifact validation, performance gain or exhaustive model audit is claimed. No new runtime store/index/traversal target is selected; traversal/representation changes would require the owning scale probe.
