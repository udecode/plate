Stop making reusable registry items depend on CLI-generated application types; keep descriptor inference and optional app-owned exact contracts.

Question: Should reusable registry items depend on CLI-generated plugin/editor types because they are consumer-side code?

- Keep/configure: selected. Reusable source imports the owning descriptor and obtains inferred feature APIs; application-owned exact generated contracts remain optional for complete graph/data boundaries.
- Maximum-value cut: remove the mandatory edge from reusable items to the complete generated EditorKit contract. Do not delete the generator, which has a separate exact Value/schema/mutation and stale-artifact checking job.
- Change existing API: if descriptor-local operation or node inference is inadequate, repair its owner. The inspected toolbar already has an adequate tx.plugin(KbdPlugin) path, so this review identifies no new API requirement.
- Generate per registry item or publish a shared mega-editor contract: rejected. Per-item outputs duplicate descriptor facts and add synchronization; a shared graph makes unrelated application composition part of a component dependency.
- Add editor-graph generic parameters or generated assertions to ordinary context consumers: rejected for this job. They add caller work and cannot establish the runtime provider target or installed plugins.
- Replace generation with automatic recursive inference of every complete document grammar: not selected. Exact static data remains a separate useful output, and no exactness/type-cost comparison justifies replacing it to solve a local feature-access job.
- Move all consumer typing into applications: rejected for reusable source. Applications own complete composition and optional specialization; Plate owns inferred reusable feature contracts, while npm-published declaration files remain ordinary dependencies.

Proof limits: Read-only source and existing fixture inspection. No product changes, test execution, generation replay, browser/native proof, typechecker benchmark or compiler-wide certification. A bounded current non-generated registry TS/TSX scan found no plugins.generated imports; the app integration type fixture does import that generated graph, which is a distinct static consumer. Older formal Plate API proofs and unrecorded transaction-correction claims are context, not replayed evidence.
