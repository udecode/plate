### 2026-09-24: 2026-09-24-exports-audit

[Immutable record](../review-records/2026-09-24-exports-audit.json) — review; pursue; observation stale.

Pursue. The five formats share exactly one law beyond the menu: which authored projection is exported, with loss reported. The copied menu violates it: on a proposing or markup view, HTML exports the view children (proposed), Markdown serializes accepted content, Word exports proposed or review, and PDF/PNG screenshot the markup paint; only Word reports loss (probe log). The package already owns per-format projection adapters (renderAuthoredHtml, markdown.serializeAuthored, exportToDocx), but HTML and Markdown adapters throw when authored is not installed while DOCX tolerates it, and renderAuthoredHtml cannot render a live editor capture through a static kit the way exportToDocx does privately. Strongest cut: delete live-DOM raster capture. The PDF is one image-only page sized to the canvas, with no text layer or pagination, and the capture forces a sans-serif font on every descendant of the first contenteditable, so code and math lose their fonts. Replace PDF with browser print of the same static projection HTML and delete PNG unless design names a current job. HTML should stop linking https://platejs.org/tailwind.css from copied source and share one registry-owned document shell with the html-export block. Stop on any package-level cross-format export noun: codecs differ in options, results and lazy dependency weight, and a shared exportDocument/Export plugin removes no caller work.

Question: What does each export format promise, and should DOM raster capture, static HTML and document codecs share anything beyond a menu?

- Keep the menu as-is: rejected. One click set yields four different projections and silent loss in three formats (probe).
- Package-level cross-format export noun (editor.api.export(format), ExportPlugin, exportDocument): Stop. HTML, Markdown and DOCX have different options, results and lazy dependencies; the only shared inputs are projection and a download, which the copied menu can own in a few lines.
- Merge renderStaticHtml/renderAuthoredHtml and serialize/serializeAuthored into single projection-aware entrypoints: rejected for this scope. Canonical string codecs have independent jobs (clipboard, AI, persistence); forcing result/diagnostic wrapping on them adds cost without fixing the menu.
- Change existing projection adapters to match exportToDocx: accept editors without authored installed (trivial snapshot, as DOCX captureExportSnapshot does), and give renderAuthoredHtml the DOCX-style editorPlugins capture so a live editor renders its projection through a static kit. Pursue as a design candidate; it removes caller branching and lets DOCX reuse one package capture+render path.
- Keep raster PDF/PNG but fix the font override and selector: rejected as the target. It still exports session paint, is DOM-bounded (future omission), subject to canvas/PDF page limits, and yields an image-only PDF.
- Replace raster PDF with print of the static projection HTML (hidden iframe, @page CSS): strongest PDF target. Vector, selectable and paginated text with links, and no html2canvas-pro or pdf-lib. The cost is a print dialog step.
- Delete PDF from the free menu and leave PDF to Plus server export: viable fallback if print output fails design proof.
- Rasterize the static projection for PNG instead of the live editable: only if design names a current PNG job; otherwise delete PNG with html2canvas-pro.
- HTML stylesheet: keep the platejs.org link (rejected: copied output depends on Plate site CSS and version, not the app); registry preset like DOCX_EXPORT_STYLES or inlining app stylesheets at export time are the design candidates; one shell shared with the html-export block.
