Question: Should path-stable snapshot indexes keep mutating one shared provenance record when authored accepted and projected history can branch from the same source snapshot?

- Keep/configure: rejected because shared in-place provenance crashes a valid authored undo branch.
- Patch authored history or Plate heading deletion: rejected because callers cannot safely coordinate snapshot-index ownership and the same branch can occur outside heading deletion.
- Always allocate a persistent index per path-stable commit: rejected because existing core contracts require stable index identity for cached linear text edits.
- Always remap through the full structural mapper: rejected because path-stable edits do not move identities and the extra work discards the large-document optimization.
- Copy on branch at the existing snapshot-index owner: selected; linear edits keep their identity, while a detected older source receives a fresh lazy index from that exact document.
- Replace snapshot indexing: rejected because the current lazy identity and compact structural mapping contracts remain useful once branch ownership is corrected.
