### 2026-09-13: 2026-09-13-suggestions-google-docs-audit

[Immutable record](../review-records/2026-09-13-suggestions-google-docs-audit.json) — review; pursue; observation stale.

Pursue complete suggestion semantics through native per-change details and Plate review. Cut kind-plus-text-ranges as the sole review contract, the first-200-pending card assumption, and silent decision refusals. Keep native authored identity and causal decisions; restoring main would restore duplicate mutation logic and known structural/property limits. Actual Enter/Backspace and valued-mark review lifecycles are the first bounded design question.

Question: What Google Docs-style suggesting behavior is missing or unproved after the main Suggestion package cut, and should Plate restore the old engine or redesign its native review contract?

- Keep/configure: existing native contracts and useful tests remain, but current kind/range-only UI cannot express structural identity or exact property changes. More CSS or isolated command patches cannot complete the job.
- Change existing API: expose bounded per-change semantic details and structural locations from native authored facts. Plate supplies descriptions, markers, navigation and application policy; the exact public call remains unsettled.
- Add primitive: a missing native read capability may earn addition, but a separate Suggestions state store or generic review framework duplicates identity, decisions and Comments lifecycle without a current independent job.
