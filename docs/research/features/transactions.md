Pursue consistent rejection of thenable transaction authors at existing Plite extension-write and pure-spec boundaries. Keep immediate updates, prepared command specs and canonical document changes; no broader transaction rewrite is justified by the current jobs.

Question: What becomes observable when updates commit, nest, fail or repair content, and which overlapping mutation authorities can disappear?

- Keep/configure: retain the core state model and ordinary update surface, but caller discipline does not repair the inconsistent rejection of thenable authors.
- Repair existing contracts: selected. Validate extension-write and pure/extended-builder completion at existing author boundaries, preserving synchronous results and the current draft rollback owner.
- Add an async transaction primitive: reject for this job. It introduces draft lifetime, concurrency and rebasing laws without a current async-transaction requirement.
- Delete direct/configured update forms: reject. They are entrances to one commit owner; deleting them adds caller ceremony and does not remove the pure-spec hole.
- Delete prepared specs and execute commands live: reject. Media extends a downstream result; InputRules builds prefixes and continues against them before publication. Savepoints or preview editors would recreate the removed responsibility.
- Merge DocumentChange, TransactionSpec and Commit: reject. Canonical transformation/mapping, revision-bound prepared selection/effects/tags, and published revision observations have distinct lifetimes and current jobs.
- Move validation into Plate: reject. Raw Plite, extension portals and headless command builders expose the same defect; Plite owns transaction law.
- Replace all immediate updates with prepared command specs: reject here. Immediate updates also stage extension publication and local after-commit work; new command carriers would move that coordination without removing the synchronous boundary.

Proof limits: 94 existing cases pass across five package files. A source-bound 14-row public probe finds nine accepted thenable-author paths: seven publish, two return a prepared spec. Three delayed continuations show a normal async update rolling back while an extension method and command builder retain their first write after the later write fails. All 41 file inputs, one consumer-directory fingerprint and 11 scope-group fingerprints are unchanged across the final proof. This is a bounded authority review, not an exhaustive mutation-algorithm audit. No product fix, type-level rejection, new guard runtime, performance improvement, browser/native parity or strict checkout closure is certified. The selected next owner is Patch for the reproduced behavior, not an accepted new runtime architecture.
