Question: What must a saved document retain, validate and migrate, and which durable-state or migration layers can be eliminated?

- Move the current runner unchanged to Plite: reject because relocation preserves live editor and Plate-specific preparation dependencies. Move only neutral document/schema/selection laws into their canonical owner.
- Strongest proposed architecture: one detached complete conversion bound to exact target schema and explicit format policy; preflight, transform, prepare, validate, return current envelope and report, then save or load. Compare deleting automatic editor migration against retaining a thin delegate, without a second lifecycle.
- Public cuts: V53 provenance/catalog exports have only internal/test consumers in current search and can become private. Keep the migration subpath and independent legacy-comment extraction job.
- Universal saved editor session or Yjs-only persistence: reject because document data, runtime keys/views, undo replay and external app records have different lifetimes and compatibility laws.

Question: What must a saved document retain, validate and migrate, and which durable-state or migration layers can be eliminated?

- Keep/configure: rejected. Wrappers, caller discipline and an unversioned floor do not preflight callbacks, isolate caller data, align standalone success with load validation or remove ambient editor/store authority.

- Strongest proposed architecture: one complete migration operation receives an exact persisted envelope or explicit raw-source intent plus immutable compiled target facts; each step returns detached document data and optional explicit selection mapping; the owner prepares, fits, validates and returns the current envelope and applied-step report.
- Delete the shared runner and leave app functions: rejected. Exact identity checks, chain dispatch, structural selection mapping, runtime/CLI parity and reporting are repeated current jobs. Keep one operation without a manager, plugin or store.
- Delete automatic editor migration: compare this hard cut during design. A thin load adapter earns retention only if it delegates to the complete operation and adds no source inference, policy or second lifecycle.
- Merge application lineage into feature codecs or a universal saved session: rejected. Feature metadata, app AST versions, local history, collaboration and external records have different lifetimes and compatibility laws.
- Public cuts: keep platejs/migrations as the sole migration API owner; move root imports and CLI scaffolding to it, privatize V53 catalogs and delete the WeakMap selection protocol after explicit result adoption.
