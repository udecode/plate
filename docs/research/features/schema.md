Question: How should typed extensions contribute and reconfigure schema and behavior without duplicate configuration authorities?

- Keep/configure: flat descriptors and one schema compiler express current jobs with inferred callbacks.
- Change API: an overloaded configuration factory hides distinct schema/resource/replacement laws without eliminating them.
- Add primitive: a profile/container layer duplicates descriptors and slots.
- Delete/merge: fields are already extensions; merging slots into dependencies loses owned replacement, and deleting contribution points forces codec/clipboard side registries.
- Move ownership: atomic publication/schema validity belongs in Plite, not a Plate-only coordinator.
- Replace: independently published mutable registries make coherent API/schema rollback a cross-owner protocol.
