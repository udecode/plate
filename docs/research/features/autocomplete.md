That reason still holds against the shipped ordinary-text owner. In Chromium the old input exposes combobox, expanded, hasPopup, controls and activedescendant, while the new editor root exposes only textbox with autocomplete, controls and activedescendant. The repair belongs in the existing owner. While a popup is open, setting role=combobox, aria-expanded and aria-haspopup on the editor root exposes the same combobox state as the old input, with focus, IME and content intact. A polite live region announcing the active option is the fallback if screen readers ignore the role change. Every other reason to return fails. Of the twelve external designs read in shards 001 to 003, only Atlassian's type-ahead since editor-core 149 isolates the query. The old persisted void breaks the no-orphaned-node law and loses the query on undo. Under the same Pixel 5 emulation it never opens its popup, and both designs share Plite's composition caret fault. Text substitutions now rewrite query text and Copilot can fire on a space inside a multiword query; both are accepted limits, not reasons to isolate the query.

### 2026-10-02: 2026-10-02-autocomplete-input-element-rechallenge

[Immutable record](../review-records/2026-10-02-autocomplete-input-element-rechallenge.json) — review; pursue; observation stale.

Pursue ordinary text and do not return to an input element. Plate adopted the input element in 2024 for one stated reason: Joe Anderson found a void with a native input "the only way to get assistive technologies to consistently recognise that the cursor is inside a combobox" (udecode/plate#3168). That reason still holds against the shipped ordinary-text owner. In Chromium the old input exposes combobox, expanded, hasPopup, controls and activedescendant, while the new editor root exposes only textbox with autocomplete, controls and activedescendant. The repair belongs in the existing owner. While a popup is open, setting role=combobox, aria-expanded and aria-haspopup on the editor root exposes the same combobox state as the old input, with focus, IME and content intact. A polite live region announcing the active option is the fallback if screen readers ignore the role change. Every other reason to return fails. Of the twelve external designs read in shards 001 to 003, only Atlassian's type-ahead since editor-core 149 isolates the query. It uses a view-local nested contenteditable, not a document node, and pays with custom history steps, Safari and Chrome workarounds and no Android proof. The old persisted void breaks the no-orphaned-node law and loses the query on undo. Under the same Pixel 5 emulation it never opens its popup, and both designs share Plite's composition caret fault. Text substitutions now rewrite query text and Copilot can fire on a space inside a multiword query; both are accepted limits, not reasons to isolate the query.

Question: Which owner should recognize triggered editor text, retain its query, present current options and atomically accept completion across mounted views?

- Keep the shipped annotation, Lexical's pattern of textbox plus aria-activedescendant: loses, because it exposes less than HEAD and ARIA does not allow aria-expanded on a textbox, so the open state is not programmatically determinable.
- Change the existing owner (selected): switch the editor root to role=combobox with aria-expanded and aria-haspopup while a popup is open, as Draft.js mention does permanently. Chromium then exposes the same combobox state as the old input, with focus, IME and content intact. A screen-reader run decides whether a polite live region is also needed.
- Add a live region only: Atlassian pairs one with its combobox. It is announced regardless of role but carries no popup state, so it is the fallback, not the target.
- Replace the architecture with a view-local isolated query, Atlassian's nested contenteditable role=combobox in a widget decoration: gives native combobox semantics, invisible drafts and undo that reopens the menu. It loses on permanent cost: a new Plite view-local inline widget, focus transfer into a nested IME target, custom history steps, Safari undo and Chrome focusout workarounds, and Android focus problems around inline uneditable content (ProseMirror #903, Slate #5183 and #5680) with no Android proof in any editor.
- Return to the v34 persisted inline void with a native input: rejected. It leaves an author-locked node in shared documents, restores an empty input on undo, never opened its popup under the Pixel 5 emulation, and carries the nested-input failures seen in Slate (#5840, #1744, #2504, #5791) and in Plate after v34 (#3853, #4031, #4778).
- Isolate the query from input rules and Copilot instead: rejected for now. Text substitutions rewrite characters like (c) and -> inside a query and Copilot can trigger on a space in a multiword query, but completion deletes the query and only filtering is affected. ProseKit and BlockNote get partial isolation by claiming the text input first; no surveyed editor isolates query text from every transform.
