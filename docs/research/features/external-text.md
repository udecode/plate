Question: Which editing and selection authority may an external text view own while sharing canonical document text, history and other views?

- Keep/configure: ordinary slot and config are adequate, but extensions cannot repair the package adapter applying canonical updates out of order.
- Change API: returning the canonical reply from dispatch instead of synchronous update callbacks is the strongest protocol break; the textarea already handles feedback synchronously and the candidate fixes the defect with current contracts, so a new reply channel has no demonstrated independent need.
- Add primitive: reject arbitrary transaction/editor escape hatches, generic text sessions, adapter stores or another subscription owner; existing semantic actions and the shared commit fence own those jobs.
- Delete/merge/inline: pursue deletion of queued canonical-update replay and dispatchingToPlite coordination in CodeMirror; inspect rejection-reset sequencing with it. Retain composition-end ordering as its distinct native job. Collapsing the adapter/view/actions types hides real directional/lifetime contracts without deleting work.
- Move ownership: canonical changes/history stay in Plite, native DOM/parser stay in CodeMirror and presentation stays in copied UI. Compare synchronous feedback against publication from CodeMirror dispatchTransactions; no new runtime owner is accepted.
- Replace architecture: independent CodeMirror documents/history duplicate authority; universal native or universal CodeMirror rendering each discard a current independent job. A generic DOM runtime merger still needs foreign-host, coverage and retirement mechanics.
