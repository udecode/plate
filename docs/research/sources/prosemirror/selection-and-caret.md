# ProseMirror: selection and caret

## Vertical selection and geometry

- ProseMirror's browser geometry surface is `posAtCoords`, `coordsAtPos` and `endOfTextblock` (`view/src/domcoords.ts:275-515`); `endOfTextblock` caches its answer by state and direction and reads flushed DOM state for vertical textblock boundary checks. Source: `docs/plite/research/2026-06-12-huge-doc-native-selection/sources/prosemirror-view-selection-summary.md:8-12`. Limit: unpinned local checkout read on 2026-06-12.

- ProseMirror's vertical key capture (`view/src/capturekeys.ts:244-264`) leaves ordinary shifted vertical text selection to the browser and takes ownership only when vertical movement needs node or block selection; that works because its whole document is in the DOM. Source: `docs/plite/research/2026-06-12-huge-doc-native-selection/sources/prosemirror-view-selection-summary.md:15-17`, `README.md:36-42`. Limit: unpinned local checkout read on 2026-06-12.

## Atom-aware selection

- ProseMirror's native selection import does not trust one DOM endpoint: `selectionFromDOM` turns a collapsed DOM selection inside a selectable atom into a `NodeSelection`, unless the caret sits on the edge of an inline atom, folds a multi-range native selection into one range, and resolves the rest through `selectionBetween` with a pointer or direction bias (`ProseMirror/prosemirror-view@ca4c78e9:src/selection.ts:9-47`). On export, `selectionToDOM` briefly makes a neighbor editable in Safari, and in Chrome before 63, because those browsers refuse a selection that starts or ends between non-editable block nodes (`:55-115`). Source: `docs/plite/research/2026-06-14-firefox-inline-void-select-all-replacement/read-log.tsv:4-5`; lines reread on 2026-10-08 at the HEAD of the local clone the 2026-06-14 run read without recording a commit; that HEAD is dated 2026-04-01, before the read.

- ProseMirror's `selectAll` command sets an `AllSelection` over the whole document (`ProseMirror/prosemirror-commands@52a84a84:src/commands.ts:432-435`). Source: `docs/plite/research/2026-06-14-firefox-inline-void-select-all-replacement/read-log.tsv:7`; reread at the pinned commit on 2026-10-08.

## Selection sync and drag

- prosemirror-view writes the model selection to the DOM only when the editor owns the selection. In Chrome, during a mouse drag whose DOM anchor still matches the observer's recorded selection, it skips that write, sets `delayedSelectionSync` and syncs once the mouse is released (`ProseMirror/prosemirror-view@ca4c78e9:src/selection.ts:55-72`, `src/input.ts:358-370`). During a mouse drag, `updateState` also skips rewriting the DOM selection while it still matches the observer's recorded selection, because an update that lands between a DOM selection change and its `selectionchange` event would disrupt the drag (`src/index.ts:205-218`). On mouse-down on a node it might drag, the view sets `draggable` on it, or `contentEditable=false` 20 ms later, stopping the DOM observer around each change, and removes both on mouse-up (`src/input.ts:346-370`). The DOM observer listens to document `selectionchange`; for 50 ms after `suppressSelectionUpdates` it rewrites the DOM selection from the model instead of reading it, and otherwise it flushes DOM changes when the view has focus and a selection (`src/domobserver.ts:119-145`). Source: `docs/plite/research/2026-06-12-browser-longtask-selection-oracles/read-log.tsv:11-14`.

## DOM selection ownership

- ProseMirror's DOM observer owns `selectionchange`: `suppressSelectionUpdates` opens a 50 ms window in which a selection change re-exports the editor selection to the DOM instead of importing it, and `ignoreSelectionChange` skips a selection whose common ancestor's view desc ignores selection mutations, as a node view can ask (`ProseMirror/prosemirror-view@c752c6ef7225199f73cb433dd3179e7d69b840d8:src/domobserver.ts:126-134`, `:151-166`). Only where the clipboard API is unusable (old IE and Edge) does copy fall back to `captureCopy`, which blurs the editor, selects an offscreen copy of the slice and removes it later (`src/input.ts:568-585`, `:600-610`). Read 2026-10-08.

## Pointer selection

- When ProseMirror lets the browser handle a mouse-down (`allowDefault`) in Chrome and the DOM selection's anchor still matches the observer's current selection, `selectionToDOM` sets `delayedSelectionSync` and skips writing the editor selection, leaving native selection browser-owned for the pointer gesture; mouse-up cleanup then schedules the sync. Evidence: `ProseMirror/prosemirror-view@c752c6ef7225199f73cb433dd3179e7d69b840d8:src/selection.ts:55-72` and `src/input.ts:370`, checked 2026-10-08.
