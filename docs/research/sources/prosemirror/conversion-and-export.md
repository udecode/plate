# ProseMirror: conversion and export

## ProseMirror test families

- **PM-03 DOM parsing.** `model/test/test-dom.ts` checks `DOMParser` and `DOMSerializer`: lists, blockquotes, code blocks, links and marks, non-breaking spaces, meaningless whitespace, `<br>` handling, recovery of stray text and misplaced nodes, open slices, parse context and rule priority, XML namespaces and nested same-type marks (`ProseMirror/prosemirror-model@bc912ea0ff8ac935c7f1dc3cf029cd0b6ecdda97:test/test-dom.ts:15-686`). Plite's browser counterpart is `apps/plite/tests/plite-browser/donor/examples/paste-html.test.ts`; the `dom-html.test.ts` and `host-codec.test.ts` package tests the harvest named no longer exist. The harvest keeps schema fitting in Plite and DOM policy in host or Plate codecs. Source: `docs/editor-test-harvester/prosemirror/report.md:142`.

- **PM-20 Markdown.** The harvest reads `markdown/test/test-custom-parser.ts` and `test-parse.ts` as checking Markdown parsing and serialization: escaping, marks, blocks, lists, custom token bindings and round trips through schema-fitted content. Plate's Markdown codec tests live in `packages/platejs/src/markdown/lib/`, such as `MarkdownPlugin.spec.ts`, `markdownConformance.spec.ts` and `commonmarkSurface.slow.ts`, and the Plite browser counterpart is `apps/plite/tests/plite-browser/donor/examples/markdown-preview.test.ts`. Source: `docs/editor-test-harvester/prosemirror/report.md:159`.

## Serializers

- prosemirror-model 1.25.4 (`ProseMirror/prosemirror-model@6264de06`, MIT) depends on `orderedmap`, not on a view or React. `Node` is a persistent document value with `textContent`, `textBetween` and structural `toJSON` and `fromJSON`, independent of any editor (`src/node.ts` lines 1-40, 85-110 and 310-355), and `DOMSerializer` takes schema-derived or caller-supplied node and mark handlers plus a `Fragment` or `Node`, with an injectable `Document` for building DOM outside a browser (`src/to_dom.ts` lines 1-170). prosemirror-markdown 1.13.5 (`ProseMirror/prosemirror-markdown@221ec60e`, MIT) depends on prosemirror-model and markdown-it, and its synchronous `MarkdownSerializer` owns format state, node and mark mappings, escaping and list behavior. An unknown node or mark throws by default; under `strict: false` an unknown non-leaf node renders its content, an unknown leaf disappears and an unknown mark is dropped, with no report (`src/to_markdown.ts:217-224`, `:279-290`). Source: `docs/plite/research/2026-09-24-export-architecture/read-log.tsv` rows 2-8 and `shards/001-direction.md:139` (2026-09-24; strict handling reread at that commit 2026-10-08).

## Parsing documents and slices

- ProseMirror has no common codec object. Its DOM parser exposes whole-document `parse` and open `parseSlice` as separate operations (`ProseMirror/prosemirror-model@6264de06:src/from_dom.ts`), and prosemirror-markdown keeps a separate parser and serializer at the Markdown owner (`ProseMirror/prosemirror-markdown@221ec60e:src/from_markdown.ts`, `src/to_markdown.ts`). The split matches Plite's `EditorDocumentValue` versus `ContentSlice`. Source: `docs/plite/research/2026-09-25-document-codec-architecture/shards/004-editors-and-cross-language-controls.md:18-23` and read-log rows 22-23 (2026-09-25).
