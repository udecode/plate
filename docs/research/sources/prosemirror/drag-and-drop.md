# ProseMirror: drag and drop

## Drop

- **A ProseMirror drop that inserts nothing publishes nothing, not even the move's deletion.** The built-in drop handler builds one transaction that first deletes a moved source (`node.replace(tr)` or `tr.deleteSelection()`) and then inserts the slice at `dropPoint`; when the document after insertion equals the document before it (`tr.doc.eq(beforeInsert)`), it returns without dispatching, so the source survives. A custom drag handle only prepares `view.dragging` with the slice and drag image, and the editor owns the drop mutation, as Tiptap's handle does. Code: `ProseMirror/prosemirror-view@ca4c78e9b56f1b164c0b3758b59d8748f11b7534:src/input.ts:740-778`. Source: `docs/research/probes/2026-10-01-dnd/REPORT.md:160-164`, verified against that checkout on 2026-10-08; Tiptap handle in `docs/plite/research/2026-10-02-dnd-landing-policy/editors.tsv:9`.

- **ProseMirror's drop landing is schema-derived.** `handleDrop` calls `dropPoint(doc, pos, slice)`, which walks from the pointer depth up to the doc and takes the first depth whose content expression accepts the slice (`canReplace`), then makes a second pass that allows one wrapping (`findWrapping`). When `dropPoint` returns null, `handleDrop` falls back to the raw pointer position, then commits through `replaceRangeWith` or `replaceRange` (`ProseMirror/prosemirror-transform@662b7a937baf:src/structure.ts:324-349`, `ProseMirror/prosemirror-view@ca4c78e9b56f:src/input.ts:727-778`). `dropPoint` has no depth cap and no per-container policy, and it ignores `isolating`, which only replace, delete and lift consult. A block slice therefore lands inside table cells, blockquotes, list items and details wherever the content allows, and a `tableRow` slice fits any table that accepts rows, not only its source table. `NodeSpec.draggable` (default false) lets a node drag without being selected, any non-empty selection drags natively, and core has no drag handle. `prosemirror-dropcursor` recomputes on every unthrottled dragover (`posAtCoords`, `dropPoint`, one or two rect reads), so the indicator always matches the default drop, and `disableDropCursor` only hides the cursor without blocking the drop (`ProseMirror/prosemirror-dropcursor@061f64ac887a:src/dropcursor.ts:30-35`, `:88-111`). ## Drag source

- ProseMirror drags and drops on native `DataTransfer`. `dragstart` serializes the dragged slice for the clipboard and keeps it in `view.dragging` with the dragged node and a move flag; the drag copies instead of moving while Alt (macOS) or Ctrl (elsewhere) is held; and `drop` parses foreign data through the clipboard parser and places the slice with `dropPoint` from the schema (`ProseMirror/prosemirror-view@ca4c78e9b56f1b164c0b3758b59d8748f11b7534:src/input.ts:669-707`, `:719-748`). That read used the GitHub mirror; the canonical forge head `f9ac936227cf8d5d0ba6ff1b8d3bf7625aa6553a` was not inspected. Source handling does not prove OS or mobile parity.
