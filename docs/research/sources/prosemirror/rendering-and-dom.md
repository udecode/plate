# ProseMirror: rendering and DOM

## React renderers

- react-prosemirror stops ProseMirror's DOM observer, since React renders the DOM, and ignores `selectionchange` while composing, because in Safari even setting the selection to its current position ends a composition; after React's DOM commit it forces a base view update so DOM selection and node-view callbacks are validated. Its tests cover selection updates when the DOM selection parameters look unchanged after decoration redraws, and a fallback when `Selection.extend` throws. Evidence: `handlewithcarecollective/react-prosemirror@13ae2f87e726330e5f3cb0405e6b158a3d14ab95:src/ReactEditorView.ts:116-131`, `:268-289`, `src/components/__tests__/ProseMirror.selection.test.tsx:452-476`, `:478-492`, checked 2026-10-08 at the local clone.

- React-ProseMirror separates rendering from operations that need the committed view. Its `useEditorEffect` runs after the view has current state and decorations, `useEditorEventCallback` keeps handler identity stable while using the latest mounted view, and `LayoutGroup` orders editor effects after descendant layout effects. Source: `docs/plans/2026-05-23-plite-react-prosemirror-steals-ralplan.md:55-60`, citing the local `../react-prosemirror/README.md:104-123`, `:215-220`, `src/hooks/useEditorEffect.ts:11-24`, `src/hooks/useEditorEventCallback.ts:24-53` and `src/components/LayoutGroup.tsx:13-19`. That May scan pins no commit; these are historical adapter findings, not current Plite hook contracts.

## Node-view content ownership

- **Omitting contentDOM changes the node view's editing contract.** With contentDOM, ProseMirror renders the node's children into that element. Without it, the node view owns rendering or omitting those children, domFromPos resolves against the outer DOM with an atom marker, and non-text nodes other than BR receive contenteditable=false unless the view explicitly supplied that attribute. Node views can also own selection, event filtering and mutation filtering through setSelection, stopEvent and ignoreMutation. Evidence: `ProseMirror/prosemirror-view@c752c6ef7225199f73cb433dd3179e7d69b840d8:src/viewdesc.ts:31-88`, `:308-309`, `:708-711`, inspected locally. Source: `c70bacbd4a:docs/plans/2026-05-02-plite-hidden-subtree-first-class-ralplan.md:227-265`, whose original checkout was unpinned. Limit: this describes node-view ownership, not a guarantee that omitted descendants retain ordinary native editing.

## State and mounted view ownership

- ProseMirror separates persistent EditorState and transaction-applied plugin fields from EditorView's mounted DOM, plugin views, focus, coordinate mapping and paste helpers. Keymap commands receive state, dispatch and an optional view, allowing view-dependent behavior without putting the mounted view into persistent state. Evidence: docs/plans/2026-05-16-plite-unified-extension-composition-ralplan.md:698-699, citing prosemirror-state/src/state.ts:83,117 and src/plugin.ts:7, prosemirror-view/src/index.ts:27,255,336 and prosemirror-keymap/src/keymap.ts:47 in local checkouts. Limit: these May 2026 reads record no commits.

## Dirty view updates

- **The view distinguishes dirty scope and reuses composition-safe children.** ProseMirror defines clean, child-dirty, content-dirty and node-dirty levels; child reconciliation tries matching or updating existing descriptions before creating new ones and protects the local composing DOM before replacement. DecorationSet is persistent, and the DOM observer collects changed positions into an affected range. Evidence: `ProseMirror/prosemirror-view@c752c6ef7225199f73cb433dd3179e7d69b840d8:src/viewdesc.ts:130-137`, `:767-810`, `src/decoration.ts:265-302` and `src/domobserver.ts:174-205`.
