# ProseMirror: tables

## Table copy and paste

- prosemirror-tables turns pasted cells into a rectangle (`ProseMirror/prosemirror-tables@eb522f25959a1e4515a4ff5ce7e3a939f19c55e9`, the local checkout on 2026-10-08). `pastedCells` reads a slice of rows or cells into an `Area` (`src/copypaste.ts:38`), `fitSlice` fits a slice to a node type (`:109`), `clipCells` clips or repeats cells to fill the target rectangle (`:122`), and `insertCells` writes them (`:324`). Its tests cover cells, rows, partial rows, rowspans, rectangular padding, clipping and repeated cells (`test/copypaste.test.ts:31-152`, read 2026-06-13). Source: `docs/plite/research/2026-06-13-oss-rich-html-paste-clipboard-invariants/read-log.tsv:6-7`.

## Table clipboard

- prosemirror-tables treats table copy and paste as cell-rectangle algebra. Only row, cell and header-cell slices become a cell area (`pastedCells`), and pasted rows are padded to a rectangle that accounts for row and column spans (`ensureRectangular`). Pasting into a cell selection clips the area to the selection's rectangle and repeats it when the area is smaller (`clipCells`). Pasting cells into a single cell places the area's top-left at that cell, grows the table right or down as needed (`growTable`), splits row or column spans that cross the replacement edges (`isolateHorizontal`, `isolateVertical`) and leaves a cell selection over the pasted area (`insertCells`); `handlePaste` routes the two cases apart. Copying a cell selection serializes a rectangular slice of rows (`CellSelection.content`). `test/copypaste.test.ts` covers padding, clipping, repetition, table growth, header preservation, span splitting and width preservation. Evidence: `ProseMirror/prosemirror-tables@eb522f25959a1e4515a4ff5ce7e3a939f19c55e9:src/copypaste.ts:1-11`, `:38`, `:83`, `:122`, `:183`, `:238`, `:277`, `:324`, `src/input.ts:129-170`, `src/cellselection.ts:104-125` and `test/copypaste.test.ts:31-262`, checked 2026-10-08.

- Two ProseMirror forum threads add table-paste pressure: making table cells `isolating` keeps replace-fitting from lifting pasted cell content out of the table ('Broken table pasting', https://discuss.prosemirror.net/t/broken-table-pasting/5117, 2022-12), and strict per-column cell schemas can put extra nodes into copied table slices, so table clipboard needs typed slice semantics and parser normalization beyond rectangle placement (https://discuss.prosemirror.net/t/prosemirror-table-with-strict-schema-and-copy-paste/8473, 2025-07). Grades A and B in the run's ledger; threads read 2026-06-13.

## Resize issues

- Three prosemirror-tables reports read on 2026-09-17 name resize cases a table design must cover: a custom view's resize preview (#293: a width-aware `TableView`'s preview is overridden by the static `updateColumnsOnResize`, and the reporter, using it through Tiptap, proposes a preview callback or delegation to the view), deleting a table while the pointer hovers a resize boundary (#120), and right-to-left layout (#333: under `dir=rtl` handles sometimes appear on the wrong cell and resize the wrong column) (https://github.com/ProseMirror/prosemirror-tables/issues/293, /issues/120, /issues/333; docs/plite/research/2026-09-17-table-substrate-ownership/read-log.tsv:71-73). These are reports, not reproductions.

## Selection and resizing

- ProseMirror's core `Selection` is extensible, and prosemirror-tables adds an optional `CellSelection` with cell ranges, mapping, content, replacement and bookmarks, while `TableMap` and `columnResizing` stay in prosemirror-tables, not the core (ProseMirror/prosemirror-tables@eb522f25959a1e4515a4ff5ce7e3a939f19c55e9:src/cellselection.ts:1-472, src/tablemap.ts:1-330, src/columnresizing.ts:1-431; ProseMirror/prosemirror-state@ffad5d9450a0b93438be53a801deee1a223a81bf:src/selection.ts:1-270, src/transaction.ts:35-125,136-176; read 2026-09-17, not executed). A custom selection type carries obligations well beyond two endpoints: mapping, content, replacement, JSON identity, bookmarks and visibility (docs/plite/research/2026-09-17-table-substrate-ownership/REPORT.md:46; read-log.tsv:2-3,7).
