# Meowdown: drag and drop

## Cross-editor move

- **Cross-editor move.** `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/cross-editor-drag.test.ts` (lines 30-145) pins that a block or text drag into another Meowdown editor is a move: the source block is removed only after it lands, and the copy modifier makes it a copy. The source stays put when the drop carries nothing, when the drag did not start in another Meowdown editor, or when the source changed during the drag, in which case the target still receives the drag-start content. A third editor is never touched, and a same-editor drag stays on ProseMirror's move path. Plate chose another default: a drag into another editor copies and keeps the source, a drag within one document moves the content present at drop, and a source that no longer resolves refuses (`c70bacbd4a:docs/editor-behavior/editor-protocol-matrix.md:492-493`, both `tested`). Its browser cases are `apps/plite/tests/plite-browser/donor/examples/plate-dnd-cross-editor.test.ts:44` (copies into another editor and leaves a third editor isolated), the same file's case at line 268 (refuses a drop after the dragged block is removed) and `apps/plite/tests/plite-browser/donor/examples/cross-editor-drag.test.ts:257` (copies the dragged text present at drop after a source edit). Of Meowdown's cases, third-editor isolation carries over, and so does the copy modifier, which Plate reads within one editor (row 494); the delete-after-landing and changed-source guards have no cross-editor counterpart in Plate. The 2026-08-21 report's uncommitted Plate change that moved drag-start content (`docs/editor-test-harvester/meowdown/report.md:146, 240-243`) is superseded by that law; the copied UI in `apps/www/src/registry/components/editor/dnd.tsx` calls `editor.api.transfer` (checked on 2026-10-08).
