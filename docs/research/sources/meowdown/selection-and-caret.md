# Meowdown: selection and caret

## Rendered inline atoms over hidden source

- **Inline atoms.** `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/atom-mark-navigation.test.ts` (lines 64-733) pins that Arrow, Shift+Arrow, editing next to the atom, and pointer drags treat a rendered inline atom, such as a wikilink, as one unit, and that the caret never rests inside its hidden Markdown source. The rendered-atom part matches Plite's browser cases for read-only inlines (`apps/plite/tests/plite-browser/donor/examples/inlines.test.ts`), mentions (`apps/plite/tests/plite-browser/donor/examples/mentions.test.ts`) and images (`apps/plite/tests/plite-browser/donor/examples/images.test.ts`). The hidden source is Meowdown's own product policy, with no Plate counterpart. Evidence: `docs/editor-test-harvester/meowdown/report.md:142`; the Plite files were read on 2026-10-08, not rerun.

## Hidden syntax runs

- **Hidden syntax.** `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/hidden-run-caret.test.ts` and `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/hidden-run.test.ts` pin that a caret or pointer endpoint never splits a hidden syntax run, and that destructive keys keep the run or remove it whole, depending on direction. Plate has no projection that hides Markdown syntax, so these cases apply only to a future Markdown-source editing surface, which would need its own browser proof. Evidence: `docs/editor-test-harvester/meowdown/report.md:143`.

## Escape collapse

- **Escape collapse.** `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/escape-collapse.test.ts` pins that Escape collapses an expanded text selection, forward or backward, to a caret at its head, collapses a node selection to a caret, and leaves an empty selection alone, without changing content. Plite's `selection.collapse` command (`packages/plitejs/src/core/editor-commands.ts:624`) gives the same collapse; binding Escape to it is product UI policy for whichever menu or selection UI claims the key. Evidence: `docs/editor-test-harvester/meowdown/report.md:147`.

## Editor exit at the first or last visual line

- **Exit at visual edges.** `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/exit-boundary.test.ts` pins an editor-exit callback that fires on ArrowUp or ArrowDown only when a collapsed caret is on the first or last visual line of the document, so ArrowUp fires from the first wrapped line but not from a lower line of the first paragraph. A node-selected edge block fires only once it has become a gap cursor, and nothing fires with Shift held or with a non-empty text selection. Plite groups visual lines in its DOM geometry (`packages/plitejs/test/dom/dom-geometry.test.ts:294`) and moves the caret out of a nested content root on its boundary visual line (`packages/plitejs/src/react/editable/content-root-navigation.ts:325-341`), but it gives the host no exit callback. Evidence: `docs/editor-test-harvester/meowdown/report.md:148`; Plite code read on 2026-10-08.

## Custom caret

- **Custom caret.** `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/mark-mode.test.ts`, `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/virtual-caret.test.ts` and `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/virtual-caret-line-break.test.ts` pin Meowdown's virtual caret: drawn one line tall next to hidden runs and atom marks such as wikilinks, hidden for a range selection, a selected atom or a blurred editor, following layout as text wraps, and giving way to the native caret once a touch `pointerdown` arrives. The harvest rejected a custom caret for Plite (`docs/editor-test-harvester/meowdown/report.md:150, 205-206`); Plite's React layer exports the model selection to the native selection (`docs/vision/plite.md:222`).

## Scroll to selection

- **Scroll to selection.** `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/scroll-to-selection.test.ts` (lines 48-133) pins that scrolling to the selection targets the visible caret, including next to a wikilink or after hidden syntax, keeps a configured margin below the caret, and does not scroll while the caret is already visible; its implementation reads `visualViewport` (`prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/scroll-to-selection.ts`). Plite's `scrollIntoView` (`packages/plitejs/src/dom/plugin/dom-editor.ts`, tested in `packages/plitejs/test/dom/scroll-into-view.test.ts`) honors a path's scroll margin but does not read `visualViewport`; Plite reads it only to refresh selection geometry (`packages/plitejs/src/react/range-geometry.ts:326-331`). The harvest held that changing Plite's viewport policy needs real-device evidence. Evidence: `docs/editor-test-harvester/meowdown/report.md:152`; Plite code read on 2026-10-08.

## Document-edge shortcuts

- **Document edges.** `prosekit/meowdown@5b9962982a1cb3d1732355c753ce76d9a5966af3:packages/core/src/extensions/select-doc-boundary.test.ts` (lines 12-124) pins that Meta+ArrowUp and Meta+ArrowDown reach the document start or end when the document begins with a task or bullet list or ends with a task list, rest before a leading hidden run, extend the selection with Shift, and do not fire the exit callback. Plite has the leading-checklist start case: `apps/plite/tests/plite-browser/donor/examples/check-lists.test.ts:93`, 'moves document-start navigation to a leading checklist item', which skips the `mobile` project. A trailing checklist, the document end and Shift extension have no Plite case. The report says the case passed in Chromium and WebKit (`docs/editor-test-harvester/meowdown/report.md:153, 246-249`); the file was read on 2026-10-08, not rerun.
