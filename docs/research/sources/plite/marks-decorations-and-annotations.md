# Plite: marks decorations and annotations

## Rendering API boundaries

- The 2026-09-01 rendering API audit (17 references, 85 atomic rows) chose source-owned decoration descriptors with keyed, data-only range attributes and explicit observation and cleanup, and separated four concerns: range paint, positioned UI, durable anchors and application data. `CommentsPlugin` keeps editor projection ownership while applications keep threads and persistence; an earlier proposal to remove `CommentsPlugin` was reversed because copied UI would then have to rebuild editor projection. The audit rejected arbitrary transient segment rendering, a public generic Projection API, raw Plate render, decorate or provider-store props, and a generic Plite view plugin. Current owners: `DecorationSource` with `observe` and `read` (`packages/plitejs/src/interfaces/decoration.ts`), `CommentsPlugin` (`packages/platejs/src/react/features/comments/CommentsPlugin.ts:5`). Source: `docs/editor-audits/reports/rendering-api-editor-audit-2026-09-01.md:16-25`. Limit: these are the decision's boundaries, not a statement that its proposed spelling is today's API.

- In the 2026-09-01 rendering audit's captured decoration-manager experiment, four frozen scale cohorts passed the audit's budgets; on the pathological cohort, retained subscriptions fell from 320,000 to 10,032, mount p95 rose from 58.256 ms to 68.065 ms, and full reads improved from 12.604 ms to 2.865 ms. Source: `docs/editor-audits/reports/rendering-api-editor-audit-2026-09-01.md:27-32`. Limit: a manager-level experiment, not an end-to-end editing or general performance claim, and the revision measured is not pinned in the summary.
