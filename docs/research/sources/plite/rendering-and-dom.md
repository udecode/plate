# Plite: rendering and DOM

## Trailing and consecutive soft breaks

- **Trailing break line.** Wordgard `wordgard/wordgard@b5ad0d057e2790c8cf971c85a9d2fb7e4a82da54:test/webtest-coords.ts` lines 101-115 pin that consecutive soft breaks and a trailing break each keep a measurable line, and that clicks map back to the right model offset. Porting the case exposed a Plite Chromium defect: the trailing line had no physical height. The fix renders one newline after the final text for display only, while `data-editor-length` keeps the model length (`packages/plitejs/src/react/components/text-string.tsx`). The browser regression 'keeps consecutive soft-break lines and a trailing break clickable' in `apps/plite/tests/plite-browser/donor/examples/richtext.test.ts` maps the consecutive empty line to offset 6 and the trailing line to offset 18; it passed five forced runs and strict Chromium on 2026-09-02 (docs/editor-test-harvester/wordgard/report.md:123, 167). `packages/plitejs/test/react/rendered-dom-shape-contract.tsx` ('adds one rendering-only newline only to the final text child') pins the projection at package level. The report calls the attribute `data-plite-length`; the current file uses `data-editor-length`.

## Empty-block line break

- **React does not own the empty block's `<br>`.** An empty last text in an empty block renders a zero-width span marked `data-editor-zero-width="n"` with no U+FEFF (`resolveTextZeroWidth`, `packages/plitejs/src/react/components/editable-text-blocks.tsx:669-677`; `packages/plitejs/src/react/components/zero-width-string.tsx:7`), and that span sets its `<br />` through `dangerouslySetInnerHTML` instead of rendering it as a child (`zero-width-string.tsx:37-39`). The comment at `:38` gives the reason: Chromium rewrites this `<br>` during IME composition, and a React-owned `<br>` crashed reconciliation with a `removeChild` `NotFoundError`. The April 2026 proof saw that error take down the whole editable under Chromium IME, and with the DOM-owned `<br>` the composition `すし` committed with the caret after it (`52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-04-plite-no-feff-line-break-placeholders-need-dom-owned-br-interiors.md:29-34`, `:46-66`, `:84-91`). Slate #4738 reports the same `removeChild` error after typing over a multi-line mouse selection, so it shares the error, not the trigger (`c70bacbd4a:docs/plite-issues/open-issues-dossiers/4741-4643.md:54`, `:61`). Limits: the Chromium row 'commits IME composition in an empty rich text block' (`apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:2382`) composes into an empty block but asserts text and selection, not who owns the `<br>`; no test under `apps/plite/tests` or `packages/plitejs/test` names `removeChild` or `NotFoundError` (search, 2026-10-08).

## Mounted roots

- When one editor has several mounted roots, Plite's DOM runtime lookup returns the root that holds focus; with no focused root it returns the only mounted root, and with two or more unfocused roots it returns null (`findEditorDOMRootRuntime`, packages/plitejs/src/dom/plugin/dom-root-runtime.ts:158-177, rechecked 2026-10-08; first read 2026-09-11 in docs/plite/research/2026-09-11-large-documents-contract/read-log.tsv:12). Copy goes through that lookup: `writeDOMSelectionData` passes no coverage session to `writeDOMRangeData`, which then asks `findEditorDOMRootRuntime` for one (packages/plitejs/src/dom/plugin/dom-clipboard-runtime.ts:505-515,549-551). With ambiguous roots it sees no coverage boundaries and falls back to cloning the DOM range or writing the whole selection slice, so `exclude` boundaries would not apply; inferred from source, not run.

- **Browser identity is read from each mounted root's realm, never from globals.** `resolveDOMRootFacts(root)` reads the engine (`blink`, `gecko`, `webkit`, or `unknown`, which jsdom gets), the platform (`android`, `apple` or `other`), `beforeinput` target-range support, the language and a closed set of four quirks (`android-beforeinput-delete-is-uncancelable`, `compositionend-precedes-final-input`, `shadow-selection-needs-composed-range`, `webkit-contextmenu-focus`) from the navigator of the root document's `defaultView`, and caches one frozen fact set per realm (`packages/plitejs/src/dom/utils/environment.ts:71-160`). The public `isGeckoDOMHost` and `usesAppleDOMHotkeys` and the internal `hasDOMHostQuirk` first resolve an event, node, window or document to its root (`:183-257`), each mounted DOM root runtime resolves its facts from its own root node, with private `testRootFacts` overrides (`packages/plitejs/src/dom/plugin/dom-root-runtime.ts:566-571`), and the composition paths read the `compositionend-precedes-final-input` quirk through the event or root element (`packages/plitejs/src/react/editable/composition-state.ts:605`, `packages/plitejs/src/react/editable/keyboard-input-strategy.ts:381`). So an editor inside an iframe or a shadow root gets its own realm's facts, and `CAN_USE_DOM` only guards SSR initialization (`environment.ts:261-265`). Tests: 'resolves and freezes one cached fact set per realm', 'keeps iframe-style realms isolated and shadow roots realm-local', 'applies frozen private overrides without poisoning the realm cache' and 'imports without a DOM or navigator during SSR' (`packages/plitejs/test/dom/environment.ts:91`, `:117`, `:156`, `:56`; 4 passed on 2026-10-08). Limit: because facts are cached per realm, a polyfill set on a test window shared across files leaks between them (`docs/research/sources/plate-notes/testing-and-proof.md:46`). The rest of the source unit is an export inventory that the generated API reference owns. Source: `c70bacbd4a:docs/plite/reference/public-docs/libraries/plite-dom.mdx:88-89`; code read 2026-10-08.

## Decorated text and the DOM bridge

- **Decorations must not leak into offsets, copied HTML or text reads.** A decoration splits one model text into several leaf DOM nodes, so the bridge maps offsets across the slices ('converts a DOM range across decorated slices back into one Plite text range', `packages/plitejs/test/dom/bridge.ts:1419`). Copy empties zero-width spans (a newline for line-break ones) and then unwraps every span inside a `[data-editor-leaf]` that is not a `data-editor-string` or `data-editor-zero-width` node, so decoration wrappers never reach the clipboard HTML (`stripRenderOnlyLeafWrappers`, `packages/plitejs/src/dom/plugin/dom-clipboard-runtime.ts:77-89`, `:619-628`; test 'exports decorated multi-leaf text without leaking render-only wrappers', `packages/plitejs/test/dom/clipboard-boundary.ts:3023`). Reading DOM text up to the caret drops U+FEFF sentinels and removes `contenteditable=false`, retained and nested-editor content (`readTextToCaret`, `packages/plitejs/src/dom/plugin/dom-editor.ts:1110-1145`), and placeholder text stays out of native selected text (`apps/plite/tests/plite-browser/donor/examples/placeholder.test.ts:49`). These complement the Wordgard nested-wrapper round-trip row on this page. The April 2026 decorations cluster listed them as bridge contracts that browser proof had broken when decorations first split leaves. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/plite/decorations-annotations-cluster.md:231-244`. Limit: the bridge and clipboard rows are JSDOM package tests; code and tests read 2026-10-08.

## Leaf and text renderers

- **`renderLeaf` runs per segment and `renderText` once per Text.** When decorations split one Text into segments, raw Plite `Editable` calls `renderLeaf` once per segment, with `leafPosition` and children that already carry the decoration wrappers, so decorations never become `leaf` fields; it calls `renderText` once around all of that Text's segments (`packages/plitejs/src/react/components/editable-text.tsx:603-614`, `:693-701`). A wrapper or per-Text element that must not repeat belongs in `renderText`. Pass stable `renderLeaf`, `renderText` and `renderPlaceholder` functions: `EditableText` is memoized with `sameEditableTextProps`, which compares them by identity (`:966-999`), so a new function on every render re-renders every text node. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/plite/reference/public-docs/concepts/09-rendering.mdx:6-9`, `:105-137`; code read 2026-10-08.

## DOM bridge lookups

- Plite's DOM bridge pairs a nullable `resolve*` lookup with a throwing `assert*` lookup, and the split has a reason the API reference does not state. A `resolve*` lookup returns `null` for states that normal browser timing produces: DOM not yet mounted during a React commit, a stale node map, an empty or foreign DOM selection, a nested editor's ownership boundary, or an overlay whose target briefly has no range. An `assert*` lookup throws, because its failure means misuse, such as a detached node or a missing provider. `DOMApi` pairs them in both directions: `resolveDOMNode`, `resolveDOMPoint`, `resolveDOMRange`, `resolvePath` and `resolveEventRange` from model to DOM, `resolveNode`, `resolvePoint` and `resolveRange` from DOM to model, each beside its `assert*` twin, plus `resolveRangeRect` (`packages/plitejs/src/dom/plugin/dom-editor.ts:159-245`); `content/docs/api/dom.mdx` lists the model-to-DOM pairs and their null cases. In May 2026 runtime selection import and beforeinput reconciliation called strict converters with `suppressThrow: true` or local catches, which made ordinary browser timing look like exception handling; the fix added the resolvers, moved runtime and example code onto them, and added no `try*` alias and no deprecated `suppressThrow` option. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/developer-experience/2026-05-14-plite-dom-runtime-recovery-needs-resolver-apis-not-suppress-throw.md:20-44`, `:78-110`. Limit: the API list was read from source on 2026-10-08; the strict `to*` names the note uses (`toDOMRange`, `toDOMNode`) are now `assert*`.

## Schema reconfiguration

- **A schema reconfiguration rerenders only the element types and roots its delta names.** `state.schema.delta()` reports the element types, property IDs, roots and construction types that the current configuration publication changed (`EditorSchemaDelta`, `packages/plitejs/src/interfaces/schema.ts:535-541`; `packages/plitejs/src/interfaces/editor.ts:1471-1472`); it is configuration metadata read from state, not a document change. The compiler folds into `elementTypes` every element type that a changed element property applies to and every parent type of text that a changed text property applies to, and when the unknown policy changes it lists every type and root (`createCompiledEditorSchemaDelta`, `packages/plitejs/src/core/schema-compiler.ts:6413-6538`; `getPropertyAffectedElementTypes`, `:6379-6402`). On a commit whose `dirtyStateKeys` include `$configuration`, each mounted `EditorRoot` invalidates the mounted elements of every changed element type in its runtime roots and the top-level entries of every changed root, and reads neither `propertyIds` nor `constructionTypes` (`getSchemaInvalidatedNodeKeys`, `packages/plitejs/src/react/editable/schema-runtime-invalidation.ts:9-56`, called from `packages/plitejs/src/react/components/plite.tsx:677-680`). Source: `831f5e5da6a37f7d9095c1a81acc6b3de10bd3ba:docs/plite/reference/public-docs/concepts/19-schema.mdx:357-364`; code read 2026-10-08. Limit: other render paths that react to a configuration commit were not traced, and no test was run.

## React runtime rules

- **React reads committed snapshots, keys by `NodeKey` and takes no controlled value.** The April 2026 React runtime spec for the Slate v2 draft made these hard rules: derive view data from the committed snapshot instead of mirroring editor state through effects, subscribe through `useSyncExternalStore`, key rendering by persistent node identity, and keep editor writes in event handlers, commands or an explicit replacement call, never in an effect that copies a prop into the editor (`c70bacbd4a:docs/plite-draft/references/architecture-contract.md:382-398`, `:1403-1412`, `:1696-1717`). Current Plite keeps them. Selector hooks subscribe through `useSyncExternalStore` (`packages/plitejs/src/react/hooks/use-generic-selector.tsx:117`). `Editable` keys element and text children by `NodeKey` (`packages/plitejs/src/react/components/editable-text-blocks.tsx:952`, `:1056`). `EditorRootProps` takes an `editor` and reports through `onCommit`, `onSelectionChange` and `onValueChange`, with no controlled `value` prop (`packages/plitejs/src/react/components/plite.tsx:171-191`), and whole-document replacement is the transaction write `tx.value.replace` (`packages/plitejs/src/interfaces/editor.ts:4456`). Limit: checked by reading those files on 2026-10-08; no lint enforces the no-effect-sync rule.
