# Plite: large documents

## Huge-document architecture

- Plite's huge-document shape is hybrid: mounted DOM where it exists, an explicit DOM coverage boundary for every unmounted range, model-owned (projected) selection where DOM is absent, and materialization before an unmounted range is edited. Each unmounted top-level range registers a boundary with `reason: 'viewport-virtualization'`, `copyPolicy: 'model'` and `selectionPolicy: 'materialize'` (`packages/plitejs/src/react/viewport-boundary.tsx:15-45`), and TanStack Virtual drives the mounted window through `useVirtualizedRootPlan` (`packages/plitejs/src/react/virtualized/use-virtualized-root-plan.ts`). The 2026-06-12 huge-document research concluded this shape was right and that no rearchitecture was due (`docs/plite/research/2026-06-12-huge-doc-architecture/README.md:20-25`). Limit: the June run also had `auto` and `staged` strategies; today `virtualized` is the only viewport runtime type (`packages/plitejs/src/react/components/editable.tsx:45-50`).

## DOM coordinates over unmounted content

- Exact DOM resolution stays exact over virtualized content: `DOMEditor.resolveDOMPoint` and `resolveDOMRange` return `null` for a point or range with no mounted DOM (`packages/plitejs/src/dom/plugin/dom-editor.ts:189-190`, `:553-570`), and callers that must know what covers the gap use the editable DOM runtime's `domCoverage.resolveDOMPointOrBoundary` and `domCoverage.resolveDOMRangeOrBoundary`, which return the covering boundary instead (`packages/plitejs/src/dom/plugin/dom-coverage.ts:750-783`, tests in `packages/plitejs/test/dom/dom-coverage.ts`). Unlike CodeMirror, Plite has no public estimated-coordinate API; the 2026-06-12 research decided not to add one (`docs/plite/research/2026-06-12-huge-doc-architecture/README.md:99-128`).

## Virtualized selection endpoints

- The virtualizer's range extractor always keeps the top-level rows of both selection endpoints mounted, plus the selected and promoted top-level indexes, and leaves every other off-window row unmounted; during a native scrollbar drag it raises overscan to at least 96 rows (`packages/plitejs/src/react/virtualized/use-virtualized-root-plan.ts:22`, `:95-113`, `:133-176`). The 2026-06-12 decision, taken from CodeMirror's extra one-line viewports, retains endpoint rows rather than whole endpoint page units so the DOM budget holds; widen it only when a bug proves the larger DOM cost is needed (`docs/plite/research/2026-06-12-huge-doc-architecture/README.md:130-159`).

## Selection over partial DOM

- Plite keeps huge-document vertical selection native only where DOM coverage is reliable and projects it from the model where DOM is partial. ProseMirror can leave ordinary shifted vertical selection to the browser because its whole document is in the DOM; with virtualization the target line may be absent, so a native selection selects the wrong thing or nothing and brings back wrong targets and double highlighting. Pure native virtualized selection was rejected twice for this reason. Source: `docs/plite/research/2026-06-12-huge-doc-native-selection/README.md:7-14`, `:116-123`; `docs/plite/research/2026-06-12-huge-doc-architecture/README.md:1199-1200`. ProseMirror and Lexical stay behavioral and performance baselines for huge documents, not architecture targets for partial-DOM selection (`docs/plite/research/2026-06-12-huge-doc-architecture/README.md:1172-1176`).
