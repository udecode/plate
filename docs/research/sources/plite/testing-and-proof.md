# Plite: testing and proof

## Huge-document proof families

- Two first-party browser contract families cover huge documents on the `huge-document` route. `huge-document-virtualized-scroll-stability` asserts no row overlap during immediate scrollbar jumps, no gaps or overlaps after a settled repaint, mounted rows buffered during a native scrollbar drag before React commits the next range, and dynamic-height backward scroll staying near the requested offset. `huge-document-projected-vertical-selection` asserts monotonic focus under repeated Shift+ArrowDown, Shift+ArrowUp reversing the recent focus steps, view markers while native selected text stays empty, no double highlight and a hot-path budget. Code: `packages/test/src/proof/first-party-browser-contracts.ts:164-184`. The scroll family was promoted on 2026-06-12 from route-local Playwright tests so a supervisor can find it (`docs/plite/research/2026-06-12-huge-doc-architecture/README.md:36-38`).

## IME proof transports

- Synthetic composition helpers keep no active DOM composition text node before commit, so they cannot prove what happens when an edit mutates the DOM span inside an active composition; that class needs a helper that observes or mutates the real native composition span. The harness drives native composition through CDP `Input.imeSetComposition` and `Input.insertText` (`packages/test/src/playwright/ime.ts:312-319`) beside its synthetic composition events (`ime.ts:40-75`). Source: `docs/plite/research/2026-06-12-oss-input-selection-architecture/shards/001-input-selection-composition.md:38-42`, `lead-ledger.tsv:5`.

## IME and repair proof families

- First-party contract families name the IME, native-repair and external-paste proof (`packages/test/src/proof/first-party-browser-contracts.ts:185-262`): `ime-composition-formatted-boundaries` (composition inside formatted markup, active-mark cursor-wrapper composition, one replacement of several formatted text nodes, WebKit `compositionend` cleanup of an expanded rich-text selection), `ime-composition-cross-block-repair` (rapid consecutive compositions in separate blocks, cross-paragraph native composition replacing the range once, a synthetic transport that never mutates React-owned expanded DOM ranges, final selection after the committed text), `ime-composition-decoration-refresh` (prop and hook decoration sources refresh while a stepwise synthetic composition stays open, then model, DOM caret and text agree), `native-beforeinput-target-range-repair` (target ranges replace browser substitution spans, stale target ranges are rejected, native partial and mouse-drag replacements undo cleanly) and `external-clipboard-slice-context` (ProseMirror slices, comment-bounded fragments and external table HTML). They were named on 2026-06-12 from ProseMirror's composition, DOM-change and clipboard tests; overlap cancellation is deliberately absent (`EDIT-IME-OVERLAP-CANCEL-001`). Source: `docs/plite/research/2026-06-12-testing-oracles/README.md:31-57`.

## Browser harness primitives

- The browser harness `@platejs/test` (`packages/test/src/playwright/`) provides: selection snapshots of model selection, DOM selection, displayed native and view selection, selected text and caret rects, with a double-highlight flag (`displayed-selection.ts:181`); a clipboard layer with an exclusive cross-process file lock (`.editor-browser-clipboard.lock`, `clipboard.ts:10-15`), native clipboard read and write, synthetic event payloads and DataTransfer paste fallbacks; IME transports for Chromium CDP native composition (`ime.ts:312-319`), synthetic composition events, a coarse-pointer semantic `insertText` fallback (`ime.ts:213-217`) and direct insertion; and a scenario runner with trace snapshots, runtime-error checks, replay artifacts and reduction candidates (`scenario*.ts`). In June 2026 these primitives were already stronger than the ProseMirror and Tiptap test helpers read for comparison; the gap was naming contract families. Source: `docs/plite/research/2026-06-12-testing-oracles/sources/plite-browser-summary.md:10-24`, `README.md:18-24`.

## Native event trace

- Final-value assertions miss bugs where the model text ends right but the browser selection jumped, `beforeinput` targeted another node, the native composition moved or the DOM changed outside its owner. The harness records the event chain around an operation: `startBrowserNativeEventTrace`, `takeBrowserNativeEventTrace`, `resetBrowserNativeEventTrace` and `stopBrowserNativeEventTrace` (`packages/test/src/playwright/native-event-trace.ts:21`, `:490-521`) capture native `selectionchange`, `beforeinput`, `input` and composition events with the browser selection, `getTargetRanges()`, text-node snapshots, input-time DOM deltas, rects and named anomalies: `composition-mismatch`, `data-content-mismatch`, `inputtype-mismatch`, `missing-beforeinput`, `node-type-change`, `parent-mismatch`, `selection-jump` and `sibling-created` (`packages/test/src/playwright/types.ts:200-211`; test `packages/test/test/browser/native-event-trace.browser.test.ts`). The trace shape came from the `easylogic/contenteditable` playground on 2026-06-13; it validates browser event shape and Plite ownership, not OS candidate-window behavior. Source: `docs/plite/research/2026-06-13-contenteditable-event-trace-oracles/README.md:17-42`, `shards/001-event-trace-anomaly-oracles.md:3-49`.

## WPT invariant map

- WPT invariants that existing Plite proof covered on 2026-06-13: end-of-line image selection and delete map to image route rows (click-select then Backspace, Shift+ArrowRight into an image, vertical arrows into an image); character and line-boundary movement around non-editable spans, and paragraph movement across editing boundaries, map to content-root navigation contracts and editable-void, read-only-inline and synced-block route rows; target ranges fixed at dispatch map to the reconciler contract `beforeinput uses event target range instead of later live DOM selection`; `content-visibility: hidden` text staying out of native selection maps to hidden content staying out of native find until materialized, while model-backed copy includes it by policy; `Selection.deleteFromDocument()` maps to expanded-selection deletion over formatted leaves and top-level blocks, browser Backspace and Delete over a selected range, caret editability and undo; anchor-node removal maps to the detached-endpoint contract; triple-click directionless selection maps to triple-click rows over links and read-only inlines; and horizontal ArrowUp and ArrowDown caret position maps to richtext, image and code-block vertical rows. CSS generated content in `Selection.modify('word')` is out of scope, since Plite never renders model text through pseudo-elements. Source: `docs/plite/research/2026-06-13-wpt-editing-oracles/lead-ledger.tsv:30-39`. Limit: the map names behaviors, not current lines; the June tests moved to `apps/plite/tests/plite-browser/donor/examples/`.

- More WPT mappings from 2026-06-13: a click still moves the caret in an editable root under `user-select: auto | text | none | contain | all` (`apps/plite/tests/plite-browser/donor/examples/plaintext.test.ts:242`); placeholder text never enters native or model selected text (`apps/plite/tests/plite-browser/donor/examples/placeholder.test.ts:49`); forward Delete and `deleteWordForward` target ranges apply exactly over graphemes, preserved spaces and word whitespace; content-delete inputTypes over an expanded selection delete the selected fragment whatever exact `inputType` label the browser reports; contenteditable paste has `event.data === null`; an empty editor with a custom placeholder still focuses one collapsed caret through zero-width line-break rendering; inline and range deletion stay correct while browser `selectionchange` after the delete is imported or repaired, without asserting browser event counts; and native selection inside a shadow root is covered by shadow-DOM caret, model-owned movement and RTL delete rows. Out of scope, as browser API behavior Plite does not own: arbitrary `user-select: none` drag islands, DOM ranges inside empty elements (model points target text leaves), `Selection.collapse()` focus transfer across arbitrary hosts, `selectionchange` task scheduling and the raw `Selection.extend()` matrix. Vertical `writing-mode` caret movement and mixed-bidi `lineboundary` extension stay unclaimed until an accepted plan (`docs/vision/plite.md:676`). Source: `docs/plite/research/2026-06-13-wpt-editing-oracles/lead-ledger.tsv:40-54`.

## Browser matrix versus raw-device proof

- **Two proof lanes.** Plite keeps desktop browser-matrix proof apart from raw-device receipts. `pnpm check:plite:browser-matrix` (package.json:47) runs the Playwright projects in `apps/plite/playwright.config.ts`: Chromium, Firefox and WebKit desktops plus `mobile` (Pixel 5) and `mobile-webkit` (iPhone 13) emulation. `test:mobile-device-proof:raw` (package.json:126) sets `PLITE_BROWSER_RAW_MOBILE_REQUIRED=1` and requires an Appium receipt from Android Chrome and from iOS Safari for each of the 16 scenarios in `packages/test/src/proof/raw-mobile-proof.ts:7-24`. Neither an emulated mobile project nor a donor's touch-capable desktop context, as in Meowdown or ProseKit, stands in for a raw iOS receipt, and an engine skip should name exactly what that engine cannot synthesize. Evidence: `docs/editor-test-harvester/meowdown/report.md:162, 198-199, 213-214`; scripts and configuration read on 2026-10-08.
