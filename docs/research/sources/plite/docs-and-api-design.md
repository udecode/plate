# Plite: docs and API design

## Multi-editor focus and view registration

- The 2026-09-08 multi-editor focus review reproduced four defects with several Plate editors on one page: a surviving view's registration was lost when a sibling unmounted, last-focus reads lost the exact view through a toolbar blur, contextual target lookup was ambiguous, and duplicate editor ids went unchecked. Its second plan review rejected a new public View abstraction and kept ordinary contextual toolbars, private exact-mount registration and the existing root and view command owners; it deferred `useActiveEditorView`, nearest-only hook semantics and removing initial or default target behavior, and rejected an id-as-mount-identity registry, threading an editor, root and ref bundle through every toolbar control, and restoring `EventEditorPlugin`. The invariant: a private registration preserves the chosen mount's current command, read-only and focus facts, and an interaction never silently retargets after its mount is removed. Today `CommentsPlugin` and `AIChatPlugin` act on the exact mounted view (`packages/platejs/src/react/features/comments/CommentsPlugin.ts:5`, `packages/platejs/src/ai/react/AIChatPlugin.focus.spec.tsx:64`). Source: `docs/editor-audits/reports/multi-editor-focus-api-review-2026-09-08.md:16-43`. Limit: the defects were reproduced by JSDOM probes (23 focus and controller tests, 13 DOM runtime tests, three probes), not browser certification, and the target was provisional pending an integration probe and benchmark.

## Diagnostics

- Plite's diagnostic value formatter replaces every `text` string with `[text length N]` by default, so structural error messages carry no user document text (`defaultDebugValueScrubber`, `packages/plitejs/src/utils/format-debug-value.ts:6-12`); an app can install its own scrubber with `setDebugValueScrubber` (`:15-19`). ProseMirror #1330 (a `RangeError` whose message included user content) prompted it. Proof: `packages/plitejs/test/format-debug-value-contract.ts:41` ('keeps user text out of structural error messages by default'). Source: `c70bacbd4a:docs/editor-issue-harvester/prosemirror/full/checkpoints/issues-1330-1370.md:16`, `:25`.

## Editor value types

- **Editor types are per editor, not one global merge.** Plate v11 (#1500, building on ianstormtaylor/slate#4177) replaced Slate's declaration merging with an editor value generic because one globally merged type cannot tell a known element from an unknown one and cannot describe two editors with different schemas on one page. Plite keeps that direction: schema plugins are the first-party AST-shape truth, Plate infers `Editor` through creation and derives node types with `ValueOf`, `ElementOf` and `TextOf`, and only raw schema-less Plite may still pass an explicit `createEditor<ExternalValue>` generic (`docs/vision/plite.md:110-117`). The Slate home records the same pressure from Slate's global `CustomTypes` augmentation and finds none in Plite (`docs/research/sources/slate/issues-and-regressions.md`, 'Editor types from installed plugins, not global augmentation'). Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/plite/reference/history/migration/v48.mdx:2886-2892`.

## April 2026 architecture contract

- **Where Plite reversed the April 2026 Slate v2 architecture contract.** The contract was written for the fork's draft repository, where 'Plite' meant the draft and 'legacy Plite' meant Slate, and ranked its principles data-model-first, operation- and collaboration-friendly, transaction-first engine, React-optimized runtime, adapters later (`c70bacbd4a:docs/plite-draft/references/architecture-contract.md:144-160`). Its immutable-snapshot, private-draft and runtime-identity invariants hold today as Vision law (`docs/vision/plite.md:439`, `:625-648`). Seven positions were reversed. (1) It called a native transaction engine with phased plugin middleware a good v2 idea but a bad move for the rewrite, and kept `editor.apply(op)` plus `Editor.withBatch` and `Transforms.applyBatch` (`architecture-contract.md:606-633`, `:690-703`); the public lifecycle is now `editor.read`, `editor.update` and `tx` (`docs/vision/plite.md:242-244`), and `packages/plitejs/src` has no `editor.apply(` call and no `withBatch`, `applyBatch` or `withTransaction` as a word (git grep, 2026-10-08). (2) 'Operations stay first-class externally' (`architecture-contract.md:776`) gave way to `DocumentChange`: an `EditorCommit` carries `changes` and `inverseChanges` (`packages/plitejs/src/interfaces/editor.ts:3572-3590`). (3) It kept separate `slate`, `plite-dom`, `plite-react` and `plite-history` packages, and the April blocker note kept collaboration adapters external by design (`c70bacbd4a:docs/plite-draft/archive/full-replacement-blockers.md:65`); all of them, Yjs included, are now subpath entrypoints of one `plitejs` package (`packages/plitejs/package.json:33-110`). (4) Its naming rule kept legacy `Editor.*`, `Transforms.*` and `HistoryEditor.*` names wherever semantics matched (`c70bacbd4a:docs/plite-draft/archive/package-end-state-roadmap.md:269-294`); Vision now says not to keep legacy APIs for familiarity (`docs/vision/plite.md:59`). (5) Pagination and measurement were to stay out of core (`c70bacbd4a:docs/plite-draft/archive/final-synthesis.md:75-76`); `plitejs/pagination` and `plitejs/pagination/react` now ship, with `@chenglou/pretext` as an optional peer (`packages/plitejs/package.json:64-73`, `:213`, `:221-223`). (6) Plugin-defined state and update tags were deferred as wrong timing (`package-end-state-roadmap.md:953-976`); plugins now declare `stateFields` and `effectTypes` (`docs/vision/plite.md:396-398`), and update policy carries ordered tags (`:430-431`). (7) `useEffectEvent` as the standard tool for effect-owned event reactions (`architecture-contract.md:1409`) appears nowhere in `packages/plitejs/src` or `packages/platejs/src` (git grep, 2026-10-08), and the first-class `<Activity>` role for hidden UI (`:1410`) gave way to Vision's rejection of Activity hidden mode for hidden editable content (`docs/vision/plite.md:743-748`). Limit: the draft-repository paths these documents cite are gone.

## Entrypoints and peer dependencies

- **One `plitejs` package with subpath entrypoints, every peer optional.** `plitejs` exports `.`, `./dom`, `./react`, `./react/virtualized`, `./history`, `./hyperscript`, `./authored`, `./annotations`, `./diff`, `./pagination`, `./pagination/react`, `./yjs`, `./yjs/react`, `./testing` and `./internal` (`packages/plitejs/package.json` exports, read 2026-10-08). `./internal` is reserved for sibling packages in this repository (`c70bacbd4a:docs/plite/reference/public-docs/libraries/plite-dom.mdx:228-232`) and holds framework hooks with no author job (`docs/vision/plite.md:84-85`). All of its peers are optional: `react` and `react-dom` (>=19.2), `@tanstack/react-virtual`, `@chenglou/pretext`, `diff-match-patch-ts` and `yjs`. Its runtime dependencies are `@noble/hashes`, `csstype`, `lodash` and `scroll-into-view-if-needed`. Only `plitejs/diff` and the Yjs replacement path import `diff-match-patch-ts` (`packages/plitejs/src/diff/lib/comparison-matcher.ts:1`, `packages/plitejs/src/yjs/core/replacement.ts:1`). `@platejs/test` is a separate distribution for tests and proof harnesses. The retired overview listed seven `plitejs` entrypoints and the 2026 architecture contract six (it omits `hyperscript`); the current exports add `authored`, `annotations`, `diff`, `testing`, `react/virtualized`, `pagination/react` and `yjs/react`. Source: `c70bacbd4a:docs/plite/reference/public-docs/index.mdx:18-34`, `:119-130`; `c70bacbd4a:docs/plite/references/architecture-contract.md:193-207`; checked 2026-10-08.

## Helper namespaces

- **Pure helper namespaces are frozen.** `ElementApi`, `LocationApi`, `NodeApi`, `PathApi`, `PointApi`, `RangeApi`, `SelectionApi`, `SpanApi` and `TextApi` are each built with `Object.freeze` (`packages/plitejs/src/interfaces/element.ts:139`, `location.ts:48` and `:88`, `node.ts:621`, `path.ts:142`, `point.ts:48`, `range.ts:102`, `selection.ts:158`, `text.ts:155`), so the Slate habit of patching a static helper throws in module code. Custom helpers wrap or compose them, and editor-dependent behavior goes through plugins. Inside an editor, one-shot `editor.read.<group>.<method>()` and `editor.update.<group>.<method>()` calls take the helpers' place; the helpers serve pure operations on Plite data outside a transaction. Source: `c70bacbd4a:docs/plite/reference/public-docs/libraries/plite.mdx:180-193`; code read 2026-10-08.

## Slate 0.x names in Plite

- **Where Slate 0.x names went (checked against current exports).** `createEditor()` plus `withReact` becomes `useEditor({ initialValue, plugins })` or `createEditor` from `plitejs/react`, which installs `react({ dom: dom() })` before custom plugins. `withHistory` becomes an explicit `history()` plugin. `<Slate editor initialValue>` becomes `<EditorRoot editor>`, because the editor seeds its own value. `Transforms.*` and `Editor.*` calls become `editor.update.<group>.<method>()` and `editor.read.<group>.<method>()`, or grouped `tx` and `state` callbacks. Pure node, path, point, range and text helpers become `NodeApi`, `PathApi`, `PointApi`, `RangeApi`, `TextApi` and `ElementApi`. `ReactEditor.*` becomes `editor.api.dom.*` and `editor.api.react.*`, for example `resolvePath`, `focus` and `isComposing`. Hooks: `useSlate` and `useSlateStatic` become `useEditorContext()`; `useSlateSelector` becomes `useEditorState` or `useEditorSelector`; `useSlateSelection` becomes `useEditorSelection`; `useSelected`, `useFocused` and `useReadOnly` become `useElementSelected`, `useEditorFocused` and `useEditorReadOnly`. `onChange(value)` becomes `onValueChange` on `EditorRoot`, or `editor.read.value()` for a multi-root document. `decorate` becomes a keyed decoration source passed to `<EditorRoot decorations>`. Checked on 2026-10-08 in `packages/plitejs/src/react/index.ts` (`EditorRoot` `:61`, `useEditor` `:136`, `useEditorHistory`, `useRootChrome`, `useRootEditor`), `packages/plitejs/src/react/components/plite.tsx:131` (`onValueChange`) and `packages/plitejs/src/react/plugin/with-react.ts:185-189`. The retired guide's `<Plite>`, `usePliteHistory`, `usePliteRootChrome`, `usePliteRootEditor` and `Plite*` render primitives no longer exist; their current names are `EditorRoot`, `useEditorHistory`, `useRootChrome`, `useRootEditor` and `EditorElement`, `EditorText`, `EditorLeaf` and `EditorPlaceholder`. Source: `c70bacbd4a:docs/plite/reference/public-docs/migration.mdx:68-83`, `:354-365`. Its 'Slate 0.x' column was rename-damaged (`<Plite>`, `usePlite`) and is restored here to Slate's own names. Limit: names only; per-hook behavior was not compared. Public migration docs for Plate users are `content/docs/migration/plite-to-plate.mdx`.

## Why the core was rebuilt

- **Why the fork rebuilt the core instead of only the React layer.** The first design kept upstream Slate core intact and rewrote only slate-react, hoping that extra roots, document metadata, overlays and React performance could come from the renderer alone. It failed because a renderer cannot own write boundaries, selection authority, canonical changes, dirty regions, stable node identity, history grouping, collaboration metadata or DOM repair. An adapter that tried would become a hidden second runtime translating between mutable editor fields, React subscriptions, native selection, history and collaboration. The page gave these cases: Shift+Down in a huge document needs one selection target, one DOM import and export path and one dirty-render plan; Cmd+A then Delete needs one transaction that owns the deletion, selection collapse, history grouping, change output, DOM repair and follow-up typing; extra regions and document metadata must serialize with the document, or history, collaboration and persistence grow side channels; durable comments and transient search hits share node identity and change facts but need separate owners; and browser proof needs one commit that model, DOM, native selection, focus and replay can all inspect. The fork kept Slate's JSON nodes, paths, points, ranges and app-owned schema, and made `DocumentChange` the one source of truth for mutation, mapping, history and replay. It took Lexical as the reference for read/update discipline and dirty reconciliation, and ProseMirror for transaction authority and DOM-selection import and export. Source: `c70bacbd4a:docs/plite/reference/public-docs/why-this-fork.mdx:41-60` (retired public page, undated), where the rename turned slate-react into 'plite-react'. Limit: recorded rationale, not a measured result; the current law is `docs/vision/plite.md:26-28`.
