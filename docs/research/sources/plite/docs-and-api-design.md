# Plite: docs and api design

## Multi-editor focus and view registration

- The 2026-09-08 multi-editor focus review reproduced four defects with several Plate editors on one page: a surviving view's registration was lost when a sibling unmounted, last-focus reads lost the exact view through a toolbar blur, contextual target lookup was ambiguous, and duplicate editor ids went unchecked. Its second plan review rejected a new public View abstraction and kept ordinary contextual toolbars, private exact-mount registration and the existing root and view command owners; it deferred `useActiveEditorView`, nearest-only hook semantics and removing initial or default target behavior, and rejected an id-as-mount-identity registry, threading an editor, root and ref bundle through every toolbar control, and restoring `EventEditorPlugin`. The invariant: a private registration preserves the chosen mount's current command, read-only and focus facts, and an interaction never silently retargets after its mount is removed. Today `CommentsPlugin` and `AIChatPlugin` act on the exact mounted view (`packages/platejs/src/react/features/comments/CommentsPlugin.ts:5`, `packages/platejs/src/ai/react/AIChatPlugin.focus.spec.tsx:64`). Source: `docs/editor-audits/reports/multi-editor-focus-api-review-2026-09-08.md:16-43`. Limit: the defects were reproduced by JSDOM probes (23 focus and controller tests, 13 DOM runtime tests, three probes), not browser certification, and the target was provisional pending an integration probe and benchmark.
