## Presence metadata

- **Cursor metadata is validated at both ends.** `yjs({ cursorData: { validate } })` gives collaborator metadata one runtime type predicate. The installed plugin carries the validated type through `api.yjs` and the React hooks, with no caller-chosen generic (`packages/plitejs/src/yjs/core/types.ts:61-63`, `packages/plitejs/src/yjs/react/useYjs.types.spec.ts:29`). ## Room schema identity

- **A Yjs room records one schema identity, and a mismatched editor cannot join.** The binding stores the compiled schema identity of the primary and named roots as room metadata. `assertYjsSchemaIdentity` compares the kind first. A derived schema matches only an equal fingerprint. A named schema must match id, version and fingerprint; a changed fingerprint at the same version fails with '…semantics changed without a version bump' (`packages/plitejs/src/yjs/core/schema-metadata.ts:110-150`). A nonempty Yjs document without schema metadata is refused ('Cannot import a nonempty Yjs document without schema metadata.', `packages/plitejs/src/yjs/core/controller.ts:861`), and so is reconfiguring the schema over such content (`:745`). An empty room is claimed only after readiness, with its identity written in the same step as the seeded content. Tests: 'rejects nonempty documents that never claimed schema metadata', 'claims an empty room and seeds content atomically after readiness', 'blocks a room schema mismatch before content import', 'diagnoses changed semantics without a schema version bump' and 'rejects local schema reconfiguration against a claimed room' (`packages/plitejs/test/yjs/schema-identity-contract.spec.ts:241`, `:378`, `:419`, `:475`, `:531`). So a schema change for a populated room is a versioned document migration before peers join, never an in-place reconfiguration. Source: `c70bacbd4a:docs/plite/reference/public-docs/libraries/plite-yjs.mdx:169-183`; code read 2026-10-08, tests not run.

## Named roots in a room

- **One room holds every root.** `rootName` names the whole collaboration document. Primary children live at `rootName`, and named roots live in the `${rootName}:roots` Y.Map (`packages/plitejs/src/yjs/core/controller.ts:241`). A named root synchronizes with no root view mounted ('synchronizes an offscreen named root without mounting a root view', `packages/plitejs/test/yjs/multi-root-contract.spec.ts:153`), and owner and child-root changes publish and undo atomically (`:180`). An awareness selection whose anchor and focus name different roots is dropped (`sanitizeYjsSelection`, `packages/plitejs/src/yjs/core/awareness-adapter.ts:225-230`). Source: `c70bacbd4a:docs/plite/reference/public-docs/libraries/plite-yjs.mdx:185-216`; code read 2026-10-08. ## Shared effects and log compaction

- **Shared effects declare how late joiners replay them, and one authority compacts the log.** A shared effect must declare `collabReplay: 'live'` (delivered once to active peers) or `'latest'` (an absolute, idempotent value); a local effect may only be `'live'`. `'latest'` requires a `collabSnapshot(state)` function, and every other policy forbids one; a violation throws at registration (`packages/plitejs/src/core/plugin-registry.ts:776-800`). Shared state fields get `'latest'` automatically, with a snapshot of the field's current value (`packages/plitejs/src/core/state-field.ts:133-134`). `yjs({ sharedEffectCompaction: { authorityId, threshold } })` names one stable compaction authority per document (`packages/plitejs/src/yjs/core/shared-effect-log.ts:71-78`, `:157-166`). The compaction contract pins this behavior: it checkpoints absolute state and expires acknowledged live events; it captures custom latest effects instead of replaying their last event; it resumes one stable authority across Y.Doc client generations; it targets live effects only to active peers and keeps their retry across reconnect; it lets the authority retire one crashed peer generation (`api.yjs.retireSharedEffectPeer`) without replaying its live tail; and it never checkpoints a non-contiguous source sequence (`packages/plitejs/test/yjs/shared-effect-compaction-contract.spec.ts:35`, `:193`, `:446`, `:622`, `:737`, `:889`). So a `'live'` effect must never be the only carrier of durable shared state. Source: `c70bacbd4a:docs/plite/reference/public-docs/libraries/plite-yjs.mdx:218-295`; code read 2026-10-08, tests not run.

## Remote import and outbound lowering

- **Remote Yjs events import as a ranged change, with a traced full fallback.** The binding translates a remote Yjs event batch against its synchronized mirror into a root-scoped `DocumentChange` and applies it as one remote update, recording `importKind: 'event-change'` with `changedRanges` and `readTopLevelNodes` in its trace (`importYjsEvents`, `packages/plitejs/src/yjs/core/controller.ts:1419-1460`). When the translation falls back, for projected content, root attributes, an invalid delta, a mirror mismatch, an empty root, a failed read or an unknown target, it reimports through a full diff traced as `full-diff-fallback` with that reason (`:1438-1446`; `YjsTraceFallback`, `packages/plitejs/src/yjs/core/types.ts:105-114`). Local commits go out through the canonical change, with their own `canonical-change-*` fallbacks (`types.ts:103-121`). Tests: 'keeps an untouched projected sibling on the sparse event path' asserts one changed range and one read top-level node for a remote insert (`packages/plitejs/test/yjs/move-node-contract.spec.ts:202`), and 'transports registered domain effects exactly once' (`packages/plitejs/test/yjs/remote-import-contract.slow.ts:139`). In June 2026 the remote import path was still a full read and replace (`docs/plite/research/2026-06-14-yjs-large-doc-import-readback/README.md:146`). Source: `c70bacbd4a:docs/plite/reference/public-docs/libraries/plite-yjs.mdx:297-310`; code read 2026-10-08, tests not run. Limit: the trace is package-private diagnostics, and outbound region lowering was read at the type level only.

## Presence across provider reconnects

- **The host re-publishes presence around provider reconnects.** The presence API on `api.yjs` (`setCursorData`, `clearSelection`, `syncSelection`, `remoteCursor`, `remoteCursors`, `subscribeRemoteCursors`) is per mounted view (`packages/plitejs/src/yjs/core/plugin.ts:60-73`, `packages/plitejs/src/yjs/core/types.ts:87-96`) and exists only when awareness is supplied (`docs/vision/plite.md:278-279`). ## Offline structural edits and undo

- **Offline structural edits converge with concurrent remote text, and undo reverses only the local edit.** The Yjs package contracts reconnect an offline peer against a connected one. An offline split of `alphabeta` at `alph|abeta` with a remote `!` at the split point gives `['alph!', 'abeta']` on every peer; undo gives `['alph!abeta']` and redo restores the split (`packages/plitejs/test/yjs/split-node-contract.spec.ts:230`, `:320`). A remote `!` appended at the end of the unsplit paragraph also lands at the end of the left half, `['alph!', 'abeta']` (`:401`), which fits the split keeping the original container as the left half (`:99`); in May 2026 Potion likewise put a remote insert made after the split point at the end of the left half. An offline merge of `alpha` / `beta` with a remote `!` after `alpha` converges to `alpha!beta`, and undo gives `['alpha!', 'beta']` (`merge-node-contract.spec.ts:69`, `:97`). An offline move of `alpha` to the end with a remote `!` in it converges to `['beta', 'gamma', 'alpha!']`, and undo puts `alpha!` first again (`move-node-contract.spec.ts:118`, `:152`). An offline wrap keeps the remote `!` inside the quote (`wrap-nodes-contract.spec.ts:76`), and an offline fragment insert with a remote append converges to `alpha AdaLin fragment` (`insert-fragment-contract.spec.ts:102`). The May 2026 donor reached these outcomes case by case against Potion, Plate's production collaborative editor; in one of its cases, an offline move down, Potion itself dropped the concurrent insert. Source: `c70bacbd4a:docs/transplant/slate-v2/archive/docs/plans/2026-05-26-yjs-potion-differential-fixes.md:8-37`, `c70bacbd4a:docs/transplant/slate-v2/archive/docs/plans/2026-05-28-yjs-potion-parity-regressions.md:47-54`, `c70bacbd4a:docs/transplant/slate-v2/archive/docs/plans/2026-05-26-yjs-potion-differential-bug-hunt.md:30-38`; tests run 2026-10-08, all pass. ## Presence

- **Open lead: an awareness writer that skips equal payloads needs a reset when the provider disconnects.** On 2026-06-13 a real Hocuspocus room showed the bug: after peer A went offline and came back, selecting the same place again left every other peer showing A's cursor selection as `null`, because A's local awareness selection still equaled the payload sent before the disconnect, so the write was skipped while the remote peers had dropped A's state. ## Yjs shared-type identity

- **One Plite text leaf can span adjacent Yjs text containers.** Plite does not fold one `Y.XmlText` into another when the model joins two text leaves, so a concurrent remote insert stays attached to its own container: after an offline merge of the leaves `alpha` and `beta`, a remote `!` after `alpha` reaches every peer as `alpha!beta` (`packages/plitejs/test/yjs/merge-node-contract.spec.ts:116`). The raw reader maps each `Y.XmlText` to its own text node (`readPliteNodeFromYjsWithResolver`, `packages/plitejs/src/yjs/core/document.ts:1327-1341`), and the editor value joins adjacent containers with equal properties into one leaf: a paragraph whose Yjs children are the containers `al` and `pha` reads as `alpha`, and a split at offset 3 lowers through the physical container boundary to `alp` / `ha` (`packages/plitejs/test/yjs/split-node-contract.spec.ts:135`). The split walks only contiguous containers whose text properties match (`packages/plitejs/src/yjs/core/canonical-split.ts:320-354`), so it never crosses into a leaf with other marks (`split-node-contract.spec.ts:164`). The May 2026 donor reached the same split between stored containers and canonical leaves after a canonical read sent operation replay to a snapshot fallback and turned an offline merge undo into `alpha` / `!beta`. Source: `c70bacbd4a:docs/transplant/slate-v2/archive/docs/solutions/logic-errors/yjs-merge-read-virtual-text-leaves-2026-05-27.md:22-107`, `c70bacbd4a:docs/transplant/slate-v2/archive/docs/plans/2026-05-27-yjs-merge-node-canonical-late-peer.md:18-34`; tests run 2026-10-08, all pass. Limit: `merge-node-contract.spec.ts:116` compares block text, not leaves, and no contract asserts the leaves a late-joining peer reads after a text merge.

- **The Yjs binding keeps original shared types alive and reads them through visible slots.** Concurrent remote text survives a structural edit only if the edit keeps the `Y.XmlText` or `Y.XmlElement` the remote peer is editing, so Plite's binding does not clone and hide a moved subtree. `setVirtualYjsMove` hides the source with `plite:yjs-hidden` and points a wrapper at it through `plite:yjs-virtual-child-id`; `createVirtualYjsMovePlaceholder` creates a `plite-yjs-virtual-placeholder` element for the destination that resolves to the hidden source; `setVirtualYjsUnwrapMove` restores the source and hides the emptied wrapper (`packages/plitejs/src/yjs/core/document.ts:39-43`, `:1812-1913`). Because hidden nodes and placeholders sit among raw children, raw Yjs indexes and visible Plite indexes are two coordinate systems: a virtual wrapper lists its referenced source first and then raw visible siblings such as a split's right half, and insertion and removal go through `insertYjsChild` and `removeYjsChild`, which resolve visible slots (`:473-545`, `:1839-1882`, `:1965-2040`). A split keeps the left text node's identity ('applies a local offline public split as a canonical change', `packages/plitejs/test/yjs/split-node-contract.spec.ts:99`), a relocated node keeps its identity under later edits without a snapshot fallback (`packages/plitejs/test/yjs/move-node-contract.spec.ts:137`), and redundant empty text nodes are removed (`removeRedundantEmptyYjsTextNodes`, `document.ts:1171`). The May 2026 donor found each rule by losing data: a wrap clone dropped a remote `!`, a raw-index split insert threw `Length exceeded!`, and a raw-index split undo deleted a hidden merge source instead of the visible right block. Source: `c70bacbd4a:docs/transplant/slate-v2/archive/docs/solutions/logic-errors/yjs-structural-wrap-fragment-parity-2026-05-28.md:24-127`, `c70bacbd4a:docs/transplant/slate-v2/archive/docs/solutions/logic-errors/yjs-forward-move-history-fallback-2026-05-26.md:35-53`; code read 2026-10-08. Limit: the notes' operation-level fallback traces (`virtual-move-ref`, `virtual-unwrap-ref`) and `slate:` attribute names are gone; today's bridge encodes canonical changes.

## Text attributes

- **Read Yjs text from delta inserts, never from `toString()`.** `Y.XmlText.toString()` serializes formatting as XML-like tags, so formatted text imported through it reads as markup; plain text comes from joining the string inserts of `toDelta()`. Plite reads text that way in `getYjsTextContent` and reads text attributes from the delta, kept when uniform across parts and empty when they differ (`packages/plitejs/src/yjs/core/document.ts:216-240`, `:1260-1298`). Yjs deltas omit a `null`-valued attribute, so Plite also keeps text properties as node attributes and copies them into the read text (`:1327-1341`); 'preserves null-valued text attributes through readback' and 'preserves attributes on empty Yjs text nodes' pin both (`packages/plitejs/test/yjs/attributes-contract.spec.ts:87`, `:68`). Source: `c70bacbd4a:docs/transplant/slate-v2/archive/docs/solutions/logic-errors/yjs-text-leaf-metadata-delta-sync-2026-05-26.md:41-42`, `:89-101`; code read 2026-10-08. Limit: the note's `slate:text-leaves` metadata, which split one `Y.XmlText` into several leaves, is gone; Plite reads each `Y.XmlText` as one text node.

## Authored changes over Yjs

- **Authored changes travel as a shared effect, and concurrent review decisions stay conflicted.** The `authored` plugin records each authored operation batch as the shared effect `authored.operation` (`collab: 'shared'`, `collabReplay: 'latest'`, history skipped), whose `collabSnapshot` is a checkpoint of the accepted document, the accepted positions and the authored state (`packages/plitejs/src/authored/state.ts:1656-1679`), so the Yjs binding carries it through the shared-effect log like any other shared effect. The Yjs contracts pin what peers see. When one peer accepts a pending change and the other rejects it concurrently, both end with the change `conflicted`, the accepted document unchanged (`Base`) and the proposed view still holding the insert (`Baseq`), also after a reload from the saved value ('keeps concurrent opposite decisions conflicted on both peers', `packages/plitejs/test/yjs/authored-contract.spec.ts:1468`). Proposals made on two disconnected peers merge, with both pending on each peer ('merges independent proposals from disconnected peers', `:1438`). An offline peer's proposal survives a newer compacted checkpoint, even after the compacting peer retired that peer's generation ('keeps an offline contribution when receiving a newer compacted checkpoint', `:1274`). A peer's local undo and redo replay in the other peer's proposed view without entering that peer's history ('replays a peer local undo and redo without recording remote history', `:1424`). The four tests passed on 2026-10-08. `docs/research/decisions/authored-change-ownership.md:113-114` says only that collaboration snapshots keep the existing atomic shared-effect owner. Limit: the source also says duplicate delivery is idempotent and that malformed identities, missing checkpoints and document mismatches fail without publishing partial content; no test was matched to those claims. Source: `c70bacbd4a:docs/plite/reference/public-docs/libraries/plite-yjs.mdx:137-167`; code and tests read 2026-10-08.
