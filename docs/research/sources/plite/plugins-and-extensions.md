# Plite: plugins and extensions

## Read middleware

- **Read middleware nests in plugin order, delegates at most once and stays a pure read.** A plugin's `readMiddleware` wraps a declared `editorReads` descriptor with `around`. Handlers nest in plugin order, the first installed outermost: two handlers log `first:before`, `second`, `first:after` (`packages/plitejs/test/read-middleware-contract.test.ts:25`, export projections at `:98`). `next()` may take a replacement input and may run at most once; a second call throws "handlers may delegate only once" (`packages/plitejs/src/core/read-registry.ts:201-213`, test `:191`). A handler that skips `next()` decides the result, such as `false` to veto a schema-selectable node (`:64`), and an explicit `undefined` stands (`:215`). The handler runs inside the read boundary, so starting `editor.update` there throws, even from a lazy generator's cleanup (`:80`, `:281`), and during a command its `state` sees the transaction draft (`:240`). Two read descriptors with the same id cannot both install (`:167`). The public docs name the slot and none of these rules (`content/docs/api/core/plate-plugin.mdx:483-484`); `docs/vision/plite.md:387` says only that core-read policy composes through `readMiddleware`.
