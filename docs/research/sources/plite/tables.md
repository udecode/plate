# Plite: tables

## Rejected designs

- The 2026-09-17 table review rejected, each with a reopen condition: a core table engine in Plite, because spans, clipboard tiling, merge policy and width redistribution are feature semantics and the raw Plite tables example (apps/www/src/app/(app)/examples/plite/_examples/tables.tsx) is a minimal containment demo with its own schema, not a second engine consumer; a parallel table selection store; a custom selection protocol justified only by ProseMirror's or Lexical's extensibility; the naive React paint sink; generic box resize for table boundaries; an unmeasured grid rewrite or new public grid package; width units without a responsive or import job; and replacing the table tree with a spreadsheet model while rich nested cell content, codec dispatch, static rendering and complete slices are current jobs (docs/plite/research/2026-09-17-table-substrate-ownership/rejected-ledger.tsv:2-8; REPORT.md:201-216).

## Ownership

- Table work splits across three owners. Plite owns document identity, roots, canonical selection and its mapping, transactions, history, and generic mounted-host lifecycle and geometry. The Plate table feature owns span-aware topology, logical selection and navigation, edit and transfer policy, and width and height calculation and persistence; its React adapter turns events and measured geometry into those operations. Copied UI owns appearance, menus, which controls appear, and whether a resize previews live widths or a guide line (docs/plite/research/2026-09-17-table-substrate-ownership/REPORT.md:24-33). The 2026-09-17 review found no job for a second selection store or a public `TableController`, `GridManager`, `ResizeManager` or table package.

## Selection

- Plate has no headless command that builds or extends a table selection. Public table reads return a compact `TableSelection` (packages/platejs/src/features/table/lib/BaseTablePlugin.ts:1358), logical Shift+arrow extension and Select All stay private to the React plugin (packages/platejs/src/react/features/table/TablePlugin.tsx:212,554-627), and the copied row handle's Select row action reads the row's range and calls `editor.update.selection.set` (apps/www/src/registry/components/editor/table.tsx:853-860), all checked 2026-10-08. The 2026-09-17 review proposed headless `select` commands on the table plugin taking canonical targets with a cell, row or column unit, rejecting cross-table or cross-root endpoints and computing span closure once, so mouse, keyboard, handles and programmatic callers share one implementation while DOM caret-edge measurement stays in the mounted adapter (docs/plite/research/2026-09-17-table-substrate-ownership/REPORT.md:67-100); it was not built. Milkdown's controls already call headless row and column selection commands.

- A Plate table selection is Plite's directional `NodeSelection` of exact cells: Plite maps each selected path through edits and drops deleted ones (`mapSelectionWithContext`, packages/plitejs/src/core/selection-protocol.ts:760-822, checked 2026-10-08), and the table feature derives its projection and intercepts table-sensitive generic commands. ProseMirror's `CellSelection` instead recomputes from its endpoints and keeps whole-row or whole-column extent when cells are inserted (ProseMirror/prosemirror-tables@eb522f25959a1e4515a4ff5ce7e3a939f19c55e9:src/cellselection.ts). These are different semantics, not a Plite bug; the 2026-09-17 review keeps exact membership for node selection and defers any enduring rectangle or whole-column intent until a product contract needs it through remote structural edits, without hiding it in React or widening every node selection (docs/plite/research/2026-09-17-table-substrate-ownership/REPORT.md:102-116; lead-ledger.tsv:6).

## Resize controls

- The copied table UI mounts a wrapper and two pointer-only resize handles, right edge and bottom edge, in every editable cell (`TableCellResizeControls`, apps/www/src/registry/components/editor/table.tsx:947-1020, checked 2026-10-08), so an unmerged 50×40 table declares 2,000 wrappers and 4,000 handle elements; that is a count from source, not a measured cost. The handles have no keyboard, focus or ARIA contract. On 2026-09-17 the cells also rendered first-column left handles, 4,050 handles in all, gated on the ending column index so a first cell spanning several columns lost its left handle (docs/plite/research/2026-09-17-table-substrate-ownership/REPORT.md:118-127); current source renders no left handle. The review proposed a table-scoped active-boundary overlay resolved through the topology owner, plus keyboard size controls that add no thousands of tab stops; ProseMirror uses active-column decorations and Lexical a shared active-cell resizer (REPORT.md:129-141). Not built as of 2026-10-08.

- Table resizing splits preview from commit. `api.createResize` computes constrained deltas without editing; `useTableResize` owns the exact table, owner window and pointer through the private `bindPointerSession`, which media resizing also uses; `update.resize` commits once at pointer end when the delta is nonzero; copied UI picks a live or guide-line preview (packages/platejs/src/react/features/table/useTableResize.ts:84-125; packages/platejs/src/react/utils/bindPointerSession.internal.ts; packages/platejs/src/react/features/resizable/Resizable.tsx). The session stays current only while the table node object is unchanged, so any edit inside the table cancels the drag, which is safe but broader than a topology or size change (useTableResize.ts `isCurrent`, checked 2026-10-08; docs/plite/research/2026-09-17-table-substrate-ownership/REPORT.md:143-156). Table width redistribution stays separate from image aspect-ratio resizing, and promoting the pointer helper into Plite would only move code.

- Table sizes are plain numbers in a pixel-oriented contract: `columnWidths`, row `height` and `marginLeft` (packages/platejs/src/features/table/lib/BaseTablePlugin.ts:406,639-643). Responsive or percentage widths would be a separate table-domain contract with import conversion and total-width invariants, not a reason to move resizing into Plite, and the numeric API does not imply percentage fidelity; the 2026-09-17 review deferred unit modes until a current responsive or import-fidelity job exists (docs/plite/research/2026-09-17-table-substrate-ownership/REPORT.md:158-164; lead-ledger.tsv:8).

## Selection paint

- Table selection paint follows the current host element, not only the NodeKey. `tableSelectionHostBinding.internal.ts` keeps a per-editor controller of host bindings set through ref callbacks and repaints `data-table-cell-selected` and the caret style on whichever element currently hosts each key (packages/platejs/src/react/features/table/tableSelectionHostBinding.internal.ts), and the test 'paints a contract-compliant custom cell across same-key host replacement and cleanup' covers the case (packages/platejs/src/react/features/table/TablePlugin.hostBinding.spec.tsx:60). On 2026-09-17 a probe replaced the selected anchor `td` with a `th` that kept the node key, and the then-current `useTableSelectionDOM` hook, which cached keys and DOM nodes, left the new host unpainted after 11 passing controls (docs/plite/research/2026-09-17-table-substrate-ownership/REPORT.md:166-181). The review ruled out the plain React view-attribute path because the earlier table plan measured it at p95 48.79 ms against 8.75 ms (25×20) and 163.52 ms against 35.71 ms (50×40), with 15,045 and 60,045 cell renders against zero (REPORT.md:192-199, from docs/plans/2026-09-17-table-api-design.md:280-315,380-398). Limit: happy-dom attributes and styles, not pixels or the native caret.

- Table selection paint reads both the command editor and the model editor: `TableSelectionHostEffect` subscribes to both and paints from whichever owns the selection, and its cleanup only resets the paint (`packages/platejs/src/react/features/table/TablePlugin.tsx:364-397`). On 2026-09-18 two deletion experiments, subscribing only to the mounted view or only to the command editor while deleting the model fallback, painted zero cells for both imperative row or table selection and cell selection in the full EditorKit fixture. Strict Mode cleanup reuses the ordinary empty-selection update and ref cleanup releases detached hosts, so one controller per editor survives effect replay. Source: `docs/research/history/2026-09-18-feature-history-exercises.md:239-242`, `docs/plans/2026-09-17-table-selection-host-projection-design.md:13-27`.

## Capability packaging

- Table ships no separate public capability plugin. Schema validity, grid correction, cache invalidation, selection clamping and destructive-boundary protection are mandatory Table behavior; table-selection mapping, command interception, deletion, fragment, paste and typing behavior jointly define Table selection and have no independent fallback; `Tab`, arrow-boundary movement, selection escalation, copy and cut stay in the React `TablePlugin` because they depend on DOM geometry, hotkeys and native events; and headless `BaseTablePlugin` against React `TablePlugin` is the proven host boundary. Table clipboard customization is the most plausible future capability, but it first needs a real omit or replace caller, explicit fallthrough semantics, public dependency closure and default, omitted and replaced browser proof. Source: `docs/research/systems/editor-behavior-architecture.md:319-341` (a 2026-07-23 audit; its count of seven extension contributions was not rechecked).
