# Tiptap: conversion and export

## Content parsing and insertion

- **Content parsing and insertion.** Tiptap's `insertContent` and `setContent` treat whitespace differently. `insertContent` parses with `preserveWhitespace: 'full'` by default (`ueberdosis/tiptap@91c51be53c:packages/core/src/commands/insertContentAt.ts:97`). It keeps spaces between tags, empty spaces, and newlines and tabs inside a paragraph, strips them with `preserveWhitespace: false`, and inserts an incomplete tag such as `foo<p` as literal text (`ueberdosis/tiptap@91c51be53c:demos/src/Commands/InsertContent/React/index.spec.js:17-97`). `setContent` collapses newlines and tabs to spaces and drops the incomplete tag unless `preserveWhitespace: 'full'` is passed, and a TODO in its spec says the authors are unsure what the incomplete-tag case should do (`ueberdosis/tiptap@91c51be53c:demos/src/Commands/SetContent/React/index.spec.js:73-176`). Invalid content is dropped without an error by default: `createNodeFromContent` returns nothing for a JSON node of an unknown type and keeps only the text of an unknown HTML tag. With `errorOnInvalidContent: true` it throws for unknown node or mark types and for JSON that breaks the schema's nesting (`ueberdosis/tiptap@91c51be53c:packages/core/__tests__/createNodeFromContent.spec.ts:190-286`). An editor emits `contentError` only with `enableContentCheck: true`; invalid initial content then leaves it empty, and the handler can call `disableCollaboration()` (`ueberdosis/tiptap@91c51be53c:packages/core/__tests__/onContentError.spec.ts:8-170`). `ueberdosis/tiptap@91c51be53c:packages/core/__tests__/requiredAttributes.spec.ts` pins that an attribute with `isRequired` and no default reaches the ProseMirror schema with no `default`, which makes it required. The harvest routes this to Plate's HTML, Markdown and DOCX parsers and leaves Plite only browser paste insertion (`docs/editor-test-harvester/tiptap/report.md:98`). Read at that commit on 2026-10-08; the 2026-05-10 harvest pinned no commit, but its cited lines match this one.

## Serialization and static rendering

- **Serialization and static rendering.** Tiptap's export and static-rendering tests each check one output path against a fixed string for a small document. The ExportHTML and ExportJSON guide demos check `editor.getHTML()` and `getJSON()`. `ueberdosis/tiptap@91c51be53c:packages/core/__tests__/generateHTML.spec.ts`, `generateJSON.spec.ts` and `generateText.spec.ts` in that folder check the helpers that run without an editor instance. The GenerateHTML, GenerateJSON, StaticRenderHTML and StaticRenderReact guide demos check the browser and static renderers (`ueberdosis/tiptap@91c51be53c:demos/src/GuideContent/`). No test compares one path's output with another's, and the two HTML demos expect different strings: GenerateHTML's `<p>` carries an `xmlns` attribute that StaticRenderHTML's lacks. These are smoke checks, not proof that live and static output agree. The harvest routes this to Plate's serializers and docs examples (`docs/editor-test-harvester/tiptap/report.md:100`). Read at that commit on 2026-10-08; the 2026-05-10 harvest pinned no commit, but its cited lines match this one.

- Tiptap 3.21.0 (`ueberdosis/tiptap@91c51be53c`, MIT) converts documents without an editor, but not without a DOM. The editor getters `getJSON`, `getHTML` and `getText` read `state.doc` (`ueberdosis/tiptap@91c51be53c:packages/core/src/Editor.ts:721-757`). `generateHTML(json, extensions)` builds a schema and ProseMirror node with no `Editor` (`ueberdosis/tiptap@91c51be53c:packages/core/src/helpers/generateHTML.ts`), but its HTML helper runs ProseMirror's `DOMSerializer` against the global `document` (`ueberdosis/tiptap@91c51be53c:packages/core/src/helpers/getHTMLFromFragment.ts`). `@tiptap/static-renderer` dispatches node and mark mappings over JSON or a ProseMirror node, computes children lazily, accepts an unhandled-node callback and otherwise throws a missing-handler error (`ueberdosis/tiptap@91c51be53c:packages/static-renderer/src/json/renderer.ts:57-105`, `:147-241`). Its `renderToHTMLString` turns `DOMOutputSpec` arrays into a string without a DOM and throws on real DOM objects (`ueberdosis/tiptap@91c51be53c:packages/static-renderer/src/pm/html-string/html-string.ts:1-114`), its `renderToMarkdown` calls itself an incomplete example (`ueberdosis/tiptap@91c51be53c:packages/static-renderer/src/pm/markdown/markdown.ts:9`), and the package declares React and react-dom peers even for string-only consumers. Tiptap's `renderHTML` declarations become ProseMirror `toDOM` handlers and `@tiptap/pm/model` re-exports prosemirror-model, so the model behavior is ProseMirror's. Source: `docs/plite/research/2026-09-24-export-architecture/read-log.tsv` rows 9-20, 35, 51 and 53, `sources/web-and-issues.md:10` (2026-09-24; source read, nothing executed).

## HTML parse rules for marks

- **HTML parse rules for marks.** Tiptap's Bold, Italic, Strike and Underline demo specs pin, through `setContent`, how each mark parses from HTML (`ueberdosis/tiptap@91c51be53c:demos/src/Marks/Bold/React/index.spec.js:13-41` and the matching Italic, Strike and Underline specs). Bold takes `<strong>`, `<b>` unless its `font-weight` is `normal`, and a `font-weight` of `bold`, `bolder` or 500 and above; `font-weight: 400` clears an inherited bold (`ueberdosis/tiptap@91c51be53c:packages/extension-bold/src/bold.tsx:65-83`). Italic takes `<em>`, `<i>` unless its `font-style` is `normal`, and `font-style: italic`. Strike takes `<s>`, `<del>`, `<strike>` and any `text-decoration` containing `line-through`, and Underline takes `<u>` and any `text-decoration` containing `underline`. The other tests in these specs toggle each mark by button, shortcut and Markdown shortcut. Plate differs, by a code reading on 2026-10-08 that ran nothing: `BaseBoldPlugin` matches `font-weight` 600, 700 or `bold` only, and the strikethrough and underline rules compare `text-decoration` by exact value. So 500, 800, 900 and `bolder` do not become bold, though `BaseFontWeightPlugin`, when installed, keeps any weight as its own `fontWeight` mark, and `underline line-through` matches neither mark (`packages/platejs/src/features/basic-nodes/lib/BaseMarkPlugins.ts:163`, lines 312 and 338; `packages/platejs/src/lib/plugins/html/HtmlPlugin.ts:881-918`; `packages/platejs/src/features/basic-styles/lib/BaseStylePlugins.ts:135-156`). Evidence for the routing: `docs/editor-test-harvester/tiptap/portable-mixed-routing.md:34-43`. Read at that commit on 2026-10-08.

## Markdown

- `@tiptap/markdown` 3.21.0 (MIT, built on `marked`) exports a standalone `MarkdownManager` whose constructor takes extensions, indentation and `marked` options without an editor. It reads each extension's Markdown handlers and serializes JSON, and a missing node handler or mark renderer returns an empty string instead of reporting loss (`ueberdosis/tiptap@91c51be53c:packages/markdown/src/MarkdownManager.ts:29-55`, `:887-950`, `:1164-1180`). The installed `editor.getMarkdown()` delegates to `manager.serialize(editor.getJSON())` (`ueberdosis/tiptap@91c51be53c:packages/markdown/src/Extension.ts:175-201`). Source: `docs/plite/research/2026-09-24-export-architecture/read-log.tsv` rows 12, 21-22, 36-37 and 54 (2026-09-24; empty-string returns reread at that commit 2026-10-08).

## Detached conversion

- Tiptap converts HTML from extension configuration with no editor, also on a server (`ueberdosis/tiptap@91c51be53c:packages/html/src/server/generateJSON.ts`), but its server path requires happy-dom (same file, lines 4 and 8), which Plate rejected for its own server adapter after a happy-dom stress parse exhausted a 4 GB process, and the 2026-09-25 read found no loss diagnostics in its converters. Source: `docs/plite/research/2026-09-25-document-codec-architecture/shards/004-editors-and-cross-language-controls.md:25-27` and read-log row 24 (2026-09-25); the happy-dom requirement reread at that commit on 2026-10-08.
