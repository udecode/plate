# Tiptap: conversion and export

## Content parsing and insertion

- **Content parsing and insertion.** Tiptap's `insertContent` and `setContent` treat whitespace differently. `insertContent` parses with `preserveWhitespace: 'full'` by default (`ueberdosis/tiptap@91c51be53c:packages/core/src/commands/insertContentAt.ts:97`). It keeps spaces between tags, empty spaces, and newlines and tabs inside a paragraph, strips them with `preserveWhitespace: false`, and inserts an incomplete tag such as `foo<p` as literal text (`ueberdosis/tiptap@91c51be53c:demos/src/Commands/InsertContent/React/index.spec.js:17-97`). `setContent` collapses newlines and tabs to spaces and drops the incomplete tag unless `preserveWhitespace: 'full'` is passed, and a TODO in its spec says the authors are unsure what the incomplete-tag case should do (`ueberdosis/tiptap@91c51be53c:demos/src/Commands/SetContent/React/index.spec.js:73-176`). Invalid content is dropped without an error by default: `createNodeFromContent` returns nothing for a JSON node of an unknown type and keeps only the text of an unknown HTML tag. With `errorOnInvalidContent: true` it throws for unknown node or mark types and for JSON that breaks the schema's nesting (`ueberdosis/tiptap@91c51be53c:packages/core/__tests__/createNodeFromContent.spec.ts:190-286`). An editor emits `contentError` only with `enableContentCheck: true`; invalid initial content then leaves it empty, and the handler can call `disableCollaboration()` (`ueberdosis/tiptap@91c51be53c:packages/core/__tests__/onContentError.spec.ts:8-170`). `ueberdosis/tiptap@91c51be53c:packages/core/__tests__/requiredAttributes.spec.ts` pins that an attribute with `isRequired` and no default reaches the ProseMirror schema with no `default`, which makes it required. The harvest routes this to Plate's HTML, Markdown and DOCX parsers and leaves Plite only browser paste insertion (`docs/editor-test-harvester/tiptap/report.md:98`). ## Serialization and static rendering

- **Serialization and static rendering.** Tiptap's export and static-rendering tests each check one output path against a fixed string for a small document. The ExportHTML and ExportJSON guide demos check `editor.getHTML()` and `getJSON()`. `ueberdosis/tiptap@91c51be53c:packages/core/__tests__/generateHTML.spec.ts`, `generateJSON.spec.ts` and `generateText.spec.ts` in that folder check the helpers that run without an editor instance. The GenerateHTML, GenerateJSON, StaticRenderHTML and StaticRenderReact guide demos check the browser and static renderers (`ueberdosis/tiptap@91c51be53c:demos/src/GuideContent/`). No test compares one path's output with another's, and the two HTML demos expect different strings: GenerateHTML's `<p>` carries an `xmlns` attribute that StaticRenderHTML's lacks. These are smoke checks, not proof that live and static output agree. The harvest routes this to Plate's serializers and docs examples (`docs/editor-test-harvester/tiptap/report.md:100`). ## HTML parse rules for marks

- **HTML parse rules for marks.** Tiptap's Bold, Italic, Strike and Underline demo specs pin, through `setContent`, how each mark parses from HTML (`ueberdosis/tiptap@91c51be53c:demos/src/Marks/Bold/React/index.spec.js:13-41` and the matching Italic, Strike and Underline specs). Bold takes `<strong>`, `<b>` unless its `font-weight` is `normal`, and a `font-weight` of `bold`, `bolder` or 500 and above; `font-weight: 400` clears an inherited bold (`ueberdosis/tiptap@91c51be53c:packages/extension-bold/src/bold.tsx:65-83`). Italic takes `<em>`, `<i>` unless its `font-style` is `normal`, and `font-style: italic`. Strike takes `<s>`, `<del>`, `<strike>` and any `text-decoration` containing `line-through`, and Underline takes `<u>` and any `text-decoration` containing `underline`. The other tests in these specs toggle each mark by button, shortcut and Markdown shortcut. Plate differs, by a code reading on 2026-10-08 that ran nothing: `BaseBoldPlugin` matches `font-weight` 600, 700 or `bold` only, and the strikethrough and underline rules compare `text-decoration` by exact value. So 500, 800, 900 and `bolder` do not become bold, though `BaseFontWeightPlugin`, when installed, keeps any weight as its own `fontWeight` mark, and `underline line-through` matches neither mark (`packages/platejs/src/features/basic-nodes/lib/BaseMarkPlugins.ts:163`, lines 312 and 338; `packages/platejs/src/lib/plugins/html/HtmlPlugin.ts:881-918`; `packages/platejs/src/features/basic-styles/lib/BaseStylePlugins.ts:135-156`). Evidence for the routing: `docs/editor-test-harvester/tiptap/portable-mixed-routing.md:34-43`. Read at that commit on 2026-10-08.
