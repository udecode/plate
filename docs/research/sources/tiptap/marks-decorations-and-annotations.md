# Tiptap: marks decorations and annotations

## Mark ranges

- **Mark ranges.** `ueberdosis/tiptap@91c51be53c:packages/core/__tests__/getMarkRange.spec.ts:26-163` pins how Tiptap resolves the range of a mark at a position. It resolves from inside the mark or at its start or end, returns `undefined` where no mark is found, and never crosses a node boundary in either direction. Two adjacent links with different `href` values are separate ranges, and a lookup without attributes at the position between them returns the link that follows. `ueberdosis/tiptap@91c51be53c:packages/core/__tests__/extendMarkRange.spec.ts:10-289` pins that `extendMarkRange` grows the selection to the whole mark, or to the run whose attributes match, and leaves the selection unchanged when it holds no such mark or any non-matching one. `ueberdosis/tiptap@91c51be53c:packages/core/__tests__/isActive.spec.ts` (8 tests) checks active nodes and marks by attribute value and skips code blocks when checking marks. The harvest routes this to Plate's link and mark toolbar, such as extending a link range by href within a paragraph (`docs/editor-test-harvester/tiptap/report.md:93`, and lines 131-132).
