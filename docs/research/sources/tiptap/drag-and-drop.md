# Tiptap: drag and drop

## Drag handle

- Tiptap's drag handle is native. Floating UI's `computePosition` places the handle (`ueberdosis/tiptap@91c51be5:packages/extension-drag-handle/src/drag-handle-plugin.ts:121`); on `dragstart` the handler clears the `DataTransfer`, sets its own drag image and hands ProseMirror a `view.dragging` slice that is always a move, so ProseMirror commits the drop and no rich external payload is written (`ueberdosis/tiptap@91c51be5:packages/extension-drag-handle/src/helpers/dragHandler.ts:124-125`, `:150`). The remote head `c402400e60192895cfed85e1a72adf3fbb43d08e` was not inspected. Source: `docs/plite/research/2026-10-02-dnd-library-choice/README.md:109`, `repo-registry.tsv:6`; code reread at that commit on 2026-10-08.

- **Tiptap lands drops through unmodified ProseMirror `dropPoint` and `prosemirror-dropcursor`.** Its DragHandle only sets `view.dragging = { slice, move: true, node }`, and core's Drop extension emits an event and returns undefined (`ueberdosis/tiptap@91c51be53c46:packages/extension-drag-handle/src/helpers/dragHandler.ts:140-154`, `ueberdosis/tiptap@91c51be53c46:packages/core/src/extensions/drop.ts:14-21`). The drop is therefore schema-derived, and a dragged top-level block can land inside isolating cells, list items, blockquotes and details content (inferred from `dropPoint`, not run). By default (`nested: false`) the handle targets the top-level block under the pointer. With `nested: true` it scores every ancestor depth from 1000 minus rule deductions and prefers parents near the left edge; its default rules exclude a list item's first child, list wrappers, table rows, cells, headers and inline nodes, and an `allowedContainers` whitelist narrows it further (`ueberdosis/tiptap@91c51be53c46:packages/extension-drag-handle/src/helpers/defaultRules.ts:10-98`). Its only container rule is source-side: row and cell dragging belongs to table extensions, so nothing keeps rows in their table or columns in their group. Handle hover coalesces mousemove into one animation frame, and nested mode costs a `posAtCoords` plus a rect read per candidate depth. Source: `docs/plite/research/2026-10-02-dnd-landing-policy/editors.tsv:8-13`.
