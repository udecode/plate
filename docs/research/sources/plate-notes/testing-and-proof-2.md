# Testing and browser proof, part 2

## Stand-ins and drift

- **A dependency fixture must return the dependency's real result shape.** The July Code Block review found a legacy Lowlight `{ value }` fixture that kept obsolete decoration parsing alive. The correction used Lowlight's root, element and text tree, with classes in element properties (docs/plans/2026-07-10-plate-next-uncommitted-code-block-files.md:507-508, 525). Today's proof starts from `createLowlight()` and constructs results through its inferred highlight return type (`packages/platejs/src/features/code-block/lib/BaseCodeBlockPlugin.spec.tsx:1444-1470`); production traverses element children and text values (`BaseCodeBlockPlugin.ts:806-825`). Limit: production now declares its own structural HighlightNode/HighlightResult contract, so the July claim that all local structural types were removed is no longer current.

- **Default typing must not silently become semantic insertion on mobile.** Routing mobile `editor.type()` through a model handle made browser rows pass while bypassing keyboard, beforeinput, DOM input and Android repair. Restoring `page.keyboard.type` exposed both a visible-text/model split after paste and stale-target text ordering, which then needed runtime repairs. Current `packages/test/src/playwright/harness.ts:492-500` keeps typing on the keyboard path. Evidence: `c70bacbd4a:docs/plans/2026-06-07-plite-8h-supervision.md:638`. Semantic insertion remains useful when explicitly selected; an emulated mobile keyboard row still does not establish raw Android or iOS support.

- **Model a stale browser selection without replacing the ownership check.** jsdom cleared a selection after its selected node was removed, so the first detached-endpoint test could not reproduce Chromium's stale endpoint shape. The kept contract supplies a root `getSelection()` that returns the detached text node while retaining the real `ReactEditor.hasSelectableTarget` check; it asserts that range resolution never runs and model selection stays unchanged (`packages/plitejs/test/react/selection-controller-contract.ts:1287-1378`). Source: `c70bacbd4a:docs/plans/2026-06-12-plite-8h-post-delete-supervision.md:757`. This proves the controller's import boundary, not that a real browser produces or repairs that stale selection.

- **Direct DOM tests expose ambient-global assumptions.** The first draft Plite DOM package proof found that point conversion assumed global `Text`, ordering helpers assumed global `Node` constants, and clipboard helpers assumed global window/style functions (docs/plans/2026-04-19-plite-dom-react-tranche-5-6-execution.md:162-167). Current Plite's `isDOMText` checks node type, while `isBefore` and `isAfter` resolve document-position constants through host-aware helpers (`packages/plitejs/src/dom/utils/dom.ts:102`, `:377-390`). Exercise DOM helpers directly with their supplied document instead of relying solely on a React/browser harness that supplies ambient globals. Limit: this records the host-assumption failure class; the original package suite was not rerun.

## Headless composition

- **Prove headless usability through composition.** Separate tests of history, fixtures and fragment insertion do not establish that those surfaces work together without React. The April 2026 headless plan assigned one owner to compose package imports, hyperscript-built content, fragment replacement and undo (`docs/plans/2026-04-09-plite-non-react-headless-core-usability-completion-plan.md:143-211`). That owner survives in `packages/plitejs/test/headless-contract.ts:1-100`: it imports `plitejs`, `plitejs/history` and `plitejs/hyperscript`, inserts a slice and checks that undo restores content and selection. The old separate packages and `withHistory` API have become subpaths and `history()`. Limit: this is a source composition contract, not packed-artifact or browser proof; it was read, not rerun.

## Harvesting other editors

- **Port the editing outcome before requiring another editor's DOM identity.** The May 7 draft-Plite IME run initially required ProseMirror-style text-node identity during marked input. That assertion failed, while the retained row proved inserted text, preserved bold formatting, caret movement and Backspace restoration. Treat node identity as an additional contract that needs justification, rather than importing it with a behavior test. Evidence: docs/plans/2026-05-07-plite-mobile-ime-input-runtime-ralplan.md:1568-1579. Limit: this records the historical test-design finding; it does not establish that current Plite must replace or preserve a particular DOM node.

## Identity contracts

- **Compare allocation order without comparing editor identity.** An August 2026 discarded-spec test compared full node keys from two editors and blamed allocation, although both local ordinals were already n4. Full keys intentionally include different editor scopes (c70bacbd4a:docs/plans/2026-08-15-fix-plite-ci-failures.md:257-260). Current packages/plitejs/src/utils/node-keys.ts:16-34 allocates scoped keys, while getNodeKeyDOMValue at :62 removes that scope for deterministic SSR tokens. Use the local token when testing cross-editor allocation order; retain full keys when testing identity. The related DOM-attribute contract uses string tokens, not branded runtime keys.

## Package and API proof

- **An import cut must include JavaScript fixtures.** The June 2026 Plite static-API cut migrated TypeScript imports but missed a JavaScript history fixture that still imported the removed internal `Editor` value; the package test caught the stale import (`c70bacbd4a:docs/plans/2026-06-23-plite-editor-static-api-hard-cut.md:311-325`). Audit `.js` and `.jsx` consumers alongside `.ts` and `.tsx`, then run the owning package's real fixture loader. Current `packages/plitejs/src/index.ts` exports `Editor` only as a type and `isEditor` as the predicate; this lesson records the migration blind spot, not a claim that the removed fixture still exists.
