# Selection, navigation and delete, part 2

## Multi-root focus

- **Keep a selection's root through every read and mutation.** The hard cut exposed reads that resolved a header path against the body and Core/AI mutations that lost the root before reusing paths. Exact named-root regressions caught the errors after ordinary single-root tests passed. Current node selection carries an explicit root (`packages/plitejs/src/interfaces/selection.ts`), and `packages/plitejs/src/core/node-selection.ts` derives replacement targets with that root. Source: `docs/plans/2026-08-24-single-selection-authority-hard-cut.md:389-413`. The historical fix read `selection.anchor.root`; current node selections use their own root field.

- **A shared root's identity does not identify its visible occurrence.** The May synced-block repair found navigation choosing the first owner of shared content instead of the owner where the gesture occurred. Cross-root mouse selection could also remain a root-local DOM range or only a newline. Current `packages/plitejs/src/react/editable/content-root-navigation.ts` retains owner-aware movement, and `react/view-selection.ts` represents projected selection separately from canonical selection. Evidence: `docs/plans/2026-05-27-synced-blocks-sibling-selection.md:250-258`. This is a lesson from the fork's draft runtime; current behavior was inspected in source, not replayed.

- **Focus repair must preserve an expanded projected selection.** The synced-block repair found that focusing a view could export its collapsed model selection over an existing projected selection. Current `focusPliteEditableForRequest` in `packages/plitejs/src/react/hooks/focus-plite-editable.ts` detects an expanded view selection and focuses the element without exporting the model selection. Evidence: `docs/plans/2026-05-27-synced-blocks-sibling-selection.md:259-264,306-309`. This source check supports the guard's purpose; it does not establish complete native selection parity.

## DOM selection import and ownership

- **Guard both event paths that can import a caret during model-owned typing.** The first PR 5036 WebKit repair rejected a mismatched DOM caret in `selectionchange`, but `beforeinput` could import the ahead caret first. The current selection controller carries text-input ownership, and the reconciler rejects a different same-path collapsed offset while the model owns insertion (`packages/plitejs/src/react/editable/selection-controller.ts`, `selection-reconciler.ts:787-794`). Source: `c70bacbd4a:docs/plans/5036-complete-pushed-ci.md:301-313`. For drag undo, capture the range the browser actually established, including direction, rather than predicting direction from the browser name (`:314-319`).

- **Resolve mounted node identity before trusting its stored DOM path.** The June collaboration repair found mounted path attributes could lag structural edits and resolve a DOM point to an element instead of a text leaf. Current `resolveMountedDOMPath` in `packages/plitejs/src/dom/plugin/dom-node-path.ts` first resolves `data-editor-node-key` against the live document, then falls back to an existing attribute path; `dom-editor.ts:resolvePliteTextPoint` maps non-text nodes to a start or end text point. Evidence: `docs/plans/2026-06-08-yjs-placeholder-leaf-path-fixes.md:218-226`. The historical `data-plite-*` names are now `data-editor-*`; this does not license accepting foreign DOM.

- **A popup's Done action can overwrite a navigation landing.** The inline-equation repair rejected calling the existing `onClose` after ArrowLeft: that callback selected after the equation and would overwrite the point just selected before it. Model selection alone also failed to restore DOM focus. Keep exit direction explicit and prevent popup focus restoration from undoing it. Source: `c70bacbd4a:docs/plans/5071-fix-inline-equation-arrowleft-dismissal.md:265-298`; the historical browser sequence asserted both caret position and editor focus at lines 316-329. Current `apps/www/src/registry/components/editor/math.tsx:267-337` implements a direction-aware `close`, explicit DOM focus and an inline final-focus veto. Limit: navigation now belongs to copied UI; the old package hook and Radix-specific callbacks are historical.

- **A bounding text range cannot stand in for exact cell membership.** The left-border bug occurred when a selection override intercepted a path-targeted write to an unselected adjacent cell because the broader linear range included it (`docs/plans/4798-fix-table-left-border-multirow-selection.md:31-38`). The old override is gone. Current `packages/platejs/src/features/table/lib/BaseTablePlugin.ts:1510-1577` iterates canonical selected anchors, resolves physical edges and writes their exact paths. Preserve the membership distinction when changing table commands; the historical `withTableCellSelection` patch is not current implementation advice.

- **Use canonical row bounds for a row-specific affordance.** A generic expanded-cell-selection flag hid row controls even when several selected cells occupied one row. The repair named the actual condition and used the table selection's span-aware bounds instead of adding a cell scan or inferring rows from paths (`docs/plans/2026-08-26-keep-row-drag-handle-for-one-row-selection.md:250-267`). Current `apps/www/src/registry/components/editor/table.tsx:171-178` also requires the matching table, rectangular selection and multiple cells before comparing `maxRow` with `minRow`.

- **A captured selection and the current selection have different lifetimes.** The July guarded-string sweep replaced a local current-selection pass-through with `editor.read.text.string()`, but retained the hovering toolbar's explicit range because an Effect consumes the selection captured by its render. Source: `c70bacbd4a:docs/plans/2026-07-12-remove-guarded-text-string-callers.md:201-208`. Current `apps/www/src/app/(app)/examples/plite/_examples/hovering-toolbar.tsx:102-134` still reads `text.string(selection)` inside that Effect, while `packages/plitejs/src/core/public-state.ts` resolves an omitted target at call time. Remove a guard only when the selection lifetime and fallback remain equivalent.

- **Canonicalize selected paths before choosing endpoints.** The August marquee implementation chose a descendant focus that ancestor canonicalization later removed. A second case removed the Shift base anchor. The repair reused `SelectionApi.nodes` before endpoint selection and retained an anchor only when it survived canonicalization. Source: `c70bacbd4a:docs/plans/2026-08-26-promote-plate-block-content-read.md:142-143`, with the two recorded failures at `:202-204`. Current `packages/platejs/src/react/components/NodeSelection.tsx` still canonicalizes candidate paths through `SelectionApi.nodes` before returning selection entries. The original copied helper moved into the package; historical browser counts are not fresh proof.

- **Restore a temporarily overridden DOM method without shadowing its prototype.** Assigning `undefined` to a leaf's `getBoundingClientRect` after range-based scrolling left an own property that hid the prototype method, so the second scroll attempt returned early. Preserve whether the element originally owned the method, restore that original value when it did, and otherwise delete the temporary property in a finally block. Evidence: `c70bacbd4a:docs/plans/2026-05-11-scroll-into-view-repeat-regression.md:27-51`; current `packages/plitejs/src/dom/plugin/dom-editor.ts:2145-2160` follows this restoration pattern. This is the measurement-override bug in the draft fork, distinct from later selection-authority causes of repeated-scroll failure; no fresh browser run was performed.

## Focus and selection side effects

- **A queued selection export can steal focus after a valid blur.** Native selection followed immediately by a marked-button click exposed a queued model-to-DOM export that rewrote the browser selection and reclaimed editor focus. Captured selection-method stacks identified the export owner; adding an artificial delay would have hidden the race (`docs/plans/2026-08-31-native-inactive-selection-focus-marker.md:322-339`). Current `packages/plitejs/src/react/editable/selection-side-effect-policy.ts:17-35` checks inactive-selection state before honoring even a forced DOM-selection export and suppresses focus repair too. Limit: the historical repeated browser case certified the local Chromium interaction, not every browser.

## Pointer drag selection

- **Live pointer movement is not a stale auto-scroll frame.** A rollback guard intended for delayed auto-scroll ranges was also rejecting legitimate backward pointer movement, making table selection expand monotonically. Current `packages/plitejs/src/react/editable/root-interaction-controller.ts:1140-1178` keeps the regressive-range guard in auto-scroll processing, while `:1851-1875` applies each resolved live move range without that guard. Mouse-up retains its separate opposite-direction check. Source: `docs/plans/2026-08-26-shrink-table-cell-selection-on-drag-back.md:316-345`. Fixing Table markers alone would leave the underlying model range wrong; the browser regression checks contraction while held and after release.

- **Apply internal-control classification throughout a drag.** Checking ignored editor chrome only at mouse-down lets later moves or release resolve a new text point inside a resize handle. Current `packages/plitejs/src/react/editable/root-interaction-controller.ts:916-923,1815-1826,1929-1938` reuses target classification on move and release and preserves the current range over interactive descendants. Table marks its resize group with `data-editor-root-chrome-ignore="true"` and suppresses hover preview when `event.buttons !== 0` (`apps/www/src/registry/components/editor/table.tsx:225-236,959`). Source: `docs/plans/2026-08-26-ignore-table-resize-handles-during-cell-selection-drag.md:270-289`. The root controller owns selection protection; Table owns its preview presentation. No second selection store is needed.

## Deferred tabindex restoration

- **Rescheduling restoration preserves the first original attribute.** Temporarily setting `tabindex=-1` twice must not replace the original saved value with the temporary value. The restoration queue keeps the first value, cancels the previous timeout and schedules a replacement; it also distinguishes a missing attribute from an explicit value. Current `packages/platejs/src/tabbable/react/TabbableEffects.internal.tsx:79-119` implements this, and `TabbablePlugin.spec.tsx` covers rescheduling with both missing and explicit attributes. Source: `c70bacbd4a:docs/plans/2026-08-19-fix-oxlint-config-exceptions.md:358-360`. Limit: source and tests were read, not executed.

## Vertical caret geometry

- **Pointer hit testing is not an oracle for vertical keyboard navigation.** PR 5036's attempted point-API consensus and synthetic line-movement mirrors disagreed with Chromium's vertical-selection behavior. The kept calculation uses the painted bar caret's rounded leading edge in the local block, and carries the preferred column through staged coverage. Current `packages/plitejs/src/dom/plugin/dom-geometry.ts:47-55` retains `getVerticalNavigationCaretX`; `react/editable/runtime-keyboard-events.ts` and `keyboard-input-strategy.ts` carry the preferred vertical coordinate. Source: `c70bacbd4a:docs/plans/5036-eliminate-pr-5036-local-ci-drift.md:213-225`, with rejected attempts at :273-280 and :299-302. Limit: an internal Chromium-derived repair, not a public platform option or universal browser geometry proof.

## Projected selection

- **Test the click and typing immediately after a projected drag.** Four drag directions passed repeatedly while a later click still left the previous projected selection active, so End and typing edited the previous paragraph. Clear the prior projection when mouse-down transfers ownership to a new browser anchor, rather than adding a delay. Evidence: `docs/plans/2026-09-13-suggestion-deleted-pointer-selection.md:33-37`; current projected endpoint resolution and selection clearing remain in `packages/plitejs/src/react/editable/root-interaction-controller.ts`. The recorded reproduction covers horizontal Chromium dragging across retained deleted text; it establishes no mobile or vertical-selection parity.
