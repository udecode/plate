# Rendering, decorations and overlays, part 2

## Rendering

- **Transient feedback needs both mounted-view identity and root-local node identity.** Moving navigation feedback out of model updates fixed sibling views flashing together and read-only views rejecting presentation. Initial production adoption still accepted a key from another content root; the root-boundary regression caught that omission. Current `packages/platejs/src/react/plugins/navigation-feedback/NavigationFeedbackPlugin.ts` keeps its target and timer in a WeakMap keyed by the mounted editor, resolves the NodeKey through that editor's node read, and publishes through `useViewElementAttributes`. Its colocated spec covers calling-view isolation, read-only feedback, foreign roots, movement, deletion and retirement. Source: `c70bacbd4a:docs/plans/2026-09-09-navigation-feedback-api.md:87-89`. Limit: package source and test definitions were read; no fresh browser result is claimed.

- **Portal geometry does not prove portal paint.** The #5088 investigation found a 100×78 selection rectangle and two selected blocks, but the rectangle had a transparent background and zero border. EditorContainer descendant selectors could not style a portal mounted under `document.body`. Check paint on the actual portal during the drag and supply its presentation directly. Source: `c70bacbd4a:docs/plans/5064-reporter-retest-iteration.md:494-496`. The old Selection API is gone; current `packages/platejs/src/react/components/NodeSelection.tsx:911` portals the rectangle into the editable document's body, and `apps/www/src/registry/components/editor/editor.tsx:136` supplies its border and background classes.

- **Toolbar focus preservation and owned-popup lifetime need separate proof.** In #5085, Bold passed while Comment and Turn Into failed through different control paths. Preventing mouse focus transfer repaired the shared button behavior, but a popup also needed its trigger owner to survive legitimate outside focus. Current `apps/www/src/registry/bases/radix/toolbar.tsx:123` composes mousedown prevention with the caller handler; `components/editor/toolbar-overlay.tsx` tracks owned overlays from ARIA trigger state; and `floating-toolbar.tsx:137` stays open for an owned overlay. Source: `docs/plans/5085-toolbar-focus-execution.md:437-441`. Verify distinct control families and the next popup interaction; a green mark button does not prove menus or composers. The repair belongs to Plate UI and does not justify weakening Plite's outside-focus behavior.

- **Hide an empty caption without changing its mounted DOM lifetime.** File selection followed by TOC and text interaction exposed a React `removeChild` failure at `figcaption`. The repair kept the caption mounted, changed visibility through native `hidden`, and preserved the existing React children contract. Source: `c70bacbd4a:docs/plans/2026-08-31-file-caption-click-regression-closure.md:499`, with the exact baseline failure and browser proof recorded at lines 530-543. Current `apps/www/src/registry/components/editor/caption.tsx:98-122` still renders one unconditional `figcaption` with `hidden={hidden}` and `{children}`. This explains the mounted-caption repair; it does not establish a general ban on conditional rendering.

- **View-only controls subscribe to view state.** The Playground mode UI stayed stale because it observed document commits while the relevant state belonged to the view. Current `apps/www/src/registry/components/editor/mode-toolbar-button.tsx:72` reads read-only state through `useEditorViewState`; `packages/plitejs/src/react/hooks/use-editor-view-state.ts:23` subscribes through `subscribeEditorViewState`. Source: `c70bacbd4a:docs/plans/2026-09-12-playground-chrome-startup-regression.md:564`. Use the publisher for the selected state; document publication alone does not cover focus, composition or read-only changes.

- **An abandoned render must not publish a selector.** July's API execution found that render-time callback and data writes could escape work React abandoned. Publish selectors and change filters after commit, then catch up when subscribing or changing the filter. Current `packages/plitejs/src/react/hooks/use-generic-selector.tsx` commits its selector in a layout effect and rejects stale render snapshots; `use-editor-selector.tsx` commits `shouldUpdate` and updates after subscribing. `packages/plitejs/test/react/provider-hooks-contract.tsx:628,738,792` covers abandoned filter, selector and provider-callback renders. Source: `c70bacbd4a:docs/plans/2026-07-22-execute-agent-native-api-shapes.md:398-401`. These owners and tests were inspected, not rerun.

- **Compiler diagnostics do not turn imperative editor state into React state.** The August 2026 cleanup moved input-controller and DOM-runtime writes behind semantic transitions at their existing owners, preserving event and transaction timing. A generic field setter would only hide the mutation, while mirrored React state would introduce another authority. Source: `docs/plans/2026-08-23-close-react-compiler-lint-and-react-19-migration.md:199-200`. Current `packages/plitejs/src/react/editable/runtime-before-input-events.ts` still coordinates model-selection preference, pending-input flush and DOM repair through runtime owners. The lesson concerns ownership; the August private method inventory is historical.

- **Derive remount identity from published state instead of incrementing a ref during render.** The August 2026 text-render repair replaced a mutable remount counter with identity derived from the rendered revision and segment content. An A-to-B-to-A sequence still remounts at each adjacent identity change. Source: `docs/plans/2026-08-23-close-react-compiler-lint-and-react-19-migration.md:201`. Current `packages/plitejs/src/react/components/editable-text.tsx:457-464` keys each fragment from `nodeKey`, `renderRevision` and `segment.identity`. Preserve all identity inputs when changing this key; this source inspection is not a fresh IME or browser replay.

- **A custom memo comparator can preserve stale behavior while visible values stay equal.** The August 2026 `ColorPicker` comparator ignored callbacks and DOM props, so unchanged color data could retain obsolete behavior. Removing the wrapper fixed correctness rather than merely satisfying Compiler policy. Source: `docs/plans/2026-08-23-close-react-compiler-lint-and-react-19-migration.md:210`, :327-329. Current `apps/www/src/registry/components/editor/font-color-toolbar-button.tsx:281-325` renders `ColorPicker` as an ordinary function and forwards current callbacks and remaining DOM props. The former regression-test path is historical; no test was rerun here.

- **A body portal cannot inherit an editor container's descendant styling.** The missing marquee came from placing the rectangle under `document.body` while its brand styles were descendant selectors on EditorContainer. Keep portal lifecycle and geometry in the reusable component, and pass presentation directly to the portal element from copied UI. Source: `c70bacbd4a:docs/plans/5088-block-marquee-paint.md:436-441`. Current `packages/platejs/src/react/components/NodeSelection.tsx:911-930` forwards `className` to a body portal, and `apps/www/src/registry/components/editor/editor.tsx:136` supplies literal border and fill classes. The former `selectionAreaClassName` option has been replaced by the component's ordinary className prop.

- **Check whether scroll restoration observes an earlier jump.** In the August 2026 annotation regression, the selection controller entered with `preserveScroll=true` after the browser had already moved the scroll position. Changing that controller could not recover the earlier position. The trigger was registry hover state publishing a React contenteditable commit merely to change colors; CSS hover removed that publication. Current `apps/www/src/registry/components/editor/comment.tsx:50` and `suggestion.tsx:218` retain native hover presentation. Source: `docs/plans/2026-08-29-comment-suggestion-scroll-jump-regression.md:474-483`. Limit: CSS hover highlights the pointed segment; this does not promise synchronized hover across every segment of one annotation.

- **DOM resolution errors must not serialize the editor's content.** A lint repair used `outerHTML` in a Plite DOM error, exposing the subtree in diagnostics. Review replaced it with `nodeName`. Current `packages/plitejs/src/dom/plugin/dom-editor.ts:2260` builds a node-name label, and its point-resolution error at `:2609` also reports the node name and offset. Source: `c70bacbd4a:docs/plans/2026-08-20-implement-oxlint-audit-cleanup.md:236`. This preserves useful location diagnostics without making the error a document dump; it is not an audit of every logging path.

- **Check a component's actual state owner before retaining forwarded props.** The registry image/video cleanup removed a forwarded `readOnly` value because Resizable already derived editor read-only state. Current `packages/platejs/src/react/features/resizable/Resizable.tsx:205` reads `useEditorReadOnly()`, and its resize handle returns null when read-only at `:215`. Source: `c70bacbd4a:docs/plans/2026-07-29-repair-registry-cleanup-drift.md:286-287`. This applies to that editor-owned resize behavior; it is not a reason to remove independent consumer overrides from other components.

- **A renderer primitive should require only the context it consumes.** The August heading cleanup could not forward either a generic or a concrete union of descriptor-owned props into the shared primitive because its input carried an unused invariant plugin context. Repairing the primitive's input preserved exact public props without six duplicated bodies or caller casts. Source: `docs/plans/2026-08-13-repair-heading-component-family.md:597-608`. Current `packages/platejs/src/react/components/plate-nodes.tsx` keeps a narrow primitive input with only the selection rules it reads; the static primitive lives in `packages/platejs/src/static/components/plite-nodes.tsx`. Today's heading family has one level-based descriptor, so the old six-wrapper topology is historical.

- **Coalesce node-bind exports without losing the trailing caret repair.** The external-text execution found repeated selection-export scheduling during synchronous node binds. Its first coalescing attempt moved work to a leading frame and broke two caret-scroll cases. The successful form coalesced the binds in a microtask and retained a trailing animation-frame export. Source: `docs/plans/2026-09-03-external-text-execution.md:256-265`. Current `packages/plitejs/src/react/editable/editable-dom-runtime.ts:1023-1050` still schedules the immediate microtask export and the trailing frame. A scheduling optimization needs the caret-visible browser cases as well as its mount benchmark.

- **Suppress table selection paint at the table boundary.** A vertical drag from `Plugin` to `Heading` selected two projected cells, but its native row-major Range also crossed unselected `Element`, `Inline` and `Void` cells. CSS limited to selected cells therefore left native highlight visible. The fix suppressed selection paint across the table while preserving the native Range and canonical cell selection. Source: `docs/plans/2026-08-26-table-native-highlight-reporter-contradiction-regression.md:381-392`. Current `apps/www/src/registry/components/editor/table.tsx:371` retains table-wide transparent selection paint under `hasExpandedCellSelection`; the historical DOM selector has changed.

- **Scroll proof must include the rendered endpoint and its portaled controls.** Generate Markdown first passed an endpoint-only check while Accept/Discard/Try again escaped the bounded docs editor. The expanded browser oracle checked both vertical bounds of the endpoint and review menu against the same scrollport, exposing the missing menu containment. Current `apps/www/src/registry/components/editor/ai-menu.tsx` observes the rendered draft's size and centers its end marker inside the editor scrollport. Source: `docs/plans/2026-09-16-ai-continuation-render-recovery.md:517-575`. Transport completion and model content do not prove committed layout; this is an AI UI lesson, outside the editing spec's stated AI-workflow scope.

- **Installed style expansion does not style raw registry previews.** The floating link toolbar retained the correct `cn-popover-content` marker, and installed JSON expanded it correctly, but the website rendered the raw marker without its CSS and produced a transparent surface. Generate scoped preview rules from the same pinned style maps used for installation. Current `apps/www/scripts/registry-style-transform.mts` emits those rules, and `apps/www/src/app/globals.css` imports the generated stylesheet. Source: `docs/plans/2026-08-25-fix-floating-toolbar-border-regression.md:112-129`. Nova's visible edge is a ring and shadow, so checking border width alone would miss the intended surface.

- **Reject an unusable native caret rectangle at the geometry owner.** ControlOrMeta+K opened the Link store from an empty paragraph, but Chrome's collapsed Range on its `<br>` returned an all-zero rectangle, placing the mounted toolbar at the viewport origin. The rendered zero-width line had usable geometry. Current `resolveDOMRangeGeometry` in `packages/plitejs/src/react/range-geometry.ts` falls back to `[data-editor-zero-width]` and returns unavailable geometry when neither source is usable. Source: `docs/plans/2026-08-31-fix-floating-link-toolbar-in-empty-paragraph.md:294-317`. The former Widget API is removed; the fallback now belongs to range geometry, and Link must not invent coordinates.

- **Renderer callback classes arrive through attributes.** A renderer callback's caller classes live in `attributes.className`; adding or casting a top-level callback `className` invents a different contract. Current live and static `EditorElement` primitives merge attribute classes with their explicit presentation class (`packages/platejs/src/react/components/plate-nodes.tsx:145`, `packages/platejs/src/static/components/plite-nodes.tsx`). Source: `c70bacbd4a:docs/plans/2026-08-12-descriptor-owned-renderer-props.md:166-168`. The source calls these primitives PlateElement and PliteElement; their current names are EditorElement.

- **A type migration can change presentation through JSX spread order.** The descriptor-only refactor accidentally reversed heading class precedence; scoped review caught it and restored the original order. Current `apps/www/src/registry/components/editor/heading.tsx:31` supplies the variant class before spreading caller props. Source: `c70bacbd4a:docs/plans/2026-08-13-descriptor-owned-renderer-props-hard-cut.md:227-229`. Review runtime expressions and prop order even when the intended change is type-only.

- **Editable disclosure and exported disclosure need different DOM owners.** Details uses an explicit non-editable button in live editing and hides its direct body through Plite's content boundary with model copy, skipped selection and materialization. Static output uses native `details` and `summary` and retains every body child. Current owners are `apps/www/src/registry/components/editor/details.tsx:18-94` and `details-static.tsx:8-32`. Source: `docs/plans/2026-08-29-replace-toggle-with-semantic-details.md:266-281`. A body-wrapper model node is unnecessary when the renderer can cover a direct child range.

- **Move dynamic paint out of per-node transform callbacks.** Navigation and block placeholders once called hooks from injection transforms, requiring dummy calls on rejected nodes and waking every matching element for one target change. The repair gave the dynamic work a mounted lifetime and published attributes by NodeKey, while retaining pure document injection. Source: `c70bacbd4a:docs/plans/2026-09-04-cleanup-hook-bearing-render-injection.md:231-308`.

- **Try owner-local placement before subscribing to peer feature state.** Link read active Comment and Suggestion state only to choose toolbar placement, which also pulled those features into its registry install dependencies. - **Moving a controller must preserve hidden-to-open transitions.** Review of the registry-controller migration found that Link's `triggerEdit()` filled form state after the toolbar had been hidden but did not reopen it.
