# Performance diagnosis, part 2

## Where the time goes

- **A lazy identity index must not eagerly build an unrelated catalog.** The August audit found a complete element-type traversal during SnapshotIndex construction that the full-index counter did not count. Current `packages/plitejs/src/core/snapshot-index.ts:166-193` defers that catalog to ensureElementPaths. `packages/plitejs/test/document-change.test.ts:1079` counts construction reads, checks that a key lookup reads only its target, and exercises catalog demand separately. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:223-233`. Limit: test catalog-first and identity-first request orders; laziness must preserve both results and historical snapshots.

- **Batch immutable publication at shared ancestors.** Applying a canonical batch one text replacement at a time repeatedly copied the same wide root. The August repair resolved replacements against the immutable input, accumulated final leaf text in reverse offset order and published common ancestors through the existing grouped updater. Current `packages/plitejs/src/core/change/root-change.ts:2701-2745` retains the pure-text batch path and calls document.withNodeUpdates once. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:234-245`. Limit: overlapping, ambiguous or structural replacements keep their separate fallback; value equality alone does not prove identity, inverse or historical correctness.

- **Prepare schema property context only when a resolver asks for it.** The August Yjs event bridge indexed the old root even for text imports that never queried property policy. Current `packages/plitejs/src/yjs/core/event-change-bridge.ts:1547-1561` creates the context lazily and limits indexing to the event's changed source regions. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:246-255`; locality cases counted unrelated type reads and preserved named-root paths and later edits to untouched nodes. Limit: explicit full reconciliation remains a full-root job, and the historical Plate Yjs path has moved into Plite.

- **Reject an impossible DOM lookup before resolving model identity.** A headless clipboard copy built the complete identity index while looking for descendant DOM that could not exist. Current `packages/plitejs/src/dom/plugin/dom-editor.ts:1951-1953` handles direct editor-root lookup first, then returns null unless a connected Editable exists. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:277-284`; the regression traversed missing, disconnected, mounted and unmounted states. Limit: an early negative check must still allow a later mount to resolve the same node.

- **Skip a copy-policy walk when every policy preserves content.** The August clipboard audit found property traversal after the DOM lookup cost was removed. Current `packages/plitejs/src/core/editor-schema.ts:2864-2886` weakly caches whether the compiled schema has any copy transformation and returns the original children when none exists. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:285-292`; preserve/drop/preserve reconfiguration checked that the optimization followed the current immutable schema. Limit: schemas with drop policies still need their placement- and ancestor-aware traversal.

- **Co-located handles can share calculations without sharing mutable results.** Once unrelated Anchor dispatch was removed, many affected handles still mapped identical endpoints and repeatedly projected the same range. Current `packages/plitejs/src/core/anchor.ts:1552` memoizes mapping within the change using root, path, offset, identity, association and deletion options, then creates each handle's returned point. `packages/plitejs/src/range-projection.ts:10-23` weakly retains one last projection per immutable snapshot and copies caller ranges into the cache key. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:295`. Limit: mutable caller input and distinct endpoint options must never collide.

- **A lazy query can still hide a document-wide first read.** The July `commit.changed` implementation rebuilt both document indexes on its first classification query, so listener notification made an ordinary text commit expensive. The repair used verified per-root classification metadata while retaining canonical-change inspection as the fallback. Source: `c70bacbd4a:docs/plans/2026-07-18-plite-canonical-change-architecture.md:360`, `:376`. Current `packages/plitejs/src/core/commit.ts:843-875` checks canonical root changes and cached classification before deriving detailed property changes. Limit: this establishes the ownership lesson and current branch structure, not a fresh timing result.

- **Guard expensive arguments as well as the function that consumes them.** History recovery mapping can return immediately for an absent payload, yet eagerly constructing its document argument still performs unused work. The Phase 1 intervention removed six fallback projections while retaining seven commits, seventy-seven selector events and zero renders. Source: `docs/plans/2026-09-07-editor-performance-phase-1.md:212`, `history-counter-validation.json`. Current `packages/plitejs/src/history/history-plugin.ts` evaluates the current recovery mapping and its `change.apply(...)` argument only when `anchorCapture?.recovery` exists; `core/anchor-state.ts` also returns early for null recovery. Canonical history changes and actual anchor recovery remain required.

- **Share an identical per-handle query through the existing editor root.** Phase 2 removed repeated table-selection subscriptions from drag handles while preserving the table query, editor/view scope, optional-table behavior and cleanup. Its frozen production comparison established fewer callbacks with neutral latency, rather than a speedup. Source: `docs/plans/2026-09-07-editor-performance-phase-2.md:217-233`, `dnd-frozen-comparison-results.json`. Current `apps/www/src/registry/components/editor/dnd.tsx` keeps one table-cell-selection subscription in `DndRoot` and distributes the result through `TableCellSelectionContext`. This does not justify moving table algorithms or feature state into DnD.

- **Resolve an exact property before allocating prefix candidates.** The Phase 2 property resolver deleted eager prefix checks and candidate-array construction after a successful exact match. Its proof compared contextual, prefix and unmatched cases against the original resolver; matching an exact key still had to satisfy its target before returning. Source: `docs/plans/2026-09-07-editor-performance-phase-2.md:234-251`, `property-lookup-count-results.json`. Current `resolveCompiledSchemaProperty` in `packages/plitejs/src/core/schema-compiler.ts` checks exact candidates first and then the ordered prefix list. Exact-key precedence does not permit skipping contextual fallback when an exact candidate fails.

- **Delete a preparatory registry build only when no factory consumes it.** Schema reconfiguration originally built a declarative registry for API-factory context and then built the final registry, even when no installed definition had an API factory. Phase 2 removed that unused first build while preserving guarded factory context, validation and atomic publication. Source: `docs/plans/2026-09-07-editor-performance-phase-2.md:252-279`, `schema-reconfiguration-count-results.json`. The current owner is `prepareRecordPublication` in `packages/plitejs/src/core/plugin.ts`, which conditionally builds the preparatory registry when a definition has `api`. The plan's former `editor-extension.ts` path is obsolete.

- **Prove that correction setup runs before proposing a correction cache.** The Phase 2 inline-normalization diagnostic ran no extension corrections, while the correction-worklist diagnostic attributed at most 0.52% of even the transaction callback to route indexing. The apparent collaboration replacement time also included editor setup, so it could not identify replacement mapping as the sole cause. Source: `docs/plans/2026-09-07-editor-performance-phase-2.md:640-649`, `normalization-profile-01.json`, `correction-profile-01.json` and `collab-profile-01.json`. These are historical workload-specific negative controls, not a claim that correction setup is always negligible.

- **A second root-fitting pass needs a dependency that the first pass resolves.** Primary and explicitly declared roots already have their grammar, while projected roots can depend on owners installed by the first pass. Phase 2 therefore removed duplicate primary/declared fits and retained projected refitting, with nested child-before-owner and selection-mapping guards. Source: `docs/plans/2026-09-07-editor-performance-phase-2.md:680-699`, `fit-roots-candidate-probe-02.json`. Current `packages/plitejs/src/core/slice-fit/compiled-slice-fitter.ts` retains exactly that distinction. A focused migration gain did not itself close the complete schema command.

- **Use compiled membership for simple targets without replacing the contextual solver.** Phase 2 removed repeated general satisfiability calls when indexing null, type, types and group property targets. Its oracle required the complete serialized schema contract to remain identical, including ordering and fingerprint. Source: `docs/plans/2026-09-07-editor-performance-phase-2.md:700-709`, `schema-compile-membership-prototype-02.json`. Current `packages/plitejs/src/core/schema-compiler.ts` uses existing element/group membership for those simple cases. Parent, root and Boolean targets retain their independent contextual work.

- **Count component executions before accepting fewer subscriptions.** The first node-only element-selector prototype reduced global callbacks but replaced a derived row-index subscription with a full path subscription, adding eight row renders per Enter. Direct function-entry counters rejected it; Fiber commit flags alone were insufficient. The revised API kept node payload and derived path subscriptions separate and removed the extra renders. Source: `docs/plans/2026-09-07-editor-performance-phase-2.md:804-873`, `element-selector-render-results.json` and `element-path-profile-results.json`. Current `packages/platejs/src/react/stores/element/useElementSelector.ts` observes payload only, `usePath.ts` supports equality-filtered projections, and the registry table reads `usePath(path => path.at(-1))`. Fewer global callbacks do not prove less total render work.

- **Share native event transport without sharing selection state.** Per-root document listeners duplicated selection dispatch even when React rendered nothing. The repair shares one Document listener, resolves live roots through canonical DOM ownership, and includes previous owners so focus transitions finish correctly. Root selection state and schedulers remain independent. Current `packages/plitejs/src/react/editable/selection-change-listener.ts` retains the Document WeakMap, current/previous-owner routing and reference-counted cleanup. Source: `docs/plans/2026-09-08-editor-performance-phase-4.md:329-337`. Limit: transport locality does not establish native editing latency.

- **Returning null does not stop hidden positioning work.** FloatingToolbar previously acquired geometry while its output was hidden. Move positioning into a visible child while keeping dismissal, selection and overlay state in the existing parent. Current `apps/www/src/registry/components/editor/floating-toolbar.tsx:206-231` returns before mounting `PositionedFloatingToolbar`, which owns `useSelectionGeometry`. Source: `docs/plans/2026-09-08-editor-performance-phase-4.md:372-377`. Limit: verify positioning, focus and reopening separately; eliminated geometry calls alone prove no browser latency gain.

- **Coordinate-only reads should not construct keyed selection state.** Every table cell once rebuilt keyed geometry to obtain its row and column, although those answers needed only immutable topology. Phase 5 removed that projection and reused the existing geometry compiler. The current API has replaced getCellIndices: `cellAt` in `packages/platejs/src/features/table/lib/BaseTablePlugin.ts:1215-1233` resolves a known path through `createDetachedTableContext`, and `read.cell` sends path targets directly there. Source: `docs/plans/2026-09-09-editor-performance-phase-5.md:368-376`. Limit: keep keyed identity and selection jobs separate; this does not imply that all table work can use an unkeyed view.

- **An explicit node selector should not observe an unused parent context.** A memoized keyed selector rerendered when its parent's element context changed even though its own node was unchanged. Current `packages/plitejs/src/react/hooks/use-node-selector.tsx` conditionally calls React.use on ElementContext only for a null or undefined explicit key. Preserve inherited updates, keyed updates and transitions between both modes when deleting that dependency. Source: `docs/plans/2026-09-09-editor-performance-phase-5.md:394-398`. Limit: measured text-event counts cover that profiler family, not every React execution.

- **Deferred cache admission must preserve observable result identity.** The first decoration-cache sentinel prototype met timing budgets but broke immutable slice identity. The useful design keeps the first compiled slice, recompiles on reuse, retains the old slice only when complete equality holds, and then admits fully immutable input to the guarded fast path. Current `packages/plitejs/src/react/decoration-source.ts:647-740` retains that distinction between a slice-only record and an admitted source/input/path/root record. Source: `docs/plans/2026-09-10-editor-performance-execution.md:66-72`. Limit: first reads still validate and snapshot; mutable or getter-backed inputs must not gain an unsafe cache hit.

- **After reducing selection subscriptions, profile the complete toolbar endpoint again.** The September follow-through found that the retained table-context repair reduced selected-element checks and notifications, while React before-mutation work and Radix Presence animation-style reads still occupied the complete selection profile. That evidence motivated toolbar experiments rather than another selection-selector rewrite. Source: `docs/plans/2026-09-10-editor-performance-follow-through.md:246-249`, citing `e04-current-profile-top.json`. Current copied table UI still includes `TABLE_MULTI_SELECTION_TOOLBAR_DELAY_MS = 150` in `apps/www/src/registry/components/editor/table.tsx:97`; a selection-only clock omits a deliberate part of toolbar readiness. The profile is historical attribution, not a current latency measurement.

- **Split remote synchronization before choosing its optimization owner.** The June 14 donor Yjs investigation first separated local editing from remote synchronization, then separated update encoding from applying the update and running the receiving editor's import observer. That distinction prevented an import/readback problem from being assigned to update encoding. Evidence: `docs/plans/2026-06-14-yjs-research-mode-8h.md:593-596`; the corresponding trace oracle and repeated calibration are recorded at lines 597 and 602. Current `packages/plitejs/src/yjs/core/controller.ts:1778-1820` has an event importer with a separate full-diff fallback, so the old full-read/replace diagnosis is historical. The source does not pin the measured runtime revision, and its timings do not establish the current bottleneck.

- **Copy a lazy descriptor instead of chaining snapshot getters.** Forwarding each selection snapshot's index getter through the preceding snapshot accumulated a recursive chain and caused browser stack overflows. Copying the existing property descriptor preserves lazy construction without extending that chain; current `getSelectionOnlySnapshot` still does this in `packages/plitejs/src/core/public-state.ts:9991`. The historical browser reproduction used 1,000 proposals, while the Bun selection-session guard passed before the repair, so that guard did not establish the failure. Source: `docs/plans/2026-09-10-native-authored-changes-and-suggestions.md:588`, naming `execution/native-authored-deferred-index-red-1.log`. This is a snapshot-ownership lesson, not a current authored-performance measurement.

- **Use profiler packets for diagnosis and an uninstrumented packet for user latency.** The June 2026 pagination investigation found that recording profiler events could dominate selector-dispatch timings. Its retained distinction was diagnostic profiler-on runs versus profiler-off interaction measurements. The surviving runner still selects instrumentation through `PLITE_PAGINATION_REAL_OPS_PROFILER` (`benchmarks/slate-v2/donor/browser/react/pagination-virtualized-real-editor-ops.mjs:27`). Source: `docs/plans/2026-06-02-pagination-virtualized-stability-perf.md:229`. Limit: disabling instrumentation does not by itself establish source freshness, fixture parity or a comparable environment.

- **Read layout metadata without materializing a document snapshot.** The June 2026 pagination investigation found layout refresh requesting a full runtime snapshot merely to read its version, then extracting roots through the serializable document accessor. Use committed metadata and direct read-only root access when those supply the needed values. Current `packages/plitejs/src/pagination/index.ts:1677-1687` reads `state.children()` or `state.root(root)` and prefers `state.lastCommit()?.version`, with a snapshot fallback for initialization. Source: `docs/plans/2026-06-02-pagination-virtualized-stability-perf.md:232-233`. Limit: the plan's former `state.value.root` spelling is obsolete.

- **Page overscan can multiply expensive child work.** The May 27 pagination repair found that an implicit page buffer also widened table-row materialization. Bound expensive content separately from decorative page surfaces, and retain selected content explicitly instead of enlarging every viewport window. Source: `docs/plans/2026-05-27-pagination-fast-scroll-virtualization.md:13-22`. Current `packages/plitejs/src/pagination/react.tsx:1118-1192` requests zero-overscan visible items and adds selected or promoted paths separately. Limit: the historical `plite-layout` and `domStrategy` APIs have been replaced.

- **Plugin access reads the published schema instead of reevaluating its factory.** The #5066 repair removed schema-factory work from repeated plugin access (c70bacbd4a:docs/plans/5066-fix-homepage-typing-latency.md:318-319). Current packages/platejs/src/lib/plugin/createPluginContext.internal.ts resolves the compiled binding, and its spec, 'does not reevaluate published schema factories for plugin access', checks that twenty accesses add no evaluations. This protects repeated access after publication; it does not imply schema compilation itself is free.

- **Place graph closure at a schema boundary.** The September clipboard investigation rejected six rewrite-path candidates because eager closure failed its frozen stress budget. The surviving design retains immutable roots during pure rewrites and computes reachability at export and fitting. Current `packages/plitejs/src/core/content-slice.ts:396-428` preserves roots without walking their graph, while `core/editor-read-execution.ts:59-125` owns export closure. Source: `docs/plans/2026-09-13-clipboard-transfer-policy.md:167-178`. This explains the placement decision; it is not a current performance measurement.

- **Retain an already admitted immutable Blob instead of copying compressed input again.** The DOCX design's pathological cohort rejected a second compressed-byte copy, so retention moved to the package reader's existing Blob. Current `packages/platejs/src/docx/internal/source.ts:90` constructs the source with `blob: pkg.source` and separately clones the semantic baseline. Source: `docs/plans/2026-09-15-docx-retained-source-preservation.md:735-742`. This preserves the ownership lesson without treating the overwritten original benchmark receipt as current timing evidence.

- **Do not copy render-derived highlight targets into effect state.** NodeSelectionHighlight first rendered old targets and then committed again after a layout effect copied the new targets. Inline portals also rendered existing selected children again. Deriving targets during render and memoizing each portal removed that repeated work; an equality-guarded layout retry remains for a structural commit that replaces a portal host after render. Source: `docs/plans/2026-08-26-selected-node-render-performance.md:180-191`; current owner `packages/platejs/src/react/components/NodeSelection.tsx` retains all three mechanisms. The narrow owner improvement did not prove that the whole route stopped rerendering.

- **Select the identity a closed control needs.** The selected-node route kept rerendering after its highlight owner improved because TOC returned a fresh heading array on selection commits and the closed link toolbar observed the complete Range. The registry fix filters TOC to document commits and compares heading key, level and title; the link toolbar selects only a collapsed link NodeKey or null. Current `toc.tsx` and `link.tsx` retain those selectors. Source: `c70bacbd4a:docs/plans/2026-08-26-selected-node-rerender-fix.md:223-227,290-301`. The remaining text-toolbar transition was retained because it was bounded lifecycle work, rather than repeated selection-step work. No new query cache or public hook was needed.

- **Suppress equal drag selections where the derived target is known.** The August 2026 marquee diagnosis found two costs: a text toolbar mounting for a node selection, and a drag controller rereading every candidate rectangle and publishing equal selections on pointer frames. The durable repair kept one canonical selection authority, cached candidate geometry for the gesture, invalidated it on layout changes, and published only changed paths or direction; transient rectangle pixels moved imperatively. Source: `docs/plans/2026-08-26-block-selection-performance.md:290-301`. Current `packages/platejs/src/react/components/NodeSelection.tsx:480-569` retains this split, and `NodeSelection.spec.tsx:510-631` checks contraction, unchanged commit version and scroll-triggered remeasurement. The historical timing is recorded separately in the Plite performance home; these checks were inspected, not rerun.

- **A causal shortcut is not automatically a valid initialization fix.** The #5066 investigation isolated slow Plate startup to routing the initial document through a generic live replacement path. Direct adoption proved the owner but skipped preparation, identity, selection and normalization requirements, so it was rejected as a shipping fix. The kept repair provided a separate schema-publication bootstrap while preserving those laws. Source: `docs/plans/5066-benchmark-native-typing-regression.md:223-248,342-359`; current owners are `packages/plitejs/src/create-editor.ts:571` and `packages/platejs/src/lib/editor/withPlite.ts`. Keep the causal control distinct from the law-preserving implementation.

- **A capture-only win can reverse during mutation.** In the 2026-09-10 React selection-mutation run on Apple M5 Max, Chromium 149, Firefox 151 and WebKit 26.5, the Range arm materially regressed in 10 of 81 cohorts. WebKit's 10,000-line end-caret subtree-replacement cohort rose from 6.5039 to 41.6465 ms per cycle; mutation alone rose from 0.6387 to 35.2695 ms. The two-exit walker had 20 material improvements, zero material regressions and two inconclusive cohorts. Each primary arm used 32 warmups, 256 cycles and six balanced order packets; original blob `4b0dfb0bf2f9855ad1152f0abbe88907ee51f17a` and patch fingerprint `a8a0ce32e62a1cc49f004e521673d9741756d3e4ba5dfe6b01f36cc363e628fb` identify the historical algorithms. Source: `docs/plans/2026-09-10-react-selection-mutation-benchmark.md:161-165`, run `artifacts/2026-09-10-react-selection-mutation/summary.json`. Native guards matched 4,678 supported endpoint pairs; 365 WebKit pairs were unsupported. This rejected the Range recommendation, established no permanent leak and did not prove a production React replacement.

- **Batch publication before adding another saved-state cache.** The September 2026 authored reload repair found independent pending insertions repeatedly publishing wide immutable ancestor arrays. It grouped eligible restoration edits through the existing bulk change owner while leaving dependent, structural, inverse, property and custom-validator cases sequential. Removing a frozen-array check had missed the declared improvement threshold and was reverted. A concurrently changed baseline was also rejected, leading to immutable measurement bundles with source manifests. Source: `docs/plans/2026-09-12-authored-reload-performance.md:104-116`. This is a historical causal lesson: the current `authored/tree` implementation replaced that operation-graph restorer, so its old batching path is not current API advice.

- **Batching document edits can leave index publication incremental.** After the first authored reload repair batched document changes, each insertion still rebuilt immutable position-index paths and record pages. The third trial built one final position index for dense independent batches and retained incremental updates for sparse batches. Matched complete-load measurements isolated that remaining publication cost; nested profile totals were not added to their children. Source: `docs/plans/2026-09-12-authored-reload-prosemirror.md:127-139`, before/after bundle manifests differing in the former `positions.ts` and `decisions.ts`. Those owners were replaced by the current review-tree implementation; the reusable lesson is to count every derived structure's publications separately.

- **Cache topology at configuration lifetime, then remove hidden selector delay.** The read-view repair rejected a document-revision cache because it would rebuild on every keystroke, and rejected implicit double-animation-frame selector scheduling because it moved work while leaving UI stale. Current `packages/plitejs/src/core/public-state.ts:5490-5503` keys its one cached view by registry identity and transform generation; `packages/plitejs/src/editor-runtime-view.ts:1092-1104` caches a scoped projection by base-view identity; `packages/plitejs/src/react/hooks/use-editor-runtime-state.ts:68-86` updates directly from commit subscriptions. Plate's separate `packages/platejs/src/internal/plugin/mergePluginCapabilities.ts` owns capability-tree composition. Source: `docs/plans/2026-08-18-cache-editor-read-views-and-cut-hot-path-capability-rebuilding.md:231-266`. Configuration-scoped caching must not capture changing document values.

- **A thread-body edit need not republish collection membership.** The September Comments audit identified whole-map copying on every record edit as a separate cost from subscription targeting (`docs/plans/2026-09-04-comments-source-and-api-architecture-audit.md:255`). Current `setThread` mutates the private keyed Map, preserves thread-ID snapshots when membership and status do not change, and publishes the affected thread ID (`packages/platejs/src/features/comments/BaseCommentsPlugin.ts:665-724`). Limit: creation, deletion, resolution and draft-status changes can legitimately rebuild their affected membership lists.

- **A data-slice prototype can hide package setup costs.** The Comments prototype timed its data owner, but the production comparison also constructed the editor and projected initial annotations. That wider boundary exposed repeated cloning and freezing of plugin initialization data. The repair reused internally owned immutable data rather than adding another live store. Current `packages/platejs/src/internal/utils/mergePlugins.ts:292-374` retains branded immutable-data reuse and cloning for unowned input. Source: `docs/plans/2026-09-09-comments-package-data.md:123-126`. Prototype acceptance therefore did not transfer automatically to production, and neither run measures browser typing latency.

- **An owned immutable array can be one reuse boundary.** The Comments setup repair recursively copied and froze array descendants but stopped registering each descendant separately for reuse. Current `packages/platejs/src/internal/utils/mergePlugins.ts:328-341` passes `track: false` for array children and tracks the containing array; nominal plugin references still take their separate path. Source: `docs/plans/2026-09-09-comments-package-data.md:144-147`. This avoids duplicated ownership bookkeeping without granting caller-owned arrays automatic reuse or treating functions and opaque resources as inert serializable data.

- **Fewer compiler requests need not mean lower generation latency.** The August TS7 optimization tried restricting materialization queries to property-owning aliases and removing a concurrent semantic-diagnostics request. The former worsened warm-tail latency despite a small cold improvement; the latter worsened both lanes, so both trials were reverted. Current `packages/cli/src/typescript.ts:818-827` still collects semantic diagnostics concurrently with the other compiler results. Source: `c70bacbd4a:docs/plans/2026-08-13-optimize-plate-cli-ts7-codegen.md:239-266`. Limit: the plan does not pin an immutable measured revision, so its numerical timings are not retained as a reproducible performance baseline.

- **Include equivalent publication work in both transaction timers.** The prototype comparison initially timed publication on the editor side but omitted it on the candidate side, and later used a direct assignment instead of subscriber dispatch. The repaired comparison included one subscriber and commit publication in both paths, including serialized replay. Source: `c70bacbd4a:docs/plans/2026-07-17-wordgard-changeset-prototype-batch.md:309-322`. The current artifact at `f03d2b8c23:docs/plans/artifacts/wordgard-plite-rewrite-comparison/changeset-prototype-benchmark.json` still declares that symmetric workload in its `fairness` fields, but contains a later production run. Limit: this preserves the comparison lesson, not the prototype's reported speed ratios.

- **A hover selector's final target can invalidate unrelated large subtrees.** Removing the Tailwind compiler patch initially failed because component-owned selectors still ended in bare `span`, `div` or `svg` targets. The matched intervention isolated those targets, including styles for an unmounted component; changing the targets to specific classes restored the native code-block guard. Keep the interaction region on its actual owner: current media image and video figures target `.editor-media-resize-handle`, which also keeps captions inside the hover region (`apps/www/src/registry/components/editor/media-image.tsx:45`, `media-video.tsx:68`). Preserve legitimate theme and data-state descendant styling rather than banning every universal selector. Source: `c70bacbd4a:docs/plans/2026-09-10-tailwind-hover-selector-removal.md:172-179`; historical measurements are separate from current source inspection.

- **Bounded DOM does not rule out a startup replay.** In the May 2026 fork draft, pagination compared a stress-block count with a stress-page count, treated an already-loaded fixture as stale, and deleted and reinserted it on mount. Profiling traced normalization and path-reference work rather than excessive mounted page surfaces (docs/plans/2026-05-28-pagination-initial-load-performance.md:134-150). Current `apps/www/src/app/(app)/examples/plite/_examples/pagination.tsx` prevents initial stress replay by skipping the first reconciliation effect. Check fixture reconciliation before changing virtualization, and use model metadata for offscreen content rather than waiting for content that virtualization should omit. The original block-count guard has been replaced; no historical latency is asserted for today's implementation.

- **Check whether generic detachment copies data a codec already owns.** The September authored checkpoint initially paid a second deep copy after its codec had validated and detached the input. Moving ownership to the decoding boundary removed that duplicate work. Current `packages/plitejs/src/core/value-codec.ts:372-386,520-542` still distinguishes current-version decoders that validate and return owned JSON from ordinary decoders whose input is cloned first. Preserve validation and ownership checks when removing a copy. Source: `docs/plans/2026-09-12-authored-live-state-implementation.md:200-209`. The authored checkpoint format has since been replaced; this retains the ownership lesson, not its old performance guarantee.

## Benchmark validity

- **Keep a runtime locality verdict separate from a combined target's compiler verdict.** The August projected-clipboard repair removed repeated frozen-root validation from the value builder and stopped reading the entire document for a fixed-size slice. Its runtime work guards passed while the complete schema target still failed Plate compiler budgets. Current `packages/plitejs/src/core/public-state.ts:1909` builds values from canonical root arrays; the historical compiler result does not measure clipboard fan-out. Current `mapTextOffset` prepares the before/after indexes and `DocumentChange.between` once through the mapping context's `memoize`, keyed by the root and text identity (`packages/plitejs/src/core/anchor.ts:452-482`). Source: `c70bacbd4a:docs/plans/2026-09-03-plate-and-plite-rendering-safety-architecture.md:319,426-434`. The contract must bound construction work as endpoint count grows; the disposable browser target's timing is historical causal evidence, not a current product latency result.

## Table host measurement

- **An empty production Profiler result requires a different measured boundary.** September's table comparison received no production mount samples from React Profiler, so the harness measured wall-clock remount to second paint. Because it saved packet p95 values rather than raw remount timings, the final comparison reports a distribution of packet p95 values. Expanding the owner run also exposed a hard-coded sample-count assertion, which was replaced before rerunning. Source: `docs/plans/2026-09-17-table-selection-host-projection-design.md:288-292` and `2026-09-17-table-host-delivery-benchmark/final-comparison.json` (an uncommitted run file), `harnessRepairs` and `methodology`. These are measurement-contract lessons; neither zero samples nor a percentile of packet percentiles is a raw mount-latency percentile.

## Yjs lookup ownership

- **Share virtual-id resolution without inventing an unmaintained cache.** The June 12 traversal repeatedly scanned one Yjs tree to resolve virtual references. Its repair built an id resolver lazily and shared it within a traversal, because remote Yjs mutations could invalidate a persistent snapshot. Current `createLazyYjsNodeIdResolver` still lazily builds that fallback, but can instead borrow the maintained `RootProjectionIndex` through the document helpers (`packages/plitejs/src/yjs/core/document.ts:2470`; `packages/plitejs/src/yjs/core/root-projection-index.ts:148`). Source: `docs/plans/2026-06-12-yjs-optimization-strict-8h.md:456`. Cache lifetime needs an explicit mutation owner; the historical rejection of all persistent caching is not current policy, and this plan supplies no measured speedup.

## React Compiler

- **Compiler eligibility and compiler coverage answer different questions.** The August 2026 registry audit showed that every audited memoized body could compile, while development configuration disabled the Compiler and copied-code consumers had no enforced Compiler baseline. A diagnostic success therefore could not justify a performance claim for every runtime. Current `apps/www/next.config.ts:144` enables `reactCompiler: true`, replacing the old development exception. Source: `c70bacbd4a:docs/plans/2026-08-23-audit-registry-memo-and-display-names.md:186-200`. Limit: the www setting proves nothing about an arbitrary downstream app that copies registry code.

## Benchmark interpretation

- **A new composition or edit action needs a new matched packet.** The September 4 Lowlight comparison could not reuse September 3's core-Editor, JavaScript midpoint-burst result for an official React-example, TypeScript end-insertion claim. Standalone Tiptap trials also drifted enough to require rotating all three strategies through fresh contexts in one run. Keep cross-host navigation, mount and heap as support metrics when one host is a full Next product and another is a minimal example. Source: `docs/plans/2026-09-04-tiptap-lowlight-huge-code-benchmark.md:401-411`, with packet history at `:304-306`. Current `docs/plans/topics/code.md` still distinguishes native syntax from the optional CodeMirror adapter; this experiment did not isolate a Plate engine defect.

- **Extract replacement runs once, then query the shared result.** The comments repair rejected repeatedly deriving replacement ancestry for each target. Its ordinary-anchor candidate instead extracted replacement runs once per change and used binary intersection lookup. That mechanism remains in `packages/plitejs/src/core/change/document-change.ts:486-585`: a WeakMap caches runs by change and root, and `mapDocumentRangeReplacement` binary-searches the first overlap. Source: `docs/plans/2026-09-18-comments-attachment-discovery.md:423-448`. The plan's contended timing comparison stayed gated; the reusable result is the shared computation and lookup boundary.

- **A number copied into generated docs is still not a benchmark artifact.** The June performance-guide rewrite found its old comparison numbers only in authored docs and generated registry JSON. Repetition in generated output did not provide independent provenance, so the rewrite removed those snapshots and separated public-harness claims from the standalone Evidence Kit's different comparisons. Source: `docs/plans/2026-06-02-rewrite-performance-guide.md:175-203`; current owners remain `apps/www/scripts/run-editor-perf.mts` and `benchmarks/editor`. The plan's Plate-versus-"Plite" wording is rename-damaged: its `public-slate-vs-plate` command identifies the legacy Slate comparison. No old timing is promoted here.

## Structural edits

- **Resolve a planned selection after structural writes instead of repeatedly simulating it.** The September table insertion investigation first saw nested runtime-index timings that overlapped and therefore did not identify an exclusive cause. A matched follow-up isolated eager planner selection simulation; the surviving mutation path resolves plan.selection from the live transaction draft after all operations (packages/platejs/src/features/table/lib/internal/mutation.ts:1472-1487). Inspect the complete operation and preserve work/correctness parity before optimizing a lower-level index. The historical timings belong to the retained insertion and isolated unit-paste runs, not a current-source or browser latency claim. Source: docs/plans/2026-09-17-table-api-design.md:304-315.

## Code-block representation

- **Fewer model nodes do not guarantee faster native editing.** The September CodeLine prototype removed line nodes but rendered one giant DOM string; at 10,000 lines its five-character burst p95 was 634.6 ms, against 438.7 ms for CodeLines and 282.8 ms for a private bounded-string prototype. Decoration-based chunking also missed the normal DOM text-sync path. Source: `docs/plans/2026-09-02-remove-code-line-model.md:451-463` and its `huge-code-block-probe.json`, measured at `a6afd55c30e97c74fe895d1ad005ca75413110f3` with ten samples after one warmup on Playwright Chromium/Darwin arm64. Current `packages/platejs/src/features/code-block/lib/BaseCodeBlockPlugin.ts` keeps the one-Text model, while optional CodeMirror rendering has a separate adapter. Preserve the distinction between canonical representation and rendering cost; the discarded chunk prototype is not today's implementation.

## Benchmark evidence

- **An unrelated-import stub can recover diagnosis without recovering bundle evidence.** The August 2026 audit built a scratch candidate with inert stubs for 157 stale generated-registry imports. That let its selected runtime routes execute, but could not establish canonical cold loading or bundle size. Such a host must remain a scoped diagnostic; source generation and a replay against the real delivered build are separate obligations. The current app still composes generated registry sources, so repairing an import graph for a probe does not make it the shipped graph. Source: `docs/plans/2026-08-18-full-non-huge-mount-and-editing-performance-audit.md:299`.

- **Keep cold-mount findings separate from warm-route findings.** In the August 2026 non-huge audit, the first five mount samples ranked Excalidraw and List as regressions. Ten additional suspect-route runs and a full warmed pass reversed those findings because server, OS and route cold state dominated. Warming is not permission to erase cold cost: report cold and warm cohorts separately, and keep any unresolved cold-bundle claim open. Source: `docs/plans/2026-08-18-full-non-huge-mount-and-editing-performance-audit.md:300`, with the reconciliation at lines 142-143 and 335.

## Measurement boundaries

- **A production mount metric needs a producer that emits samples.** The table host comparison initially received no production Profiler mount samples. It replaced that empty metric with wall-clock remount-to-second-paint timing for both arms, then reported the distribution of packet p95s because raw mount samples were not retained. Deleting a surviving copied overlay changed the candidate again, so its browser packets were invalidated and rerun. Source: `docs/plans/2026-09-17-table-host-delivery-benchmark.md:253-267`; current `packages/platejs/src/react/features/table/tableSelectionHostBinding.internal.ts` retains the private binding architecture. An empty profiler output is not a zero-cost mount, and a percentile of packet percentiles is not a percentile of raw operations.

## Pagination virtualization

- **Retain the selected editing unit without retaining its whole page.** The June draft-Plite pagination optimization found that keeping an entire selected page mounted defeated scroll bounds after other rendering costs were reduced. Current `packages/plitejs/src/pagination/page-mount-plan.ts:168-180` combines visible item indexes with the selected top-level item. Source: `docs/plans/2026-06-01-pagination-virtualization-char-burst-perf.md:74-85`. Selection retention and visible-window planning need separate correctness checks; this source inspection does not establish today's end-to-end latency.

## Read invalidation

- **Measure cached follow-up work before accepting a cheaper first query.** The reads review rejected an uncached direct path-membership prototype even though one watched key at 8,192 paragraphs reduced index calls from 32,788 to two: its dense repeated read took 1.308 ms against 0.173 ms. The revised probe required zero index calls on repeated reads and kept the cache on the disposable commit reader. Source: `docs/plans/2026-09-11-reads-api-review.md:101-134`, with direct and cached packets named at lines 74-77 and the review anchored to `2e865a0bc4`. Current `packages/plitejs/src/core/commit.ts:1025-1044` caches membership per node key. The probe used warm primary-root indexes; it did not prove cold-index, native-ordering or complete mounted-runtime performance.
