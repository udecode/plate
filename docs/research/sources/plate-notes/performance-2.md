# Performance diagnosis, part 2

## Where the time goes

- **A lazy identity index must not eagerly build an unrelated catalog.** The August audit found a complete element-type traversal during SnapshotIndex construction that the full-index counter did not count. Current `packages/plitejs/src/core/snapshot-index.ts:166-193` defers that catalog to ensureElementPaths. `packages/plitejs/test/document-change.test.ts:1079` counts construction reads, checks that a key lookup reads only its target, and exercises catalog demand separately. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:223-233`. Limit: test catalog-first and identity-first request orders; laziness must preserve both results and historical snapshots.

- **Batch immutable publication at shared ancestors.** Applying a canonical batch one text replacement at a time repeatedly copied the same wide root. The August repair resolved replacements against the immutable input, accumulated final leaf text in reverse offset order and published common ancestors through the existing grouped updater. Current `packages/plitejs/src/core/change/root-change.ts:2701-2745` retains the pure-text batch path and calls document.withNodeUpdates once. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:234-245`. Limit: overlapping, ambiguous or structural replacements keep their separate fallback; value equality alone does not prove identity, inverse or historical correctness.

- **Prepare schema property context only when a resolver asks for it.** The August Yjs event bridge indexed the old root even for text imports that never queried property policy. Current `packages/plitejs/src/yjs/core/event-change-bridge.ts:1547-1561` creates the context lazily and limits indexing to the event's changed source regions. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:246-255`; locality cases counted unrelated type reads and preserved named-root paths and later edits to untouched nodes. Limit: explicit full reconciliation remains a full-root job, and the historical Plate Yjs path has moved into Plite.

- **Reject an impossible DOM lookup before resolving model identity.** A headless clipboard copy built the complete identity index while looking for descendant DOM that could not exist. Current `packages/plitejs/src/dom/plugin/dom-editor.ts:1951-1953` handles direct editor-root lookup first, then returns null unless a connected Editable exists. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:277-284`; the regression traversed missing, disconnected, mounted and unmounted states. Limit: an early negative check must still allow a later mount to resolve the same node.

- **Skip a copy-policy walk when every policy preserves content.** The August clipboard audit found property traversal after the DOM lookup cost was removed. Current `packages/plitejs/src/core/editor-schema.ts:2864-2886` weakly caches whether the compiled schema has any copy transformation and returns the original children when none exists. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:285-292`; preserve/drop/preserve reconfiguration checked that the optimization followed the current immutable schema. Limit: schemas with drop policies still need their placement- and ancestor-aware traversal.

- **Co-located handles can share calculations without sharing mutable results.** Once unrelated Anchor dispatch was removed, many affected handles still mapped identical endpoints and repeatedly projected the same range. Current `packages/plitejs/src/core/anchor.ts:1552` memoizes mapping within the change using root, path, offset, identity, association and deletion options, then creates each handle's returned point. `packages/plitejs/src/range-projection.ts:10-23` weakly retains one last projection per immutable snapshot and copies caller ranges into the cache key. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:295`. Limit: mutable caller input and distinct endpoint options must never collide.

- **A lazy query can still hide a document-wide first read.** The July `commit.changed` implementation rebuilt both document indexes on its first classification query, so listener notification made an ordinary text commit expensive. The repair used verified per-root classification metadata while retaining canonical-change inspection as the fallback. Source: `c70bacbd4a:docs/plans/2026-07-18-plite-canonical-change-architecture.md:360`, `:376`. Current `packages/plitejs/src/core/commit.ts:843-875` checks canonical root changes and cached classification before deriving detailed property changes. Limit: this establishes the ownership lesson and current branch structure, not a fresh timing result.

## Benchmark validity

- **Keep a runtime locality verdict separate from a combined target's compiler verdict.** The August projected-clipboard repair removed repeated frozen-root validation from the value builder and stopped reading the entire document for a fixed-size slice. Its runtime work guards passed while the complete schema target still failed Plate compiler budgets. Current `packages/plitejs/src/core/public-state.ts:1909` builds values from canonical root arrays; the historical compiler result does not measure clipboard fan-out. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:267-276` and its projected-clipboard-width-rerun receipt. Limit: report the complete target as failed even when retaining its independently proved runtime repair.

- **Pin the resolved JavaScript executable on both comparison sides.** The August integrated comparison first ran current code on Node 22 and legacy Slate through Yarn on Node 24, invalidating its relative results. The repaired launcher resolved one absolute executable, loaded the repository's PnP hooks explicitly and recorded executable, Node and V8 identities in both artifacts. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:397`, receipt `integrated-mixed-engine-invalid.json`; `final-proof.json` records matching Node 24.14.1/V8 identities. Limit: a later diagnostic that fails to reproduce an outlier neither explains it nor clears the original strict failure.

- **Readiness instrumentation must leave the measured path.** The June 2026 draft Plite cross-editor benchmark initially timed staged selection before its native surface finished mounting. Waiting for completion corrected the workload, but review then found that leaving the Plite-only metrics callback attached added observer work during measurement. Use instrumentation to establish readiness, then detach it before measuring the steady-state lane; measure cold activation separately. Source: `c70bacbd4a:docs/plans/2026-06-05-plite-two-hour-backlog-continuation.md:321-331`, `:455-466`. Limit: the staged renderer has since been removed; this is a benchmark-design lesson, not a current rendering recommendation.

- **A skipped build needs an identified output owner.** After another browser lane rebuilt the shared static output, a skip-build huge-document trace produced doubled DOM counts and misleading timings. A fresh build restored the expected surface. Reuse a build only when its source identity and ownership are established; interleaved lanes can invalidate an otherwise unchanged benchmark command. Source: `docs/plans/2026-06-05-plite-two-hour-staged-full-dom-experiments.md:387-392`, `:440-448`. Limit: the incident involved the donor checkout's static output, not a reproduced failure in today's app runner.

- **Settle setup and disposal independently for every comparison lane.** April 2026 draft Plite promotion and select-all rows looked slower than legacy Slate while focused default-renderer probes showed little promotion work and no typing renders. The comparison mixed old `act` behavior, queued mount/frame work and select-all measured after heavier lanes. Matching the renderer, preferring `React.act`, settling setup and disposal, and measuring select-all as an independent lane removed those confounders. Source: `docs/plans/2026-04-21-plite-hard-cut-transaction-runtime-architecture-plan.md:1030-1156`. Limits: this is a historical harness diagnosis; the old comparison script is absent from today's checkout, and its unpinned timing table is not a current speed claim.

## Keyboard hot paths

- **Classify a key before discovering content-root owners.** The May 2026 vertical-navigation review found that ordinary keydowns could scan content-root owners before the handler knew whether the key was relevant (c70bacbd4a:docs/plans/2026-05-25-plite-vertical-content-root-navigation.md:488-495). The current getContentRootNavigationTarget classifies the action and checks hasContentRootOwner before findContentRootOwners (packages/plitejs/src/react/editable/content-root-navigation.ts:1196-1210); hasContentRootOwner consults the compiled content-root capability (content-root-owners.ts:180-181). The package contract 'does not scan plain documents when looking for content-root owners' guards the fast path. This establishes an early no-scan exit, not constant-time navigation for documents that contain many roots.

## Comparable rendering workloads

- **Match highlight work before freezing a code-input budget.** The text-flow plan initially compared highlighted Plite with unhighlighted ProseMirror and Wordgard, producing an invalid 263.2 ms code ceiling. It reran both controls with the identical 40k-decoration packet and measured input separately from delayed highlight settlement (docs/plans/2026-09-02-plite-text-flow-benchmark-first.md:825,233-243). The resulting historical ceilings are not a general editor budget. A current comparison must match text, decorations and action, and must retain settlement time so scheduling cannot hide work.

## Benchmark harnesses

- **Check benchmark assumptions before changing the editor.** The June 2, 2026 regression sweep found three harness failures while the requested editor behavior passed: an editable-void fixture expected two shells after the example changed to one, pagination timing defaulted to Next development mode, and overlay warmup selected a block that was already active. The retained pagination runner opts into development mode only through `PLITE_PAGINATION_CHAR_BURST_DEV=1` (`benchmarks/slate-v2/donor/browser/react/pagination-virtualized-char-burst.mjs:20`), and the overlay picker excludes the initial active window (`huge-document-overlays.tsx:46-61`). Source: `c70bacbd4a:docs/plans/2026-06-02-plite-ar-perfect-regression-sweep.md:185-200`. These repairs establish the harness contract; their old smoke timings do not establish current product performance.

- **Equal text is not equal rendered work.** The September 3, 2026 rendering benchmark initially reported a false win because compared surfaces did not render the same mark wrappers. The corrected run gave production and control identical semantic mark renderers, rejected signature drift and alternated sample order. Source: `c70bacbd4a:docs/plans/2026-09-03-plate-and-plite-rendering-safety-architecture.md:156-162,322,488-496`. Current normal rendering still materializes mark and decoration segments through `compileTextFlowSegments` and `renderLeaf` (`packages/plitejs/src/react/components/editable-text.tsx:232,444-465`). A whole marked leaf and thousands of alternating mark runs are different DOM workloads even when their character counts match.

## Core hot paths

- **Share a text-pair change across mapped endpoints.** The September 2026 anchor investigation found that mapping many anchors rebuilt the same text change once per endpoint. Current `mapTextOffset` prepares the before/after indexes and `DocumentChange.between` once through the mapping context's `memoize`, keyed by the root and text identity (`packages/plitejs/src/core/anchor.ts:452-482`). Source: `c70bacbd4a:docs/plans/2026-09-03-plate-and-plite-rendering-safety-architecture.md:319,426-434`. The contract must bound construction work as endpoint count grows; the disposable browser target's timing is historical causal evidence, not a current product latency result.
