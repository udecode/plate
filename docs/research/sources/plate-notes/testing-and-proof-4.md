# Testing and browser proof, part 4

## Harness traps

- **A held-selection paint report needs pixels during the exact gesture.** The first table fix passed computed-style assertions and five repeated runs, yet the reporter still saw native highlight while the mouse was down. A horizontal drag had also missed the failing geometry. Replaying the vertical gesture with a held native Range exposed 3,023 changed pixels against an allowance of 82; controlled screenshots then distinguished the repaired paint from the false green. Source: `docs/plans/2026-08-26-table-native-highlight-reporter-contradiction-regression.md:393-412`, with the exact Chrome 151/macOS receipt at `:323`. Computed styles and cell counts diagnose state; they cannot certify visible paint, and a mouse-up screenshot cannot establish the held state.

- **Native timing needs a settled target and an explicit caret.** The #5066 gate initially used a route without an editable, relied on `End` to position the caret and measured before asynchronous playground setup stopped replacing the target. Its repair selected the equivalent real playground route, set the exact DOM caret, waited for host settlement and asserted model, DOM, focus, selection and trusted input counts. Source: `docs/plans/5066-benchmark-native-typing-regression.md:293-317,360-374`; durable owner: `apps/www/scripts` homepage-input runner. A route response and a successful key dispatch alone do not establish a comparable native-edit workload.

- **Do not let assertion transport change the gesture being tested.** Remote PR 5036 runs crossed the history merge interval because assertions sat between an import and its supposedly immediate typed follow-up. Other rows assumed pixel-exact vertical columns or blur after clicking non-focusable space, which differed across engines. Perform the immediate action before assertion round trips, and assert semantic path/root and rendered selection unless exact geometry is the contract. Use a real outside focusable control for a blur action. Source: `c70bacbd4a:docs/plans/5036-complete-pushed-ci.md:243-281`. This does not justify weakening an explicit caret, paint or timing requirement.

- **Counting generic overlays can miss a component-owned duplicate.** The first table selection proof counted generic selection portals, so a table that opted out of that portal still passed while painting its own outer rectangle over selected cells. Inventory every paint owner and compare captured pixels with correct single-layer, absent and intentionally duplicated controls. Current `table-selection.spec.ts:775-929` checks the wrapper-layer inventory and all three controls; its mixed-block drag cases also sample empty space beside the table. Source: `docs/plans/2026-08-26-table-cell-only-selection-paint-regression.md:399-410`. A zero generic-portal count alone says nothing about total painted layers.

- **Keep JSX development metadata out of document fixtures.** Browser closure of the July plugin-name migration exposed strict-schema failures caused by React's `__self` and `__source` attributes entering hyperscript-generated document data. Strip those attributes before constructing fixture nodes; weakening the schema would conceal a fixture-builder defect. Current `packages/plitejs/src/hyperscript/hyperscript.ts:56-57` still deletes both attributes. Source: `docs/plans/2026-07-20-camel-case-plugin-key-migration.md:296-306`. The surrounding media and decoration incidents are separate failures, not evidence that metadata caused them.

- **Regenerating registry output can invalidate an existing dev tab's error evidence.** During the Discussion demo rename, registry generation changed watched `public/r/registry.json` and produced transient missing-module HMR errors in the existing tab. A restarted dev process and fresh tabs then rendered the canonical block and docs example without warnings or errors. Source: `docs/plans/2026-09-02-restore-discussion-demo-identity.md:329-350`. This diagnoses that recorded run; it does not justify dismissing a new missing-module error without checking the final generated inputs and a fresh process.

- **A nearby entry path can miss the reporter's failing component topology.** For Plate #5086, the old regression opened the aggregate discussion-count trigger and passed. The reporter clicked the red removal text, which installed a text-derived Radix anchor and reproduced `removeChild` with the editor removed. Tightening the test to that exact entry path exposed the defect; final assertions checked text and card removal, editor survival, follow-up typing and runtime errors. Source: `docs/plans/5086-seeded-removal-suggestion-crash-regression.md:318-354,380-399`. The historical owner was conditional anchor topology in copied `block-discussion`, not suggestion acceptance. Current `apps/www/src/registry/components/editor/discussion.tsx` and the floating-popover bases replace that component, so the old stable-anchor patch is not current implementation advice.

- **A reduced review bundle can invent missing-file findings.** The July architecture review omitted unchanged root context from synthetic owner bundles, and the reviewer reported missing scripts and proof runners that existed in the real checkout. The run rejected those findings only after checking the live manifest and runner. Source: `docs/plans/2026-07-28-execute-editor-architecture-upgrades.md:296-317`. A bundle is a scoped review input; absence from that bundle is not evidence of absence from the repository.

- **A continuous hotkey session must not refocus between keys.** PR #5115's rich-text oracle used `locator.press()` repeatedly, introducing focus transitions that raced active-mark restoration and left italic enabled during underline typing. The repair focused once, used `page.keyboard` for subsequent shortcuts and typing, and asserted exactly one element per mark before checking its text. Current `apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:760-810` retains that sequence. Source: `c70bacbd4a:docs/plans/2026-08-30-pr-5115-feedback.md:252-281`; the retained commit was `c7c7658d75971ea1b4764e3c093cd54d889b973c`, with five retry-free Chromium repetitions and the exact eight-row, two-worker batch recorded. This was an interaction-delivery repair, not evidence of a deterministic rich-text runtime defect.

- **Visible server output is not a mounted editor.** The Comments browser helper started native typing after static records became visible but before hydration completed, changing the DOM before React attached. The repair reused the browser editor harness's readiness check while preserving real input and the original outcome assertions. Current `apps/www/tests/browser/comment.spec.ts:181-190` waits through `createBrowserEditorHarness(...).ready(...)`. The same investigation found suggestion actions manually focusing the editor while the outer popover already owned focus restoration, closing the discussion; current `apps/www/src/registry/components/editor/discussion.tsx:670-694` applies decisions without that manual editor focus. Source: `docs/plans/2026-09-09-comments-package-data.md:127-131`. Readiness and focus ownership are separate causes and need separate checks.

- **Browser text assertions must exclude rendering-only characters.** Repairing trailing-newline layout made the shared blockTexts helper report the display-support newline as document content. The repair reads declared logical string lengths from cloned DOM before collecting block text, preserving the live editor DOM. Source: `docs/plans/2026-09-02-wordgard-diff-proof-closure.md:302`. Current `packages/test/src/playwright/dom-text.ts:7-29` trims data-editor-string nodes carrying data-editor-length. This helper proves logical block text; it does not prove the physical trailing line exists, which still needs the layout-engine regression.

- **Measure the frame the visual claim names.** The retained-deletion repair initially sampled caret geometry immediately after an arrow and mistook a pre-paint DOM sample for visible drift. Capturing the first animation frame from the input event resolved the diagnosis while retaining the strict alignment and single-caret checks. Source: `c70bacbd4a:docs/plans/2026-09-14-retained-deletion-editing.md:174`. Current `apps/www/tests/browser/suggestion.spec.ts:1712-1785` similarly installs its first-frame capture before typing, scheduling it from `beforeinput` because handled typing cancels the native input event. Limit: the current case checks suggestion paint; it does not preserve the retired retained-caret implementation or prove device IME behavior.

- **Correct text geometry does not prove correct selection paint.** In the local Chromium reproduction of #5091, the selected text shrank after a font-size dropdown choice while the inactive highlight retained its previous width. Browser screenshots and text geometry isolated the defect to the dropdown's focus handling; a model-format assertion alone would have passed. Source: `docs/plans/5091-fix-stale-font-size-selection-highlight.md:257-270,310-317`. Current `apps/www/src/registry/components/editor/font-size-toolbar-button.tsx` uses the later toolbar-overlay interaction architecture, so retain the visual diagnostic, not the old unconditional focus call as a current implementation recipe.

- **Correct Range geometry does not prove correct selection paint.** In #5091, changing selected Playground text from font size 16 to 10 updated the marks and DOM Range while Blink kept the old highlight width. A toolbar-focus diagnosis therefore tested the wrong layer. Measure painted selection pixels against an unselected clone with matching computed styles as well as reading the model and Range. The retained browser case, `tooling/e2e/font-size-selection.test.ts:532`, includes pixel analysis and settled-paint checks. Source: `docs/plans/5091-stale-selection-geometry-after-font-size-change.md:225-228`, `:267-271`. Limit: the original evidence was local Chromium; this compilation did not rerun the case.

- **Assert transient UI in the phase that owns it.** The first pushed-ref #5113 replay passed four runs and failed a toolbar assertion before the second drag began. With product bytes frozen, moving the assertion into the held-drag interval passed five local runs. A setup click does not prove the toolbar state required while the primary button is held. The retained case is `apps/www/tests/browser/selection-drag-scroll.spec.ts`, which records pointer and scroll state across the gesture. Source: `docs/plans/5113-ship-native-selection-autoscroll-fix.md:229-235`, `:240-255`. Limit: the plan records the corrected harness's local result; it does not record completion of the final corrected pushed-ref replay.

- **A stubbed response can hide a broken demo encoder.** AI Comment's existing browser case selected a plain paragraph and supplied a stubbed response, while the real demo interpolated quoted command text into invalid JSON and showed no result. The actual endpoint case exposed the failure; dynamic comment events now use `JSON.stringify` in `apps/www/src/lib/ai-chat-demo.ts:501`. Source: `c70bacbd4a:docs/plans/2026-09-17-ai-comment-regressions.md:53-54,65-77`. Keep a real endpoint case when response construction is part of the product path. The first transient hydration observation was not proved to have the same cause.

- **Do not normalize actual output until a broken insertion passes.** Affinity's `normalizeAdjacentText` comparator hid adjacent-leaf splits caused by the draft Plite insertion wrapper bypassing its text-insertion owner when marks were pending. Removing the comparator made the product defect visible. Current `packages/platejs/src/lib/plugins/affinity/AffinityPlugin.spec.tsx:47` compares children directly; `packages/plitejs/src/editor/insert-text.ts` routes insertion through `applyInsertText`, whose transform resolves compatible marked insertion points. Source: `c70bacbd4a:docs/plans/2026-06-30-affinity-normalize-adjacent-text-cleanup.md:44-55`. The old raw-operation normalizer restriction is historical; retain strict product output and the canonical insertion owner.

- **An alignment repair must also preserve wrapping width.** The draft-Plite pagination regression measured text before and after a projected paragraph switched to native flow. Adding the missing 2 px inset repaired the left coordinate but initially narrowed the wrapping area by 2 px; review required compensating width and a separate `wrapWidthPreserved` assertion. Source: `docs/plans/2026-05-30-fix-pagination-virtualized-selection-shift.md:69-82`. Current pagination uses the consolidated package renderer rather than the plan's example-local padding branch. Retain the two geometry assertions as a proof lesson, not the obsolete CSS patch.

- **A movement fixture must start away from its expected destination.** The table pass corrected a collapsed-selection fixture that already sat at the expected endpoint, so a no-op could pass its movement assertion. The repaired case moved from cell 21 to cell 22. Source: `docs/plans/2026-03-15-phase-4-table-execution.md:44`. Current table tests live under `packages/platejs/src/features/table/lib`; the old `moveSelectionFromCell` helper is retired. Retain distinct initial and final positions whenever a test claims a navigation command moved the selection.

## Ownership and type checks

- **Do not invent an inference repair for an uncaptured compiler failure.** The literal-option task reported four errors, but the owning typecheck passed before any edit and all three focused specs passed. The parent confirmed no intervening generic repair and accepted non-reproduction instead of a speculative change. Source: `c70bacbd4a:docs/plans/2026-07-24-core-plugin-literal-inference-closure.md:252-269`. The original failing state was unavailable, so shared-checkout timing or declaration state remained a possible explanation, not an established root cause.

- **Assignable API access does not prove discoverable API keys.** The full-editor inference regression allowed some explicit nested accesses while IntelliSense omitted installed APIs. The durable contract therefore checks missing keys, phantom keys and whether `string` has widened the key union, as well as representative methods. Those assertions remain in `apps/www/src/__tests__/package-integration/core-runtime/editor-api-inference.contract.ts:5-72`. Source: `c70bacbd4a:docs/plans/2026-07-24-plate-full-inferred-editor-api.md:255-267`, with the permanent-fixture repair at lines 285-288. - **An inference migration needs emitted declarations and cold consumers.** The July generic-removal migration made optional Indent and Node ID inputs required until feature declaration builds caught the narrowed domains. A warm www cache then hid a List render-wrapper incompatibility that `tsc --incremental false` exposed; cold package integration separately exposed expansion of an AI transaction callback. - **Check inference again in emitted consumer declarations.** The unified-authoring migration passed direct callback inference while generic Media and published List declarations still failed overload selection or lost dependency witnesses. Package source checking therefore did not establish the published inference contract; exact declaration builds caught failures that required owner-level generic repairs. - **Check whether a fixture uses the contract that fails inference.** Moving a Selection fixture into its constructor rejected a partial plugin API. The fixture never used that API's `set`; its assertion concerned only `selectedIds`, so deleting the fake API fixed the type failure without an annotation or cast. Source: `c70bacbd4a:docs/plans/2026-07-25-apply-constructor-first-extend-cleanup.md:269-270`, with the precise failure and resolution at line 298. Limit: the old Selection fixture and package layout are gone from current packages/platejs/src; retain the fixture-design lesson, not its deleted API.

- **A command-contract check must reject flags split across commands.** The typed-lint checker initially accepted its two required flags anywhere in one script, so separate Oxlint invocations joined by `&&` falsely satisfied an atomic command requirement. The negative regression required the executable and both flags in the same command segment (`c70bacbd4a:docs/plans/2026-08-22-simplify-typed-oxlint-lane.md:257-261`). This is a historical checker failure and a reusable adversarial case; it does not establish that a general substring scan understands shell syntax.

- **A documentation code checker must recognize the document's fence grammar.** A checker that sees only backtick fences silently excludes tilde-fenced examples, and a shorter nested fence must not close a longer outer fence. Current `extractJavaScriptCodeFences` in `tooling/scripts/check-plate-doc-code-contracts.mjs:203-245` matches the closing marker type and requires sufficient closing length. Source: `docs/plans/2026-09-05-comments-improve.md:78`, which records two failing parser cases before the repair. A clean checker result certifies only examples its parser actually discovers.

- **A call-site audit must include generic and multiline syntax.** The July plugin-stage audit's first regex missed `.extend<{...}>` calls. A Babel AST call manifest and a separate literal-token cross-check exposed the omission; a production-only checker also could not establish coverage of fixtures and loaded teaching examples. Source: `docs/plans/2026-07-25-audit-all-plugin-extend-stages.md:307-317`. Limit: its reconciled counts describe the July snapshot, not today's source inventory; the reusable result is the coverage check.

- **Execute generated consumer fixtures during an API migration.** The plugin-store migration found obsolete `.plugins` and `.options` calls embedded inside generated release-consumer source only when the packed-artifact gate executed that source. A source-name audit alone had missed those consumers. Source: `c70bacbd4a:docs/plans/2026-07-26-migrate-plugin-options-to-plugin-stores.md:201-203`, with the historical NodeNext, Bundler and runtime proof recorded at lines 262-264. This is a lesson about executable distribution proof; those package counts and fixture spellings are historical.

- **Prove a composed resource's capability instead of its object identity.** The DOCX kit repair initially compared Lowlight objects, but plugin resolution cloned the runtime object. Its stronger regression checked that the final resource still contained the TypeScript grammar registered by the earlier kit after a later renderer override. Source: `docs/plans/2026-08-15-restore-docx-export-kit-composition.md:198-207`. Current `packages/platejs/src/internal/plugin/resolvePlugins.ts` still snapshots plugin initial state, and `pluginSourceResolution.spec.ts:100-140` verifies that composed state preserves earlier fields and drives final capabilities. The old DOCX kit was later removed; the reusable lesson is semantic composition proof, not preserving that kit API.

- **Importability, execution host and declaration dependencies are separate proofs.** The August 2026 entrypoint work initially treated a React reference in Excalidraw declarations as a React runtime dependency. Separating declaration closure from runtime loading removed that false failure (docs/plans/2026-08-28-entrypoint-runtime-proof-generation.md:178-200). - **Source typechecking does not prove declaration emit can name an inferred export.** The August 2026 plugin-chain sweep passed source typechecking but failed declaration emit with TS7056 on the complete Code Block and Code Highlight chains, including their React adapters. A review caught an unsupported claim that only one stage was needed and required exact direct-emit evidence (c70bacbd4a:docs/plans/2026-08-03-inline-one-use-plugin-chains.md:212-240). Current `packages/platejs/src/features/code-block/lib/BaseCodeBlockPlugin.ts` exports both base plugins directly, so the old private-stage workaround is obsolete. Keep source checking and declaration building as distinct evidence when changing inferred public exports; do not turn one compiler version's workaround into a permanent API rule.

## Package boundaries

- **Prove a headless entrypoint through its emitted local import closure.** A clean entry file can still reach React through a generated chunk. Scope forbidden runtime packages to the headless entrypoint, traverse local imports, reject missing chunks and package subpaths, and leave React sibling entrypoints legal. Current `tooling/scripts/check-package-build-artifacts.mjs` derives root boundaries from export maps and reports the import trace; `tooling/config/direct-package.config.mts` forwards configured boundaries. Source: `docs/plans/2026-08-23-plate-base-runtime-boundary.md:268-296`. Source greps and browser editing smoke do not prove this artifact boundary.

## Proof width
