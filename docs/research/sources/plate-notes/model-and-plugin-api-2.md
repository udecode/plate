# Model, plugin and history API, part 2

## Model and transforms

- **A semantic cell variant need not duplicate the cell grammar.** The separate header-cell plugin duplicated the ordinary cell's schema, codecs and rendering while differing in its tag and discriminator. One cell with `header?: boolean` keeps arbitrary HTML header placement without imposing GFM's first-row rule on the document model. Current `packages/platejs/src/features/table/lib/BaseTablePlugin.ts:340-407` declares the property, decodes `<th>` into `header: true`, chooses `<th>` or `<td>` on HTML export, and claims Markdown header preservation only when the property matches row-zero position. Source: `docs/plans/2026-08-03-hard-cut-table-cell-header-plugin.md:190-199`. Markdown's positional limitation does not define Plate's richer HTML model.

- **Migration versions identify persisted boundaries, while private phases preserve implementation order.** The migration cut removed unreleased v55/v56 steps because they represented implementation batches rather than released data contracts. It folded profile conversion, final AST and code-line flattening into v54, while keeping private phases. Selection must follow those phases in order: a later code-line mapper needs the document produced by earlier structural changes. Source: `docs/plans/2026-09-03-hard-cut-plate-migrations-after-v54.md:222-237`. Current `packages/platejs/src/migrations/migratePlateV54.ts` exports `migrateV54`, shapes the document through private phases and maps selection between successive documents. Its comment explains that one diff across renaming and restructuring stages can replace everything between them. The old public spelling `migratePlateV54` is historical.

- **A canonical commit type does not prove a canonical write path.** The July rewrite reported immutable change ownership while ordinary writes still executed operations and reconstructed changes afterward. Re-reading the writer, selection mapper, configuration publisher and consumer stores reopened the supposedly completed work (`docs/plans/2026-07-18-wordgard-plite-full-architecture-ledger.md:295-318`). Current native construction lives in `packages/plitejs/src/core/change/builder.ts`, and text insertion calls that builder through `applyBuiltDocumentChange` (`src/transforms-text/insert-text.ts:185-193`). When checking such a migration, trace an ordinary write through publication and inspect the replaced owners; a new public type and green closure ledger alone cannot establish ownership.

- **Convergence can still lose an independent property edit.** The July change representation replaced a node's whole property token and resolved concurrent replacements by bias, so edits to different keys converged while discarding one valid edit (`docs/plans/2026-07-19-wordgard-plite-final-extraction.md:152`). Current `packages/plitejs/src/core/change/transform.ts:105-114` transforms modifications by key and preserves an earlier modification when the later key differs. `packages/plitejs/test/document-change.test.ts:2732` guards independent element and text keys. Check preservation of both intents alongside convergence; same-key conflicts still need their own explicit policy.

- **Root-owner provenance must survive clones and ordinary path shifts.** The July root-owner index initially relied on object identity and relocation history. A text clone followed by a sibling shift then produced a stale conflict path. Reuse the canonical complete-change path mapper and retain the owner's path origin through index updates. Current `packages/plitejs/src/core/element-owned-root-index.ts` uses `appendCanonicalDocumentPathMapping` and `mapCanonicalDocumentPath` for rebasing and lookup. Source: `docs/plans/2026-07-21-wordgard-plite-schema-contribution-architecture.md:1018`. Relocation-only evidence cannot establish the path after every canonical change.

- **Removing a validation fallback requires repairing every publication boundary that supplied its authority.** The July full-scan fallback cut exposed initial no-op publications and nested command specs that lacked a validated baseline. The repair assigned initial documents, outer transactions and configuration publication their explicit validation responsibility. Current `packages/plitejs/src/core/editor-schema.ts:4921-4935` rejects incremental changes whose immutable baseline lacks the active validation authority and directs external inputs through `assertDocument()`. Source: `docs/plans/2026-07-21-wordgard-plite-schema-contribution-architecture.md:1020`. Restoring a hidden full scan would conceal the missing boundary and reintroduce document-wide work.

- **Persist child-root identity explicitly.** The May Plite draft replaced the canonical island's independent nested editor with a root view of the same runtime, but distinguished persisted `childRoots[slot]` identifiers from its ephemeral runtime-identity fallback. A root key that works during one mounted session is not automatically a persistence contract. Source: `docs/plans/2026-05-24-plite-editable-islands-multi-root-execution.md:178-184`. Current `useChildRoot` prefers explicit element root references and otherwise derives `core:child:${nodeKey}:${slot}`; its documentation still limits that fallback to ephemeral roots (`packages/plitejs/src/react/hooks/use-plite-child-root.ts:12-77`). The current editable-voids example stores the body reference on its element and renders that root in the same runtime. Limit: this establishes identity authoring, not copy remapping or collaboration compatibility.

## Plugins and types

- **A scoped update facade carries policy into one root update.** Adding tagged descriptor-scoped commands must preserve the root transaction boundary rather than open an untagged or nested update. Current `packages/platejs/src/lib/plugin/createPluginContext.internal.ts:497-526` resolves the scoped method inside one callback and invokes `editor.update` once, with either that callback or the policy and callback. Source: `c70bacbd4a:docs/plans/2026-08-04-hard-cut-generic-plugin-mutations.md:139-154`; the plan records focused history, rollback and delegation proof at lines 237-239. The historical feature CRUD inventory is not part of this lesson.

- **Removing handwritten AST mirrors can expose schema-owner defects.** The August sweep found widened validated JSON, an Image codec persisting undeclared `title`, and Table fixtures treating installed element IDs as Table-owned fields. Repairing those owners removed the need for local property bags. Current `packages/plitejs/src/interfaces/schema.ts:74` and `:132` carry and recover exact property values; `packages/platejs/src/lib/plugin/pluginNodeTypes.ts:154-176` derives element/text property capabilities, and `features/media/lib/image/BaseImagePlugin.ts:155` declares `title`. Source: `c70bacbd4a:docs/plans/2026-08-06-hard-cut-handwritten-ast-mirrors.md:162-176`. Derive owned shapes, compose cross-plugin properties explicitly, and keep runtime narrowing for open or malformed input.

- **Application schema policy can invalidate descriptor-only command inference.** The CLI ownership review found that overrides or application properties can rewrite the shapes generic commands accept. Raw editor types therefore cannot promise descriptor-derived exact mutations in those cases. Current `packages/platejs/src/lib/editor/pluginRuntimeTypes.ts:1566-1603` detects policy distributively across schema unions and marks policy-bearing editors; `internal/editor/generatedEditorTypes.ts:40-63` supplies the optional exact generated mutation contract. Source: `docs/plans/2026-08-14-hard-cut-plate-cli-runtime-ownership.md:279-290`. Test union branches and empty generated maps as well as a single non-empty schema; the detector now also considers root policy.

- **A cursor-data type needs a runtime validator at the network boundary.** Replacing caller-selected cursor result generics with an extension-level generic alone would still let callers assert the shape of untrusted awareness data. Current `packages/plitejs/src/yjs/core/types.ts:43-63` requires a validating `YjsCursorDataSchema` for a narrowed cursor-data type; `core/awareness-adapter.ts:363` validates incoming data, and `core/controller.ts:344-345` supplies that validator. Source: `docs/plans/2026-08-15-hard-cut-caller-selected-read-update-generics.md:202-205`. Input-derived inference and runtime admission must share the same owner.

- **Removing an explicit generic does not close a bivariant callback escape.** The caller-generic cut still accepted an explicitly annotated transaction containing fabricated capabilities because the update callback was bivariant. Review caught the hole and added a negative annotation contract. Current `packages/plitejs/src/interfaces/editor.ts:2012-2036` declares update authors as ordinary function parameters whose transaction comes from installed plugins. Source: `docs/plans/2026-08-15-hard-cut-caller-selected-read-update-generics.md:208-211`. Check explicitly narrowed callback annotations as well as rejected type arguments.

- **Separate renderer composition from imperative synchronization.** The August table review found single-consumer hooks returning renderer state and events, including values their caller ignored. Existing plugin reads already supplied the semantics; only subscription, selection attributes, caret restoration and cleanup needed an imperative owner. Source: `docs/plans/2026-08-17-hard-cut-table-renderer-hooks.md:169-233`. Do not preserve a broad public state bag merely because one part performs necessary synchronization. The intermediate public `useTableSelectionDOM` hook was later removed: current `docs/plans/topics/table.md:5-14` assigns selection paint to a private binding on canonical cell hosts. This is an ownership lesson, not advice to restore the hook.

- **A sibling slot receives its lifecycle ref, not the host's prop bag.** The sibling-render cut replaced broad Editable and container props with the exact mounted ref, allowing copied floating UI to register complete components directly. Source: `c70bacbd4a:docs/plans/2026-08-31-hard-cut-sibling-render-props.md:1-59`. Current `packages/platejs/src/react/plugin/PlatePlugin.ts:101-123` declares only `editableRef` or `containerRef` for these sibling contracts. `EditorContentView.internal.tsx:292` and `:310`, and `PlateContainer.tsx:58` and `:76`, pass those exact refs. This contract concerns sibling placement; wrapping slots separately receive children.

- **A cleanup correction can hide an overly permissive schema declaration.** The July Plate adapter copied every non-element plugin's element properties onto every element. Indent then removed the property from nodes it never intended to support (`docs/plans/2026-07-20-wordgard-plite-schema-architecture.md:241-246`). Current `packages/platejs/src/features/indent/lib/BaseIndentPlugin.ts:86-95` contributes `indent` with `schema.elementProperty` and an explicit `target.types(targetElementTypes)`. Fix property placement at declaration and admission; keep corrections for relationships that property targets cannot express.

- **Cache schema structure without retaining another configuration's live validator.** The July schema audit found that equal persisted declarations could reuse a compiled entry containing an earlier validator function. Separate the structural cache from configuration-local validation resources and rebind those resources on reuse. Current `packages/plitejs/src/core/schema-contribution-registry.ts:39-44` strips runtime validations before caching, and its merge path rebinds the current declarations; `schema-compiler.ts:5445` implements the rebinding. Regression cases in `packages/plitejs/test/schema-compiler.test.ts:2194` and `:2273` cover changed live validation, including a nested descriptor. Source: `docs/plans/2026-07-21-wordgard-plite-schema-contribution-architecture.md:727-740`. Equal persisted identity permits structural reuse, not reuse of arbitrary live functions.

- **Delete a redundant runtime bridge after checking its callers and its replacement owner.** The July React cleanup found that Plate's keyboard API had no callers outside its bridge and its test, while Plite already owned editable keyboard handling. Moving the old plugin wholesale would have preserved a second runtime owner; the plan instead cut the bridge and kept app handlers on the editable component. Source: `docs/plans/2026-07-04-plite-react-runtime-cleanup-plan.md:173-186`. Current `packages/platejs/src/react/editor/getPlateCorePlugins.internal.ts` composes Plite's React plugin without keyboard dispatch, and `packages/plitejs/src/react/editable/keyboard-input-strategy.ts` owns the user-handler and default-strategy path. Limit: the historical caller inventory establishes why the cut was chosen; this reader inspected current source but did not rerun browser proof.

- **A DOM primitive and the product policy that calls it can have different owners.** The React cleanup kept operation-triggered auto-scroll in Plate while leaving the scrolling primitive in Plite; moving everything that touches the DOM into Plite would also move Plate's product policy. Source: `docs/plans/2026-07-04-plite-react-runtime-cleanup-plan.md:214-218`. Current `packages/platejs/src/lib/plugins/dom/DOMPlugin.ts` owns the enabled change kinds, first-or-last target choice and scoped `autoScroll` transaction wrapper, then calls `editor.api.dom.scrollIntoView`. Limit: this preserves the ownership lesson, not the plan's old package paths or an assertion that Plite has no other scrolling capabilities.

- **Extract a semantic subsystem rather than every pure helper.** The Python grammar extraction found that grammar construction, aliases and registration belonged together; purity alone did not justify a generic `utils.ts`, and unrelated code-block regexes stayed with their commands. The original private package adapter was later removed, but the grammar family remains together at the current resource-construction boundary in `apps/www/src/registry/components/editor/code-block-lowlight.ts`, using types derived from Lowlight's `LanguageFn`. Evidence: `docs/plans/2026-07-28-code-block-pure-utility-ownership.md:487-501`. Retain the ownership lesson, not the obsolete package path or hidden highlighter mutation.

- **Keep public generic precision without forcing it through every runtime registry.** The April fork draft's generic migration found that making every internal editor method fully generic caused TypeScript variance failures. It retained value-derived public contracts while allowing broader internal runtime boundaries. Current Plite still distinguishes `Editor<V, TPlugins>` from the internal existential `AnyEditor` boundary and uses bivariant callback contracts (`packages/plitejs/src/interfaces/editor.ts:739-741`, `:2116-2130`). Source: `c70bacbd4a:docs/plans/2026-04-26-plite-plate-generics-type-system-plan.md:12-48`. Limit: this supports an explicit internal boundary, not erasing types in public APIs; the April declaration layout is historical.

- **Derive mark types from the editor's text type.** Replacing ambient node types with an editor value generic leaves a hole if marks remain `Record<string, any>`. The April fork draft explicitly closed that hole instead of copying the old Plate marks alias. Current `EditorMarks<V>` derives a partial mark object from `ValueText<V>` with `text` omitted, and `EditorMarksOf<E>` derives the value from the editor (`packages/plitejs/src/interfaces/editor.ts:2217-2222`). Source: `c70bacbd4a:docs/plans/2026-04-26-plite-plate-generics-type-system-plan.md:99-118`. Limit: this is a typing guarantee; it does not establish runtime schema validation.

- **A callback is justified when it supplies inference that a static descriptor loses.** The July API audit rejected its first descriptor-owned command recommendation after checking the installed-editor generic contract. It also retained advanced schema factories because they provide configured types and candidate-installation context. Current Plite still accepts a `commands(context: PluginCommandContext<TEditor>)` callback and either a schema declaration or `PluginSchemaFactory` (`packages/plitejs/src/interfaces/editor.ts:3347-3370`). By contrast, Plate's input-rule definition is an array, without the old builder-injection factory (`packages/platejs/src/lib/plugins/input-rules/types.ts:346-348`). Source: `docs/plans/2026-07-22-plite-plate-agent-native-api-shape-audit.md:269-308`. Limit: this preserves specific inference-bearing callbacks; it does not justify injecting globally importable builders into arbitrary callbacks.

## History

- **Carry replay identity with inserted content rather than absolute paths.** The NodeKey cut first restored history keys from absolute-path metadata. A skipped sibling edit moved those paths and revived the wrong identities. The repair attached runtime-only keys to inserted token slices so change composition and transformation could carry them with the content. Current `packages/plitejs/src/core/change/tokens.ts:324-335` stores slice keys in a WeakMap, outside serialized slice data, and `core/snapshot-index.ts:1113` maps changed node keys. Source: `c70bacbd4a:docs/plans/2026-08-08-hard-cut-node-keys-and-persisted-element-ids.md:451`. Replay proof must include skipped structural edits and named roots, not only immediate undo.

- **An array offset is not a causal checkpoint for shared effects.** The July Yjs transport used an append-only array with a numeric read cursor, which could miss or replay effects under concurrent ordering (`docs/plans/2026-07-19-wordgard-plite-final-extraction.md:153`). Current `packages/plitejs/src/yjs/core/shared-effect-log.ts` records event IDs, source sequences, acknowledgements and checkpoints; `src/yjs/core/controller.ts:1059-1075` acknowledges pending event IDs after application. The retry contract in `packages/plitejs/test/yjs/admission-lifecycle-contract.spec.ts:368` requires a failed effect to remain unacknowledged and apply exactly once after retry. Delivery and compaction must preserve that identity-based accounting.

- **Root presence is history state, separate from root contents.** In the May Plite draft, replacing children could create a missing root, but undo without presence information restored an empty orphan root instead of removing the root. History must distinguish an absent root from a present empty root. Source: `docs/plans/2026-05-24-plite-editable-islands-multi-root-execution.md:176-177`. Today's `DocumentChange` carries separate `createRoots` and `deleteRoots` sets and detects presence with own-property checks, independently of the root's text changes (`packages/plitejs/src/core/change/document-change.ts:1011-1014`, `:1093-1141`). Limit: the May `replace_children` metadata is retired; this source check does not constitute a fresh undo/browser run.

## DOM scope ownership

- **Expose editor DOM scope as elements, while keeping product wrappers in Plate.** The July 2026 cleanup found that Plate's generic `containerId` mixed application markup with editor runtime ownership. Plite now supplies separate root, editable and scroll element reads; its React hooks subscribe to DOM-scope changes through `useSyncExternalStore`, and custom scroll registration uses a ref callback (`packages/plitejs/src/react/hooks/use-editor-dom-scope.ts:1-75`, `packages/plitejs/src/dom/plugin/dom-editor.ts:2063-2074`). Plate's `EditorContainer` composes that scroll ref with its product wrapper ref and retains plugin render slots (`packages/platejs/src/react/components/PlateContainer.tsx`). Source: `c70bacbd4a:docs/plans/2026-07-04-plite-dom-scope-execution.md:190-192`. Keep raw registry setters internal; ordinary HTML ids and product wrapper refs remain application or Plate concerns.

## Editor construction

- **Initialize the document before constructing readers of it.** In the May 4 fork draft, `<Plite initialValue>` seeded the editor during provider render, but projection stores could read a snapshot before that render. Examples therefore needed a manual replacement transaction before creating their stores. Moving initial data into editor construction removed that ordering trap. Source: `docs/plans/2026-05-04-plite-react-editor-initialization-value-ralplan.md:7-12`, `:106-141`. Current `packages/plitejs/src/create-editor.ts:279` applies initial data during construction, `src/react/hooks/use-editor.ts:29` describes one-time seeding, and `src/react/components/plite.tsx:164` gives `EditorRoot` no initial-value prop. The draft's `usePliteEditor`, singular `withEditor` and wrapper typing are historical; current creation uses `useEditor` and plugins.
