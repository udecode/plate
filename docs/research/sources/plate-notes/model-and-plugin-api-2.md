# Model, plugin and history API, part 2

## Model and transforms

- **A semantic cell variant need not duplicate the cell grammar.** The separate header-cell plugin duplicated the ordinary cell's schema, codecs and rendering while differing in its tag and discriminator. One cell with `header?: boolean` keeps arbitrary HTML header placement without imposing GFM's first-row rule on the document model. Current `packages/platejs/src/features/table/lib/BaseTablePlugin.ts:340-407` declares the property, decodes `<th>` into `header: true`, chooses `<th>` or `<td>` on HTML export, and claims Markdown header preservation only when the property matches row-zero position. Source: `docs/plans/2026-08-03-hard-cut-table-cell-header-plugin.md:190-199`. Markdown's positional limitation does not define Plate's richer HTML model.

- **Migration versions identify persisted boundaries, while private phases preserve implementation order.** The migration cut removed unreleased v55/v56 steps because they represented implementation batches rather than released data contracts. It folded profile conversion, final AST and code-line flattening into v54, while keeping private phases. Selection must follow those phases in order: a later code-line mapper needs the document produced by earlier structural changes. Source: `docs/plans/2026-09-03-hard-cut-plate-migrations-after-v54.md:222-237`. Current `packages/platejs/src/migrations/migratePlateV54.ts` exports `migrateV54`, shapes the document through private phases and maps selection between successive documents. Its comment explains that one diff across renaming and restructuring stages can replace everything between them. The old public spelling `migratePlateV54` is historical.

- **A canonical commit type does not prove a canonical write path.** The July rewrite reported immutable change ownership while ordinary writes still executed operations and reconstructed changes afterward. Re-reading the writer, selection mapper, configuration publisher and consumer stores reopened the supposedly completed work (`docs/plans/2026-07-18-wordgard-plite-full-architecture-ledger.md:295-318`). Current native construction lives in `packages/plitejs/src/core/change/builder.ts`, and text insertion calls that builder through `applyBuiltDocumentChange` (`src/transforms-text/insert-text.ts:185-193`). When checking such a migration, trace an ordinary write through publication and inspect the replaced owners; a new public type and green closure ledger alone cannot establish ownership.

- **Convergence can still lose an independent property edit.** The July change representation replaced a node's whole property token and resolved concurrent replacements by bias, so edits to different keys converged while discarding one valid edit (`docs/plans/2026-07-19-wordgard-plite-final-extraction.md:152`). Current `packages/plitejs/src/core/change/transform.ts:105-114` transforms modifications by key and preserves an earlier modification when the later key differs. `packages/plitejs/test/document-change.test.ts:2732` guards independent element and text keys. Check preservation of both intents alongside convergence; same-key conflicts still need their own explicit policy.

- **Root-owner provenance must survive clones and ordinary path shifts.** The July root-owner index initially relied on object identity and relocation history. A text clone followed by a sibling shift then produced a stale conflict path. Reuse the canonical complete-change path mapper and retain the owner's path origin through index updates. Current `packages/plitejs/src/core/element-owned-root-index.ts` uses `appendCanonicalDocumentPathMapping` and `mapCanonicalDocumentPath` for rebasing and lookup. Source: `docs/plans/2026-07-21-wordgard-plite-schema-contribution-architecture.md:1018`. Relocation-only evidence cannot establish the path after every canonical change.

- **Removing a validation fallback requires repairing every publication boundary that supplied its authority.** The July full-scan fallback cut exposed initial no-op publications and nested command specs that lacked a validated baseline. The repair assigned initial documents, outer transactions and configuration publication their explicit validation responsibility. Current `packages/plitejs/src/core/editor-schema.ts:4921-4935` rejects incremental changes whose immutable baseline lacks the active validation authority and directs external inputs through `assertDocument()`. Source: `docs/plans/2026-07-21-wordgard-plite-schema-contribution-architecture.md:1020`. Restoring a hidden full scan would conceal the missing boundary and reintroduce document-wide work.

- **Persist child-root identity explicitly.** The May Plite draft replaced the canonical island's independent nested editor with a root view of the same runtime, but distinguished persisted `childRoots[slot]` identifiers from its ephemeral runtime-identity fallback. A root key that works during one mounted session is not automatically a persistence contract. Source: `docs/plans/2026-05-24-plite-editable-islands-multi-root-execution.md:178-184`. Current `useChildRoot` prefers explicit element root references and otherwise derives `core:child:${nodeKey}:${slot}`; its documentation still limits that fallback to ephemeral roots (`packages/plitejs/src/react/hooks/use-plite-child-root.ts:12-77`). The current editable-voids example stores the body reference on its element and renders that root in the same runtime. Limit: this establishes identity authoring, not copy remapping or collaboration compatibility.

- **A target-dependent write guard runs after transaction target resolution.** The April editor-method sweep found that insertText checked read-only and void policy against the command's requested location or live selection before resolving the transaction target (docs/plans/2026-04-26-plite-core-editor-method-regression-sweep.md:27). Current applyInsertTextCommand resolves tx.resolveTarget, performs content landing, and only then calls shouldIgnoreTarget (packages/plitejs/src/editor/insert-text.ts:109-139). Validate the location the transaction will actually edit, because an earlier implicit selection can be stale. Limit: this describes the insertion guard, not every command's validation order.

- **Reconsider a node changed by a correction, and detect repeated transitions.** The May structural-delete plan required transformed nodes to reach a fixpoint and conflicting normalization to fail deterministically (docs/plans/2026-05-07-plite-core-structural-delete-normalization-ralplan.md:40-43). Today's semantic correction runtime observes changes, remaps pending targets and enqueues affected content; it rejects repeated transition fingerprints and exhausted mutation budgets (packages/plitejs/src/editor/correct-document.ts:307-395). The retained tests turn heading into paragraph and then apply a second correction, and reject a structural correction cycle (packages/plitejs/test/normalization-contract.ts:971-1019). Limit: these are correction contracts; the old normalizeNode API and its implementation are gone.

- **Check command metadata inside an already open update.** In the draft fork's April 2026 runtime, command context was captured only when a transaction began. A command invoked inside an existing `editor.update()` therefore edited correctly but lost its commit metadata. Source: `c70bacbd4a:docs/plans/2026-04-25-plite-editing-epoch-kernel-regression-closure-plan.md:1101-1169`. The current mechanism adds `semantic-command` to the active transaction before applying the command result (`packages/plitejs/src/core/command-registry.ts:420-439`); `packages/plitejs/test/transaction-contract.ts:747` retains the nested-update case and checks the tag and changed text range. Limit: the plan's `lastCommit.command` payload is historical; the current contract checks commit tags and changed ranges.

- **Keep fragment extraction separate from shared-property aggregation, and preserve missing values.** The July hook-local rewrite duplicated generic fragment unwrapping and changed property aggregation by filtering away missing values. Current Plite owns recursive `fragment({ unwrap })` extraction (`packages/plitejs/src/core/get-fragment.ts:12-46`), while Plate owns `getFragmentProp` and its block/text/all modes (`packages/platejs/src/lib/utils/getFragmentProp.ts:12-68`). Empty input returns the default; a missing property in block or text mode returns the default; conflicting defined values return undefined. The React selector composes those owners without a second traversal algorithm (`packages/platejs/src/react/utils/useSelectionFragment.ts:8-20`). Source: `docs/plans/2026-07-06-plite-selection-fragment-helpers.md:73-130`. Limit: all mode intentionally skips missing properties rather than applying the block/text missing-value rule; the old package layout and second hook consumer are historical.

- **Keep panel visibility separate from document content by default.** A request to reveal hidden content is an app UI reaction, so opening an accordion or activating a tab need not become a shared document edit. The current hidden-content example keeps visibility in app query state and context, and its onMaterialize callbacks update that state (`apps/www/src/app/(app)/examples/plite/_examples/hidden-content-blocks.tsx:54-83`, `:510-523`, `:614-624`). Plite supplies the boundary and reveal request; an app that wants shared visibility must model that policy explicitly. Source: `c70bacbd4a:docs/plans/2026-05-26-plite-hidden-dom-blocks-api-plan.md:577-629`. Limit: this is the example's ownership pattern, not proof of a particular collaboration provider's behavior.

- **Snapshot immutability includes selection point paths.** Draft Plite's April 2026 text fast path published a mutable transformed selection, and the first repair still needed shared point/range helpers to freeze nested point paths as well (`docs/plans/2026-04-15-plite-decoration-wave-9-execution.md:66-73`). Check every publisher when a fast path bypasses ordinary snapshot materialization; freezing only the outer range is insufficient. Current snapshot publication clones selections through `cloneFrozenEditorJsonValue` (`packages/plitejs/src/core/public-state.ts:9891`, `:9998`), whose recursive JSON snapshot routine freezes nested arrays and records (`packages/plitejs/src/core/value-codec.ts:300-350`). The April publisher layout is historical.

- **Preserve laziness when a query needs only one answer.** The May 2026 fork draft retained generator traversal but examples defeated it with `Array.from(...)[0]`; `nodes.find` and `nodes.some` made the intended first-match and boolean operations explicit (`c70bacbd4a:docs/plans/2026-05-14-plite-node-query-api-ralplan.md:9-44`). Current implementations consume only the first yield of `getNodes`, while `entries` remains a generator (`packages/plitejs/src/core/public-state.ts:5970-6064`). The contract at `packages/plitejs/test/query-contract.ts:1541` counts two predicate visits for each helper when the first child matches, including the root visit. That proves early exit for this fixture, not constant-time lookup or a timing guarantee. Here the plan's v2 and pre-June Plite names refer to the fork draft; legacy Plite means legacy Slate.

- **Resolve live targets through editor identity, not persisted-ID scans.** The July recovery separated mutation callbacks, which can pass a captured node directly, from algorithms that actually need a current path (`c70bacbd4a:docs/plans/2026-07-09-plite-node-target-and-matcher-recovery.md:404-416`). Current `resolveNodeTargetLocation` reads the node's editor-owned key and resolves that key through the live index (`packages/plitejs/src/core/public-state.ts:2189-2232`). Contracts preserve a target through immutable writes and moves, accept an inserted target later in the same transaction, and ignore detached or foreign nodes (`packages/plitejs/test/transforms-contract.ts:1499-1618`). A structural clone is not a live target. Limit: current mutations can route live targets across roots, whereas `read.nodes.path` is root-scoped; the plan's blanket wrong-root no-op advice must not be carried forward.

- **Make owned-root lifecycle a document transaction, not a rendering effect.** The May 2026 draft Plite example could render same-runtime child roots but required callers to replay a raw replace-children operation to create one. The plan exposed root lifecycle as ordinary transaction authoring so creation and owner insertion could happen together and remain visible to history. Source: `docs/plans/2026-05-25-plite-void-roots-and-editable-islands.md:215-258`. Current `packages/plitejs/src/interfaces/editor.ts:990-1002` retains roots.create, roots.replace and roots.delete; `test/content-root-lifecycle-contract.test.ts` checks exclusive/shared ownership and cascading removal. Limit: current schema ownership is richer than this draft's single-slot proposal, and editable-island no longer exists.

- **Count the federation work before replacing shared roots with independent editors.** Independent editors simplify local React containment but require another coordination layer for cross-selection, history, clipboard, focus and collaboration. The May 2026 draft Plite roots plan rejected one editor per block for a feature that required shared document behavior. Source: `docs/plans/2026-05-25-plite-void-roots-and-editable-islands.md:356-393`. Current Plite retains schema-declared contentRoots, a useContentRoot helper and explicit root-boundary navigation rather than independent editor creation (`packages/plitejs/src/interfaces/schema.ts:335-347,413-416`, `react/hooks/use-plite-content-root.ts`, `react/editable/content-root-navigation.ts`). Limit: this is a scope-specific ownership lesson, not a claim that independent editors are always inappropriate.

- **A text edit can also change selection metadata.** The April 2026 fork draft reported selectionChanged as false for insert-text commits even though their before and after selections differed. A focused metadata assertion exposed the defect; classifying only the operation kind had hidden it from history and rendering consumers. Current `packages/plitejs/src/core/public-state.ts:8628-8634` derives selection change from explicit selection writes, root changes and before/after selection equality. Source: `c70bacbd4a:docs/plans/2026-04-23-plite-perfect-architecture-master-plan.md:1960-2082`. Limit: operation arrays and the old history package are historical; the lesson applies to metadata derived from current canonical transactions.

- **Put model edit policy on the semantic edit owner.** After cutting `Editable onCommand`, the table example moved Backspace, Delete and Enter containment into `onKeyDown`. That made a model rule keyboard-only, leaving native beforeinput and programmatic edits able to bypass it. The May 18 repair used transform middleware; current examples express the same ownership through `definePlugin` command handlers: the table plugin handles `editorCommands.delete` and `editorCommands.insertBreak`, while its `onKeyDown` handles Tab navigation (`apps/www/src/app/(app)/examples/plite/_examples/tables.tsx:177`, `:208`). Source: `docs/plans/2026-05-18-plite-table-transform-boundary-ralplan.md:54-125`. Limit: retain the ownership lesson, not the obsolete `defineEditorExtension({ transforms })` call shape or the plan's blanket rejection of public commands.

- **Expected absence and callback failure need separate query paths.** A catch around an entire optional query also catches a user's matcher failure and can report `undefined`, `false` or an empty collection instead of the bug. The June 27 investigation identified this in ancestor, last-node and materialized collection reads (`c70bacbd4a:docs/plans/2026-06-27-plite-strict-path-safe-queries.md:370-375`). Current Plite guards readable locations before iteration, then lets callbacks run outside a catch (`packages/plitejs/src/core/public-state.ts:3582`, `:5996`); `above.ts` and `last.ts` likewise use targeted existence checks. The contract 'does not hide query callback failures behind safe collection results' pins thrown find/some matchers (`packages/plitejs/test/state-query-contract.ts:600`). Limit: the plan's non-optional public path API and private helper design were later replaced, so keep this error-boundary lesson without restoring those call shapes.

- **Enforce read purity at the write authority boundary.** In April 2026 a compatibility transform reached raw operation application without passing the transaction wrapper, so guarding the wrapper alone still allowed a write from `editor.read`. The failing compatibility-transform contract led to a guard on raw application too (docs/plans/2026-04-24-plite-post-closure-proof-hardening-plan.md:829-849). The current owner is `assertCanStartEditorWrite` in `packages/plitejs/src/core/public-state.ts:1804`, called when starting the write at `:11334`; it rejects a write started inside a read and a write without update authority. Audit every route into mutation authority when adding a write entry point. The old `Transforms` and `editor.apply` paths are historical, not current public APIs.

- **Safe reads distinguish absent content from invalid input and callback failures.** The first June 2026 safe-read patch missed collection and point helpers, including levels, next, previous and positions; a follow-up runtime probe found the remaining throws (c70bacbd4a:docs/plans/2026-06-27-plite-safe-read-api-completion.md:226-240). The durable fix checks location shape and existence before calling the query, rather than catching arbitrary exceptions: current `packages/plitejs/src/core/public-state.ts:2107-2173` validates paths and returns absence for missing nodes, while `:2506-2585` applies that boundary to child, leaf and point reads. `packages/plitejs/test/state-query-contract.ts:441` checks optional reads and malformed locations, and `:600` checks callback-error propagation. The historical `{ required: true }` overload is gone; preserve the distinction, not that retired option.

- **A committed update must not look rejected because an observer threw.** The August publication repair found that authoritative state had already published when an extension commit observer threw back to the caller. Isolate post-publication callbacks, report their owner and phase, continue later observers and test a follow-up update. A pre-publication transaction participant instead aborts the draft. Evidence: `c70bacbd4a:docs/plans/2026-08-21-plite-publication-architecture-closure.md:131-176`. Current `packages/plitejs/src/core/public-state.ts:10960` wraps public observers, and `core/plugin.ts` wraps plugin commit, node-change and text-change listeners. This describes those callback boundaries, not every possible exception after publication. The current lifecycle reporter also has a default reporting fallback, unlike the historical host-only reporting limit.

- **Resolve a relative insertion's reference inside the target root.** The July block-relative insertion review caught explicit-root loss and a partially rooted range lookup: routing only the final mutation still lets the reference lookup choose a block in the wrong document. The review added sibling-root and partially rooted range regressions. Evidence: c70bacbd4a:docs/plans/2026-07-13-execute-plite-block-relative-insertion-api.md:174-219. Current tx.blocks.insert resolves the reference and calls landAfter inside runTargetMutation, or inside runWithMutationRoot for a node selection, in packages/plitejs/src/core/public-state.ts:7246-7381. The old insertAfter name is retired; preserve the shared root scope for lookup and mutation when changing the current insertion API.

- **Replace the semantic target through one Plite mutation, then read the draft.** The July 2026 replacement sweep found package-local remove/insert bridges, but also found that legacy `children: true` meant replacing a parent's children rather than replacing the parent. Review caught a streamed multiblock replacement split across writes and a code-block caret calculation reading committed state after a write. Current Plite's `replaceNode` delegates to `replaceChildren` with `count: 1` (`packages/plitejs/src/core/public-state.ts:7450-7518`), and the code-block rule reads `tx.points.start(match.path)` after mutation (`packages/platejs/src/features/code-block/lib/CodeBlockRules.ts:38`). Choose exact-node versus child-range replacement by semantics, and read the active transaction after changing it. Source: `c70bacbd4a:docs/plans/2026-07-13-plite-exact-node-replace-sweep.md:506-515`. Limit: the July raw-operation representation is historical; today's mutation records use DocumentChange.

- **Editor detection must not validate the edit log.** The May 2026 draft investigated Slate #5977, where custom operation records made editor detection fail and then broke DOM path lookup. Identity detection and validation of data to replay are separate boundaries. Today's `isEditor` checks the private runtime or an editor-shaped `id` and `read.runtime.snapshot`; it does not inspect an operation list (`packages/plitejs/src/editor/is-editor.ts:1-29`). Source: `c70bacbd4a:docs/plans/2026-05-07-plite-operation-extensibility-validation-ralplan.md:82-102`. Limit: this retains the detection lesson only; the plan's Operation guards and proposed operation registry belonged to the draft and are not today's public API.

- **Decide whether a mark is being disabled before applying exclusions.** The July toolbar repair found that clearing mutually exclusive marks before testing the target could remove unrelated marks or re-enable the target when the clear list contained it (c70bacbd4a:docs/plans/2026-07-06-plite-marks-toggle-clear.md:464-474). Current packages/plitejs/src/editor/toggle-mark.ts removes an active target directly and applies schema canonicalization when enabling it. Preserve that branch order when changing exclusion handling. The old caller-supplied clear option is historical; current exclusions come from the schema.

- **Selection helpers read the active draft.** The April draft already documented collapse before implementing it, and the important repair was reading the live selection inside an outer transaction (c70bacbd4a:docs/plans/2026-04-07-plite-op-family-eighth-slice.md:11-19). Current collapse.ts, set-point.ts and set-selection.ts under packages/plitejs/src/transforms-selection use getCurrentSelection; packages/plitejs/src/core/public-state.ts resolves the active transaction context before committed selection. The nested-update cases in packages/plitejs/test/snapshot-contract.ts exercise collapse, directional setPoint and move. A helper tested only after a commit can miss this stale-read bug.

- **Property-update support needs a round trip through publication.** The April draft lacked setNodes, but the deeper defect was that its draft and snapshot model discarded custom node properties; adding only a transform wrapper would have hidden the missing data contract (c70bacbd4a:docs/plans/2026-04-07-plite-op-family-second-slice.md:11-23). Current packages/plitejs/src/transforms-node/set-nodes.ts carries property changes into the document writer, and packages/plitejs/test/snapshot-contract.ts:3029 checks custom element and text properties after replacement and snapshot publication. That replacement case does not alone prove every mutation, split or fragment path; check the paths a property-changing feature actually uses.

- **Limit an insertion before publishing its correction.** The July 2026 length-limit review rejected Plate's post-apply trimming because late cleanup can disturb selection and history; it placed local insertion admission in Plite and kept imported replay outside that local policy (`c70bacbd4a:docs/plans/2026-07-02-plite-length-limit-ownership.md:310-314`). Current `packages/plitejs/src/core/insert-limit.ts:71-89` computes remaining capacity after subtracting the text being replaced, and Plate forwards constructor `maxLength` in `packages/platejs/src/lib/editor/withPlite.ts:1045`. The proposed Editable override was later cut; this lesson supports insertion admission, not a validator that truncates every imported document.

- **Mapped-location APIs distinguish lifetimes, not parallel implementation names.** The August anchor cut removed the duplicate transaction `refs` vocabulary: persistent `editor.anchor` handles require release, while `tx.anchor` returns a resolve-only handle that expires with its transaction (`docs/plans/2026-08-23-unify-plite-selection-anchors.md:137-145`). Current `packages/plitejs/src/core/public-state.ts:7542` registers the underlying handle in `scopedAnchors` and checks transaction activity before resolution; transaction cleanup releases the set at `:1094`. Anchor and selection mapping still share `getRangeEndpointAssociations` through `core/anchor.ts` and `core/selection-protocol.ts`. This preserves distinct lifecycle owners while preventing policy drift; it makes no native-selection claim.

- **Replacement selection follows reused node identity, not equal content.** The July replaceChildren repair removed the need for a blockquote-local path mapper: when selected descendants are reused inside replacement children, Plite can locate those same objects at their new paths; equal-looking duplicates are not evidence of identity (`docs/plans/2026-07-07-plite-replace-children-selection-repair.md:232-246`). Current `packages/plitejs/src/transforms-node/replace-children.ts` uses `findNodeReferencePath`, retains text or node selections when their replaced targets can all be mapped, clears unresolvable wholly replaced selections, and honors an explicit `newSelection`. Other selections follow canonical change mapping. The inference is deliberately limited to actual reused objects, not semantic replacement.

- **Replacement selection repair belongs to the replacement owner.** The July initialization repair found that `pipeTransformInitialValue` replaced content with `selection: null`, losing the caret when a transform wrapped a text node. Fixing that in Core with another path walk would duplicate snapshot semantics. Current Plate initialization translates `autoSelect` into a selection intent in `packages/platejs/src/lib/editor/withPlite.ts:382-415`; Plite resolves start/end intents, clamps text offsets and repairs element-path points in `packages/plitejs/src/core/public-state.ts:12147-12212`. Source: `c70bacbd4a:docs/plans/2026-07-06-plite-value-replace-init-closure.md:183-202`. Limit: the old transform-initial-value helper is gone; retain the ownership lesson rather than its historical callback or replacement-options API.

- **Guard an expected query miss without catching unrelated errors.** The June audit removed broad catches where path-presence checks already expressed the supported missing-node result. Current `packages/plitejs/src/editor/previous.ts` checks `PathApi.hasPrevious` and `NodeApi.has`; `editor/last.ts` checks location paths; `core/public-state.ts:2108-2157` validates path shape before testing existence. Source: `c70bacbd4a:docs/plans/2026-06-27-plite-try-catch-audit.md:155-170`. This does not justify removing transaction rollback, registration rollback or cleanup guards, which protect runtime state rather than classify an ordinary query miss.

- **A fluent API needs a batching job the existing boundary does not do.** The May 2026 review rejected `tx.chain().…run()` because ordered statements already execute inside `editor.update`; returning `tx` from every transform would also replace useful return semantics with fluency. Source: `c70bacbd4a:docs/plans/2026-05-18-plite-tx-chaining-dx-ralplan.md:84-113`. Current grouped transform interfaces still expose no raw `tx.chain`, while prepared command specs have a separate, real composition owner in `packages/plitejs/src/core/public-state.ts:8926-8970`. Limit: this rejects a redundant raw-transform wrapper; it does not reject prepared command composition.

- **Flat-container migration compares semantic sibling depth.** Converting legacy Toggle blocks into nested Details requires reading following siblings until their effective depth returns to the Toggle's depth. A legacy list item's positive indent includes a list level, so its effective enclosure depth is `indent - 1`; other blocks use indent. Consuming the enclosure then reduces body indentation by one. The current converter refuses non-finite indentation, missing Details plugins and properties neither Details nor Summary owns. Source: `docs/plans/2026-08-29-semantic-details-hard-cut.md:2165-2168`; current implementation: `packages/platejs/src/migrations/migratePlateV54Ast.internal.ts:87-194` and `:670-715`. Limit: the plan's private `migratePlateV55` owner is superseded; current conversion belongs to the v54 migration, and its source leaves non-positive list indentation unchanged. Code was read, not run.

- **Give shared Yjs semantics neutral owners.** The draft Plite cleanup found attribute access duplicated between document materialization and operation dispatch, generic path helpers owned by split history, and compatible replacement machinery mixed into dispatch. Extracting those responsibilities removed competing implementations without changing the public exports; the run recorded passing package contracts and typechecks after the extractions. The boundary survives in today's `packages/plitejs/src/yjs/core/attributes.ts`, `path.ts` and `replacement.ts`; `change-bridge.ts` delegates compatible replacement to the latter. Source: `c70bacbd4a:docs/plans/2026-06-11-yjs-cleanup-8h.md:262-267`. Limit: the source's `@slate/yjs`, operation dispatcher and test counts describe the draft fork, not today's package or proof results.

- **Test shared-node identity even when the visible text is correct.** In June 2026 inserting before a virtual moved child produced the correct text while replacing the original Yjs node; moving before that child could overwrite its reference. Compatible replacement, split, removal and insertion must all use the visible-child projection. Current `packages/plitejs/src/yjs/core/replacement.ts` reads projected children recursively, and `document.ts:2090` materializes a leading virtual reference as a placeholder after the inserted child. The compatible-replacement contract asserts both output and reference equality (`packages/plitejs/test/yjs/canonical-replacement-contract.spec.ts:176`); split and leading-child move contracts cover the adjacent operations. Source: `docs/plans/2026-06-11-yjs-perfection-8h.md:329-333`. These checks preserve shared identity; matching text alone does not prove concurrent-edit safety.

## Plugins and types

- **A scoped update facade carries policy into one root update.** Adding tagged descriptor-scoped commands must preserve the root transaction boundary rather than open an untagged or nested update. Current `packages/platejs/src/lib/plugin/createPluginContext.internal.ts:497-526` resolves the scoped method inside one callback and invokes `editor.update` once, with either that callback or the policy and callback. Source: `c70bacbd4a:docs/plans/2026-08-04-hard-cut-generic-plugin-mutations.md:139-154`; the plan records focused history, rollback and delegation proof at lines 237-239. The historical feature CRUD inventory is not part of this lesson.

- **Removing handwritten AST mirrors can expose schema-owner defects.** The August sweep found widened validated JSON, an Image codec persisting undeclared `title`, and Table fixtures treating installed element IDs as Table-owned fields. Repairing those owners removed the need for local property bags. Current `packages/plitejs/src/interfaces/schema.ts:74` and `:132` carry and recover exact property values; `packages/platejs/src/lib/plugin/pluginNodeTypes.ts:154-176` derives element/text property capabilities, and `features/media/lib/image/BaseImagePlugin.ts:155` declares `title`. Source: `c70bacbd4a:docs/plans/2026-08-06-hard-cut-handwritten-ast-mirrors.md:162-176`. Derive owned shapes, compose cross-plugin properties explicitly, and keep runtime narrowing for open or malformed input.

## Yjs replacement validation

- **Validate replacement compatibility before writing shared content.** Combining compatibility checks with writes can mutate earlier children before a later incompatible child forces fallback. The June 12 optimization explicitly rejected that single-pass shortcut. Current `replaceCompatibleYjsChildren` calls recursive `canReplace` before attribute or text-run writes (`packages/plitejs/src/yjs/core/replacement.ts`). Source: `docs/plans/2026-06-12-yjs-optimization-strict-8h.md:203`. This protects compatibility rejection; it is not a claim that every later runtime exception rolls back all Yjs writes.
