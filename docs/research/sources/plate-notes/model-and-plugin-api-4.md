# Model, plugin and history API, part 4

## Plugins and types

- **Own plain store data without pretending to own host resources.** Publishing caller-owned seed objects lets later caller mutation change a store without a store write. Plate snapshots and freezes plain state graphs while treating non-plain resources as opaque; current `packages/platejs/src/internal/plugin/pluginStore.ts:113-201` implements that boundary. The hook regression at `packages/platejs/src/react/stores/plate/usePluginStore.spec.tsx:36` mutates an incoming array after publication and checks that the published value stays unchanged. Source: `c70bacbd4a:docs/plans/2026-07-26-migrate-plugin-options-to-plugin-stores.md:205-209`. Opaque resources do not acquire observable mutation semantics merely by being stored.

- **Middleware can intentionally replace a delegated result with undefined.** The extension API review caught a dispatcher treating `undefined` returned after `next()` as an omitted return and restoring the delegated value. A handler's result remains authoritative even after delegation. Current `packages/plitejs/src/core/read-registry.ts` returns `registration.run(...)` directly, and `packages/plitejs/test/read-middleware-contract.test.ts:215-237` delegates to a true result, returns undefined and asserts undefined. Source: `c70bacbd4a:docs/plans/2026-07-28-perfect-editor-extension-api.md:197-201`. This concerns read middleware; it does not redefine event-handler return contracts.

- **Derive a plugin's public node type from its final schema descriptor.** The August audit removed handwritten Footnote and Column AST mirrors because they duplicated persisted schema fields and could drift independently. Current `packages/platejs/src/features/footnote/lib/BaseFootnotePlugin.ts:761-762`, `packages/platejs/src/features/layout/lib/BaseColumnPlugin.ts:121` and `packages/platejs/src/features/table/lib/BaseTablePlugin.ts:1106-1108` derive public node aliases with `ElementOf`. Source: `docs/plans/2026-08-06-derive-plugin-node-types-from-schema.md:177-199`. Property capabilities and genuinely recursive private compiler scaffolding need separate ownership analysis; this does not require copying the plan's old Table helper.

- **Separate schema property presence from runtime identity lookup.** The stable-ID review found an element-form ID reader asserting a property that an erased generic element did not guarantee. Exact schema-derived nodes can expose their own property; generic lookup uses runtime identity and returns an optional result. Current `packages/platejs/src/lib/plugins/element-id/ElementIdPlugin.ts:224-229` accepts a `NodeKey`, rejects a missing live node and returns `string | undefined`. Source: `docs/plans/2026-08-25-repair-stable-node-identity-apis.md:160-174`. Persisted element IDs remain distinct from runtime NodeKeys, and the old preparation helper is not retained.

- **A callable plugin selector must preserve a plugin named `plugin`.** The August portal implementation initially treated `plugin` as a reserved implementation name, although users could legally install a plugin with that name. Preserve both descriptor selection and the named group's methods through a callable proxy. Current `createTransactionPluginSelector` in `packages/plitejs/src/core/public-state.ts:6366` retains that distinction through `directPluginGroup`. Source: `c70bacbd4a:docs/plans/2026-08-12-transaction-plugin-portal-hard-cut.md:155-156`. The lesson survives the later move of portal ownership from Plate to Plite.

- **An optional patch property needs explicit `undefined` when deletion is a value.** With `exactOptionalPropertyTypes`, making a patch key optional does not itself permit an explicit `undefined` write. The object-only node-set review caught this gap. Current `NodePropertyPatch` explicitly unions every property's value with `undefined` (`packages/plitejs/src/interfaces/editor.ts:166-170`), so one object can update some properties and delete others. Source: `c70bacbd4a:docs/plans/2026-08-09-object-only-node-set-api.md:171-174`. This preserves the deletion typing lesson, not the retired plugin index-validation machinery.

- **Repair a missing callback field without expanding every surrounding generic.** The July shortcut sweep found that reconstructing callback state as `{}` lost `read` inference. Threading the full inferred state through all React plugin configuration fields then caused TS2589 in the legacy list model. Narrowly projecting the affected callback fields restored inference without that expansion. Source: `c70bacbd4a:docs/plans/2026-07-27-plugin-context-shortcut-sweep.md:123-130`; its package graph was rerun after removing the broad change. Current callback types live in `packages/platejs/src/react/plugin/PlatePlugin.ts` and the plugin runtime type owners; the July `C` projection spelling is historical, not a patch to copy.

- **Deleting a wrapper must not move preset behavior into package import behavior.** During the August method cut, heading and blockquote shortcuts first moved from registry configuration into package React plugins. Review rejected the move because importing the plugin would acquire behavior it previously received only from a preset. The repair kept configuration ownership while inlining the generic operation. Source: `docs/plans/2026-08-04-cut-redundant-plugin-read-update-methods.md:161-167`. Current feature plugins may deliberately declare shortcuts; the lesson is to compare the before/after activation boundary, not to forbid package-owned shortcuts.

- **Derive a renderer's props from a stable descriptor outside its own initializer.** The Comment leaf migration found that deriving component props from the configured plugin that installs that component creates a TypeScript initializer cycle. The imported owner descriptor supplied the same schema and plugin context without the cycle. Source: `c70bacbd4a:docs/plans/2026-08-12-infer-leaf-props-from-plugin-descriptors.md:93-100`. Current `packages/platejs/src/react/components/plate-nodes.tsx:47-63` still derives text shape and plugin context from a descriptor, and `EditorLeafProps` uses that extraction at `:313-316`. The old Plate/Plite prop names and raw-node overload policy are historical.

- **Subscribe to the boolean a control needs.** The selection-presence hook avoided making comment and color controls observe every caret position. Current `packages/platejs/src/react/stores/plate/useEditor.ts:83` selects `state.selection() !== null` through the existing runtime subscription; both copied toolbar consumers still use it. Source: `docs/plans/2026-09-08-editor-selection-presence-hook.md:65-69,93`. Presence transitions matter, while movement between two existing text selections should preserve the boolean result. The historical optional editor-id argument and primary-root restriction are superseded: the current hook takes no argument and reads its contextual root.

- **Reuse owned immutable branches without trusting a caller's shallow freeze.** A subscription probe exposed full-graph copying on each plugin-store write. Current `packages/platejs/src/internal/plugin/pluginStore.ts:111-123` recognizes snapshots the store owns with a private WeakSet and reuses those branches; newly supplied caller data still crosses the snapshot boundary. The regression in `resolvePlugins-store.spec.tsx:76-108` checks reference sharing and isolation from caller mutation. Source: `c70bacbd4a:docs/plans/2026-09-06-subscription-cleanup.md:45`. `Object.freeze` on a caller's outer object does not establish that its descendants are immutable.

- **A required kit wrapper need not create another plugin identity.** The AI/DnD cut removed companion descriptors whose only job was to install their feature's root integration. Current copied `ai.tsx:88` and `dnd.tsx:464` attach `wrapRoot` to their feature descriptor. Source: `docs/plans/2026-09-07-ai-dnd-root-slots.md:61-65,79-84`. Different plugins already compose at the root-rendering boundary; deliberately replacing one feature's root slot makes the replacement responsible for its composition. This preserves the ownership lesson, not the retired React DnD manager implementation.

- **Require complete top-level state at the authoring boundary.** The initial-state repair prevented a declared plugin field from silently disappearing because its default was optional or undefined. Current `packages/platejs/src/lib/plugin/pluginInitialState.internal.ts` removes optionality and excludes undefined while permitting null; `definePlugin.ts:293-299` applies that contract to initial state inputs. Source: `c70bacbd4a:docs/plans/2026-09-08-required-plugin-initial-state.md:16-25,105-113`. Nullable empty values, nested domain optionality and partial configuration have different jobs and remain valid. This is TypeScript authoring enforcement, not runtime validation against casts or untyped input.

## Model and transforms

- **A nearest-block query checks an exact block target before its ancestors.** The selection API migration initially made `nodes.block({ at: blockPath })` search only above the supplied block and miss the block itself. Current `packages/plitejs/src/core/public-state.ts:5669-5713` first resolves an exact path, checks the node against the active schema and caller match, and then falls back to ancestor lookup. Source: `docs/plans/2026-08-25-selection-nodes-blocks-api-hard-cut.md:177-179`. This exact-path behavior does not make the editor root a schema block.

- **Compose fitted replacement through a transaction spec.** The mention-drag repair exposed inline-void deletion followed by fitted reinsertion validating an intermediate draft as though it were an admitted immutable baseline. Reusing the detached transaction-spec path preserved validation and one outer publication. Source: `docs/plans/5087-mention-drag-regression.md:201-204`, with the historical failure at lines 221-223. Current `packages/plitejs/src/core/public-state.ts:5186-5197` creates the slice-fit spec, and `:7929-7941` applies that spec for `tx.slice.replace`. This preserves composition rather than weakening schema validation or special-casing mentions.

- **A reverse identity index does not prove that a node is still live.** Removing the live-node check from persisted-ID lookup returned a stale ID after deletion. Keep the live-key guard before reading the reverse map. Current `ElementIdPlugin.read.id` checks `state.nodes.get(key)` before ensuring its index and returning `nodeKeys.get(key)`; `packages/platejs/src/lib/plugins/element-id/ElementIdPlugin.spec.tsx:94` reads an ID, removes its node, and expects `undefined`. Source: `docs/plans/2026-08-13-separate-runtime-keys-and-persisted-element-ids.md:194-196`, with the failed optimization recorded at line 203. This guards lookup liveness independently of index maintenance.

- **Keep temporary DOM side-effect policy with the DOM extension.** Cutting `withScrolling` did not require adding scrolling policy to the document engine. The existing DOM plugin owned the temporary option merge and restoration around an update. Current `packages/platejs/src/lib/plugins/dom/DOMPlugin.ts:173` retains `autoScroll` under its update group and reads previous scrolling state before applying temporary policy. Source: `c70bacbd4a:docs/plans/2026-06-26-cut-dom-withscrolling.md:95-109`. The plan's `tx.dom` spelling is historical; retain the ownership and restoration contract rather than the old call shape.

- **Migrate a command's semantics rather than its apparent property assignment.** The paragraph shortcut's legacy intent was block toggling, so replacing it with a raw type write narrowed behavior. Source: `c70bacbd4a:docs/plans/2026-07-03-paragraph-shortcut-block-toggle.md:109-120`. Current `packages/platejs/src/react/plugins/paragraph/ParagraphPlugin.tsx` resets block metadata and calls `tx.blocks.toggle` with the resolved paragraph schema type inside one update. The July direct update-group signature and `defaultType` option are obsolete; the surviving lesson is to choose the semantic block command when migrating a shortcut.

- **Schema comparison must preserve target-specific declarations and ignore contributor labels.** The identity repair found that two properties with the same key on disjoint element targets could overwrite each other in a contract diff. Current `packages/plitejs/test/schema-contract-generation.test.ts:701` retains the regression with separate paragraph and quote `tone` declarations. Current `core/schema-compiler.ts:5090-5142` fingerprints canonical semantic data, including property target and role, rather than contributor provenance. Source: `c70bacbd4a:docs/plans/2026-08-04-fix-identity-codec-drift.md:52-56,97-99`. Removing either target's property must remain a distinct migration-producing change; relabeling its contributor must not become a document migration.

## Suggestions and comments

- **Clip prompt content to the same selection the response resolver permits.** AI Comment stopped resolving a partial-selection response after range enforcement because both prompt consumers still sent the complete referenced block. They now share `getCommentBlocks`, which intersects the selection with each referenced block and preserves rich descendants through `NodeApi.fragment` (`apps/www/src/registry/app/api/ai/command/prompt/getCommentPrompt.ts:16-61`). The package captures document-wide block references for a collapsed cursor and resolves returned comments within request-local scope (`packages/platejs/src/ai/react/AIChatPlugin.ts:715-718,1854`). Source: `c70bacbd4a:docs/plans/2026-09-17-ai-comment-regressions.md:78-90`. This concerns request scope and targeting; completed comments now publish without the old approval lifecycle.

- **Keep review discovery compact and derive detail only for the card being shown.** The September authored repair removed a React feed that treated its first 200 results as the complete document and avoided attaching semantic details to every summary. Source: `docs/plans/2026-09-13-complete-suggestion-semantics.md:49-63`. Current `packages/plitejs/src/authored/types.ts:51-77` still distinguishes a compact change from lazily derived parts; the current Suggestions subject shows block-key queries and cursor paging. The retained operation graph and `changesAt` spellings are superseded by the authored tree and ledger. Preserve complete discovery and lazy detail, not the old read API.

## History

- **Preserve structural step boundaries when publishing projected edits.** The September table-paste repair found that composing mapped accepted-coordinate steps into one structural step preserved the forward edit but made its inverse conflict with its own retained contributions. Preserve the mapped steps through publication and keep representation correction separate. Source: `docs/plans/2026-09-18-table-edge-paste-regression.md:108-115`. Current `packages/plitejs/src/authored/authored.ts:1986-1991` retains individual content steps and passes `steps` to recording at `:2178`; the recorder then owns canonical finalization. The authored implementation has since changed, so this preserves the failure mechanism rather than the historical patch.

## Table geometry

- **Merged-cell neighbors come from occupied grid slots, not sibling paths.** A top-border regression wrote to `c13` instead of the spanning `c11`, because raw path arithmetic ignored rowSpan and colSpan. Test the visible neighboring cell after a merge, then resolve border adjacency through the span-aware grid. Evidence: `docs/plans/4111-table-border-wrong-cell.md:30-38`. Current `packages/platejs/src/features/table/lib/internal/grid.ts` expands anchors into occupied slots, and `BaseTablePlugin.ts` applies border updates through physical grid edges. The old getAdjacentTableCell helper is retired; this preserves the geometry lesson, not its API.

## Input-rule match ownership

- **A custom block-start resolver adds to the core match rather than replacing it.** Letting resolveMatch replace the base payload forced list and quote rules to pass range through manually and made it easy to lose the span needed to consume the trigger. Core owns the base range and text; feature resolvers contribute extras. Evidence: `c70bacbd4a:docs/plans/2026-04-18-block-start-api-hard-cut.md:19-41`. Current `packages/platejs/src/lib/plugins/input-rules/createInputRules.ts:163-209` merges baseMatch with the resolved extras for string and regular-expression matches, while undefined still declines the match. This preserves payload ownership, not the retired factory API.
