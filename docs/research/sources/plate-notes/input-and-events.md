# Input, IME and event handlers

These lessons come from retired solution notes and Plite references, and no rule, Vision file, spec or public doc states them. A reader checked each one against the current tree on 2026-10-06. Each source is a path under `docs/` at commit `52625e8502`; read it with `git show 52625e8502:docs/<path>`.

## Native input

- **Only line-break placeholders drop the FEFF sentinel.** `ZeroWidthString` sets `includeSentinel = !isLineBreak`. Inline edges, void spacers and mark placeholders keep FEFF because no real-browser IME proof exists for them without it. Earlier failing IME proofs came from proof setup, a root click and a fake void wrapper, and a jsdom composition test could not decide either way. With FEFF, Chromium IME passed on inline edges and voids once the proof set the selection semantically and used the real void spacer. Drop FEFF on another path only after a real-browser IME row for that path. Code: `packages/plitejs/src/react/components/zero-width-string.tsx:7`. Sources: `solutions/logic-errors/2026-04-03-br-line-break-placeholders-are-already-bridge-compatible.md`, `solutions/logic-errors/2026-04-03-jsdom-contenteditable-composition-is-not-a-trustworthy-ime-proof.md`, `solutions/logic-errors/2026-04-03-legacy-line-break-placeholders-still-keep-feff-until-ime-proof-exists.md`, `solutions/logic-errors/2026-04-04-plite-no-feff-line-break-placeholders-need-dom-owned-br-interiors.md`, `solutions/logic-errors/2026-04-04-void-like-zero-width-ime-proofs-need-the-real-void-spacer-structure.md`, `solutions/logic-errors/2026-04-04-inline-edge-ime-proofs-should-set-selection-semantically-before-composition.md`.
- **OS text substitution flushes native text before the replacement.** Autocapitalize or a double-space period sends a native `insertText` beforeinput, mutates the DOM, then sends a model-owned replacement before the matching `input` event. The runtime keeps the native text as pending model work, flushes it at the next beforeinput, and applies the replacement at its expanded target range, not at the selection after the flush. An expanded `insertText` target range is a replacement even when model selection is preferred. The wrong order rendered `I` or `iSI` instead of `IS`. Code: `packages/plitejs/src/react/editable/runtime-before-input-events.ts:432`, `selection-reconciler.ts`, `apps/plite/tests/plite-browser/donor/examples/plaintext.test.ts:2165`. Source: `solutions/logic-errors/2026-05-09-beforeinput-substitutions-must-flush-native-text-before-replacement.md`.
- **An inputType-only beforeinput needs its own model command.** `insertTranspose` (Ctrl+T on a Mac) carries its intent in `inputType` with no data. Without a command, Plite blocks the native mutation as model-owned text input and drops the edit silently. Transpose swaps the characters around the caret, the previous two at a text end, and a Ctrl+T keydown fallback covers browsers without the event. When harvesting keyboard rows, look for other inputType-only events. Code: `packages/plitejs/src/react/editable/editing-kernel.ts:794`, `keyboard-input-strategy.ts:1158`. Source: `solutions/logic-errors/2026-05-09-inserttranspose-beforeinput-needs-model-owned-command.md`.
- **iOS Korean Backspace stays with the browser.** On iOS with `ko-KR`, `selectDOMInputDefaultActionPhase` moves delete-backward from keydown to the beforeinput phase, matching Lexical's `IS_IOS && ko-KR` guard. Android Backspace and other iOS Backspace stay model-owned at keydown. Android Backspace is the opposite ownership decision and Lexical's evidence covers only iOS `ko-KR`, so do not widen the guard; removing it lets keydown preempt native Korean input. The contract test proves the phase decision, not behavior on a device. Before porting a mobile or IME row from Lexical or ProseMirror, check whether that editor gave the action to the browser or to itself. Code: `packages/plitejs/src/dom/plugin/dom-input-runtime.ts:328`, `packages/plitejs/test/react/keyboard-input-strategy-contract.test.ts`. Source: `solutions/ui-bugs/2026-05-07-plite-react-ios-korean-backspace-must-stay-native-owned.md`.
- **Android flushes a stored insert early only for a material `insertText` handler.** On Android, typed text waits as a stored native DOM diff and flushes later. `shouldFlushStoredTextDiffForInsertTextHandler` requests an early flush (`scheduleFlush`) only when `probeCommandNativeEquivalent(editor, editorCommands.insertText, { text })` finds an installed handler that would change the result for that text; handlers that return `false` keep the deferred path, and delete diffs never flush early. Plate input rules count as material only for their trigger characters, which is how markdown triggers reach their handlers in the Android contract tests without the retired app-side `scheduleAndroidMarkdownShortcutFlush`; #4532 still lacks raw-device proof. The probe runs the handler chain read-only on every stored Android text insert, so an `insertText` handler must have no side effects and stay cheap. When a shortcut fails on Android, check the probe result for the typed character instead of adding flush calls. Code: `packages/plitejs/src/react/hooks/android-input-manager/android-input-manager.ts:106`, `:1166`, `packages/plitejs/src/core/command-registry.ts:486`, `packages/plitejs/test/react/android-input-manager-contract.test.ts:341-463`, `packages/platejs/src/react/utils/inputRules.spec.tsx:132-145`. Sources: `plite/ledgers/issue-coverage-matrix.md`, `plite/ledgers/fork-issue-dossier.md`.
- **Native format commands do nothing in Plate by default.** The `formatBold`, `formatItalic`, `formatUnderline` and `formatStrikeThrough` beforeinput events from the Safari and iOS text menus map to no editor command. The runtime marks them app-owned and passes them to `onDOMBeforeInput`, where the Plite hovering-toolbar example toggles marks; no platejs source outside specs handles a format inputType. The retired matrix rows for #3568 and #3586 called this runtime-owned, which the code contradicts. Code: `packages/plitejs/src/react/editable/editing-kernel.ts:784`, `packages/plitejs/src/dom/plugin/dom-input-runtime.ts:769`, `packages/plitejs/test/react/editing-kernel-contract.ts:160`, `apps/www/src/app/(app)/examples/plite/_examples/hovering-toolbar.tsx:54`. Source: `plite/ledgers/issue-coverage-matrix.md`.

## Handler return contracts

- **What "handled" means differs by layer.** In raw Plite `Editable` event props, `true` means handled (keydown also calls `preventDefault`), `false` forces the built-in handler, and `undefined` counts as handled only if the handler called `preventDefault` or `stopPropagation`. A truthy return from `onDOMBeforeInput` skips the runtime command and also calls `preventDefault`, and a nullish one falls back to `event.defaultPrevented`; without that cancel the browser still inserted the text while Plite recorded the event as handled. Plate's `pipeHandler` runs plugin `on.*` handlers first, where a truthy return stops the chain, then the `EditorContent` prop. For paste, drop and keydown that prop's `undefined` counts as handled only on `stopPropagation`; an `onDOMBeforeInput` prop also counts `preventDefault`. So in Plate, `preventDefault` alone never suppresses the built-in paste, drop or keydown. `docs/vision/plite.md` states the Plate side only in general terms. The exported `isEventHandled` and `isDOMEventHandled` (`packages/plitejs/src/react/components/editable.tsx:844`, `:878`) have no caller. Code: `packages/plitejs/src/react/editable/keyboard-input-strategy.ts:418-436`, `clipboard-input-strategy.ts:107-126`, `runtime-before-input-events.ts:72`, `packages/platejs/src/react/utils/pipeHandler.internal.ts:62-90`, `:134`. Sources: `plite/reference/public-docs/libraries/plite-react/event-handling.mdx`, `plite/reference/public-docs/libraries/plite-react/editable.mdx`, `solutions/test-failures/2026-05-20-plite-integration-local-editor-stacking-and-project-scope-failures.md`.
- **Native input listeners attach once.** The root `beforeinput` and `input` listeners read the latest app handlers from runtime state (`this.nativeInputHandlers`). App event props need no `useMemo` or `useCallback`, examples should not teach memoizing them, and listener wiring must never depend on callback identity. Code: `packages/plitejs/src/react/editable/editable-dom-runtime.ts:1215-1248`. Source: `solutions/developer-experience/2026-05-14-plite-react-native-beforeinput-formatting-needs-semantic-command-handlers.md`.
