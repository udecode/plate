# Testing and browser proof

These lessons come from retired solution notes and Plite references, and no rule in `verify`, Vision file or public doc states them. A reader checked each one against the current tree on 2026-10-06. Each source is a path under `docs/` at commit `52625e8502`; read it with `git show 52625e8502:docs/<path>`.

## Harness traps

- **`clipboard.assert.*` copies again.** The harness's `editor.clipboard.assert.*` calls `copyPayload`, which presses ControlOrMeta+C, so after a cut it re-copies the post-cut selection and changes state; read the clipboard with `readText` or `readHtml` instead. A cut proof uses the real ControlOrMeta+X, because a synthetic `ClipboardEvent('cut')` reaches only the React handler, and asserts the payload, the remaining text and a collapsed selection at the cut start. The cut handler returns a delete-fragment command plus a caret repair; Firefox lost the restored selection until cut became a model-owned repair. Code: `packages/test/src/playwright/harness-input.ts:166`, `:180`, `packages/plitejs/src/react/editable/clipboard-input-strategy.ts:388`. Sources: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-22-plite-react-cut-proof-must-use-real-shortcut-and-assert-selection.md`, `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-22-plite-react-internal-controls-must-be-native-owned.md`.
- **Typing helpers need usable keyboard focus.** A DOM selection inside the root is not enough: an app checkbox or button can hold focus while an old editor selection is still contained. Under shadow DOM, read the selection through `ShadowRoot.getSelection` when available and accept only selections inside the editor root; a document-level range outside the shadow editor is not editor selection. Checklist and WebKit shadow-DOM rows failed until these were split. Code: `packages/test/src/playwright/root-focus.ts:5`, `:32`. Source: `831f5e5da6a37f7d9095c1a81acc6b3de10bd3ba:docs/solutions/logic-errors/2026-04-24-plite-browser-proof-must-separate-model-owned-handles-root-selection-and-usable-focus.md`.
- **Stress families need a real `Editable`.** The generated stress runner opens every route with `ready: { editor: 'visible' }`, so a stress family needs a route that renders a real `Editable` and publishes the browser handle; selector-only demos stay contract rows. A row pointed at a selector-only route timed out on the textbox and stopped every later family. Set up stress cases through the smallest example control the contract needs, such as a seed button, and budget app-owned control rerenders apart from node churn. Code: `apps/plite/tests/plite-browser/donor/stress/generated-editing.test.ts:1345`. Sources: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/test-failures/2026-04-28-plite-browser-generated-stress-rows-need-real-editable-harnesses.md`, `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/test-failures/2026-05-18-plite-read-only-selection-tests-need-selector-owned-dom-selection.md`.
- **WebKit computed lengths carry float noise.** A cross-browser row parses CSS lengths and compares them within a tolerance; exact string assertions failed only on WebKit while the layout was right. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/test-failures/2026-05-20-plite-integration-local-editor-stacking-and-project-scope-failures.md`.

- **`Locator.evaluate` passes the element first.** A paste test that wrote `navigator.clipboard` from `locator.evaluate((text) => ...)` put `[object HTMLDivElement]` into the document, because Playwright passes the locator's element as the first argument; write `(_element, text)` and pass the value second. Source: `docs/plite/research/2026-06-12-oss-clipboard-paste-architecture/README.md:74-78`.

- **DOM host survival cannot prove block reuse in a static preview.** Static children are keyed by path, so React keeps the leading block hosts even when every preview replaces the whole value: in the 2026-09-29 S5 matrix 100% of leading hosts survived in both the reuse arm and the `value.replace` arm, so a host-survival assertion passes either way. `apps/www/tests/browser/markdown-streaming-contract.spec.ts` still asserts it in two tests, the paused-preview test (`kept / eligible` above 0.9 at `:1413`) and 'AI insert preview matches a one-chunk response and keeps block hosts' (`:1435`); assert reused node objects or per-commit render work when the claim is reuse. Source: `docs/research/probes/2026-09-28-conversion-boundary/lanes/s5/REPORT.md:210-212`.

- **A browser crash is not a browser limitation until a native probe says so.** Firefox crashed the Plite mentions route after a select-all replacement, and the lane was nearly scoped out as unsupported; the causes were a row that typed with `page.keyboard.insertText()`, which skips keydown, and a missing model-owned keydown replacement for selections across inline voids. Call a lane browser-unsupported only after a native probe shows no usable DOM range or target range, and record native and model selection, target ranges, operations and the error signature before keeping a runtime change. With `PLITE_MENTIONS_FIREFOX_SELECT_ALL_DIAGNOSTIC` set, the row attaches DOM, window and model selection, the kernel trace, the last commit and runtime errors at each step. Code: `apps/plite/tests/plite-browser/donor/examples/mentions.test.ts:32`, `:184`. Source: `docs/plite/research/2026-06-14-firefox-inline-void-select-all-replacement/README.md:78-82`, `rejected-ledger.tsv:2`, `shards/001-source-scan.md:28-38`.

- **Anchor an atom-adjacent IME row at the atom's leading edge, not at its spacer.** The Lexical-derived inline-void IME row puts the caret at the end of the text just before the first mention, composes `すし` through the synthetic transport and expects `like すし@R2-D2`. The spacer after a mention in the demo maps through zero-width boundary internals, so a row anchored there tests spacer mapping, not composition next to an atom. Code: `apps/plite/tests/plite-browser/donor/stress/generated-editing.test.ts:1168-1216`. Source: `docs/editor-test-harvester/lexical/report.md:223`.

- **Mutate a range copied before the events whose handlers can move the selection.** The browser IME helper's synthetic commit first puts the model selection back on the DOM, then copies the live range with `getRangeAt(0).cloneRange()`, and only then dispatches `beforeinput` with `insertFromComposition`. When the editor leaves that event unhandled, the helper inserts the committed text at the copied range, so a handler that moved the live selection cannot redirect it. Code: `packages/test/src/playwright/ime.ts:120`, `:167-170`, `:207-265`. In May 2026 the copy was taken before `compositionstart` and `compositionupdate`; the current helper dispatches those from separate calls before the commit (`ime.ts:284-305`). Source: `docs/editor-test-harvester/lexical/report.md:213`, `:224`.

- **Split browser transport rows by what each engine can prove.** Firefox blocks synthetic `ClipboardEvent('paste')` data and rejects script-driven `document.execCommand('insertText')`, so both import rows skip on Firefox with those reasons and run on the other projects; native paste inside an editable void's input skips only the `mobile` project, so Firefox proves that row. Code: `apps/plite/tests/plite-browser/donor/examples/plaintext.test.ts:758-765`, `:786-791`, `apps/plite/tests/plite-browser/donor/examples/editable-voids.test.ts:176-182`. Source: `docs/editor-test-harvester/lexical/report.md:227`, which records Firefox owning `execCommand`; the current skip reverses that.

- **Treat a failure that appears only after a test-runner upgrade as harness timing until a mismatch survives real waits.** Lexical's e2e failures after a Playwright 1.54.x upgrade were test timing, not editor bugs (facebook/lexical#7739). Do not patch the runtime from such a failure. First wait on model text, selection and clipboard payload, and keep the native and stand-in paste transports explicit. Reopen only if a route still mismatches after those waits. Code: `packages/test/src/playwright/harness-input.ts:63-133`. Source: `docs/plite/research/2026-06-13-playwright-editor-e2e-timing-oracles/rejected-ledger.tsv:2`.

- **Assert a triple-click by model endpoints, not by raw `Selection.toString()`.** Browsers differ in the whitespace of native selected text around inline boundaries. So a triple-click row asserts strict model endpoints for the intended block and compares native selected text only after normalizing non-breaking spaces, runs of whitespace and space before punctuation. It also asserts no double highlight and attaches a screenshot. With that oracle the inline triple-click row runs on Firefox instead of skipping. On 2026-06-14 it passed on Chromium, Firefox and WebKit, and the Firefox screenshot showed one paragraph highlight. Code: `apps/plite/tests/plite-browser/donor/examples/visual-native-selection-smoke.test.ts:8-13`, `:284-319`. Source: `docs/plite/research/2026-06-14-selection-triple-click-inline-normalization/README.md:7-17`.

- **A role query matches by substring unless it is exact.** Playwright's `getByRole('button', { name: 'link' })` matched both the Link and the Unlink toolbar buttons, because the accessible-name match is case-insensitive and substring by default; the ProseMirror #83 toolbar-link proof passed honestly only after the locator used the exact name `Link`. Pass `exact: true`, or an anchored regex, when sibling controls share a word. Test: `apps/plite/tests/plite-browser/donor/examples/inlines.test.ts:117` ('inserts a toolbar link at a collapsed selection'). Source: `c70bacbd4a:docs/editor-issue-harvester/prosemirror/full/checkpoints/issues-0063-0085.md:70-73`.

- **Pick the fixture that isolates the reported case, and drag where the text really is.** The first regression for ProseMirror #1180 (two spaces typed after an inline atom insert a period) ran on the `inlines` route, which already shows text and punctuation after its read-only inline, so the oracle could not tell a stray period from existing content; the durable test uses the `mentions` route with a real inline atom followed by plain text. The generic `dragTextRange` helper cannot select through rendered mention labels, which are not one continuous DOM text node, so the #1164 proof drags with real mouse geometry over the final text node. Tests: `apps/plite/tests/plite-browser/donor/examples/mentions.test.ts:1210` ('typing two spaces after an inline mention does not insert a dot') and `:991` ('selects the last character after a leading inline mention and space'). Source: `c70bacbd4a:docs/editor-issue-harvester/prosemirror/full/checkpoints/issues-1161-1187.md:63-66`.

- **Do not assume the DOM nesting order of stacked marks.** The ProseMirror #1232 regression for browser text mutations inside nested mark DOM first selected `strong em`; the renderer may nest `em strong` instead, so the selector accepts either order. Test: `apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:1612` ('syncs browser text mutations inside nested mark DOM'). Source: `c70bacbd4a:docs/editor-issue-harvester/prosemirror/full/checkpoints/issues-1220-1259.md:41`.

- **happy-dom pastes take Safari's direct branch.** happy-dom's user agent (`AppleWebKit … HappyDOM`, no `Chrome/`) matches Plite's WebKit pattern, and only jsdom is classified as a non-browser DOM, so a `paste` event under happy-dom cancels and inserts at once. happy-dom also defines a global `DataTransfer`, so testing-library rebuilds a stub from its own properties and the event carries an empty payload. Build the payload with happy-dom's native `new DataTransfer()`, dispatch `beforeinput` only when `fireEvent.paste` returned `true`, because browsers never send it after a canceled paste, and expect window polyfills to leak across files, because DOM facts are cached per realm and Bun shares one window. A paste reported twice in such a spec was this harness, not a product defect. Code: `packages/plitejs/src/dom/utils/environment.ts:28-32`, `packages/platejs/src/react/markdownPasteResult.spec.tsx:28-43`. Source: `docs/research/probes/2026-09-28-conversion-boundary/lanes/t1/REPORT.md:139-148`.

- **The www Plite browser mode renders no toasts.** With `PLATE_WWW_PLITE=1`, which the www browser runner uses, the root layout skips `<Toaster />`, so no toast can render on `/blocks/*`; a toast assertion needs a served mode that mounts it. Code: `apps/www/src/app/layout.tsx:17`, `:131`. Source: `docs/research/probes/2026-09-28-conversion-boundary/lanes/t1/REPORT.md:155-156`.

- **Spread a foreign-realm object before comparing it.** A `node:vm` test whose result object came from another realm passed only because Bun's `deepEqual` ignores prototypes; Node's `assert/strict` `deepEqual` compares `[[Prototype]]` and rejects it against a local literal, so the test was tied to its runner. Compare `{ ...result }` or its fields. Code: `packages/plitejs/test/history/history-branch-contract.spec.ts:578-579`. Source: `docs/research/probes/2026-10-05-history-replay-result/panel-diff-r2/d2-opus.md:18-22`.

- **CDP composition cannot target a mid-leaf offset.** With the model or the DOM selection placed inside the bold leaf `rich`, CDP `Input.imeSetComposition` still committed at the end of the leaf, giving `richすし` instead of `riすしch`, and its `replacementStart` and `replacementEnd` are not Plite leaf offsets: an experiment with them inserted the text after `Th`. For a composition row at a mark boundary, use the shape of ProseMirror's `webtest-composition.ts`: put a real DOM range in the text node, dispatch the composition events, mutate the captured range and let Plite import the DOM change, as 'commits IME composition inside bold markup' does (`apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:1972`, Chromium only). Keep CDP composition for end-of-text and trace rows. Source: `52625e8502:docs/solutions/developer-experience/2026-05-07-plite-browser-ime-proof-rows-need-honest-dom-composition.md`, via `docs/plite/research/2026-10-02-agentic-e2e-testing/read-log.tsv:373`.

- **Playwright screenshots hide the caret by default.** Page and locator screenshots default to `caret: 'hide'`, which sets `caret-color: transparent !important` for the capture. A caret pixel check through the default capture therefore sees no caret at all. Pass `caret: 'initial'`, and stop the blink with `caret-animation: manual`. On 2026-10-08, the preedit screenshot in `apps/www/tests/browser/homepage-ime.spec.ts:111` still used the default. Evidence: `playwright-core@1.61.0` `types/types.d.ts:12185-12189` and `lib/coreBundle.js:20719-20727`, via `docs/plite/research/2026-10-02-agentic-e2e-testing/read-log.tsv:386-387`.

- **A traced command proves a plan, not an effect.** The paste oracle once counted a paste as applied when the kernel trace held an `insert-data` entry. The runtime records that decision before `onDOMBeforeInput` runs, and a handler can then cancel the insertion, return handled, or only move the selection. Run read-only, the predicate returned true for an ignored payload. A paste now counts as applied only when the editor's last commit is newer than the one before the paste, carries the `paste` tag, and has changed roots. Check a command's outcome in the committed document, not its presence in a trace. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-gpt-6-astra.md:15-23` and `round1-gpt-6.1-sol.md:85-95`. Fix: `packages/test/src/playwright/harness-input.ts:93-105`; regression 'fails a paste the editor plans but inserts nothing for' (`apps/plite/tests/plite-browser/donor/examples/plaintext.test.ts:479`).

- **Keep local-only Playwright files out of the Bun suite.** The fast Bun suite collects `apps/**/*.spec.{ts,tsx}` and `apps/**/*.test.*` files and ignores only `tests/browser` and `tests/plite-browser`. A Playwright spec anywhere else under `apps` therefore runs under `bun test` and fails `pnpm check`. The native IME spec did exactly that until it was renamed `homepage-ime.native.ts` and given its own `testMatch`, like the `*.device.ts` cases. Also read global-setup state in `beforeAll`, not at module scope, because `playwright test --list` skips global setup. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-opus.md:3-7`; `tooling/config/test-suites.mjs:16-46`, `apps/www/playwright.native-ime.config.ts` (`testMatch: /\.native\.ts$/`) and `apps/www/tests/native/homepage-ime.native.ts:40`, checked 2026-10-08.

- **Playwright's list reporter does not print annotations.** In Playwright 1.61 the terminal reporters, `list` included, never read `testInfo.annotations`, so a known failure recorded only as an annotation passes silently in the console. The device config adds a JSON reporter, and `knownFailure` also writes a line to stdout. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-opus.md:33-38`; the reporter setting in `apps/plite/playwright.device.config.ts` and `packages/test/src/device/lane.ts:666-667`, checked 2026-10-08.

- **The native event trace keeps 100 entries by default.** `startBrowserNativeEventTrace` keeps `maxEntries ?? 100` entries and splices the front once full (`packages/test/src/playwright/native-event-trace.ts:25`, `:45`, `:378-386`), so its length stops growing and an early prefix disappears: never correlate events by array length, and never audit a long run from a trace that may have overflowed. Each entry carries a monotonic `seq` (`:379-380`). The device lane passes `maxEntries: 10_000`, gives each gesture the `seq` range from its first event until input stays quiet for 400 ms, and takes each page's trace once when it leaves the page (`packages/test/src/device/lane.ts:265-312`). Source: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/interrogate-reviewer-a.md:36-40`.

- **The www browser suite reuses whatever server holds port 3000.** Unless `PLAYWRIGHT_BASE_URL` is set, `apps/www/playwright.config.ts` starts `pnpm dev:plite` with `reuseExistingServer: true` on `http://localhost:3000` and runs with `workers: 1` and `fullyParallel: false` (`:13`, `:51-59`). A run can therefore silently test another session's or another checkout's server, which breaks serving-source identity. `dev:plite` also runs `pnpm build:registry` first, which can rewrite the tracked registry JSON under `apps/www/public/r` (`apps/www/package.json:19`). Serve a dedicated port, or check the served build's identity, before counting a run; the Android device lane's global setup refuses a www server that serves another checkout (`apps/plite/tests/device/global-setup.ts:191-199`). No full-suite wall time had been recorded as of 2026-10-02. Sources: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/interrogate-reviewer-a.md:102-105`, `interrogate-reviewer-b.md:84-87`.


- **Keep `caret: 'hide'` where a classifier measures selection paint.** The selection-highlight classifiers capture with `caret: 'hide'` on purpose, so a blinking caret column never counts as a changed pixel (`apps/www/tests/browser/code-block-selection.spec.ts:23`, `apps/www/tests/browser/comment.spec.ts:401`, `apps/www/tests/browser/link-floating-toolbar.spec.ts:29`, `apps/www/tests/browser/table-selection.spec.ts:49`); turning carets on everywhere would add caret pixels to their thresholds. Use `caret: 'initial'` with `caret-animation: manual` only where a caret is the claim, as `apps/www/tests/browser/suggestion.spec.ts` and `tooling/e2e/font-size-selection.test.ts` already pass `caret: 'initial'` and the native IME spec sets the stabilizer on the editor (`apps/www/tests/native/homepage-ime.native.ts:204`), and run positive, absent and duplicate controls through the same capture path. `caret-animation: manual` was measured only on Chromium 149 and Chrome 154, so on Firefox and WebKit a capture may still blink (inferred). Sources: `docs/plite/research/2026-10-02-agentic-e2e-testing/shards/006-real-ime-for-5137.md:79-91`, `review/interrogate-reviewer-b.md:89-92`.

- **Assert a native IME's committed text, never its candidate index.** macOS Pinyin adapts its candidate order, so a native IME proof that picks a candidate asserts the committed text (`测试` for `ceshi`), never that a given index holds it; `测试` was the first candidate in the 2026-10-02 probe, which says nothing about the next run. The native spec types `ceshi`, presses Space and asserts `测试` in the text (`apps/www/tests/native/homepage-ime.native.ts:372`, `:433-434`). The offset trap of CDP composition is 'CDP composition cannot target a mid-leaf offset' above. Source: `docs/plite/research/2026-10-02-agentic-e2e-testing/shards/006-real-ime-for-5137.md:205`.

- **The two Playwright suites read different test-id attributes.** `apps/plite/playwright.config.ts:110` and `apps/plite/playwright.device.config.ts:38` set `testIdAttribute: 'data-test-id'`, so `getByTestId` in the Plite browser suite, such as `getByTestId('mark-button-bold')`, matches `data-test-id`, and a custom touch-target resolver that assumes `data-testid` finds nothing in the Plite app, while `apps/www/playwright.config.ts` keeps Playwright's default `data-testid`, which the www specs use (`apps/www/tests/browser/document-migration.spec.ts:47` reads the `data-testid` set at `apps/www/src/registry/examples/document-migration-demo.tsx:180`). The Plite examples live under `apps/www/src/app/(app)/examples/plite/_examples/` but run in the Plite suite, so an element a Plite test finds with `getByTestId` carries `data-test-id`, as in `hidden-content-blocks.tsx`; a `data-testid` there leaves `getByTestId` waiting until it times out. `pagination.tsx` uses `data-testid`, which works only because its test reads those elements through a CSS selector (`apps/plite/tests/plite-browser/donor/examples/pagination.test.ts:75`). Source: `c70bacbd4a7523ae3ebfd820cec0ea8ec228e9ad:docs/solutions/developer-experience/2026-04-29-plite-hard-cuts-must-run-explicit-contract-files.md`, `docs/plite/research/2026-10-02-agentic-e2e-testing/review/interrogate-reviewer-b.md:119-122`.

- **Firefox table multi-range needs a native mouse drag.** Firefox exposes a table cell selection as several DOM ranges, and the normal model-to-DOM selection export collapses them to one, after which the user cannot extend the cell selection. In April 2026 a proof that scripted `Selection.addRange` reached only `rangeCount` 1 and made the row look untestable; a native mouse drag across real cells reached `rangeCount` above 1 and exposed the collapse as soon as a control forced a selection sync. The guard skips the export while the live selection holds more than one range (`packages/plitejs/src/react/editable/selection-reconciler.ts:1350-1358`), beside the Gecko anchor reads that came from Slate PR #5486 (`:1132-1146`, `packages/plitejs/src/dom/plugin/dom-editor.ts:2483-2500`). No browser row under `apps/plite/tests` asserted `rangeCount` above 1 on 2026-10-08, so the guard is unpinned. Prove it with a native drag across cells, assert several ranges before any editor sync, force a sync, and assert the ranges survive. Source: `c70bacbd4a7523ae3ebfd820cec0ea8ec228e9ad:docs/solutions/logic-errors/2026-04-12-firefox-table-multi-range-proof-needs-native-table-selection-and-a-multi-range-sync-guard.md`, whose "legacy Plite" carve-out is legacy Slate's.

- **A Playwright page function sees only its arguments.** `page.evaluate` and `locator.evaluate` send the function's source to the page, so a module-scope value of the test file, such as the browser-handle key, is not in scope there and must be passed as an argument. In April 2026 a nested-selection helper read that key from module scope and reported `null` while the page's selection was right; the fix passed the key in and waited briefly for the handle to hydrate. The harness passes `BROWSER_HANDLE_KEY` (`packages/test/src/playwright/constants.ts:2`) into its page functions, as in `{ handleKey: BROWSER_HANDLE_KEY, traceKey }` (`packages/test/src/playwright/interaction-performance.ts:474`) and `{ key: BROWSER_HANDLE_KEY }` (`packages/test/src/playwright/displayed-selection.ts:223`). The note's other trap, a browser lane running stale package `dist`, is now handled before each run: the Plite site resolves workspace packages to source (`buildWorkspaceDevAliases` in `apps/plite/next.config.ts`), `apps/plite/scripts/run-plite-browser.mjs` rebuilds the static export when its inputs changed (`build-app-if-stale.mjs`), and the `pretest:plite-browser*` scripts in `apps/plite/package.json` rebuild the `@platejs/test` build the same way (`build-browser-if-stale.mjs`). Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-04-plite-browser-nested-selection-proofs-must-pass-handle-keys-and-build-the-v2-dist-the-site-actually-runs.md:20-69`.

- **Seed every Yjs peer from one document state before its editor creates shared types.** When two docs each create the same nested shared type on their own before syncing, Yjs treats them as competing structures and the remote peer keeps its local empty type, so the test exercises an impossible setup and content seems to vanish. In March 2026 the nested shared-type fixture created `editors.main` independently on each peer; it passed only after both peers started from one bootstrap state copied with `Y.encodeStateAsUpdate` and `Y.applyUpdate`. Today's remote-import contract does the same: it applies the source doc's state to the target doc before the target editor installs `yjs(...)`. When the question is whether content arrived, check the shared type's own length, not a decoded empty leaf. Code: `packages/plitejs/test/yjs/remote-import-contract.slow.ts:121-125`. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/test-failures/2026-03-22-yjs-slow-tests-need-explicit-bun-paths-and-bootstrapped-shared-types.md`. Limit: the `sharedType` option and `yTextToPliteElement` the note named no longer exist.

- **The `plitejs` fixture corpus compiles as hyperscript only when Bun runs from the repository root.** Fixtures carry `/** @jsx jsx */` and import `jsx` from the test directory's `index.js`, which re-exports the factory in `config/plite-test-jsx.js` (that module also sets `globalThis.jsx`); on 2026-10-08, 876 `.tsx` files under `packages/plitejs/test` carried `@jsx jsx` without `@jsxRuntime classic`, which verify's testing reference says a factory pragma needs under automatic JSX. ## Device and host lanes

- **A CDP relay must also refuse the tunnels.** Blocking `Input.*` on a DevTools relay is not enough. `Target.exposeDevToolsProtocol` gives page script a binding (`window[bindingName].send(json)`) that a client can drive through an allowed `Runtime.evaluate`. Chromium dispatches the commands sent that way to the browser agent host, so they never cross the relay. The legacy `Target.sendMessageToTarget` also wraps a command for another session. The device lane's guard refuses all three on every session, Playwright's own sessions included, and its bypass case sends `Target.exposeDevToolsProtocol` outside and inside a key tap, which the guard refused 10 times in the final five-run proof (`docs/plite/research/2026-10-02-agentic-e2e-testing/sources/device-runs/2026-10-02T2315Z-final/five-runs-summary.json`). Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-gpt-6-astra.md:3-13` and `round1-gpt-6.1-sol.md:73-83` (source-level), `chromium/chromium@c81dc1b550aa5e3ef392aedd34926d6f348271f1:content/browser/devtools/protocol/target_handler.cc`. Fix: `packages/test/src/device/guard.ts:137-141`, `:228-230`.

- **Owning one tab does not license stopping the browser.** The first `restore` ran `adb shell am force-stop com.android.chrome` on any error while closing a recorded tab. That included the 'No target with given id found' error for an id gone stale after a reboot or a manual close, so recovery would have killed every Chrome tab on a physical phone. Close only the ids that `Target.getTargets` still lists, treat a missing id as closed, and force-stop only behind an explicit flag. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-gpt-6-astra.md:65-73` and `round1-opus.md:9-18`. Restore also brings Chrome to the foreground first, because Android freezes a backgrounded Chrome together with its DevTools socket. Fix: `tooling/device/android.mjs:21-78` (`--force-stop-chrome` at :80).

- **A source fingerprint must hash the contents of untracked files.** `serving-fingerprint.mjs` first hashed `git diff HEAD` and only the names of untracked files. Editing an untracked file therefore left the fingerprint unchanged while the served code changed. It now hashes each untracked file's path and bytes, and the device global setup fails when the www server serves another tree. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-gpt-6-astra.md:123-131`, `round1-gpt-6.1-sol.md:124-132`, `round1-opus.md:109-113`. Fix: `tooling/scripts/serving-fingerprint.mjs:15-43`. Limit: it still hashes `git diff HEAD` without `--binary`, which prints only 'Binary files differ' for a tracked binary file, so two different edits of the same binary file hash alike (checked 2026-10-08).

- **Forget a resource only after it is gone.** Teardown swallowed `Target.closeTarget` and `adb` failures and then removed those tabs and ports from the restore journal, so a later `restore` would have had no identifier to retry. Remove a journal entry only after the removal is confirmed or the resource is already absent, and keep and report the failed ones. The round-2 fix covers tabs: an unclosed tab stays journaled and `restore` throws naming it (`apps/plite/tests/device/global-setup.ts:90-95`, `packages/test/src/device/android.ts:973-990`). Ports are not covered: `removePorts` still treats a failed `adb forward --remove` or `adb reverse --remove` as already gone, and `releaseRunResources` drops it from the journal (`packages/test/src/device/android.ts:309-350`, checked 2026-10-08). Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-gpt-6.1-sol.md:3-11` and `round1-gpt-6-astra.md:85-93`; the fix list in `review/execution-panel/round2-prompt.md:22`.

- **A known-failure assertion names the failure it expects.** `productAssertion({ expected: 'fail' })` accepted any thrown error as the known autocorrect failure, so a worse regression, such as dropped input, would stay green under the known-failure label. Its replacement, `device.knownFailure`, takes `desired` and `observed` values and classifies only a value that held for 500 ms. It fails when the desired value appears, with a message that the known failure no longer reproduces, and it fails on any third value. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-gpt-6.1-sol.md:97-105`, `round1-opus.md:40-44`, `round2-opus.md:59-62`. Fix: `packages/test/src/device/lane.ts:624-672`.

- **Journal each original before changing it.** The first device setup tapped several Gboard toggles and recorded their original values only after the loop finished, so a failure partway left settings changed with no record. It also recorded Korean as added before the add flow finished, so after a failed add flow `restore` would throw on a language that was never installed and stop before restoring the keyboard subtype and Do Not Disturb. Journal each original value immediately before changing it, and record an addition only after the device confirms it. Make each restore step check that its target is present and continue past a failed step. Mark setup complete so `doctor` can tell a finished setup from a half-finished one. Re-read the screen after each toggle, because a toggle can reflow the rows below it. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-opus.md:20-31`, `round1-gpt-6-astra.md:45-53,75-83`, `round1-gpt-6.1-sol.md:13-21`; the fixes are listed in `round2-prompt.md:20`.

- **Allocate ports; never assume a fixed port is yours.** Without `--no-rebind`, `adb forward` and `adb reverse` silently repoint a port that another session holds. Two runs on different phones would both take host port 9500, so one run's workers could be relayed to the other phone's Chrome, and its teardown would remove the mapping the other run was using. Likewise, a Chrome launched on a taken `--remote-debugging-port` starts without DevTools, and the lane ends up driving whichever browser holds the port. Use `adb forward tcp:0` and keep the port it returns, use `adb reverse --no-rebind`, and launch Chrome with `--remote-debugging-port=0`, reading the port from `DevToolsActivePort` in the run's own profile. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-opus.md:73-77` and `round1-gpt-6-astra.md:55-63`. Fixes: `packages/test/src/device/android.ts:276-293`, `tooling/device/android.mjs:26`, `tooling/ime/native-chrome.mjs:26,74,82`.

- **A lock file needs exclusive creation and an owner token.** The first device and IME locks read the lock file and then wrote it, so two processes could both see no lock. Release and `restore` deleted the lock without checking its owner, so recovery during a live run would dismantle that run's settings, tabs, ports and lock. The IME lock was also taken per test, which let another session take over the input source between tests. The fixes: create the lock with `wx` (`O_EXCL` in Swift), let only the owner release it, make `restore` acquire the lock and take over only from a dead owner, and hold the IME lock from global setup to teardown. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-opus.md:79-90`, `round1-gpt-6-astra.md:25-43`, and the round-2 fix list in `round2-prompt.md:18-19`. Code: `acquireSerialLock` and `releaseSerialLock` in `packages/test/src/device/android.ts`, and `tooling/ime/macos-ime.swift`.

- **Record a resource as owned only after acquiring it.** Device setup added a reverse port to the run's owned list before calling `adb reverse --no-rebind`. When another session held the port, the refusal would trigger teardown, and teardown would remove the other session's mapping. Calibration's `finally` block and the fixture recorder made the same mistake. Add to the owned list only after the acquiring call returns. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round2-gpt-6-astra.md:3-11` and `round2-opus.md:5-9`; fixed in all three writers after the round-2 snapshot.

- **Exclusive creation does not make stale-lock takeover exclusive.** Two contenders that read the same dead owner can each rename the stale lock and create their own, and a delayed rename can remove a fresh owner's lock. An in-memory interleaving of the real Android acquisition function returned success for both owners, and the Swift lock used the same sequence. Serialize takeover with a second, exclusively created takeover marker, re-read the stale owner while holding it, and never leave the lock path missing. Both lanes now hold a `<lock>.takeover` marker during takeover. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round2-gpt-6-astra.md:13-23`, `round2-gpt-6.1-sol.md:15-25`, `round2-opus.md:54-57`. Code: `packages/test/src/device/android.ts:149-193`, `tooling/ime/macos-ime.swift:81-105`, checked 2026-10-08.

- **Validate every frame in a relay that runs inside the test runner.** The guard first called `JSON.parse` in the socket's `data` handler, so a malformed frame would throw an uncaught exception in the Playwright runner process, which also hosts global setup, ending the run and skipping teardown. After a catch for bad JSON was added, in-memory probes showed valid JSON of the wrong shape still throwing: `null` failed on `message.method`, and an object whose `method` is a number failed on `startsWith`. Parse each frame into a typed command and drop the client on any shape error. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round1-opus.md:92-96`, `round2-gpt-6-astra.md:37-51` (in-memory probes of the real callback), `round2-opus.md:49-52`. The current guard parses through `parseCommand` (`packages/test/src/device/guard.ts:117,220`).

- **Hiding a fixture in the types is not a boundary.** Device cases first reached the lane only through typed fixtures, but Node 22 exposes `fetch`, `WebSocket` and `process.getBuiltinModule('node:child_process')` as globals. A case could therefore run `adb` or open the guarded endpoint without any import a lint rule sees, and the helper files beside the cases were outside the lint glob. The lane now exposes only `device.www`. The lint override covers the case helpers, bans the globals `fetch`, `globalThis`, `process`, `require` and `WebSocket`, and bans imports of `child_process`, `http`, `https`, `module`, `net`, `tls`, `@playwright/test`, `playwright` or `playwright-core` and the lane's internals under `packages/test/src/device/`; `bypass.device.ts` is the one exception. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/execution-panel/round2-opus.md:17-25` and `round1-opus.md:60-71`; `oxlint.config.ts:217-250` and `packages/test/src/device/lane.ts:236`, checked 2026-10-08.

- **An event signature cannot reject keys forged through CDP.** A CDP `Input.dispatchKeyEvent` `rawKeyDown` with key `Unidentified` and `windowsVirtualKeyCode` 229, followed by `Input.insertText`, yields a trusted `keydown` (key `Unidentified`, keyCode 229, empty `code`) and trusted `beforeinput` and `input` events. These are the same fields Chrome's IME adapter sends for a Gboard tap. Only a structural check closes this path: a relay that refuses `Input.*`. A bypass test that replays forgeries outside every lane gesture also passes on the window rule alone, so it never exercises a signature check. The device lane adopted the structural guard instead of per-key signatures. Evidence: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/interrogate-pass2-a.md:60-68`, `interrogate-pass2-b.md:32-40`, `interrogate-pass2-c.md:41-53` (reasoned from CDP semantics, not run); the Defaults row 'Input witness' in `docs/plans/2026-10-02-proof-device-lane.md`.

- **Attach to a real browser with `connectOverCDP(url, { noDefaults: true })`.** Without the option, Playwright 1.61 sends `Emulation.setFocusEmulationEnabled` to every main frame of the default context and applies its media emulation defaults, such as `reducedMotion` and `colorScheme` (playwright-core 1.61.0 `lib/coreBundle.js:37045-37049`, option docs in `types/types.d.ts:23413-23426`). Under focus emulation `document.hasFocus()` stays true after the OS has moved focus elsewhere, which hides the keyboard-dismissal and focus defects a device lane exists to catch (Slate #6022). `noDefaults` covers only the default context, so use that context and never `browser.newContext()`. The device lane and the native IME lane attach this way (`apps/plite/tests/device/global-setup.ts:120`, `apps/www/tests/native/homepage-ime.native.ts:42`). Sources: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/interrogate-reviewer-a.md:42-45`, `interrogate-reviewer-b.md:51-54`, `shards/006-real-ime-for-5137.md:52`.

- **A Playwright-launched Chrome is not a user's Chrome.** Desktop `chromium.launch` applies Playwright's `chromiumSwitches()` list, which includes `--disable-field-trial-config`, `--allow-pre-commit-input`, `--disable-backgrounding-occluded-windows`, `--disable-renderer-backgrounding` and a `--disable-features` list holding `PaintHolding` and `RenderDocument` (playwright-core 1.61.0 `lib/coreBundle.js:34396-34470`). Android's experimental `_android` `launchBrowser` writes its switch list to `/data/local/tmp/chrome-command-line` before starting Chrome (`coreBundle.js:38408-38416`) and needs the `Enable command line on non-rooted devices` flag. A claim about activation, paint or pre-commit input in exact Chrome therefore launches the binary itself with only `--remote-debugging-port`, `--user-data-dir`, `--no-first-run` and `--no-default-browser-check` (`tooling/ime/native-chrome.mjs:14-19`) and attaches with `noDefaults`. The Android lane attaches to stock Chrome through `adb forward localabstract:chrome_devtools_remote` instead of `launchBrowser`. Sources: `docs/plite/research/2026-10-02-agentic-e2e-testing/review/interrogate-reviewer-a.md:107-110`, `interrogate-reviewer-c.md:90-93`, `shards/008-device-lane-arena-judge.md:6`, `shards/002-mobile-agent-tools.md:80`.

- **Drive real macOS Pinyin into the right Chrome window.** The input-source rules (an enabled parent for `SCIM.ITABC`, the macOS 26 reactivation race) are under 'IME and device automation limits' on `docs/research/sources/editor-architecture/testing-and-proof.md`. Three more checks keep a run honest. Count a run only after a probe key starts a trusted `compositionstart`, because a switch can show Pinyin as selected while keys still pass through as ASCII; the native spec gates on a probe textarea (`apps/www/tests/native/homepage-ime.native.ts:229-264`). Post keys to Chrome's pid with `postToPid`, and use the HID tap only after a per-key frontmost-pid check, because a HID post goes to whatever app is frontmost at delivery (`tooling/ime/macos-ime.swift:168-183`); that check still leaves a short window between check and post. And find the test window through a unique `document.title` nonce and activate Chrome by pid, never by app name, because the user's own Chrome shares the exact Chrome's bundle id (`homepage-ime.native.ts:51-56`, `:133-136`, `:301-306`; the helper's `window` command, `macos-ime.swift:145-155`). Source: `docs/plite/research/2026-10-02-agentic-e2e-testing/shards/006-real-ime-for-5137.md:50-54`; code read 2026-10-08.

- **Read Gboard's keys from `uiautomator dump --windows`.** A plain `adb shell uiautomator dump` lists only Chrome's window. With `--windows` it lists every interactive window: 153 Gboard nodes on the API 36 Play emulator, each letter key with a `content-desc` and bounds (`Q` at `[5,1678][112,1832]`), and taps at those centers typed `hello` correctly. The device lane caches key positions per Gboard version, language, panel, subtype and screen size and fails closed on a cache miss (`docs/plans/2026-10-02-proof-device-lane.md:82`), but it still dumps during a run to confirm the visible language or panel and to find suggestion-strip candidates (`packages/test/src/device/lane.ts:457`, `:479`, `:675`); a dump had no observable effect on page events (see 'Android device lane' on `docs/research/sources/plite/testing-and-proof.md`). One emulator run. Source: `docs/plite/research/2026-10-02-agentic-e2e-testing/shards/009-device-lane-prototype.md:13-18`.

- **Gboard setup on an emulator has its own traps.** Installing Korean raises a 'Korean is now installed' banner over the keys that setup must dismiss (`packages/test/src/device/android.ts:761-769`).
