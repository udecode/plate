# Model, plugin and history API

These lessons come from retired solution notes and Plite references, and no rule, Vision file, spec or public doc states them. A reader checked each one against the current tree on 2026-10-06. Each source is a path under `docs/` at commit `52625e8502`; read it with `git show 52625e8502:docs/<path>`.

## Model and transforms

- **Structural transforms keep NodeKey identity by moving nodes.** Wrap inserts a fresh-key wrapper and moves the node in, or transfers keys through `nodeKeyTransfers`. Unwrap and lift move children out and remove the emptied wrapper. Split keeps the original key on the left branch and gives the right branch a fresh one, and merge keeps the left key and drops the absorbed right one. Insert always allocates fresh keys, and shifted siblings keep theirs. A clone-and-reinsert version renders the same tree but swaps keys under selectors, anchors, projections and collaboration mapping; an early insert even reused the key of the node already at that path. Code: `packages/plitejs/test/snapshot-contract.ts:3447` (split), `:3510` (merge), `:4994` (wrap), `:5353` (unwrap), `:5656` (lift), `packages/plitejs/src/transforms-node/wrap-nodes.ts:274`. Sources: `solutions/logic-errors/2026-04-07-plite-wrapnodes-should-compose-insert-and-move-to-preserve-ids.md`, `solutions/logic-errors/2026-04-07-plite-unwrapnodes-should-preserve-moved-child-ids.md`, `solutions/logic-errors/2026-04-07-plite-liftnodes-should-compose-move-split-and-remove-to-preserve-ids.md`, `solutions/logic-errors/2026-04-07-plite-split-node-should-keep-left-branch-id-and-rebase-inward.md`, `solutions/logic-errors/2026-04-07-plite-merge-node-should-keep-left-branch-id-and-rebase-inward.md`, `solutions/logic-errors/2026-04-07-plite-node-op-wrappers-must-not-reuse-runtime-ids-or-read-committed-snapshots-inside-transactions.md`.
- **`tx.nodes.set` removes a key set to `null`.** It treats `null` like `undefined` (`newValue != null`), so it can never store a top-level property as `null`; use a sentinel value when null has meaning. `editor-transforms.mdx` documents only `undefined` as removal, and the retired doc's claim that a null write fails validation was false. Code: `packages/plitejs/src/transforms-node/set-nodes.ts:285`, `packages/plitejs/test/transforms/setNodes/split/text-remove.tsx`. Source: `plite/reference/public-docs/concepts/11-normalizing.mdx`.
- **`isolating: true` guards delete, merge and slice fitting, never split.** Three places enforce it: the collapsed one-character delete boundary check (`crossesIsolatingBoundary`), `mergeNodes`, and slice fitting. The delete boundary check stops Backspace in an empty paragraph right after an isolating callout, so it does nothing; `mergeNodes` returns unchanged when a merge would cross the boundary, so an expanded delete keeps the unselected suffix inside the isolating block. `splitNodes` stops only at `object` and void ancestors, so a container that must also refuse a split across its edge declares `object: true` or intercepts `insertBreak`, as the Plite tables example does. The public docs list `isIsolating` only as a query. Code: `packages/plitejs/src/transforms-text/delete-text.ts:1147`, `packages/plitejs/src/transforms-node/merge-nodes.ts:58-86`, `:184`, `packages/plitejs/src/transforms-node/split-nodes.ts:198`, `packages/plitejs/src/core/slice-fit/compiled-slice-fitter.ts:1518`, `packages/plitejs/test/delete-contract.ts:725`, `:1079`. Sources: `plite/ledgers/issue-coverage-matrix.md`, `plite/ledgers/fork-issue-dossier.md`.
- **Start an empty editor by omitting the value.** An explicit empty initial value throws in both layers, Plite with "Expected at least one element" and Plate with "must contain at least one primary-root element". Omit the value instead, and Plate builds a schema-fitted default document; neither layer turns an explicit empty value into a default document, #5351 claims only the clear error, and #3465 left that policy unclaimed. Slate habit is to pass `[]`, and no public doc says to omit it. Code: `packages/plitejs/src/create-editor.ts:256`, `:739`, `packages/platejs/src/lib/editor/withPlite.ts:314`, `:336-349`, `:379`, `packages/plitejs/test/state-tx-public-api-contract.ts:192`. Source: `plite/ledgers/issue-coverage-matrix.md`.
- **Marks on an expanded range come from its first text.** Over an expanded text range, `state.marks()` (`getSelectionMarks`) returns the marks of the first selected text, skipping an anchor at the end of its leaf; only a NodeSelection returns the marks all selected text shares. Plate's default mark `read.isActive` and `toggleMark` both read it, so a range that starts in bold shows Bold as pressed, and toggling removes bold from the whole range even when the rest is plain. This is the open Slate #4750 behavior, and the editor-behavior spec has no row for marks on a mixed selection. Code: `packages/plitejs/src/core/public-state.ts:2437`, `:3792`, `packages/plitejs/src/editor/toggle-mark.ts:92`, `packages/platejs/src/internal/plugin/resolvePlugins.ts:1293`. Source: `plite/ledgers/fork-issue-dossier.md`.
- **`nodes({ reverse: true })` returns exactly the forward result reversed.** It traverses forward through the match, mode, pass and universal pipeline, buffers the matches and reverses them at the end. Feeding a raw reverse traversal into the filter changes the order in which parents and children reach the mode logic; Plite's own query returned `1, 0, 0.3, 0.1` for a forward `0, 0.1, 0.3, 1` before the fix; #5080 is the related upstream issue. Code: `packages/plitejs/src/editor/nodes.ts:118-173`, `packages/plitejs/test/query-contract.ts:2296`. Source: `solutions/logic-errors/2026-05-07-plite-editor-query-reverse-must-reverse-emitted-matches.md`.
- **Marks are not contiguous.** One formatted run can render as several leaves wherever it overlaps other marks or decorations, like HTML tags that cannot overlap. Model a unit that must stay one piece, such as a link or a mention, as an inline element, and keep marks for character-level formatting. Source: `plite/reference/public-docs/concepts/09-rendering.mdx`.
- **Plate models exclusive marks as one enum mark.** Raw Plite has `schema.property.exclusive(id)` groups: toggling one member removes its active peers, and validation and the Yjs projection enforce the group. Plate uses one enum-valued mark instead, as `BaseScriptPlugin` does for subscript and superscript, and no Plate or app code declares an exclusive group, so the group API has no product consumer. Code: `packages/platejs/src/features/basic-nodes/lib/BaseMarkPlugins.ts:260`, `packages/plitejs/src/core/schema-compiler.ts:1164`, `packages/plitejs/test/yjs/exclusive-property-contract.spec.ts`. Sources: `plite/reference/public-docs/concepts/19-schema.mdx`, `plite/reference/public-docs/walkthroughs/04-applying-custom-formatting.mdx`.

## Plugins and types

- **A plugin with several owners stays until its last owner's cleanup.** A plugin installed by more than one owner, as a shared dependency or in two slots, activates once, and one `editor.install(...)` cleanup does not remove it. Hosts that add and remove plugins at runtime depend on this; the public docs cover transitive expansion but not lifetime. Code: `packages/plitejs/test/plugin-configuration.test.ts:3195`. Source: `plite/reference/public-docs/concepts/08-plugins.mdx`.
- **A missing optional plugin group contributes `never`.** When a type maps each installed plugin's optional `api`, `read` or `update` group into a union, a plugin without that group must contribute `never`. `unknown` absorbs the whole union and silently erases every member; it is neutral only in intersections. Code: `packages/plitejs/src/core/plugin.ts:777-803`. Source: `solutions/developer-experience/2026-05-17-plite-extension-composition-hard-cuts-need-creation-time-inference-and-browser-proof.md`.
- **A rename separates values, types and DOM globals.** `NodeApi` (a value) sits beside the `Node` model type, and DOM code uses `globalThis.Node`, `Range`, `Text` and constants such as `Node.TEXT_NODE`; a blind identifier rename rewrote type positions and DOM globals. The internal `ReactEditor` helper value (equal to `DOMEditor`) beside the `ReactRuntimeEditor` instance type is the same trap: one rewrite turned `ReactEditor.hasTarget(...)` into a type-only name. Teaching `import { Node }` from the editor package also shadows the browser `Node` global (#5400). The public-surface contract catches old names only after the fact. Code: `packages/plitejs/src/interfaces/node.ts:621`, `packages/plitejs/src/react/plugin/react-editor.ts:10-22`, `packages/plitejs/test/public-surface-contract.ts:200`. Sources: `solutions/developer-experience/2026-05-13-plite-helper-namespace-codemods-must-separate-values-types-and-dom-globals.md`, `solutions/developer-experience/2026-05-17-plite-react-public-type-hard-cuts-need-internal-runtime-type-splits.md`.
- **A recovery path warns instead of calling `DebugPlugin` error.** `error` throws by default (`throwErrors: true`), so the code-block highlight fallback never ran and `/docs/code-block` crashed during initial normalization on one block that could not be tokenized; the fallback now warns. Test a fallback with the real logging behavior, because a non-throwing `debug.error` stub hides the crash. Code: `packages/platejs/src/features/code-block/lib/BaseCodeBlockPlugin.ts:1040`. Source: `solutions/logic-errors/2026-04-17-code-block-highlight-fallback-must-not-throw-through-debug-plugin.md`.

## Links and headings

- **Only a custom `isUrl` can veto internal link shortcuts.** Link validation accepts `/path` and `#anchor` shortcuts that the default platejs `isUrl` rejects, so the plugin detects a custom `isUrl` by identity (`isUrl !== defaultIsUrl`), and only a custom one may veto them; running `isUrl` first would break default internal links. `#` text that matches a markdown heading is always rejected. Protocol-relative `//` never takes the internal-path shortcut, because link paste returns early and once autolinked a pasted `// comment` before code-block paste could run. `link.mdx` describes `isUrl` only as a validation callback. Code: `packages/platejs/src/features/link/lib/BaseLinkPlugin.ts:143-156`, `BaseLinkPlugin.spec.tsx:236-277`. Sources: `solutions/logic-errors/2026-03-28-link-validation-must-not-treat-double-slash-as-internal-path.md`, `solutions/logic-errors/2026-03-29-custom-isurl-must-be-able-to-reject-internal-link-shortcuts.md`.
- **URL paste stays literal inside markdown link source.** Autolink declines when the text before the caret matches `[text](`. A rule that declines a specialized paste inserts the raw text itself with `tx.text.insert` instead of falling through to a downstream `insertData` that may not exist; the pasted URL once vanished in bare editors. `link.mdx` does not document it. Code: `packages/platejs/src/features/link/lib/BaseLinkPlugin.ts:130`, `:767`, `LinkRules.spec.tsx:180`. Source: `solutions/logic-errors/2026-04-11-link-paste-autolink-must-stay-literal-inside-markdown-source-entry.md`.
- **Inserting an inline at a collapsed caret moves the caret out of it.** Plate calls `tx.link.exitEnd()` and the Plite example `tx.selection.move({ unit: 'offset' })`. Left inside, the next Enter splits from within and carries an empty duplicate link into the new block (the Lexical #1113 class). Every path that creates the same node, such as markdown automd and autolink, needs the same handoff, and its test should press the next key, as the Plite browser row does; the Plate automd spec only asserts the caret. Code: `packages/platejs/src/features/link/lib/BaseLinkPlugin.ts:905`, `LinkRules.spec.tsx:256`, `apps/plite/tests/plite-browser/donor/examples/inlines.test.ts:378`. Sources: `solutions/logic-errors/2026-04-17-markdown-link-automd-must-move-selection-after-inserted-link.md`, `solutions/logic-errors/2026-05-09-collapsed-inline-link-insertion-must-move-selection-outside.md`.
- **Enter at the start of a heading opens a paragraph above it.** It opens an empty paragraph before the heading, not an empty heading, and the original heading keeps its type. Plate's `splitReset` resets `blockPath` at block start, and in Plate a middle or end split makes the new block a paragraph (`EDIT-H-ENTER-001`); the Plite example wraps `editorCommands.insertBreak` with `around()` and keeps middle and end splits as headings. Placing it at the command level covers keyboard, native `insertParagraph` and programmatic calls. The heading section of `markdown-editing-spec.md` has no start-offset Enter row. Code: `packages/platejs/src/internal/plugin/OverridePlugin.ts:194`, `apps/www/src/app/(app)/examples/plite/_examples/markdown-shortcuts.tsx:148`. Source: `solutions/logic-errors/2026-05-09-heading-start-enter-must-normalize-split-block-type.md`.

## History

- **Undo restores the selection from the start of the transaction.** That holds even when the transaction moves the selection before its first document change. Only native-text-input bursts longer than one character take the undo caret from the burst's insert start. Undo from one root view never moves another root's live selection, and a primary-root caret is never restored into a sibling-root batch. The retired rule that leading selection imports are batch preconditions is superseded; do not reapply it. Code: `packages/plitejs/src/history/history-plugin.ts:379`, `packages/plitejs/test/history/history-contract.ts:613`, `:743`, `:948`. Source: `solutions/logic-errors/2026-05-13-plite-history-leading-selection-imports-are-batch-preconditions.md`.
