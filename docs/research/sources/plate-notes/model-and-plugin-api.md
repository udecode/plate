# Model, plugin and history API

These lessons come from retired solution notes and Plite references, and no rule, Vision file, spec or public doc states them. A reader checked each one against the current tree on 2026-10-06. Each source is a path under `docs/` at commit `52625e8502`; read it with `git show 52625e8502:docs/<path>`.

## Model and transforms

- **Structural transforms keep NodeKey identity by moving nodes.** Wrap inserts a fresh-key wrapper and moves the node in, or transfers keys through `nodeKeyTransfers`. Unwrap and lift move children out and remove the emptied wrapper. Split keeps the original key on the left branch and gives the right branch a fresh one, and merge keeps the left key and drops the absorbed right one. Insert always allocates fresh keys, and shifted siblings keep theirs. A clone-and-reinsert version renders the same tree but swaps keys under selectors, anchors, projections and collaboration mapping; an early insert even reused the key of the node already at that path. Code: `packages/plitejs/test/snapshot-contract.ts:3447` (split), `:3510` (merge), `:4994` (wrap), `:5353` (unwrap), `:5656` (lift), `packages/plitejs/src/transforms-node/wrap-nodes.ts:274`. Sources: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-07-plite-wrapnodes-should-compose-insert-and-move-to-preserve-ids.md`, `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-07-plite-unwrapnodes-should-preserve-moved-child-ids.md`, `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-07-plite-liftnodes-should-compose-move-split-and-remove-to-preserve-ids.md`, `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-07-plite-split-node-should-keep-left-branch-id-and-rebase-inward.md`, `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-07-plite-merge-node-should-keep-left-branch-id-and-rebase-inward.md`, `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-07-plite-node-op-wrappers-must-not-reuse-runtime-ids-or-read-committed-snapshots-inside-transactions.md`.
- **`tx.nodes.set` removes a key set to `null`.** It treats `null` like `undefined` (`newValue != null`), so it can never store a top-level property as `null`; use a sentinel value when null has meaning. `editor-transforms.mdx` documents only `undefined` as removal, and the retired doc's claim that a null write fails validation was false. Code: `packages/plitejs/src/transforms-node/set-nodes.ts:285`, `packages/plitejs/test/transforms/setNodes/split/text-remove.tsx`. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/plite/reference/public-docs/concepts/11-normalizing.mdx`.
- **`isolating: true` guards delete, merge and slice fitting, never split.** Three places enforce it: the collapsed one-character delete boundary check (`crossesIsolatingBoundary`), `mergeNodes`, and slice fitting. The delete boundary check stops Backspace in an empty paragraph right after an isolating callout, so it does nothing; `mergeNodes` returns unchanged when a merge would cross the boundary, so an expanded delete keeps the unselected suffix inside the isolating block. `splitNodes` stops only at `object` and void ancestors, so a container that must also refuse a split across its edge declares `object: true` or intercepts `insertBreak`, as the Plite tables example does. The public docs list `isIsolating` only as a query. Code: `packages/plitejs/src/transforms-text/delete-text.ts:1147`, `packages/plitejs/src/transforms-node/merge-nodes.ts:58-86`, `:184`, `packages/plitejs/src/transforms-node/split-nodes.ts:198`, `packages/plitejs/src/core/slice-fit/compiled-slice-fitter.ts:1518`, `packages/plitejs/test/delete-contract.ts:725`, `:1079`. Sources: `52625e85025313eebd4eeb9be2254249ded58676:docs/plite/ledgers/issue-coverage-matrix.md`, `831f5e5da6a37f7d9095c1a81acc6b3de10bd3ba:docs/plite/ledgers/fork-issue-dossier.md`.
- **Start an empty editor by omitting the value.** An explicit empty initial value throws in both layers, Plite with "Expected at least one element" and Plate with "must contain at least one primary-root element". Omit the value instead, and Plate builds a schema-fitted default document; neither layer turns an explicit empty value into a default document, #5351 claims only the clear error, and #3465 left that policy unclaimed. Slate habit is to pass `[]`, and no public doc says to omit it. Code: `packages/plitejs/src/create-editor.ts:256`, `:739`, `packages/platejs/src/lib/editor/withPlite.ts:314`, `:336-349`, `:379`, `packages/plitejs/test/state-tx-public-api-contract.ts:192`. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/plite/ledgers/issue-coverage-matrix.md`.
- **Marks on an expanded range come from its first text.** Over an expanded text range, `state.marks()` (`getSelectionMarks`) returns the marks of the first selected text, skipping an anchor at the end of its leaf; only a NodeSelection returns the marks all selected text shares. Plate's default mark `read.isActive` and `toggleMark` both read it, so a range that starts in bold shows Bold as pressed, and toggling removes bold from the whole range even when the rest is plain. This is the open Slate #4750 behavior, and the editor-behavior spec has no row for marks on a mixed selection. Code: `packages/plitejs/src/core/public-state.ts:2437`, `:3792`, `packages/plitejs/src/editor/toggle-mark.ts:92`, `packages/platejs/src/internal/plugin/resolvePlugins.ts:1293`. Source: `831f5e5da6a37f7d9095c1a81acc6b3de10bd3ba:docs/plite/ledgers/fork-issue-dossier.md`.
- **`nodes({ reverse: true })` returns exactly the forward result reversed.** It traverses forward through the match, mode, pass and universal pipeline, buffers the matches and reverses them at the end. Feeding a raw reverse traversal into the filter changes the order in which parents and children reach the mode logic; Plite's own query returned `1, 0, 0.3, 0.1` for a forward `0, 0.1, 0.3, 1` before the fix; #5080 is the related upstream issue. Code: `packages/plitejs/src/editor/nodes.ts:118-173`, `packages/plitejs/test/query-contract.ts:2296`. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-05-07-plite-editor-query-reverse-must-reverse-emitted-matches.md`.
- **Marks are not contiguous.** One formatted run can render as several leaves wherever it overlaps other marks or decorations, like HTML tags that cannot overlap. Model a unit that must stay one piece, such as a link or a mention, as an inline element, and keep marks for character-level formatting. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/plite/reference/public-docs/concepts/09-rendering.mdx`.
- **Plate models exclusive marks as one enum mark.** Raw Plite has `schema.property.exclusive(id)` groups: toggling one member removes its active peers, and validation and the Yjs projection enforce the group. Plate uses one enum-valued mark instead, as `BaseScriptPlugin` does for subscript and superscript, and no Plate or app code declares an exclusive group, so the group API has no product consumer. Code: `packages/platejs/src/features/basic-nodes/lib/BaseMarkPlugins.ts:260`, `packages/plitejs/src/core/schema-compiler.ts:1164`, `packages/plitejs/test/yjs/exclusive-property-contract.spec.ts`. Sources: `831f5e5da6a37f7d9095c1a81acc6b3de10bd3ba:docs/plite/reference/public-docs/concepts/19-schema.mdx`, `52625e85025313eebd4eeb9be2254249ded58676:docs/plite/reference/public-docs/walkthroughs/04-applying-custom-formatting.mdx`.

- **A large child-range replacement never spreads its children into call arguments.** V8 throws `RangeError: Maximum call stack size exceeded` once one call spreads about 125,000 arguments, while Bun's JavaScriptCore accepted 500,000 in the same probe, so a Bun test does not catch it. In June 2026, undo after a 200k-block select-all delete timed out with `undoDeleteRestored=0` although the history batch existed, because replay spread the restored children into a call; the fix built the array with `slice` and `concat` in `replaceChildRange` (`packages/plitejs/src/utils/modify.ts:46-51`), a file nothing imports today. The live writer, `spliceIndexedChildren`, spreads the inserted nodes into `Array.prototype.splice` (`packages/plitejs/src/core/change/document-index.ts:333-338`). On 2026-10-08 a Node 24 (V8) probe of `createEditor` with `history()` threw that RangeError from `spliceIndexedChildren` on undo after select-all delete of a 150,000-block document and left one block, while the same steps at 1,000 blocks restored every block; one `tx.nodes.insert` of 150,000 nodes threw the same way. The www huge-document demo offers 200,000 blocks (`apps/www/src/registry/examples/huge-document-demo.tsx:59-62`). Keep every child-range writer array-based, and test a large writer under V8. Source: `c70bacbd4a:docs/plite/research/2026-06-12-huge-doc-architecture/README.md:254-304`. Limit: the probe ran in Node, not in a browser; Chromium runs the same engine.

- **A shared state field is not a concurrent collection.** A state field's own effect replaces the whole value (`reduce` returns the effect's new value, `packages/plitejs/src/core/state-field.ts:172-176`), so two peers that each replace a record list cannot both keep their additions. In a September 2026 two-peer probe, each peer replaced one field with its own one-record list and synchronized twice; the Yjs state vectors and document JSON matched while the active field values still differed (`docs/plite/research/2026-09-10-authored-changes/sources/shared-field-probe.mjs`; its log was not committed and the probe was not rerun on the current tree). A collection that peers edit concurrently needs per-record operations and a deterministic conflict rule, and Yjs document convergence proves nothing about the editor's projected fields. Source: `docs/plite/research/2026-09-10-authored-changes/skill-audit.md:17-23`, `assessment.md:36`.

- **Repairing an invalid wrapper keeps its content.** In March 2026 the column-group repair unwrapped a group's paragraph child instead of the group, leaving invalid content for the next normalization to fail on, and removed a group with no valid column together with the user's blocks. A repair that drops a wrapper keeps its blocks, and its test asserts the content for a wrapper with one valid child, with one plain block child and with no valid child. Today `BaseColumnPlugin` declares at least two column children (`schema.content.element(BaseColumnItemPlugin, { min: 2 })`, `packages/platejs/src/features/layout/lib/BaseColumnPlugin.ts:174-180`), and its own correction only rescales widths (`:186-222`). On 2026-10-08 a scratch probe of Plate's `createEditor` with `BaseColumnPlugin`, loading package source, loaded a one-column group as that column plus an empty second column, and a group of two plain paragraphs as one column holding both plus an empty column, so schema fitting keeps the content. No test pins either load: 'constructs configured column-group content from plugin-name grammar' (`packages/platejs/src/features/layout/lib/BaseColumnPlugin.spec.ts:95`) only asserts that `schema.assertFragment` rejects both shapes. Source: `c70bacbd4a7523ae3ebfd820cec0ea8ec228e9ad:docs/solutions/logic-errors/2026-03-23-layout-invalid-column-groups-should-unwrap-content-instead-of-dropping-it.md`.

- **Anchors map in the draft and roll back with it.** A persistent anchor from `editor.anchor` checkpoints its value when a transaction begins, maps each draft change as it applies, and restores the checkpoint when the transaction discards, so an aborted update that removed the target leaves the anchor on its old range (`packages/plitejs/src/core/anchor.ts:1685-1764`, test `packages/plitejs/test/range-anchor-contract.ts:208`). Range anchors default to `inward`, so text inserted at either edge stays outside an annotation's span, while paths and points default to `forward` (`anchor.ts:573-574`, documented in `content/docs/api/anchor.mdx:32-33`). Legacy Slate's `rangeRef` updated eagerly on every operation and defaulted to `forward` although its own `Range.transform` defaulted to `inward` (`ianstormtaylor/slate@945a484df249:packages/slate/src/editor/range-ref.ts:9`, `ianstormtaylor/slate@945a484df249:packages/slate/src/interfaces/range.ts:234`). The April 2026 port rejected both habits: eager updates let refs drift from the committed document, and `forward` lets an anchored span swallow adjacent typing. Source: `c70bacbd4a7523ae3ebfd820cec0ea8ec228e9ad:docs/solutions/logic-errors/2026-04-03-plite-range-refs-must-be-transaction-aware-and-default-inward.md`.

- **A container block's insert and convert commands place the caret inside it.** When blockquote became a container in April 2026, the app's `setBlockType` still set `type` with a flat `setNodes`, normalization repaired the shape after the selection had drifted, and typing after `/quote` went into the previous paragraph while the package toggle worked in isolation. The app helper is gone: the slash menu calls `tx.plugin(BaseBlockquotePlugin).upsert({}, { select: true })` (`apps/www/src/registry/components/editor/slash.tsx:208`). On 2026-10-08 a source probe of `BaseBlockquotePlugin` put the caret at `[1, 0, 0]` after `insert` below a non-empty paragraph, at `[0, 0, 0]` after `insert` or `upsert` into an empty one, and inside the wrapped paragraph after `toggle`. `packages/platejs/src/lib/plugin/block-insertion.spec.ts:108` asserts the nested caret path for details, column groups and tables but only the top-level index for blockquote. When a node becomes a container, route every UI insert and convert through the package command and assert the nested caret path. Source: `c70bacbd4a7523ae3ebfd820cec0ea8ec228e9ad:docs/solutions/ui-bugs/2026-04-02-blockquote-transforms-must-keep-selection-inside-the-new-quote.md`.

- **A transform that moves several nodes finds each target through an anchor.** `wrapNodes` anchors every path it will move and the new wrapper with `editor.anchor(path, { association: 'forward', deletion: 'drop' })`, then resolves both before each `moveNodes` (`packages/plitejs/src/transforms-node/wrap-nodes.ts:282-308`); `liftNodes` on a node selection, and `unwrapNodes` on a node selection or a matched range, anchor every target path before the first edit and release each one just before acting on it, unwrap in reverse order (`packages/plitejs/src/transforms-node/lift-nodes.ts:112-128`, `packages/plitejs/src/transforms-node/unwrap-nodes.ts:135-150`, `:167-183`). The April 2026 first `wrapNodes` kept paths valid by arithmetic instead, moving every block from one post-insert source index, because recomputing each source path as if the tree were unchanged wrapped the wrong siblings after the first move, and the range lift and unwrap of the same month lifted in reverse index order and rebuilt the selection by hand. A new multi-node transform anchors its targets rather than recomputing paths after each edit; `docs/vision/plite.md` states the matching rule only for the selection ('Structural transforms map anchor and focus independently'). Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-07-plite-range-wrapnodes-should-move-from-a-stable-source-index.md:17-45`; also `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-07-plite-range-liftnodes-should-rewrite-selection-from-lifted-child-span.md:28-46` and `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-07-plite-range-unwrapnodes-should-rewrite-selection-from-wrapper-child-counts.md:28-48`.

- **Each mounted editor gets its own copy of a reusable value.** In March 2026 two docs pages crashed in DOM selection sync with "Unable to find the path for … node": the version-history demo mounted the same node objects in the live editor, the saved revisions and the diff inputs, and `/docs/table` mounted the generic table demo and the no-merge table demo from one `tableValue` tree. Both looked like table or diff bugs, and the first hard error came from the editable's selection handling; the cause was two mounted editors sharing one node graph, and saved revisions that were new outer arrays over shared nodes. Clone at the editor boundary, as today's demos do: `createValue` deep-clones each `DEMO_VALUES` entry, and the version-history demo saves and compares `structuredClone(editor.read.value())`. Treat two demos on one page that start from one constant as a multi-editor case even when both look read-only. Limit: the crash was on the March 2026 runtime; whether today's Plite still fails when two editors share node objects was not rechecked, so keep cloning until a test shows sharing is safe. The diff-only plugin the note scoped to the comparison pane is gone; the demo now compares through `compare` from `platejs/diff`. Code: `apps/www/src/registry/examples/values/demo-values.tsx:112-114`, `apps/www/src/registry/examples/version-history-demo.tsx:188`, `:225`. Sources: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/ui-bugs/2026-03-27-version-history-demo-must-clone-snapshots-per-editor.md`, `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/ui-bugs/2026-03-30-docs-demos-must-clone-reusable-values-per-editor.md`.

- **`tx.value.replace` gives every node a fresh NodeKey and clears local history.** It fits and reinserts the whole document, so even a replacement with equal content re-keys every node, while `tx.nodes.remove` and `tx.nodes.insert` leave untouched and shifted siblings on their keys; its JSDoc says it resets local history (`packages/plitejs/src/interfaces/editor.ts:695`). So an example control or app action that changes part of a mounted document edits the affected nodes with `tx.nodes.*`, which keeps keyed selectors, overlays, selection, collaboration mapping and undo on the same nodes; keep `value.replace` for loading a document. In April 2026 a mount-time replace churned runtime ids and desynced keyed projections from the mounted tree, and example controls that changed generated stress content moved to removing and inserting their own blocks. Bun probes on 2026-10-08 against `packages/plitejs/src` found both keys of a two-paragraph `createEditor` document changed after replacing it with a deep copy of the same children, the shifted key kept after `tx.nodes.remove({ at: [0] })`, and, with `history()` installed, undo after a typed insert returning `applied` while undo after the same insert followed by a replace returned `empty`; the probes were not committed. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-20-editable-blocks-app-owned-surfaces-must-not-churn-runtime-ids-or-miss-plain-editor-updates.md:64-66`, `:125-128`.

- **Separate property presence from metadata policy.** The July ElementState repair moved generic property iteration into `NodeApi.hasProps(node, { ignore })` instead of moving Plate's entire empty-state plugin into Plite. Current `packages/plitejs/src/interfaces/node.ts:734-753` removes structural fields and checks whether any remaining property survives the caller's ignore predicate. `packages/platejs/src/lib/plugins/element-state/ElementStatePlugin.ts` supplies the product policy: ignore `type` and element properties whose installed schema role is `metadata`. The generic helper's text, mark and ignored-property cases remain in `packages/plitejs/test/interfaces-contract.ts:92-108`. Source: `c70bacbd4a:docs/plans/2026-07-02-plate-next-element-state-plite-primitive.md:291-299`. Limit: current metadata lookup uses schema roles, replacing the plan's plugin `node.isMetadataProp` callback; tests were not rerun.

## Plugins and types

- **A plugin with several owners stays until its last owner's cleanup.** A plugin installed by more than one owner, as a shared dependency or in two slots, activates once, and one `editor.install(...)` cleanup does not remove it. Hosts that add and remove plugins at runtime depend on this; the public docs cover transitive expansion but not lifetime. Code: `packages/plitejs/test/plugin-configuration.test.ts:3195`. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/plite/reference/public-docs/concepts/08-plugins.mdx`.
- **A missing optional plugin group contributes `never`.** When a type maps each installed plugin's optional `api`, `read` or `update` group into a union, a plugin without that group must contribute `never`. `unknown` absorbs the whole union and silently erases every member; it is neutral only in intersections. Code: `packages/plitejs/src/core/plugin.ts:777-803`. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/developer-experience/2026-05-17-plite-extension-composition-hard-cuts-need-creation-time-inference-and-browser-proof.md`.
- **A rename separates values, types and DOM globals.** `NodeApi` (a value) sits beside the `Node` model type, and DOM code uses `globalThis.Node`, `Range`, `Text` and constants such as `Node.TEXT_NODE`; a blind identifier rename rewrote type positions and DOM globals. The internal `ReactEditor` helper value (equal to `DOMEditor`) beside the `ReactRuntimeEditor` instance type is the same trap: one rewrite turned `ReactEditor.hasTarget(...)` into a type-only name. Teaching `import { Node }` from the editor package also shadows the browser `Node` global (#5400). The public-surface contract catches old names only after the fact. Code: `packages/plitejs/src/interfaces/node.ts:621`, `packages/plitejs/src/react/plugin/react-editor.ts:10-22`, `packages/plitejs/test/public-surface-contract.ts:200`. Sources: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/developer-experience/2026-05-13-plite-helper-namespace-codemods-must-separate-values-types-and-dom-globals.md`, `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/developer-experience/2026-05-17-plite-react-public-type-hard-cuts-need-internal-runtime-type-splits.md`.
- **A recovery path warns instead of calling `DebugPlugin` error.** `error` throws by default (`throwErrors: true`), so the code-block highlight fallback never ran and `/docs/code-block` crashed during initial normalization on one block that could not be tokenized; the fallback now warns. Test a fallback with the real logging behavior, because a non-throwing `debug.error` stub hides the crash. Code: `packages/platejs/src/features/code-block/lib/BaseCodeBlockPlugin.ts:1040`. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-04-17-code-block-highlight-fallback-must-not-throw-through-debug-plugin.md`.

- **`Extract` keeps or drops whole union members.** `Extract<HistoryOutcome, { status: 'applied' | 'failed' } | { reason: string }>` silently dropped the member `{ status: 'applied' | 'empty' | 'busy' }`, because that whole member is not assignable to the filter, so the planned `HistorySettlement` could never be `applied`; three reviewers caught it in the 2026-10-05 plan. Give each status its own member, or write the narrower union first and extend it, and check that the wanted value is assignable. Code: `packages/plitejs/src/interfaces/editor.ts:399-420` declares `HistorySettlement` explicitly. Source: `docs/research/probes/2026-10-05-history-replay-result/panel-r1/r1-astra.md:15-23`, also `r1-opus.md:32-35` and `r1-sol.md:13-21`.

- **A custom prop that reuses a native attribute name omits the native key.** Plite's `EditableProps` declares `placeholder?: ReactNode` and also spreads textarea attributes, which carry their own `placeholder?: string`. Before the April 2026 fix TypeScript intersected the two, a type narrower than either contract, so a JSX placeholder such as `<><p>Type something</p></>` failed `tsc` with a string-heavy union error while the runtime rendered it. `EditableProps` now omits `placeholder` (with `autoFocus`, `children`, `className`, `id`, `onKeyDown`, `onPaste`, `readOnly`, `spellCheck` and `style`) from `TextareaHTMLAttributes` (`packages/plitejs/src/react/components/editable-text-blocks.tsx:683-739`). Omit the native key whenever a public prop redefines a DOM attribute, and pin the wider type with a compile-time case. Source: `831f5e5da6a37f7d9095c1a81acc6b3de10bd3ba:docs/solutions/developer-experience/2026-04-15-plite-react-text-block-placeholder-contract-must-omit-native-textarea-placeholder.md:22-86`. Limit: the compile-time JSX placeholder case it added to `primitives-contract.tsx` is gone, and no test or Plite example passes a JSX placeholder to `Editable` (checked 2026-10-08), so nothing pins the omission.

- **A public barrel cut starts with its own importers and its type re-exports.** Cutting value exports from the Plite root in May 2026 broke Plite itself first: `create-editor.ts` imported runtime helpers through the root barrel (`Export named 'toggleMark' not found`), benchmark scripts imported the internal `Editor` value through the public root, and a root `export type * from './interfaces'` kept the internal `EditorStaticApi` method table in autocomplete after its runtime value was gone. Today the root names its `interfaces/editor` exports one by one (`packages/plitejs/src/index.ts:108-111` and the type list after it), so `EditorStaticApi` (`packages/plitejs/src/interfaces/editor.ts:3877`) stays internal, and benchmarks import internals from `packages/plitejs/src/internal` (`benchmarks/editor/benchmarks/plite-command-dispatch-benchmark.ts:9`). Other interface files are still re-exported whole (`index.ts:305-319`), so any export added to them becomes public. Before cutting a barrel, find the source files and scripts that import through it, and remove a type export together with its value, because the type alone keeps the deleted API discoverable. Source: `c70bacbd4a7523ae3ebfd820cec0ea8ec228e9ad:docs/solutions/developer-experience/2026-05-03-plite-public-root-hard-cuts-need-internal-imports-and-explicit-type-exports.md`.

- **A public option type lists exactly the options the runtime reads.** Plite's exported transform types drifted from the runtime twice in April 2026: `delete`, `liftNodes`, `wrapNodes` and `unwrapNodes` took optional `at` and options at runtime while the exported types still required some of them, and later the wrap, unwrap and lift option bags were narrowed to `{ at? }` while the runtime still honored `match`, `mode`, `split` and `voids`. Typed callers and agents then could not reach supported behavior, the docs described the narrower cut, and proof ledgers had to pick a fake pass or a fake skip. The current interfaces list those options (`packages/plitejs/src/interfaces/transforms/node.ts:51-60`, `:100-122`, `text.ts:4-17`). Type and document every option the implementation reads, or remove the behavior instead of keeping untyped support. ## History

- **Undo restores the selection from the start of the transaction.** That holds even when the transaction moves the selection before its first document change. Only native-text-input bursts longer than one character take the undo caret from the burst's insert start. Undo from one root view never moves another root's live selection, and a primary-root caret is never restored into a sibling-root batch. The retired rule that leading selection imports are batch preconditions is superseded; do not reapply it. Code: `packages/plitejs/src/history/history-plugin.ts:379`, `packages/plitejs/test/history/history-contract.ts:613`, `:743`, `:948`. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/solutions/logic-errors/2026-05-13-plite-history-leading-selection-imports-are-batch-preconditions.md`.

- **Undo, pending review, authored history and revert are four jobs.** Local undo reverses the user's recent action in the active view, mapped through later changes; pending review accepts or rejects selected proposals, including by author; authored history reads retained changes and decisions by author or revision; and reverting accepted work creates a new compensating change after dependency checks, never erasing history. A decision scoped to an author means that author's pending proposals, not every operation they ever made, and adding `userId` to History batches or to Yjs or Loro undo stacks does not make an audit log. Capture authorship at the committed transaction or change-group boundary, before publication, and keep the human author, the device or replica and the later reviewer distinct; AI edits keep their source and initiating user. Dependencies govern decisions: if Alice proposes a paragraph and Bob edits inside it, rejecting Alice must either be refused or return the closure that also removes Bob's work. Plite's authored capability keeps these apart today: `read.select({ ids, authorId, status })` and `read.preview` feed `update.decide`, and `update.revert` compensates retained accepted content (`packages/plitejs/src/authored/authored.ts:175-198`). Source: `docs/plite/research/2026-09-10-authored-changes/assessment.md:87-106`; the landed contract is `docs/research/decisions/authored-change-ownership.md`.

- **Detect an asynchronous result by a callable `then`.** History's first synchronous-result build tested `ownerResult instanceof Promise`, which is false for a promise from another realm or a replaced global `Promise`, so a foreign promise went to synchronous settlement with an undefined status and value; the next attempt, `'then' in ownerResult`, threw on `undefined`, `null` or a primitive outside the guarded `try` and left `pending` stuck, and sent a result with `then: undefined` down the pending path. The shipped check is `typeof ownerResult?.then === 'function'`, adopted with `Promise.resolve(ownerResult).then(settle, fail)`; anything else settles in the call, where a malformed value fails inside the guarded settlement. ## Suggestions and comments

- **A range record cannot own a proposed edit.** Comments annotate content that already exists, so a range plus a record is enough for them. A suggestion can add content that does not exist in the accepted document, and a comment-style range cannot make that content editable, keep its deleted counterpart or map edits between the accepted and proposed coordinate spaces. Replying to a suggestion also does not make the reply store the owner of acceptance, rejection or history: Comments keeps its own thread lifecycle and references the change identity. Native authored changes own proposals now (`docs/research/decisions/authored-change-ownership.md`). Source: `docs/plite/research/2026-09-10-authored-changes/assessment.md:9-15`.

- **A correction a proposal triggers joins that proposal.** In April 2026 `TrailingBlockPlugin` inserted its paragraph inside `normalizeNode`, suggestion mode recorded the insert as a user edit, and typing in a table showed an unrelated `Add: Paragraph` card; the fix added an `insert` hook that app kits wrapped in `withoutSuggestions`. Both are gone. Trailing blocks are now a `children` correction (`packages/platejs/src/utils/plugins/TrailingBlockPlugin.ts:28-57`), and native authored changes compose a correction into the captured change of the operation that triggered it (`packages/plitejs/src/authored/authored.ts:2652-2686`). On 2026-10-08 a Bun probe on source, with `authored({ authorId: 'alice' })` and a stand-in trailing-paragraph correction rather than Plate's plugin, proposed a quote at the end of a one-paragraph document: the proposed view gained the quote and an empty trailing paragraph, the store held one pending `structure` change, and rejecting it removed both. A correction therefore needs no suggestion escape hatch. The limit runs the other way: loading a saved document with authored changes throws when a correction would change it ('Corrections cannot change a loaded document with authored changes.', `authored.ts:2384-2390`, test `packages/plitejs/test/authored-ingress-contract.test.ts:295`). Source: `c70bacbd4a7523ae3ebfd820cec0ea8ec228e9ad:docs/solutions/logic-errors/2026-04-06-trailing-block-normalize-inserts-must-run-without-suggestions.md`.

- **String content is not a deletability test.** The retired suggestion-mode delete loop stopped when `tx.text.string(range)` was empty, so Backspace after a mention, an inline void whose only text is empty, proposed nothing, while a link worked because it holds text. Fixing that exposed a chain in April 2026: neighbor text marked for removal, the caret past the mention's left edge, a second suggestion card on the next Backspace, an expanded delete stopping at the void, and an endless forward loop when typing over a range that crossed it; Backspace at a paragraph start after an image was also mislabeled a paragraph-break removal. The rules: check for inline elements, not only text, before calling a range empty; treat an inline void as one unit; keep walking an expanded delete past it and advance a forward walk past its right edge; keep a block void a block removal. Suggesting mode now sets a native authored `propose` view (`packages/platejs/src/features/suggestion/BaseSuggestionPlugin.ts:15-29`) that records the ordinary delete, and `apps/plite/tests/plite-browser/authored-changes.spec.ts:380` and `:502` prove mention Backspace and selected block media deletion through undo, redo and rejection. On 2026-10-08 no test in the twenty `authored-*` files under `packages/plitejs/test/`, from `authored-anchor-contract.test.ts` to `authored-view-contract.test.ts`, in that spec or in `apps/www/tests/browser/suggestion.spec.ts` proposed an expanded delete across a mention, deleted a date or inline equation, or pressed Backspace at the start of the paragraph after an image. Source: `c70bacbd4a7523ae3ebfd820cec0ea8ec228e9ad:docs/solutions/logic-errors/2026-04-08-suggestion-delete-backward-must-mark-inline-voids.md`.

- **A change summary must include inline voids' visible text.** In April 2026 the suggestion card built its `Delete:` summary from text leaves only, so `Hello @Ada!` summarized as `Hello !` and dates and inline equations vanished; the fix read each inline void's display field instead of adding a summary protocol. Those fields have moved, and the plain-text encoders now own the visible text: a mention encodes `@label` (`packages/platejs/src/features/mention/lib/BaseMentionPlugin.ts:55-56`), an inline equation its `latex` (`packages/platejs/src/math/lib/BaseEquationPlugin.ts:65-66`), and `platejs/plain-text` serializes through them (`packages/platejs/src/plain-text.ts`). The current registry card has the old defect again: `readContentText` returns `text` leaves and recurses into children, so a mention's empty child contributes nothing to `Delete “…”` (`apps/www/src/registry/components/editor/discussion.tsx:593-609`; read on 2026-10-08, not run), and no test renders a summary over an inline void.
