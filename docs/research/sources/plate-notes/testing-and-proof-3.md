# Testing and browser proof, part 3

## Release claims

- **Choose the release claim before harvesting parity tests.** The April 2026 Slate v2 draft separated confidence in one proved default stack from a claim to replace all legacy Slate behavior. It chose the narrower claim, required reasons for excluded legacy cases, and kept full replacement at No-Go. This prevents test-file counts or success on a small stack from becoming a blanket compatibility claim. Source: `c70bacbd4a:docs/plans/2026-04-07-plite-remaining-release-hardening-plan.md:30-102`, with the final decision at `:466-547`. Limit: the draft's `Plite + EditableBlocks + withHistory(createEditor())` stack is historical; current release-proof tooling and current public APIs own today's claim.

- **Prove the default stack together.** Green core, history and DOM packages do not establish that their public integration works. The April 2026 draft therefore required one browser stack to exercise typing, selection recovery, clipboard, undo/redo, reset/load and an outer transaction as one history step. Current richtext browser proof still exercises integrated behavior; for example, `apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:5361-5414` combines DOM selection, a mark command, a native click, follow-up typing, runtime-error capture and selection assertions. Source: `c70bacbd4a:docs/plans/2026-04-07-plite-remaining-release-hardening-plan.md:265-351`. Limit: one integrated route establishes only the behaviors and transports it exercises.

## Harness traps

- **A text-offset click must distinguish model splits from DOM splits.** The mark-click tracer first exposed a real stale-node exception, then exposed a helper that clicked the wrong segment after marking changed model paths. A later highlighted-text row had the opposite shape: decorations split DOM leaves while preserving one model path. Resolve the current model point, then count offsets across its DOM segments when a fallback is needed. Current `packages/test/src/playwright/dom-text-actions.ts:108-183` prefers the browser handle's resolved DOM point and otherwise accumulates string-segment lengths. Source: `c70bacbd4a:docs/plans/2026-04-23-plite-remaining-perfect-architecture-batches-plan.md:1455-1493`, `:1796-1807`. Limit: model path indices and DOM text-node indices are not interchangeable.

- **Capture runtime errors around every generated scenario step.** The April 2026 bridge work found that browser rows could pass model assertions while a hidden stale-node exception occurred between steps. Moving error capture into the shared scenario runner made that failure visible across generated tests. Current `packages/test/src/playwright/harness-scenario.ts:121-124` enables `recordBrowserRuntimeErrors` unless explicitly disabled and asserts the recorder after steps at `:806`; the richtext mark-click row also asserts the DOM caret, model selection and follow-up text. Source: `c70bacbd4a:docs/plans/2026-04-23-plite-remaining-perfect-architecture-batches-plan.md:1583-1673`. Limit: the recorder's default filters are narrower than strict error capture, as the existing 'shared runtime-error recorder is lenient unless strict' lesson explains.

- **A browser command assertion reads the event trace before relying on the latest commit.** The June 2026 richtext gate failed because browser selection synchronization could publish after a keydown command and replace `lastCommit.command`. The kept browser assertion finds the `move-selection` entry in the kernel trace (`apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:5211-5245`); a focused caret-engine test checks the immediate command commit separately (`packages/plitejs/test/react/caret-engine-contract.test.ts`, 'caret movement tags the semantic command commit'). Source: `c70bacbd4a:docs/plans/2026-06-25-auto-six-hour-plate-plite-quality.md:156`, `:342`. Limit: today's immediate commit contract uses the `semantic-command` tag rather than the retired `move_selection` metadata field; a trace alone does not prove the resulting selection.

- **Finish barrel generation before starting tests that import those barrels.** In the June 2026 deprecated-prop cleanup, Core tests ran while `brl` rewrote component barrels and failed with transient ENOENT on `src/static/components/index.ts`; the serial run passed after generation completed. Source: `c70bacbd4a:docs/plans/2026-06-25-auto-six-hour-plate-plite-quality.md:427`. Limit: this is a producer-consumer scheduling failure in the historical Core package, not evidence of a current Plate runtime defect.

- **Re-anchor the native caret in a repeated native-typing benchmark.** The June 7 draft Plite cross-editor harness reset model selection between iterations without restoring native selection at mounted text. A repeated run then failed its visible-text check. The repair anchored the browser caret, asserted the typed-count delta for that iteration, waited for pending native repair and recorded model, view and DOM selections separately. Source: `c70bacbd4a:docs/plans/2026-06-07-plite-eight-hour-automation.md:450`, with the failure described at lines 246-247. Current native selection setup remains explicit in `packages/plitejs/src/react/editable/browser-handle.ts:839-875`. Limit: model-only selection setup cannot certify native typing, and the old helper names are not current API guidance.

- **Native-caret helpers must use the editable's selection root and realm.** A promoted draft Plite helper used ownerDocument.getSelection and missed nested shadow-root selection. The June 7 audit repaired it to resolve Document or ShadowRoot selection and dispatch a realm-correct event, then added a nested-shadow browser row. Source: `c70bacbd4a:docs/plans/2026-06-07-plite-eight-hour-automation.md:459`. Current `packages/plitejs/src/react/editable/browser-handle.ts:839-875` resolves the mounted element's root and its document's ShadowRoot constructor. Limit: a document-level helper passing in ordinary DOM does not prove shadow-root behavior.

- **Compare native and model caret coordinates after resolving the DOM endpoint.** The June 7 draft Plite virtualized typing row assumed one raw browser offset across engines. The repaired oracle kept exact text assertions but required collapsed model selection and resolved native selection to agree, within narrowly allowed browser outcomes. Source: `c70bacbd4a:docs/plans/2026-06-07-plite-eight-hour-automation.md:466,472`. Current DOM-to-model projection is owned by nullable resolveRange in `packages/plitejs/src/dom/plugin/dom-editor.ts`, and nested keydown reads use that projection (`react/editable/keyboard-input-strategy.ts:233-257`). Limit: equal paths alone do not establish equal caret positions; compare offsets too.

- **Visible virtualized text is not proof that pointer hit testing reaches it.** In the June 7 draft Plite pagination run, row wrappers overlapped spread pages and intercepted clicks even though text looked correctly rendered. A DOM hit-test probe found the wrapper owner; the repair bounded row hitboxes horizontally and checked actual text-leaf hits, native/model caret placement, clicks, double-clicks and margin drags. Source: `c70bacbd4a:docs/plans/2026-06-07-plite-eight-hour-automation.md:469-470`. Limit: the historical pagination implementation has since changed; retain the hit-test proof requirement rather than copying its old layout mechanism.

- **After undo, type again to prove the restored caret is usable.** The May scroll-into-view regression passed a text-visible assertion while delayed undo left the selection at the wrong offset. The stronger row asserts model selection after undo, scrolls away again, types a third marker and checks that the marker lands in the edited block rather than the first block. That sequence survives in `apps/plite/tests/plite-browser/donor/examples/huge-document.test.ts:2216`, including caret visibility and the third insertion target. Source: `docs/plans/2026-05-13-plite-history-selection-precondition-ralplan.md:31-76`. Limit: this desktop browser test body was inspected, not rerun; it does not reinstate the plan's superseded mixed-commit selection-precondition rule.

- **A bulk-mapping benchmark must construct one bulk change.** The July anchor calibration initially measured hundreds of complete editor commits when the question concerned mapping many anchors through one change containing many edits. Those workloads include different costs. Construct the intended canonical change explicitly and report document size, anchor count and edit count separately. Evidence: `c70bacbd4a:docs/plans/2026-07-18-execute-wordgard-plite-architecture-ledger.md:318`. This is a workload-design lesson; the later timing in the plan lacks a measured source revision and is not promoted as a reproducible performance result.

- **A successful aggregate must prove its leaf work ran.** Root Turbo aggregates once returned success under `--only` without executing their source checks. The repair made the aggregate reject missing partition proof rather than treat being inside Turbo as success. Evidence: `c70bacbd4a:docs/plans/2026-08-28-platejs-plitejs-turbo-ci-closure.md:341-348`. Current `tooling/scripts/run-entrypoint-package-task.mjs:85-117` inspects the dry graph and requires successful dependency cache entries. Test aggregate scheduling and controlled add/edit/rename/delete invalidation; an empty or disconnected green aggregate establishes no source correctness.

## Ownership and type checks

- **Prove a configuration hard cut at both the type and runtime boundaries.** Removing an option from TypeScript does not prove that JavaScript callers or cast values stopped activating its old behavior. The May 2026 draft Plite void migration paired a public no-boolean type contract with a runtime negative case and positive cases for each retained preset. Source: `c70bacbd4a:docs/plans/2026-05-13-plite-void-kind-api-ralplan.md:251-263,289-300`. Current code retains that distinction: `packages/plitejs/test/public-element-void-kind-contract.ts:15-23` excludes boolean, and `src/core/schema-compiler.ts:2046-2051` rejects unsupported kinds. Limit: current runtime refusal throws during compilation; it does not preserve the draft's silent non-void fallback.

- **Test disappearance separately from a path shift.** A selection hook surviving an insertion does not prove it survives its watched element disappearing. The self-removal investigation required two distinct lifecycles: a selected renderer removing itself, and an explicit-path observer remaining mounted after its target is removed. Current `packages/plitejs/test/react/use-element-selected.test.tsx:319-405` retains both cases. `packages/plitejs/src/react/hooks/use-element-selected.ts` resolves and validates the watched path before querying selection intersection, returning false for a missing path. This supports a precise guard rather than a broad catch that could conceal tree errors. Source: `c70bacbd4a:docs/plans/2026-05-08-plite-use-element-selected-self-removal-ralplan.md:65-113`, with the proof split explained at lines 353-364. Limit: source and test inspection only; these package cases do not certify browser selection scheduling.

## Proof width

- **A programmatic selection limitation narrows the proof claim.** In the June 7 draft Plite shadow-DOM run, a direct WebKit probe found the nested editor but adding a native range inside it left rangeCount at zero. Firefox passed the helper row; WebKit was explicitly skipped instead of being counted as proven native-caret behavior. Source: `c70bacbd4a:docs/plans/2026-06-07-plite-eight-hour-automation.md:461,572-583`. The current browser test retains that scoped reason (`apps/plite/tests/plite-browser/donor/examples/shadow-dom.test.ts:178-179`). Limit: this historical probe does not establish behavior for every WebKit version or Safari.

- **A nearby table regression does not close a stronger upstream repro.** The May 23 table lane kept generic boundary proof separate from a custom-table outside-typing report, unsupported `colgroup`/`col` DOM, and a real multi-cell selection model. Its claim bar required a matching repro, native enough browser actions, model and DOM selection assertions, and a follow-up edit that proves the editor remains usable (`docs/plans/2026-05-23-plite-table-selection-arrow-navigation-ralplan.md:177-188`). This prevents a green navigation test from becoming a broader selection or custom-DOM support claim. Limit: this is a proof lesson; historical issue classifications are not a fresh audit of current fixes.

- **A history oracle must inspect anchors as well as document equality.** The September 2026 Comments repair began with green document-history tests while nearest anchors drifted after deletion and undo. Its stronger matrix checked Path, Point and directional Range geometry, grouped and skipped edits, release and creation timing, named roots and repeated history. Current `packages/plitejs/test/history/anchor-history-contract.ts` owns anchor-history contracts, and `apps/www/tests/browser/comment.spec.ts` retains full-deletion and overlapping-comment history cases. Source: `docs/plans/2026-09-03-plite-comment-anchor-edit-and-history.md:366-411`. Model contracts do not establish popup placement or native input behavior; those require the browser owner.

- **One-source replay convergence does not prove concurrent collaboration.** The May 2026 ProseMirror-harvest pass added a three-peer matrix for text, marks, range deletion and block movement, while explicitly excluding simultaneous typing, rebasing and browser Yjs claims (c70bacbd4a:docs/plans/2026-05-10-plite-all-editor-harvest-test-processing-ralplan.md:319-355). The current test, `packages/plitejs/test/collab-history-runtime-contract.ts:290`, still edits one source and imports that commit into two peers, checking equal children, empty remote undo stacks and history-skip tags. Use that row to prove deterministic remote replay and history isolation; use independent concurrent edits and real transport rows for convergence under conflict.

- **A range-offset assertion does not prove visual direction or wrapping.** The May 2026 harvest added rendered-browser checks because the existing selection rows proved only offset import/export and FEFF normalization (c70bacbd4a:docs/plans/2026-05-10-plite-all-editor-harvest-test-processing-ralplan.md:395-428). `packages/test/test/browser/selection.browser.test.ts:165` checks that the first logical RTL character renders to the right of the last, and `:207` checks that one selection yields multiple wrapped-line rectangles. Keep geometry assertions beside model offsets when the claim concerns visual selection. These rows do not establish RTL Enter behavior, mobile scrolling or atom navigation.

- **Cached proof is not another stability execution.** The long-IME investigation initially counted one browser execution and four cached results as five stability runs. That loop was rejected, and five forced executions replaced it. Evidence: `docs/plans/2026-08-22-plite-long-ime-history-atomicity-regression.md:359-372`. Repeating a command proves stability only when each repetition actually exercises the case; record execution and retry counts separately from successful cache reuse. This lesson concerns proof execution, not a new product behavior.

- **Bind proof to the producer's artifact and the bytes being released.** The August 2026 release-proof review found successive gaps: validating caller-written lane results and SHAs still let callers manufacture evidence; checking GitHub only in the workflow left direct publication paths unguarded; checking a producer run still allowed an unrelated local manifest; and checking HEAD did not identify dirty publish bytes. The final verifier acquires the named artifact through GitHub, checks its archive digest, binds the manifest to the producer run and attempt, and rejects tracked or untracked checkout changes (`tooling/scripts/check-plite-release-proof.mjs`, producer validation, artifact download and CLI paths). Raw receipt validation also requires an exact 40-character expected commit (`packages/test/src/proof/raw-mobile-proof.ts:117-123`, `:210-212`). Source: `docs/plans/2026-08-22-bind-plite-release-proof-to-source.md:291-331`. Limit: the plan records mocked boundary/contract proof, not a real canonical producer artifact; package-only publication has a separate proof scope.

## Fixture harness boundaries

- **A fixture helper import must not start another test runner.** The April Bun migration could not safely import legacy fixtures because their jsx import also bootstrapped the entire Mocha suite. Separate reusable fixture exports from suite registration before moving a family between runners. Source: `docs/plans/2026-04-17-plite-plite-editor-above-bun-migration.md:21-25`; its slate paths refer to the legacy-facing fork during migration. Current `packages/plitejs/test/index.js` is a pure re-export of the shared JSX helper. The temporary dual-runner arrangement is historical.

## Proof process completion

- **A clean soak summary does not prove the proof process completed.** The June Hocuspocus soak wrote a clean summary but kept running until interrupted. Closure repaired cleanup and verified that the process returned its resolved exit code. Source: `docs/plans/2026-06-17-plite-plite-yjs-beta-readiness-closure.md:301`, with the interrupted and completed runs at lines 322-323. ## Test gate reachability

- **A passing package command does not prove the default gate invokes it.** The June Yjs beta review found that the package contracts passed when run directly but were absent from the default Bun and prerelease gate. Closure added the package to that aggregate gate and checked the wiring. Source: `docs/plans/2026-06-17-plite-plite-yjs-beta-readiness-closure.md:303`. ## Regression proof

- **Identity mapping needs serialized deletion and every-character formatting oracles.** Removing the draft's quadratic text-similarity guesser initially preserved values but let serialized deletion steal a surviving sibling's key. A later split/merge repair restored text while reversing the selection. Current `packages/plitejs/test/document-change.test.ts:2142` checks sibling identities through serialized insertion/deletion, and `:2349` maps every retained character through serialized text-run merges/splits; `core/change/root-change.ts` owns the canonical structural mapping. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:256-266`, `:408` and `:411`. Limit: in-process metadata, value equality and a green locality counter cannot replace these mapping oracles.

- **Selective invalidation needs an unchanged read and a later affected read.** The first August Anchor optimization skipped unrelated edits but then mapped from stale absolute positions; another attempt rebuilt an unchanged range with the wrong shape. A timing pass and non-null resolve caught neither defect. The repaired proof required exact unchanged reads and unrelated-then-affected transitions, with mapping derived from the canonical before snapshot. Current Anchor state and mapping remain in `packages/plitejs/src/core/anchor-state.ts` and `core/anchor.ts`, and the unchanged-snapshot round trip remains in `packages/plitejs/test/anchor-mapping-contract.ts:73`. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:415-425`. Limit: a counter proving that work was skipped does not prove the next relevant update remains observable.

## Test runners

- **Exercise relative report paths in runner contracts.** The August pagination browser cases passed, but the wrapper could not find their report because Playwright resolved the relative path from the configuration directory and the wrapper resolved it from the repository root. The fake CLI had tested only an absolute override. Resolving the report path once to an absolute path and adding a relative-path fixture caught the disagreement. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:394`, receipt `pagination-report-path-red.json`. Limit: an absolute-path fixture does not prove the default path.

- **A benchmark runner must fail when its measured owner or fresh report is missing.** The August integrated runner could silently fall back from failed Plite imports to Slate, and the pagination wrapper could succeed after failed tests or read a stale report. Repairs used explicit public package bindings, required fresh metric attachments and propagated the test exit status; executable fake-CLI and package-resolution cases exposed the failures first. Source: `docs/plans/2026-08-31-audit-and-repair-plite-fan-out.md:398-400`, receipt `integrated-comparison-runner-red.json`. Limit: a successful process exit is not evidence that the named implementation ran.

## Focus regressions

- **Reproduce focus history before testing a search input.** The April 2026 draft Plite search example lost input focus only after the editor had previously held focus; typing into the input from a cold page passed. The plan traced the failure to rebuilding its projection store on each query change (c70bacbd4a:docs/plans/2026-04-27-plite-search-highlighting-input-focus.md:22-27). The current browser regression preserves the important sequence: click the editor, click the search input, type, then assert input focus, query value and visible highlights (apps/plite/tests/plite-browser/donor/examples/search-highlighting.test.ts:36-59). The projection-store API is gone; the reusable lesson is to include the preceding focus transition in the regression.

## False passes

- **A browser gate must skip explicitly or execute its assertions.** A richtext right-margin test returned early outside Chromium and therefore reported success without testing Firefox or WebKit. Widening the row produced actual passing desktop proof in all three engines. Use an explicit, reasoned `test.skip` for an unsupported primitive; an early return cannot establish browser coverage. Source: `c70bacbd4a:docs/plans/2026-06-05-plite-two-hour-backlog-continuation.md:369-372`. Limit: this records the draft checkout's repaired rows, not a claim that today's entire browser suite has been audited.

## Browser environment diagnosis

- **Isolate a browser launch failure before changing editor code.** The July 2026 closure found that pinned and newer WebKit runtimes both hung before protocol startup, including on an independent empty-page smoke. System logs identified `syspolicyd` file-descriptor exhaustion. A clean, symlink-preserving HFS scratch runtime launched the pinned browser and allowed the required matrix to run. Source: `c70bacbd4a:docs/plans/2026-07-18-plite-canonical-change-architecture.md:167-170`, `:321-327`, `:396-397`. Limit: this was one historical macOS environment failure; it does not prescribe a general WebKit workaround or describe the host's current health.

## Generated change laws

- **Generate structural interactions, not only text edits.** The July canonical-change work found root-delete inversion, identical-move rebasing and a property edit at a moved-node boundary only after adding reproducible structural and multi-root generators. Give inversion, composition and pair-transform checks an independent document model and include root lifecycle, moves and property edits. Source: `c70bacbd4a:docs/plans/2026-07-18-plite-canonical-change-architecture.md:165`, `:358`. Current `packages/plitejs/test/document-change-laws.test.ts` retains a separate model and generated nested-edit and root-lifecycle families. Limit: pair-transform laws do not establish an arbitrary multi-peer OT protocol.

## Migration proof

- **Classify deleted proof against the surviving public claim.** A rewrite can pass a narrow replacement harness while silently losing a broader helper or example contract. Freeze the deleted families, name the current owner of each kept behavior, and distinguish recovered behavior from an explicit product cut or deferred surface. A benchmark or one browser invariant cannot stand in for example parity. Source: `c70bacbd4a:docs/plans/2026-04-18-plite-lossless-remaining-work-replan.md:94-149`. The later helper recovery found actual missing semantics after rename/merge claims; current owners include `packages/plitejs/src/core/get-fragment.ts`, `packages/plitejs/src/editor/unhang-range.ts` and `packages/plitejs/test/upstream-slate-helper-loss-contract.ts`. Limit: this is a method for bounding migration claims, not a claim that the entire legacy surface survives.

- **Check claim references in both directions.** The first issue-ledger consolidation checked overlay claims against the coverage matrix but still allowed coverage `Fixes` entries with no matching `fixes-claimed` overlay row. A follow-up added the reverse requirement and repaired the omitted classifications. Matching totals alone cannot establish that two claim surfaces contain the same claims. Source: `c70bacbd4a:docs/plans/2026-05-09-plite-issues-ledger-consolidation-ralplan.md:475-499`. Limit: this preserves the checker-design lesson; its historical issue counts and fix labels are not assertions about current upstream state.

- **A renamed helper needs semantic proof, not a name match.** The June recovery scan found only 13 of 168 old test titles preserved by name, but a missing title alone did not prove missing behavior. Mapping old APIs and their dependencies to current contracts exposed actual losses: fragment unwrapping, safe finder reads, traversal starts, previous-sibling lookup, level-based last lookup and character or opt-out unhang behavior. Source: `c70bacbd4a:docs/plans/2026-06-25-plite-slate-helper-loss-recovery.md:308-311`. Current implementations remain in `packages/plitejs/src/core/get-fragment.ts` and `packages/plitejs/src/editor/{next,previous,last,unhang-range}.ts`, with the recovery corpus in `packages/plitejs/test/upstream-slate-helper-loss-contract.ts`. Limit: the title counts describe the June scan; they do not measure today's missing coverage.
