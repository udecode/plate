# Testing and browser proof, part 3

## Release claims

- **Choose the release claim before harvesting parity tests.** The April 2026 Slate v2 draft separated confidence in one proved default stack from a claim to replace all legacy Slate behavior. It chose the narrower claim, required reasons for excluded legacy cases, and kept full replacement at No-Go. This prevents test-file counts or success on a small stack from becoming a blanket compatibility claim. Source: `c70bacbd4a:docs/plans/2026-04-07-plite-remaining-release-hardening-plan.md:30-102`, with the final decision at `:466-547`. Limit: the draft's `Plite + EditableBlocks + withHistory(createEditor())` stack is historical; current release-proof tooling and current public APIs own today's claim.

- **Prove the default stack together.** Green core, history and DOM packages do not establish that their public integration works. The April 2026 draft therefore required one browser stack to exercise typing, selection recovery, clipboard, undo/redo, reset/load and an outer transaction as one history step. Current richtext browser proof still exercises integrated behavior; for example, `apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:5361-5414` combines DOM selection, a mark command, a native click, follow-up typing, runtime-error capture and selection assertions. Source: `c70bacbd4a:docs/plans/2026-04-07-plite-remaining-release-hardening-plan.md:265-351`. Limit: one integrated route establishes only the behaviors and transports it exercises.

## Harness traps

- **A text-offset click must distinguish model splits from DOM splits.** The mark-click tracer first exposed a real stale-node exception, then exposed a helper that clicked the wrong segment after marking changed model paths. A later highlighted-text row had the opposite shape: decorations split DOM leaves while preserving one model path. Resolve the current model point, then count offsets across its DOM segments when a fallback is needed. Current `packages/test/src/playwright/dom-text-actions.ts:108-183` prefers the browser handle's resolved DOM point and otherwise accumulates string-segment lengths. Source: `c70bacbd4a:docs/plans/2026-04-23-plite-remaining-perfect-architecture-batches-plan.md:1455-1493`, `:1796-1807`. Limit: model path indices and DOM text-node indices are not interchangeable.

- **Capture runtime errors around every generated scenario step.** The April 2026 bridge work found that browser rows could pass model assertions while a hidden stale-node exception occurred between steps. Moving error capture into the shared scenario runner made that failure visible across generated tests. Current `packages/test/src/playwright/harness-scenario.ts:121-124` enables `recordBrowserRuntimeErrors` unless explicitly disabled and asserts the recorder after steps at `:806`; the richtext mark-click row also asserts the DOM caret, model selection and follow-up text. Source: `c70bacbd4a:docs/plans/2026-04-23-plite-remaining-perfect-architecture-batches-plan.md:1583-1673`. Limit: the recorder's default filters are narrower than strict error capture, as the existing 'shared runtime-error recorder is lenient unless strict' lesson explains.

- **A browser command assertion reads the event trace before relying on the latest commit.** The June 2026 richtext gate failed because browser selection synchronization could publish after a keydown command and replace `lastCommit.command`. The kept browser assertion finds the `move-selection` entry in the kernel trace (`apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:5211-5245`); a focused caret-engine test checks the immediate command commit separately (`packages/plitejs/test/react/caret-engine-contract.test.ts`, 'caret movement tags the semantic command commit'). Source: `c70bacbd4a:docs/plans/2026-06-25-auto-six-hour-plate-plite-quality.md:156`, `:342`. Limit: today's immediate commit contract uses the `semantic-command` tag rather than the retired `move_selection` metadata field; a trace alone does not prove the resulting selection.

- **Finish barrel generation before starting tests that import those barrels.** In the June 2026 deprecated-prop cleanup, Core tests ran while `brl` rewrote component barrels and failed with transient ENOENT on `src/static/components/index.ts`; the serial run passed after generation completed. Source: `c70bacbd4a:docs/plans/2026-06-25-auto-six-hour-plate-plite-quality.md:427`. Limit: this is a producer-consumer scheduling failure in the historical Core package, not evidence of a current Plate runtime defect.

- **Re-anchor the native caret in a repeated native-typing benchmark.** The June 7 draft Plite cross-editor harness reset model selection between iterations without restoring native selection at mounted text. A repeated run then failed its visible-text check. The repair anchored the browser caret, asserted the typed-count delta for that iteration, waited for pending native repair and recorded model, view and DOM selections separately. Source: `c70bacbd4a:docs/plans/2026-06-07-plite-eight-hour-automation.md:450`, with the failure described at lines 246-247. Current native selection setup remains explicit in `packages/plitejs/src/react/editable/browser-handle.ts:839-875`. Limit: model-only selection setup cannot certify native typing, and the old helper names are not current API guidance.

- **Native-caret helpers must use the editable's selection root and realm.** A promoted draft Plite helper used ownerDocument.getSelection and missed nested shadow-root selection. The June 7 audit repaired it to resolve Document or ShadowRoot selection and dispatch a realm-correct event, then added a nested-shadow browser row. Source: `c70bacbd4a:docs/plans/2026-06-07-plite-eight-hour-automation.md:459`. Current `packages/plitejs/src/react/editable/browser-handle.ts:839-875` resolves the mounted element's root and its document's ShadowRoot constructor. Limit: a document-level helper passing in ordinary DOM does not prove shadow-root behavior.

- **Compare native and model caret coordinates after resolving the DOM endpoint.** The June 7 draft Plite virtualized typing row assumed one raw browser offset across engines. The repaired oracle kept exact text assertions but required collapsed model selection and resolved native selection to agree, within narrowly allowed browser outcomes. Source: `c70bacbd4a:docs/plans/2026-06-07-plite-eight-hour-automation.md:466,472`. Current DOM-to-model projection is owned by nullable resolveRange in `packages/plitejs/src/dom/plugin/dom-editor.ts`, and nested keydown reads use that projection (`react/editable/keyboard-input-strategy.ts:233-257`). Limit: equal paths alone do not establish equal caret positions; compare offsets too.

- **Visible virtualized text is not proof that pointer hit testing reaches it.** In the June 7 draft Plite pagination run, row wrappers overlapped spread pages and intercepted clicks even though text looked correctly rendered. A DOM hit-test probe found the wrapper owner; the repair bounded row hitboxes horizontally and checked actual text-leaf hits, native/model caret placement, clicks, double-clicks and margin drags. Source: `c70bacbd4a:docs/plans/2026-06-07-plite-eight-hour-automation.md:469-470`. Limit: the historical pagination implementation has since changed; retain the hit-test proof requirement rather than copying its old layout mechanism.

- **After undo, type again to prove the restored caret is usable.** The May scroll-into-view regression passed a text-visible assertion while delayed undo left the selection at the wrong offset. The stronger row asserts model selection after undo, scrolls away again, types a third marker and checks that the marker lands in the edited block rather than the first block. That sequence survives in `apps/plite/tests/plite-browser/donor/examples/huge-document.test.ts:2216`, including caret visibility and the third insertion target. Source: `docs/plans/2026-05-13-plite-history-selection-precondition-ralplan.md:31-76`. Limit: this desktop browser test body was inspected, not rerun; it does not reinstate the plan's superseded mixed-commit selection-precondition rule.

- **A bulk-mapping benchmark must construct one bulk change.** The July anchor calibration initially measured hundreds of complete editor commits when the question concerned mapping many anchors through one change containing many edits. Those workloads include different costs. Construct the intended canonical change explicitly and report document size, anchor count and edit count separately. Evidence: `c70bacbd4a:docs/plans/2026-07-18-execute-wordgard-plite-architecture-ledger.md:318`. This is a workload-design lesson; the later timing in the plan lacks a measured source revision and is not promoted as a reproducible performance result.

- **A successful aggregate must prove its leaf work ran.** Root Turbo aggregates once returned success under `--only` without executing their source checks. - **Isolate a hanging handler test from its rendered harness.** The June check:core repair isolated a hanging shortcut case and replaced its unnecessary rendered harness with a direct plugin-handler test (c70bacbd4a:docs/plans/2026-06-25-core-plite-check.md:282-287). - **A selection snapshot refuses a partly foreign range.** The WPT processing run hardened `takeEditorSelectionSnapshot` to return null when either endpoint is outside the editor and added Shadow DOM snapshot coverage (`c70bacbd4a:docs/plans/2026-05-11-plite-wpt-harvest-test-processing-ralplan.md:140-148`). A test helper that fabricates a partial editor range can hide an ownership failure in the runtime it measures. This helper check does not itself prove native Shadow DOM focus behavior.

- **Reject a test-speed win that requires retries.** The June browser-runner experiment rejected higher worker counts after an initially clean faster run was followed by teardown retries; it also reverted running another heavy suite concurrently when that introduced a retry. - **Pair an absent-control assertion with a state where the control must appear.** The table smoke counted an obsolete cell-handle attribute and mistook intentional multi-row suppression for missing UI. - **Target live editor DOM before trusting a visual negative control.** Phase 2's first-table selector hit an inert DnD preview instead of the live keyed table. The absent and duplicate-layer controls therefore observed the wrong element. Selecting live keyed cells exposed a real duplicate highlight; subsequent proof also had to distinguish editor-owned DOM from non-editable chrome before its injected control survived. Source: `docs/plans/2026-09-07-editor-performance-phase-2.md:874-887`, `element-path-paint-control-fixed.json` and `table-selection-chrome-warm-summary.json`. - **Wait for the complete settled predicate.** A placeholder test waited for one attribute to disappear and then immediately checked a separately updated class. The strict suite observed the intermediate state, while repeated diagnostic passes did not establish its cause. The verifier repair waited for both conditions together, preserving positive and negative assertions and the original timeout. Source: `docs/plans/2026-09-07-editor-performance-phase-2.md:1244-1268`. Current `packages/platejs/src/react/utils/BlockPlaceholderPlugin.spec.tsx` keeps placeholder and class assertions in the same `waitFor`. - **Count independent documents by identity and contents, not mounted roots.** Adding DnD support made the multiple-editor demo mount, but every root then displayed the image document through one runtime editor. The useful oracle binds each root to its complete configured fixture, edits and undoes each document independently, and checks shared controls against the focused document. - **Prove that a copied-source compiler control actually transforms copied source.** The first consumer-on fixture lived under node_modules, where React Compiler excluded it, so it was an invalid on-control. Source: `docs/plans/2026-09-08-editor-performance-phase-4.md:412-420`. Limit: compiler events and zero render counts do not establish that a hot function executed or became faster.
