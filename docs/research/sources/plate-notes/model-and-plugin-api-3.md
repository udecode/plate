# Model, plugin and history API, part 3

## Yjs storage boundaries

- **Guard public properties against internal storage keys at every writer.** June 12 regressions showed that imported node properties and split-created properties could forge hidden or virtual Yjs state. Current `assertPublicYjsAttributeCanBeSet` rejects structural properties and the reserved `yjs:` namespace, and current creation and element-attribute replacement paths call it (`packages/plitejs/src/yjs/core/document.ts:2290`; `replacement.ts`). The attribute contract tests forged keys on both elements and text (`packages/plitejs/test/yjs/attributes-contract.spec.ts:174`). Source: `docs/plans/2026-06-12-yjs-optimization-strict-8h.md:459`. The plan's `slate:type` and `slate:yjs-*` spellings are historical draft storage names; current keys are defined in `packages/plitejs/src/yjs/core/keys.ts`. The contract was read, not run.

## Plugins and types

- **Count factory calls as well as plugin registrations.** A map with one plugin key can still hide repeated API, selector or update factory execution when an implicit dependency also appears as an explicitly extended plugin. Prove that shared factories execute once while distinct extensions survive. The July List review identified this failure mode (`docs/plans/2026-07-12-list-v2-api.md:1062-1068`). Current proof constructs both dependency forms and asserts one call for each shared factory and the distinct extension (`packages/platejs/src/lib/editor/withPlite.schema-plugins.spec.ts:582-623`); current resolution expands each graph node once (`packages/platejs/src/internal/plugin/resolvePlugins.ts:2456-2476`). Limit: these sources were inspected, not rerun; the historical extension-array implementation is gone.

- **Store the domain data a command needs before inventing an editor interface.** The July 2026 AI cleanup found that `AIChatSourceEditor` hid compiler recursion while every caller supplied the preview editor already owned by the plugin. The commands needed generated nodes, so replacing the stored editor object with `previewValue: Value` removed both the structural editor alias and the redundant command argument. Current `packages/platejs/src/ai/react/AIChatPlugin.ts:140` retains domain preview state, and its option-only commands at :1528 and :1571 consume that state. Source: `docs/plans/2026-07-31-fix-ai-chat-source-api-and-doctrine.md:323-327`. The preview lifecycle has since changed; this preserves the ownership lesson, not the removed preview-editor effect.

- **Migration scaffolding can expose a change without inventing its meaning.** The generated-contract work separated structural schema comparison and typed old/new snapshots from the application-specific transformation and deployment decision. A required property or renamed field does not tell tooling what existing data should become. Source: `docs/plans/2026-08-03-generated-editor-schema-contracts.md:181`. Current CLI migration coverage in `packages/cli/test/generate.test.ts:1321` checks versioned from/to schemas, declarations and a typed migration scaffold. Explicit migration execution is a separate supported operation; this lesson forbids inferring semantic data transformations from structural differences alone.

- **Materialize a closed type contract instead of moving recursive inference into a generated alias.** The full editor exposed two limits: projecting the entire raw mutation graph recreated TS2589, and third-party persisted types expanded into unsafe or irrelevant implementation types. Keep reusable access descriptor-local, emit concrete application declarations, and represent opaque leaves honestly rather than leaking `any`. Source: `docs/plans/2026-08-03-generated-editor-schema-contracts.md:429-431`. Current `packages/cli/src/generate.ts:929` emits named element, value and mutation declarations; `packages/cli/src/typescript.ts:147-160` bounds recursive printing, maps `any` to `unknown` and rejects `never`. This preserves the emission lesson without claiming the old compiler measurements apply to the current emitter.

- **A caller-selected JSON generic cannot replace runtime validation.** The July schema audit found that property.json could claim a narrow type without proving that decoded data had that shape (docs/plans/2026-07-31-schema-api-hard-cut.md:229). Current packages/plitejs/src/core/schema-definition.ts returns EditorJsonValue without validation and infers a narrower value only from a predicate paired with validationVersion. The plan's PropertyJsonValue name has since been replaced by EditorJsonValue. Keep compile-time narrowing tied to the validator the runtime actually executes.

- **A private inference carrier must survive downstream declaration emission.** A hidden unique-symbol schema carrier failed with TS4023; replacing it with a string carrier passed Core but still failed downstream declaration builds. Inferring from the authored schema removed the carrier, and const-generic overloads preserved exact textBlock option keys (docs/plans/2026-07-31-schema-api-hard-cut.md:311-313). Current packages/platejs/src/lib/plugin/pluginSchemaModel.internal.ts derives declaration types from schema, and packages/plitejs/src/core/schema-definition.ts retains the const-generic textBlock overload. A local typecheck alone does not prove that downstream packages can name emitted types.

- **Replay API factories for the mounted editor with the preceding stage's API.** The navigation adoption reproduced native and Plate APIs capturing the model editor instead of the calling mounted view. Rebinding also had to preserve staged composition: a factory that receives the final merged API can recurse into itself. Current `packages/platejs/src/internal/plugin/resolvePlugins.ts:1238-1278` evaluates contributions for the supplied editor and supplies `snapshotApiValue(resolvedApi)` to each definition factory. Source: `c70bacbd4a:docs/plans/2026-09-09-navigation-feedback-api.md:74`, which names the binding RED and GREEN receipts. Limit: the source was inspected; those historical tests were not rerun.

- **Optional arrival feedback must not become a navigation dependency.** The footnote adoption initially made `navigationFeedback: false` prevent complete footnote navigation. Current `packages/platejs/src/react/features/footnote/FootnotePlugin.tsx:14-25` performs focus and scroll, then flashes only when the navigation portal is installed. Its colocated spec exercises feedback enabled and disabled. Source: `c70bacbd4a:docs/plans/2026-09-09-navigation-feedback-api.md:90`, naming `footnote-disabled-red.log` and `footnote-disabled-green.log`. Limit: this preserves the navigation command's required work; it does not make every footnote dependency optional.

- **Keep schema-derived node vocabulary finite instead of evaluating recursive content grammar in every editor type.** The schema-value experiment passed focused package checks but hit TS2589 when a large EditorKit evaluated ordinary capabilities. Increasing a recursion budget only moves the failure, and embedding the installed union into every child's type recreates recursion. Current `packages/plitejs/src/interfaces/schema.ts:1627-1710` keeps exact discriminators and properties while descendants use `BaseElement['children']`; `SchemaValue` carries a separate node-provider witness and leaves root and child grammar to runtime validation. Source: `docs/plans/2026-08-02-schema-derived-editor-value-types.md:361-402`. Limit: this retains the failure mechanism and surviving representation, not the plan's retired editor type names or an unmeasured current compiler-speed claim.

- **Runtime-equivalent builder methods can carry different inferred contracts.** In the July builder review, ordinary `.extend()` widened only some accumulator dimensions while specialized stages widened others. Fewer method names therefore did not prove a safe consolidation. Preserve contextual inference, accumulated capabilities, configuration, portal projection, emitted declarations and rejected calls before deleting an authoring path. Source: `c70bacbd4a:docs/plans/2026-07-24-best-api-generic-inference-gate.md:227-242`. Current `packages/platejs/type-tests/base-plugin-contracts.ts` remains the capability-channel proof owner, and current `packages/platejs/src/internal/plugin/resolvePlugins.ts` preserves ordered prior-stage API composition. Limit: the historical builder family is retired; this is a proof lesson, not a requirement to restore its methods.

- **Keep an independent mutation algorithm while removing a one-owner forwarding layer.** The July 2026 Table repair retained the typed mutation planner but inlined the one-use prepared-paste applier. The useful boundary was planning and applying a real operation sequence, not a helper file around one call. Source: `docs/plans/2026-07-28-repair-media-table-list-utils-plugin-ownership.md:489-490`. Current `packages/platejs/src/features/table/lib/internal/mutation.ts:1437` still applies a typed TableMutationPlan through transaction operations, and BaseTablePlugin calls that owner. The historical 98184323b5:packages/table path now lives under packages/platejs; this is not a blanket claim that every current Table helper should be inlined.

- **Split a plugin at the actual renderer boundary.** The July 2026 List repair moved JSX out of BaseListPlugin and into its live React adapter. Current `packages/platejs/src/features/list/lib/BaseListPlugin.ts` remains renderer-neutral, while `packages/platejs/src/react/features/list/ListPlugin.tsx` imports React and owns mounted-view work such as ListNumberWriter. Source: `docs/plans/2026-07-28-repair-media-table-list-utils-plugin-ownership.md:493`. Preserve semantic behavior in the Base owner and mounted behavior in the adapter; the historical two-file repair does not describe every helper added since.

- **A callback schema needs the same dependency portal as a static schema.** Playground startup failed because a required dependency declared its schema through a callback and the authoring portal omitted that schema. Repair the shared portal rather than each consumer. Current `packages/platejs/src/lib/plugin/createPluginContext.internal.ts:660-710` evaluates declarations and exposes schema access; `packages/platejs/src/internal/plugin/resolvePlugins.spec.tsx:60` reads the callback-declared dependency's default type during another plugin's authoring callback. Source: `c70bacbd4a:docs/plans/2026-09-12-playground-chrome-startup-regression.md:563`. The current lookup is `editor.plugin`, replacing the plan's `editor.extension` spelling.

- **Freeze descriptor data and preserve declared host resources.** July's immutable-publication cut exposed consumers that mutated published values. Repair those consumers at their mutable boundary. Browser proof then isolated EditorKit failures to React resources for `img` and `placeholder`: walking their accessors as descriptor data violated their ownership. Current `packages/platejs/src/internal/plugin/resolvePlugins.ts:127-184,274-344` preserves resources at declared component, override and slot locations while rejecting ordinary descriptor accessors and freezing copied snapshots. Source: `c70bacbd4a:docs/plans/2026-07-22-execute-agent-native-api-shapes.md:413-421`. Opaque locations are explicit; a React marker alone does not exempt arbitrary data.

- **Separate a canonical rule's semantics from its activation.** Feature owners export concrete input-rule factories, while copied kits choose the rule instances to register. This replaced string-key activation maps that made public names carry configuration and discovery responsibilities. Source: `c70bacbd4a:docs/plans/2026-04-14-input-rules-recipe-registration-plan.md:12-35`. Current `packages/platejs/src/features/code-block/lib/CodeBlockRules.ts` owns code-fence semantics, and `apps/www/src/registry/components/editor/basic-marks.tsx:30-79` explicitly registers mark rules. This does not imply that shipped kits are neutral: a kit may deliberately register shortcuts.

- **Delete an accidental public hybrid instead of hiding its render mutation.** The August 2026 immutability audit found that `useEditor()` mutated the selected editor only to graft on a store that no production caller read. Removing the graft and `PlateEditorWithStore` corrected both ownership and public typing; a ref wrapper would have preserved the defect. Source: `docs/plans/2026-08-23-close-react-compiler-lint-and-react-19-migration.md:198`, :321-323. Current `packages/platejs/src/react/stores/plate/useEditor.ts:29-32` returns the context-selected editor directly. The historical store-hook names are not a current API recommendation.

- **Keep plugin discovery outside a deterministic planner.** The Table refactor found selection knowledge repeated across queries, mutations, extensions and drag/drop. Runtime context belongs with those plugin capabilities; a detached paste planner earns a separate owner because callers can supply domain factories and policy without handing it an editor or plugin portal. Current `packages/platejs/src/features/table/lib/internal/paste.ts:84-95` accepts cell/row factories and expansion policy, while `BaseTablePlugin.ts:1205-1212` and `:1419-1426` bind selection reads to their snapshot or active transaction. Source: `docs/plans/2026-07-24-table-staged-capability-refactor.md:591-602`. Limit: the July extendApi/extendTx/getSelection syntax is retired; preserve the ownership distinction.

- **Mapped generic factories must reapply the exact input-to-output relation.** A direct Yjs call inferred optional capabilities, but forwarding it through another generic function widened awareness and cursor metadata. Renaming that function to `.create()` would not fix the relation. The repair carries a private input/output type witness through every mapped author stage and reapplies it to each exact construction input. Source: `docs/plans/2026-09-14-parameterized-plugin-factories.md:251-408`. Current `packages/platejs/src/react/plugin/pluginFactory.internal.ts` uses `ApplyPluginFactory` and the shared `InternalPluginAuthorExtension` operation; `packages/platejs/src/yjs/react/YjsPlugin.tsx` derives its native relation from the Plite provider. The public factory stays concrete; this does not establish a need for a general public factory-definition grammar.

- **Type refinement needs the matching runtime precondition.** `YjsPlugin.require('awareness')` lets a mapped author stage use presence APIs, so erased JavaScript must also be refused when awareness is nullish. Current `packages/platejs/src/react/plugin/pluginFactory.internal.ts:260-270` checks required root keys before invoking the source constructor; its public type uses `NonNullable` for the same keys. Source: `docs/plans/2026-09-14-parameterized-plugin-factories.md:717-720`. This is a non-nullish root-key requirement, not a nested validation or default-injection language.

- **Keep mutation inference smaller than the application grammar.** The August property-mutation audit found that current-plugin-only inference excluded legitimate dependency-owned fields, while carrying the entire EditorKit schema caused TS2589. It also found that structurally identical property laws could lose their distinct provenance during union normalization. Source: `c70bacbd4a:docs/plans/2026-08-04-typed-plugin-property-mutations.md:475-502`. Current `packages/platejs/src/lib/editor/pluginRuntimeTypes.ts` retains a separate writable-property provider and patch-validation layer. Its public mutation spelling has changed to object patches; the historical literal-key overload and collision policy are not current API guidance.

- **Separate author schema handles from consumer identities at runtime.** The schema-access cleanup found that one shared proxy exposed compiler-normalized property maps to ordinary consumers; removing those fields from TypeScript alone would still leak them through reflection. Current `packages/platejs/src/lib/plugin/createPluginContext.internal.ts` creates separate author and consumer schema proxies. Consumers use primary `schema.type` or `schema.key`, typed node fields and semantic feature methods; authors retain additional property handles, while generic inspection belongs to the editor schema. Source: `docs/plans/2026-08-03-simplify-plugin-schema-property-access.md:172-322`. This boundary does not remove declaration grammar or Plite's compiled schema handles.

- **Schema-derived mark defaults must preserve authored overrides.** Repeated raw-key reads and trivial mark setters were symptoms of a missing semantic consumer surface. Plate now synthesizes primary-mark `value`, `isActive`, `set`, `clear` and `toggle` capabilities, then merges authored methods over the defaults (`packages/platejs/src/internal/plugin/resolvePlugins.ts`). Boolean activation tests for `true`; value-mark activation tests for presence or an explicitly supplied value. Source: `docs/plans/2026-08-03-simplify-plugin-schema-property-access.md:378-394`. Defaults belong only to primary marks, and custom side effects must remain authored.

- **Initialize dependent capabilities against the candidate being published.** Schema factories once resolved dependencies before final publication, and deferred command registration read the previous compiled model. The repair carried the same compiled candidate through schema resolution and extension initialization instead of fabricating an identity from a plugin name. Current candidate-aware identity resolution remains in `packages/platejs/src/lib/plugin/createPluginContext.internal.ts`. Source: `docs/plans/2026-08-03-simplify-plugin-schema-property-access.md:533-576`. A candidate-aware initialization path does not authorize ordinary consumers to inspect unpublished compiler state.

- **Callable plugin facades must preserve ordinary function coercion.** React development inspection converted a callable facade to a string, and the proxy treated that conversion as a plugin query for a nonexistent method. Read and update facades now forward `toString` and `valueOf` to their callable target while preserving legitimate feature methods (`packages/platejs/src/lib/plugin/createPluginContext.internal.ts`). Source: `docs/plans/2026-09-16-ai-continuation-render-recovery.md:249-256`. This repairs inspection and serialization safety without reserving every ordinary method name on installed feature groups.

- **External transaction grouping cannot promise editor-style rollback.** Yjs groups mutations in a transaction but does not reverse partial external writes when application code throws. Collaboration initialization must prepare fallible framework work before external mutation; after publication, a seed/import failure enters an error state rather than claiming restoration of the old CRDT. Source: `docs/plans/2026-09-14-collaboration-lifetimes.md:260-267`; current admission and recovery owner: `packages/plitejs/src/yjs/core/controller.ts`. Pre-publication editor configuration rollback and post-publication external failure are distinct guarantees.

- **Shared runtime identity does not require eager recomputation of another layer's types.** The shared-descriptor migration's eager and incrementally reconstructed capability carriers exceeded its type-instantiation budget even after runtime identity passed. A lazy package-owned capability provider retained Plate's staged definition as the evolving generic while Plite extracted the resulting capability. Large production cohorts separately exposed quadratic conflict scans and candidate-map copying; direct descriptor maps and an unpublished mutable draft removed that work without weakening rollback. Source: `docs/plans/2026-09-13-shared-plugin-identity-feasibility.md:455-496`; current owners are `packages/platejs/src/lib/plugin/definePlugin.ts`, `packages/plitejs/src/interfaces/editor.ts` and `packages/plitejs/src/core/plugin.ts`. The lesson preserves the compiler boundary; it does not move Plate's product grammar into Plite.

- **Separate runtime reachability from installation and type dependencies.** A Base constructor loaded React because its DOM descriptor shared a module with an eagerly constructed React descriptor. The repair gave Base one private DOM descriptor and made React consume that exact object; constructing another equivalent descriptor would break capability identity. Current owners are `packages/platejs/src/lib/plugins/dom/plateDOMPlugin.internal.ts` and `packages/platejs/src/react/editor/getPlateCorePlugins.internal.ts`. Source: `docs/plans/2026-08-23-plate-base-runtime-boundary.md:139-164`. A headless runtime boundary alone does not promise an installation or declaration graph without React.

- **Choose target identity representation for the consumer's contract.** The registry sweep standardized copied configuration on capability-name constants but retained exact descriptors in package definitions and type contracts, where replacing them with strings would weaken identity proof. Current `packages/platejs/src/lib/plugin/BasePlugin.ts` admits both references and strings, and `lib/utils/getInjectMatch.ts` resolves targets against compiled plugin ownership. Source: `c70bacbd4a:docs/plans/2026-08-04-target-plugins-identity-sweep.md:617-623`. This is a representation lesson; the historical Font-kit overrides and audit counts are no longer current.

- **Remove a generic that only creates a cast.** The former `useAIChatEditor` accepted a generic editor type that never reached its output, then cast through `unknown` to recover capabilities already available on its non-generic Markdown editor contract. Removing the generic and alias passed the focused type, declaration and runtime checks. Source: `docs/plans/2026-08-06-remove-useaichat-runtime-editor-cast.md:594-608`. That hook has since been removed; current `packages/platejs/src/ai/react/useAIChat.ts` uses a concrete `Editor` parameter for its private chat-session owner, so this preserves the type-design lesson rather than the old signature.

- **Centralize first-party names without closing the consumer namespace.** The override cleanup replaced duplicated first-party literals with `PLUGINS` constants while retaining arbitrary consumer descriptor names. Current List overrides use `[PLUGINS.indent]`, and SingleBlock/SingleLine use `[PLUGINS.trailingBlock]` in their direct `override` objects. Source: `c70bacbd4a:docs/plans/2026-08-11-normalize-first-party-override-plugin-names.md:605-608`; current owners are `packages/platejs/src/features/list/lib/BaseListPlugin.ts` and `packages/platejs/src/utils/plugins/SingleBlockPlugin.ts` and `SingleLinePlugin.ts`. The historical `override.plugins` nesting is superseded.

- **Restore resources against the final candidate before publication.** Comments could not reject malformed saved ranges from `afterPublish`, because that observer runs after publication; moving earlier validation or activation broke other initialization dependencies. Synchronous `beforePublish` work instead sees the final candidate while rollback remains possible. Current `packages/platejs/src/features/comments/BaseCommentsPlugin.ts` registers initialization there, and `packages/plitejs/src/core/plugin.ts` owns the callback lifecycle. Source: `docs/plans/2026-09-16-comments-history-api.md:109-127`. The proof covered both construction and dynamic installation, including cleanup and preservation of the previous document, APIs, selection, version and anchors.

- **Reflection can silently widen an exported return type.** The CI repair found `getCompiledSchemaPropertyId` emitting `any` after reading reflected metadata. Validate the reflected value and declare the public return type, then inspect rebuilt declarations and regenerate their API reference. Current `packages/plitejs/src/core/schema-compiler.ts:3219` returns `string` and accepts the reflected override only when it is a string. Source: `c70bacbd4a:docs/plans/2026-08-14-fix-all-ci-tests.md:350`. Runtime correctness alone did not catch this declaration leak.

- **A renderer-props parameter needs one ownership meaning.** Accepting either a node type or a plugin descriptor made the same generic change both node ownership and plugin-context semantics. Plugin components now use one required descriptor; arbitrary-node renderer infrastructure uses lower-level `Render*Props` with its actual context. Current live and static `EditorElementProps<TPlugin extends NodePropsDescriptor>` derive both node and configuration from that descriptor (`packages/platejs/src/react/components/plate-nodes.tsx:47-84`, `packages/platejs/src/static/components/plite-nodes.tsx:68-81`); leaf and text aliases follow the same split. Source: `c70bacbd4a:docs/plans/2026-08-13-descriptor-owned-renderer-props-hard-cut.md:222-226`. The plan's Plate*Props and Plite*Props names are historical.

- **Replacing a props alias must preserve required fields.** Moving static wrappers to a lower-level render contract initially made `path` optional. The repair explicitly restored `path: Path`, which current `RenderStaticNodeWrapperProps` still requires (`packages/platejs/src/lib/plugin/BasePlugin.ts:1095-1106`). Source: `c70bacbd4a:docs/plans/2026-08-13-descriptor-owned-renderer-props-hard-cut.md:230-231`. A structurally broader replacement can compile while weakening the consumer contract.

- **Separate inserted data from insertion controls.** A descriptor's insert operation keeps domain properties in its first argument and placement controls in its second, so custom construction can preserve the ordinary insertion surface without mixing node data with command policy. Current generated inserts use `(properties, insertOptions)` in `packages/platejs/src/internal/plugin/resolvePlugins.ts:1452`, with current block placement typed by `BlockInsertOptions`. Source: `docs/plans/2026-08-04-audit-plugin-read-update-generic-mutations.md:322-352`. The plan's older NodeInsertNodesOptions details and explicit-generic migration inventory are historical.

- **A scoped update keeps transaction policy on the facade.** The audit found tagged Equation updates escaping to raw generic node methods because the descriptor facade could not carry policy. Current `packages/platejs/src/lib/plugin/createPluginContext.internal.ts:497-595` makes `portal.update(policy)` callable and delegates each selected command through the existing editor update once. Source: `docs/plans/2026-08-04-audit-plugin-read-update-generic-mutations.md:353-372`. This preserves descriptor inference without adding a plugin overload to raw node mutations or copying transaction policy into every method's options.

- **Inferred capability does not prove optional installation.** The audit rejected deleting DOCX's Table-presence check merely because descriptor inference knew the Table type. Current `packages/platejs/src/lib/plugin/createPluginContext.internal.ts:196-214,690` still separates the non-throwing `installed` check from access that requires installation. The newer `WordPastePlugin` depends on HTML and asks the format registry for optional table identities (`packages/platejs/src/docx/paste/lib/WordPastePlugin.ts:331-350`). Source: `docs/plans/2026-08-04-audit-plugin-read-update-generic-mutations.md:379-382`. The old exact DOCX guard is historical; optional integration still must not force an otherwise unnecessary feature dependency.

- **An authored same-name update already replaces the generated operation.** Plate builds schema-backed defaults and then merges authored updates over them; current `packages/platejs/src/internal/plugin/resolvePlugins.ts:1566-1570` returns `{ ...defaultUpdate, ...authoredUpdate }`. A semantic insert can use the active transaction and schema construction directly. Source: `docs/plans/2026-08-04-audit-plugin-read-update-generic-mutations.md:396-404`. Do not add baseInsert, super.insert or a second override protocol without an actual composition need; the authored method owns its complete behavior.

- **Construction properties are not all reuse identity.** Comparing every compiled construction property can make injected alignment or line height prevent reuse, while ignoring another feature's insertion semantics can mistake a list paragraph for plain text. The private policy now checks target type and relevant explicit or insertion-owning construction properties (`packages/platejs/src/internal/plugin/blockInsertion.ts:110-154`). Authored structural insertion must also own its upsert instead of inheriting an unsafe generic constructor. Source: `c70bacbd4a:docs/plans/2026-09-18-slash-ui-actions-design.md:251-297`. This is a Plate semantic decision; Plite's structural placement primitive does not know plugin identity.

- **Exact inference needs a finite expansion boundary.** The August node-query hard cut tried three forms of final-application-schema projection on every direct structural mutation callback; each exhausted Node's normal 4 GB heap on the full EditorKit. The accepted implementation kept precise descriptor/schema-handle paths where affordable and honest broader callback types elsewhere instead of restoring unchecked output generics. Source: `c70bacbd4a:docs/plans/2026-08-15-execute-inferred-node-query-hard-cut.md:260-280`, historical full-EditorKit typecheck trials. Current `packages/plitejs/src/interfaces/node.ts:80-92` and `utils/node-match.ts` still separate structural `type` selection from function-only `match`. The historical precision boundary is evidence about that type graph, not a guarantee that every current mutation signature has the same shape.

- **Classify identity uses before renaming a plugin.** The July 2026 migration found that the same `KEYS` values served plugin lookup, command namespaces, serialized node types and decoration properties. Replacing every use would silently change document data or compare a runtime name with a stored discriminator. Audit constructors, parsers, action maps and marks by their consumer contract, then verify insertion and serialization separately from command typing. Source: `docs/plans/2026-07-20-camel-case-plugin-key-migration.md:142-190`. The old `KEYS`/`NODES` API is retired: current `packages/platejs/src/utils/plate-keys.ts` explicitly defines PLUGINS as capability names, while feature code resolves schema types, as in `packages/platejs/src/features/code-block/lib/BaseCodeBlockPlugin.ts`.

- **A cached read namespace must contain live methods rather than captured document values.** The August lifecycle repair removed rebuilding every read group on every read, but caching arbitrary factory output would have frozen state-derived data at construction time. Its hard cut required callable method trees, moved stable services to `api`, and rejected read reentry during construction. Current `packages/plitejs/src/core/public-state.ts:5269-5327,5490-5510` retains method-tree validation, registry/transform-generation invalidation and the construction guard. Source: `docs/plans/2026-08-18-cache-editor-read-views-and-cut-hot-path-capability-rebuilding.md:131-160`. Cached object identity does not make an ordinary editor read a transaction-draft read; each read still follows its current owner's committed or draft boundary.

- **Resolve and invoke a direct read inside the same read boundary.** The pre-repair direct extension path obtained a method inside `editor.read` and invoked it afterward, so direct syntax escaped the callback form's write guard and could retain an obsolete capability. Current `packages/plitejs/src/core/editor-lifecycle-api.ts:63-99` caches only a recursive path facade; each call resolves the installed group and invokes its method inside `read`. Source: `docs/plans/2026-08-18-cache-editor-read-views-and-cut-hot-path-capability-rebuilding.md:196-230`. This preserves current lookup and guard semantics without promising that a removed method remains callable.

- **Trace a hook through wrappers to its terminal consumer before calling it reusable.** The August controller migration found package hooks whose only real consumer was one copied registry family; intermediate package wrappers had made that dependency look reusable. Stores, providers, hotkeys and UI plugin state had to move with the controller to avoid leaving the same ownership inversion behind. Source: `docs/plans/2026-08-16-registry-owned-react-controllers.md:198-223,337-348`. Current copied `apps/www/src/registry/components/editor/link.tsx` owns its transient state and commands, and `floating-toolbar.tsx` owns FloatingToolbarPlugin. The historical 53-row manifest describes that migration's tree, not the current public API inventory.

- **A common text-block helper must preserve explicit structural grammar.** The full-schema audit found repeated text-plus-inline declarations, but rejected making that grammar implicit for every editable element because omitted container grammar would then become silently valid. Current `packages/plitejs/src/core/schema-definition.ts:1246-1283` provides `schema.element.textBlock()` with text-or-inline content, minimum one child and a text default; its accepted options exclude content, inline and void overrides. ## Links and headings

- **Classify list compatibility by semantic role rather than raw block type.** The #4985 repair initially separated every element type, which broke valid mixed paragraph/blockquote lists. Subsequent controls exposed overly broad breaks at nested, unnumbered and differently styled headings. Source: `docs/plans/4985-ordered-list-heading-paragraph-numbering.md:228-280`. Current `packages/platejs/src/features/list/lib/listIdentity.internal.ts` still compares heading role, list kind and optional marker style when joining items. Numbering itself now follows list identity; the old normalizer, same-indent breakQuery and polite-restart API are not current implementation advice.
