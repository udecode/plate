# Model, plugin and history API, part 3

## Yjs storage boundaries

- **Guard public properties against internal storage keys at every writer.** June 12 regressions showed that imported node properties and split-created properties could forge hidden or virtual Yjs state. Current `assertPublicYjsAttributeCanBeSet` rejects structural properties and the reserved `yjs:` namespace, and current creation and element-attribute replacement paths call it (`packages/plitejs/src/yjs/core/document.ts:2290`; `replacement.ts`). The attribute contract tests forged keys on both elements and text (`packages/plitejs/test/yjs/attributes-contract.spec.ts:174`). Source: `docs/plans/2026-06-12-yjs-optimization-strict-8h.md:459`. The plan's `slate:type` and `slate:yjs-*` spellings are historical draft storage names; current keys are defined in `packages/plitejs/src/yjs/core/keys.ts`. The contract was read, not run.

## Plugins and types

- **Count factory calls as well as plugin registrations.** A map with one plugin key can still hide repeated API, selector or update factory execution when an implicit dependency also appears as an explicitly extended plugin. Prove that shared factories execute once while distinct extensions survive. The July List review identified this failure mode (`docs/plans/2026-07-12-list-v2-api.md:1062-1068`). Current proof constructs both dependency forms and asserts one call for each shared factory and the distinct extension (`packages/platejs/src/lib/editor/withPlite.schema-plugins.spec.ts:582-623`); current resolution expands each graph node once (`packages/platejs/src/internal/plugin/resolvePlugins.ts:2456-2476`). Limit: these sources were inspected, not rerun; the historical extension-array implementation is gone.

- **Store the domain data a command needs before inventing an editor interface.** The July 2026 AI cleanup found that `AIChatSourceEditor` hid compiler recursion while every caller supplied the preview editor already owned by the plugin. The commands needed generated nodes, so replacing the stored editor object with `previewValue: Value` removed both the structural editor alias and the redundant command argument. Current `packages/platejs/src/ai/react/AIChatPlugin.ts:140` retains domain preview state, and its option-only commands at :1528 and :1571 consume that state. Source: `docs/plans/2026-07-31-fix-ai-chat-source-api-and-doctrine.md:323-327`. The preview lifecycle has since changed; this preserves the ownership lesson, not the removed preview-editor effect.

- **Migration scaffolding can expose a change without inventing its meaning.** The generated-contract work separated structural schema comparison and typed old/new snapshots from the application-specific transformation and deployment decision. A required property or renamed field does not tell tooling what existing data should become. Source: `docs/plans/2026-08-03-generated-editor-schema-contracts.md:181`. Current CLI migration coverage in `packages/cli/test/generate.test.ts:1321` checks versioned from/to schemas, declarations and a typed migration scaffold. Explicit migration execution is a separate supported operation; this lesson forbids inferring semantic data transformations from structural differences alone.

- **Materialize a closed type contract instead of moving recursive inference into a generated alias.** The full editor exposed two limits: projecting the entire raw mutation graph recreated TS2589, and third-party persisted types expanded into unsafe or irrelevant implementation types. Keep reusable access descriptor-local, emit concrete application declarations, and represent opaque leaves honestly rather than leaking `any`. Source: `docs/plans/2026-08-03-generated-editor-schema-contracts.md:429-431`. Current `packages/cli/src/generate.ts:929` emits named element, value and mutation declarations; `packages/cli/src/typescript.ts:147-160` bounds recursive printing, maps `any` to `unknown` and rejects `never`. This preserves the emission lesson without claiming the old compiler measurements apply to the current emitter.

- **A caller-selected JSON generic cannot replace runtime validation.** The July schema audit found that property.json could claim a narrow type without proving that decoded data had that shape (docs/plans/2026-07-31-schema-api-hard-cut.md:229). Current packages/plitejs/src/core/schema-definition.ts returns EditorJsonValue without validation and infers a narrower value only from a predicate paired with validationVersion. The plan's PropertyJsonValue name has since been replaced by EditorJsonValue. Keep compile-time narrowing tied to the validator the runtime actually executes.

- **A private inference carrier must survive downstream declaration emission.** A hidden unique-symbol schema carrier failed with TS4023; replacing it with a string carrier passed Core but still failed downstream declaration builds. Inferring from the authored schema removed the carrier, and const-generic overloads preserved exact textBlock option keys (docs/plans/2026-07-31-schema-api-hard-cut.md:311-313). Current packages/platejs/src/lib/plugin/pluginSchemaModel.internal.ts derives declaration types from schema, and packages/plitejs/src/core/schema-definition.ts retains the const-generic textBlock overload. A local typecheck alone does not prove that downstream packages can name emitted types.

- **Replay API factories for the mounted editor with the preceding stage's API.** The navigation adoption reproduced native and Plate APIs capturing the model editor instead of the calling mounted view. Rebinding also had to preserve staged composition: a factory that receives the final merged API can recurse into itself. Current `packages/platejs/src/internal/plugin/resolvePlugins.ts:1238-1278` evaluates contributions for the supplied editor and supplies `snapshotApiValue(resolvedApi)` to each definition factory. Source: `c70bacbd4a:docs/plans/2026-09-09-navigation-feedback-api.md:74`, which names the binding RED and GREEN receipts. Limit: the source was inspected; those historical tests were not rerun.

- **Optional arrival feedback must not become a navigation dependency.** The footnote adoption initially made `navigationFeedback: false` prevent complete footnote navigation. Current `packages/platejs/src/react/features/footnote/FootnotePlugin.tsx:14-25` performs focus and scroll, then flashes only when the navigation portal is installed. Its colocated spec exercises feedback enabled and disabled. Source: `c70bacbd4a:docs/plans/2026-09-09-navigation-feedback-api.md:90`, naming `footnote-disabled-red.log` and `footnote-disabled-green.log`. Limit: this preserves the navigation command's required work; it does not make every footnote dependency optional.

- **Keep schema-derived node vocabulary finite instead of evaluating recursive content grammar in every editor type.** The schema-value experiment passed focused package checks but hit TS2589 when a large EditorKit evaluated ordinary capabilities. Increasing a recursion budget only moves the failure, and embedding the installed union into every child's type recreates recursion. Current `packages/plitejs/src/interfaces/schema.ts:1627-1710` keeps exact discriminators and properties while descendants use `BaseElement['children']`; `SchemaValue` carries a separate node-provider witness and leaves root and child grammar to runtime validation. Source: `docs/plans/2026-08-02-schema-derived-editor-value-types.md:361-402`. Limit: this retains the failure mechanism and surviving representation, not the plan's retired editor type names or an unmeasured current compiler-speed claim.

- **Runtime-equivalent builder methods can carry different inferred contracts.** In the July builder review, ordinary `.extend()` widened only some accumulator dimensions while specialized stages widened others. Fewer method names therefore did not prove a safe consolidation. Preserve contextual inference, accumulated capabilities, configuration, portal projection, emitted declarations and rejected calls before deleting an authoring path. Source: `c70bacbd4a:docs/plans/2026-07-24-best-api-generic-inference-gate.md:227-242`. Current `packages/platejs/type-tests/base-plugin-contracts.ts` remains the capability-channel proof owner, and current `packages/platejs/src/internal/plugin/resolvePlugins.ts` preserves ordered prior-stage API composition. Limit: the historical builder family is retired; this is a proof lesson, not a requirement to restore its methods.

- **Keep an independent mutation algorithm while removing a one-owner forwarding layer.** The July 2026 Table repair retained the typed mutation planner but inlined the one-use prepared-paste applier. The useful boundary was planning and applying a real operation sequence, not a helper file around one call. Source: `docs/plans/2026-07-28-repair-media-table-list-utils-plugin-ownership.md:489-490`. Current `packages/platejs/src/features/table/lib/internal/mutation.ts:1437` still applies a typed TableMutationPlan through transaction operations, and BaseTablePlugin calls that owner. The historical 98184323b5:packages/table path now lives under packages/platejs; this is not a blanket claim that every current Table helper should be inlined.

- **Split a plugin at the actual renderer boundary.** The July 2026 List repair moved JSX out of BaseListPlugin and into its live React adapter. Current `packages/platejs/src/features/list/lib/BaseListPlugin.ts` remains renderer-neutral, while `packages/platejs/src/react/features/list/ListPlugin.tsx` imports React and owns mounted-view work such as ListNumberWriter. Source: `docs/plans/2026-07-28-repair-media-table-list-utils-plugin-ownership.md:493`. Preserve semantic behavior in the Base owner and mounted behavior in the adapter; the historical two-file repair does not describe every helper added since.

- **A callback schema needs the same dependency portal as a static schema.** Playground startup failed because a required dependency declared its schema through a callback and the authoring portal omitted that schema. Repair the shared portal rather than each consumer. Current `packages/platejs/src/lib/plugin/createPluginContext.internal.ts:660-710` evaluates declarations and exposes schema access; `packages/platejs/src/internal/plugin/resolvePlugins.spec.tsx:60` reads the callback-declared dependency's default type during another plugin's authoring callback. Source: `c70bacbd4a:docs/plans/2026-09-12-playground-chrome-startup-regression.md:563`. The current lookup is `editor.plugin`, replacing the plan's `editor.extension` spelling.

- **Freeze descriptor data and preserve declared host resources.** July's immutable-publication cut exposed consumers that mutated published values. Repair those consumers at their mutable boundary. Browser proof then isolated EditorKit failures to React resources for `img` and `placeholder`: walking their accessors as descriptor data violated their ownership. Current `packages/platejs/src/internal/plugin/resolvePlugins.ts:127-184,274-344` preserves resources at declared component, override and slot locations while rejecting ordinary descriptor accessors and freezing copied snapshots. Source: `c70bacbd4a:docs/plans/2026-07-22-execute-agent-native-api-shapes.md:413-421`. Opaque locations are explicit; a React marker alone does not exempt arbitrary data.

## Model and transforms

- **Classify missing reads by the caller's invariant.** Removing a strict-read flag requires more than replacing its syntax. The July migration separated stale DOM and input targets, which need guards or domain fallbacks, from model-owned expectations, which need explicit failures, and already-checked array entries, which need no second lookup (c70bacbd4a:docs/plans/2026-07-15-internalize-required-node-reads.md:279-305). Current lifecycle reads remain optional in packages/plitejs/src/interfaces/editor.ts:1076-1100, while mutation-full-block-editing.ts:28-45 asserts model-owned expectations around the first read result. Assert or guard that result without changing its snapshot owner. The plan's caller counts describe the July migration, not today's inventory.

- **Keep an invariant failure separate from optional lookup.** An internal failure function returning `never` lets `value ?? failInvariant(context)` preserve the lookup's inferred type and report a violated expectation without adding an assertion mode to every public read (c70bacbd4a:docs/plans/2026-07-15-internalize-required-node-reads.md:306-338). Current packages/plitejs/src/internal/fail-invariant.ts retains this function, and internal/index.ts exports it. Its current prefix is `Invariant failed:`, replacing the plan's `Plite invariant failed:` prefix. The plan's post-query-middleware mechanism is historical: current core/editor-read-runtime.ts contains direct static wrappers rather than that middleware chain.

- **A feature owns the meaning of a split that copies its wrapper.** Generic block splitting copied media properties when Enter split a direct caption. Suppressing the split with a soft break stopped duplication but produced the wrong document (docs/plans/2026-08-25-media-caption-enter-regression.md:373-384). Keep caption policy in the shared media command owner so model callers receive the same behavior as keyboard callers. Current `commands` in packages/platejs/src/features/media/lib/BaseMediaPlugin.ts handles insertBreak by moving the suffix through slice operations and break.exit, and its contract at BaseMediaPluginContracts.spec.ts:200 covers file, audio, video, image and embed. The August split-then-convert implementation is historical; its ownership lesson still holds.

- **Test a default that depends on where the block lives.** Review of blocks.reset challenged construction of a destination without its parent context. A nested default carrying `sectionTone: "nested"` exposed the distinction that a root-only paragraph fixture could miss (docs/plans/2026-08-26-media-caption-block-reset-api.md:478-492,499-511). Current packages/plitejs/src/core/public-state.ts:6886-6920 asks `schema.elementPropertiesForResetAt(element, path, root)` for each destination before applying patches. Keep a context-dependent property in reset proof, alongside ordinary defaults. Current reset returns false when conversion is unavailable; the plan's earlier throw contract is superseded.

- **Assert that corrections stay outside the update callback.** June's mining run found that transform-level `withoutNormalizing` flushed during an outer update and exposed intermediate work. The repair deferred flushing to the outer boundary. Source: `c70bacbd4a:docs/plans/2026-06-15-source-mining-coverage-hardening.md:415-419`. The helper is gone, but `packages/plitejs/test/transaction-contract.ts:200` retains the decisive oracle: remove and insert by NodeKey, assert no correction or publication during the callback, then require one publication and check discard on failure. Current `packages/plitejs/src/core/public-state.ts` owns finalization. This preserves the atomicity lesson, not the deleted API.

- **Local provenance does not require persisted node properties.** June's mining run used commit tags and local state while deferring distributed provenance. Source: `c70bacbd4a:docs/plans/2026-06-15-source-mining-coverage-hardening.md:442-444`. Current `packages/plitejs/src/core/state-field.ts` keeps fields nonpersisted without a codec; `packages/plitejs/test/commit-metadata-contract.ts:738` checks provenance without serialization, and line 870 uses a declared update annotation for `metadata.origin`. Declared annotations replace the old arbitrary metadata bag. These local contracts prove nothing about Yjs provenance.

## Transaction identity and callbacks

- **Detached work must not publish identity or start host work.** An upload needs the original File and a stable inserted-node key, but a detached spec may be discarded. Carry host objects in private after-commit closures, assign prepared keys during detached insertion, and adopt those keys only when the spec commits. Current `packages/plitejs/src/transforms-node/insert-nodes.ts:110` distinguishes prepared from live identity, and `core/public-state.ts` stores and carries private spec callbacks. The current Upload owner registers its task startup after commit (`packages/platejs/src/features/upload/lib/BaseUploadPlugin.ts:854`). Source: `docs/plans/2026-09-13-clipboard-transfer-policy.md:601-626`. The historical Placeholder API has been replaced; this lesson does not preserve that API or put File objects into effects, history or transport.

## History

- **Prepare fallible inverse history before publishing an edit.** Moving replay behind a service did not repair an edit that published before its effect inversion failed. The history design stages authored capture, affected anchors, history reduction and merge recovery before publishing their coherent results; merely reordering the old callback lost authored selection and deleted-range recovery. Source: `docs/plans/2026-09-15-history-explicit-replay-and-one-grouping-authority.md:220-284`. Current `packages/plitejs/src/history/history-plugin.ts` prepares state inside `registerEditorTransactionGuard`, and `packages/plitejs/src/core/public-state.ts` prepares anchors and guards before publication. Rollback covers supported rejection paths, not an extension's unrelated external side effects.

- **Preview state stays outside document history until acceptance.** Keep draft preview in an application-owned, nonpersisted state field with `history: 'skip'`. Cancel clears that field; accept clears it and edits the document in one fresh history batch, so undo and redo do not resurrect preview UI. Source: `c70bacbd4a:docs/plans/2026-06-15-source-mining-coverage-hardening.md:434-437`. Current `packages/plitejs/src/core/state-field.ts` makes persistence opt-in; `packages/plitejs/test/history/document-state-history-contract.ts:320-399` covers preview, cancel, accept and replay. The plan's literal `persist: false` is historical.

## Suggestions and comments

- **Build rejection and replacement as one unpublished action.** AI cancellation could not safely compose undo with replacement or restore copied preview blocks over foreign edits. The bounded repair stages proposal rejection and the accepted edit together, resolves targets against the resulting draft, and commits UI cleanup only after acceptance. Returning after staging rejection would publish half the action. Source: `docs/plans/2026-09-15-history-explicit-replay-and-one-grouping-authority.md:511-632`; current `packages/platejs/src/ai/react/AIChatPlugin.ts` retains complete accept, reset, insertBelow and replaceSelection API owners. This explains the history adoption; it is not a complete specification of the subsequently evolving AI feature.

## View initialization

- **Reconcile declarative view policy by value.** Depending on an inline authored-prop object's identity can reset a mode selected through view commands on an unrelated parent render. The suggestion initialization repair compares the policy values instead, preserving the mounted view while applying an actual policy change. Source: `docs/plans/2026-09-13-suggestion-package-over-authored-changes.md:40-44`. Current `packages/plitejs/src/react/components/plite.tsx:337-342` keys reconciliation on intent or preview and the editor, rather than the object. The September intent/projection shape has since become an intent-or-preview input.

## Model and view boundaries

- **Do not encode a foreign text renderer as a void kind.** The editable-island design let some queries enter its text while ordinary void handling omitted that text from public representation and collapsed DOM offsets. Its hidden canonical spacer also retained the full text in DOM. The repair made the content an ordinary exact-one-Text block and delegated only the mounted view. Source: `docs/plans/2026-09-03-editable-island-substrate-closure.md:173-214`. Current `packages/plitejs/src/react/external-text.ts` and `react/components/editable-text-blocks.tsx` implement the narrow adapter boundary. The old defects are historical; rich children still require a different rendering contract.

## Schema identity

- **Element remapping and property-key renaming have different costs.** Element-sensitive operations can follow compiled handles, but feature code legitimately reads structural fields such as node.header and node.indent. Making those property keys configurable would force ordinary algorithms, renderers and codecs through dynamic lookup. Keep application overrides narrow: current EditorSchemaElementOverrideInput permits type/content/groups, while EditorSchemaPropertyOverrideInput permits only target (packages/plitejs/src/interfaces/schema.ts:620-647). A new persisted field needs a migration or a different feature descriptor; the retired defineEditor recipe is not the current entrypoint. Source: docs/plans/2026-08-03-application-schema-overrides-and-property-handles.md:366-380.

- **Reject competing override facets before resolving renamed relationships.** Two patches to one source/facet must not become last-writer-wins merely because plugins appear in a different order. The current schema compiler records claimed facets, throws when another owner claims one, builds the final element rename map, and rejects duplicate final types before compiling the prepared declarations (packages/plitejs/src/core/schema-compiler.ts:1690-1805). This preserves the August design's deterministic ownership lesson without retaining its obsolete Plate portal shape. Source: docs/plans/2026-08-03-application-schema-overrides-and-property-handles.md:381-403.

## Optional plugin integration

- **An optional plugin's absent schema must stay absent.** Schema-handle adoption exposed crashes in standalone kits that read another plugin's schema without checking installation. Tabbable now builds blocking types only from installed CodeBlock and Table portals, returning an empty contribution for an absent owner (apps/www/src/registry/components/editor/tabbable.tsx:19-24). Do not fabricate a persisted type string as a fallback, and do not treat a kit passing inside the full EditorKit as proof that it works alone. Source: docs/plans/2026-08-03-application-schema-overrides-and-property-handles.md:667-679.

## Mutation ownership

- **A private mutation plan is not a second committed document.** The September table redesign found independent jobs in detached repair, simulation and diagnostics. Deleting every plan or wrapping every existing plan in another transaction did not fix merge identity loss. The surviving implementation keeps private planning, moves live children canonically during merge, and applies a plan's selection only after its writes (packages/platejs/src/features/table/lib/BaseTablePlugin.ts:1803-1855; internal/mutation.ts:1472-1487). Remove duplicated publication or work, rather than declaring all intermediate representations redundant. Source: docs/plans/2026-09-17-table-api-design.md:57-84.
