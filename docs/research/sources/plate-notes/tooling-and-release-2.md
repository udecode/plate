# Tooling, docs build and release, part 2

## Lint policy

- **A rule's proposed cleanup must preserve type and lifecycle evidence.** The August 2026 lint migration withdrew four re-enable recommendations after source inspection: cleanup already lived in unsubscribe or owner teardown, generic parameters carried subtype and exact-type evidence, dependency cycles expressed intentional recursion or hubs, and nested expressions preserved lazy selection and inference. Rewriting those solely for lint would have changed ownership or hidden contracts. Current `oxlint.config.ts` retains explicit reasons for `typescript/no-unnecessary-type-parameters`, `import/no-cycle` and `no-nested-ternary`. Re-evaluate a rule from representative semantic counterexamples and the installed implementation, not its diagnostic count; these findings do not justify disabling unrelated correctness rules. Source: `c70bacbd4a:docs/plans/2026-08-22-upgrade-ultracite-lint-stack.md:254-263`.

## Build

- **Fine-grained source checks do not require parallel package assembly.** The entrypoint consolidation kept per-feature lint, typecheck and test caches while retaining one atomic package build, because parallel entrypoint builds would write the same `dist` (`docs/plans/2026-08-28-finalize-platejs-entrypoint-ownership.md:301-303`). Current `tooling/entrypoints/entrypoint-dag.mjs` still models feature and adapter partitions independently. Limit: this is a shared-output ownership constraint, not a reason to serialize independent read-only checks.

- **An import boundary must include first-party tests.** A package-wide raw-Plite exemption let authorable Plate code bypass its public facade; exempting every spec preserved the same privileged access in examples future authors would copy. The repair added the missing `platejs/testing` mirror and migrated tests through Plate-owned leaves while retaining explicit bridge and parity-proof exceptions. Current `oxlint.config.ts:79-89` states the boundary, and `tooling/scripts/entrypoint-dag-plugin.test.mjs:96-195` checks the exact allowlist against parsed imports across Plate source, tests and type tests. Source: `docs/plans/2026-08-30-enforce-plate-facade-dogfooding.md:175-252`. The allowlist has since expanded; the historical ten-file count is not the current boundary.

- **Audit module syntax separately from runtime strings.** The August facade rewrite accidentally changed a persisted Yjs namespace because a runtime string resembled a module name. Its first inventory then mistook that legitimate string for a forbidden import. Parse import, export, dynamic import, require and TypeScript import-type syntax when enforcing dependency boundaries; a quoted-text regex cannot distinguish protocol data from module specifiers. Current `tooling/scripts/entrypoint-dag-plugin.test.mjs:25-27,166-195` parses source and compares actual module specifiers with the bridge allowlist. Source: `docs/plans/2026-08-30-enforce-plate-facade-dogfooding.md:253-275`. The old Yjs default namespace is historical; the durable lesson is the syntax-aware audit.

- **Registry author paths and installed targets are different contracts.** Flattening provider-specific authors must preserve one provider-neutral installed filename, or neutral consumers become coupled to a primitive implementation. Current `apps/www/src/registry/registry-variants.ts:9-54` keys variants by flat `@components/editor/*` targets and resolves author source as `bases/<base>/<filename>`; the eight Base/Radix authors remain under `apps/www/src/registry/bases/`. Source: `c70bacbd4a:docs/plans/2026-08-25-flatten-registry-provider-sources.md:296-338`. Its exact local Radix-alias recipe is superseded: today's `apps/www/tsconfig.json` routes relevant canonical imports through `src/components/site-registry`, where the site selects its preview provider.

- **A Tailwind test oracle can become an unwanted utility input.** During the table-handle repair, a test included the malformed escaped utility it intended to forbid. Tailwind source discovery scanned that literal and broke the real route before the behavior could be reproduced. Source: `docs/plans/2026-08-26-hide-drag-handles-during-table-cell-selection.md:260-267`. Current `apps/www/src/lib/tailwind-registry-source.test.ts` expresses the forbidden output through a regular expression rather than the original contiguous utility string. Keep negative CSS fixtures from creating the input they are meant to reject; the historical compile failure was not rerun.

- **A publication lock needs one deterministic storage root.** Moving CLI scratch out of source must preserve a shared lock and journal identity across concurrent processes. Choosing the first writable Git or user-cache location can split that identity; staging on another filesystem also loses atomic-rename assumptions. Source: `c70bacbd4a:docs/plans/2026-08-13-move-plate-cli-transient-state-outside-worktrees.md:249-268,283-289`. Current `packages/cli/src/state.ts` derives durable state from the real project path under node_modules/.cache/plate/state, checks the artifact device and fails when that root is unusable. Disposable compiler directories use OS temp storage. Intentional generated contracts remain beside their source.

- **Optional editor capabilities must leave every default import path.** Removing DOCX file plugins from the default kit did not remove their cost while the default toolbar still statically imported file controls or generic demos imported the full DOCX kit. The repair moved full composition and controls into a dedicated example, aligned registry dependencies and generated API expectations, and checked the bundler's input graph instead of matching strings in emitted JavaScript. Source: `docs/plans/2026-08-18-isolate-docx-io-example-composition.md:208-240`. Current `apps/www/src/registry/components/editor/plugins.ts` imports WordPastePlugin from platejs/docx/paste; `examples/docx-demo.tsx` owns full DocxKit composition. Historical package names and bundle sizes do not describe the current build.

Export generation also failed on a string-form package `bin`; keeping manifests authoritative avoided that failure. Current `getPackageBuildArtifacts` in `tooling/scripts/check-package-build-artifacts.mjs` collects runtime and type targets from the export map, while `withDirectPackageConfig` in `tooling/config/direct-package.config.mts` preserves declaration options and composes warning suppression. ## Dependencies

- **Optional peer metadata does not prove entrypoint isolation.** npm declares peers for a package rather than for each export, so marking an advanced dependency optional cannot prove that an unrelated root or headless subpath avoids it. The entrypoint cut paired explicit DAG edges with isolated packed consumers that installed only each entrypoint's peer closure (`docs/plans/2026-08-28-finalize-platejs-entrypoint-ownership.md:304-308`, `:329-332`). Current `tooling/entrypoints/entrypoint-dag.mjs` retains per-entrypoint runtime and peer metadata. Limit: metadata alone is the declared contract; runtime and declaration consumers must prove actual reachability.

- **Consolidating packages also consolidates module identity.** The August 2026 cut exposed two identity failures: moved DnD source loaded a different React DnD version from its provider, and formerly separate Bun mocks overwrote one another after their imports became the same `platejs` module. Audit provider/library versions and merge mocks by the final module specifier when packages merge. Source: `c70bacbd4a:docs/plans/2026-08-28-full-platejs-package-cut.md:311-325`. The current implementation resides under `packages/platejs/src`; the historical v14/v16 mismatch describes that migration, not a current defect.
