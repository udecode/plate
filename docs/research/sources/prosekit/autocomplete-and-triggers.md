# ProseKit: autocomplete and triggers

## Autocomplete plugin

- ProseKit's autocomplete keeps the query as document text with a tracked range. State is `{ignores, matching}` (`prosekit/prosekit@3fbfe790:packages/extensions/src/autocomplete/autocomplete-helpers.ts:42-52`). The range maps through `tr.mapping`, is re-validated against the rule regex (`prosekit/prosekit@3fbfe790:packages/extensions/src/autocomplete/autocomplete-plugin.ts:135`, `:161-172`), and is marked by an inline decoration. It opens only from `handleTextInput` or an explicit `triggerAutocomplete` scan (`autocomplete-plugin.ts:22-27`; `prosekit/prosekit@3fbfe790:packages/extensions/src/autocomplete/autocomplete.ts:20-32`), so paste, undo and remote edits never open it (inferred). Leaving the match or pressing Escape records a sticky ignore that maps through later edits (fixed #976). Undo restores the query text without reopening the menu (`autocomplete-plugin.ts:138-141`, inferred). Its highest-priority DOM keydown bridge ignores keys while `view.composing` and for 50 ms after `compositionend`, a WebKit workaround (PR #1759). It has no `isComposing` or 229 check, and open PR #1743 reports Pinyin's commit Enter selecting an item. The popup is a `role=listbox` that carries `aria-activedescendant` itself, while focus stays on a contenteditable with no combobox role, so screen readers likely do not announce the active option (inferred). When a rule matches, `handleTextInput` dispatches its own transaction and returns true, which pre-empts later input rules (inferred). The default `canMatch` excludes code.
