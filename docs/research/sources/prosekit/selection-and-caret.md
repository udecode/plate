# ProseKit: selection and caret

## Staged select-all

- **Staged select-all.** `prosekit/prosekit@3fbfe7906c3448328e80c1c1333647d08e50907e:packages/core/src/extensions/keymap-base.spec.ts` (L12-L69) pins ProseKit's default staged select-all. The first Mod-A selects the current textblock and a second selects the document. Mod-A goes straight to the document when the textblock is already selected, when several blocks are selected or when the textblock is empty, and `defineBaseKeymap({ preferBlockSelection: false })` turns the staging off. ProseKit issue #1077 ('The first Ctrl + A should select only the entire block', closed) asked for it (`docs/editor-issue-harvester/prosekit/full/issues.md:65`). Plate stages Mod-A only inside containers: a code block, a table and then the document, and a column and then its column group (`docs/editor-behavior/markdown-editing-spec.md:1020`, 1198-1207, 1860-1862). Elsewhere Plite's editing kernel maps Mod-A to its model-owned `select-all` command, which selects the whole root (`packages/plitejs/src/react/editable/editing-kernel.ts`, `packages/plitejs/src/react/editable/mutation-controller.ts`). No law asks for ProseKit's paragraph-level staging; a product that wants it would own it in selection UI and prove it with a browser row (`docs/editor-test-harvester/prosekit/report.md:137`).

## Blurred selection

- **Blurred selection.** `prosekit/prosekit@3fbfe7906c3448328e80c1c1333647d08e50907e:packages/extensions/src/virtual-selection/index.spec.ts` (tests at L89-L139) pins `defineVirtualSelection`. When focus moves elsewhere in the page, a non-empty selection paints as an inline decoration; a blur from leaving the window paints nothing. The decoration follows selection changes dispatched while blurred and survives document edits. A primary press in a nested editable removes it before mousedown, so its wrapper spans cannot disturb pointer placement (`prosekit/prosekit@3fbfe7906c3448328e80c1c1333647d08e50907e:packages/extensions/src/virtual-selection/index.ts`, lines 65-73); a click on a non-editable control and a secondary-button press keep it. Plite has the same ordering in `packages/plitejs/src/react/inactive-selection.ts`: `packages/plitejs/test/react/editable-behavior.tsx` ('resolves inactive selection before mousedown for $name') clears it for a primary press in a nested editable and keeps it for a secondary or non-primary pointer, an embedded control and a marked control, and 'shows an expanded selection while focus is in a marked control' repaints it when the selection changes while blurred. Plite differs in activation: an Editable paints its inactive selection only when focus moves to an element marked `data-editor-keep-selection-visible`, and it also paints a collapsed caret. ProseKit issue #1670 reports a wrong virtual selection after blur when a color picker sits in a popover (`docs/editor-issue-harvester/prosekit/full/issues.md:101`; `docs/editor-test-harvester/prosekit/report.md:138`).
