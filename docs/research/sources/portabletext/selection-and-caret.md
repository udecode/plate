## Object boundaries

- **Object boundaries.** The harvest groups 8 Portable Text files (75 indexed test and describe names) on block and inline objects (report.md:117). At `portabletext/editor@ad2a52d13d9f:packages/editor` they pin objects as atoms: ArrowRight before or ArrowLeft after an image selects it; ArrowUp or ArrowDown on a lonely image, or ArrowDown on a final image, adds an empty text block above or below it; one Delete before, or one Backspace after, an image or inline object removes it whole; Enter on a void block object inserts a sibling text block; and a decorator or annotation toggled across an inline object marks the text on both sides (`gherkin-spec/block-objects.feature`, `gherkin-spec/inline-objects.feature`, `tests/inline-objects.test.tsx`, `tests/define-leaf-block-object-wrapper.test.tsx`). The rendering tests pin a `contenteditable="false"` wrapper and an engine-emitted void spacer that reaches the consumer's renderer through `children` (`tests/define-leaf-inline-object-spacer.test.tsx`, `tests/inline-object-contenteditable.test.tsx`). The harvest's summary, atoms "without hidden spacer nodes intercepting" movement, delete, paste or drag, is its target for Plite, not what these tests assert: Portable Text keeps a spacer.
