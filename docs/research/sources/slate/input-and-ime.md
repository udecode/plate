# Slate: input and IME

## Android input manager

- **Slate's Android rewrite and its later selection fix.** Slate PR #4988 (merged 2022-07-29 as commit `fbab6331a`) rewrote Android input around `beforeinput`, and its description rests on the premise that Android's `beforeinput` cannot be canceled. So Slate lets the browser change the DOM, stores each text edit as a pending diff, and applies the diffs to the model later: 25 ms after `compositionend`, when a model action is scheduled, or 200 ms after a selection change that moves to another leaf or arrives while diffs are pending (`ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-react/src/hooks/android-input-manager/android-input-manager.ts:32-35`, `:249-260`, `:738-767`). PR #5901 (merged 2025-06-26 as `5a20ea3ad`, for #5892 and #5893) makes each stored text insert also schedule a select action to the end of the inserted text (`:691-711`), and on Android makes `editor.insertText` drop the pending selection first, because on Samsung devices the selection change that typing had scheduled ran after a programmatic insert and put the caret back (`ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-react/src/plugin/with-react.ts:28-40`). PR #6096 closed #5883 on 2026-08-18, after the fork's head commit of 2026-04-13, so its code was not read here; its description fixes four paths that cancel composition in an empty leaf, shows a Gboard Korean device trace, and says Pinyin and Gboard English autocorrect break the same way. Plite's device lane records Gboard Korean and English autocorrect failures in an empty editor; whether they share Slate's cause is unchecked. Evidence: commit messages and code in the local fork at `945a484d`, read 2026-10-08, and the three PR descriptions read on GitHub on 2026-10-02 (`docs/plite/research/2026-10-02-agentic-e2e-testing/read-log.tsv:325-327`).

- **Slate's Android input manager special cases.** Slate's Android `beforeinput` handler collapses a line-break delete's target range to one character, so an empty leaf before the break is not unhung out of the range; schedules a model action instead of storing a diff when a delete would empty a text leaf; strips the U+FEFF that a pending mark placeholder leaves in IME text; drops the extra trailing newline Android appends to a multi-line clipboard `insertText`; and moves SwiftKey's off-by-one `insertCompositionText` target back one character for the second word after a mark placeholder (`ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-react/src/hooks/android-input-manager/android-input-manager.ts:403-423`, `:439-444`, `:605-616`, `:648-670`). RestoreDOM, mounted only on Android, buffers tracked DOM mutations after user input and undoes them in `getSnapshotBeforeUpdate`, right before React commits; it skips `characterData` mutations, because restoring text interrupts the composition (`ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-react/src/components/restore-dom/restore-dom.tsx:56-66`, `:82-84`, `ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-react/src/components/restore-dom/restore-dom-manager.ts:33-49`). `Editable` passes the app's `spellCheck`, `autoCorrect` and `autoCapitalize` through when the browser supports `beforeinput` or during server rendering, and turns them off otherwise (`ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-react/src/components/editable.tsx:1035-1054`). Evidence: read 2026-10-08 at the local fork; first read 2026-10-02 (`docs/plite/research/2026-10-02-agentic-e2e-testing/read-log.tsv:339-341`).

- **What PR #6096 changed, read in code.** At ianstormtaylor/slate@b96028a57a90099d07c615a0b8d8ae06c3b86f12 (#6096, merged 2026-08-18 for #5883), the commit names the root cause that the bullet above gives only from the PR text: on Android an empty leaf's zero-width string rendered a bare `<br>` with no text node, so an IME composing the first character made the browser create the text node, and any path that then replaced the leaf's DOM cancelled the composition and left the first jamo behind (typing 안녕 gave ㅇ안녕). The fix renders U+FEFF before the `<br>` on Android too, so the composition lives in a React-owned text node (`ianstormtaylor/slate@b96028a57a90099d07c615a0b8d8ae06c3b86f12:packages/slate-react/src/components/string.tsx:161`), and skips `TextString`'s `textContent` write while an Android composition sits in that span (`:90-99`). It defers flushes while pending diffs target an empty leaf and the composition is live, treating one that lost focus or stayed quiet for 5 s as over (`ianstormtaylor/slate@b96028a57a90099d07c615a0b8d8ae06c3b86f12:packages/slate-react/src/hooks/android-input-manager/android-input-manager.ts:43`, `:145-200`), applies them synchronously at `compositionend` under `flushSync`, because Hangul and kana IMEs start the next composition in the same tick (`:326`), and drops them when the IME sends an empty `insertCompositionText` (`:455`). Its only test is a manual 'IME first character' case in the `android-tests` example. Plite's line-break placeholder, which the block renderer uses for the empty last text of an empty block, also renders a `<br>` with no U+FEFF text node, on every platform (`packages/plitejs/src/react/components/zero-width-string.tsx:27-39`, `packages/plitejs/src/react/components/editable-text-blocks.tsx:669-677`). Plite's recorded Gboard Korean failure also happens at the end of existing text in the plaintext example, where no empty leaf is involved (the `plite` input page's Gboard Korean entry), so this shape cannot be its only cause; whether it contributes in the empty paragraph is untested.

- **Which Android keyboards compose, from Slate's threads.** Read on 2026-10-02: Gboard Korean (두벌식) composes, and PR #6096's device trace shows `compositionstart` and then `compositionupdate` for `ㅇ`, `아`, `안`, `안ㄴ`, `안녀`; Gboard Japanese romaji composes (#5883, Gboard 14.2), as do Gboard Chinese Pinyin (#5984, PR #6096) and Sogou handwriting (#5979). Whether Gboard English composes tapped letters is disputed in the threads (#5078, #5019, #5493, PR #6096), while on a 2026-10-02 API 36 emulator it committed each letter as `insertText` (see 'Android device lane' on `docs/research/sources/plite/testing-and-proof.md`), so a composition case types Korean, Japanese or Pinyin. Slate's SwiftKey branch is under 'Slate's Android input manager special cases' above. Limit: thread reports, not device runs, and glide, voice and suggestion taps were not classified. Source: `docs/plite/research/2026-10-02-agentic-e2e-testing/shards/005-android-scenarios-from-slate.md:43-53`.

- **Slate's Android `RestoreDOM` undoes structural DOM mutations before React commits.** On Android only, Slate wraps the editable's children in `RestoreDOM`, a class component because it needs `getSnapshotBeforeUpdate`. A `MutationObserver` on the root buffers tracked childList and characterData mutations once `receivedUserInput` is set. Right before React commits an update, it takes the pending records, disconnects and replays the buffer in reverse, reinserting removed nodes and removing added ones; it skips characterData records because restoring text interrupts the composition. After the update it clears the buffer and observes again. On other platforms it renders its children unchanged (`ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-react/src/components/restore-dom/restore-dom.tsx:15-84`, `ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-react/src/components/restore-dom/restore-dom-manager.ts:21-54`, mounted at `ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-react/src/components/editable.tsx:1030`). The April 2026 Plite file ledger classed it as a rerender-era guard and recorded its Android rows green without it (`c70bacbd4a:docs/plite-draft/release-file-review-ledger.md:252-265`); Plite has no counterpart, as the plite input page's 'Plite's Android input manager.' entry records. Limit: source read on 2026-10-08 at that commit; no device run.
