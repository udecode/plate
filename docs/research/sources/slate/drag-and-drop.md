# Slate: drag and drop

## Native drag

- Legacy Slate drags and drops with native React handlers: `onDragStart` writes the selected fragment through `setFragmentData`, and `onDrop` maps the drop point with `findEventRange`, selects it and inserts through `insertData` (`ianstormtaylor/slate@945a484d:packages/slate-react/src/components/editable.tsx:1426-1510`); the DOM plugin writes and reads fragments as `application/x-slate-fragment` (`ianstormtaylor/slate@945a484d:packages/slate-dom/src/plugin/with-dom.ts:237`, `:323-331`). The bounded read found no dedicated touch or keyboard reorder controller. The read used the zbeyens fork; the canonical upstream head `0f847cb9b059debdfd125dd62e967cb3b3ca3a62` was not inspected. Source: `docs/plite/research/2026-10-02-dnd-library-choice/README.md:112`, `repo-registry.tsv:9`.

- **Where a Slate drop lands.** Over a void, `findEventRange` snaps the drop point before or after the void by the nearer edge (`ianstormtaylor/slate@945a484df249:packages/slate-dom/src/plugin/dom-editor.ts:314-375`). For an internal drag, `onDrop` deletes the dragged range unless it equals the drop range or the drop lands in a void, then calls `insertData` at the drop point with no schema or depth check (`ianstormtaylor/slate@945a484df249:packages/slate-react/src/components/editable.tsx:1475-1514`), so a dragged block fragment merges into or splits whatever block holds the drop caret, including cells, quotes and list items, and normalization repairs the structure. Dragstart over a void selects that void, and there is no indicator beyond the browser caret. Source: `docs/plite/research/2026-10-02-dnd-landing-policy/editors.tsv:32-37`.
