# Slate: issues and regressions

## Core model, operations, normalization and history

- **Normalization (#3950, #5811, #2039, #3465, #2355, #3275, #4701, #4641).** Plite calls normalizers corrections. A correction runs on a `children`, `content` or `properties` event and receives `{ editor, entry, tx }` (`packages/plitejs/src/interfaces/editor.ts:2435-2456`), so corrections stay entry-based, with no path-only `normalizeNode` (#3275), and no correction event covers the selection (#2355). Plite rechecks a node that a correction changed until it reaches a fixpoint ('rechecks a corrected node until it reaches fixpoint', `packages/plitejs/test/normalization-contract.ts:974`), which is the ledger's fix for #3950 (re-normalizing a transformed node). It fails deterministically when a correction revisits an earlier draft state and reports correction cycles with a deterministic transition fingerprint (`packages/plitejs/test/normalization-contract.ts:931`, `:1251`), which improves Slate's 'Could not completely normalize the editor' loop (#5811); conflicting app corrections stay app or schema work, and no separate named or stack diagnostic is claimed for #2039. An invalid initial value is repaired only by the explicit maintenance call `editor.update.value.repair()` (`packages/plitejs/test/normalization-contract.ts:34`), so automatic normalization of `initialValue` (#3465) is not claimed. Command-owned selection targets survive canonical repair, as 'preserves the caret inside text merged during automatic canonicalization' shows (`packages/plitejs/test/normalization-contract.ts:361`). No custom empty-text factory is claimed for #4701, and #4641's property-update case lacks exact package proof. Source: `docs/plite-issues/gitcrawl-v2-sync-ledger.md:21-34`, hydrated on 2026-07-12, which supersedes the older rows for these issues.

- **History and selection (#3534, #3551, #4559, #3499, #3705, #3921, #3756).** The ledger keeps fix claims for four undo reports, each with a matching contract in `packages/plitejs/test/history/history-contract.ts`. #3534 (selection broken after undoing): undo after Enter over a selection spanning three blocks restores the document and that selection ('restores the saved multi-block selection after insertBreak and undo', `packages/plitejs/test/history/history-contract.ts:2148`). #3551 (undoing `move_nodes` gives the wrong state): undo after a `moveNodes` commit restores the original tree and selection (`packages/plitejs/test/history/history-contract.ts:2211`). #4559 (`deleteFragment` undo should select the reinserted fragment): undo reselects the restored text, also after blur and refocus (`packages/plitejs/test/history/history-contract.ts:2078`, `:2100`). #3499 (marks on a selected word moved to a new line): Enter at the start of a bold word moves the bold run into the new block, and undo restores the paragraph, its marks and the selection (`packages/plitejs/test/history/history-contract.ts:2167`). Ledger rows: `docs/plite-issues/gitcrawl-v2-sync-ledger.md:223`, `:625`, `:765`, `:776`, `:944`. For #3705 and #3921 ('Cannot apply an incomplete set_selection operation properties', the second after history refocus), the ledger records partial undo coverage as improvements; the nearest current contract is 'does not replay partial selection range patches after selection is cleared' (`packages/plitejs/test/history/history-contract.ts:2029`), and the ignored-template case of #3705 and the refocus browser case of #3921 are unproven. #3756 (slate-history does not undo selection movement) stays related (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:330-332`). Limits: these rows rest on the fork dossier, deleted in `c5a1fc3f17` on 2026-10-08; no test carries an issue tag, so matching tests to issues is inferred from their titles; and the ledger contradicts itself on #3756 (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:331` says cluster-synced, `:617` triage-closed).

- **Collaboration (#5533, #1770, #2288, #3741, #5771).** Plite transactions build a canonical `DocumentChange` rather than a Slate operation list (`docs/vision/plite.md:26-28`). Core replay of text, mark, range-delete and move commits converges three package peers ('converges three peers across text, mark, delete, and move commits', `packages/plitejs/test/collab-history-runtime-contract.ts:290`), and a range delete is stored as one canonical undo batch (`packages/plitejs/test/collab-history-runtime-contract.ts:453`). Through the Yjs binding, offline same-parent and cross-parent moves reconnect with concurrent remote text kept, and undo and redo touch only the local move (`packages/plitejs/test/yjs/move-node-contract.spec.ts:105-258`). For #5771 (an exception between select and anchor operations in collaboration), core contracts keep a local collapsed selection valid through remote prefix bursts, same-offset contention, suffix inserts, split and merge, and removal of the selected node (`packages/plitejs/test/collab-selection-stress-contract.ts:111-199`), and anchor rebasing and remote canonical reconcile have their own contracts (`packages/plitejs/test/collab-anchor-position-contract.ts`, `packages/plitejs/test/collab-canonical-reconcile-contract.ts`). The ledger keeps #5533 (collaboration without Yjs), #1770 (combining operations), #2288 (range operations) and #3741 (a moved-node payload for OT undo) related, and claims an improvement for #5771 (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:440`, `:525`, `:623`, `:626`, `:877`). Limits: Plite ships no first-party OT or Yjs-free protocol, no general operation-composition utility and no moved-node payload; exposing range operations publicly is a separate API decision; and #5771 has no real adapter or browser repro.

- **Core deletes stay inside the selection (#4121, #3965).** For #4121 (deleting selected text deletes all preceding text under some conditions), an expanded delete across bold, plain and italic leaves removes only the selected content and collapses at the selection start ('deletes only the selected formatted leaf window', `packages/plitejs/test/delete-contract.ts:600`). For #3965 (a deletion bug at a marked block start), Backspace at the start of a block whose first leaf is an empty bold leaf merges it into the previous bold paragraph and keeps the text on both sides ('merges same-mark text when Backspace crosses an empty marked block start', `packages/plitejs/test/delete-contract.ts:809`). The ledger claims both fixes (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:835`, `:864`). The `plate-notes` selection page holds the delete lessons for #5972, #5847 and #2500.

## Selection, focus and DOM bridge

- **Nested editors and editable void content (#5212, #2072, #4984, #4842, #3909, #3482, #3367).** Slate's reports here ask for editing inside voids, an island component, void children, or nested editors that do not break DOM point resolution. Plite keeps default voids atomic and answers nested editors with a same-runtime child root that the element declares in its schema. The editable-voids example declares `'editable-void': { contentRoots: { body: ... }, void: 'block' }`, names each body root `editable-void:<id>:body`, and creates it with `tx.roots.create` before it inserts the node (`apps/www/src/app/(app)/examples/plite/_examples/editable-voids.tsx:35`, `:111-123`, `:240-241`). Renderers mount the root with `useContentRoot(element, { slot })` (`packages/plitejs/src/react/hooks/use-plite-content-root.ts:28`), and a content root is `exclusive` or `shared` (`packages/plitejs/src/interfaces/schema.ts:317`). Browser rows cover editing, focus, paste, copy and cut, drop, undo, redo and keyboard selection across the child root, such as 'extends keyboard selection from editable void child root into outer siblings' (`apps/plite/tests/plite-browser/donor/examples/editable-voids.test.ts:960`). The ledger keeps a fix claim only for #4984, which the DOM point family entry states, and holds #5212, #2072, #4842 and #3909 as related or cluster-synced (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:118-122`). Child roots do not answer Slate's inline-void mobile (#5183, #5391), inline-void clipboard (#4806, #4802, #4104, #3926), drop and drag (#4888, #4623), spacer and cursor (#5087, #5411, #3611, #3435, #3449, #4839), Firefox embed caret (#4110), deep-nested emptying (#3858) or external focus (#1769, #3893) reports (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:123-132`). Limits: the 2026-05-24 plan also kept an `editable-island` mode for native controls, which was later removed (`packages/plitejs/src/core/schema-compiler.ts:1353-1354`). Current law requires independent addressing, lifecycle, sharing or transaction semantics for an explicit root, and models a block whose identity stands apart from its editable children as `object: true` with normal children (`docs/vision/plite.md:530-544`).

- **Blur, unfocused updates and spellcheck (#4376, #5171, #5095, #5096).** For #4376 (Safari: the selection becomes null when the editor blurs), Plite keeps the model selection when focus moves to an outside input ('keeps model selection when focus moves outside the editor', `apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:3125`). For #5171 (Firefox makes an invalid selection update on editor change while the editor is unfocused), an unfocused editor's update does not import an outside input's DOM selection ('keeps unfocused editor updates from importing external selection', `apps/plite/tests/plite-browser/donor/examples/document-state.test.ts:109`, desktop projects only). The ledger claims both fixes on 2026-05-23 and describes the #4376 WebKit proof as also refocusing and typing at the kept point (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:147-148`). Limits: the current row stops at the selection check, and the `webkit` project runs only on macOS hosts (`apps/plite/playwright.config.ts:72-88`). For #5095 and #5096 (Safari spellcheck with Cyrillic text), 'keeps Cyrillic input stable with spellcheck enabled' (`apps/plite/tests/plite-browser/donor/examples/document-state.test.ts:474`) guards typed Cyrillic text only, not Safari's spellcheck UI or dictionary, so neither issue is claimed (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:149`).

- **Refocus scroll, and what TanStack's iOS fix does not prove (#5826 and others).** For #5826 (unexpected auto-scroll when the editor is refocused), Plite's huge-document row clicks the top block, moves focus out, scrolls to the final block and clicks back in, and then keeps the clicked final-block selection visible instead of restoring the top one ('keeps clicked refocus position visible in a long editor', `apps/plite/tests/plite-browser/donor/examples/huge-document.test.ts:2138`, desktop only). 'does not scroll to top when refocusing a scrollable editor' covers a scrollable richtext editor (`apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:3301`, desktop only). The ledger claims the fix (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:240`, `:353`, `:422`). Plite's virtualized rendering uses TanStack Virtual through an optional `@tanstack/react-virtual` peer (`packages/plitejs/package.json:214`, `:224`; `packages/plitejs/src/react/virtualized/use-virtualized-root-plan.ts`). TanStack's iOS momentum-scroll handling is not proof for Slate's focus and selection scroll reports (#5538, #4995, #5088, #5473), nor for its iOS selection, IME, spellcheck or native toolbar reports (#5391, #5095, #4751, #4354, #3760). Each needs a targeted browser repro or a raw iOS run before any claim (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:241-242`).

- **Zero-width placeholders (#5760, #2597, #1971).** Plite keeps the U+FEFF sentinel in empty-text, inline-edge, void-spacer and mark placeholders and drops it only in line-break placeholders, which render a bare `<br>` (`packages/plitejs/src/react/components/zero-width-string.tsx:7`, `:27-41`; `packages/plitejs/src/react/components/editable-text-flow.tsx:519`). `docs/research/sources/plate-notes/input-and-events.md` gives the IME reason. So the ledger claims neither #2597 (U+FEFF as a zero-width no-break space is deprecated) nor #1971 (use `<br>` for zero-width white space) (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:433`, `:979`). For #5760 (`setStart` called with offset 1 on a zero-length text node), it claims an improvement: the DOM bridge maps a zero-width DOM point back to the Plite start offset and adjusts zero-width DOM offsets when it converts a collapsed Plite range (`packages/plitejs/test/dom/bridge.ts:1321`, `:1519`; ledger `docs/plite-issues/gitcrawl-v2-sync-ledger.md:443`). Limits: no raw iOS device run backs #5760, and the real-browser test that the #2597 and #1971 rows cite only checks that a test helper reads both placeholder shapes (`packages/test/test/browser/zero-width.browser.test.ts:5-30`).

- **The 'Cannot resolve a DOM point' family (#4984, #4789, #4564, #4088, #5947, #5938).** Slate throws when a selection or lookup crosses DOM that the editor does not own. Plite imports a native selection only when both endpoints belong to the editor (`docs/research/sources/plate-notes/selection-and-editing.md` states the mechanism), and its DOM bridge resolvers return `null` instead of throwing: `resolveDOMNode`, `resolveDOMPoint`, `resolveDOMRange`, `resolveEventRange`, `resolvePath` and `resolveRangeRect` (`packages/plitejs/src/dom/plugin/dom-editor.ts:188-193`). The ledger claims fixes for two reports. For #4984 (selecting over a nested editor throws), a parent selection that crosses into a same-runtime child root is ignored with no runtime error ('ignores a parent selection that crosses into a same-runtime child root', `apps/plite/tests/plite-browser/donor/examples/editable-voids.test.ts:1381`, desktop only). For #4789 (a selection that starts outside the editor and ends inside it throws), such a native selection is ignored and the editor still takes typing after refocus ('ignores a native selection that starts outside the editor and ends inside it', `apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:5778`). It claims improvements for two lookup reports: for #5947 (`toSlatePoint` can find a point in a parent editor), the bridge refuses path-tagged nodes outside its editor and keeps parent and nested editor points apart (`packages/plitejs/test/dom/bridge.ts:367`, `:554`); for #5938 (`findPath` returns no or the wrong path), lookup falls back to mounted path and runtime metadata when the weak maps lag (`packages/plitejs/test/dom/bridge.ts:169`, `:190`). #4564 (removing content programmatically throws) rests only on a model test that replaces the document and clears the selection in one transaction (`packages/plitejs/test/state-tx-public-api-contract.ts:199`). #4088 (the mention example's range logic throws) stays related until a mention browser row replays it, and none of the current mention tests is named for it. Ledger rows: `docs/plite-issues/gitcrawl-v2-sync-ledger.md:394`, `:397`, `:670`, `:694`, `:703`, `:847`. Limits: the #4984 proof covers a same-runtime child root, not a second React editor mounted inside a void, and the exact Slate repros of #5947, #5938 and #4564 were not replayed.

- **Block-level gestures around blocks, voids and tables (#3871, #4301, #3991, #6034).** Browser rows on the raw Plite examples prove four Slate reports that the ledger marks fixed. For #3871 (triple-clicking selects part of the block below), a triple-click on the first richtext paragraph selects that block only, from `{ path: [0, 0], offset: 0 }` to `{ path: [0, 6], offset: 1 }` ('selects the current block on browser triple click', `apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:7254`), and Backspace or typing after a triple-click removes or replaces that block (`apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:7310`, `:7353`). For #4301 (a slate-react 0.62 regression broke void selection), Enter or Shift+Enter on a clicked image inserts an editable paragraph after it, and typing lands there (`apps/plite/tests/plite-browser/donor/examples/images.test.ts:911`, `:941`). For #3991 (void delete behavior), Backspace in an empty paragraph right after an image removes the paragraph and selects the image instead of deleting it ('removes an empty paragraph after an image before deleting the image', `apps/plite/tests/plite-browser/donor/examples/images.test.ts:828`). For #6034 (ArrowDown at the end of a table that is the last node moves the caret), after the trailing paragraph is deleted, ArrowDown keeps the caret in the last cell and typed `X` makes the cell text `9X` (`apps/plite/tests/plite-browser/donor/examples/tables.test.ts:112`). Ledger rows: `docs/plite-issues/gitcrawl-v2-sync-ledger.md:370`, `:513`, `:671`, `:680`. Limits: every row skips the `mobile` project, #3991's also skips Firefox, which moves the caret after the image, and the `webkit` project runs only on macOS hosts (`apps/plite/playwright.config.ts:72-88`).

- **Caret at inline edges (#3148, #4074, #3429, #4618).** Plite keeps the end of an inline and the start of the following text as distinct caret positions, and its private DOM selection bridge owns that choice. In the inlines example, a DOM selection at offset 0 of the text after the link types outside the link ('keeps the start of following text distinct from the end of an inline', `apps/plite/tests/plite-browser/donor/examples/inlines.test.ts:480`), and a selection at the end of the link text types inside it ('types inside an editable inline at its end', `apps/plite/tests/plite-browser/donor/examples/inlines.test.ts:398`). Those rows back #3148 (Chrome and Safari cannot select the end of an inline) and #4074 (writing inside inline elements). A caret in the text before the padded editable-button inline stays outside it ('places the caret outside a padded inline before typing', `apps/plite/tests/plite-browser/donor/examples/inlines.test.ts:1392`), which backs #3429 (padding puts the caret inside the inline). The ledger claims fixes for all three, for Chromium and, for #3148, WebKit (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:770`, `:830`, `:857`). #4618 asks for a `normalizePoint` method to customize caret movement, and Plite rejects a public cursor-normalization hook (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:747`). The `normalizePoint` that `plitejs/dom` exports is a different helper, which walks a pending DOM text-diff point to a valid text point (`packages/plitejs/src/dom/index.ts:83`, `packages/plitejs/src/dom/utils/diff-text.ts:180-186`). Limits: the three rows skip the `mobile` project, the `webkit` project runs only on macOS hosts (`apps/plite/playwright.config.ts:72-88`), and Slate's tracker #3150 for these boundaries stays related (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:150`).

- **RTL caret after a new line (#1498).** Related only: real-browser tests map RTL DOM selection offsets while keeping the browser's geometry direction, and keep wrapped-line DOM rectangles tied to one editor selection (`packages/test/test/browser/selection.browser.test.ts:165`, `:207`). The exact RTL Enter caret case still needs a browser repro in a real editor (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:980`).

## Mobile, IME and input semantics

- **Android typing after a mark toggle (#6022).** Slate #6022 reports that on Android the soft keyboard closes and the caret jumps when the user types after toggling a mark on a collapsed selection. Plite's Android input manager had the same stale path: after a collapsed marked insert split the text into a new marked leaf, it reapplied the old leaf's raw selection. The fix keeps the selection on the new leaf. The contract 'keeps selection on the marked inserted leaf after collapsed mark typing' types `w` with bold pending after `a` and expects the selection at path `[0, 1]`, offset 1 (`packages/plitejs/test/react/android-input-manager-contract.test.ts:1202`). Upstream PR #6027 targets the same root-cause class and stays linked evidence only (`docs/plite-issues/gitcrawl-recluster-map.md:188`). Limit: the contract drives the input manager with mocked DOM resolution, and the keyboard dismissal needs a raw Android Chrome or WebView run, so the ledger claims no fix (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:158-168`, `:372`).

- **Input events for start-of-content typing, numbers and Backspace (#5669, #5603).** Slate reports that `input` does not fire when deleting text or typing numbers (#5669) or when typing at the start of a contenteditable (#5603). Plite routes start-of-content and number typing through `beforeinput` and Backspace through a model-owned keydown delete command ('exposes input intent for start insert, number insert, and delete', `apps/plite/tests/plite-browser/donor/examples/richtext.test.ts:1907`, desktop only; routing in `packages/plitejs/src/react/editable/runtime-input-events.ts`). The ledger keeps both related (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:392`, `:496`). Limit: parity with native `input` events is not claimed.

## Performance and scalability

- **Large paste, copy and cut (#5945, #4056, #5992).** The `clipboard-large-payload` benchmark target (`benchmarks/targets/slate-v2.json:1559-1560`) runs one issue-target lane per report: '10,000-line plaintext paste' for #5945, 'large text paste/copy into populated editor' for #4056 and '50,000-block two-node cut' for #5992. Their issue budgets gate the canonical artifact, which requires 50,000 cut blocks and 10,000 issue-stress lines (`benchmarks/slate-v2/donor/core/current/clipboard-large-payload.mjs:79-85`, `:1592-1604`, `:1749-1772`). A selected full-document block range deletes as one structural change ('deletes a selected full-document block range as one structural change', `packages/plitejs/test/delete-contract.ts:1302`), and a browser stress family cuts two top-level blocks of a 5,000-block document (`apps/plite/tests/plite-browser/donor/stress/generated-editing.test.ts:178-185`). The ledger claims improvements only: exact browser reproduction of each report is unclaimed, and closing #5992 waits on maintainer acceptance (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:197-199`, `:378`, `:395`, `:698`). Its rows name the operations `replace_fragment` and `replace_children`, which no longer appear in `packages/plitejs/src`, and give timings with no pinned run: a 2026-05-23 plan recorded 49.35 ms to copy 10,000 populated blocks and 235.22 ms to paste 10,000 plaintext lines into a 10,000-block editor (`docs/plans/2026-05-23-plite-clipboard-fragment-serialization-ralplan.md:126-128`), and that run's artifact was not kept. The `plate-notes` performance page holds the cost model behind these lanes. Limit: `benchmarks/editor/benchmarks/results/rich-text-editors-latest.json:140` reports no current observation for this workload, so this entry states no current timing.

- **Pagination, unmounted DOM and accessibility (#5944, #5924, #3892, #790, #2793, #2572).** Plite's paged editable takes `pageView` and a `virtualize` option (`packages/plitejs/src/pagination/react.tsx:768-784`), plans which page items mount (`packages/plitejs/src/pagination/page-mount-plan.ts`), and resolves a range that crosses hidden content to a DOM coverage boundary ('resolves a range crossing hidden content to boundary policy', `packages/plitejs/test/dom/dom-coverage.ts:426`). The ledger maps Slate's layout reports onto that design and closes none of them (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:282-289`). #5944 (stable per-line pagination without flicker at page boundaries) stays related until browser rows cover page-boundary flicker, caret mapping and page-break stability. #5924 (excluding structural DOM from the contenteditable context) is answered by DOM coverage and mount planning, not by a public ignore-cursor API. #3892 (a custom editor surface and layout engine) gets a generic layout substrate only, and product layout engines stay outside Plite. #790 (dynamic rendering) stays open until mount, edit and scroll benchmarks, mounted-count proof, DOM coverage and native-behavior browser proof exist. #2793 (Slate does not work with screen readers) is the release guard for any mode that leaves DOM unmounted: no native-equivalence claim without assistive-technology proof or documented degradation, and #2572 stays broad accessibility pressure. Layout and page subscriptions must keep the nested rerender breadth measured for #4141 and must not widen invalidation (#5131, #2051).

- **Batched transactions (#6038).** For #6038 (repeated tree updates need a batch-aware apply engine), the `plite-transaction-execution` target asks whether one native transaction publishes a mixed structural and text command batch once and beats five equivalent publications (`benchmarks/targets/slate-v2.json:1893-1899`). Its script always fails when the batched and separate lanes end in different snapshots or the batch publishes more than once (`benchmarks/slate-v2/donor/core/current/transaction-execution.mjs:176-187`). With `PLITE_TRANSACTION_EXECUTION_STRICT=1`, which the target sets, it also fails when the batched median exceeds the separate median or the batched p95 exceeds 1.25 times the separate p95 (`benchmarks/slate-v2/donor/core/current/transaction-execution.mjs:219-276`). The ledger row claims an improvement and says no accepted threshold exists (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:369`); the script now has one. Limit: no run result is pinned here.

## React runtime, identity and subscription model

- **One editor, several roots, and per-root history (#6016, #5515, multi-editor focus).** For #6016 (two Slate components with the same `initialValue` break the page), Plite's answer is one editor that hosts several root-bound `Editable` surfaces ('Plite editor hosts multiple root-bound Editable surfaces', `packages/plitejs/test/react/plite-runtime-provider-contract.test.tsx:672`). Sharing node objects across independent editors stays unsupported, and the ledger triage-closes the issue (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:216`). For #5515 (Undo/Redo All), `useEditorHistory` returns undo, redo, `canUndo`, `canRedo` and a keyboard handler for one root. That root is the current selection's root, else the last root it saw, or a fixed named root (`packages/plitejs/src/react/hooks/use-plite-history.ts:45-54`, `:81-90`, `:110`). The hook does not implement Undo/Redo All (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:219`, `:326`). Focus reports with several editors or outside controls stay unclaimed until targeted browser proof exists: #5537 (input after programmatic focus with several editors), #3893, #3634, #4961 and #5117 (placeholder height applied to the wrong editor), for which root-local DOM state is the proposed route (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:217-221`).

- **`useElementSelected` when the selected element removes itself (#6053).** The ledger claims a fix (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:365`): `useElementSelected()` does not throw when the selected rendered element removes itself, and `useElementSelected(path)` returns `false` once the watched path is removed ('unmounts cleanly when the selected rendered element removes itself' and 'returns false when an explicit watched path is removed', `packages/plitejs/test/react/use-element-selected.test.tsx:319`, `:354`). The row cites paths in the retired `plite-react` package.

- **Editor lifetime and the provider (#6013, #5605, #5709, #5568).** Plite seeds the document once, when the editor is created, and the React provider takes the created editor with no `initialValue` of its own: `EditorRoot`'s props hold none (`packages/plitejs/src/react/components/plite.tsx:171-191`), and `useEditor` documents that `initialValue` seeds the editor once (`packages/plitejs/src/react/hooks/use-editor.ts:20`). The ledger claims fixes for #6013 (omit `initialValue` for a pre-initialized editor) and #5605 (why `initialValue` is required on the provider) (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:375`, `:458`). Its #5709 fix row (the hook keeps the old editor after a new one is created) says hook consumers receive the replacement editor (`docs/plite-issues/gitcrawl-v2-sync-ledger.md:428`).
