# Slate: autocomplete and triggers

## Mentions example

- Legacy Slate ships no autocomplete code. Its mentions example keeps the query as document text: React state holds `target: Range`, `search` and `index`, recomputed in `onChange` (`ianstormtaylor/slate@945a484d:site/examples/ts/mentions.tsx:41-43`, `:106-130`), and selecting an option inserts an inline void mention. The menu opens when `^@(\w+)$` matches one word unit plus one character before a collapsed caret, so a bare `@` never opens it (#5844), and non-ASCII or hyphenated names stop matching (#4570). Escape only clears `target`, so the next change reopens the menu (inferred), and there is no blur handling. The example has no `isComposing` or 229 check, and Slate calls the user `onKeyDown` before its own composing gate (`ianstormtaylor/slate@945a484d:packages/slate-react/src/components/editable.tsx:1575-1578`), so Enter or Tab during IME can insert the mention (inferred). On Android, #5357 (Gboard duplicated a name after Enter-complete then space) was fixed by PR #5360, which moved the FEFF spacer after the mention; #5183 (selecting an inline void does not summon the keyboard) and #5680 (removing an inline element hides it) stay open. The editor is `role=textbox` and the example has no ARIA; #2572 asks for combobox ARIA on the contenteditable. Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/002-lexical-slate-draft.md:35-45`.

- In legacy Slate's mentions example, undo after a completion restores `@que` as selected text, and the list stays closed (inferred). `slate-history` merges `insert_text`, does not save `set_selection`, and starts a new batch at the completion's `remove_text`, whose `selectionBefore` is the expanded target (`ianstormtaylor/slate@945a484d:packages/slate-history/src/with-history.ts:69-163`). Keys reach the menu through `Editable onKeyDown`, which runs before Slate's defaults. Events from a native `<input>` under `contenteditable=false` never reach the editor's handlers, because `hasEditableTarget` fails (`ianstormtaylor/slate@945a484d:packages/slate-dom/src/plugin/dom-editor.ts:502-516`). Slate filtered composition events from nested inputs only in October 2025: before PR #5965, Chinese IME in an input inside a void inserted the text at the editor's previous caret (#5840; `editable.tsx:1277`, `:1338`, `:1350`, with copy and cut filters at `:1381` and `:1399`). Inputs inside voids have a regression history, all now closed: broken arrows and typing in Firefox (#1744), focus stolen from inputs in voids (#2504), and a Chrome 127 selection revert when a click made an input appear (#5791). Options use `onClick`, `onBlur` does not deselect, and the click handler re-selects the stored target. Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/002-lexical-slate-draft.md:46-50`, `:83-84`.
