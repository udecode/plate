## Typeahead menu

- Lexical's `LexicalTypeaheadMenuPlugin` keeps the query as ordinary document text. `getTextUpToAnchor` slices the anchor text node up to the caret (`facebook/lexical@dd5c41b1:packages/lexical-react/src/LexicalTypeaheadMenuPlugin.tsx:51-62`), and the only stored state is the React `resolution = {match, getRect}`. On select, `$splitNodeContainingQuery` splits the query out, and the app replaces it (mentions) or removes it (component picker, emoji). The update listener runs on every update with no tag filter, so selection moves, paste, undo and collaboration updates can open the menu (inferred). The trigger needs start of text, whitespace or `(` before it. Mentions and emoji use minLength 1; the slash picker uses minLength 0 and allows whitespace. Only a simple text node matches, so `TextNode` subclasses never do (`isSimpleText`, #6269 open). Escape only clears `resolution`, so the next matching update reopens the menu (inferred), and there is no blur handling. While composing, the listener returns early, so the menu neither closes nor refilters (`LexicalTypeaheadMenuPlugin.tsx:288-290`); this came from the Korean flicker in #7985, and 'Typeahead menu should not close during IME composition' tests it (`facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/e2e/Composition.spec.mjs:671`). Core `onKeyDown` dispatches no key command while composing and defers Safari's compositionend-before-keydown through `compositionPhase = 'ending-safari'` (`facebook/lexical@dd5c41b1:packages/lexical/src/LexicalEvents.ts:1549-1569`). The root keeps `role=textbox`, and the menu writes `aria-activedescendant` and `aria-controls` onto it; `aria-expanded` renders only when the app passes `role=combobox` (`facebook/lexical@dd5c41b1:packages/lexical-react/src/shared/LexicalContentEditableElement.tsx:69`, `:115-117`). The listbox and option ids, `typeahead-menu` and `typeahead-item-<i>`, are fixed, so they collide across editors (`facebook/lexical@dd5c41b1:packages/lexical-react/src/shared/LexicalMenu.tsx:314`, `:386-398`, `:723-724`). Android mention bugs concern the finished mention, not the query. Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/002-lexical-slate-draft.md:20-28`, read at dd5c41b1 on 2026-10-02.

- Lexical's typeahead has no guard against document transforms. Markdown shortcuts skip only collaboration, historic and composing updates and code (`facebook/lexical@dd5c41b1:packages/lexical-markdown/src/MarkdownShortcuts.ts:540-599`). The playground emoji transform rewrites `:)`, `:D`, `:(` and `<3` in any simple text node, so an emoji query that starts with `D` can become an emoji mid-query (inferred). Query characters merge with adjacent typing in history, and completion pushes a new entry. Undo then restores `@que` with a collapsed caret and reopens the menu (inferred). Peers see partial and abandoned queries, and a remote edit before the caret recomputes the match (inferred). The playground forces emoji minLength 1 because a menu opened by a bare `:` would take Enter before rich text and steal paragraph breaks, which was flaky under collaboration (`facebook/lexical@dd5c41b1:packages/lexical-playground/src/plugins/EmojiPickerPlugin/index.tsx:77-82`). Menu keys are editor commands at `COMMAND_PRIORITY_LOW`, against rich text's Enter at priority 0, so any higher-priority plugin wins. Tables took the arrow keys until #5819 and PR #5820 made `lexical-table` yield when the root's `aria-controls` is `typeahead-menu` (`facebook/lexical@dd5c41b1:packages/lexical-table/src/LexicalTableSelectionHelpers.ts:2499-2510`). Options use `onClick` with no mousedown `preventDefault`. Lexical keeps the range selection in state and refocuses the root after the update (`facebook/lexical@dd5c41b1:packages/lexical/src/LexicalSelection.ts:3901-3914`). Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/002-lexical-slate-draft.md:29-33`.

- A dead branch in Lexical's typeahead positioning: `tryToPositionRange` returns a boolean (`facebook/lexical@dd5c41b1:packages/lexical-react/src/LexicalTypeaheadMenuPlugin.tsx:64-80`), but its caller checks `isRangePositioned !== null` (`:315-321`), which is always true. When positioning fails, the menu still opens instead of closing. Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/002-lexical-slate-draft.md:89-93`; checked at dd5c41b1 on 2026-10-08. The same lines' fixed ids and `isSimpleText` gate are in this page's typeahead bullet.
