# Lexical: drag and drop

## Native drag and draggable blocks

- Lexical has native text drag and a native React draggable-block plugin whose handle writes the block key under its own drag format (`facebook/lexical@dd5c41b1:packages/lexical-react/src/LexicalDraggableBlockPlugin.tsx:531-546`). Dropped files go through the separate `DRAG_DROP_PASTE` command (`facebook/lexical@dd5c41b1:packages/lexical-rich-text/src/index.ts:148-149`), and `@lexical/clipboard` writes a drag-source marker so that a drag ending in another editor can cut and paste (`facebook/lexical@dd5c41b1:packages/lexical-clipboard/src/clipboard.ts:168-190`). Its four draggable-block end-to-end tests skip collaboration, plain text and Firefox (`facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/e2e/DraggableBlock.spec.mjs:27-29`, `:76-78`, `:118-120`, `:160-162`). In `TextDragDrop.spec.mjs` four tests dispatch synthetic drag events, and the one test that composes a real browser drag, a drop of text from a non-Lexical source, runs only in Chromium and skips collaboration (`facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/e2e/TextDragDrop.spec.mjs:195-208`). - **Lexical's block plugin reorders root children only.** `DraggableBlockPlugin_EXPERIMENTAL` inserts the dragged node before or after the nearest root child by pointer Y, with no schema or node policy, so a drop over a quote, list item or table cell lands beside the whole top-level node (`facebook/lexical@dd5c41b13193:packages/lexical-react/src/LexicalDraggableBlockPlugin.tsx:390-436`). Every root child (a whole list, table or quote) is draggable. Core has no per-node draggable flag. The playground's images use their own drag handling, and its `TableHoverActionsV2` column reorder through Pragmatic Drag and Drop keeps columns in their table by requiring the same `tableKey` (`facebook/lexical@dd5c41b13193:packages/lexical-playground/src/plugins/TableHoverActionsV2Plugin/index.tsx:173-179`); that rule exists only in the playground, not the package. Hover is unthrottled: it copies the root keys (O(n)), then walks from the last hit with one rect read and three `getComputedStyle` calls per step.
