# Lexical: input and IME

## Composition ownership

- Lexical models composition ownership explicitly: `$setCompositionKey()` stores the active composition node key and marks the old and new composition nodes writable when ownership changes; dirty-node transforms skip the active composition node; a composition-key change forces a synchronous flush; and text-node split and merge transfer composition ownership when the composing node moves. The inspected slices have no explicit tests for edits that overlap a composition. Source and historical source slices: `docs/plite/research/2026-06-12-ime-overlap-policy/sources/lexical-summary.md:1-15`. Limit: unpinned local checkout read on 2026-06-12.

## Beforeinput handling

- Lexical's `beforeinput` handler reads only the first target range (`getTargetRange`, `facebook/lexical@dd5c41b1:packages/lexical/src/LexicalEvents.ts:636-646`). When two `beforeinput` events arrive in one event loop, as macOS autocorrect plus autocapitalization causes, it first updates its state from the DOM text, then applies the target range to a collapsed selection before inserting (`:986-1009`). For the iOS 10-key Korean keyboard, which fires no composition events and deletes the composing jamo with a non-collapsed `deleteContentBackward` target range, it applies that range and removes the text instead of deleting one character (`:909-935`). Native `historyUndo` and `historyRedo` dispatch `UNDO_COMMAND` and `REDO_COMMAND` (`:1182-1190`). Source: `docs/plite/research/2026-06-14-selection-paste-undo-oracles/read-log.tsv:8-9`; reread at the pinned commit on 2026-10-08, later than the run's read, so the line numbers differ from the run's.

## Composition tests

- Lexical's composition tests (`facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/e2e/Composition.spec.mjs`) drive composition through Chrome DevTools Protocol `Input.imeSetComposition`, so each one skips every browser but Chromium. 'Can type Hiragana via IME' (`:183`) commits `すし もじあ` and asserts the HTML and the caret after it. 'Can type Hiragana via IME into a new bold format' (`:250`) toggles bold after `Hello` and expects the composed text in a bold node with the caret inside it. 'Can type Hiragana via IME between emojis' (`:291`) composes between two emoji text nodes, backspaces the result away, then cancels a composition, and checks the HTML and caret after each step. 'Can type Hiragana via IME at the end of a mention' (`:377`) composes after a completed mention and keeps the mention node intact. 'Can type, delete and cancel Hiragana via IME' (`:555`) cancels compositions in an empty paragraph and after a typed space and leaves no composed text. In `History.spec.mjs`, 'Cancel composition not push undo stack' (`:742`) types `a`, composes and cancels `ｓ`, and one undo empties the editor, so a canceled composition records no undo entry. Regression #8153 (`facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/regression/8153-safari-ime-delete-selection.spec.mjs:39`) runs only on WebKit: it dispatches a synthetic `compositionend`, as Safari fires it before keydown, and then select-all and Backspace must empty a two-paragraph document. Source: `docs/editor-test-harvester/lexical/report.md:166-172`; the report's line numbers predate dd5c41b1, where the bodies were read on 2026-10-08. Limit: CDP composition drives Chromium's IME API, not an OS input method.

## Native input transport tests

- Lexical tests native input transport directly. Regression #7163 (`facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/regression/7163-graphemes.spec.mjs:21`) inserts one grapheme per case and presses Backspace until it is gone. One press removes a ZWJ emoji sequence, a skin-tone, flag or keycap emoji, or a surrogate-pair character. Hangul jamo, Tamil, Devanagari and Arabic combining sequences and a decomposed Latin `n` with tilde take one press per code point, so Lexical deletes those one code point at a time, not as whole grapheme clusters. `facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/e2e/Extensions.spec.mjs:25` imports `document.execCommand('insertText')` into editor state with the caret after it, and `:47` imports a synthetic `ClipboardEvent('paste')` and returns early on Firefox, which blocks synthetic paste data. `facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/e2e/Mutations.spec.mjs:53` rewrites a text node's value from outside and checks that editor state and selection follow it. It first waits 100 ms, because a DOM text mutation within `TEXT_MUTATION_VARIANCE` of typing is not synced to editor state. Source: `docs/editor-test-harvester/lexical/report.md:174-177`; bodies read at dd5c41b1 on 2026-10-08.

## beforeinput target ranges

- Lexical reads `beforeinput` target ranges as event data, separate from the live DOM selection. It enables its beforeinput path only when `InputEvent` has `getTargetRanges` (`facebook/lexical@dd5c41b1:packages/lexical/src/environment.ts:36-40`). `getTargetRange` returns the first range, or null when the API is missing or the list is empty (`facebook/lexical@dd5c41b1:packages/lexical/src/LexicalEvents.ts:637-646`). Before inserting text, it applies a non-null target range through `applyDOMRange` to a collapsed range selection that is not on the root, when the selection is clean or beforeinput data is still unprocessed (`LexicalEvents.ts:1001-1009`); `applyDOMRange` resolves the StaticRange endpoints into Lexical points (`facebook/lexical@dd5c41b1:packages/lexical/src/LexicalSelection.ts:787`). In `$shouldPreventDefaultAndInsertText`, an expanded target range, or one that does not start at the DOM selection's anchor, is one reason to cancel the native insertion and insert the text through the model (`LexicalEvents.ts:231-303`, `:290-296`). Source: `docs/plite/research/2026-06-13-beforeinput-target-range-selection-policy/read-log.tsv:5-9`, read 2026-06-13 at older line numbers, when the feature gate sat in `shared/src/environment.ts`, and rechecked at dd5c41b1 on 2026-10-08.

## Composition

- Lexical leaves `insertCompositionText` `beforeinput` to the browser (`facebook/lexical@dd5c41b1:packages/lexical/src/LexicalEvents.ts:829-830`) and orders composition end per browser: Firefox fires `compositionend` before `input`, so Lexical finishes the composition in the next `input` and adds the same end tag Chrome gets (`:1549`, `:1344-1352`); desktop Safari fires it before `keydown`, so Lexical defers it to that keydown (`:1551-1554`); Chrome and other WebKit-free paths dispatch it at once. Composition-key ownership is under 'Composition ownership' on this page. Read 2026-10-08; the June run read an older unpinned checkout (`docs/plite/research/2026-06-13-ime-composition-policy-scout/read-log.tsv:6-8`).

## Native input timing

- Lexical handles native `input` by stopping propagation and running `updateEditorSync` at once (`facebook/lexical@dd5c41b1:packages/lexical/src/LexicalEvents.ts:1199-1216`); it commits dirty updates synchronously when asked and otherwise in a microtask (`facebook/lexical@dd5c41b1:packages/lexical/src/LexicalUpdates.ts:1254-1262`, `scheduleMicroTask` with `queueMicrotask` or a Promise fallback at `facebook/lexical@dd5c41b1:packages/lexical/src/LexicalUtils.ts:187-190`), and its FAQ describes reconciliation as microtask batching (`facebook/lexical@dd5c41b1:packages/lexical-website/docs/faq.md:43`). `beforeinput` dispatches commands synchronously except for composition and a Firefox clipboard case (`LexicalEvents.ts:826-830`), and its 20 ms timeout is an Android composition cleanup that removes an emptied node (`LexicalUtils.ts:945-958`). When `beforeinput` exists, plain-text and rich-text Enter do not block the browser default on iOS, Safari and WebKit (`facebook/lexical@dd5c41b1:packages/lexical-plain-text/src/index.ts:350-355`, `facebook/lexical@dd5c41b1:packages/lexical-rich-text/src/index.ts:1612`). Read 2026-10-08; the June run read these unpinned.

## Input ownership

- **When Lexical takes over text input.** `$shouldPreventDefaultAndInsertText` decides whether Lexical prevents the browser's text insertion and inserts the text itself (`facebook/lexical@dd5c41b1:packages/lexical/src/LexicalEvents.ts:231-305`). It takes over when the selection spans nodes or sits outside a text node, when the anchor is a token or segmented text node, when a dirty node receives more than one character, when the DOM selection's text node differs from the anchor's backing DOM node or the `beforeinput` target range differs from the DOM selection, and when the selection's format or style differs from the anchor node's; several of these tests are skipped while the anchor node is composing. Read 2026-10-08; the June run read it unpinned at `:214-266`.
