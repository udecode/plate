# Lexical: testing and proof

## Platform-gated tests

- **Platform gates sit inside the test bodies.** `Tab.spec.mjs`'s 'can tab + IME' opens a Chrome DevTools Protocol session and sends `Input.imeSetComposition`, so it runs only in Chromium (`facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/e2e/Tab.spec.mjs:23-49`). It combines a paragraph Tab, which inserts a TabNode, with CDP composition. Its sibling 'can go to start of line after a tab character' (`:116`) checks that Ctrl/Meta+ArrowLeft after a typed Tab returns to the line start. Mac-only rows return early on other platforms, as #399 does with `if (!IS_MAC)` (`facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/regression/399-open-line.spec.mjs:27`), so on Linux CI they pass without running. Source: `c70bacbd4a:docs/editor-test-harvester/lexical/plite-processing-ledger.md:931-934`. Limit: CDP composition drives Chromium's IME API, not an OS input method.

## Recorder and selection fixtures

- Lexical's playground `TestRecorderPlugin` records click, press, keydown, keyup, type, select-all and snapshot steps and prints them as Playwright code, a snapshot becoming `assertHTMLSnapshot` plus `assertSelection` with anchor and focus paths and offsets (`facebook/lexical@dd5c41b1:packages/lexical-playground/src/plugins/TestRecorderPlugin/index.tsx:62-95`). It has no shrinking or reduction step. Source: `docs/plite/research/2026-06-14-generated-stress-replay-reduction/read-log.tsv:8`; the file was reread at the pinned commit on 2026-10-08, later than the run's 2026-06-14 read.

- The `lexical-selection` package's unit tests run input sequences, such as typing, `deleteWordBackward`, undo and redo, and assert the exact editor HTML and the DOM selection paths and offsets (`facebook/lexical@dd5c41b1:packages/lexical-selection/src/__tests__/unit/LexicalSelection.test.tsx:392-410`, `:1205-1240`). Its block-selection suite reruns every node insertion, removal and replacement case with anchor and focus swapped and expects the swapped result, which catches anchor and focus drift (`:1367-1971`). Source: `docs/plite/research/2026-06-14-selection-paste-undo-oracles/read-log.tsv:11-12`; reread at the pinned commit on 2026-10-08.

## Reusing Lexical tests

- Lexical is MIT-licensed (`facebook/lexical@dd5c41b1:LICENSE:1`). A port re-expresses a Lexical test's behavior in Plate's own tests, and any copied Lexical source keeps the MIT notice. The July 2026 harvest copied no Lexical runtime or test code. Source: `docs/editor-test-harvester/lexical/report.md:58-65`.

- Lexical's plugin and product test families port to Plate packages, not to raw Plite. These are: link and autolink (`lexical-link/*`, `AutoLinks.spec.mjs`); lists and checklists (`lexical-list/*`, `List.spec.mjs`); markdown transformers (`LexicalMarkdown.test.ts`, `MarkdownTransformers.test.ts`, `Markdown.spec.mjs`); mention, hashtag, keyword, date-time, emoji, equation, character-limit and media plugins; clear formatting, toolbar state and styling; and React Composer, menu, typeahead and plugin-host rows. Plite keeps only the editor invariant inside each family: inline boundaries, paste, safe link insertion, list fragments and ancestry, raw markdown-shortcut behavior, and inline atoms and voids. Source: `docs/editor-test-harvester/lexical/report.md:128-139`, at `facebook/lexical@dd5c41b13193efa9ab1574234d8593d2c9e4f988`.

- Lexical's strongest testing habit is issue-shaped browser coverage: one regression file per real browser failure, run through real browser transport, such as `facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/regression/8153-safari-ime-delete-selection.spec.mjs`. Worth taking: browser-first regression rows for IME, paste, table selection and DOM repair; an external paste corpus grouped by source app (Google Docs, Word, Sheets, image HTML, nested lists); explicit per-engine rows where Firefox or Safari event order matters; mobile and table rows that refuse viewport emulation as device proof; and undo-granularity rows around composition, paste and collaboration. Not worth taking: Lexical's private clipboard MIME format as a public requirement, React Composer and plugin-identity tests, node-class lifecycle and command-registry mechanics, playground product chrome, and ESLint, release and ESM-fixture tests. The harvest read one negative control per rejected family: `facebook/lexical@dd5c41b1:packages/lexical-react/src/__tests__/unit/LexicalComposer.test.tsx` checks React context and editor identity, `facebook/lexical@dd5c41b1:packages/lexical-eslint-plugin/src/__tests__/unit/rules-of-lexical.test.ts` checks lint-rule examples, `facebook/lexical@dd5c41b1:packages/lexical-utils/src/__tests__/unit/LexicalUtilsKlassEqual.test.ts` checks the `objectKlassEquals` helper, and the Next.js ESM fixture test `facebook/lexical@d52f66e2:scripts/__tests__/integration/fixtures/lexical-esm-nextjs/tests/test.ts` checks only example-app wiring. That fixture was deleted before dd5c41b1, where `lexical-esm-astro-react` is the remaining ESM fixture. Source: `docs/editor-test-harvester/lexical/report.md:141-160`, `:195-204`.

## Browser test helpers

- Lexical's playground e2e helpers check native selection. `assertSelection` reads `window.getSelection()` and compares anchor and focus as child-index paths from the contenteditable root plus offsets, normalizing WebKit's image-plus-line-break offset (`facebook/lexical@dd5c41b13193efa9ab1574234d8593d2c9e4f988:packages/lexical-playground/__tests__/utils/index.mjs:532-599`). `dragMouse` (`:1132-1173`) drags between two bounding boxes with one mouse move, or ten moves when `slow` is set, so drag tests control the move count. Source: `docs/plite/research/2026-06-12-browser-longtask-selection-oracles/read-log.tsv:8-9`.

- Lexical's e2e clipboard helpers are mostly synthetic (`facebook/lexical@dd5c41b1:packages/lexical-playground/__tests__/utils/index.mjs`). `copyToClipboard` dispatches a synthetic `copy` event whose `clipboardData.setData` records into a plain object and returns that object, so the system clipboard is not touched (`:652-690`). `pasteFromClipboard(page, data)` dispatches a synthetic `paste` event carrying a fake `clipboardData` with `getData`, `types` and `files`, turning `playwright/base64` entries into `File` objects, and, when nothing prevented that event, a synthetic `beforeinput` of type `insertFromPaste` with the same data. Only a call without data presses the real Ctrl or Meta+V (`:695-812`). `withExclusiveClipboardAccess` serializes clipboard tests with a `proper-lockfile` lock on `.playwright-clipboard.lock`, retried five times (`:403-413`). Source: `docs/plite/research/2026-06-13-playwright-editor-e2e-timing-oracles/read-log.tsv:3-5`, `README.md:56-59`; the June read's line numbers predate dd5c41b1, where the helpers were read on 2026-10-08.

- Lexical's `assertHTML` prettifies both the expected HTML and the first contenteditable's `innerHTML` with optional `ignoreClasses`, `ignoreInlineStyles` and `ignoreDir`, strips playground-only markup (sticky-scrollbar and drop-target attributes, a Safari line-break image hack) and retries through `expect(...).toPass` at 100, 250 and 500 ms intervals for up to 5 s (`facebook/lexical@dd5c41b13193efa9ab1574234d8593d2c9e4f988:packages/lexical-playground/__tests__/utils/index.mjs:356-398`, entry at `:418`). `assertSelection` accepts each offset as an exact number or a `[min, max]` range (`:583-596`). `initialize` (`:84`) sets up the page, collab mode and many playground feature flags through one options object, and `createHumanReadableSelection` (`:1553`) lets a test label each path step and offset in prose. Source: `c70bacbd4a:docs/plite-browser/four-way-api-deep-dive.md:44-121` (2026-04-04); helpers re-read at dd5c41b1 on 2026-10-08.
