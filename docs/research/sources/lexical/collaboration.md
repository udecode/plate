## Remote cursors

- **Remote cursors render outside the editor's text DOM.** Lexical's `useYjsCursors` portals an empty `<div>` into the app's `cursorsContainerRef` element, or `document.body` when none is given, and stores it as `binding.cursorsContainer` (`facebook/lexical@dd5c41b13193efa9ab1574234d8593d2c9e4f988:packages/lexical-react/src/shared/useYjsCollaboration.tsx:495-511`). `SyncCursors` positions each remote caret against that container's offset parent and appends and removes it there, never inside the content-editable tree; by default each remote selection is drawn the same way, as absolutely positioned rectangles in the container (`facebook/lexical@dd5c41b13193efa9ab1574234d8593d2c9e4f988:packages/lexical-yjs/src/SyncCursors.ts:296-311`, `:423-437`, `:517-561`). With the opt-in `selectionHighlight` prop, which defaults to false, and a browser that supports CSS Custom Highlights, the remote selection is instead a `Highlight` over the DOM range styled by a `::highlight(lexical-cursor-<binding>-<client>)` rule, and only the caret stays in the container (`SyncCursors.ts:380-391`, `:466-515`, same commit). The April 2026 Plite decorations cluster cited the container as the reason cursor UI stays out of the text-leaf lane (`c70bacbd4a:docs/plite-draft/decorations-annotations-cluster.md:306-336`). Limit: read on 2026-10-08 at that commit; no Lexical test was run.
