# Editor architecture: rendering and DOM

## Canvas rendering

- **html-in-canvas is a hybrid DOM-to-canvas primitive, not a DOM replacement.** The WICG proposal, implemented behind the Chromium flag `chrome://flags/#canvas-draw-element`, lays out the children of a `<canvas layoutsubtree>` for hit testing, draws one with `drawElementImage()` (or `texElementImage2D` and `copyElementImageToTexture` for WebGL and WebGPU), and returns the CSS transform the page must apply so the element's DOM location matches its drawn location for hit testing, intersection observers and accessibility (`WICG/html-in-canvas@e15927dd:README.md:9`, `:28-31`, `:41-42`, `:54`, `:70`). It therefore still depends on DOM layout, DOM hit testing and transform sync. The html-in-canvas-room demo draws a whole page as a WebGL texture on a 3D screen and forwards native clicks and scrolling through a `matrix3d` transform on the wrapper (`SawyerHood/html-in-canvas-room@4aadf7b6:README.md`, 'How it works'); it shows projected surfaces work but says nothing about editor-grade IME, caret or history correctness. A 2026-04-09 Plite brainstorm therefore placed any canvas runtime downstream of committed snapshots, for read-only, paged, offscreen or projected surfaces, with selection, caret, composition and accessibility focus kept on the DOM (`c70bacbd4a:docs/brainstorms/plite-canvas.md:89-118`, `:194-266`). Limit: no spike ran; the brainstorm cited unpinned local clones, and these pins are the local clones read on 2026-10-08, whose last commits (2026-04-08 and 2026-04-09) predate or match the brainstorm.

## Bounded text rendering

The September 2026 source comparison distinguished bounded render-only text tiles from model splitting and viewport virtualization. CodeMirror View 6.41.0 at `codemirror/view@fbff59ba004d80d8c914f64c42586387b08706ac:src/buildtile.ts:19,53-64,543-556` uses a 512-character Chunk and maps positions through tile-local DOM offsets (`src/tile.ts:301-343,383-425`, `src/docview.ts:300-324`). Slate at `ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-react/src/components/text.tsx:43-65` and `ianstormtaylor/slate:packages/slate-dom/src/plugin/dom-editor.ts:576-635` offers partial prior art: decorations split one logical Text into rendered strings, and DOM mapping accumulates their lengths, without fixed-size splitting of undecorated text. The comparison classified ProseMirror's undecorated TextViewDesc as one DOM Text and Wordgard/Lexical code blocks as model segmentation. Source: `docs/plans/2026-09-02-wordgard-huge-code-block-benchmark.md:308-324,365-369`. Only the CodeMirror and Slate source identities are pinned here; these source classifications are not a cross-editor native-behavior certificate.
