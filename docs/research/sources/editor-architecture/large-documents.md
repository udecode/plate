# Editor architecture: large documents

## CodeMirror viewport and selection

- CodeMirror's view package makes the drawn viewport and `visibleRanges` public (`src/editorview.ts:90-103`). When a selection endpoint falls outside the main viewport it draws an extra one-line viewport so the DOM selection never lands in a gap (`src/viewstate.ts:157-204`). It computes the viewport from a measured height map that includes scroll targets (`src/viewstate.ts:393-416`), scales very large document heights around the active viewports (`src/viewstate.ts:693-736`), keeps a scroll anchor through its measure loop and corrects the offset after height changes (`src/editorview.ts:413-496`), and documents coordinate lookup as precise only where DOM exists and estimated elsewhere (`src/editorview.ts:741-765`). Plite took the contract shape, not the code: CodeMirror is a line-block text editor, while Plite needs rich-block DOM coverage and model-owned selection. Source: `docs/plite/research/2026-06-12-huge-doc-architecture/README.md:27-34`, `:1156-1170`, `:1196-1198`. Limit: line numbers come from an unpinned local `codemirror/view` checkout read on 2026-06-12.

- More CodeMirror view mechanics (unpinned local checkout read on 2026-06-13): measurement reads geometry, the visible pixel viewport, line heights and scroll state and recomputes the viewport when geometry or heights change (`src/viewstate.ts:267-372`); the measure loop restarts until the layout is coherent, caps restarts, and runs measure requests only once the viewport is stable (`src/editorview.ts:421-483`); `requestMeasure` schedules a requestAnimationFrame read-then-write request deduplicated by key (`src/editorview.ts:577-590`); long-line gap and visible-range logic never hides the selection endpoints and treats viewport movement apart from mapped changes (`src/viewstate.ts:446-579`); the drawn selection layer redraws on document, selection, viewport or config changes (`src/draw-selection.ts:102-122`) and clips rectangles to the viewport and visible ranges with bidi-aware spans (`src/layer.ts:102-171`). Its tests assert endpoint coordinates inside the scroll box after scrolling a range into view, viewport DOM text equal to the document slice after random changes, visible ranges smaller than the viewport on long wrapped lines, and plugins observing viewport changes (`test/webtest-draw.ts:120-137`, `:155-161`, `:287-296`, `test/webtest-extension.ts:7-31`). The public reference describes `drawSelection` as hiding the native selection and cursor (https://codemirror.net/docs/ref/), and a focused widget needs a native-selection exception under it. Source: `docs/plite/research/2026-06-13-oss-viewport-selection-proof/read-log.tsv:2-19`.
