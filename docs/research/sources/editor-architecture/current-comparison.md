# Editor architecture: current comparison evidence

## Result and coverage

- **Use a comparison set for each question.** The October 13 research found useful additions in Wordgard, ProseKit, current Lexical Extensions, BlockSuite, Blok, Portable Text, Meowdown, MDXEditor, Milkdown, OpenDoc, canvas-editor, Lexxy and Proof SDK. Their value differs by owner and behavior. The [candidate selector](candidates.md) maps those jobs. The [research run](../../../plite/research/2026-10-13-editor-comparison/README.md), [repository registry](../../../plite/research/2026-10-13-editor-comparison/repo-registry.tsv), [source reads](../../../plite/research/2026-10-13-editor-comparison/read-log.tsv) and [corpus ledger](../../../plite/research/2026-10-13-editor-comparison/corpus-ledger.tsv) bound the result.

- **Breadth is distinct from source depth.** The combined registry contains 274 discovered source-host identities. Eighty-two received a targeted metadata screen. Forty-one have recorded local source reads, including six with only documentation or manifest reads. Thirty-five have implementation or test reads. The 161 distinct recorded files include implementation, tests, configuration, manifests and source documentation. GitHub mirrors and canonical ProseMirror components are separate identities. Renamed edix is normalized to editate. Counts derive from the run's TSVs and [count record](../../../plite/research/2026-10-13-editor-comparison/counts.json).

- **This is discovery and compilation, not executed comparison.** Four issue bodies and three PR bodies were read, without comments. Twenty-seven invariant findings were compiled as documentation packets. No upstream test, performance comparison, browser interaction or native-device scenario ran. The registry retains discovery-only projects instead of silently treating them as rejected implementations.

## Engines and framework composition

- **Wordgard broadens independent engine evidence.** Wordgard represents changes as sections that preserve, mark or replace content. Its collaboration owner composes pending changes, maps effects and integrates updates from an authority. Its composition tests also assert DOM ancestry and native selection identity, although their input events are synthesized. Study the change and proof contracts. Do not infer a better replacement for Plite from source size or recency. Evidence: `obsidianmd/wordgard@51f2fff9a2fa6633ecfbae6e3f972feb790d854f:src/doc/change.ts:113-155`, `obsidianmd/wordgard@51f2fff9a2fa6633ecfbae6e3f972feb790d854f:src/collab/collab.ts:11-20,23-37,122-160` and `obsidianmd/wordgard@51f2fff9a2fa6633ecfbae6e3f972feb790d854f:test/webtest-composition.ts:29-92`. The GitHub repository is a mirror of the canonical Wordgard project.

- **Lexical now supplies a framework-independent extension comparison.** Its builder checks descriptor identity, adds dependency edges and provides once-only disposal. Its current extension types and tests cover configuration and capabilities beyond the older React plugin scheme. This is useful pressure on Plate and Plite's existing installation owners. It does not justify importing Lexical's node classes or another dependency framework. Evidence: `facebook/lexical@80b6fb25c40378f010a3bde70bf2be104aaae4ba:packages/lexical-extension/src/LexicalBuilder.ts:210-243,283-425` and `facebook/lexical@80b6fb25c40378f010a3bde70bf2be104aaae4ba:packages/lexical/src/__tests__/unit/LexicalExtensionCore.test.ts:20-69`. The [official Extensions introduction](https://lexical.dev/docs/extensions/intro) describes the framework-independent direction.

- **ProseKit supplies typed grouping evidence separately from its inherited engine.** Its union constructor and tests preserve node, mark and command capabilities through nested groups. Compare that authoring contract with Plate's type inference. ProseKit's ProseMirror state, transforms and DOM behavior are not independent engine confirmation. Evidence: `prosekit/prosekit@46963df47bddb13f9dd2aa896c6255e55fdb0e87:packages/core/src/editor/union.ts:34-39` and `prosekit/prosekit@46963df47bddb13f9dd2aa896c6255e55fdb0e87:packages/core/src/editor/union.spec.ts:1-104`.

- **Mature independent engines remain useful.** CKEditor 5 separates model changes from editing conversion. TinyMCE supplies exception-safe nested history grouping. RoosterJS formats through its content-model owner and preserves unfocused selection behavior. Quill maps local undo intent through remote edits. Slate supplies a relevant inherited baseline. Tiptap supplies command applicability and dispatch evidence at the framework layer. These findings and their exact source/test pairs are in the [engine shard](../../../plite/research/2026-10-13-editor-comparison/shards/001-engines-and-frameworks.md) and [lead ledger](../../../plite/research/2026-10-13-editor-comparison/lead-ledger.tsv).

## Shared blocks, schema and document identity

- **BlockSuite and Blok add distinct CRDT ownership evidence.** BlockSuite puts shared block state in its store and filters undo by local client origin. Blok, an Editor.js fork, separates block identity from placement and tests concurrent content preservation. Blok also has custom structural undo handling. A CRDT dependency does not make every structural operation or undo rule automatic. AFFiNE is BlockSuite's application context, not another engine. Evidence: `toeverything/blocksuite@5cb5cb68471ca692f3c162258f0087cb22fcb82d:packages/framework/store/src/model/block/block-model.ts:1-155` and `toeverything/blocksuite@5cb5cb68471ca692f3c162258f0087cb22fcb82d:packages/framework/store/src/extension/history/history-extension.ts:19-24`; `JackUait/blok@3300748a3a89e8531d722aedbdd98df3b59b429d:src/components/modules/yjs/document-store.ts:1-180`. Blok's convergence and undo test anchors are recorded in the lead ledger.

- **BlockNote remains an active block-framework reference.** Its default branch had October 13 activity and v0.55.0 shipped September 22. Its exported block JSON is a projection of ProseMirror nodes. Its schema-admission tests retain shared text while materializing only allowed formatting and exercise follow-up typing. Keep those contracts without counting BlockNote as a new text engine. Evidence: the official metadata and release entrypoints recorded in the registry; `TypeCellOS/BlockNote@ce806b17f1d899d2766df2d1b9a58ef624aee65e:packages/core/src/api/nodeConversions/nodeToBlock.ts:1-210` and `TypeCellOS/BlockNote@ce806b17f1d899d2766df2d1b9a58ef624aee65e:packages/core/src/yjs/extensions/FixUpSchema.test.ts:203-295`.

- **Portable Text contributes schema and behavior evidence.** The current package contains an in-tree editing engine, schema packages and behavior specifications. Its annotation guard explicitly resolves the same effective selection as the removal it raises, preventing disagreement in a recursive remove/re-add path. The two-editor annotation scenario checks the distinction between retained marks and newly inserted unmarked text. Keep the specification and oracle discipline without adopting its public behavior DSL or stored format. Evidence: `portabletext/editor@dd533ff1ffc3d5e975b57da1985ae2ed14f0626e:packages/editor/package.json:92-103`, `portabletext/editor@dd533ff1ffc3d5e975b57da1985ae2ed14f0626e:packages/editor/src/engine/create-editor.ts:1-46`, `portabletext/editor@dd533ff1ffc3d5e975b57da1985ae2ed14f0626e:packages/editor/src/behaviors/behavior.core.annotations.ts:68-111` and `portabletext/editor@dd533ff1ffc3d5e975b57da1985ae2ed14f0626e:packages/editor/gherkin-spec/annotations-collaboration.feature:1-19`.

- **Applications and bindings add narrower evidence.** AppFlowy Editor contributes Flutter node identity and transaction selection contracts. SiYuan contributes stale-root cancellation and materialization progress checks. Yoopta contributes Slate block bindings and origin-filtered undo. Editor.js contributes tool save/validation contracts. Loro's ProseMirror binding contributes local echo, initialization and stable-cursor history scenarios. These do not establish browser-native behavior or live-provider success. Exact reads and limitations are in the [document shard](../../../plite/research/2026-10-13-editor-comparison/shards/002-blocks-and-documents.md).

## Markdown, input and focus

- **Meowdown contributes hidden-syntax caret contracts.** Its tests distinguish content edges from outer syntax edges, constrain keyboard and pointer selection, and check subsequent typing affinity. This is useful evidence for Plite's selection and DOM owners and Plate's Markdown policy. Its configured browser contexts use a 900 by 600 viewport and touch emulation. Those tests do not establish iOS or native IME correctness. Evidence: `prosekit/meowdown@55940d37847e12f8c1a8b83a2d468436fc9b6e55:packages/core/src/extensions/hidden-run-caret.ts:1-145`, `prosekit/meowdown@55940d37847e12f8c1a8b83a2d468436fc9b6e55:packages/core/src/extensions/hidden-run-caret.test.tsx:1-489` and `prosekit/meowdown@55940d37847e12f8c1a8b83a2d468436fc9b6e55:packages/vitest/src/config.ts:39-78`.

- **MDXEditor, Vditor and Milkdown answer different Markdown questions.** MDXEditor and Vditor contribute selected-fragment export contracts. Milkdown contributes lazy nested code-editor mounting, serialization while unmounted, focus retention and follow-up typing. MDXEditor's inspected drag helper resets DOM selection after the gesture, so its export checks do not prove native drag geometry. Vditor's Android user-agent tests and rich-textarea's Chromium CDP composition tests retain those narrower scopes. Evidence and exact tests are in the [Markdown shard](../../../plite/research/2026-10-13-editor-comparison/shards/003-markdown-input-and-layout.md) and read log.

- **Lexxy contributes focus-preserving prompts.** Filtering keeps focus on the editor and updates the ARIA active descendant instead of focusing an option after each keystroke. Its extension wrapper also has explicit disposal. This is product evidence over Lexical. It is not a new engine or proof of a real Android keyboard. Evidence: `basecamp/lexxy@b384704c1c334509c07d3eb66ae6aa2e65742e3d:test/browser/tests/prompts/filter_keeps_editor_focused.test.js:10-47` and `basecamp/lexxy@b384704c1c334509c07d3eb66ae6aa2e65742e3d:src/editor/extensions.js:24-27`.

## Layout, DOCX and agent integration

- **OpenDoc and public SuperDoc code add layout oracles.** OpenDoc compares windowed output with full pages and explicitly refuses unsupported document shapes. Bounded paint or retained memory does not establish bounded traversal. SuperDoc's public painter contributes page-root, hydration and stale-generation checks. Its current v2 package depends on proprietary DOCX Engine, so the complete current model and collaboration engine are an explicit source gap. Evidence: `CasualOffice/opendoc@e81336419d1e7cea0043ead7a1ca0d8fd8fc1636:crates/casual-doc-layout/src/windowed.rs`; `superdoc/docx-editor@e3f0db31de195f4e2363a0f193c1f669c88c8cd2:packages/superdoc/package.json` and `CasualOffice/opendoc@e81336419d1e7cea0043ead7a1ca0d8fd8fc1636:apps/docs/content/docs/resources/docx-engine-license.mdx:13-21`. Public painter test paths are in the lead ledger. This records the declared package boundary, not legal reuse advice.

- **Pretext remains measurement evidence, while Premirror needs a freshness qualification.** Current Pretext separates preparation from repeated layout and tests retained-handle and cursor behavior. Premirror's inspected adapter uses the older argument order and contains proportional or fixed-width fallbacks. Its local stub is TypeScript-only. This source mismatch against current Pretext was not reproduced as an integration failure. Remove the old claim that Premirror is the leading proven pagination path. Evidence: `samwillis/premirror@29b78634d6496206c84015068eb7d66d9cdc312c:packages/composer/src/index.ts:26-42,85-111` and the current Pretext source/test pins in the Markdown shard.

- **Canvas editors expose input costs instead of eliminating them.** Canvas-editor has explicit composition commit/cancel handling and undo tests. The newer ProseMirror/Pretext adapter has composition-preview test ideas, but its inspected tests use happy-dom and mocked widths. These sources justify a rendering/input comparison for a concrete custom-renderer job. They do not establish accessibility, native IME or performance superiority. Evidence: `Hufe921/canvas-editor@e8d0be8f4c7d23ef1056a35b0891a3bc1083db82:src/editor/core/event/handlers/composition.ts:5-39` and `Hufe921/canvas-editor@e8d0be8f4c7d23ef1056a35b0891a3bc1083db82:cypress/e2e/menus/undoRedo.cy.ts:12-97`; the adapter's pinned tests are in the read log.

- **Proof SDK adds agent/provider/persistence scenarios.** Its agent bridge is a service boundary over Milkdown and ProseMirror. The inspected integration test asserts exactly-once persisted and shared text, stability and reconnect. Study those scenarios for Plate's app/service and authored-change owners without introducing a second Plite document authority. Evidence: `EveryInc/proof-sdk@fb2578758f1c62776301209131181643c5f4a19a:packages/agent-bridge/src/index.ts:10-38,162-180`, `EveryInc/proof-sdk@fb2578758f1c62776301209131181643c5f4a19a:package.json:24-45` and `EveryInc/proof-sdk@fb2578758f1c62776301209131181643c5f4a19a:src/tests/agent-edit-collab-propagates.test.ts:230-285`. The test was read, not run.

## Freshness and unresolved evidence

- **Follow canonical source after a migration.** ProseMirror's archived GitHub view/state READMEs point to its canonical host. The canonical view commit is dated October 6 and its changelog records a September release. Keep it as a current reference while identifying the host and exact revision. Evidence: `ProseMirror/prosemirror-view@ca4c78e9b56f1b164c0b3758b59d8748f11b7534:README.md:1-5` and canonical view `3c28f8e797e8fd7e45b72616ba1ce51b6eb8582e` in the read log.

- **Upstream reports choose investigations, not adoption.** The sampled BlockNote collaboration reports, Lexical asynchronous-result PRs, BlockSuite selection/testing issues and SuperDoc host-scroll PR provide concrete risk scenarios. Their bodies were read without comments, local reproduction or patch validation. Their state and scope remain in the [issue read log](../../../plite/research/2026-10-13-editor-comparison/issue-read-log.tsv).

- **Keep source gaps visible.** ONLYOFFICE, Collabora, LibreOffice, Monaco, Zed, Gutenberg, Trix, Squire, newer DOCX projects and remaining discovery candidates do not have current implementation acceptance from this pass. Some official docs entrypoints were inaccessible. The corpus ledger records fallback sources and gaps. Owner: the lead of the next feature-specific comparison. Close each gap only with pinned source and the proof that the proposed claim requires.

- **Research does not alter editor behavior law.** No editor behavior or runtime adoption was accepted. The editor-behavior spec and current-evidence records therefore receive no new coverage claim. Future adoption resolves the native owner and proof through Verify, with Benchmark for a scale claim. The decision (`2e865a0bc4:docs/research/decisions/editor-comparison-set.md`) rejects a universal ranking and an unsupported runtime replacement.
