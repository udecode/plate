# Editor architecture: model and schema

## Document version migrations

- Four non-editor libraries each own one part of a versioned migration chain. Dexie 4.4.5 declares content upgrades per target version and runs every version from the stored one upward, oldest first, inside one upgrade transaction (`dexie/Dexie.js@22bdff16:src/classes/version/version.ts:108-115`, `src/classes/version/schema-helpers.ts:205-272`, tests `test/tests-upgrading.js:123-180`, `:294-323`). Redux Persist 6.1.0's `createMigrate` picks the keys with stored < key <= current and reduces them in ascending order, but skips a missing step silently and returns a newer stored state unchanged after logging that downgrade is unsupported (`rt2zz/redux-persist@d8b01a08:src/createMigrate.ts:6-56`). Zustand 5.0.15's `persist` stores the version beside the state, passes the stored version to one `migrate` callback on mismatch and writes the result back at the current version, leaving step order to the app (`pmndrs/zustand@2115efb9:src/middleware/persist.ts:94-105`, `:269-310`). Sanity Migrate 8.0.2 feeds one migration definition to a dry run and a write runner that stream documents, batch mutations, bound concurrency, report progress and report transactions whose outcome is unknown (`sanity-io/migrate@cae816be:src/runner/dryRun.ts:17-70`, `src/runner/run.ts:117-247`). Plate's chain took Dexie's target-version steps with fail-closed gaps and Zustand's app-owned envelope (`docs/vision/plate.md:587-602`). Source: `docs/plite/research/2026-08-17-document-schema-migrations/read-log.tsv:2-5`, `repo-registry.tsv:2-5`; the local clones sit at those release tags, and the Dexie, Redux Persist, Zustand and Sanity lines were spot-read on 2026-10-08.

## Node model shapes

- UNIST gives every node a `type`, parents `children` and literals `value` (`syntax-tree/unist@8b10b611:readme.md:102-219`); MDAST builds on it with typed text and `value`, wrapper marks, heading `depth`, nested lists and a root node (`syntax-tree/mdast@c034ec9d:readme.md:100-1035`). Plate keeps both as adapter targets, not the live AST (`docs/vision/plate.md:698`), because typed `{ type, value }` text would put a permanent cost on every leaf. Source: `docs/plite/research/2026-08-17-editor-node-model-standards/README.md:93-96`, `read-log.tsv:2-3`.

- BlockNote blocks are `{ id, type, props, content, children }` under a typed block schema (`TypeCellOS/BlockNote@1e26f1c5:packages/core/src/schema/blocks/types.ts:404-444`, MPL-2.0). Its heading is one type with a validated `level` (`TypeCellOS/BlockNote@1e26f1c5:packages/core/src/blocks/Heading/block.ts:11-60`), and its code block persists `language` (`TypeCellOS/BlockNote@1e26f1c5:packages/core/src/blocks/Code/block.ts:11-35`). Splitting one node across `props`, `content` and structural `children` makes traversal heavier and narrows custom structural content. Source: `docs/plite/research/2026-08-17-editor-node-model-standards/README.md:100`, `read-log.tsv:12-14`.

- Editor.js output is a flat array of `{ id?, type, data, tunes? }` tool blocks with no recursive typed rich-text grammar (`codex-team/editor.js@5f45dabb:types/data-formats/output-data.d.ts:11-45`). Quill's Delta is a linear list of insert operations with attributes, with line formats on newline attributes (`slab/quill@539cbffd:packages/website/content/docs/delta.mdx:5-95`): a strong change and OT representation, not a canonical tree. Source: `docs/plite/research/2026-08-17-editor-node-model-standards/README.md:102-103`, `read-log.tsv:16-17`.

## Field conventions across editors

- Editor schemas converge on field conventions. ProseMirror and BlockNote model a heading as one type with `level`, Lexical as one type with an `h1` to `h6` tag, and only MDAST says `depth`. ProseMirror, Lexical, CodeMirror and Wordgard keep code as source text independent of physical-line rendering, and Lexical, BlockNote and Portable Text name the code field `language` where MDAST says `lang`. Portable Text and Quill keep list metadata flat on blocks or lines; MDAST, ProseMirror and Lexical nest structural lists; BlockNote uses list block types with nested children. Lexical and BlockNote store rendered media width, WHATWG and CSS Images call image-owned geometry natural dimensions, and MDAST images cannot own editable captions. Lexical and BlockNote give tables explicit widths, `backgroundColor` and row or column header metadata. BlockNote and Editor.js require block IDs, Lexical persists per-node versions, MDAST and Slate carry no migration lineage, and every external format has one root or list. Plate adopted `heading.level`, `codeBlock.language` and `table.columnWidths` (`docs/vision/plate.md:690-699`). Source: `docs/plite/research/2026-08-17-editor-node-model-standards/README.md:109-125`.

## Rich-text format standards

- No maintained standard combines a syntax tree, an extensible rich-text editor tree, block embedding and collaboration; the candidates solve different jobs. UNIST is a generic syntax-tree interface and MDAST its Markdown AST; MyST (an MDAST superset) and Pandoc are conversion and rendering IRs; Portable Text is the closest open rich-text specification, still a working draft, with a flat block and span ontology, `markDefs` and required keys; Mobiledoc is a versioned article format whose index tables and flat sections trade away readability and nesting; Atlassian Document Format and Contentful Rich Text are closed vendor schemas, and Contentful forbids custom nodes; ProseMirror or Tiptap JSON and Draft.js raw content are editor storage formats; Quill Delta and `ottypes/rich-text` are linear operation formats; Block Protocol standardizes block-component and embedder messages and, in its rich-text hook RFC (`blockprotocol/blockprotocol@7acf45e3:rfcs/text/0430-hook-module.md:1-125`), lets each host keep bespoke rich-text data; Gutenberg's PEG grammar serializes blocks into HTML comments; W3C Web Annotation standardizes annotation bodies, targets and selectors; and Peritext specifies concurrent text and mark intent. A GitHub search for rich-text specifications surfaced only Portable Text. Plate keeps its native AST with explicit format adapters (`docs/vision/plate.md:698`). Source: `docs/plite/research/2026-08-17-editor-node-model-standards/shards/002-standards-proposals.md:37-64`, `read-log.tsv:35-44`, `repo-registry.tsv:12-15`.
