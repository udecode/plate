# Editor architecture: marks decorations and annotations

## Mark and link boundary affinity: Typora versus Milkdown

- **Boundary affinity diverges.** Typora's Markdown Reference says moving the cursor into a span element expands it into its Markdown source, and the audit read Typora as treating many spans as hard boundaries. Milkdown keeps marks inclusive: no mark schema in `Milkdown/milkdown@6a4db480b` sets `inclusive`, so every mark, inline code included, keeps ProseMirror's inclusive default, and in `Milkdown/milkdown@6a4db480b:e2e/tests/plugin/clipboard.spec.ts` text-only HTML pasted inside a link joins the link. The audit also cited `Milkdown/milkdown@6a4db480b:docs/api/component-link-tooltip.md`, `Milkdown/milkdown@6a4db480b:packages/crepe/src/feature/top-bar/config.ts` and `Milkdown/milkdown@6a4db480b:e2e/tests/plugin/automd.spec.ts`. It sent soft marks and links to the dominant mainstream rich-text precedent instead of either reference or legacy Plate behavior, and kept hard boundaries for source-like inline nodes. The spec now locks directional affinity for soft marks and links and hard affinity for inline code and kbd (EDIT-AFF-MARK-001, EDIT-AFF-LINK-001, EDIT-AFF-HARD-001), so Plate's inline code departs from Milkdown's inclusive default. Evidence: `docs/research/history/2026-04-02-markdown-editing-reference-audit.md:205-207`, `../raw/typora/pages/markdown-reference.json` (fetched 2026-04-02); the `inclusive` search ran on 2026-10-08. Limit: the audit named no specific mainstream editor as the precedent, and neither editor was run.

## CodeMirror range sets

- CodeMirror's `RangeSet` is a chunked immutable range collection with mapping and shared comparison, and its view decorations are RangeSet-backed (codemirror/state@9c801279cb83011e6f92af778f4443406e8f1200:src/rangeset.ts:1-36,95-159,182-319,338-356; codemirror/view@fbff59ba004d80d8c914f64c42586387b08706ac:src/decoration.ts:166-257). Its range deletion semantics are not anchor identity, so it is a candidate private mapping kernel for paint, not a replacement for semantic annotation targets. Each `EditorView` owns explicit plugin lifetimes and paints decorations for its viewport, with one editor state per view (codemirror/view@fbff59ba:src/editorview.ts:175-224,873,1054; src/extension.ts:101-163; src/docview.ts:57,626). Read 2026-09-21, not executed (docs/plite/research/2026-09-21-annotation-architecture-oss/read-log.tsv:14-16,29).

## Monaco decorations

- Monaco, the VS Code editor core, keeps one text model that many editors share; decorations carry owner IDs, so per-editor ownership needs explicit tokens and cleanup (microsoft/vscode@f487add297079a02eb836810185b165e50cadabc:src/vs/editor/common/model.ts:370-445,1073-1100). Decorations live in an augmented interval tree with lazy shifting (src/vs/editor/common/model/intervalTree.ts:141-333,416-632,711-865), and each view model materializes inline decorations only for its visible viewport through a decoration cache (src/vs/editor/common/viewModel/inlineDecorations.ts:45-175; src/vs/editor/common/viewModel/viewModelDecorations.ts:16-81). Read 2026-09-21: the interval tree is a benchmark candidate for dense flat paint, not a semantic target owner, and a resolved projection cache should not be shared across views (docs/plite/research/2026-09-21-annotation-architecture-oss/read-log.tsv:17-19).

## CRDT cursors and marks

- Automerge cursors are persistable and move to the nearest position before or after a deletion, with no terminal-absence policy (automerge/automerge@4d2a8f6bfecfb7f1e4fca126e6d2122ac526f903:rust/automerge/src/cursor.rs:9-79). Automerge marks are collaborative rich-text state with one value per mark name (rust/automerge/src/marks.rs:13-26), and a fully deleted mark does not reattach to equivalent inserted text (test 'fully deleted marks will not attach to new text', rust/automerge-wasm/test/marks.mts:617-631, body reread 2026-10-08), which does not show terminal anchor death through undo. Read 2026-09-21 (docs/plite/research/2026-09-21-annotation-architecture-oss/read-log.tsv:24-26).

## Flat offsets

- Quill transforms flat document offsets through deltas for history and positions (slab/quill@539cbffd0a13b18e9c65eb84dd35e6596e403158:packages/quill/src/modules/history.ts:201-205; slab/quill@539cbffd:packages/quill/src/core/quill.ts:1009-1044; read 2026-09-21). Delta-transformed offsets cannot represent tree roots, authored views or retained annotation identity, so the 2026-09-21 review rejected them as an annotation model for a tree editor (docs/plite/research/2026-09-21-annotation-architecture-oss/read-log.tsv:27).

## VS Code visual channels

- **VS Code renders inline paint, line zones and side-channel markers on separate paths.** At `microsoft/vscode@df2411cf7d8f2e0cfc79109a3bc8eaab2c69165b`, the marker decorations service turns each diagnostic into one model decoration whose options carry a range class, an inline class for unnecessary or deprecated code, an overview-ruler entry and, above hint severity, an inline minimap entry, with a z-index by severity (0, 10, 20, 30) and `NeverGrowsWhenTypingAtEdges` stickiness (`microsoft/vscode@df2411cf:src/vs/editor/common/services/markerDecorationsService.ts:226-297`). Inline-completion ghost text paints same-line text as decorations whose `after` injected text carries a left cursor stop (`microsoft/vscode@df2411cf:src/vs/editor/contrib/inlineCompletions/browser/view/ghostText/ghostTextView.ts:317-340`) and puts added lines in a view zone through `AdditionalLinesWidget` (same file, `:461`, `:575-582`), and line projection consults each injected text's cursor stops when it normalizes an offset (`microsoft/vscode@df2411cf:src/vs/editor/common/modelLineProjectionData.ts:202-231`, `:300-306`). One decoration can feed several paint surfaces, while injected text, line-attached zones and ruler or minimap markers stay separate rendering paths. Source: `52625e85025313eebd4eeb9be2254249ded58676:docs/plite/decorations-annotations-cluster.md:634-667`, an April 2026 read of an unpinned clone; reread at the pinned commit on 2026-10-08. Limit: source reading, not run; Plite keeps inline paint in decorations and exposes no generic widget lane (`docs/vision/plite.md:597-600`).
