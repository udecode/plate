# Editor architecture: history and undo

## Undo versus authored history

- Lexical's history stores editor-state snapshots (`facebook/lexical@dd5c41b1:packages/lexical-history/src/index.ts:1-75`) and Quill's history stores and transforms inverse Deltas (`slab/quill@539cbffd:packages/quill/src/modules/history.ts:1-100`); neither undo stack is an authored journal. Fidus Writer was screened by metadata only. This bounded 2026-09-10 read does not claim their ecosystems lack tracking plugins. ## Undo return types

- **Editor undo is synchronous; only VS Code and Monaco admit async completion.** ProseMirror's `undo(state, dispatch)` (`ProseMirror/prosemirror-history@768b74205ad59919ed54d75e197312964ddcf3c2:src/history.ts:391-447`), CodeMirror 6's `undo` (`codemirror/commands@5b9bac974f2c4af3e20b045adef949667872ecad:src/history.ts:117-134`), Lexical's `UNDO_COMMAND` dispatch (`facebook/lexical@dd5c41b13193efa9ab1574234d8593d2c9e4f988:packages/lexical-history/src/index.ts:415-449`), Tiptap's `commands.undo()` (`ueberdosis/tiptap@91c51be53c4655ef07e29ec489471524debfa0ca:packages/extensions/src/undo-redo/undo-redo.ts:56-68`) and BlockNote's `editor.undo()` (`TypeCellOS/BlockNote@1e26f1c5e1cd7df81df9d4ab2a853bf1b298b163:packages/core/src/editor/BlockNoteEditor.ts:1108`) return `boolean`; Slate's `editor.undo()` (`ianstormtaylor/slate@945a484df2497e4c448b33f417b0de2a49840032:packages/slate-history/src/history-editor.ts:17-21`), Quill's `history.undo()` (`slab/quill@539cbffd0a13b18e9c65eb84dd35e6596e403158:packages/quill/src/modules/history.ts:85-150`) and Liveblocks' `room.history.undo` return `void`; the Yjs `UndoManager.undo()` returns a `StackItem` or `null` (`yjs/yjs@da0523008392f10b078bcbf7f056ec9a478c4585:src/utils/UndoManager.js:342-366`); tldraw returns `this` (`tldraw/tldraw@e8f61acedcbf2dc69693ea1e1f612a7f635fb4b5:packages/editor/src/lib/editor/Editor.ts:1551`) and Loro `LoroResult<bool>`. VS Code's undo service and its elements return `Promise<void> | void` (`microsoft/vscode@df2411cf7d8f2e0cfc79109a3bc8eaab2c69165b:src/vs/platform/undoRedo/common/undoRedo.ts:17-72`) and Monaco's `ITextModel.undo()` returns `void | Promise<void>` (`microsoft/vscode@df2411cf7d8f2e0cfc79109a3bc8eaab2c69165b:src/vs/monaco.d.ts:2385`); besides file and notebook elements, the service can await a confirmation before undo (`microsoft/vscode@df2411cf7d8f2e0cfc79109a3bc8eaab2c69165b:src/vs/platform/undoRedo/common/undoRedoService.ts:1099-1129`), so async is not limited to file operations. Comment threads stay out of document history in the Lexical playground (a `CommentStore` outside history; undo unwraps only the mark, `facebook/lexical@dd5c41b13193efa9ab1574234d8593d2c9e4f988:packages/lexical-playground/src/plugins/CommentPlugin/index.tsx:752-805`), BlockNote (creation awaits the server, then sets a mark; undo removes only the mark, and orphaned marks reconcile, `TypeCellOS/BlockNote@1e26f1c5e1cd7df81df9d4ab2a853bf1b298b163:packages/core/src/comments/extension.ts:120-160`) and Liveblocks (creation is optimistic and rolls back on server failure); no surveyed library makes undo wait on a server. ## Pending undo

- **VS Code's rules for a pending undo.** When a stack is locked, `_resourceUndo` shows a warning that another undo or redo is running and drops the press instead of queueing it; `moveBackward(element)` moves the stack pointer before the element's undo, and `_safeInvokeWithLocks` holds the lock until the promise settles; on failure `_onError` reports the error, removes the undo and redo stacks of every affected resource and notifies, and the returned promise resolves rather than rejects; workspace undo asks for scope, awaits `prepareUndoRedo` and rechecks after each await whether the stack changed, locked or was undone meanwhile; an element from another source or with `confirmBeforeUndo` prompts first; `pushElement` has no lock check, so edits still land while an undo is pending; and callers fire and forget (the explorer returns `true` without awaiting, the keybinding layer attaches a warning `.then`). Text edits are synchronous; file operations and notebook cell edits are async.
