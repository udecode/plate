# Editor architecture: autocomplete and triggers

## BlockNote

- BlockNote's `SuggestionMenu` keeps the query as document text after the trigger (MPL-2.0; the xl packages are GPL-3.0 or proprietary). The query is recomputed as `textBetween(queryStartPos, selection.from)`, and a decoration covers only the trigger (`TypeCellOS/BlockNote@1e26f1c5:packages/core/src/extensions/SuggestionMenu/SuggestionMenu.ts:141-150`, `:330-334`, `:409-421`). It opens when typed text equals a registered trigger, longest first. It closes on a non-empty selection, on blur, when the caret moves before the start or into another block, and after more than three consecutive characters with no items. Enter checks `isComposing` only, with no 229 check. The menu closes during Chinese IME because prosemirror-view can expose a non-empty selection mid-composition: #1283 is closed while fix PRs #2731 and #1295 stay open, and the read commit is unfixed. The contenteditable gets `aria-expanded`, `aria-controls` and `aria-activedescendant` but no `role=combobox` (`TypeCellOS/BlockNote@1e26f1c5:packages/react/src/components/SuggestionMenu/SuggestionMenuWrapper.tsx:60-88`). Query characters after the trigger reach input rules unguarded. Selecting an item runs close, clear-query and the item action as separate transactions. Under collaboration, `queryStartPos` is a Yjs relative position because y-prosemirror's sync can break ProseMirror position mapping (`TypeCellOS/BlockNote@1e26f1c5:packages/core/src/api/positionMapping.ts:4-41`). A capture-phase keydown listener on the editor DOM handles the arrows, PageUp, PageDown and Enter while focus stays in the editor. BlockNote has no home, so it lives on this page. Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/001-prosemirror-family.md:51-63`, read at that commit on 2026-10-02.

## prosemirror-suggest

- remirror's `prosemirror-suggest@3.0.0` keeps the query as document text with an inline decoration, keeps ignored matches as decorations, and has no composition handling (`dist/prosemirror-suggest.js:566-577`, `:886-895`). Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/001-prosemirror-family.md:93`.

## Isolated query versus document-text query

- The 2026-10-02 read of ProseMirror-family trigger autocomplete weighs isolating the query against keeping it as document text. For isolation (Atlassian): it gives the focused element correct combobox ARIA, which every document-text design read gets wrong or skips. Document-text menus keep hitting composition bugs in menu state (Tiptap #1449, BlockNote #1283, ProseKit #1759 and #1743). A document-text query leaks to collaborators and lets remote transactions drive the local menu (Tiptap PR #7384, BlockNote's Yjs positions). Input rules apply to document-text queries unless a plugin claims `handleTextInput` first. Against isolation: document text is the family norm (Tiptap, ProseKit, BlockNote, Milkdown, prosemirror-suggest). Atlassian pays with custom history steps, undo interception, Safari, Chrome and Edge workarounds and a separate composition path for the fullwidth slash. Android Chrome copies an adjacent `contenteditable=false` inline's text into the active composition, which ProseMirror could not hide (ProseMirror#903, Chromium bug 612446), and no isolated design shows Android proof. The browser composes a document-text query natively, so the remaining bugs are in menu state, not text entry. ProseKit closes the document-text failure modes without custom steps. Moving focus into an input right after the trigger would end a Gboard composition in flight (inferred). Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/001-prosemirror-family.md:102-118`.

## Draft.js mention

- `@draft-js-plugins/mention@5.3.0` (with `draft-js@0.11.7`, read from the published dist) keeps the query as block text marked by a decorator. A strategy regex finds `@...` ranges in non-entity text, a portal span registers each range, and the search text runs from the last trigger to the caret (`lib/index.esm.js:124-147`, `:206-262`, `:897-919`). The list closes when the editor loses focus and reopens on return. Escape memoizes `escapedSearch` by decorator offset key, so that range stays closed until the caret moves to another search (`:543-550`, `:965-970`). Keydown reaches edit mode only when not composing, and composition does not push state, so the query does not update until commit (#2543 with a Vietnamese keyboard; #1673 and #1431 with Android prediction). Draft does not support mobile (#2661). The plugin makes the contenteditable root a combobox, with role, `aria-autocomplete=list`, `aria-haspopup`, `aria-expanded`, active-descendant and owns ids, and the ids are per instance (`:1056-1066`, `:565`, `:696`). Completion pushes an `insert-fragment` change, which forces an undo boundary. On open the plugin swaps `handleReturn` and `keyBindingFn` for the arrows, Escape and Tab, a method its own comment calls nasty. Options prevent default on mousedown and commit on mouseup, so the editor never blurs. Draft.js has no home, so it lives on this page. Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/002-lexical-slate-draft.md:52-65`.

## CKEditor 5 mention

- CKEditor 5's mention plugin keeps the query as document text and re-derives it from the text before the caret on every change (mention 48.0.1; GPL-2.0-or-later or commercial, so read only). A local marker named `mention` covers only the trigger. It is created with `usingOperation: false`, so it is neither undone nor synced (`ckeditor/ckeditor5@14e73cc3:packages/ckeditor5-mention/src/mentionui.ts:382-412`; `ckeditor/ckeditor5@14e73cc3:packages/ckeditor5-engine/src/model/markercollection.ts:314-320`). Commit replaces the range from the marker start to the caret with text that carries a `mention` attribute and a uid, in one `model.change`, plus a trailing space. Post-fixers strip partial mentions (`mentioncommand.ts:152-183`, `mentionediting.ts:91-93`). The TextWatcher regex lets spaces continue the query and ignores undo and remote batches, so remote typing never opens a local menu, and undo restores `@query` without reopening it (`ckeditor/ckeditor5@14e73cc3:packages/ckeditor5-typing/src/textwatcher.ts:125-129`). Mention has no composition code. With Korean IME the dropdown shows only after composition ends (#15616, open), and Japanese IME after a mention inserts a stray Latin letter (#6700, open). Android mention bugs were fixed in the typing layer, not in mention: a doubled trigger on Gboard (#12567) and a duplicated word on Samsung Chrome (#15950, PR #16289). The list exposes no combobox, listbox or live-region ARIA (#11710, open). TextTransformation and Autoformat never reference the marker, so they can fire inside a query (inferred). A keydown handler at highest priority handles the arrows, Escape and the commit keys while the balloon shows. CKEditor has no home, so it lives on this page. Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/003-ckeditor-quill-atlassian.md:13-27`, read at that commit on 2026-10-02.

## quill-mention

- quill-mention 6.1.1 (MIT; 3.4.1 uses the same design) keeps the query as document text with no range object. The integers `mentionCharPos` and `cursorPos` are rescanned up to 31 characters before the caret on each user text change and each collapsed selection change (`src/mention.ts:250-262`, `:927-1008`). The default `allowedChars`, `/^[a-zA-Z0-9_]*$/`, ends the query on a space or on any non-ASCII letter (#358). Commit deletes the query, then inserts the mention embed and an optional space, all as user changes. Quill History merges changes within 1000 ms, so a fast completion may undo together with the query typing (inferred). Quill 2 batches the scroll during composition, so the scan runs after composition ends (inferred), and Quill's keyboard module ignores `isComposing` and 229 keydowns. On `quill.root` it sets `aria-owns` permanently and `aria-activedescendant` while the list is open, with no combobox role or expanded state, which validators flag (#418). Items prevent default and stop propagation on mousedown and select on mouseup, which keeps editor focus. Mobile Backspace bugs (#170, #40) are open. Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/003-ckeditor-quill-atlassian.md:29-43`.

## Atlassian type-ahead

- Atlassian's type-ahead keeps the open query out of the document (`@atlaskit/editor-plugin-type-ahead@24.0.0`, Apache-2.0, built on ProseMirror). A `Decoration.widget` at the caret renders a `<mark role=search>` host whose widget spec stops events except ArrowLeft at offset 0. The query lives in a nested `<span contentEditable role=combobox>`, which holds an empty 5 px `<input aria-label>` placeholder until the first query character arrives (`dist/es2019/pm-plugins/decorations.js:43-65`, `:116-129`; `ui/InputQuery.js:438-457`). The trigger is not inserted while the menu is open (`allowInsertTextOnDocument: false`), and the query is copied into plugin state with meta-only transactions. Before editor-core 149.0.0 (2021-08-26, ED-12933), the query was document text under a `typeAheadQuery` mark. That design forced shared input rules and emoji ASCII rules to skip marked text, and it needed an Android Q `compositionend` hack for a doubled trigger (`@atlaskit/editor-core@148.0.0`). The only reason the changelog gives for the move is that type-ahead is no longer part of the document. The same release added the local `InsertTypeAheadStep`. Atlassian therefore supports an isolated editable element, not a native input. Atlassian has no home, so it lives on this page. Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/003-ckeditor-quill-atlassian.md:45-51`.

- Atlassian type-ahead behavior at 24.0.0. An input rule opens it on the trigger after the start of text, whitespace or `.!?`. Every exit commits the raw text and loses nothing. Escape writes `trigger+query` with the caret after it. Backspace at offset 0 writes the query without the trigger. Arrows past an edge write it with the caret outside. Blur writes `trigger+query` without refocusing the editor (`ui/InputQuery.js:140-176`, `:233-310`; `ui/hooks/use-item-insert.js:12-33`). Enter is guarded by `!isComposing && keyCode !== 229`, because virtual keyboards also report `isComposing`. A fullwidth `／` opens the menu on the Enter that confirms the composition. A trigger that composition duplicated before the widget is deleted, citing ProseMirror#903 (`InputQuery.js:177-198`; `pm-plugins/main.js:54-166`; `open-typeahead-at-cursor.js:75-89`). The query span's keydown listeners are plain DOM listeners since 149.0.1 (ED-13713), so product code cannot hijack them through bubbling (`InputQuery.js:233-255`). The focused query span carries `role=combobox`, `aria-activedescendant`, `aria-controls`, `aria-autocomplete=list`, `aria-expanded` and `aria-labelledby`, and the options use roving DOM focus. A polite `role=status` live region, debounced 1400 ms, announces when there are no results (`@atlaskit/editor-common@127.1.1:ui/AssistiveText/AssistiveText.js`). Inside the query, Ctrl+Z is native contenteditable undo, and ProseMirror history runs only on an empty query, so there are two undo stacks. Completion is three history events, and undoing the item reopens the menu with the stored query and selected index (`pm-plugins/reducer.js:8-23`). `InsertTypeAheadStep` serializes as a no-op replace, so peers see nothing until commit, and a collab rebase does not reopen the menu (`@atlaskit/adf-schema@57.6.19:steps/type-ahead.js:10-74`; `main.js:18-27`). The current package has no Android or mobile branch. Its changelog records the workaround cost: Safari undo and `beforeinput` branches, a Chrome and Edge spurious-focusout filter, a Firefox caret TODO, a rich-paste fix, a focus-loss fix, a focus-timing experiment and a VoiceOver refactor. Source: `docs/plite/research/2026-10-02-autocomplete-query-representation/shards/003-ckeditor-quill-atlassian.md:52-60`.
