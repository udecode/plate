## What the lead's restatement said, which the owner accepted

The deliverable is the basis natamox builds and the team then uses: prepared human scenarios per page, weighted toward what agents historically miss; one capture format for a find; a P6 loop where each find becomes a fix plus the missing or corrected test at the lowest layer that can see it (mostly unit or integration, browser only for things like cursor drift); a repeat rule where scenarios a test now covers drop out, heading toward zero manual testing. Agent-run testing of the scenarios is a later extension, not the first step. The plan does not execute P1 to P6.

## Repository conventions the design must match

- A project skill is a thin `.agents/rules/<name>.mdc` (frontmatter `description`, `argument-hint`), synced to `.claude/skills/<name>/SKILL.md` by `pnpm run prepare`. `verdict.mdc` is the model: it says "Run the Verdict playbook in full", loads `pstack:poteto-mode`, and runs `check-playbooks.mjs`.
- A project playbook lives in `.agents/playbooks/<name>.md` with frontmatter `extends` (a pstack playbook stem, such as `investigation` or `bug-fix`, or empty), `when`, and optional `page-lead`, `page-pairs`, `page-require`, `page-pr`. Its body applies anchored deltas to the pstack playbook's steps: list items that start with **Before**, **After**, **Replace** or **In** followed by a quoted run of the pstack step's own words. `node <plugin>/skills/poteto-mode/scripts/check-playbooks.mjs` refuses a quote the pstack step no longer has. Read `.agents/playbooks/verdict.md` (extends `investigation`, has a Verdicts table, a One item per session section and Steps of deltas) and `.agents/playbooks/bug-fix.md` (extends `bug-fix`).
- The pstack playbooks live under `/Users/zbeyens/.claude/plugins/cache/pstack-claude/pstack/0.9.84/skills/poteto-mode/playbooks/`. Read `investigation.md`, `bug-fix.md`, `eval.md`, `prototype.md` there.
- Work hands back as a plan page: a plan in `docs/plans/<date>-<slug>.md` with `Status:`, `Topic:` or `review_scopes`, `Playbook:`, `## Brief`, `## Teach`, `## Defaults`, steps as `- [ ]` boxes that name their proof, and a decision log `docs/plans/<slug>.decisions.tsv`. `.claude/skills/plan-page/SKILL.md` owns the shape. `AGENTS.md` owns delivery: the user owns commits on `next`; public issue posts need the user's explicit word; one session per find, one at a time per set of files.
- `.agents/playbooks/references/workflow-change.md` governs any change to agent instructions: keep every method it touches, a repository skill holds only Plate or Plite method, no skill exists only to rename another owner, and a broad change to discovery, method selection or completion behavior gets a paired baseline-versus-revised trial (pstack's Eval playbook) before adoption, with the lead never seeing the answer key. `.agents/playbooks/plan.md` line 15 says that trial runs on the first working prototype before the plan's panel.
- `docs/development/agent-skills.md` restates the workflow for contributors and must change with it.
