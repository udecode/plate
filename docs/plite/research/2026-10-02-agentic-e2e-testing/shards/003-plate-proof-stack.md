### What `createBrowserEditorHarness` gives a spec (`src/playwright/harness.ts:81-582`)

- **Model reads.** `get.modelText`, `modelBlockText(s)`, `modelValue`, `kernelTrace`, `history`, `lastCommit` (`:133-192`).
- **DOM reads.** `text`, `blockTexts`, `renderedDOMShape`, `selectedText`, `html`, `placeholderShape` (`:156-208`).
- **Selection.** `get.selection` (model), `domSelection`, `displayedSelection`, `location`, `rect`, plus writers `select`, `selectDOM`, `collapse`, `selectAll`, `dragTextRange`, `doubleClickDragTextRange`, range anchors (`:210-387`). `select` writes through the page handle first, then mirrors to the DOM and dispatches a synthetic `selectionchange` (`:211-262`).
- **Focus owner.** `get.focusOwner` (`:165`) and `assert.focusOwner` (`harness-assertions.ts:84`).
- **Input.** `type` uses `page.keyboard.type` (trusted CDP) (`:490-498`). `press` sends any modifier shortcut except Mod+C/X/V/A as an untrusted `KeyboardEvent` dispatched on the root (`:499-527`, `keyboard.ts:12-53,73-110`), so `Mod+B`, `Mod+Z` and friends never reach the browser's native command path. `insertText`, `insertBreak`, `deleteBackward/Forward`, `deleteFragment`, `undo`, `redo` call the page handle, not the browser (`:528-548`). The scenario runner's `undo` step also goes through the synthetic `press('Meta+Z')` (`harness-scenario.ts:124-136,786-792`).
- **IME.** `composeText` uses CDP `Input.imeSetComposition` + `Input.insertText` on Chromium and falls back to dispatched `CompositionEvent`s on Firefox/WebKit or when `transport: 'synthetic'` (`ime.ts:284-322`).
- **Clipboard.** `pasteNativeText` writes the real clipboard and presses Mod+V (`harness-input.ts:107-113`). `pasteText` and `pasteHtml` try the native path, then silently fall back to the page handle's `insertText`/`insertData` or a synthetic paste event when the native paste did not change the model (`harness-input.ts:114-176`). verify.mdc:264-267 documents this fallback.
- **Scenarios.** `scenario.run(name, steps)` executes 55 declarative step kinds (from `applyChange` to `typeThenUndo`, `harness-scenario.ts:114+`), records a trace snapshot per step, records runtime errors, and emits replay JSON plus delta-reduction candidates (`createScenarioReplay`, `createScenarioReductionCandidates`). `classifyScenarioTransportClaim` labels each run with one of 12 transport claims (`types.ts:733-745`, `scenario-replay.ts:1124-1154`), for example `desktop-semantic-handle` or `playwright-mobile-viewport`.
- **Assertions.** 20+ assertion helpers, including `collapsedModelDOMSelection`, `noDoubleSelectionHighlight`, `caretVisibleInScrollableParent`, `noVisibleCaretInRoot`, `domCaret`, `noUnexpectedZeroWidthBreaks`, `renderedDOMShape` (`harness-assertions.ts:43-181`).

### How the model oracle reaches into the page

Every mounted Plite editable attaches a `PliteBrowserHandle` object as the expando property `__pliteBrowserHandle` on its root element (`packages/plitejs/src/react/editable/browser-handle.ts:74-150` type, `:924` attach, `:927-928` detach), from `useRuntimeBrowserHandle` in a layout effect (`runtime-browser-handle-events.ts:42-60`), which `runtime-event-engine.ts:193` calls for every editable. Neither file gates it on `NODE_ENV` (grep of both files for `NODE_ENV|__DEV__` returns nothing), so production builds carry it too (inferred from those two files). The harness reads it with `root.evaluate(el => el[BROWSER_HANDLE_KEY][method](...))` (`src/playwright/handle.ts:28-61`, key in `constants.ts:2`). The handle exposes about 45 methods: reads (`getValue`, `getSelection`, `getViewSelection`, `getKernelTrace`, `getInputState`, `getLastCommit`, `getDOMPhaseSchedulerDiagnostics`) and writers (`insertText`, `applyChange`, `selectRange`, `setNativeDOMSelection`, `importDOMSelection`, `undo`). So one handle is both the test oracle and a back channel for input. 133 hits of `__pliteBrowserHandle` sit directly in Playwright specs (`census.tsv`), outside the harness.

### Engine drift: green on Chromium, red elsewhere

On every push the gate runs Chromium only. One PR's recorded CI ledger shows what the manual matrix then found (`docs/plans/5036-complete-pushed-ci.md:79,95,98-108`):

- Chromium shard 1/4 failed with "three rich-text IME rows lost active marks" (`:79`).

- A Plite CI run had a WebKit focus defect reproduce on held block drag (`:95`).

These are product defects, test assumptions and harness faults together, and the record does not split them per row (inferred). Playwright WebKit is not Safari (`verify.mdc:275-277`), so a Safari user can still hit a defect after all five projects pass.

### Drift paths built into the harness

These are not incidents. They are paths in the current proof stack where a green result can coexist with broken native behavior. Each one is a documented or code-visible proxy:

1. **Shortcuts are untrusted events.** `harness.press('Mod+B')`, `press('Meta+Z')` and every modifier chord except Mod+C/X/V/A become a constructed `KeyboardEvent` dispatched on the root (`packages/test/src/playwright/harness.ts:507-519`, `keyboard.ts:25-53`). The browser's own command path and `beforeinput` `historyUndo`/`formatBold` never fire. The scenario runner's undo step uses the same path (`harness-scenario.ts:124-136,786-792`). Raw counts: about 342 harness or locator `.press(` calls against 696 `page.keyboard.press` calls in the Playwright trees (`census.tsv`).
2. **Paste falls back silently.** `clipboard.pasteText`/`pasteHtml` retry through the handle or a synthetic event when native paste did not change the model (`harness-input.ts:114-176`), so a broken native paste can still go green. verify.mdc:264-267 warns about this, but the helper does not mark its result as fallback-delivered.
3. **Model setters as setup.** `selection.select`/`collapse` write through the page handle and then dispatch a synthetic `selectionchange` (`harness.ts:211-262`). They appear 454 times. This is legitimate setup, but `regression-oracles.md:358-368` exists because a programmatic caret once certified a broken physical-click path (case D12).
4. **Non-Chromium IME is synthetic.** On Firefox and WebKit, `composeText` dispatches `CompositionEvent`s (`ime.ts:297-306`), and the autocomplete decision record says "Playwright's WebKit exposes no composition protocol, so no emulated WebKit proof exists" (`docs/research/decisions/autocomplete-ownership.md:186-189`).
5. **Mobile is a viewport.** The `mobile` and `mobile-webkit` projects are Pixel 5 and iPhone 13 descriptors on desktop engines (`apps/plite/playwright.config.ts:56-81`). 387 of 704 mobile rows were skipped in the last recorded matrix (`2026-08-01-final-wordgard-adoption-plan.md:394`).
6. **Unit DOM is happy-dom or jsdom.** Every Bun test has happy-dom globals (`bunTestSetup.ts:62-68`), and `docs/solutions/test-failures/2026-04-17-plite-react-focus-tests-need-vitest-jsdom-20-not-happy-dom-or-jsdom-26.md:20-58` shows the three DOM shims disagreeing on one focus row.

## 5. The verify skill's proof law

Source: `.agents/rules/verify.mdc` (384 lines) and `.agents/rules/verify/references/{editor-proof,regression-oracles,commands,testing}.md`. Generated copies live under `.agents/skills/verify/`.

**Proxy layers diagnose, they do not prove native input.**

> "A model test, detached transform, alternate route, synthetic click or model-set selection can diagnose a browser defect without proving its native input, focus consumer, paint or event ordering." (`verify.mdc:29-32`)

> "Internal setters or model-only assertions cannot replace the actual reporter path." (`verify.mdc:341-342`)

> "For keyboard, text-input, trigger, or semantic-command regressions, a passing detached root-editor test cannot overrule a failing mounted Browser case." (`regression-oracles.md:70-72`). Completion then requires a Browser oracle recording `runtime-owner: pass` and `mutation-owner: pass` (`:74-79`).

> "A fake runtime cannot certify native browser behavior." (`testing.md:99`)

**Five warm runs.**

> "For flaky, native, lifecycle, compositor, focus, selection, drag-and-drop or device risk, run the final proof five times, warm and without retries. One failure keeps the case open. Each run executes the proof command; a cached result does not count." (`verify.mdc:52-55`)

**Emulation and synthetic events.**

> "Existing repository Playwright specs are executable proof owners. ... Do not build a parallel Puppeteer, raw CDP or standalone Playwright driver for interactive QA. Browser emulation does not prove raw Android/iOS input." (`verify.mdc:259-262`)

> "The harness's `clipboard.pasteHtml` and `clipboard.pasteText` can fall back to synthetic events or editor handles. Native clipboard proof must capture a trusted paste event with the intended formats and confirm the rendered result." (`verify.mdc:264-267`)

> "Only Chromium exposes clipboard permissions to automation, and Playwright's WebKit build is not Safari; claim Safari behavior only with Safari proof." (`verify.mdc:275-277`)

> "Mobile viewport and synthetic composition tests retain their proxy scope. Raw Android/iOS or OS IME claims require the actual device/input method." (`verify.mdc:314-315`)

> "For keyboard-formatting claims, use the control's key-by-key typing operation (`pressSequentially` in the current browser API). Direct text insertion can follow a different input path." (`verify.mdc:254-256`)

> "Mobile-emulation proof is scoped proof. ... `page.keyboard.type(...)` is not raw mobile native typing." (`editor-proof.md:82-85`)

> "Raw mobile/device claims are deferred by default until the repo has a real, repeatable Android/iOS/Appium or equivalent device lane with artifacts. Do not ask the user to reconfirm this in every handoff. Record the claim as `deferred-with-owner` or `scoped proof only`" (`editor-proof.md:91-94`)

> "`bun test:mobile-device-proof:raw` requires actual Appium Android/iOS artifacts. Semantic mobile handles and Playwright mobile viewports never prove a raw device." (`commands.md:199-200`)

> "Do not trust Playwright rows that use browser/project-gated `return` statements ... That is fake green: Playwright reports a pass while no behavior ran." (`editor-proof.md:67-69`)

**Exact browser, physical pointer, pixels.**

> "When the report names Chrome, Blink, a compositor, or browser-native behavior, record `exact-chrome: <environment>` and use exact Chrome for the full final replay. Playwright Chromium remains useful diagnosis but cannot certify that claim." (`regression-oracles.md:418-421`)

> "A `locator.click()`, element-dispatched click, or programmatically created caret cannot certify the contradicted physical path." (`regression-oracles.md:367-368`)

> "DOM markers, computed styles, geometry, model state, a passing browser test or an uninspected screenshot path cannot close a visual claim." (`verify.mdc:348-350`). A pixel classifier must first pass positive, absent and duplicate sentinels (`regression-oracles.md:471-484`).

> "`activeElement` without a native caret or selection in the target, a mount-only fixture that skips the popup's real lifecycle, waiting for `toBeFocused()`, using a locator-owned key method, or sending a programmatic text insertion before the first-key assertion is a false green." (`regression-oracles.md:250-253`)

**Doctrine.** The claim-width table puts "mobile viewport behavior" at "Playwright/mobile semantic proof, explicitly scoped" and "raw mobile/device behavior" at "real device/Appium/equivalent artifacts" (`docs/vision/common.md:76-84`). `docs/vision/plite.md:445-446` says native mobile, semantic mobile, Playwright mobile viewport and Appium raw device proof are distinct claim classes. `VISION.md:39` forbids calling live behavior fixed without live proof and requires naming the missing device.

The oracle reference (`regression-oracles.md`, 564 lines) records past drift. Each section encodes a prior false green as a marker the next proof must record: `first-key-boundary`, `physical-hit-path`, `reporter-profile-replay`, `pre-handler-state`, `boundary-exit-trace`, `positive-control/negative-control/duplicate-control`.

## 6. Test-shape law

`AGENTS.md:39` (Tests rule, worktree):

- "Every test must fail for a named, plausible defect and pass only once it is fixed. Add nothing when an existing test, type, lint rule, static check or direct runtime proof already catches the defect."
- "When the test would be expensive, integration-heavy or unclear, skip it and prove the fix at runtime."
- "One regression usually gets one public-boundary test, and more cases need distinct failure modes."
- "Never test source text, copy or labels, constants, fixture construction, mock returns, implementation order, library behavior or another test's boundary, and never recompute the implementation in the assertion."
- "Cut duplicate and lower-signal tests instead of porting them. No exhaustive matrices, snapshots, broad smoke suites or speculative cases; a static invariant belongs in lint or a check script."
- "committed code has no `.only` or `.skip`."

`AGENTS.md:137` (Tests addendum): no TDD cases asserting removed legacy APIs. A runtime capability gate (a skip that fires only when the browser, platform or engine lacks a capability) is allowed, and unconditional `.skip`/`.only` stay banned.

`.agents/rules/verify/references/testing.md`:

- Smallest boundary first: pure unit, thin editor contract, golden I/O, then "Managed browser tests for native input, focus, selection, rendering and real component interactions that the lower layers cannot prove" (`:7-14`).
- "A unit regression may accompany a browser regression when they guard distinct failure boundaries. Avoid duplicate assertions, not necessary integration proof." (`:22-23`)
- One logical assertion per test (`:34`). No asserting private state, call order or implementation detail (`:41`). Prefer explicit assertions over snapshots (`:49`). No spec imports another spec (`:46`). No app-registry imports in package tests (`:53`).
- "never turn an unavailable browser/device case into a passing no-op or erase its coverage gap." (`:51-52`)
- Fake runtimes must exercise both directions of a boundary, and "A fake runtime cannot certify native browser behavior." (`:76-99`)
- Fast-lane timing budgets are enforced by `bun run test:slowest`, and slow cases move to `*.slow.*` rather than being split (`:55-57`).

`editor-proof.md` adds shape bans for browser rows: no project-gated `return` (fake green, `:67-81`); no single-DOM-text-node row standing in for rich-text coverage (`:98-103`); vertical Shift+Arrow rows must run the reverse leg (`:60-65`); complete-vs-virtualized parity is never sufficient alone (`:63-65`). `docs/vision/plite.md:439-440` allows route-local Playwright only for first reproduction and says a repeated action or assertion moves into `@platejs/test`.

## Pressure

### Where the stack is strong

- **One oracle reads model, DOM and native state together.** `createBrowserEditorHarness` reads model value, model selection, DOM selection, displayed selection, focus owner, kernel trace, last commit and history from the same mounted root (`harness.ts:133-209,420-432`). The caret and selection assertions (`collapsedModelDOMSelection`, `noDoubleSelectionHighlight`, `caretVisibleInScrollableParent`) catch model/native splits that unit tests cannot see. Cases D18 and D04 closed on exactly those reads.
- **Native input where Chromium allows it.** Trusted typing goes through `page.keyboard`, IME through CDP `Input.imeSetComposition` (`ime.ts:309-321`), and clipboard through real clipboard permission (`apps/plite/playwright.config.ts:47`). CDP composition caught D01 after the jsdom suite missed it.
- **Honest claim labels.** Scenario runs carry a transport claim (`types.ts:733-745`). The raw-device validator fails closed (`tooling/plite/donor/proof/mobile-device-proof.mjs`, `packages/test/test/proof/mobile-device-proof-command.test.ts:29-40`). Doctrine separates mobile viewport from raw device (`docs/vision/common.md:82-84`). Nothing in the stack silently counts emulation as device proof, except the paste fallback below.
- **Replay and reduction exist.** Declarative scenarios emit replay JSON and delta-reduction candidates (`harness-scenario.ts:114-118`), and seeded generated editing runs ship (`donor/stress/generated-editing.test.ts:39-48`).
- **The Chromium lane is disciplined and fast enough.** It allows no retries (`plite-browser-runner.mjs:69-77`), shards 4 ways with exact coverage merge, and reuses only fingerprinted results. 767 tests take about 7 to 8 min of wall time per push (`5036-complete-pushed-ci.md:76-115`).
- **Lessons become law.** `regression-oracles.md` turns each escaped false green into a required marker, so the same proxy does not certify the same class twice.

### Where it is blind

- **Paint.** Headless Chromium never paints a caret (D07). Only 2 of 20 drift cases closed on a controlled pixel classifier (D06, D07). Native OS caret paint is unverified (`docs/editor-behavior/current-evidence.md:29`).
- **Real OS IME, Safari, phones and screen readers.** CDP composition is not an OS input method (G01, D02 open). Playwright WebKit is not Safari, and WebKit has no composition protocol at all (`autocomplete-ownership.md:186-189`). No Android or iOS device has run (G05, G06). Nothing in the repository drives a device; the receipt validator has no producer (gates Tooling). 387 of 704 mobile-viewport rows skip (`2026-08-01-final-wordgard-adoption-plan.md:394`). No screen reader has ever run (G04, G13). 6 of 16 open gates name no owner, and the rest scatter across six owner strings for a lane that does not exist.
- **Reporter environment, physical pointer and focus timing.** 12 of 20 drift cases went red only in the installed Google Chrome binary, headed Chrome or Computer Use OS input. In 12 of 20 the reporter, not the suite, contradicted a claimed fix. Repeat failures cluster on focus and popup (D12 8 failed fixes, D14 6, D15 5).
- **Engines other than Chromium between manual runs.** PRs and pushes run Chromium only. Firefox, WebKit and mobile run only on `workflow_dispatch` (`plite-ci.yml:347,432`), and that matrix repeatedly found WebKit caret and focus defects after Chromium passed (`5036-complete-pushed-ci.md:98-108`).
- **Suites no workflow runs.** `apps/www/tests/browser` (44 files, 295 tests per project, 885 in total) and `tooling/e2e` (10 files) are in no workflow. Yet the www suite owns most Plate UI reporter cases: comment, suggestion, combobox, table selection, homepage IME drag scroll and block-void caret (D02, D03, D05, D06, D07, D09, D13, D14, D15). Those regression tests only fail when someone runs them by hand.
- **Proxies inside green specs.** Synthetic shortcut keys, silent paste fallback and handle writes (section 3, drift paths 1 to 3) let a spec pass while the native path is broken. The same `__pliteBrowserHandle` is both the oracle and a back channel for input, and 133 raw references to it sit in specs outside the harness.
- **Unit DOM shims.** happy-dom (all Bun tests) and jsdom (Plite React) differ from each other and from browsers on focus and selection. Nine drift cases had a green unit, package or detached-editor test first.
- **The browser gate does not block.** Plite CI is not a required check (`2026-09-29-optimise-github-actions.md:107`), and day-to-day work lands by pushing to `next`. Plite push runs failed 18 of 39 in the sample (`:130`).

### The most expensive part

- **By runner minutes: the manual five-project browser matrix.** It took 5,354 of 8,026 Linux-equivalent minutes in 14 days (66.7%), over 18 dispatches with a median of 10.5 min wall (`2026-09-29-optimise-github-actions.md:86-88`). WebKit runs on `macos-latest` runners (`plite-ci.yml:431`).
- **By engineering time: the failed-fix and proof ritual.** Proxy greens get contradicted after the fix, and each contradiction costs another exact-Chrome or Computer Use replay with five warm runs: 8, 6, 5 and 4 failed fixes in D12, D14, D15, D03 and D16. 212 of the 586 plans dated 2026-08 or later mention five warm runs or `repeat-each=5` (grep), and the oracle law it produced is 564 lines. This is inferred to be the dominant cost: suite wall time is minutes, while a failed-fix loop spans several sessions and attempts per case.
- **By code: the Playwright corpus.** 100 spec files and 60,562 lines, with `donor/examples/richtext.test.ts` alone at 7,809. The harness adds about 12,000 lines in `packages/test/src/playwright`. 767 Plite tests run on four engine projects, and 48 of the 56 Plite files sit under `donor/`, which reads as ported Slate example and stress suites (inferred from the path and the transplant history).

**Implication for the e2e tradeoff (judgment).** The suite's wall time is not the cost: about 8 min on Chromium per push, about 11 min for the full matrix. The cost is the gap between what the suite can observe (Chromium, CDP input, DOM and model state) and what reporters see (installed Chrome with a real profile, painted pixels, OS IME, Safari, phones). Adding more Playwright rows does not close that gap. A lane that replays the reporter's route with physical input in the real browser and judges inspected pixels targets the 12 of 20 cases that needed it, so any agentic e2e candidate should be measured against those cases. The cheap structural repairs sit inside the current stack. Run the www suite in CI, at least on Chromium. Make the paste fallback and synthetic shortcuts report themselves as proxy transports. Give the device lane one owner and a producer.
