## Overview
The query is ordinary document text. Each mounted Editable that hosts at least one popup gets one private ComboboxOwner (O:75), found by element in a module WeakMap (O:61, O:441-450). The owner holds at most one occurrence, rebuilds a match snapshot from anchors plus the selection on every commit, view-state change, composition or input DOM event and document focusin (O:405-420), claims five keys before Plate's shortcut table, is the only writer of the Editable's ARIA, and completes in one new-batch update. Popups are afterEditable slot components (P:306-321) that call useCombobox through the copied InlineCombobox.

## Load-bearing decisions
1. Query text is document text; popup state is view-local, one owner per Editable element (O:61, O:441).
2. Only locally typed commits open an occurrence (M:13-50, O:243-248); Escape needs no dismissed state.
3. An occurrence is two anchors: a drop trigger range for identity and an outward typedExtent as the bound (O:277-282); the match is recomputed, never stored.
4. One owner multiplexes every popup; latest trigger start wins, then mount order (O:251-269); policy read live from plugin state.
5. Keys claimed before shortcuts through an element-keyed registry, five unmodified keys, not while composing (P:241, O:292-314).
6. Completion matches by value, settles input, rechecks inside one new-batch update, refuses by throwing to roll back (O:97-153).
7. The model decides eligibility and completion; the DOM preedit only previews the query (O:341-368).
8. The trigger scan is bounded (M:171-175).

## Gotchas
- complete captures occurrence before settleInput() (O:95); if settling commits text and replaces the occurrence, the old anchors resolve null and the call refuses.
- complete does not recheck isAnotherEditorFocused or triggerQuery.
- open reaches the hook one render late (IC:133).
- ARIA attributes are set imperatively on a React-rendered element; an app passing aria-controls itself would fight the owner.
- The key registry holds one handler per element; a second claimant silently replaces the first (editableKeyDown:13).

## Workarounds for missing primitives
- Which Editable holds a shared selection: DOM activeElement check plus document focusin (O:223-230, O:420), because Plite's focus flag trails the DOM.
- Key arbitration: a key-claim WeakMap around PlateContent's onKeyDown (editableKeyDown:7-22, P:239-242), blind to keys Plite's capture handler consumes (runtime-keyboard-events.ts:563-575).
- Owner discovery: element-keyed WeakMap instead of a context (O:61).
- Composition preview: DOM listeners plus Range.toString() with U+FEFF stripping (O:54-59, O:371-389), holding the old match while the model lags (O:353-358).
- WebKit confirming Enter: keyCode 229 check (O:302-304).
- No "end composition" operation: IC lets the option's mousedown blur the editor (IC:206-209).
- No text-run read: the matcher walks sibling leaves by index and maps offsets back to points by hand (M:52-96, M:117-129).
- No transaction abort: refusal throws a private symbol; async callbacks caught by a thenable check (O:60, O:63-64, O:145-148).
- No bound on typed text: a second anchor, typedExtent, exists only to bound the query (O:277-280).
- No mounted runtime: settleInput falls back to "not composing" (with-react.ts:57-60).
- Custom triggers in stored inputs: migration falls back to default trigger literals (I:15-19, I:43-48).
