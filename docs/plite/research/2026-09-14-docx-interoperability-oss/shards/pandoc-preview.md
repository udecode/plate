**Pandoc findings**

- **P1 — Adopt as a semantic reference/oracle candidate; reject as a preservation engine.** The reader returns `Pandoc meta blks`, with media handled separately. The writer accepts a Pandoc document, generates document/comments/relationships/content-type parts, and assembles an `emptyArchive`. A reference DOCX supplies selected styles, layout, headers/footers, fonts, media, and ancillary entries; it does not preserve every original part. This is regeneration from an AST, even when the input document is also chosen as the reference. Evidence: [reader](/Users/zbeyens/git/pandoc/src/Text/Pandoc/Readers/Docx.hs:107), lines 107–122 and 342–348; [writer](/Users/zbeyens/git/pandoc/src/Text/Pandoc/Writers/Docx.hs:65), lines 65–88, 125–171, 496–513, 842–874.

- **P2 — Adopt explicit revision/comment import policy as a reference behavior.** Accept/reject/all is a real branch in the converter. Comments survive only `AllChanges`; accept and reject both remove their markers and bodies. Moves are normalized to insertion/deletion. Original change IDs are discarded when forming AST spans, and the writer allocates new IDs. Thus `AllChanges` preserves selected revision meaning, not original move pairing or revision identity. Evidence: [reader](/Users/zbeyens/git/pandoc/src/Text/Pandoc/Readers/Docx.hs:389), lines 389–422; [parser](/Users/zbeyens/git/pandoc/src/Text/Pandoc/Readers/Docx/Parse.hs:1354), lines 1354–1367; [serialization](/Users/zbeyens/git/pandoc/src/Text/Pandoc/Writers/Docx/OpenXML.hs:890), lines 890–915. The reader also emits paragraph-insertion/deletion marker classes, lines 749–775. Scoped writer search found no matching paragraph-marker handling, and the general span serializer recognizes exact insertion/deletion classes, lines 872–922. **Defer paragraph-revision round-trip claims:** this is a source-inferred gap, not an executed failure.

- **P3 — Adopt concrete loss cases; reject warning-free as a fidelity certificate.** Comment blocks are flattened to inlines; non-paragraph structures produce a warning. Export reconstructs comment content inside one paragraph. Charts and diagrams become placeholders. Parser helpers catch errors and return no elements, without adding a diagnostic there. Writer raw OpenXML passthrough exists, but does not reconstruct source content already discarded by import. Evidence: [reader](/Users/zbeyens/git/pandoc/src/Text/Pandoc/Readers/Docx.hs:347), lines 347–367; [parser](/Users/zbeyens/git/pandoc/src/Text/Pandoc/Readers/Docx/Parse.hs:148), lines 148–154, 502–513; [comment writer](/Users/zbeyens/git/pandoc/src/Text/Pandoc/Writers/Docx/OpenXML.hs:309), lines 309–326, 537–543, 947–952. Existing warnings are useful but not an exhaustive inventory of dropped OOXML or package parts.

- **Tests support selected semantics, not complete round-trip fidelity.** Reader tests compare imported ASTs to native goldens and explicitly inspect warning logs; they cover accept/reject/all, comments, moves, paragraph revisions, and scrubbed metadata. Writer tests register native-to-DOCX goldens for insertion/deletion/moves/comments and directly inspect selected reference XML properties. Evidence: [reader tests](/Users/zbeyens/git/pandoc/test/Tests/Readers/Docx.hs:36), lines 36–57, 397–487; [writer tests](/Users/zbeyens/git/pandoc/test/Tests/Writers/Docx.hs:47), lines 47–53, 206–232, 281–325. A coverage caution: the test labelled “keep insertion (all)” actually uses the deletion fixture, reader-test lines 422–429. Test names alone overstate distinct coverage. The shared OOXML golden-comparison helper and fixture contents were not inspected.

**docx-preview findings**

- **D1 — Reject as an editable-model-to-DOCX writer.** `WordDocument` loads the ZIP and recognized relationship parts; `save()` delegates directly to the retained package. Package save calls JSZip generation. A separate `Part.save()` serializes its retained XML DOM, which is kept only with `keepOrigin`; that flag is absent from the public option interface/defaults. No save caller that flushes parts or serializes parsed-model/HTML edits appeared in the scoped source search. Evidence: [document](/Users/zbeyens/git/docxjs/src/word-document.ts:53), lines 53–72, 74–158; [package](/Users/zbeyens/git/docxjs/src/common/open-xml-package.ts:7), lines 7–34; [part](/Users/zbeyens/git/docxjs/src/common/part.ts:13), lines 13–28; [public API](/Users/zbeyens/git/docxjs/src/docx-preview.ts:6), lines 6–49, 52–77. **Inference:** unmodified/unrecognized ZIP entries can remain available for regeneration even when absent from the projection. This is package retention, not proof of byte-identical ZIP output, valid relationship-preserving edits, or an OOXML writer.

- **D2 — Adopt as a preview candidate and source reference; defer fidelity claims.** The parser retains ordinary comment IDs, author, initials, date, body, and range markers. The renderer builds comment ranges and popovers; range highlighting depends on the browser Highlight capability. Insertion/deletion metadata is parsed, and enabled rendering emits `ins`/`del`. Defaults hide comments, display inserted text without change markup, and suppress deleted text. The full paragraph dispatcher has ins/del cases but no moveFrom/moveTo cases; no reject-all or edit/accept/reject transaction API is established here. Evidence: [parser](/Users/zbeyens/git/docxjs/src/document-parser.ts:87), lines 87–100, 479–549, 631–654; [renderer](/Users/zbeyens/git/docxjs/src/html-renderer.ts:82), lines 82–84, 127–129, 947–994, 1048–1073; [defaults](/Users/zbeyens/git/docxjs/src/docx-preview.ts:29), lines 29–48. Extended comments parts are loaded (word-document lines 136–142), but reply/resolution/thread fidelity was not established.

- **D3 — Defer Word-equivalent layout and repeat-render guarantees.** Pages are formed from section/page-break cues, with cached last-rendered page breaks ignored by default; headers, footers, and notes are projected into DOM. The inspected pagination path splits and mutates parsed paragraph/run children. That projection should not be treated as an immutable canonical editing model. Evidence: [renderer](/Users/zbeyens/git/docxjs/src/html-renderer.ts:325), lines 325–367, 402–409, 421–508, especially 460–475; [default options](/Users/zbeyens/git/docxjs/src/docx-preview.ts:29), lines 29–48. This source path does not prove Word's layout, overflow repagination, or repeat-render correctness. No browser comparison was performed.

- **D4 — Reject projection tests and console warnings as preservation proof.** Unknown body/paragraph children have no default diagnostic in the inspected dispatchers; unsupported styles can yield debug-only console warnings. Render fallback returns null. There is no structured loss report returned by the inspected public pipeline. Evidence: [parser](/Users/zbeyens/git/docxjs/src/document-parser.ts:127), lines 127–150, 286–287, 493–549, 1378–1389; [renderer](/Users/zbeyens/git/docxjs/src/html-renderer.ts:870), lines 870–896; [API](/Users/zbeyens/git/docxjs/src/docx-preview.ts:52), lines 52–77. The [render test](/Users/zbeyens/git/docxjs/tests/render-test/test.spec.js:1), lines 1–54, enables `renderChanges` and compares whitespace-normalized HTML. It includes a revision fixture but does not enable comments, assert export, or compare screenshots. No comment/save tests appeared in the scoped test search.
