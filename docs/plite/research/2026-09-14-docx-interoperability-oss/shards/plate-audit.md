**Critical source findings and strongest cuts.** These are current-source conclusions. Unexecuted reproduction predictions are labeled; main supplies runtime confirmation independently.

1. **Stale native data overrides current Word content.** [importDocx.ts:464](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/import/lib/importDocx.ts:464) checks for `editor/authored.json`, deserializes it, and returns at 475 with its children, empty comments and empty warnings. Only line 482 opens `word/document.xml`. [deserializeAuthoredJson:318](/Users/zbeyens/git/plate-2/packages/plitejs/src/authored/format.ts:318) validates JSON/document shape, not agreement with the DOCX. Export [authoredDocx.ts:279](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/authoredDocx.ts:279) writes raw document JSON and package metadata without binding it to the generated Word parts. Import does not validate the authored relationship either. **Cut unconditional sidecar authority.** Native metadata may supplement a verified corresponding document; a changed package requires explicit reconciliation/fallback/conflict handling. A check only of document.xml would omit changes to relevant styles, numbering, relationships, comments and media. Native Word preservation of the custom part remains untested here.

2. **Export can create inconsistent parts itself.** [authoredDocx.ts:331](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/authoredDocx.ts:331) captures the review snapshot; line 345 awaits conversion; line 348 embeds a fresh `editor.read.value()`. Edits during that await can separate visible XML from native JSON. **Replace separate live reads with one immutable capture for every emitted part.** Main owns the race/authority replay; sidecar has not claimed runtime reproduction.

3. **Review mode has a second, less capable serializer.** [options:26](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/authoredDocx.ts:26) inherits `DocxExportOptions`, including editor plugins and static wrapper, but [review dispatch:344](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/authoredDocx.ts:344) bypasses those serializers. [ELEMENT_TAGS:44](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/authoredDocx.ts:44) and [marks:87](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/authoredDocx.ts:87) repeat literal schema interpretation. Recognized elements emit tag/href/revision attributes but not ordinary table spans, alignment, widths or other properties: [258](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/authoredDocx.ts:258). Unsupported node/leaf properties have some diagnostics; recognized element properties are not equivalently audited. **Delete the parallel schema serializer.** Compare reuse of configured semantic serialization with direct OOXML conversion. Do not simply call `renderAuthoredHtml`: its current review output is proposed HTML plus JSON, not Word revision markup ([authoredHtml.ts:72](/Users/zbeyens/git/plate-2/packages/platejs/src/static/authoredHtml.ts:72)). DOCX owns Word encoding; authored owns the canonical review model.

4. **Word formatting history is emitted empty.** [xml-builder.ts:1258](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/internal/xml-builder.ts:1258) writes `w:rPrChange` with empty prior `w:rPr`; [1779](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/internal/xml-builder.ts:1779) does the same for `w:pPrChange`. Import restores those prior properties ([importDocx.ts:336](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/import/lib/importDocx.ts:336)), so arbitrary previous formatting cannot survive rejection. The existing test covers plain-to-bold and paragraph-to-heading, then validates native JSON ([authoredDocx.spec.ts:42](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/authoredDocx.spec.ts:42)). Actual before/after properties already exist at [format.ts:267](/Users/zbeyens/git/plate-2/packages/plitejs/src/authored/format.ts:267). **Reuse those values; delete fabricated empty history or diagnose an unsupported encoding.** No authored-state redesign is needed to establish this format defect.

5. **The copied import action drops the canonical document and all feedback.** [import-toolbar-button.tsx:60](/Users/zbeyens/git/plate-2/apps/www/src/registry/components/editor/import-toolbar-button.tsx:60) always replaces with `result.nodes`, ignoring `document`, `comments` and `warnings`. A rejected HTML decode returns empty nodes and a warning ([importDocx.ts:163](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/import/lib/importDocx.ts:163)); the action can therefore replace current content with an empty import. Docs correctly demonstrate whole-document replacement for authored imports ([docx.mdx:117](</Users/zbeyens/git/plate-2/content/docs/(plugins)/(serializing)/docx.mdx:117>)). **Reuse `editor.update.value.replace` for canonical documents and make failure/partial conversion actionable.** Comment storage remains a distinct product owner. Export's copied action also takes only canonical children ([export-toolbar-button.tsx:153](/Users/zbeyens/git/plate-2/apps/www/src/registry/components/editor/export-toolbar-button.tsx:153)), offering no explicit authored projection or review-loss feedback.

6. **Paste intentionally discards images and table geometry.** After private Word cleanup, [DocxPlugin.ts:355](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/paste/lib/DocxPlugin.ts:355) removes every image. The fragment hook removes table columnWidths, cell borders and cell size at [374](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/paste/lib/DocxPlugin.ts:374). Image deletion is an explicit passing test, not an inferred regression ([DocxPlugin.spec.ts:387](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/paste/lib/DocxPlugin.spec.ts:387)). **Challenge blanket deletion; preserve supported information through installed codecs with explicit limits.** Keep media security and table placement with their existing owners. CSS inlining also serves non-Word HTML ([DocxPlugin.ts:151](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/paste/lib/DocxPlugin.ts:151)); moving it behind Word detection would regress a real job.

7. **Private cleaner still has smaller fidelity defects recorded in old history.** It reads `backgroundColor` but never transfers it to the generated span, and tests `color` before copying `fontStyle`: [cleanWordHtml.internal.ts:474](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/html/cleanWordHtml.internal.ts:474), [503](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/html/cleanWordHtml.internal.ts:503). **Repair the existing cleanup owner rather than adding another public normalizer.** These are bounded source defects; the final DOM effect depends on downstream codecs. Previously noted parenthesized-list-marker concerns are not carried forward blindly: current explicit tests cover them ([DocxPlugin.spec.ts:142](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/paste/lib/DocxPlugin.spec.ts:142)).

8. **Ordinary export has no diagnostic channel for missing content.** [exportToDocx.tsx:80](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/exportToDocx.tsx:80) returns only Blob. [xml-builder.ts:343](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/internal/xml-builder.ts:343) silently rejects WebP and catches image fetch failure; [407](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/export/lib/internal/xml-builder.ts:407) swallows invalid/unavailable image errors and returns null. Remote images remain opt-in, a boundary to preserve. **Unify conversion loss reporting at the file-export result, including normal exports.** Do not equate a valid ZIP with successful preservation.

9. **File import mixes direct XML revision handling with repeated HTML projections.** [importDocx.ts:385](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/import/lib/importDocx.ts:385) creates a baseline and one cumulative projection per revision; each rewrites/repackages the ZIP and calls Mammoth/HTML decoding. **Strongest replacement candidate: a direct OOXML adapter for file structure and revisions.** This can remove the repeated format translations as an ownership target, but no performance acceptance follows from source. Installed schema limits, external unsupported constructs and correctness still need proof. Keep Word clipboard HTML/RTF processing separate.

10. **Public dependency teaching lags the import graph.** Source directly imports JSZip ([importDocx.ts:3](/Users/zbeyens/git/plate-2/packages/platejs/src/docx/import/lib/importDocx.ts:3)); the entrypoint DAG declares jszip and mammoth ([entrypoint-dag.mjs:309](/Users/zbeyens/git/plate-2/tooling/entrypoints/entrypoint-dag.mjs:309)). The DOCX import install command lists mammoth and validator but not jszip ([docx.mdx:89](</Users/zbeyens/git/plate-2/content/docs/(plugins)/(serializing)/docx.mdx:89>); CN line 88). **Repair dependency teaching and verify isolated consumer installation; do not infer failure merely from a transitive installation arrangement.** Both file converters now depend on authored in the DAG; September 8's historical packed proof must not certify this changed graph.
