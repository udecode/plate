## SuperDoc: current public v2 boundary, incomplete engine evidence

- **License and availability:** root `LICENSE:1-40,540-550` is AGPLv3 (R11); README `103-107` advertises commercial licensing (R10). Crucially, `apps/docs/content/docs/resources/docx-engine-license.mdx:13-21` explicitly distinguishes the AGPL editor from the proprietary, non-OSS `@superdoc/docx-engine` (R14). This is the repository's license statement, not a legal-enforceability opinion. No proprietary artifact was downloaded, installed, inspected or executed.
- **Current architecture claim:** `README.md:75-84` says v1 used ProseMirror authority and v2 uses an OOXML-backed model (R10). Actual public v2 source, `packages/superdoc/src/core/v2-integration/v2-integration.js:1-18,40-64`, imports the separate engine and consumes its integration factory (R21). `packages/superdoc/package.json:128-129` pins engine `0.14.0-next.11`; the shell version is `2.15.0-next.12` at line 4 (R19). A current recursive Git-tree filename census found no engine implementation tree. Therefore OOXML authority is a current public architecture declaration corroborated by the integration boundary, **not an inspection of the engine's mutation or serialization implementation**.
- **Export contract:** `packages/document-api/src/export/export.types.ts:13-55` defines default `review-preserving`, `final`, and `original`, plus byte length, base64 bytes and structured warnings (R12). Its comments promise warnings only for allowed degradation and failure before bytes for forbidden semantic loss. `export.ts:42-72` actually validates mode before checking adapter availability or invoking the adapter (R13). The shared public layer does not implement serialization or warning generation. The [official reference](https://docs.superdoc.dev/document-api/reference/export/to-docx/) agrees with these mode semantics.
- **Distinct owners:** Document API validates intent; the engine adapter/session serializer owns byte production, review projection and degradation reporting; the SuperDoc shell owns orchestration/download/error propagation. `packages/superdoc/src/core/SuperDoc.ts:4161-4206` delegates to mounted `editor.exportDocx`, supplies comments policy rather than a v2 legacy comments payload, and rethrows a v2 generation error (R22). It can return original stored data for an absent exporter or a falsy export result, so “no fallback ever” would overstate the source. Word-paste normalization internals were not available in this public engine boundary.
- **Strongest inspected tests:** `document-api/src/export/export.test.ts:6-19,22-71` uses a stub adapter to assert defaults, all modes, invalid input before adapter work, and missing capability (R18). It does not produce a real DOCX. `SuperDoc.export.test.ts:45-118` uses mocked exporters to assert v2 generation failures reject without downloading and successful export returns edited bytes rather than the opened file (R23). These prove intended boundary behavior only; not roundtrip package integrity.
- **Not established:** preservation of untouched/unknown OPC parts, relationship graphs, XML extensions, styles/numbering identities, comments/anchors, embedded media, section/header/footer variants, revision semantics through save/reopen, actual degradation detection, or Word-paste fidelity. Public API types and mocked tests cannot establish those engine behaviors. The actual current v2 serializer source was unavailable in the named public repository, so Main's direction to read actual v2 source before claims limits claims to the public v2 source just identified.

Narrow proof ideas for Main: test invalid export intent causes zero document work; an active edited session must not silently return its original uploaded file after serialization failure. For a separately justified package-retention implementation, independently authored DOCX fixtures should verify untouched-part hashes and relationship reachability after no-op save and one local edit; compare review/final/original exports semantically while the live source document remains unchanged. These are proposed acceptance checks, not upstream engine tests or behavior reported as passing.

## CKEditor 5: inspectable Word-paste normalization, separate DOCX service

- **License:** `packages/ckeditor5/LICENSE.md:7-14` and `packages/ckeditor5-paste-from-office/LICENSE.md:7-10` specify GPL version 2 or later, or commercial terms (R24–R25). Root LICENSE in the preliminary checkout delegates to the package license (R05). No source or fixture content was copied into Plate.
- **DOCX ownership:** `docs/features/cloud-services-overview.md:47-67` describes DOCX→HTML import and HTML→DOCX export as Cloud Services converters (R30). Filename discovery found no corresponding converter implementation in the inspected public Git tree; assets/icons are not implementation. This corpus therefore does not demonstrate retention of arbitrary original package parts across import/edit/export. That is a proof limit, not an assertion that every proprietary conversion loses them.
- **Clipboard ownership and invariant:** `pastefromoffice.ts:107-138` uses raw clipboard `text/html` only to detect Office, parses/processes `data.content`, and applies matching normalizers at high `inputTransformation` priority (R26). `mswordnormalizer.ts:22-27,61-78` detects Word/Office namespaces and Excel, then orders bookmarks → lists → RTF images → tables → invalid widths → footnotes → removal of MS attributes (R27). Format interpretation belongs here; `clipboardpipeline.ts:249-282` separately converts normalized view through `data.toModel(..., '$clipboardHolder')` and fires insertion in one model change block (R34).
- **Normalize before discarding evidence:** `parse.ts:25-63,97-107` parses clipboard HTML, normalizes spacing, keeps usable head stylesheet text, removes body style blocks and omits comments (R28). `removemsattributes.ts:18-54` finally strips mso classes/styles and unwraps selected Word wrappers (R43). This is intentionally normalization for a destination editor, not preservation of all original Office metadata.
- **Lists depend on identity and destination capability:** `list.ts:57-125` tracks continuation counters by list identity and level, scopes resets, and keeps or clamps indent gaps based on `enableSkipLevelLists`; `130-157` creates intermediate unnumbered wrappers for the enabled case (R31). Current `pastefromoffice.ts:91-101` passes plugin capabilities and that setting (R26). The May checkout lacked this argument and also lacked current Excel detection; freshness mattered to the facts.
- **Images require the actual clipboard payload:** `image.ts:26-41,241-267,300-352` handles shapes separately, selects local-file images, keeps their index among all images and substitutes PNG/JPEG data from RTF when present (R32). Missing RTF leaves unresolved local sources at this filter. `tests/filters/image.js:35-62` explicitly expects empty/no-image RTF to leave input unchanged and HTTP sources to stay unchanged (R38). No arbitrary shape/vector or missing-clipboard-asset fidelity follows.
- **Footnotes require linked content:** `replacemsfootnotes.ts:60-139` collects references and definitions, returns without normalization if the definitions list is absent, skips unmatched references, and moves matched definition content into the target footnote structure (R33). `tests/filters/replacemsfootnotes.js:185-219` asserts the missing-definitions-list case (R39). It is not proof of DOCX footnote-part retention.
- **Strongest test design and its limits:** `tests/README.md:3-20` specifies captured native clipboard fixtures with browser variants, original documents, normalized output and model expectations (R35). `tests/data/normalization.js:15-62` and `tests/data/integration.js:26-85,115-128` keep normalization separate from feature-configured integration (R36–R37). The helper compares normalized view; its integration spy captures the model fragment **before** insertion, not final post-fixer state, and both comparators permit NBSP/space equivalence (`tests/_utils/utils.js:185-207,232-245,307-351`, R42). Safari/Edge skips are explicitly present. Thus this fixture suite is not proof of exact whitespace, final destination fitting, all browsers, or native Word rendering.
- **Concrete proof warning:** the continuation fixture's normalized HTML includes `<ol start="3">` at line 16, while its expected model, lines 1-9, has no restart attribute (R40–R41). This is an observed expected-artifact difference under the suite's configuration, **not a replayed bug or a general claim that CKEditor cannot preserve list starts**. It illustrates why normalized HTML alone is insufficient.

The documentation explicitly conditions preservation on the enabled editor features (`docs/features/paste-from-office.md:37-38,64-68`, R44). Its broad VML non-support statement at line 94 is not promoted here: the current image source already contains shape/image handling, so that documentation line cannot establish a blanket current implementation limit without a specific fixture.

Narrow proof ideas for Main: use independently authored native clipboard HTML+RTF captures and assert (1) normalized fragment, (2) destination model after fitting, and (3) final observable list numbering/media/footnote behavior. Prioritize an interrupted/restarted list with skipped levels under supported/unsupported destination configuration; mixed inline/HTTP/file images with present and absent RTF; and footnote references with/without definition content. Preserve exact significant whitespace in the oracle rather than borrowing the upstream comparator's NBSP equivalence. These are test ideas; no upstream tests were run.

## Bounded Best API Review input for Main

The maximum-value hard-cut counterfactual is to remove a mandatory lossy HTML/editor-tree reconstruction from the **DOCX package-retention** job if that representation cannot retain the required package information. Either a package-backed editing owner or an explicit retained-package companion must earn its complexity against independently verified retention laws. Current SuperDoc publicly claims the former direction; its OSS boundary does not prove the implementation.

That cut does **not** collapse Word paste into DOCX import: a clipboard fragment may never contain the original package, and the destination schema legitimately constrains it. Reuse destination conversion/insertion for fitting; keep Word-specific interpretation with the ingress converter; keep serialization/retained parts with the package owner. A generic “Office” plugin, duplicate insertion pipeline, or promise that one HTML representation preserves every package concern has no supporting current job in these two corpora.

Lanes screened: keep/configure is valid for bounded paste fidelity when destination features suffice; repair existing conversion owners before introducing public nouns; a retention primitive earns consideration only for actual package information the model cannot retain; moving ownership to the package level is the strongest architecture alternative. Main must compare that against Plate's current owner and the other five corpora before choosing a target. No Plate design or adoption verdict is implied.
