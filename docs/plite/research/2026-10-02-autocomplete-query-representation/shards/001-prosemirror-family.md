## Shared ProseMirror mechanics that shape every design

- prosemirror-view never calls `handleKeyDown` during composition, and drops one Safari Enter within 500 ms of `compositionend` (`src/input.ts:109`, `:435-452`). A doc-text menu wired through `handleKeyDown` inherits this guard for free. ProseKit's and BlockNote's DOM listeners do not, which is why they re-implement it.
- On Chrome Android, Enter keydowns never reach `handleKeyDown` (`src/input.ts:115`). The editor reads the browser's paragraph split and replays a synthetic Enter (`src/domchange.ts:89-91`, `:124-127`, `:181-189`, `:212-219`). Android compositions time out after 5 s of inactivity (`src/input.ts:454-455`), and the editor is "almost always composing" there (`:656-660`).
- When a decoration change would redraw the focused composition text node, prosemirror-view keeps that node as a `CompositionViewDesc` (`src/viewdesc.ts:807-812`, `:835-848`). That is what lets an inline query decoration appear around text mid-composition without killing the IME.
- prosemirror-inputrules skips during composition (`src/inputrules.ts:113`) and in code (`:119-128`), but knows nothing about autocomplete. Only a plugin that claims `handleTextInput` first keeps rules off query text.

## Pressure on Plate

### For a transient input inside an inline void

1. The one large PM-family product that isolates the query, Atlassian, gets correct combobox ARIA on the focused element as a direct result (`InputQuery.js:444-449`, A). Every doc-text editor read here gets it wrong or skips it. ProseKit puts `aria-activedescendant` on an unfocused listbox (`listbox-root:245`, A). BlockNote sets it on the contenteditable without `role=combobox` (`SuggestionMenuWrapper.tsx:60-88`, A). Tiptap and Milkdown ship none (A).
2. Doc-text menus keep reopening composition bugs in menu state. Tiptap needed #1449's composing carve-out (commit `9789372ce`, A). BlockNote still closes the menu mid-Chinese-IME at HEAD, with four fix PRs unmerged (#1283, #2731, B). ProseKit shipped a WebKit `compositionend` workaround and still has an open PR for Pinyin Enter selecting an item (#1759, #1743, B).
3. Doc-text queries leak to collaborators and let remote transactions drive the local menu. Tiptap added `shouldShow` for this (#7384, B). BlockNote needed Yjs relative positions for the range (`positionMapping.ts:4-41`, A). An isolated query sidesteps both (Atlassian `main.js:18-27`, A).
4. Input rules, autoformat and stored marks apply to doc-text queries unless a plugin claims `handleTextInput` (tiptap, BlockNote and Milkdown have no guard, A). Isolation makes that impossible by construction (Atlassian `decorations.js:120-127`, A).

### Against it

1. Four of the five PM-family editors read, plus `prosemirror-suggest`, keep the query as ordinary document text. Tiptap, ProseKit, BlockNote and Milkdown are cited above, all A. Isolation is the outlier, not the family norm.
2. Isolation's bill at Atlassian is large and visible in source. Custom `InsertTypeAheadStep` stages make undo and collab rebase coherent (`insert-type-ahead-item.js:69-108`, `reducer.js:8-23`, `main.js:18-27`). Undo is intercepted inside the input (`InputQuery.js:209-212`, `:311-325`). There are Safari-only `beforeinput` and undo branches (`:329-368`), a guard for Chrome and Edge spurious focusout (`:288-295`) and focus scheduling races (`:65-93`). Composition can duplicate the trigger before the widget (`open-typeahead-at-cursor.js:75-89`), and fullwidth `／` needs its own composition path (`main.js:111-153`). All A.
3. The closest Android evidence is hostile to an inline void. In ProseMirror #903, reported by an Atlassian engineer, Android Chrome treats an adjacent `contenteditable=false` inline as part of the active composition and copies its text into the focused node. The ProseMirror maintainer gave up on hiding it (B). The Atlassian type-ahead has no Android branch at all (not found, A), so there is no evidence that isolation was ever proven on Gboard.
4. Doc-text designs get IME for the query characters themselves for free. The browser composes in the main contenteditable, and prosemirror-view protects the composition node from redraws (`viewdesc.ts:807-848`, A). The remaining doc-text bugs are in menu state (open, close, Enter routing), which is fixable state logic. They are not text-entry failures.
5. ProseKit shows the doc-text failure modes can be closed without custom steps. It opens only on a local typed trigger (`autocomplete-plugin.ts:22-27`, A), keeps a sticky ignore list mapped through remote edits (`:125-135`, A), and does not reopen on undo (`:138-141`, A). The ARIA gap is separable. BlockNote already puts `aria-activedescendant` and `aria-expanded` on the contenteditable, and adding `role=combobox` there is a smaller change than moving the query out of the document (inferred).
6. Moving DOM focus into a native input ends any Gboard composition in flight, and Android is "almost always composing" (`prosemirror-view src/input.ts:656-660`, A). Inferred: an input that grabs focus right after the trigger fights the IME at exactly the moment the user is mid-word.
