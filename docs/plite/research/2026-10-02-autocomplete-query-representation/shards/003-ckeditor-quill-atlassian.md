## Pressure on Plate

The question: should Plate move from "query is ordinary editor text" back to "query lives in a transient native input inside an inline void"?

For an isolated input:

- Atlassian, the most mature of the three, did move the query out of the document, from a `typeAheadQuery` mark to a widget decoration, in editor-core 149.0.0 (2021-08-26). (A for both designs, B for the changelog.)
- The mark design leaked into other features. Shared input-rule code had to skip `typeAheadQuery` text, emoji ASCII rules had to check it, and Android Q needed a `compositionend` hack for a doubled trigger. (A, editor-core@148.0.0 `utils/input-rules.js:62,195`, `ascii-input-rules.js:56-58`, `main.js:208-228`.) CKEditor has no such guard, so TextTransformation and Autoformat can fire inside a query. (A, absence after grep.)
- Accessibility is the clearest win. Atlassian's query element is a real `role=combobox` with `aria-activedescendant`, `aria-controls`, `aria-expanded` and `aria-autocomplete`, plus a polite live region. (A.) CKEditor exposes nothing and has an open screen-reader issue (#11710) where a commenter proposes a focused text field. (A, B.) quill-mention hangs `aria-activedescendant` on the whole editor root with no combobox role, and the validator flags it (#418). (A, B.)
- Collaboration comes free when the query is not document data. Atlassian peers never see an open query, and its flow-control step serializes as a no-op. (A, `steps/type-ahead.js:58-70`.) CKEditor keeps its marker local, but the query characters are still document text. (A for the marker, inference for peer visibility.)
- Undo can restore the open menu. Atlassian's undo of a completion reopens the menu with the query and selected index. (A.)

Against, or at least not supporting the specific proposal:

- Atlassian does not use a native `<input>` for the query. The query is a nested `contenteditable` span. The `<input>` is only an empty 5 px placeholder until the first query string exists. (A, `InputQuery.js:438-457`.) So Atlassian supports "isolated editable element", not "native input".
- Atlassian's container is a view decoration, not a document node. A Plate inline void is a document node, so it does not inherit Atlassian's collab invisibility or undo isolation without extra work, such as filtering the node from sync and history. (Inference about Slate/Plate semantics; Plate source not read in this shard.)
- The isolated design carries a large browser-workaround tax. Safari has its own undo and beforeinput branches. A Chrome/Edge spurious-focusout filter exists because of trigger duplication. A Firefox caret TODO (ED-17022) is open. Rich paste needed a fix (ED-28449). The query was lost on focus loss (ED-28214). An extra trigger appeared with composition (187.2.1, PM #903). Focus timing needed an experiment, and VoiceOver needed a refactor. (A in `InputQuery.js`, B in changelogs.)
- There are two undo stacks. Typing undo inside Atlassian's query is native contenteditable undo, and PM history is consulted only when the query is empty. (A, `InputQuery.js:209-212`, `decorations.js:68-89`.)
- Android evidence is absent. The current Atlassian type-ahead has no Android or mobile branch, and nothing in the changelog ties the decoration move to Android. Atlassian mobile historically used native bridges for type-ahead. (A absence, B.) The isolated design is not shown to be better on Android.
- IME is hard in both designs. CKEditor has open CJK issues on the in-document design: Korean dropdown only after composition (#15616), stray letter after a mention in Japanese (#6700). (B.) Atlassian's isolated design still shipped several composition fixes. (B.) Neither design is clean.
- Two mature editors keep the query in the document. CKEditor uses a local marker on the trigger plus live regex re-derivation; quill-mention uses integer positions. Both are simple. CKEditor's local, non-operation marker shows the trigger anchor can stay out of undo and sync without moving the query out of the document. (A, `markercollection.ts:314-320`.)
