---
title: "History Editor API"
description: "Read history state, replay complete batches, and control history grouping."
---

History adds an owner-local read group, a replay service, and transaction
controls for the update being built.

## Read API

#### `editor.read.history(): History`

Read the full history value.

#### `editor.read.history.hasUndo(): boolean`

Return whether the undo branch has a surviving mapped batch.

#### `editor.read.history.hasRedo(): boolean`

Return whether the redo branch has a surviving mapped batch.

#### `editor.read.history.pending(): "undo" | "redo" | null`

Return the replay direction currently waiting for a live-session owner. Pending
state belongs to this editor runtime and is not included in History JSON,
snapshots, or collaboration.

Use `editor.read.history().undos` and `editor.read.history().redos` when you need
the full immutable arrays. The same group is available as `state.history` inside
`editor.read((state) => ...)`.

## Replay service

#### `editor.api.history.undo(): Promise<HistoryResult>`

Claim and replay the current undo batch.

#### `editor.api.history.redo(): Promise<HistoryResult>`

Claim and replay the current redo batch.

```typescript
type HistoryResult =
  | Readonly<{ status: "applied" | "busy" | "empty" }>
  | Readonly<{
      status: "blocked";
      conflicts?: readonly string[];
      reason?: string;
    }>;
```

Both methods claim the current branch head before returning. Ordinary document
batches settle in that call. A live-session batch publishes its pending
direction while its external owner finishes. Document edits, selection updates,
and collaborative imports continue during that wait; another replay returns
`busy` without claiming a batch.

`blocked` reports an authored dependency conflict or a refusal from the
live-session owner and keeps that batch at the branch head. Invalid runtime use
and other failures reject. Invoke replay outside an active read or update.
Replay always applies the complete document-wide batch, including changes in
other roots.

## Transaction API

#### `tx.history.skip(): void`

Do not save the current transaction to history.

#### `tx.history.merge(): void`

Merge the current transaction into the previous compatible undo batch.

#### `tx.history.newBatch(): void`

Start a fresh undo batch for the current transaction.

## Update policy

#### `editor.update({ history: "skip" }, fn): void`

Run one update without saving it to history.

#### `editor.update({ history: "merge" }, fn): void`

Run one update that merges into the previous compatible undo batch.

#### `editor.update({ history: "new-batch" }, fn): void`

Run one update where the first write starts a fresh history batch, then the
rest of the callback merges into that batch.

Configure a direct write by calling `editor.update(policy)` first.

```typescript
editor.update({ history: "skip" }).text.insert("draft");
```

## Types

```typescript
import type {
  DocumentChange,
  EditorEffect,
  EditorSchemaIdentity,
  Selection,
} from "plitejs";

type History = {
  readonly redos: readonly Batch[];
  readonly revision: number;
  readonly schema: EditorSchemaIdentity;
  readonly undos: readonly Batch[];
};

type Batch = {
  readonly change: DocumentChange;
  readonly effects: readonly EditorEffect[];
  readonly selectionAfter: Selection;
  readonly selectionAfterRoot?: string;
  readonly selectionBefore: Selection;
  readonly selectionBeforeRoot?: string;
};
```

Persist the installed stacks with `History.toJSON(editor)`. Decode them with
`History.fromJSON(editor, json)`, then install the returned value through
`tx.history.restore(...)`. Custom standalone effects belong to an installed
plugin's `effects` resource so their keyed versioned codecs can decode the
batch. The version 4 envelope requires the current derived or named schema
identity and rejects `null` or mismatched schema semantics before decoding a
batch.

Compatible typing and same-node property updates coalesce from canonical
`DocumentChange` classifications and changed ranges. Grouping fingerprints are
runtime-only; loading persisted history starts a fresh automatic group.
