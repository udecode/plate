`plitejs/dom` is the DOM bridge for Plite editors. It owns DOM point/range
conversion, selection conversion, clipboard formatting, hotkey helpers,
contenteditable helpers, and DOM coverage metadata used by framework runtimes.
React apps normally use these APIs through `plitejs/react`.

## Usage

Framework runtimes usually call the DOM bridge through installed editor APIs.

```ts
editor.api.dom.focus();
editor.api.dom.clipboard.insertTextData(dataTransfer);
```

Use direct public imports from `plitejs/dom` for framework integration
code that needs DOM bridge helpers without React.

```ts
import { DOMCoverage, Hotkeys, isDOMNode } from "plitejs/dom";
```

## Public utility groups

`dom()` installs the DOM bridge plugin on a core editor.
`PliteDOMResolutionError` is the thrown error type for failed assert-style DOM
resolution.

`DOMCoverage.create(editor)` creates a view-local session for hidden, external,
and virtualized same-root coverage metadata.

`Hotkeys`, `isHotkey`, and `Key` cover keyboard matching and keyboard names.
`TRIPLE_CLICK` is the click count Plite uses for block-level triple-click
handling.

Framework adapters can use `DOMEditor`, `getEditorDOMRoot`,
`createCompiledHotkeyMatcher`, `isGeckoDOMHost`, and
`usesAppleDOMHotkeys` for explicit host integration without importing private
runtime modules.

DOM utilities include shadow-aware traversal, active element/window/selection
lookups, DOM type guards, DOM point normalization, plain-text paste detection,
tracked mutation detection, and DOM order checks:

```ts
import {
  closestShadowAware,
  containsShadowAware,
  getActiveElement,
  getDefaultView,
  getSelection,
  hasShadowRoot,
  isAfter,
  isBefore,
  isDOMElement,
  isDOMNode,
  isDOMSelection,
  isDOMText,
  isPlainTextOnlyPaste,
  isTrackedMutation,
  normalizeDOMPoint,
} from "plitejs/dom";
```

Plite node marker helpers include `getElements`, `getNodeDataAttributeKeys`,
`keyToDataAttribute`, `isEditor`, `isElement`, `isLeaf`, `isNode`, `isString`,
`isText`, and `isVoid`.

Text-diff utilities include string diff normalization, merging, point/range
projection, target-range calculation, and state verification:

```ts
import {
  applyStringDiff,
  mergeStringDiffs,
  normalizePoint,
  normalizeRange,
  normalizeStringDiff,
  targetRange,
  verifyDiffState,
} from "plitejs/dom";
```

`CAN_USE_DOM` guards SSR-only initialization. Mounted DOM adapters resolve
browser behavior from their own root.

## DataTransfer formats

`dataTransferFormats` installs schema-aware browser transfer representations as
one named plugin. Each `DataTransferFormat` decodes or encodes one MIME type.
Callbacks receive an immutable editor-state view; decode callbacks also receive
an immutable snapshot of the incoming types, strings, and files.

```ts
import { ContentSlice, definePlugin, property, schema, target } from "plitejs";
import { dataTransferFormats } from "plitejs/dom";

const Bold = schema.textProperty("bold", property.boolean(), {
  target: target.type("paragraph"),
});
const DataAttribute = schema.elementProperty(
  schema.key.prefix("data_"),
  property.string(),
  { target: target.group("block") }
);

const editor = useEditor({
  plugins: [
    definePlugin("app-schema", {
      schema: { properties: [Bold, DataAttribute] },
    }),
    dataTransferFormats("app-html-transfer", [
      {
        mimeType: "text/html",
        key: "app-html",
        claims: [{ kind: "element", type: "paragraph" }, Bold, DataAttribute],
        decode: ({ data }) => ({
          diagnostics: [],
          ok: true,
          slice: ContentSlice.closed([
            { type: "paragraph", children: [{ text: data }] },
          ]),
        }),
        encode: ({ slice }) => ({
          data: JSON.stringify(slice),
          diagnostics: [],
          ok: true,
        }),
      },
    ]),
  ],
  initialValue,
});
```

Successful decode results contain a `ContentSlice` and warning diagnostics.
Successful encode results contain a string and warning diagnostics. A failed
result contains at least one error and delegates to the next independent
format. Return `null` for a mismatch that should not create an attempt. Return
`false` from `accept` to skip decoding without an attempt.

Decoded slices keep their open edge depths and detached roots. Use
`ContentSlice.closed(content)` for a closed fragment or
`ContentSlice.fromJSON(payload)` for validated open data. Insertion fits the
slice against the actual target. An unfit result delegates without publishing a
partial write.

Decode callbacks receive `{ data, mimeType, snapshot, state }`. Encode
callbacks receive `{ mimeType, slice, state }`. They do not receive the editor,
a live `DataTransfer`, a fitter, or a transaction. Formats run in reverse
configuration order, so the last configured format gets the first opportunity
for its MIME type.

Ownership claims compile against the candidate editor schema before a plugin
revision publishes. `{ kind: "schema" }` owns the complete schema. Element
claims use stable element types. Property claims reuse the same
`schema.elementProperty(...)` or `schema.textProperty(...)` declaration in the
schema contribution and format. Matching is structural, not object-identity
based. The compiler derives one stable identity from the declaration's
placement, key, and target, so equal keys with disjoint targets remain
independently claimable. Key-only claims and raw compiled IDs are not accepted.
Duplicate keys, unknown declarations, and overlapping claims in the same MIME
type and direction reject the complete configuration revision. Decode and
encode ownership are independent.

Expected source failures stay in diagnosed results. Exceptions from `accept`,
`decode`, or `encode` go to the editor's `lifecycleErrorSink` with
`source: "data-transfer-format"`; negotiation then continues. Configure
`dom({ onDataTransferReport })` to receive the final immutable report after an
insert commits, after a write finishes, or after the outer command chain leaves
the payload unhandled. A rejected or unfit rich attempt remains visible even
when a later fallback succeeds. Exceptions from the report sink are isolated
and lifecycle-reported in the `notify` phase.

Framework clipboard writers call
`writeDataTransferFragment(editor, data, slice)` to run registered encoders into
a `setData`-compatible sink. Applications normally use
`editor.api.dom.clipboard.writeSelection(dataTransfer)`, which writes the native
Plite payload and registered MIME representations together.

## Public type groups

DOM bridge types include `DOMApi`, `DOMClipboardApi`,
`DOMClipboardInsertDataHandler`, `DOMEditorOptions`, `ScrollIntoViewOptions`,
and `ScrollIntoViewTarget`.

DOM coverage types include `DOMCoverageSession`, `DOMCoverageBoundary`,
`DOMCoverageSelectionPolicy`, `DOMCoveragePlitePointResult`, and
`DOMCoverageDOMRangeResult`. Use these when a framework layer needs to describe
hidden or virtualized same-root content.

DOM primitive type names include `DOMNode`, `DOMElement`, `DOMText`, `DOMPoint`,
`DOMRange`, `DOMStaticRange`, and `DOMSelection`.

DataTransfer types include `DataTransferFormat`, `DataTransferDecodeContext`,
`DataTransferEncodeContext`, `DataTransferSnapshot`,
`DataTransferSchemaClaim`, `DataTransferDiagnostic`, and
`DataTransferReport`.

Hotkey and diff helper types include `HotkeySpec`, `HotkeyPlatform`,
`HotkeyMatchOptions`, `KeyboardEventLike`, `StringDiff`, and `TextDiff`.

## DOM coverage

DOM coverage boundaries model same-root content whose DOM is hidden or
virtualized. They keep selection, copy, find, and Plite-to-DOM conversion tied
to explicit policies instead of assuming every document node is mounted.

React applications configure coverage through
[`slots.contentBoundary`](./plite-react/dom-coverage-boundaries) or
[`slots.externalText`](./plite-react/external-text). Each `Editable` owns its
session and releases it on unmount.

Framework integrations create one session per mounted view:

```ts
import { DOMCoverage } from "plitejs/dom";

const coverage = DOMCoverage.create(editor);
const dispose = coverage.registerBoundary(boundary);

dispose();
coverage.destroy();
```

Call query, conversion, and materialization methods on that session. Do not
share registrations between views of the same editor. A registration's disposer
cannot remove a later replacement with the same boundary id.

## Internal subpath

The `/internal` package subpath is reserved for sibling Plite packages in this
repo. Applications, plugin libraries, and framework adapters outside this
workspace should use the root `plitejs/dom` export.
