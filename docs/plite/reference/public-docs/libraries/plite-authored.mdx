---
title: Plite Authored Changes
description: Capture attributed edits, review native proposals, and retain accepted work by author.
---

`plitejs/authored` owns attributed document changes. It keeps accepted content and native operation records in one persisted document, then derives proposed and markup views without adding review properties to nodes.

## Install

```tsx
import { createEditor, createEditorView } from 'plitejs';
import { authored } from 'plitejs/authored';
import { history } from 'plitejs/history';

const editor = createEditor({
  plugins: [
    authored({
      authorId: () => session.user.id,
      retainHistory: true,
    }),
    history(),
  ],
  initialValue,
});

const reviewView = createEditorView(editor, {
  authored: { intent: 'propose', projection: 'markup' },
});
```

The author callback must return a nonempty author ID for every write. The application owns authentication. `retainHistory` keeps closed edit bodies for selective author-history revert. Proposal originals are retained independently of this option. Set `automaticFormatting: 'edit'` to apply ordinary text mark commands directly; explicit proposals still retain their formatting until reviewed.

## Views

| Policy | Content and input |
| --- | --- |
| `{ intent: 'edit', projection: 'accepted' }` | Show and edit accepted content. |
| `{ intent: 'edit', projection: 'proposed' }` | Show pending content without retained fragments. Publish independent accepted-content edits directly. |
| `{ intent: 'edit', projection: 'markup' }` | Show pending content and retained fragments. Publish independent accepted-content edits directly. |
| `{ intent: 'propose', projection: 'proposed' }` | Show the proposed result and record input as proposals. |
| `{ intent: 'propose', projection: 'markup' }` | Show the proposed result with retained review fragments and record input as proposals. |

Call `view.api.authored.setView(policy)` to change one view. The source editor and sibling views keep their own policies and selections. In an editing proposed or markup view, inserted text is independent ordinary content, including inside pending insertions or retained deletions. Deletion removes only the selected portion without deciding the surrounding proposal. In Suggesting, input amends your own pending insertion and creates a separate proposal inside another author's insertion. Input inside a retained deletion creates an independent insertion proposal; Backspace within existing deleted text moves the caret left without creating another proposal. Replacing a selection applies these rules in one undoable transaction. Projection changes alone never accept or reject changes.

## Propose and decide

```tsx
let id = '';

reviewView.update((tx) => {
  id = tx.authored.propose();
  tx.text.insert('draft');
});

const selection = editor.read.authored.select({ ids: [id] });
const result = editor.update.authored.decide({
  action: 'accept',
  selection,
});
```

Pass `{ changeId: id }` to `tx.authored.propose(...)` to assign a new change identity or amend an owned pending change. Decisions are atomic and snapshot-bound. Use `read.authored.preview(...)` before presenting a bulk decision and handle every `AuthoredResult` status.

## Import a comparison

```tsx
import { proposeAuthoredComparison } from 'plitejs/authored';
import { compare } from 'plitejs/diff';

const incomingDraft = [
  { type: 'paragraph', children: [{ text: 'Revised sentence.' }] },
];
const comparison = await compare({
  before: editor.read.value(),
  after: incomingDraft,
  schema: editor.read.schema,
});
const result = proposeAuthoredComparison(editor, { comparison });
```

Import validates the accepted baseline, schema, authored frontier, and selected groups before creating one native pending proposal. Pass `groupIds` to select a dependency-closed subset. The result maps comparison groups to the authored change ID. A resolved three-way result uses the same import path when its baseline matches the live accepted document.

## Query changes

```tsx
const page = editor.read.authored.changes({
  authorId: 'alice',
  cursor,
  from,
  limit: 50,
  status: 'pending',
  to,
});
const change = editor.read.authored.change(id);
const changesAtRange = editor.read.authored.changesAt(range);
```

`AuthoredChange` exposes stable identity, author and timestamps, revision, status, kind, dependencies, and current ranges. Use cursor paging for lists and `change(id)` for keyed readers. Pass `proposals: true` to list only proposals, including decided proposals and those with no current ranges. Load `details(id).original` when opening a proposal: `available` supplies its semantic parts, `unavailable` identifies legacy records whose originals cannot be recovered, and `null` denotes an ordinary direct edit. Editing leaves this content unchanged; amendments to your own proposal in Suggesting update it by content identity.

## Retained author history

```tsx
const alice = editor.read.authored.select({
  authorId: 'alice',
  status: 'accepted',
});
const result = editor.update.authored.revert({ selection: alice });
```

Revert creates a new compensating authored contribution. It does not rewrite the original author. A dependency can block compensation, and disabled or expired retention returns `unavailable`.

History undo and redo retain their local interaction lifetime. They can reverse an authored transaction and restore its mapped selection, but they do not act as collaborative review decisions.

## Persistence and collaboration

Save `editor.read.value()` as one document. The native codec validates document identity, operation identity, checkpoints, positions, retained content, and decisions on load. Unknown or malformed data fails before publication.

Install `yjs` from `plitejs/yjs` on every peer to transport authored operation batches and checkpoints. The adapter preserves causal decisions, duplicate delivery idempotence, offline tails, named roots, and retained history through compaction. All writers must support the current authored format and collaboration capability. The host must reject incompatible writers or isolate them in another document generation, preserving old offline work for explicit conversion.

## Format helpers

`plitejs/authored` exports pure document transforms. Use `projectAuthoredDocument(document, { projection })` for accepted or proposed content, `projectAuthoredReview(document)` for complete review markup and property changes, and `projectAuthoredRange(document, range, { from, to })` to map a range between projections. `parseAuthoredDocument(data)` validates persisted JSON before returning a document. These helpers do not construct or activate an editor runtime. Plate HTML and Markdown serializers accept visible `accepted` or `proposed` projections; exact review state stays in authored JSON. DOCX review export represents visible changes as Word revisions and attaches Plate-native state only when the caller explicitly requests the trusted exact-round-trip job. See [Authored Changes](/docs/authored-changes).

## API reference

| Surface | Purpose |
| --- | --- |
| `tx.authored.propose(options?)` | Start or amend a proposal in the active transaction. |
| `read.authored.view()` | Read the current view policy. |
| `read.authored.change(id)` | Read one keyed change. |
| `read.authored.details(id)` | Read proposal originals, current parts, and review provenance. |
| `read.authored.changes(query?)` | Read a cursor-paged change list. |
| `read.authored.changesAt(range)` | Read changes intersecting a range. |
| `read.authored.select(query)` | Capture a snapshot-bound selection. |
| `read.authored.preview(decision)` | Validate a decision without applying it. |
| `update.authored.decide(decision)` | Accept or reject selected changes. |
| `update.authored.resolve(decision)` | Apply an explicit conflict resolution. |
| `update.authored.revert({ selection })` | Compensate retained accepted changes. |
| `api.authored.setView(policy)` | Set one view's authored policy. |
