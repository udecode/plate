---
title: "Decorations, annotations, and widgets"
description: "Choose the owner for transient text paint, durable ranges, and anchored UI."
---

Decorations paint text, annotations give ranges durable identity, and widgets
place UI against nodes, selections, or annotations. Keep these owners separate
so a paint update does not force an editor-wide React render.

## Choose the owner

| Need | API | Owner |
| --- | --- | --- |
| Paint a transient range | `PliteDecorationSource` and `<Plite decorations>` | `plitejs/react` |
| Track a durable range id | `usePliteAnnotationStore` and `PliteAnnotationProvider` | `plitejs/react` |
| Place UI against a node, selection, or annotation | `usePliteWidgetStore` and targeted widget hooks | `plitejs/react` |
| Add text paint from a Plate feature | `plugin.decorate` | `platejs/react` |

Document content stays in Plite nodes, roots, and document state. Decorations,
annotation metadata, and widget geometry are view data.

## Decorations

A decoration source reads one editor entry at a time and returns keyed ranges
with render-safe attributes. Plite maps those ranges to text node keys, merges
overlapping sources, and renders the attributes as nested `span` elements.

```tsx
import { NodeApi } from "plitejs";
import {
  Editable,
  Plite,
  type PliteDecorationSource,
  useEditor,
} from "plitejs/react";
import { useMemo } from "react";

const Editor = ({ query }: { query: string }) => {
  const editor = useEditor({ initialValue });
  const searchDecorations = useMemo(
    () =>
      ({
        id: "search",
        read: ({ entry: [node, path] }) => {
          if (!query || !NodeApi.isText(node)) return [];

          const start = node.text.toLowerCase().indexOf(query.toLowerCase());

          return start === -1
            ? []
            : [
                {
                  attributes: {
                    className: "search-match",
                    "data-search-match": true,
                  },
                  key: `search:${path.join(".")}:${start}`,
                  range: {
                    anchor: { path, offset: start },
                    focus: { path, offset: start + query.length },
                  },
                },
              ];
        },
      }) satisfies PliteDecorationSource<typeof editor>,
    [editor, query]
  );

  return (
    <Plite decorations={[searchDecorations]} editor={editor}>
      <Editable />
    </Plite>
  );
};
```

`attributes` accepts `className`, `style`, `aria-*`, and `data-*`. Keep each
`key` stable and unique within its source. Rendering is automatic; `Editable`
does not need a decoration callback.

## External refresh

Use `observe` when a non-React store can report affected input node keys. Plite
subscribes once when it mounts the source and runs the returned cleanup when the
source leaves the provider.

```tsx
const diagnosticDecorations = {
  id: "diagnostics",
  observe: ({ refresh }) =>
    diagnostics.subscribe(({ nodeKeys }) => refresh({ nodeKeys })),
  read: ({ entry }) => diagnostics.readDecorations(entry),
} satisfies PliteDecorationSource<typeof editor>;
```

Use `{ nodeKeys: "all" }` only when the external owner cannot identify changed
inputs. Document edits already refresh affected entries. Selection-only commits
do not rerun decoration sources.

## Annotations

Annotations attach stable ids and app data to anchors. The store resolves each
anchor against editor commits and exposes targeted subscriptions for sidebars,
widgets, and other UI.

```tsx
const annotations = comments.map((comment) => ({
  anchor: comment.anchor,
  data: comment,
  id: comment.id,
}));

const annotationStore = usePliteAnnotationStore(editor, annotations);

return (
  <Plite decorations={[commentDecorations]} editor={editor}>
    <PliteAnnotationProvider store={annotationStore}>
      <Editable />
      <CommentsSidebar />
    </PliteAnnotationProvider>
  </Plite>
);
```

`PliteAnnotationProvider` only supplies the default annotation store to reader
hooks. Inline annotation paint is a separate decoration source owned by the
feature that knows its visual states. This keeps comment data, text paint, and
editor rendering independently replaceable.

Use `annotationStore.refresh({ ids })` when an external channel names changed
annotations. `usePliteAnnotation(id)` subscribes to one id;
`usePliteAnnotations()` is the deliberate aggregate reader.

## Widgets

Widgets describe UI anchored to a node, selection, or annotation.

```tsx
const widgets = comments.map((comment) => ({
  data: { label: comment.label },
  id: `comment-widget:${comment.id}`,
  target: { annotationId: comment.id, type: "annotation" },
}));

const widgetStore = usePliteWidgetStore(editor, widgets, {
  annotationStore,
});
```

Use `usePliteWidgetIds(widgetStore)` for list membership,
`usePliteWidget(widgetStore, id)` for one item, and
`usePliteWidgetGeometry(widgetStore, id, { editableRef })` for exact mounted
geometry. Reserve `usePliteWidgets(widgetStore)` for consumers that need the
complete snapshot.

## Performance rules

| Rule | Why |
| --- | --- |
| Keep source objects stable | A changed `read` function recompiles that source. |
| Refresh exact node keys | Unaffected inputs are not reread. |
| Use targeted annotation and widget hooks | One changed item wakes only its consumers. |
| Keep decoration attributes small | They are compared and rendered on text segments. |
| Prove visible behavior in a browser | Selection, focus, and follow-up typing are DOM behavior. |

Use [Improving Performance](../walkthroughs/09-performance) for large-document
measurement and [Annotations](../libraries/plite-react/annotations) for the
annotation store API.
