# useSyncExternalStore ownership audit

Read-only source audit, 2026-09-06. No product changes, test runs, browser replay, commits or performance measurements were performed.

Reviewed **57 calls in 36 files**: 55 application/library calls and two intentional test probes. **11 production calls should be removed, replaced or moved to their existing owner; 44 remain justified.** The findings group into three P2 and six P3 items. No P0/P1 defect was established. DnD is included in these totals; ten additional calls are implicated.

The largest useful cut is Find's custom editor-scoped state framework. Keep the existing Find plugin and search/decoration behavior, and remove its parallel snapshot/listener owner. The DnD hook and collaboration history reader are smaller direct duplicates of existing framework hooks. Most calls are legitimate bridges to browser state, canonical runtime state, keyed application records or view-local geometry.

## Scope and evidence

Discovery used `rg` across `packages`, `apps`, `tooling` and `benchmarks` for authored JS/TS sources, followed by a Babel AST walk of named/aliased calls and member calls. A repository-wide source search found no additional calls outside these roots and no external-store shim usage. Dependencies, built output, generated registry payloads, generated templates, temporary CLI fixtures and proof output are excluded; these are not independent authored owners. Both discovered test calls were read and retained as controls.

Every call body and its publishing owner was inspected. Caller/export/registry checks distinguish dead helpers from published primitives. The original source SHA-256 inventory and complete call arguments are retained locally in `docs/plans/artifacts/2026-09-06-use-sync-external-store-audit/inventory.json`. All 36 call-bearing files matched that inventory when this report was written. This is ownership/reachability evidence, not runtime certification or proof of a speedup.

## Exact existing routes

```tsx
import { DndPlugin } from 'platejs/dnd/react';
import { useEditorRuntimeState, usePluginStore } from 'platejs/react';
import { useMounted } from '@/registry/hooks/use-mounted';

const isDragging = usePluginStore(DndPlugin, 'isDragging');
const dropLine = usePluginStore(DndPlugin, (state) =>
  state.dropTarget?.key === key ? state.dropTarget.line : ''
);
const history = useEditorRuntimeState(editor, (state) => state.history());
const hydrated = useMounted();
```

These are target call shapes, not compiled changes. Internal DnD imports must retain an acyclic descriptor/component graph. A drop-line selector reduces unrelated React result changes; it does not make the underlying global store listener delivery keyed.

## Required proof before implementation closure

- DnD: node/scroller state, missing-plugin behavior, drag/drop cleanup and drop-line result locality. Preserve cross-editor/file-drop behavior and SSR.
- Find: preserve current inline-descendant search, wraparound navigation, document-only rescans, result activation, keyboard/focus behavior, deferred input, and exact affected-node decoration refresh. Do not collapse the keyed decoration publisher into an all-node refresh. A replacement must pass focused source/browser checks and a matched scale comparison before making any performance claim.
- Collaboration: retain displayed undo/redo counts and commit updates for the explicit peer editor outside its provider.
- Browser and URL hooks: retain hydration output, exact media breakpoint/change cleanup, source replacement and URL revocation. Existing `use-object-url.spec.tsx` covers replacement/unmount; it was inspected, not rerun here.
- Dead hooks: remove directly and verify import/export reachability; do not add tests asserting that old names no longer exist.

No new doctrine is needed for the direct duplicate hooks: `docs/vision/plate.md` already assigns plugin subscriptions to `usePluginStore` / `useEditorPluginStore` and forbids manual portal/external-store plumbing. The source failed to follow that rule. A subsequent implementation should update current examples and affected generated registry output through their owners.
