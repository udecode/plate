# Pagination and page layout

Page: https://claude.ai/artifact/X2TpUgz6JwrqLGB8ahiEub

Pagination gives a Plate document measured pages. It covers live paged editing with custom page chrome, fragmentation and optional page omission, and one-shot headless measurement for previews and export inputs. The ledger asks which document and measurement contracts determine pages, and which layout authority can be removed or reused (`docs/research/review-scopes/pagination.json`). Plite owns the paged view: `PagedEditable` owns live layout, page surfaces and omission, `measurePages` is the headless path, fragmentation is `text`, `atomic` or `direct-children`, and page-break persistence is deleted (`docs/plans/2026-09-15-pagination-view-owned-layout.md`). A Plate app renders pages through `PagedEditorContent` from `platejs/pagination/react`, which runs `EditorContent`'s pipeline with `PagedEditable` as its editable, so plugin components, handlers, shortcuts and slots work on pages; the Plate facade does not export the raw `PagedEditable` (`docs/plans/2026-10-06-pagination-review.md`). The decision page is `docs/research/decisions/pagination-ownership.md`.

## Public API

A Plate app renders a paged editor with its plugins through `PagedEditorContent` inside `EditorRoot`.

```tsx
// content/docs/(guides)/pagination.mdx
import { createPretextPageLayoutEngine } from 'platejs/pagination';
import {
  PagedEditorContent,
  usePageLayout,
} from 'platejs/pagination/react';
import { EditorRoot, useCreateEditor } from 'platejs/react';

<EditorRoot editor={editor}>
  <output>{layout?.pages.length ?? 0} pages</output>
  <PagedEditorContent
    ref={editableRef}
    engine={engine}
    page={{ margins: 72, preset: 'letter' }}
    pageView={{ gap: 24, mode: 'single' }}
    renderPage={renderPage}
  />
</EditorRoot>
```

## What other editors do

From `docs/research/sources/editor-architecture/pretext-pagination-page-virtualization.md`, a 2026-05-25 reading of local Pretext and Tiptap docs checkouts and one Pretext article, without running either. Its recommendation of authoritative page-break snapshots was later rejected by `docs/research/decisions/pagination-ownership.md`, whose probe showed stored breaks never enter layout.

| Library | What it does with pages | Limit the comparison recorded |
| --- | --- | --- |
| Pretext | Measures text segments once through a canvas, then lays out lines with arithmetic over cached widths | Not headless: measurement needs OffscreenCanvas or a DOM canvas and varies by browser profile, fonts, emoji and scripts |
| Tiptap Pages | Positions blocks around page gaps with CSS floats; tables need a separate Pages TableKit | A block that creates its own formatting context, such as a table or figure, cannot split and breaks pagination when too tall |
| Premirror | Snapshot, measure, compose, render: pages and fragments are derived layout, and page chrome sits outside content | Read as a shape to follow, not run |
| TanStack Virtual | A range engine for mounted rows | Kept internal; selection, IME, clipboard and accessibility policy stay editor-owned |

## Layer and owner

| Change | Layer (Plite or Plate) | Package | Why |
| --- | --- | --- | --- |
| One private content view renders the editable component its variant passes, with that variant's own props | Plate | private `react-core` (`packages/platejs/src/react/components/EditorContentView.internal.tsx`) | Ends the inherited override and its untyped props; no public noun |
| `VirtualizedEditorContent` passes its editable to that view | Plate | `platejs/react/virtualized` | Same public type, no context |
| The paged view keeps one editable host, drops stale placements after an error, lets its canvas keys win, renders one container per measured run and settles with inline inputs | Plite | `plitejs/pagination/react`, with the run projection in `pagination/react.tsx` | Plite behaviors that break raw Plite apps too; Plate adds no CSS |
| Element placement lands on the outermost box that holds only that element, and projected text is positioned against its real containing box | Plite | `plitejs/react` (`editable-text-blocks.tsx`) with `plitejs/pagination/react`, in its own placement module | A neutral placement law; no renderer author forwards anything |
| `PagedEditorContent` | Plate | `platejs/pagination/react`, with new edges to `react-core` and `pagination` in `tooling/entrypoints/entrypoint-dag.mjs` and its own partition | Keeps Pretext out of `platejs/react` |

## Main changes

- `packages/plitejs/src/pagination/index.ts` owns headless measurement (`measurePages`), the page layout engines and the `NodeFragmentationPlan` contract.
- `packages/plitejs/src/pagination/react.tsx` owns the live paged view: `PagedEditable`, page surfaces, page-window omission, the run projection and the exact-host `usePageLayout` read.
- `EditorContent`'s body moves into a private `EditorContentView` that renders its one editable as JSX with the forwarded ref. `EditorContent` passes `Editable`, `VirtualizedEditorContent` passes `VirtualizedEditable` with its window props, and `PagedEditorContent` passes `PagedEditable` with its page props, so no React context selects an editable and no untyped props bag overrides Plate's computed props.
- Plite's `PagedEditable` renders one tree in its flow and paged states, its layouts provider is always present, it never reuses a previous snapshot after a failed measurement, and a placement that disappears is cleared. Measurement recovery, a lagging version or a failed measurement never replaces the host or leaves blocks at old positions.
- Plite places each element's outermost box that holds only that element through a `data-editor-placed` attribute and four registered CSS variables, which one rule applies over the box's own styles, so a renderer keeps owning its inline styles. Each call to the placement ref clears the box the previous call placed, and React and every ref merge that forwards it deliver a detach as a call with null, so a detach or a layout change clears the box in its commit. The placement ref changes with its node binding, as the base's element ref did, so an edit rebinds the element before the renderer's own layout effects and re-places the edited block in the same commit. Each projected run is positioned against its real containing box in that box's own CSS pixels, so a scale transform on the page view does not move it; each box and containing box is measured once per read (by code reading; the read-count probe shows the per-text-node reads gone, not the per-box bound).
- Each measured run renders as one positioned container outside the leaf and outside decoration segments, with no fixed color; the break marker sits only at a line's last source boundary, and the paged component renders its own break rule.
- Publication converges: a component that passes inline `fragmentation` or `typography` and reads `usePageLayout` settles, and a later document change still publishes.
- Placement moves out of `editable-text-blocks.tsx` into its own module, `editable-element-placement.tsx`, the run-container grouping lives in `editable-text-containers.tsx`, one `useHydrated` hook replaces four copies of the hydration flag, and one `getElementTransformScale` in `editable.tsx` replaces the drop cursor's two copies of the scale math. The run projection stays in `pagination/react.tsx`, which grows from 1214 to 1399 lines, and `editable-text.tsx` goes from 991 to 999 (`wc -l` against `git show HEAD`).
