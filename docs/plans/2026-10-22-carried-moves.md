# Let a moved node drop a default its new place cannot hold

Status: executed: landed with the storage and joins slices
Topic: cut-join
Playbook: bug-fix

## Brief

### What will change?

Moving, wrapping, merging or retyping a block into a place that cannot hold a default someone wrote drops that value instead of failing. The storage slice needs this, and review rejected the first version.

### What could go wrong?

Moves the editor cannot trace still fail on schemas with such defaults, such as moving blocks to another document. Plate declares no such default, so Plate editors see only a fix to suggested formatting.

## Teach

Some schemas allow a value only in some places, and leave the default out of the saved document. The storage slice saves a value someone wrote even when it equals that default, so a later retype cannot lose it.

That breaks one thing next allowed. Moving a block into a place that cannot hold the value used to work, because next never saved the default. Now the saved value is not allowed at the new place, and the move fails.

This plan makes the code that moves a node record where the node came from. When the moved value was the left-out default where the node came from, the move drops it, and a suggestion gives it back on reject. Any other value still refuses, as on next. A suggested join stores nothing in the wrong place, and accepting it drops the value where it lands. A move refuses while someone's change to that block's place is pending.

## Design

The design is the arena's cand-2, which the cross-judge also picked, narrowed by the plan panel's first two rounds; the synthesis, scores, verdict, premise probes, cost probe and panel rows are in the decision log.

- **Writes refuse, decisions drop.** A write, Editing or proposed, stores a value only where its key can stand. A place whose declaration of the key rejects the value, such as an enum that differs by place, cannot hold it either (C11). It drops a carried value only when that value was the left-out default where the node stood when the current command began, and that place is settled: no other change has a pending tag on that key, a pending type change on the node or an ancestor, or a pending wrap or unwrap above it. A pending join does not count, because the review document keeps the joined content where it was (D11). It refuses any other value, as next does. A decision cannot refuse, so a decision or a preview that lands content where its value cannot stand drops the value there, through `heldProps`, which is the joins slice's work (S17, M1). This plan, the storage slice and the joins slice land together. So Editing refuses a carried value that is not the default, while proposing and accepting the same change drops it where it lands; `docs/plans/topics/authored.md` states this beside its sentence that Editing records the same way.
- **Who records.** A producer that relocates a node records a `Relocation` on the draft step it already writes: the run of tokens it carried and where they came from. `moveNode` records its subtree, `splitNode` records that the new node's open token continues the split one, and `replaceChildren` records each inserted node that is, by reference, one removed child or a descendant of one, looked up one level deep and only inside its own removed window. `mergeNode` and a retype keep tokens, so a retyped container's children read their place from before the retype (C8). A same-root transfer of whole blocks calls `moveNode` (D3). A same-root text transfer lands its payload through the fitter, so the transfer marks each payload block's source place, and the fitter's origin tracker (`slice-fit/provenance.ts`) carries it to each landed text (C9). Both landing guards, `sameContent` for blocks and `landsMoved` for a text range (`transfer-guard.ts`), accept exactly the drops the canonical pass recorded on what the transfer moved. Each removes a dropped key from the expected payload before it compares.
- **Former place.** `formerPlace(steps, root, at)` returns the place a token stood when the current recording span began, or null. In an editor with a recorder every semantic command is a recording frontier (`command-frame.ts`), and `commitRecordedDraft` starts a new builder there (`public-state.ts`), so the span is the command and a relocation never crosses commands (L6). An editor without a recorder has no frontier, so its span is the update, cut only where a finalize falls (G1, C10). It looks each token up in a hashed index built on its first call and extended with each step recorded after that, so each query costs the same however many moves the command made. A text whose letters mix a known former place with an unknown one counts as unknown, so it refuses (D5). `carriesDefault` applies the write rule inside the canonical pass's existing misplaced-property branch and keeps its drops as `CarriedDrop` entries on the canonical step.
- **Proposals.** A proposal's plain draft is the proposed view and is never stored, so its canonical pass drops a misplaced value instead of refusing. So is the plain draft of a framed write, Editing included, since it is a view under someone's pending change; both modes then judge a carried value where the review document keeps it (D13). The authored plugin tells core the draft is a proposal, so core never imports authored. The recorder then applies the write rule to what the review document stores. A moved copy is an own insertion and drops a left-out default with no tag. A kept node in a new place takes a removal tag with its prior value. Anything else refuses, such as S34's url `x`. A proposed Backspace keeps the merged content under its own paragraph in the review document, so S17's proposal stores nothing misplaced and records (D8).
- **Recorder.** The recorder skips the plain draft's canonical steps, so it maps each `CarriedDrop` of the plain draft's canonical pass through the fold to the review document and applies the write rule there. That covers a merge or a retype, which relocates nothing (C8, C12). `settleCarried` then judges every node, element or text, live or struck, inside a run the command relocated, where the review document stores it, before `completeProposed`. That includes a value the command's projection hid, such as the text or link of a paragraph a pending join shows inside a heading (D11, D12). `dropCarried` writes every drop: an own insertion gets no tag, Editing unsets, and Suggesting writes a removal tag with the prior value. The recorded document's canonical pass refuses any misplaced value no recorded drop covers. `completeProposed` reads a pending join's content where the proposed view shows it, so it judges that content at the receiving block through `heldProps`, as the resolver's preview does, and a later command under the pending join completes (M2).
- **D6.** Every property change on a plain text's open token, framed or not, maps each letter by its end with backward association, through `reviewOpensOf`, so the letter after a mid-text insertion lands in its own review text. The reported case is unframed: a Suggesting update that inserts and then unsets records with no frame, so next maps the whole plain text to its first review text. An unframed step reads its plain index from `step.indexedBefore`. This replaces next's per-letter `openContextAt` loop on the framed path, which reads the index about once per letter, and keeps next's handling of an empty text. The leaf lines of the cost probe bind both paths. It changes how Plate's Suggesting property writes record, so it is the build's first commit and carries Plate's proof.
- **Off where unused.** The compiled schema's `tracksPlaces` flag is true only when some declaration's target can fail at a place where its node can stand, decided from where each node type can stand. The authored plugin's own element key targets the root or anything else, which never fails, so it does not count. Plate declares no target that can fail, so nothing new runs for Plate except D6's mapping (G3, and the cost probe's Plate cohort).
- **Limits.** These refuse when they carry such a value: a transfer across roots (L1 and L2), an ancestor retype that carries another change's struck text (L3), a move whose node's place is pending, as the write rule says (L4), and a Plate producer that rebuilds blocks instead of moving them, such as column shrink and column toggle, which reuses nodes two levels deep, unreachable in Plate today (L5). Paste refuses by law, because a copy has no former place. A node moved into such a place and back out comes back without the stored default when a finalize or a command boundary falls between the two moves (L6). Next gives the same, because it never stored the value. A value that is not the left-out default where it stands refuses like any other, such as `u` on a heading after S12's retype (C10). A decision that drops a key under another change's pending tag reads differently after a reload once a retype gives the key a place again, as the storage plan's Upgrade line accepts; recorded joins (D8) reach that state more often (L7).
- **Cost.** Plain typing records nothing and never reaches the misplaced branch. Typing with an active mark that splits a text records one relocation per split. A container property change opens no child, because the canonical pass skips unchanged children by identity. A text property set scales with the review texts it touches. A move, wrap or transfer scales with the content it moves, also across many primitive moves in one command, through the hashed index.

## Main changes

- A producer that relocates a node records where it stood, and `formerPlace` in `packages/plitejs/src/core/change/lineage.ts` reads that place back for the current command. A write that carries a value its new place cannot hold drops it only when `carriesDefault` in `packages/plitejs/src/core/default-storage.ts` finds it was the left-out default there and no other change is pending on that key or on the node's place; any other value still refuses. In Suggesting, `carriedJudge` in `packages/plitejs/src/authored/tree/carried.ts` writes the drop as a removal tag, so rejecting gives the value back.
