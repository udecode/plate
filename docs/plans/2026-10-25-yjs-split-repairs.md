Status: executed: landed on next with the split plan; the split plan's typing speed gate stays open
Playbook: plan

A line one teammate removes still comes back when another joins it at the same moment, because its letters stay hidden in the line above. ## Brief

### What will change?

A removed line stays gone when a teammate joins it, a teammate's undo after an Enter at a link's end works, and repeated Enters and undos stop the stored document growing. The Close lists every proof and limit.

### What could go wrong?

If the code misjudges which letters show, it deletes one you can see. A randomized test covers paragraphs and quotes, and links, spans, marks and undo have only hand-written cases. Some undo races lose a teammate's letter, as on next.

## Teach

After the split plan, an Enter keeps the second half's letters in the first line's Yjs text, after a cut marker. The new line is an empty view that shows them. A teammate who removes the new line must also delete those letters. Otherwise a join made at the same moment deletes the cut, and they show again.

An Enter at a link's end copies the link into the new line, empty, and moves the text after it there by placeholder. The import looks for that copy at the new line's start. A stored or typed text there hides it, so the import misses the split.

Undoing that Enter joins two lines and two links at once. The join writer reads one level, so the undo rewrites the line and keeps the old one hidden, and the room grows each time. Lookups by path also count Yjs children, which goes wrong once a removed link leaves extra stored texts.

## Main changes

- `withYjsWrite(root, run)` in `document.ts` opens a write scope and hands `run` a `YjsWrite` handle for the root. While the scope is open, a module map keyed by the root holds its root index, with the index's chosen referrers, and its notes. The module-level `lent` goes, and `withYjsRootIndex` fills the scope's index, so the settle reads the index the write used. Every reader of the lent index reads the handle's instead, root inserts included, and next's fill runs inside the lowering's scope. The handle also carries the index's read mode, so an import's settle, which runs under `withYjsRootIds`, walks the root's own children rather than slots that describe the root before the batch. A nested call for the same root joins the open scope. The controller's seven `doc.transact` calls become one private `transact`, which opens a scope for each root it writes, so local commits, canonicalize, repair, seed and remote prepare all run inside one.
- The two raw element deletes merge into one, and it, `writeYjsVisibility` and `cutTextAt` take the handle, as does every helper that reaches them. A hide notes the node it hides, which stays readable after the write. A delete notes what outlives the deleted subtree: each cut view's source and cut, and each placeholder's target outside the subtree. `cutTextAt` notes the cut it inserts. `setYjsAttribute` refuses the visibility keys, and a check in the Yjs partition fails when an element `.delete(` appears outside the merged delete.
- When the scope ends, in `finally` inside the same Yjs transaction, the settle reads each noted node with `showsInYjsRoot`. It reads letters only for a node that shows nowhere. Each live letter that node held finds the piece that holds it now and the node that shows that piece, which is the source text for the head piece and the cut's view for any other. The settle deletes the letters whose node shows nowhere. It also removes a noted cut whose view never reached the document, so that cut's letters join the piece before it again. A write that throws still settles, then rethrows its own error; an error from that settle never replaces it. A healed cut needs nothing, because its letters now belong to the piece before it.
- `showsInYjsRoot` reads the projection's rule upward. A hidden node, this node included, shows only through the referrer `shownYjsReferrerAmong` picks, and the walk must reach the root. A property test checks the settle against the document reader, letter by letter, over edits of paragraphs and quotes.
- `addresses.ts` adds `yjsAddressesOf(root, nodes)`. Its `elementAt(path)` pairs each level against `nodes` through `alignYjsChildren`, checks each element's type and returns null on a mismatch. Its `childAt(element, index)` gives a Plite child's Yjs element, text chain or missing empty text. The root step reads the handle's root index. `planJoin` reads the tree before the commit, `lowerInlineTextCut` and the nested splice read the mirror they found their edit in, and `lowerCompositeRelocations` reads the tree before the move; `writeSplit`'s walk and `pliteToYjsTextPosition`'s element walk call it too. `findJoins` takes its line paths from the batch view's `pathOf`, and `FoundUnsplit` carries both halves. `getYjsNodeIf`, `getYjsNodeWithResolverIf`, `getYjsNodeWithResolver`, `getYjsParent`, `oneYjsChildPerChild` and `getYjsNode` leave `src`; tests that build raw Yjs states read by Yjs position through a test-support helper named for it.
- The batch keeps each visibility key's old value and each deleted placeholder's reference, read while the observer runs, and a merge of batches keeps the first value. It also keeps the id of each node it deletes, those inside a deleted element included, because Yjs fires no event on them. The import then reads again the line of each live view or placeholder that showed one. A node counts as moved in the batch when the batch hid it or a placeholder the batch inserted shows it, and it counts where it showed before the batch.
- `splitsInBatch` stops descending through each first child element (`boundaries.ts:528`). It walks the inserted line one level at a time and finds the witness first: the first placeholder in that level's new element that shows a node the batch moved and that followed the level's original element before the batch. The copy is the element right before the witness. Every child of the new line is new, so the walk skips each text before the copy, whatever it holds. The walk ends at the first level whose copy holds no witness, where `endPointOf` reads the split's end from the witness one level up. `endPointOf` drops its empty-text test and checks neither the copy's type nor its text, because the same commit can change both (`boundaries.ts:246` opens each copy with the original's props, then sets the new ones).
- `joinRunsOf` in `yjs/core/joins.ts` also reads a join that crosses several levels, as the undo of an Enter inside an inline element writes it, with the inline elements it rejoins at each level. Core's `joinsOf`, which history also reads, stays one level. `lowerJoins` lowers it as one run instead of refusing nested runs. `planJoin` resolves each level's lines under their own parents, and its `place()` recurses. At each matching inline element it heals the cut, or deletes the empty copy when the Enter cut at the element's end, then moves the second line's later children to the first line's end by placeholder, as a one-level join does. On the receiving peer, `findJoins` also reads a removed line whose inline copies the join healed or dropped, `readsAsExactly` checks against `joinRunsOf`, `joinedChange` builds each level's edits, and `unsplitsInBatch` reads a deleted cut inside an inline element. `joinRunsOf` reads no join that ends at a child boundary inside a nested inline element, and `findJoins` pairs only inline elements of one type, so those two undos stay limits (Open work).
- `lowerRegions` lets a touched line take the range rewrite unless it holds a hidden node (`holdsHiddenNode`, beside `hasProjectedContent`). A line that only shows another line's node through a placeholder may be rewritten; the rewrite deletes the placeholder, and the settle deletes the letters no line shows. A cut source holds no hidden node, so the check does not protect it. The rewrite's delete in `deleteYjsChildren` keeps a cut source hidden while a view shows its letters elsewhere.
- `lowerJoins` and `lowerSplits` report the Yjs lines they wrote, not root indexes, which a later lowering in the same change can move. After next's fill, a function beside `fillYjsTextGaps` in `text-runs.ts` drops from each of those lines, and from each inline element the line shows, through a placeholder too, every empty text that the same Yjs transaction stored, that never held a letter, whose Yjs text has no item, and that sits next to another text. An empty text that once held letters stays, because an undo puts them back in it. In a line that the undo of an Enter inside an inline element joins, the drop also takes such texts from earlier writes, because each cycle stores them again. Typing into a run of texts with no letters goes into the text the drop keeps.
- When a split ends its first line with an empty text, `writeSplit` keeps the empty texts at the start of the moved part in the first line, whether the split falls inside a text or between children (`secondLineStart` in `canonical-split.ts`). The first line then needs no new empty text, so repeated Enters and undos after a link store no more.

## Failure modes

The change rewrites what the binding deletes, so it records seven realistic failures, its blast radius and its rollback.

- The still-shown rule says a node shows nowhere while a line still shows it, and its letters go, as in round 3. The per-letter property test, Astra's view race, Opus's one-user sequence and a mutant that settles with `documentPositionOf` guard it.
- A write hides a node or cuts a text outside a scope and its letters stay, as Sol's hidden-parent case showed. The handle makes such a write fail to compile, `setYjsAttribute` refuses the hidden key, and the delete check fails on a new element delete. M1-c, M1-e and M1-f cover a throw after a removal, a fallback rewrite and a throw after a cut.
- The settle loses the root index and walks the whole tree on every Enter, join and move, as a 1,000-line probe showed for a lookup after the index loan ended (2,001 child reads). The read counts in step 3.6 guard it.
- A later change to next's fill stores texts somewhere else in a split's lines, and the read misses the split again, as the rebase showed. The witness-first walk skips every text before the copy, M3-g and M3-h cover the stored and the typed shapes, and a mutant that restores the step-over fails M3-h.
- The join read across levels pairs the wrong levels or misses a moved child, and the writer's undo shows a letter twice or loses one, or the teammate's import reads no join and its undo misses. M5-a to M5-f and the round-2 unsplit cases guard it, a mutant that reads one level only brings the fallback back in M5-c's trace, and a mutant that shows a moved child again where it sits hidden fails M5-e and M5-f.
- The narrower rewrite check lets a line be rewritten while a teammate edits the node one of its placeholders shows, and that edit is lost, as in any rewrite. A line that holds a hidden node still refuses, so no node another line shows is rewritten. M1-k and the authored named races guard it.
- The drop deletes only empty texts the same write stored, so a letter a teammate types into an older empty text stays, as on next. The undo of an Enter inside an inline element also drops older empty texts, and a teammate's letter typed into one at that moment is lost, as on next, whose undo rewrites the line. The drop never takes an empty text that once held letters, so an undo's letters keep their text. M4-c, Astra's repeated-Enter race, the authored heading race and diff round 3's join and removal races guard it. A mutant that drops any empty text fails the heading race, and one that drops older texts in every line fails the round-3 cases.

Blast radius: no code outside `packages/plitejs` imports these helpers. Inside it, the twelve Yjs test files, `join-collab.test.ts` and the benchmark script listed under Dependents call them (blast/callers-a1.log). The design is safe because only two writes can stop a node showing and one can cut a text, and the delete check keeps it that way.

Rollback: each phase reverts on its own. No stored shape changes, so a room written by a build of this plan opens in a build without it.
