## How to run a phase

Use Task with Benchmark for causal performance work, Patch or Regression for exact behavior repairs, and Verify Plate for the affected package and live routes. Best API and the owning Plate or Plite Plan decide any public API or runtime architecture change before adoption. This is a local, sequential program. Starting one phase does not start another phase or authorize commits, pushes, PRs, releases, external messages or another checkout.

Each phase request authorizes its diagnosis, necessary implementation and verification together. Work through small changes serially, verifying each before the next. At intake, put the exact selected findings, source identities, commands and frozen budgets in the active phase record. Use the native goal for that phase under the standing project instruction. Do not keep an implementation goal running between user-selected phases.

Preserve one canonical document, change, history, selection and feature owner. First test deleting unnecessary work, merging duplicate mechanics or reusing that owner. Do not introduce another kernel, store, index, scheduler or renderer merely because a donor has one. Compatibility affects sequencing, not the ideal target; correctness, native behavior, serialization, collaboration and resource lifetime constrain the target.

## Finish each phase before choosing the next

Record static/unit, live and performance evidence separately. Tests alone do not close an interaction or performance change. Refresh invalid comparisons explicitly, without selecting lucky retries or relaxing a failing budget. Apply repository generation and final handoff checks only where the changed source requires them.

A kept implementation needs exact before/after proof on the final local source. An ineffective hypothesis may be rejected within the phase. A still-failing required behavior cannot be relabeled deferred merely to finish. If a finding changes the best target, revise the remaining phase scope and record why. Stop after reporting the completed phase; the next phase starts on its own request.
