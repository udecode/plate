## Brief

### What will change?

For your ask that the agent checks pages in a real browser, each page again carries its server render time, and a script Next runs first on every page reports its errors, so a page that crashes shows as failing.

### What could go wrong?

The check still judges when a page rendered, not which code ran. An error now marks every later report from that page load, so a healthy page reached by link from a broken one shows as failing until reloaded.

## Teach

Every page in a hand drive tells the drive log when the server rendered it and which errors it hit. The check counts a page only if it rendered 5 s after the last edit, and fails it on any error.

Both used to go through a small React component. A refresh could hand it a later render time, and a page that crashed while rendering never mounted it, so its errors never left.

Now the server writes the render time into the HTML as a tiny script, which the browser runs once while loading. A module Next runs first on every page, its error page included, collects the errors and posts each one. Errors belong to the whole page load, because React logs a page's warnings before the address changes.

## Main changes

- The visit's `rendered` comes from the document's own HTML. `DriveStamp` in `apps/www/src/components/drive-stamp.tsx` awaits `io()` and renders a `div hidden` whose inner HTML is `<script>window.__driveRendered = <time></script>`, with `Date.now()` as the time. The parser runs that script once while the document loads. React never runs a script it creates or updates on the client, and a script set through `innerHTML` never runs, so a router refresh, an HMR update or a remount leaves the value alone. The layout renders `DriveStamp` in its own drive-mode Suspense boundary beside the beacon, because `cacheComponents` needs one around `io()`. A stamp that throws replaces the page with Next's error screen, and the reporter, which React does not run, still posts that error.
- The page's reporter starts before Next's client. `apps/www/src/instrumentation-client.ts` calls `installDriveReporter` from `apps/www/src/lib/drive-reporter.ts` when `process.env.PLATE_WWW_DRIVE` is set, and `next.config.ts` sets that flag on the development server when `PLATE_WWW_DRIVE_DIR` is set. Next requires that module at the top of its client entry, before `appBootstrap`, in every document, its error shell included (`next/dist/client/app-next-turbopack.js`, `app-next-dev.js`). The layout's `beforeInteractive` script, `driveErrorsScript` and the beacon's fallback start go.
- The reporter posts every visit. It keeps the document's errors, each message once, and posts an error visit as each one arrives, until it holds 20. One function builds and sends every visit: the path the page shows when it posts, the window width, the painted theme, the frame and webdriver flags, `window.__driveRendered`, the previews it measures and the errors. The errors list a rendered Not Found and the server's error status first, then the document's errors, at most 20, each cut to 300 characters. Each visit goes out once through `sendBeacon`, which refuses it while the page's unanswered keepalive requests, its earlier visits included, pass 64 KiB. The reporter does not send a refused visit again, and the reference's Limits say what that loses. The message of a string-form `console.error` substitutes its arguments for `%s`, `%d`, `%i`, `%f`, `%o` and `%O`, and drops the argument each `%c` consumes.
- `DriveBeacon` only tells the reporter when to post: after each navigation, resize, theme change and pointer or key release, and when a preview panel resizes. It posts its settled visit once the document has fired `DOMContentLoaded`, which comes after the parser has read the whole streamed response, the stamp's segment included.
- `check` lets a counted visit that reports an error fail every cell of its page, whatever its width, theme or previews, so a crash after a clean preview visit fails the preview cell too. Of two visits sent in the same millisecond, it takes the one with more errors as the later.
