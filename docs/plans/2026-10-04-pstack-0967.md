# Move to pstack 0.9.67 and audit the skills

Status: executed
Topic: pstack

pstack moved from v0.9.64 to v0.9.67. Release 0.9.65 syncs upstream v0.15.9. It adds the `correct` skill, teaches `architect` to design for agents that see only the files they opened, and replaces the Perf issue playbook's eight strategy families with seven performance mantras. 0.9.66 and 0.9.67 change only the session hook on Windows Codex and how it reads the models sheet. The owner also asked that the skill set use the latest pstack skills, so sync-pstack's Sync mode now runs its Audit after a bump that adds or changes a skill, and this bump is its first run.

## Main changes

- **Sync audits project skills after a bump that adds pstack skills.** Sync step 6 runs Audit on each synced project when `CHANGES.md` adds or changes a skill or principle, judging first the skills whose job the new one covers. Audit step 2 runs an interrogate panel only when the block's Panel review rule lets it or the owner says "panel"; otherwise the lead judges the report and says so. dotai cc0639d.
- **user-pin refreshes Claude Code from the pinned entry.** It prints `claude plugin marketplace add michael-denyer/pstack-claude#<tag> && claude plugin update pstack@pstack-claude`, because Claude Code hides a marketplace whose settings entry and registry disagree. dotai 04a4bb3; this bump is its first real run.
- **The bump itself changes no block text.** No override quotes text 0.9.65 to 0.9.67 changed, and no live file quotes the removed strategy families; the bump moves only the pins.
- **A repeated code mistake goes to `correct`.** The block's Improve the workflow mid-task rule sends a code mistake the user corrects a second time to `/pstack:correct`, whose commits follow Delivery; plate-2's `best-api repair` and Ellie's fidelity rule point there too. dotai f977334.
- **Performance numbers go through `benchmark-checklist`.** plate-2's `benchmark` skill and Perf issue playbook and Ellie's performance rule hand every number to `benchmark-checklist`. It asks for five alternating runs per side unless the owner asked for a ballpark, and each packet records the limiter, error count and work count. Work deferred by the later or not-looking mantras counts only when the whole user-facing operation gets faster.
