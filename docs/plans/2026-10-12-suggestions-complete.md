## Brief

### What will change?

First we fix the page's bugs in the new model. Then everything switches over at once and the docs page works, with each change in its own color. Tables, lists and generated ids get their own plans after that.

### What could go wrong?

It's a big switch, since AI, Word files, version history and every demo move too. One bug may need a deeper change in how keys treat crossed-out text. Until the later plans land, suggesting is off in tables and lists.

## Teach

Suggestions let you propose edits that someone else accepts or rejects. Crossed-out text is a proposed deletion, and highlighted text is a proposed insertion.

The docs page still runs the old model. There, crossed-out text lives in small separate documents painted beside the real one, and the editor has to translate every key you press between them. That translation is where the page breaks. Select all does nothing, bold gets no highlight, and Backspace across lines loses the caret.

The new model keeps crossed-out text inside the one document you type in, so those keys work like normal editing. In Chrome it already handles select all and bold. Moving the page onto it fixes those bugs for good. First, though, the new model's own Enter and Backspace bugs need fixing.

## Public API

The cutover keeps the parent plan's Public API unchanged. The page's own demos change in two places. A suggesting view passes only its intent, because every editable view shows the review tree.

```tsx before
// apps/www/src/registry/examples/suggestion-demo.tsx
<EditorRoot
  editor={editor}
  authored={{ intent: 'propose', projection: 'markup' }}
>
```

```tsx after
// apps/www/src/registry/examples/suggestion-demo.tsx
<EditorRoot editor={editor} authored={{ intent: 'propose' }}>
```

The review card decides the change it rendered, so the selection token and the conflicted branch go.

```tsx before
// apps/www/src/registry/components/editor/discussion.tsx
const input = {
  action,
  selection: authored.read.select({ ids }),
};
const result =
  latest.status === 'conflicted'
    ? authored.update.resolve(input)
    : authored.update.decide(input);
```

```tsx after
// apps/www/src/registry/components/editor/discussion.tsx
const result = authored.update.decide({ action, changes: [change] });
```

### Proof limits

- Each browser gesture ran once by hand, not as five warm Playwright runs.
- IME composition that starts inside a crossed-out line goes through native input, which the landing rule does not see. This run wrote no case for it.
- Until P1.8 lands, these keys differ from a plain editor on the accepted text:
  - Word and line deletes stop at a pending join's boundary (`p16-join-probe-a1.log`).
  - Backspace at a quote's first live line after a struck sibling leaves the line in the quote, where a plain Plite editor merges it into the line before. Backspace at the first live line after a struck heading joins into the heading, so in Editing the line becomes a heading (`p16-flagd-probe-a4.log`, E and D).
  - Delete at the end of a line before a quote's struck last line joins into that struck line (round 2, Opus 4).
  - Typing over whole struck lines accepts as `[P("keep"), P("Z"), P("tail")]` where a plain editor gives `[P("keepZ"), P("tail")]`, in every editor, since round 3's revert (`r3-claim-a1.log`).
  - A pending join keeps the type of the block that survives when it is accepted. So `[H("hel"), P("lo world")]` with a pending join, after striking "hel" and "lo", accepts as `P(" world")` where a plain editor gives `H(" world")` (`p18-q-probe-a3.log`, Q4).
