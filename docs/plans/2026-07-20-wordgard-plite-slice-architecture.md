## Decision brief

- Outcome: rearchitect the public lifecycle and fitter while keeping Plite's
  JSON slice DTO, private token algebra, canonical change persistence,
  multi-root model, compiled extension configuration, and browser transport.
- Chosen shape: closed application content uses `fragment`; structurally open
  transport content uses generic `ContentSlice<V>`; one compiled candidate
  scorer/lowerer turns both into `TransactionSpec`/`DocumentChange` while
  allowing multiple bounded candidate generators.
- Strongest rejected alternative: publish Wordgard's `Slice` class, token
  arrays, numeric positions, and separate context stack. It looks concise only
  because Wordgard uses one class ontology everywhere and has a narrower host,
  root, collaboration, and product surface.
- Consequence: hard-cut `createContentSlice`, `EditorContentSlice`, public
  `schema.fit`, caller-provided full values, duplicate vocabulary checks,
  `semanticType`, split fitter paths, and closed-fragment factory boilerplate.

## Final public API

### Public types and value helpers

```ts
export type ContentSlice<V extends Value = Value> = Readonly<{
  content: readonly DescendantIn<V>[];
  openEnd: number;
  openStart: number;
}>;

export const ContentSlice: {
  readonly empty: ContentSlice;

  closed<V extends Value>(
    content: readonly DescendantIn<V>[]
  ): ContentSlice<V>;

  fromJSON<V extends Value = Value>(value: unknown): ContentSlice<V>;

  withContent<V extends Value>(
    slice: ContentSlice<V>,
    content: readonly DescendantIn<V>[],
    options: { open: 'closed' | 'preserve' }
  ): ContentSlice<V>;
};
```

`ContentSlice.closed` and `fromJSON` snapshot, validate, and freeze once.
Slices returned by `state.slice.get` are already trusted immutable values.
`withContent(...,{open:'preserve'})` validates that both edge spines still
support the original depths; it never silently clamps them. The explicit
`closed` choice prevents the current raw spread/reconstruction ambiguity.

### State and transaction APIs

```ts
type EditorStateSliceApi<V extends Value> = {
  fit(
    slice: ContentSlice<V>,
    options?: WithNodeTarget<
      TextInsertFragmentOptions,
      DescendantIn<V>
    >
  ): false | TransactionSpec;

  fitContent(
    slice: ContentSlice<V>,
    options: { parent: ElementIn<V>; root?: RootKey }
  ): readonly DescendantIn<V>[] | null;

  get(options?: { at?: Range }): ContentSlice<V>;
};

type EditorTransactionFragmentApi<V extends Value> = EditorStateFragmentApi<V> & {
  delete(
    options?: WithNodeTarget<
      EditorFragmentDeletionOptions,
      DescendantIn<V>
    >
  ): void;
  replace(
    content: readonly DescendantIn<V>[],
    options?: WithNodeTarget<
      TextInsertFragmentOptions,
      DescendantIn<V>
    >
  ): boolean;
};

type EditorTransactionSliceApi<V extends Value> = Pick<
  EditorStateSliceApi<V>,
  'get'
> & {
  replace(
    slice: ContentSlice<V>,
    options?: WithNodeTarget<
      TextInsertFragmentOptions,
      DescendantIn<V>
    >
  ): boolean;
};
```

Direct one-shot fragment and slice updates dispatch the same typed
`replaceSlice` command. Transaction-callback methods are primitive composition
and lower through the same fitter without redispatching middleware; redispatch
inside a command handler would recurse. Plate keeps one interception point.

### Simple application use

```ts
editor.update.fragment.replace([
  { children: [{ text: 'Hello' }], type: 'p' },
]);
```

No factory, openness, transaction callback, schema, value, or selection input
is required. The editor derives all of them.

### Advanced copy/move use

```ts
const slice = editor.read.slice.get({ at: sourceRange });

editor.update((tx) => {
  tx.slice.replace(slice, { at: destination });
});
```

### Pure command/extension-author use

```ts
editorCommands.replaceSlice.handle(({ command, state }, next) => {
  if (!shouldHandle(command.slice, state)) return next();

  const slice = ContentSlice.withContent(
    command.slice,
    rewriteSuggestionContent(command.slice.content),
    { open: 'preserve' }
  );

  return state.slice.fit(slice, { at: command.options?.at });
});
```

The command returns a complete immutable `TransactionSpec`; no bespoke
`{change,selection}` or internal transaction application is exposed.

### Synthetic parent/table use

```ts
const content = state.slice.fitContent(command.slice, {
  parent: createCellElement(),
});

if (!content) return next();

return state.transaction((tx) => {
  tableGrid.replaceSelection(tx, content);
});
```

Plite owns grammar fitting. Plate still owns rectangular cells, row/colspan,
expansion policy, and table selection.

### Codec-author use

```ts
const html = defineHostCodec<MyValue>({
  format: 'text/html',
  key: 'html',
  parse: ({ data, state }) =>
    parseHtmlSlice(data, {
      schema: state.schema,
      target: state.selection(),
    }),
  schema: [{ kind: 'schema' }],
  serialize: ({ slice, state }) =>
    serializeHtmlSlice(slice, { schema: state.schema }),
});
```

The context carries one read-only `state` (which already owns `schema`). There
is no redundant schema argument, `semanticType`, mutable editor, fit callback,
or direct write. The host dispatcher validates and fits the result.

### Element slice policy

```ts
const Heading = element({
  content: schema.content.group('inline', { min: 1 }),
  groups: ['block'],
  slice: {
    preserveContext: true,
    replaceWhenCovered: false,
  },
});
```

Defaults are deterministic: `preserveContext` is `false`, and
`replaceWhenCovered` defaults to `!preserveContext`. Compilation rejects policy
on nodes whose content/role makes the flag meaningless.

## Final compiled and internal architecture

### Value/trust model

- `ContentSlice<V>` is schema-neutral immutable JSON. It contains no editor,
  schema, root, runtime ID, path, or class reference.
- `ContentSlice.closed/fromJSON` perform one clone, structural validation, and
  freeze. `state.slice.get` builds a detached frozen value directly.
- Internal trusted values are tracked by one private weak-key preparation
  record; there is no public brand, `unsafe`, or `trusted` option.
- Reusing a trusted slice never deep-clones or repeats generic JSON validation.
  Fitting under a new schema revision still rechecks vocabulary and policy.
- Slice preparation uses weak keys. Dropped slice values retain no cache entry
  or explicit cleanup obligation; compiled schema policy stays owned by the
  immutable schema revision rather than a second slice cache.

### Minimal trusted preparation

`packages/plite` caches one full encoded `DocumentSlice` for each trusted
frozen content identity. Alternate valid open depths reuse that encoding and
apply only cheap boundary slicing. The 10k variant profile makes this cache
non-speculative: recloning/re-encoding variants cost about 269ms and 62MB.

No prepared spine, text-length summary, schema-keyed slice cache, or mutable
invalidation protocol exists without a measured consumer. Edge context stays
derivable from the immutable nested content and compiled schema policy.

### Compiled schema policy

The shared schema plan's compiled element record gains normalized slice policy
alongside its containment/default/wrapping indexes. Policy is declared only
through the final `element(...)` / Plate `node.element` vocabulary, compiled by
the one schema compiler, conflict-checked, frozen, and published atomically
with the extension revision. Execution never adds an interim
`EditorElementSpec.slice`; that type is already condemned by the schema hard
cut. No codec or Plate plugin keeps a second policy registry.

### One `SliceFitter`

One private fitting pipeline owns the candidate contract, scoring, and
lowering:

1. Resolve the target root/range from state, including implicit selection,
   node targets, unhang policy, protected voids, and named roots.
2. Prepare or reuse the slice; apply max-length budget once while preserving
   valid spines.
3. Read only the target root's `IndexedDocument` boundary/context windows.
4. Let bounded structural and local-context generators emit the same candidate
   shape from exact boundaries, open spines, compiled wrappers, preserved
   context, covered-node replacement, and isolating barriers.
5. Score candidates deterministically: information loss, boundary expansion,
   non-neutral replacement, wrapper synthesis, and distance from source
   openness. Configuration order never breaks a tie.
6. Build sparse changes through `DocumentChangeBuilder`; construct required
   defaults and canonical text leaves inside changed windows only.
7. Validate the winning local result and root cardinality once, then return one
   private `{ change, selection? }` lowerer result to the active transaction.

There is no second fitter result/application pipeline, whole-root output token
array, full-value diff, or per-candidate document canonicalization. The private
lowerer result is consumed only by `tx.slice.replace`; public
`state.slice.fit` builds and returns the complete `TransactionSpec` through
that same transaction path. A bounded local candidate generator may remain
where inline/open context semantics differ, but it cannot lower or validate
changes itself. Closed fragments and open slices differ only in preparation
and candidate generation, not scoring or execution.

### Synthetic content fitting

`fitContent` treats the supplied element as a detached parent, replaces its
entire current child content with the candidate slice, invokes the same scorer
and lowerer, and returns the fitted children. `root` supplies named-root context
for compiled property targets; omission means the implicit primary root. The
parent type and child placement participate exactly as they would in a
document, but the detached parent's own ancestor-dependent properties are not
revalidated or changed. It cannot publish, select, add effects, or cross a real
root. Table is the proven production consumer. List already delegates its real
target fit, and code block rewrites one closed command, so neither pre-fits.

### Transaction, history, and collaboration lifecycle

- `ContentSlice` is pre-commit content input. `TransactionSpec` is the atomic
  command result.
- `DocumentChange` is the sole committed, invertible, serializable, mappable,
  and collaborative change truth.
- History stores/inverts `DocumentChange`; Yjs lowers/imports it; neither
  package imports `ContentSlice` in production.
- Selection is mapped in the transaction spec with its root. Slices remain
  root-neutral and cannot represent a cross-root replacement.
- Runtime IDs are derived by canonical construction and mapped change ranges,
  never serialized into slice content.

### Host ownership and failure isolation

- `plite`: value, extraction, preparation, schema policy, fitting, commands,
  transaction lowering, and laws.
- `plite-dom`: versioned DataTransfer envelope, HTML/plain codecs, browser
  platform repair, exact fragment fallback, and codec runtime.
- `plite-react`: model/DOM coverage and mutation recovery only.
- Plate core: plugin parser registration and schema claims.
- Plate plugins: product transformations such as suggestion marking, code-line
  conversion, list semantics, and table grids; they consume Plite fit APIs.
- Product code: chooses formats and invokes fragment/slice updates; it never
  sees `DocumentSlice`, fitter candidates, or schema snapshot input.

Codec query/parse/serialize errors carry codec key, format, direction, and
cause to the existing lifecycle error sink. A malformed/unrecognized payload
is a recoverable decode miss and continues to the next codec/fallback. A codec
bug or configuration invariant is reported and fails that codec invocation;
it never leaves a partial editor mutation because codecs cannot mutate.

## Why this is better than Wordgard

1. It retains Wordgard's strongest idea—one context-aware fitter reused by
   changes, clipboard, and tables—without publishing tokens, classes, or raw
   offsets.
2. A slice is plain generic JSON, so workers, persistence envelopes, server
   codecs, tests, and agents can construct and inspect it without a live schema
   or class registry.
3. Nested content and open depths form one consistent value; Wordgard's slice
   and separate context stack can disagree.
4. The editor derives target, root, document snapshot, context, schema
   revision, max-length budget, and selection. Wordgard and current Plite both
   expose some of that implementation burden.
5. Deterministic explicit grammar and slice policy replace Wordgard's
   configuration-order defaults and current Plite heuristics.
6. One `TransactionSpec` carries change, selection, effects, tags, and roots;
   Wordgard couples slice tokens directly to `ChangeSet`, while current Plite
   returns a partial transaction duplicate.
7. History and Yjs remain on canonical `DocumentChange`, so slice redesigns do
   not alter persisted or collaborative identity.
8. Prepared slices and sparse fitting make warm-fit cost depend on slice plus
   changed context, not total document width, without exposing an unsafe trust
   flag. Cold immutable-index construction is measured separately and is
   allowed to scale with the indexed root once.
9. Pure codecs can fail and fall back without mutating. Wordgard filters and
   current Plite codecs execute in mutable runtime paths.
10. Plite keeps exact versioned MIME/HTML transport, hidden DOM, void,
    multi-root, React, IME, mobile viewport, and browser-matrix proof that
    Wordgard's cleaner but narrower host does not cover.

## Pressure tests and failure policy

| Scenario | Expected architecture response |
| --- | --- |
| Cyclic/repeated/non-JSON content or impossible open depth | `ContentSlice.fromJSON/closed` throws before any transaction; clipboard decode reports a recoverable miss and falls through. |
| Frozen slice reused after extension reconfiguration | Structural preparation is reused; schema validation/policy cache misses by compiled schema identity and refits under the new revision. |
| Open partial list pasted into paragraph/list/table cell | One candidate engine derives both spines and target context; compiled policy decides wrapper preservation; product handler only transforms list/table semantics. |
| Selection spans roots | Fit returns false before change construction; one slice replacement never crosses roots. |
| Named-root insertion | Transaction spec carries root-aware selection and only changes that root. |
| 10k-node slice into 100k-block document | No whole-root reconstruction, repeated clone, or repeated schema walk; metrics scale with slice plus changed ancestor window. |
| Concurrent Yjs edit/undo/reconnect | Only canonical `DocumentChange` enters history/Yjs; convergence and undo grouping match direct edits. |
| Codec throws or returns malformed content | No mutation is possible; diagnostic goes to lifecycle sink; declared decode miss continues to exact HTML/plain fallback. |
| Custom MIME stripped | Embedded versioned HTML payload wins; if absent, host HTML codec; then target-aware plain text. |
| Hidden/model DOM, void, decoration, IME follow-up | Existing Plite DOM coverage and browser matrix remain mandatory; no donor simplification may bypass them. |
| Table row/colspan paste | Plite fits cell content; Plate repairs rectangular grid and spans. No table model leaks into core. |
| Max-length truncates an open edge | Preparation truncates text once, recomputes valid edge spine, and fitter supplies required defaults without a second public slice clone. |

Findings:
- `createContentSlice` is not the best ordinary API. It is a correct explicit
  boundary helper used as universal insertion ceremony.
- Wordgard is superior on cohesive context-aware fitting and synthetic reuse,
  not on its public slice class.
- Plite's public JSON/open-depth representation, private `DocumentSlice`,
  explicit grammar, canonical `DocumentChange`, multi-root behavior, and browser
  transport are stronger and should survive the rewrite.
- The biggest current architecture fault is public `schema.fit(slice,{at,value})`
  backed by two fitter implementations and a partial transaction result.
- The registered large-clipboard benchmark is stale enough to be false comfort;
  performance closure begins by repairing the proof owner.

Decisions and tradeoffs:
- Keep explicit `openStart/openEnd`; a nested `open` object is prettier but adds
  no semantic value and churns the exact payload for cosmetics.
- Keep `ContentSlice` structurally constructible at TypeScript level, but treat
  raw/untrusted values as validated only at `fromJSON` or transaction/codec
  boundaries; no unsafe brand leaks publicly.
- Add `fragment.replace` rather than letting `slice.replace` accept arrays.
  One union signature would blur closed content and open transport again.
- Keep one semantic `replaceSlice` command so Plate middleware does not bifurcate.
- Expose `fitContent` narrowly for detached parent content; do not expose fitter
  candidates, costs, context stacks, token positions, or fake documents.
- Preserve Plate table code that is genuinely product-specific; only grammar
  fitting moves down.

Review fixes:
- Rejected the tempting Wordgard-style public token class after tracing JSON,
  multi-root, history/Yjs, React, and clipboard consequences.
- Replaced an early idea of a single union `slice.replace(nodes | slice)` with
  distinct `fragment.replace` and `slice.replace` concepts over one command.
- Kept open-depth field names rather than performing cosmetic serialization
  churn.
- Added benchmark repair as an early proof dependency after verifying the live
  target calls obsolete APIs.
