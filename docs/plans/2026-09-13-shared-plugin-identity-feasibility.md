Findings:

- Source evidence: current Plite registers source references and validates the
  direct dependency graph for every installed extension. The first prototype
  baseline omitted both operations while the candidate included them, so its
  runtime ratio did not isolate descriptor identity.
- Measurement evidence: the first fully executable run failed the frozen
  budgets (candidate runtime p50 1.62-1.68x baseline; TypeScript instantiations
  1.56x baseline), but the baseline also omitted React view capability from its
  generated type workload. Preserve that receipt; rerun with matched runtime
  work and capability surfaces before using it to accept or reject the target.
- Measurement evidence: the corrected runtime comparison passes every cohort
  at 0.84-1.16x baseline and the candidate records zero synthetic descriptors,
  aliases, name remaps, portal-kind branches and runtime descriptor
  allocations. Its first type carrier still fails at 1.47x baseline
  instantiations, isolating the remaining issue to eager recomputation of Plate
  capabilities rather than shared runtime identity.
- Source evidence: raw Plite descriptors publicly carry normalized immutable
  definition fields. Shared nominal identity only requires separating those
  objects from installed records; deleting author-time fields would add an
  unsupported breaking change, so the target preserves them pending a separate
  caller-backed cut.
- Measurement fact: the final prototype passes ten correctness laws. Runtime
  candidate/baseline p50 ratios are 1.22, 0.92, 0.88 and 0.89 for 1, 32, 128
  and 512 plugins. TypeScript ratios for 128 descriptors are 0.99
  instantiations, 1.04 check time and 1.04 memory.
- Measurement fact: candidate deterministic counters are zero for synthetic
  descriptors, global aliases, name remaps, portal-kind branches and runtime
  descriptor allocations. Direct dependency/conflict checks and source
  bindings remain linear and descriptor-based.
- Inference: runtime identity and product authoring are separable. Plate's
  compiler is justified; its replacement descriptor, topology translation and
  portal dispatch are not.
- Recommendation: pursue one Plite nominal `PluginReference`, one installed
  record and `editor.plugin`, with a lazy owner-supplied type provider and
  Plate-owned product compilation.
- Production fact: the recommendation is implemented. Plate lowering publishes
  private compiled entries keyed by the authored descriptor; Plite snapshots
  installed behavior into a distinct record and resolves source ancestors by
  direct descriptor identity.
- Production fact: authored descriptors are frozen, independently authored
  same-name descriptors do not replace direct dependencies, and candidate
  publication restores the exact outer candidate after nested failure.
- Production measurement: the final current-source benchmark passes with
  runtime ratios no greater than 0.846 and TypeScript ratios of 0.856 check
  time, 1.003 instantiations and 1.005 memory.

Decisions and tradeoffs:

- Select the shared nominal reference plus private compiled input. The compiled
  input is an internal publication value, never a public descriptor or user
  configuration noun.
- Keep Plate's product stages, terminal configuration, schema, stores, codecs,
  rendering and view policy. Moving them into Plite loses substrate clarity and
  raw independence.
- Rename Plite `extension` vocabulary to `plugin` only after the shared
  identity path exists; no permanent aliases or dual portal spellings.
- Use a lazy type-only capability provider. Reject eager whole-definition and
  incremental structural carriers based on measured 1.47x and 1.65x
  instantiation ratios.
- Preserve raw immutable descriptor fields. Installation snapshots them into a
  separate record; removal of author fields needs its own caller evidence.
- Core Plite/Plate architecture is one coherent migration. Substantial Plate
  features stay separate; math, emoji and AI each have an independent change.
