## Teach

Plate keeps list items side by side, and each item stores its own depth. When you paste list items, the PR lands them at the caret's depth, keeps their nesting and continues the numbering. Pasting into an empty line turns that line into the first copied item.

To turn the line into an item, the PR's list code checks Plite's placement rules itself, then asks Plite to replace the exact blocks it names. That puts Plite's rules in two places, and it adds two public options.

Now Plite first trims the paste to fit and tells the list code where it will land. The list code answers with plain content: "replace this empty line with these items, or else paste this". Plite checks its rules once, then places the items or the fallback. It's still one undo step.

## Main changes

- Plite's `replaceSlice` builder resolves the target on the command's current draft and view, computes the remaining length budget once for a caret or range target, limits the slice against it, then runs `slice.landing` once. The PR ran the read on the raw command, and List applied the limit itself on its empty-line path only, so List now lands what survives the limit on every caret or range paste.
- The whole-block attempt and the fallback fit use that one budget through a private option, so a caret or range paste in a `maxLength` editor reads the document text once. When a middleware adds text, Plite refuses its replacement and cuts its fallback to the budget. A paste over a node selection keeps next's own limits in both of its branches.
- One private whole-block attempt replaces a resolved empty block with an admitted proposal at exact bounds taken from the fitter's own document index, or falls back to fitting `landing.slice` and keeps nothing from the refused attempt.

## Design

The [synthesis](artifacts/2026-10-14-pr-5168-redo/architect/synthesis.md) records the candidates, the judge and the grafts. The build follows this shape.

```ts
// packages/plitejs/src/core/editor-reads.ts
export type SliceLandingTarget =
  | Readonly<{ kind: 'empty'; block: NodeEntry<Element>; root?: string }>
  | Readonly<{ kind: 'context'; block: NodeEntry<Element> | null; root?: string }>;

export type SliceLandingInput = Readonly<{
  /** The command's slice as handlers left it, before the length limit. */
  source: ContentSlice;
  /** What survives the length limit at a caret or range, or the handed slice over a node selection; its head decides type, identity and starts. */
  slice: ContentSlice;
  target: SliceLandingTarget;
}>;

export type SliceLanding = Readonly<{
  slice: ContentSlice;
  replaceEmpty?: Readonly<{
    slice: ContentSlice;
    omitTargetProperties?: readonly string[];
  }>;
}>;

// slice: { landing: defineRead<SliceLandingInput, SliceLanding>('slice.landing') }
// default result: { slice: input.slice }
```

The builder runs these steps in order.

1. Command handlers run first. A terminal handler keeps ownership, and retargeting and prefixes finish before landing.
2. Plite resolves the target on the command's current draft and view, from the explicit `at` or the selection. The empty-block lookup takes the element that holds the caret's text, and its predicate requires a non-inline block that `isEmptyElement` accepts, that owns no content roots and that has no `slice.preserveContext`. A collapsed caret in such a block gives `kind: 'empty'`. Anything else gives `kind: 'context'`, whose block is the block at the range's start. Over a node selection it is the block that holds the first selected node, as the PR's read saw it through the selection's text range, and `null` only without a target. `root` is the public key of the effective mutation root, the view's root included, and is absent for the main document.
3. With `maxLength` set and a caret or range target, Plite computes the remaining budget once, inside the effective mutation root, crediting the target range's text as the fitter does. A limit that empties a slice that had content refuses the command, as next's fitter does. A paste over a node selection skips this step, and next's two node branches keep their own limits.
4. Plite limits the slice against that budget. The read gets the handlers' slice as `source`, and the limited slice, or the handed one over a node selection, as `slice`.
5. The landing read runs once.
6. Plite honors `replaceEmpty` only when its own resolution was `empty`, and replaces its own resolved block, whatever target an outer middleware passed down the chain. It refuses a proposal that the budget would cut, so no later limit can drop the head it prepared. It closes the proposed slice only when every declared content root on an open edge was copied. Three rules decide which of the target's properties the head keeps, after `omitTargetProperties` is removed. A head of the same type keeps them all. A text head of another type keeps what the schema's type-change lifecycle allows. An object or void head keeps none. The copied head's own properties win over the kept ones. Plite then admits the whole sequence at the actual parent with the target removed, fits it at the block's exact bounds and discards the block's keys.
7. Without an honored `replaceEmpty`, or when Plite refuses it, Plite fits `landing.slice` as ordinary content, limited against the same budget, so a middleware that adds text cannot pass `maxLength`. An empty `landing.slice` refuses, as on next. On the node-selection path, that slice replaces the selected nodes as on next.
8. Either way, one spec commits, so the paste is one canonical change and one undo step. A refused attempt leaves no node, key or root behind.

- The read's doc comment says that a middleware that rewrites `slice` must rewrite or drop `replaceEmpty`.
- `landListPaste` keeps the PR's wrapper handling. While both open edges are deeper than 1 and the content is one element, it sets that wrapper aside to reach the list items inside, and it wraps its result back with the wrapper count added to the result's open depths and the input's roots kept.
- `landListPaste` decides eligibility on `source`, as the PR did before its limit: an empty paragraph or heading in the main document, a list item at the head, and two or more blocks or a closed slice. It lands the limited `slice`, and refuses the replacement when the limit left a lone empty element from an open slice. So a two-item copy cut to one item with text still becomes a list item.
- The empty target's start and restart go on `replaceEmpty.slice`. `omitTargetProperties` is List's `LIST_FIELDS`. List builds the fallback without the tentative join, so later items never join the list above. Each alternative allocates its own fresh list ids, and only one commits.
- Raw `tx.slice.replace`, `editor.read.slice.fit` and transfer copies run no landing policy, as on next and on the PR.
