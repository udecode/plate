# One blocking test lane

Status: executed
Playbook: refactoring
Page: https://claude.ai/artifact/Ajkbk1UDhGPp2E9fzzYWNE

## Brief

### What will change?

Every test now runs in one lane. 85 of the 93 slow files took under five seconds, and the eight heavy files run fewer random cases. Package test tasks hash every file their tests load, and each run checks it. A fix in Plite core also ends garbage collection pauses of 4 to 71 seconds that two Yjs tests hit in Bun's JavaScript engine, JavaScriptCore, which Safari also uses.

### What could go wrong?

Heavy tests check fewer cases per run, so a rare bug can take days to show. The daily check's new seeds also hit two law bugs that next already has, on about one day in three, until their tasks fix them. CI has not timed the heaviest cases.

## Teach

Plate's tests ran in two lanes. The normal lane held every spec and stopped a case after five seconds in CI. The slow lane held files whose names ended in slow, and every landing and CI run waited on it too.

Timed one file at a time on a loaded machine, 85 of the 93 slow files finished in under five seconds. Eight files held most of the cost, because they ran thousands of random cases or built huge documents. A second lane that every gate waits on saves nothing. So every file moves back, judged by the behavior principle on the way, and the heavy ones run fewer cases with new seeds each day.

The slow files ran outside Turbo, which replays a cached pass when none of a task's inputs changed. Inside it, a test's task has to hash every test file it runs, reads or imports, and pass through the switches that replay a failing seed.

## Main changes

- The `.slow` suffix stops being a lane. `TEST_SLOW_FILE_PATTERNS`, the `slow` mode of `tooling/scripts/test-suite.mjs`, the `test-slow` step of `tooling/scripts/check.mjs`, the slow handling in `tooling/entrypoints/entrypoint-turbo.mjs` and the `test:slow` and `test:all` scripts go away. Each slow file becomes a `.spec` file, or a `.test.mjs` file under `tooling/scripts`, and runs in the lane that owns its path.
- The eight heavy files run a bounded number of random cases and smaller documents by default, sized so each case fits the five second CI limit. `FAST_CHECK_SEED=random` in the daily full check gives fast-check and the docx, list and history-soak generators new seeds. The ledger laws in `packages/plitejs/test/authored-tree-recording-laws.spec.ts` check their pinned histories in cases of their own, and those hold the coverage floors on every seed. The random cases only require that enough random steps edit.
- `tooling/entrypoints/entrypoint-turbo.mjs` builds each package test task from the files its tests and the Bun preloads import. Package source becomes a dependency on the typecheck task that hashes it, and every other loaded file is hashed directly. Each task also gets the `test/` globs the runner's ownership rule implies, the docx fixtures the docx import tests read, and the `BENCH_MEASURE`, `PLATE_*`, `PLITE_*` and `FILL_LAW_*` variables. `docs/plans/2026-10-20-test-task-hashing.md` lands in the same commit. It hashes the imports built at run time and the root Bun config, and replaces the static import check in `tooling/scripts/entrypoint-turbo.test.mjs` with a check of what each test run loaded. `tooling/scripts/entrypoint-turbo.test.mjs` still fails when a variable a test reads misses its task.
- `tooling/scripts/import-graph.mjs` resolves imports the way Bun's test runtime does, through the workspace source aliases and then TypeScript's resolver. The Turbo generator uses it, and both Bun runners use it to give a test file its own process when it, or any helper it imports, calls `mock.module`.
- `packages/plitejs/src/core/change/tokens.ts` no longer links each prepared token to the next through a WeakMap. Each prepared open token holds the token array it was encoded into and its index there, and `decodeNodes` in `document-index.ts` compares against that array. JavaScriptCore marked the old chain one token per pass, so one collection during the 500-child unwrap cases in `packages/plitejs/test/yjs/authored-key-work.spec.ts` needed over 1,200 passes.
- The generated plitejs tests typecheck lists the ten former slow `test/` files by name, because they check clean.
- The move cuts 4 plitejs, 9 platejs and 50 www cases that the behavior principle rejects, each with the mutant or refactor that shows it, and deletes one plite tooling test that never ran.
- 882 plitejs hyperscript fixtures declare the classic JSX runtime, which the core partition needs.
- The `bench:*` scripts run their files through the normal runner. `BENCH_MEASURE=1` turns on the table and relocation wall-clock budgets. The html mapping benchmark keeps only its work counts, because its wall-clock budget could never fail, so `pnpm bench:html` goes away.
