Conditional evidence:

External editor research, issue publication, release and raw-device certification are outside this scope.

Candidate sketches:
1. Keyed `update.flashTarget({ key, attributes, duration? })` retains model effect/store ownership. It deletes string variants and path mirrors but must prove exact-view targeting and read-only feedback.
2. View-bound `api.flashTarget({ key, attributes, duration? })` keeps presentation outside model updates and uses one private target/timer per mounted view. The existing navigation descriptor is the feature owner; native view API binding or its Plate adaptation must be traced, not assumed.
3. Delete the navigation descriptor and add a raw DOM/React transient-attributes capability. Evaluate whether it merely moves the same product policy into Plite and forces new public lifetime/configuration machinery.

Frozen probe contract (before target execution):
- Operation: flash a whole element, replace it with another target, repeat on the same target, expire/clear, follow movement, drop deletion, and retire a mounted view.
- Baseline: actual current `NavigationFeedbackPlugin` and shared Plate attribute host. Target: disposable implementation using the same public view attribute host and full Plate element rendering. A prototype may bridge a proposed call shape privately; disclose which public binding is not production code.
- Independent scale variables: element hosts per view (100 normal, 1,000 large, 10,000 stress), mounted sibling views (1, 2 and 4 with 100 hosts), and 32 rapid repeat activations. Node move/removal, stale/foreign keys and teardown are pathological correctness rows.
- Timing: reuse the September 4 paired budget, target p50 <= baseline p50 + max(1 ms, 15%); target p95 <= baseline p95 + max(2 ms, 20%). Five warmups, 31 alternating paired samples per host-count row; preserve all raw samples. Initial/cold mount is diagnostic only. A timing failure is inconclusive on a shared host unless reproduced with a changed explanation; no retries solely to obtain green.
- Deterministic target guards: at most two target-host updates per target change; zero sibling-view host updates; one target contribution per originating view; no per-element producer subscription; no model/selection/history/collaboration mutation for a pure flash. Key lookup must use the canonical node read; no document scan or duplicate node index.
- Correctness: presentation appears and clears, repeats replace the timer, movement retains identity, removal clears target, unmount cancels pending work, readonly views allow presentation, wrong/foreign/retired targets fail closed, base editor has no implicit mounted-view fallback. Preserve existing footnote selection/focus/final-scroll behavior during later adoption.
- Native limit: the mounted DOM runner proves React publication and view identity, not real browser scrolling, focus, CSS animation or IME. Run existing focused navigation/footnote contracts; full native proof belongs to final production adoption.
