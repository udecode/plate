# Link toolbar: Cmd+K opens the link form

Status: executed: built and verified, waiting on your commit

Playbook: bug-fix

The owner's "Do this task here: 'Check Cmd+K on a selected word in the link demo'" took the link subject's open work item that the links review filed while proving the toolbar. In the link demo, Cmd+K opened no link form, from a selected word or from an empty caret, while the toolbar's link button did.

## Brief

### What will change?

Cmd+K opens the link form again, on a selected word or at the cursor. It broke on September 21, when the shortcut started looking for your selection in the wrong place.

### What could go wrong?

Only Chromium was tested. The browser tests that would have caught this never run in CI, so the same kind of break can come back unnoticed.

## Teach

One command, trigger, opens the link form. It looks at your selection: on a link it opens the edit form, and anywhere else it opens the insert form for the selected text.

Plate splits each editor in two: the document, and the view you type in. Only the view knows your selection. Cmd+K asked the document, found no selection and did nothing. The toolbar button asked the view, so it worked.

Now Cmd+K just names trigger, and Plate runs it on the view. Trigger also checks for itself that the editor is focused and editable.

## Demo

1. Run the www dev server with pnpm --filter www dev, open http://localhost:3000/blocks/link-demo, double-click a word and press Cmd+K. The link form opens with the cursor in its address field, and the word stays highlighted. ![after](artifacts/2026-10-12-link-cmd-k/final-browser/run-5/data/7e694d208d888bd00401202e86a0d3f519cd22bf.png)
2. Click into an empty paragraph and press Cmd+K. The link form opens there too.

## Main changes

- The copied link `trigger` reads focus and read-only state from the editor it runs on, and returns `false` when the form stays closed. The `mod+k` shortcut names `trigger` with no handler, so Plate runs it on the view's command editor, which holds the selection.

## Close

`apps/www/src/registry/components/editor/link.tsx` now runs Cmd+K through the shortcut's command form, so `trigger` runs on the view's command editor, and `trigger` reads focus and read-only state itself and returns `false` when the form stays closed. `link-toolbar.spec.ts` expects `false` for an unfocused trigger. `link-url-policy.spec.ts` gains "opens the link form with Cmd+K on a selected word". The registry entry `2026-10-12-link-shortcut-view` and the `link` payloads describe it.

The cause was commit `a6177b8a85` (2026-09-21), which changed the shortcut handler from `editor.plugin(linkPlugin).api.trigger` to the `extend` context's `api.trigger`. That `api` is bound to the model editor, which holds no selection, so `triggerEdit` and `triggerInsert` returned before opening anything. `docs/vision/plate.md` puts selection on the command editor that `useEditor()` returns. Calling `editor.plugin(linkPlugin)` inside `linkPlugin`'s own initializer is circular for TypeScript, which the handler-less form avoids.
