# Registry install edges: derive what imports require

Status: executed: built, reviewed and folded; waiting on your commit
Playbook: plan

This plan adopts the 2026-10-04 Pursue (`2026-10-04-ui-audit-2`) under the Build playbook, `.agents/playbooks/build.md`. `node tooling/scripts/review-ledger.mjs next` returned `ui` on 2026-10-08, open as `pursue-not-adopted`. Its verdict read stale only because `apps/www/src/registry/components/editor/dnd.tsx`, an evidence input whose imports did not change, and three law files moved; the install bullet in `docs/vision/plate.md` that starts "Derive required package and registry-item dependencies" reads the same at its new line 1271. The gap is still live. `apps/www/scripts/registry-package-dependencies.mts:435` throws `missing direct registry dependency` instead of deriving the edge.

The analyzer becomes the one owner of every import-required registry edge. It derives `@plate/*` and shadcn edges from each published item's copied imports and writes them into `registryDependencies` on its output, so every downstream reader keeps its input shape. The authored `registryDependencies` of a published item then holds only install policy that source cannot express: styles, companions, bundles and providers. The analyzer rejects an authored edge that the item's own imports already require, so a removed import takes its edge with it. It judges no other authored edge, because the law gives intentional bundles to authors. Six authored edges that the source shows are stale are removed one by one, each with its evidence. The same duplicate rule applies to npm packages first: today an authored bare package name hides the version range the build derives from the package DAG, which happens 19 times per base, and some of those installs get a version outside the range `platejs` or `plitejs` declares. Derived edges are sorted, so the edge order of every payload changes once, and shadcn's own resolver proves that reorder changes no install. A three-runner `architect` arena and its cross-judge picked this shape, and three plan panel rounds narrowed it (Synthesis and Panel in Evidence).

## Brief

### What will change?

The build now finds the registry links and package versions that copied code imports, so authors list only extra links. Thirteen installs stop adding unused files, and some installs ask for the versions Plate declares.

### What could go wrong?

No new app was built: the first one stopped on a separate drag-and-drop error, and the others did not run. The installer logic proved every change instead. Another session's emoji work fails two checks.
