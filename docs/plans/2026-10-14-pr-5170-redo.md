## Brief

### What will change?

A Details title turns into a list or code block from any menu, shortcut or call. A block added from a closed title shows up after it. Tab, Shift+Tab and drag move a list item with its nested blocks.

### What could go wrong?

In every list, Tab, Shift+Tab, drag, Cut and Move carry nested blocks, skipping custom Indent commands. Code across a section, and a list toggle over one that can't convert, now do nothing. The site's generated types miss twelve indentable blocks.

## Teach

A Details block is a collapsible section: a title, then a body that hides while closed. Plate lists are flat: a list item is a block with a list type and an indent, and deeper blocks after it read as nested under it.

On next, turning a title into a list does nothing, turning it into code leaves an empty title, and a block added from a closed title ends up hidden in the body. The PR fixed these by putting Details checks in List, Code block and Indent, and fixed the hiding in the slash menu only.

The redo keeps those fixes but moves the logic. Details tells Plate how to turn its title into a plain block and drop the section, and where a block added from a closed title goes. List moves an item's nested blocks itself. So List, Code block and Indent no longer mention Details, and Indent no longer knows List.

## Main changes

- Details contributes two functions through package-internal Plate plugin points, the pattern `inputRuleVeto` already uses. The first releases a title: it names the blocks that will replace the section, with the title typed the way Details' own unwrap types it, and writes the retype and the unwrap with every key kept. The second makes a caret-relative insert from a closed title land after the Details.
- `list.toggle` and `codeBlock.toggle` read releases, check the whole result of every parent they change through Plite's placement owner and Indent's maximum before any write, and only then apply them. A title converts from a direct call, the Turn into menu and the list Markdown markers alike. Neither command names Details or Summary. `codeBlock.toggle` also refuses a selection in a named root that the editor or view running it does not edit, because Plite's replace writes by bare path.
- Plite's `canPlaceAtPath` lets a parent with no content program take any fit, the rule Plite's node-selection replacement already applied, and `plitejs/internal` exports `canPlaceBlocksAtPath` over it. List and Code check each changed parent's window of replaced siblings, with their full ancestry, through one shared `canReplaceContainers` beside the release point, without copying placement law. The approved text said "`plitejs/internal` exports a wrapper around Plite's `canPlaceAtPath` that passes a parent with no content program"; the quality review moved that rule into Plite, so the wrapper reads its parent itself.
- Block insertion resolves the anchor first, before the `replaceEmpty` shortcut and before it decides whether to reuse an empty block, for every plugin `insert` and `upsert`, upload's caret insert, file paste and both AI insert paths. One predicate says whether an empty block may be replaced, and every Plate path that honors `replaceEmpty: true` asks it, so an empty structural block, such as a title, keeps its slot. `tx.blocks.insertAfter` stays literal, and the slash menu goes back to next.
- List owns one family definition, a list item and every deeper sibling after it, which feeds transfer source, transfer landing, Tab, Shift+Tab and `list.outdent`. List expands each family itself and writes each member's new depth by key: its list depth plus or minus one, with the indent unset at 0. `BaseIndentPlugin.ts` is byte-identical to next. The approved text said List "moves every member through Indent's own command, matched to that member's exact path"; the diff panel's second round and the quality review replaced that route, and the Close says why.
- `ListKit` keeps next's targets; `IndentKit` adds twelve of the thirteen body types the PR added to `ListKit`, all but the table.
- Every key these commands and contributions read comes from a path in the target's root, never from a node, and each plugin point receives that root. `rootOf` gives a range or node selection's root through `SelectionApi.root`, the owner it once copied. Inside an input rule's draft, Plite has no key for a node the draft just wrote, so a key read from the node fails while one read from its path works. That is how a list marker typed in a title converts it.
- Plite's contribution reader returns each contribution as its own type. It wrapped function values in `Readonly`, which drops their call signature, and Plite cast around that in two places.

### Title release

- `blockRelease`, a package-internal point in `platejs`. Details contributes a function of `(state, entry, root)`: `null`, or, for the title of a Details, `{ block, container, fit, key, apply }`.
  - `fit` is the blocks that will replace the Details, title first. The title's type follows Details' own `unwrap`: a title with a level becomes that heading, otherwise a paragraph. The release and `unwrap` share that mapping in one function.
  - `apply(tx)` writes by node keys: it retypes the title, then unwraps the Details with every key kept, and returns whether it wrote.
- `readBlockReleases(tx, entries, accept)` collects releases outermost first; `applyBlockReleases(tx, releases)` applies them innermost first and fails an invariant when an `apply` returns `false`, because the caller's preflight already showed the writes fit. Both are package-internal helpers beside the point.
- The release drops the section's indent, as Details' `unwrap` does on next.
- Under List's default targets, which hold no heading, a leveled title declines as a heading does.

### List conversion

In `features/list/lib/listConversion.internal.ts`, so `BaseListPlugin.ts` stays a caller.

1. Collect the blocks List matches, plus each release whose released type List would match.
2. Return `false` when there is nothing to convert.
3. Compute every final block before any write: its type and its depth. A title's depth is `max(1, details.indent)`; each direct body block's depth is the title's depth plus `max(1, its list depth)`; a body block that was itself a released Details nests its own title and body the same way.
4. Preflight, and return `false` with nothing written when any check fails:
   - every final block deeper than 0 has the `indent` property;
   - no final depth passes Indent's `indentMax`;
   - the final children of the parent of each outermost release fit. One check per parent and root covers the window from its first released Details to its last, with the unchanged siblings between them. `canReplaceContainers` calls `canPlaceBlocksAtPath`, and through it Plite's `canPlaceAtPath`, at the window's first index with every index in the window removed, so allowed types, positions, child limits and properties that resolve through ancestors all count. A parent with no content program passes, a rule `canPlaceAtPath` now applies itself;
   - a named-root target resolves in that root.
5. Apply the releases innermost first, run the toggle over the matched blocks and released titles by node key, then write each final depth by key.
6. A second toggle on the result toggles the list off, as on next.

### Code conversion

- `codeBlock.toggle()` returns `boolean`: `true` when it changed the document, `false` when it refused or when unwrap could not replace a code block. Unwrapping a code block of several lines whose paragraphs do not fit the parent still throws, as on next; round 2 of the diff panel made Plite's replace refuse it, and round 3 reverted that because AI accept then dropped its answer.
- A selection inside one title runs the same placement check, through `canReplaceContainers`, on a code block followed by the body in place of its Details, and refuses with nothing written when it fails. Otherwise it releases the title and converts it alone. The body follows as siblings with its indent unchanged.
- A selection whose span holds a title and anything outside that title, or two titles, refuses with nothing changed, before either direction runs. A block selection counts its span, so two selected blocks around an unselected Details refuse too; the conversion joins every block of the span, at next as well, which `task_5b278db5` owns.
- A selection in a named root that the editor or view running the toggle does not edit refuses.
- The code fence rule stays as on next, so a fence typed in a title stays text.

### Landing

- `insertionAnchor`, a package-internal point. In Details' contribution, the title of a closed Details anchors to the Details. Open titles anchor to themselves, so an insert lands in the body as today.
- `applyBlockInsertion` resolves the anchor first when the caller gave no `at` or `after`, before the `replaceEmpty` shortcut and before it decides whether to reuse an empty source.
- `isReplaceableEmptyBlock` is the one predicate for replacing an empty block, and it gains upload's rule that an empty structural block keeps its slot. `applyBlockInsertion`'s `replaceEmpty` shortcut asks it and turns replacement off when it says no; upload's explicit `after` path asks it in place of its own copy. So an empty title, open or closed, is never replaced, and `UploadPlugin.spec.ts`'s "keeps an empty details summary when a file drops after it" keeps passing.
- Upload's caret-relative insert, file paste, AI "Insert below" and AI accept resolve their anchor through the same helper. File drop keeps its pointer target. An explicit `at` or `after`, `tx.blocks.insertAfter`, Duplicate and transfer keep their own placement.

### List families

- `features/list/lib/listFamily.internal.ts` holds the one definition. A family is a list item and every following sibling deeper than it, list or not; an omitted indent reads as 1 on a list item and 0 elsewhere. It feeds transfer source, transfer landing, Tab, Shift+Tab and `list.outdent`. Next's transfer family stops at the first non-list block, so drag, copy, block-menu Cut and Move up or down of a list item now also carry its continuation blocks in every list.
- List moves families itself, and Indent stays byte-identical to next. One helper groups the targets into families, so a selected child of a selected parent moves once. It skips a whole family whose deepest member would pass `indentMax`, then writes each member's depth by key: its list depth, where an omitted list-item indent reads as 1, plus or minus one, with the indent unset at 0. It writes the container itself, so a Details' or a quote's inner blocks stay where they are.
- The approved text said the helper "calls Indent's `increase` or `decrease` once per member with a `match` on that member's exact path", which needed Indent's commands to write each block by its key, because next's wrote a named root's block into the main document (`docs/plans/artifacts/2026-10-14-pr-5170-redo/probes/indent-named-root-a2.log`). The quality review replaced the route: `list.toggle` already writes depths directly, no plugin in the repository wraps Indent's commands (a `git grep` of Indent plugin uses outside its own folder in `packages/*/src` and `apps/www/src`, run 2026-10-14, finds only `configure` calls and command calls), and the route through Indent crashed on keys in round 1 of the diff panel. An app that overrides Indent's commands no longer sees Tab on a list item; the Defaults word `indent route` brings the route back.
- `handleListTab` and `handleListUntab` each call that helper once over the selection. Shift+Tab keeps next's root filter, so `ListPlugin.spec.tsx:419` keeps passing. A quoted root item lifts out of the quote with its whole family, which ends one level shallower.
- `list.outdent` moves each target's family, then clears the list fields of a target left at 0. Enter and Backspace call it, so a root item with a body at depth 2 ends with no indent and its body at 1, as the PR's spec asserts.
- The toolbar and block-menu Indent buttons call Indent and stay per block, as on next.

### Registry

- Turn into a list is one module-level command. It resets every selected block with `level` unset, as on next. The exception is a block directly inside a Details body, which becomes a paragraph with `level` unset. Details has one content default, the Summary, so a reset would turn that block into a Summary. Then the list clears and the toggle runs; a `false` toggle discards everything. A code block still becomes a paragraph list item, and a slot that requires a heading keeps it, as on next.
- The Turn into menu disables Code for a selection that holds a title and anything else, which `codeBlock.toggle` refuses.
- `IndentKit` and its static kit add twelve of the thirteen body types the PR added to `ListKit`: audio, callout, code drawing, column group, equation, Excalidraw, file, horizontal rule, media embed, table of contents, upload and video. `ListKit` keeps next's targets, so those types take an indent without becoming list items. The table stays out. Table already stores its own left margin in `marginLeft` and writes it to HTML, and Indent would read and write the same CSS. So a section whose body holds a table stays unconverted in the app. The indent buttons still indent the lowest blocks of a selected container, as on next.
- `slash.tsx`, `list.tsx` and `list-static.tsx` go back to next.
