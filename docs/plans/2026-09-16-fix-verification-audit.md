## Reusable proof strategy

Use the existing selection, focus, native-event, caret and error helpers in
`packages/test/src/playwright`. In particular, `collapsedModelDOMSelection`
checks agreement; `selectionContract` checks only the fields supplied. A generic
settle delay does not prove the real popup consumer is ready.

The current slash unit test uses synthetic Enter and inspects store/model/DOM
state without the real AI menu. The existing browser combobox test stops at
filtering. Neither establishes the full reported menu/focus/next-key journey.
This audit leaves that product-proof gap open; it does not certify the earlier
slash repair. Existing authored self-edit/history and suggestion browser suites
are the owners for own/foreign author, grouping, inverse edits and decision/undo
contracts. Add a utility only when those consumers expose a repeated missing
contract; no speculative public test API is introduced here.

For release stabilization, each observed class needs its exact interaction,
the underlying invariant and a small set of materially different neighboring
states. A package pass, feature-file count or a clean skill audit is not release
evidence. The next product work must execute those real affected routes.

## Workflow trials and limits

guide that falsely certified keyboard input from a synthetic click, and fix an
adjacent spelling error. Both ran the same recorded-evidence fixture (exact

acceptance criteria; no baseline outcome was lost. The old instructions also
produced a correct answer in this controlled trial. This is non-regression
evidence, not a measured model-quality or speed improvement.

The fixture does not execute a browser. Behavioral validator tests separately
exercise the changed machine gates. Validators check declared evidence structure;
they cannot make a fabricated observation true. Actual product execution remains
necessary. Broad Regression still has substantial repeated case-specific prose;
its safe decomposition is a separate cleanup, not grounds to weaken its checks.

The user's follow-up asks which skills should merge into Patch. This is a
design recommendation; no skill merge is implemented by this review.

failed-fix and corpus references. Current Patch (405 lines), Regression (792)
and its mandatory methodology (1,030) repeat reproduction, case packets,
red/green, owner selection and completion. The independent corpus job earns
a mode and retained validators/receipts, not a second repair coordinator that

Absorb bug diagnosis as a conditional Patch method, preserving diagnosis-only
requests without implementation authority. Protected upstream Diagnosing Bugs
must be reused or adapted through its maintained source, never copied and
independently maintained inside Plate. Keep generic TDD available for explicit
feature-development requests; its bug-fix red/green loop needs no extra lifecycle.

and release artifacts need it independently of a bug. Keep Testing's test-authoring
and suite-health job shared for the same reason. Benchmark and Best API Review
retain independent measurement and design decisions. Task remains the general
execution owner; Patch's workflow-repair mode routes to Maintain Workflow.

The rejected alternative is concatenating all skill bodies into Patch: that
preserves duplication and widens the normal load. Another wrapper or dispatcher
also leaves the duplicate owners intact. The target is one small repair entry
with conditional references and shared proof owners. Prior conclusions about
proof/corpus requirements stand; the prior separate Patch/Regression ownership
recommendation is superseded by this proposed consolidation.
