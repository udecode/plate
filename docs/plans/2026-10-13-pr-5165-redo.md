## Teach

A Details block is a collapsible section. Its first child, the Summary, is the title that stays visible. The blocks after it form the body, which hides when the section closes.

The author's commits let the title carry a heading level, so the repair that keeps the title first never sees it go missing. Their drag-select scrolled with its own 40 px edge zone.

These commits keep that model. Heading toggle-off and Text reset each block to its own default in one call that changes every block or none. Drag-select scrolls through the helper text selection uses, and its start follows the nearest block. The merge brought in next's rewrite, which keeps Details open after undo. The author's undo fix went with the code that rewrite replaced.

## Document shape

A leveled title stores its level on the Summary; a plain title is unchanged.

```json before
{ "type": "summary", "children": [{ "text": "Title" }] }
```

```json after
{ "type": "summary", "level": 2, "children": [{ "text": "Title" }] }
```

HTML writes the heading inside the summary, and Markdown writes the level as an attribute.

```html before
<summary>Title</summary>
```

```html after
<summary><h2>Title</h2></summary>
<!-- Markdown: <summary level="2">Title</summary> -->
```

### Heading on a title

Synthesis: `architect/synthesis.md`. Four candidates competed: the draft, Opus, Astra and Sol. The cross-judge preferred the nested-title candidate behind a three-part gate, and the lead overruled it on domain fit, block UI and blast radius.

- Kept from the draft: Summary `level`; `read.level`; `setLevel`; wrap and unwrap carrying the level; the function form of `tx.blocks.set`, which round 1 dropped and round 2 restored.
- `setLevel(level)` is one `tx.blocks.set((node) => (isSummary(node) ? { level } : { level, type }))`, so one admission decision covers the whole selection. It returns `true` without writing when every target already has the level, so `false` means only a refusal. Round 3 showed that a bulleted H2 kept its bullet when the menu read a no-op as a refusal. Round 2 found two flaws in the two-step version. An app schema can require a fixed Summary level, so a Summary write can be refused. And `tx.blocks.set` also returns `false` when nothing needs to change.
- `setLevel` takes a level only. Removing a level is Text, which in the turn-into and block menus is `tx.blocks.reset({ unset: ['level'] })`: each block goes to its own default, a title stays a title, and the level goes. Those menus call it whether or not Heading is installed. Text keeps its early return for an already-plain selection only when no selected block carries a level, because without Heading a leveled title reads as plain, and the base menu also reads quotes and code as plain. Slash Text keeps the Paragraph upsert, which inserts after a block with text, and clears the level only on a title. Round 3 found both cases.
- `tx.blocks.reset` checks every target before it writes, as `tx.blocks.toggle` already does when it turns blocks off, and returns `false` with the document unchanged when one is refused, `true` otherwise. `unset` takes the input `tx.nodes.unset` takes and removes the named properties the default does not set, as toggle-off already does. Reset still throws when a parent declares no default child, as today. Round 2 showed that reset threw at commit for a required heading inside a container whose other blocks default to Paragraph.
- `toggle` turns the selection off with `tx.blocks.reset({ unset: ['level'] })` when any target already has that level, through `read.level`, and otherwise calls `setLevel`. For a selection without a title this is what `tx.blocks.toggle({ level, type })` did; `probes/reset-level-a2.log` shows both give the same paragraph.
- Every caller that composes reset with other edits checks its result first, because a refusal no longer rolls the transaction back. The Text and heading menus clear list formatting only after the format returns `true`; the list items reset first, with `unset` level so a leveled title loses its level as an H2 does, and stop on refusal; `OverridePlugin` returns no handler when its reset is refused, so the default command runs; split-reset keeps the split, so Enter at the start of a required heading inserts an empty heading above it; the editor view returns reset's result. All three round-3 seats raised this.
- The heading menus keep their early return when that heading is already active. Heading's toggle no longer dispatches the `block.toggle` command, and the changeset says so.
- Heading finds the Summary, and Details finds Heading, through the PR's internal compiled-model lookup. The plan named `editor.plugin(PLUGINS.x)`, but the build showed that a plugin definition's editor takes only a plugin object, so the name form compiles only in input rules, where every Code block lookup sits. A typed lookup is Open work.
- Heading keeps its generated upsert. The slash Heading items call `setLevel` on a title, empty or not, because inserting after a title puts the new block into the body, hidden when closed (round 1), and call `upsert` elsewhere. The plan had Heading author its own upsert; the build dropped it because it copied the generated insert policy over the internal `applyBlockInsertion`.
- The block menu labels H4 to H6 by level; HTML reads a level only from a sole heading child.
- The Details grammar and its repair stay as on `next`. All three round-1 seats showed that under `schema.content.prefix` most writers throw at commit instead of refusing, and that values `next` loads stop loading, such as a struck Summary followed by a live one, or Summaries out of order. Moving the title slot into the grammar is a separate plan.
- The TOC stays as on `next`; listing leveled titles waits for navigation that opens a collapsed outer Details (round 1).
- Unchanged heading-type readers: list numbering (`listIdentity.internal.ts`, `BaseListPlugin.ts`), the AI heading type and the pagination demo treat a Summary as a title, not a document heading.

### Marquee near the editor edge

Synthesis: `architect-marquee/synthesis.md`. The lead and the cross-judge both picked Sol's one-shot DOM method as the base.

- Kept from the draft: the frame loop continuing while scrolling moves; candidate rectangles reread after each scrolled frame; paint clipped, hit-testing unclipped; the gesture-scoped MutationObserver with its filter and the ResizeObserver; the four stationary-pointer browser cases and the clip case.
- Changed: scrolling through `editor.api.dom.drag.autoScroll`, which calls the same helper as text drag and block drag; that helper measures each scroller's visible part (round 1); the origin as a content point that follows its nearest block, as the last bullet says; one ordered invalidation state; the paint clip read through `visibleRect` after the scroll write; tests use measured viewport geometry and check that the marquee calls the helper once per frame.
- Dropped: the private scroll policy; the block-key origin; content-space rectangle caching. Round 1 showed that an image loading mid-drag inside a fixed-height editable moves blocks without any signal the cache watches.
- The public method returns only the pixels it scrolled, 0 when it did not; text drag keeps the clamped point inside Plite, and the marquee's rectangle uses the raw pointer.
- The helper finds each scroller's visible rectangle in one outward walk along the containing-block chain: a fixed box clips only to the viewport, an absolute box skips ancestors up to its positioned containing block, and `html` and `body` count as the viewport, measured as `documentElement.clientWidth` and `clientHeight` so a horizontal scrollbar does not count. Each edge zone is capped at half the visible height, so the two never overlap. `editor.api.dom.visibleRect(element)` returns that rectangle. Round 2 found the outer-scroller case; round 3 found the `html` and `body`, fixed-box and short-strip cases.
- Built: the helper moved to `packages/plitejs/src/dom/plugin/dom-drag-scroll.ts`, and text drag and block drag call it there. It matches clipping `overflow` values and positioned `position` values by name, because jsdom reports unset ones as empty strings. `visibleRect` returns a plain rectangle with the four edges and two sizes, Plite's existing `DOMGeometryRect`, now exported. The marquee clips its paint to `visibleRect(editable)`, which already cuts to every clipping ancestor and the viewport.
- Built after the build found the origin drift: the start follows the edge of the block nearest it. Selecting a block can grow it, as a Summary does when it shows its open state, and a content-point start then sits in a different block. The start stores that block's key, which edge it sits beyond (above, below or within) and the offset from that edge; each frame it rereads that block's rectangle and moves the start with it, and a start within a block stays inside it when it shrinks. While that block has no box, the last position stands. Synthesis: `architect-origin/judge/verdict.md`, where the cross-judge picked the same base.
- After diff round 3, the marquee's ResizeObserver is the PR head's again. It watches only the editable and rereads geometry on every report. Rounds 1 and 2 also watched each candidate block, and round 3 showed their size check could miss growth under a scale transform. So a block that grows when selected, such as media showing its caption, keeps stale hit rectangles inside a fixed-size editable until the next scroll or resize. Each gesture start also rereads every candidate once, for the editable's first report. A tested fix for both waits in Open work. Pointer release stops both observers after the last selection update. The visible rectangle clips each axis only when an ancestor clips that axis, and it scales an ancestor's client box to its transformed border box.
- The authored view-selection cache stays, by G3.

### G2 authored history per commit

- Operation: typing in an editor with the authored plugin and history, in edit and propose views, and undoing a large deletion.
- Cohorts: typing at 1,000 and 10,000 paragraphs; undo in an edit view after deleting 100 and 1,000 paragraphs at 10,000; undo in a proposing view after deleting 100 paragraphs at 10,000.
- Count lines, which decide on a loaded host: document index builds per typing commit and per undo, counted at `DocumentIndex.remember`, at most the base's plus 2 in every cohort. The base builds 1 per typing commit and about 2 per restored node on undo (`scale/g2v2b-smoke-base-a1.log`).
- Typing line: 200 single-character commits after 20 warmups; candidate p95 per commit at most the larger of the base p95 times 1.10 and the base p95 plus 0.5 ms.
- Delete and undo lines: candidate p95 at most the base plus the larger of 20% and 5 ms per cohort, with every restored node key checked. At 1,000 deleted paragraphs the base already takes about 10 s to undo, so that line measures existing cost.
- Controls: a planted 2 ms delay per commit must fail the typing line; a mutant that copies the root array before each lookup at `packages/plitejs/src/authored/history.ts:81`, so every restored node builds an index, must fail the count line at both deletion sizes; the three base passes compared with each other must pass every line, with the key check off because the base never restores keys; a pass missing a cohort and a pass missing a count must each fail with `budget input missing`.
- Protocol: three interleaved base and candidate passes, median of the per-pass p95, load average recorded. The comparison names the four typing and three undo cohorts itself and fails on fewer than three passes per side, a missing cohort or a value that is not a finite number. When the 1-minute load average passes the core count, a timing miss is reported inconclusive and only count and key misses fail. Harness: `scale/g2-probe-v2.ts` and `scale/g2-compare-v2.mjs`. The `plite-authored-scale` target is not a guard here, because its workload file is missing (Open work).
- Result before the fix: every count line passes with the candidate equal to the base. On a quiet host, at load 4 to 8 on 18 cores, the delete of 1,000 of 10,000 paragraphs missed conclusively, with medians of 2,249 to 2,290 ms at the base and 2,901 to 2,955 ms on the candidate, which sent undo identity to `architect`. Typing at 10,000 and undo in a proposing view also missed at p95.
