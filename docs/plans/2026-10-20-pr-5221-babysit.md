## Teach

A click past a code line's end used to stop before plain runs like a closing bracket, because Plite's word search skips them. The PR's fix asks the browser where its caret would go. My commit uses that answer only when the two answers differ.

The PR's typing fix covers a selection from a paragraph's end into a synced copy. Each delete of the selection moves the caret, and the last one left it inside the copy, so typed text went there. The fix reordered the deletes, which changed nothing, and reset the caret. My commit drops the reorder and carries the start through the deletes, so the caret lands there even when a delete reshapes that paragraph, as a table's does. It also reads the start in the outer document when you type through the copy.

Enter works as before.
