# Link href: one public link decision for copied chips

Status: executed: built, reviewed and verified; waiting on your commit
Topic: link
Playbook: plan

The tags review left one item open. A read-only chip links its stored `url` as given, because Plate's navigation check is internal. A malformed absolute url such as `https://` throws while the chip renders. The owner asked to "give copied UI a public way to decide a navigation URL, the same decision BaseLinkPlugin uses, then make tag.tsx link a chip only when that decision accepts its url, and never throw on a malformed one", keeping `mailto:` and `tel:` links and adding cases for `"https://"`, `" data:text/html,x"` and `"\tjavascript:alert(1)"`. The run's base is `5fc246c291`. The owner's commit `6fa1169c5e` landed before this run edited anything, so this run measures its diff from that commit.

## Brief

### What will change?

Read-only tag chips link only addresses Plate's link check accepts, and broken or bracketed addresses no longer crash them. Copied UI gets that check as `getLinkHref` from `platejs`.

### What could go wrong?

Nothing is committed yet, and the registry files also hold other sessions' changes, so commit them together. Chips still save any address, and only a test outside the suite runs Next's app router link.

## Teach

A navigation check decides whether a stored address may become a clickable link. Plate's link feature runs it for every link. It trims spaces, refuses addresses that can run script, such as javascript or data addresses, and refuses broken ones, such as https with no host. It allows web, mail and phone addresses plus relative paths, unless the app changes that list.

Today that check is private, so the copied tag chip makes its own guess. The guess turns a data address with a leading space into a relative link, and a bare https crashes the read-only field.

After this change the link feature exports the same check as one function. The chip asks it before it links, with the editor's link settings when links are installed. A refused address shows as an unlinked chip.

## Public API

Copied UI asks link's decision before it renders a stored address as a link.

```tsx before
// apps/www/src/registry/components/editor/tag.tsx
{readOnly && element.url ? (
  <Link href={toLinkHref(element.url)}>{badge}</Link>
) : (
  badge
)}
```

```tsx after
// apps/www/src/registry/components/editor/tag.tsx
{readOnly && element.url ? (
  editor.plugin(BaseLinkPlugin).installed ? (
    <ConfiguredTagLink url={element.url}>{badge}</ConfiguredTagLink>
  ) : (
    <TagLink href={getLinkHref(element.url)}>{badge}</TagLink>
  )
) : (
  badge
)}

function ConfiguredTagLink({ children, url }) {
  const allowedSchemes = usePluginStore(BaseLinkPlugin, 'allowedSchemes');

  return <TagLink href={getLinkHref(url, { allowedSchemes })}>{children}</TagLink>;
}
```

## Main changes

- `BaseLinkPlugin.ts` keeps link's default schemes in one private constant that `initialState.allowedSchemes` and `getLinkHref` share. The private `getLinkHref(allowedSchemes, url)` goes away; HTML decode, input admission and `getAttributes` call the public `getLinkHref(url, { allowedSchemes })`, and `getAttributes` keeps its `typeof` guard for an element's untyped `url`.
- `tag.tsx` asks `getLinkHref` with link's default schemes, or, when the editor installs link, with its `allowedSchemes` through `usePluginStore`, so a later change re-renders the chip. `TagLink` treats an accepted href that parses on its own (`URL.canParse`) as absolute, because a relative reference never parses without a base. It renders an `http` or `https` href through `next/link` with `new URL(href)`, as before, and a relative href through `next/link` split into `pathname`, `search` and `hash`, so `?` and `#` stay unescaped. Both paths reach Next with `[` and `]` escaped as `%5B` and `%5D`, because Next's development check throws on a bracketed segment, which it reads as a route pattern. A `mailto:`, `tel:` or custom-scheme href renders a plain anchor, because Next's formatter drops a custom scheme's `//` and Next does not navigate those in the app.

### Must-answer answers from the arena

1. This plan adds no floor to the chip. A validator makes `createEditor` and `tx.value.replace` throw `EditorSchemaValidationError` on a chip url such as `https://` (`docs/plans/artifacts/2026-10-12-link-href/premises-a2.log`, `docs/plans/artifacts/2026-10-12-link-href/installed-a1.log`), so the floor needs admission, a report for what it refuses and a migration note, which the owner's ask does not cover. The judge, two runners and all three plan panel seats asked for the floor; the plan defers it with an owner and a stop under Open work.
2. With no schemes passed, `getLinkHref` allows link's defaults (`http`, `https`, `mailto`, `tel`) plus relative URLs. A chip in an editor that installs link passes that plugin's `allowedSchemes`, so it activates what that editor's links activate.
3. The default list is one private constant in `BaseLinkPlugin.ts`.
4. An accepted absolute href always parses with `new URL`, because `decideUrl` refuses one that does not (`urlPolicy.ts:110`). A web href goes to `next/link` as `new URL(href)`, whose `pathname` holds no host, so Next's App Router link renders `https://[::1]/docs` in development, while a split that left the host in `pathname` throws (`docs/plans/artifacts/2026-10-12-link-href/ipv6-a4.log`). Other schemes render a plain anchor, because Next's formatter drops `//` from a custom scheme (`docs/plans/artifacts/2026-10-12-link-href/basepath-a1.log`).
5. `docs/vision/plate.md:742` bars a format from adding its own check. This plan deletes the chip's own check and exports link's. The deleted public `sanitizeUrl` took any role and had a bypass. `getLinkHref` decides navigation only and has no bypass.
6. The input type is `string`, because `decideUrl` reads a string. With `unknown`, `getLinkHref(element)` would compile and never link.
