## Harsh verdict

The original plan treated a well-populated inventory as an accepted design.
Its strongest findings were mixed with unjustified moves and removals:

1. Two compiler namespaces would preserve much of the internal protocol
   without proving a useful public interface. The CLI consumes facts about
   schema and bindings; that does not justify exposing live runtime caches.
2. Phase 1 bundled unrelated architecture projects. A failed checkpoint could
   not identify which decision to keep or undo.
3. The generic-hook cut omitted lifetime differences. Slots can be suppressed
   by read-only policy; the DnD scroller can be disabled; a menu can be hidden.
   None of those states may silently disable cleanup or stream ownership.
4. Whole-feature Tabbable relocation confuses browser mechanics with product
   policy. Deleting `platejs/testing` confuses no internal callers with no
   public job. The proposed replacement does not export equivalent helpers.
5. `DocumentChange` serialization is not a complete suggestion model.
   Durable proposal identity, historical base, selective resolution, retained
   deleted content, and concurrency are still unanswered.
6. The 28 checker diagnostics do not establish a need for a new policy
   framework. First adjudicate the actual source/rule failures.

These are changes to the plan's decisions, not merely stronger wording.

## Selected target

Keep the four distributions and their dependency-aware entrypoint graph.
Plite owns neutral editing and collaboration. Plate owns plugin authoring,
product policy, and its facade. Registry components own application sessions
and copied UI.

- Move raw Yjs and neutral cursor reads/projection to `plitejs/yjs[/react]`.
  Keep `BaseYjsPlugin`, `YjsPlugin`, configuration, and Plate paint policy
  in `platejs/yjs[/react]`. One controller and one change pipeline survive.
- Replace CLI access to mutable Plate runtime structures with one immutable
  compilation result. A narrow `platejs/compiler` serves this actual
  build-time job. Its implementation reuses the same lowering as runtime
  construction; it never becomes a second compiler.
- Do not add `plitejs/compiler` as a generic framework-access bucket.
  After Yjs moves, classify the remaining cross-package calls individually:
  delete obsolete demand, reuse a canonical public operation, or retain the
  smallest supported framework contract with explicit proof.
- Replace generic `useHooks` with explicit component ownership only after
  the current mounting and cleanup laws are reproduced. Keep specialized
  view-attribute publication and editor mounted-state handling private.
- Retain Tabbable product policy, the testing facade, current Suggestion
  storage, Comments anchors, and distinct rendering strategies. The deferred
  rows below name the evidence needed for any further cut.

This chooses ownership and interface direction. It does not accept an
unmeasured hot-runtime implementation.

Proposed public calls:

```ts
// Existing ordinary path: no generated contract or compiler import.
import { createEditor } from 'platejs';
import { EditorKit } from './components/editor/editor';

const editor = createEditor({ plugins: EditorKit });

// Existing customization remains descriptor-owned.
import { DndPlugin } from 'platejs/dnd/react';

const dragHandles = DndPlugin.configure({
  initialState: { enableScroller: true },
});

// Proposed advanced build-time boundary; not implemented.
import { compileEditor } from 'platejs/compiler';

const artifact = compileEditor({
  plugins: EditorKit,
  schema: applicationSchema,
});
```

The proposed artifact contains only validated serializable schema and binding
facts needed by the CLI: capability names, persisted identities, and authored
mutation eligibility. It exposes no editor instance, candidate runtime,
plugin cache, store, callback graph, or private witness. It does not serialize
TypeScript property domains. Those remain CLI type materialization, with
existing descriptor-derived public types tested before any additional
type-only compiler contract is allowed.

Public compilation syntax is a proposal. Its exact output/type contract and
declaration-isolation fixture must pass before phase 2 is accepted.

Three design passes:
1. **Ideal:** private lowering, one canonical runtime, minimal author API,
   optional exact build artifacts; compare moving machinery with deleting access.
2. **Hostile:** test the new namespaces, whole-feature moves, helper replacement,
   suggestion semantics, lifecycle mounts, and combined phase blast radius
   against E01–E13.
3. **Replay:** select the narrower target. Keep testing and Tabbable. Gate
   compiler type output and hook lifetime. Remove DnD/Suggestion rewrites and
   AI/HTML policy moves from the three-phase execution spine.

Challenge delta: **replaced**. Two general compiler surfaces and bundled
runtime rewrites become one narrow artifact boundary, a proven Yjs ownership
correction, and a separately falsifiable lifecycle cut. The selected target
retains fewer new public concepts and makes no unsupported parity claim.

Residual falsifiers:
- If moving Yjs does not reduce cross-layer demand, retain its independent raw
  distribution job but correct the remaining bridge owner explicitly.
- If a compilation artifact needs mutable runtime access or cannot preserve
  exact output, reject that interface before moving any root export.
- If named components cannot preserve hook lifetime without another generic
  host or duplicate subscriptions, retain the current mechanism while fixing
  the owning mount contract. Do not ship partial cleanup.
- Keep deferred representations and backends until their own evidence wins;
  they are not mandatory later phases hidden behind the word “cleanup.”
