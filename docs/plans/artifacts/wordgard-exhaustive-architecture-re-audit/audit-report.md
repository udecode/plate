Two reproducible read paths also violate Wordgard's documented immutable-state model. Calling `collab.sendableUpdate` on one state changes a later transaction derived from that same state from `AB` to `A` because transport reservation mutates the embedded field. Serializing History preserves the field object but replaces its live `done` branch (identity changed). Transport reservation belongs outside an immutable snapshot; serialization must copy/map instead of normalizing the live field.

The persistence contract fails at construction too. Plot and Slice constructors retain caller-owned arrays: appending a second text leaf changes their serialized content to `AB` and `AB` while both cached lengths remain stale. Leaf construction likewise retains a caller-owned mark array, so the same node changes from `"A"[Strong]` to `"A"[Strong,Emphasis]`. `Transaction.newDoc` is publicly writable; replacing it makes the published state disagree with the canonical change (empty versus `A`). A failed lazy field update also leaves `tr._state` cached: the next read exposes document `A` and reports `Cyclic dependency between fields and/or facets` instead of preserving failure atomicity. Wordgard's nominal classes therefore do not currently deliver the immutable-value or publication guarantees used to justify them.

## Attachment verdict

The persisted-identity law is right: first-party persisted AST identities should be explicit semantic names, while behavior-only plugins should have no AST type. Two attachment details lose: `KEYS` cannot spread `NODES`, and migration is a pure host persistence operation rather than an installed compatibility plugin. Its `h1` through `h6` exception survives. Plate exposes real per-level installation, component, rule, shortcut, injection, and finite-type configuration; collapsing those contracts into one `heading + level` plugin would trade away useful plugin granularity for prettier algebra.
