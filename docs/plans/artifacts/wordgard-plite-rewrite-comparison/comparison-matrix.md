# Wordgard versus Plite

## Current implementation note (2026-07-18)

The five highest-ranked residual gaps from this comparison are implemented in
the live Plite tree:

- commits expose lazy `DocumentChange` queries instead of an eager
  `EditorCommitImpact` object or duplicate operation classifiers;
- Yjs translates remote events to canonical incremental changes and lowers
  canonical changes outbound, with intents restricted to replay-verified
  optimization;
- active anchors share one incremental root index per change while retaining
  per-change mapping semantics;
- generated model/property laws cover nested structure, properties,
  multi-root lifecycle, serialization/inversion, corrections, and pairwise
  transforms;
- each Plite React root owns one bounded DOM phase scheduler for model work,
  DOM reads, DOM/React writes, and selection repair.

The ratings below preserve the source comparison that motivated the rewrite.
Rows describing those five gaps are historical inputs, not claims about the
current implementation. Current execution evidence lives in
`docs/plans/2026-07-18-plite-canonical-change-architecture.md`.

Ratings compare the current checked-out sources, not project reputation or
code size. “Superior” means a better substrate design or a materially stronger
proven capability for Plate's target. “Incomparable” means the systems chose
different product boundaries or no fair behavioral/performance evidence exists.

## Model, schema, and change law

| Surface | Rating | Why | Rewrite verdict |
| --- | --- | --- | --- |
| Public document representation | **Plite superior** | Plite's plain `{ type, children, ...props }` JSON is easy to inspect, serialize, type, sync, and hand to arbitrary app code (`packages/plite/src/interfaces/element.ts:11-17`). Wordgard serializes to JSON but makes class instances, tags, params, and mark sets the live public model (`../wordgard/src/doc/node.ts:23-25`, `:61-95`). | Keep plain JSON as the public/storage format; publish frozen persistent snapshots. Do not import `Plot`/`Leaf` classes. |
| Published immutability | **Wordgard superior** | Wordgard nodes and `GardState` are persistent values and every transaction creates a new document/state. Plite publishes immutable snapshots but mutates editor-owned trees during a transaction, snapshots/rolls back, and reconstructs the commit (`packages/plite/src/core/public-state.ts:4934-5035`, `:5037-5244`). | Make the transaction draft the only mutable object and publish a structurally shared immutable snapshot. No mutable editor tree as engine truth. |
| Tree vocabulary | **Plite superior** | `Element`/`Text` over JSON has less ontology than plot/leaf/tag/param/mark and matches Plate's existing data. Wordgard's vocabulary enables its token algebra but leaks engine machinery into user data. | Keep element/text JSON vocabulary; build the token index as a private snapshot sidecar. |
| Canonical coordinates | **Wordgard superior** | One integer token space lets a single mapping law cover text, nodes, marks, selection, history, collab, decorations, and view invalidation (`../wordgard/src/doc/index.ts:52-57`; `change.ts:302-435`). Plite repeatedly transforms path/point/range refs, bookmarks, implicit targets, dirty paths, and runtime impact for each operation (`packages/plite/src/core/apply.ts:58-71`, `:130-177`). | Introduce opaque root-aware `Position`/`Anchor` values backed by a token index. Keep `Path` as a snapshot query address, not live identity or mapping truth. |
| Structural path queries | **Plite superior** | Paths are excellent for tree queries, plugin targeting, fixtures, and JSON debugging. Raw offsets are worse for “the third list item” style work and require resolution. | Keep `Path`, `NodeEntry`, and structural query DX over snapshots. Resolve paths to anchors at the transaction boundary. |
| Runtime node identity | **Plite superior** | Plite has runtime IDs, path/id indexes, React bindings, and impact subscriptions without polluting JSON. Wordgard reuses tiles and object equality but has no explicit stable identity contract. | Preserve runtime-only stable IDs. Transfer identity through the change map across property edits and moves. |
| Adjacent text canonicalization | **Wordgard superior** | Wordgard joins adjacent equivalent text while constructing immutable plots; Plite repairs empty/adjacent text through normalization loops (`packages/plite/src/core/normalize-node.ts:74-199`). | Canonicalize leaf runs while applying a change. Do not spend normalizer passes on representation invariants. |
| Marks and arbitrary properties | **Plite superior** | Plite's JSON properties naturally model element attributes and text marks. Wordgard's typed marks are validated, but the same abstraction also carries data such as image alt text and alignment, coupling unrelated concepts. | Keep JSON properties and leaf marks; add typed schema property descriptors and validation instead of importing Wordgard mark semantics wholesale. |
| Registered node/mark membership | **Wordgard superior** | Wordgard rejects unknown types/marks and caches validation (`../wordgard/src/doc/schema.ts:43-74`). Plite schema registration currently describes behavior/property equality, not document membership or validity (`packages/plite/src/core/editor-schema.ts:183-233`). | Require a compiled schema assembled from extensions. Unknown node types and invalid property shapes are errors. |
| Parent/child grammar | **Wordgard superior** | Wordgard has groups, roles, allowed content, mark targets, default content, and wrapping queries (`../wordgard/src/doc/schema.ts:86-172`, `:199-267`). Plite mostly infers block/inline compatibility and relies on normalizers. | Add a typed content-query DSL and compiled containment tables. Avoid magic content-expression strings. |
| Defaults, wrapping, and fitting | **Wordgard superior** | `createAndFill`, `findWrapping`, `fit`, and whole-change correction make insert/paste structurally valid (`../wordgard/src/doc/schema.ts:133-178`; `change.ts:288-300`, `:500-544`). | Port the laws, not the classes: schema-guided default content, wrapping, slice fitting, and transaction-wide correction over JSON snapshots. |
| Construction/deserialization validation | **Wordgard superior** | Wordgard validates schema membership, params, mark targets, content, and non-empty blocks on construction/deserialization. Plite accepts broad JSON and repairs later. | Validate external values and provider payloads at boundaries; use trusted internal constructors inside transactions. |
| Normalization/correction scheduling | **Wordgard superior** | Wordgard scans changed `ChangeSet` regions and schedules query-specific corrections as transaction extenders (`../wordgard/src/state/correction.ts`). Plite derives dirty paths per operation and drains normalizers from the latest operation per root (`packages/plite/src/core/public-state.ts:5150-5198`). | Replace per-op dirty-path normalization with schema fitting plus changed-range correction queues. Rerun affected corrections to a fixed point with cycle diagnostics and a hard cap. |
| Multi-root documents | **Plite superior** | Plite has named roots in values, locations, operations, read/write views, selection policy, history, React, and browser proof (`packages/plite/src/interfaces/editor.ts:100-108`, `:317-319`, `:707-734`). Wordgard has one document root. | Define `DocumentChange` as an ordered root-to-`ChangeSet` map and keep root-scoped views. Cross-root selection remains invalid; one transaction may atomically change multiple roots. |
| Canonical document delta | **Wordgard superior** | Wordgard's sectioned `ChangeSet` is the actual edit: apply, serialize, map, compose, invert, transform, correct, and enumerate changed ranges all share one representation (`../wordgard/src/doc/change.ts:109-446`). Plite's operation list is mutated first and a very wide `EditorCommit` is inferred afterward (`packages/plite/src/interfaces/editor.ts:2145-2185`). | Make a root-aware `ChangeSet` the sole canonical document delta. Hard-cut operation-by-operation mutation as engine truth. |
| Composition, inversion, mapping | **Wordgard superior** | These are algebraic methods on one value with explicit laws (`change.ts:247-337`). Plite distributes equivalent logic across every operation, ref, selection, history, dirty-path, and runtime-impact implementation. | Port and fuzz the algebra for JSON token slices and property modifications before adopting it. |
| Concurrent transform/rebase | **Wordgard superior as an algebra; Plite superior as a product** | Wordgard has convergent two-way OT transform (`change.ts:234-249`, `:477-485`). Plite's production collaboration uses Yjs rather than owning a general local change transform. | Keep `ChangeSet.transform` for deterministic rebasing/testing/OT adapters; do not replace Yjs with Wordgard's central-authority protocol. |
| Serialized changes | **Wordgard superior** | `ChangeSet` and slices have validated JSON forms (`change.ts:204-231`). Plite serializes/replays operation arrays and state patches in separate systems. | Define versioned `DocumentChange` JSON for diagnostics, history persistence, replay, and non-Yjs transport. |
| Dirty-region derivation | **Wordgard superior** | Changed ranges fall directly out of sections (`change.ts:417-435`) and drive correction, decorations, and tiles. Plite's commit has dozens of eager impact arrays/classes/flags. | Replace the wide eager impact object with `commit.changes` plus a lazy `commit.impact` index derived once from changed ranges and stable IDs. |
| Semantic operation interoperability | **Plite superior** | Named operations such as `set_node`, `move_node`, and `replace_children` are useful for middleware, Yjs lowering, diagnostics, and existing callers (`packages/plite/src/interfaces/operation.ts`). Wordgard's delta is semantically compact but less descriptive to integrations. | Preserve normalized semantic intents as a **derived** commit view. They may optimize adapters but must replay to the same after-snapshot and never become a second truth. |

## State, transaction, extensions, and commands

| Surface | Rating | Why | Rewrite verdict |
| --- | --- | --- | --- |
| Native transaction model | **Wordgard superior** | A transaction owns one `ChangeSet`, selection, effects, annotations, and new immutable state; selection maps automatically (`../wordgard/src/state/transaction.ts:12-74`). Plite's public `editor.update(tx => …)` DX is good, but the engine snapshots mutable state and gathers operations before constructing a commit. | Keep Plite's `read`/`update` DX; replace its internals with a native immutable transaction and one atomic commit. |
| Atomic failure behavior | **Equivalent** | Wordgard never installs a failed persistent state. Plite explicitly inverts operations, restores roots/indexes/selection/marks/state, and rethrows (`packages/plite/src/core/public-state.ts:4934-5035`, `:5200-5215`). Both protect published state, but Plite pays much more machinery for mutation rollback. | Preserve atomic abort; implement it by discarding the draft rather than inverse-replaying live mutation. |
| Selection mapping inside edits | **Wordgard superior** | Unset selections map through the transaction's one change automatically (`transaction.ts:32-36`); effects can map the same way. Plite transforms selection/ref categories operation by operation. | Transaction selections and anchors map once through composed changes. |
| Metadata, effects, annotations | **Wordgard superior** | Typed annotations distinguish metadata from mapped state effects; time, user event, history, remote, and appended status are first-class (`transaction.ts:189-335`). Plite has tags, command context, state patches, update reasons, and policy spread across separate structures. | Add typed `Annotation` and mappable `Effect`; express history modes, origin, remote provenance, scroll requests, and reconfiguration with them. Keep ergonomic update options as sugar that creates annotations. |
| Persistent state fields | **Wordgard superior** | Fields own `create`, reducer-like `update`, compare, provide, and JSON hooks (`../wordgard/src/state/state.ts:319-417`). Plite fields mainly expose keyed values plus patch/diff/invert policy. | Redesign fields as transaction reducers with serialization and optional history/collab codecs. State patches become effects or derived history data. |
| Derived facets | **Wordgard superior** | Facets combine multiple providers, track dynamic dependencies, support precedence, and can derive extensions (`state.ts:423-548`, `:908-1026`). Plite has named state groups but no equivalent dependency-aware derived configuration. | Add typed named facets/selectors with automatic dependency tracking and stable memoized results. Do not expose anonymous `instanceof`-identified values. |
| Dynamic configuration | **Wordgard superior** | Precedence and compartments allow transactional reconfiguration (`state.ts:590-801`). Plite has setup/cleanup and extension registration but no equally coherent transactional compartment model. | Add named extension slots with transactional reconfiguration, setup/cleanup, dependencies, conflicts, and precedence. |
| Extension type/DX | **Plite superior** | Plite's named `api`, `state`, and `tx` groups compose into editor types and clearly split read/write capabilities (`packages/plite/src/interfaces/editor.ts:1672-1847`). Wordgard flattens heterogeneous extension arrays and can fail when duplicate module instances break `instanceof` (`state.ts:700-734`). | Keep Plite's named, structurally typed extension definition. Back it with Wordgard-like fields/facets/effects; never use class identity as extension identity. |
| Commands | **Wordgard superior in semantics; Plite superior in typing/dispatch** | Wordgard distinguishes pure state-to-transaction commands from imperative view commands and makes pure commands trivial to test (`../wordgard/src/command/command.ts:19-60`). Plite has typed command tags, priority, chaining, and transaction context (`packages/plite/src/core/command-registry.ts:33-148`). | Combine them: typed command definitions whose core/default handler returns `false | TransactionSpec`; imperative handlers live at DOM/Plate edges. Preserve priority and `next`. |
| Extension failure policy | **Equivalent but complementary** | Plite aborts core transactions and cleans setup failures. Wordgard catches/deactivates crashed view plugins and routes errors through a facet (`../wordgard/src/editor/editor.ts:1060-1129`). | Core/state/normalizer failures abort the transaction. View observers, decoration sources, and optional UI providers get isolated fault boundaries and an error sink. Never silently continue a corrupting core extension. |

## Selection, DOM, view, and React

| Surface | Rating | Why | Rewrite verdict |
| --- | --- | --- | --- |
| Selection extensibility | **Wordgard superior** | `GardSelection.define` supports custom serialized/mappable selection classes; tables add a real `CellSelection` (`../wordgard/src/state/selection.ts:18-135`; `../wordgard/src/table/cellselection.ts:100-224`). Plite's core selection is `Range | null`. | Replace the closed range type with a discriminated, registry-backed `Selection` protocol for text, node, cell, and custom/multi-range selections. Use structural types, not required subclasses. |
| Affinity, goal column, bidi | **Wordgard superior** | Selection owns head/anchor side, goal column, active marks, textblock maps, and bidi spans (`selection.ts:18-166`). Plite handles much of this later in DOM/React controllers rather than in the model contract. | Put logical affinity and vertical goal in text selection; keep physical geometry in `plite-dom`. |
| Live refs/bookmarks | **Plite superior in capability, Wordgard superior in mechanism** | Plite exposes path/point/range refs and bookmarks, but transforms all of them for every operation. Wordgard maps any position-aware value through one `ChangeSet`. | Hard-cut public path/point/range refs in favor of typed `Anchor<T>` values with association/deletion policy. Keep serializable bookmarks as anchor codecs. |
| HTML parsing/serialization | **Wordgard superior in capability, inferior in layering** | Shapes, parse rules, fitting, parser, and serializer form one declarative system (`../wordgard/src/doc/index.ts:25-66`). But DOM shape lives beside the core model and couples semantic schema to one presentation. | Add optional schema-linked codecs in `plite-dom`; keep the core DOM-free. A node may register multiple codecs (HTML, Markdown, clipboard), not one canonical DOM shape. |
| Clipboard | **Plite superior** | Plite separates internal JSON fragment transport, DOM clipboard parsing, input routing, projection, and fallback, with extensive browser proof. Wordgard has compact HTML/model clipboard integration but less platform/proof breadth. | Keep Plite ownership; feed fitted slices and mapped selections through the new schema/change law. |
| Rendering architecture | **Incomparable** | Wordgard's imperative custom view is compact and directly consumes changes. Plite's React runtime is much larger but is the required host for Plate composition. Replacing React with tiles would regress product fit; pretending the tile design has nothing to teach React would be equally dumb. | Keep React as reference renderer. Treat an imperative `plite-dom` projector as optional; steal the tile/change invalidation laws for React and non-React views. |
| Incremental view invalidation | **Wordgard superior** | `DocTile.update` consumes `ChangeSet.Sections`, reuses DOM/tiles/widgets, and rebuilds only affected spans (`../wordgard/src/editor/tile.ts:302-366`, `:790-1115`). Plite reconstructs many eager impact sets before React stores can decide what changed. | Make all render stores consume changed ranges/stable IDs from `DocumentChange`; delete duplicated operation-to-impact classifiers as adoption completes. |
| DOM read/write scheduling | **Wordgard superior** | State updates immediately, DOM flush is rAF-deferred, reads/writes have explicit phases, and flush loops are bounded (`../wordgard/src/editor/editor.ts:178-225`, `:354-367`). | Add a shared DOM scheduler in `plite-dom`: model commit, DOM read phase, React/DOM write phase, post-write selection phase, loop diagnostics. Integrate with React commits rather than mutating behind React. |
| DOM/model mapping | **Plite superior** | Wordgard tiles provide elegant position resolution, but Plite covers runtime IDs, shadow roots, hidden/materialized ranges, virtualized content, multiple roots, and projected DOM. | Keep Plite DOM contracts; implement them over anchors/token indexes so mapping no longer depends on path transforms. |
| Decorations, annotations, widgets | **Equivalent** | Wordgard has cohesive point/range sets, wrappers, widgets, mapping, and tile reuse. Plite has React-native projection, annotation, widget stores, runtime-ID subscriptions, and multi-root behavior. Each is stronger in its host model. | Unify Plite's stores behind one mapped `ViewLayer` protocol inspired by Wordgard range sets; keep React rendering and stable-ID subscriptions. |
| Input, IME, mobile | **Plite superior** | Both are model-owned and contain hard browser handling. Plite has dedicated input/composition/Android/repair kernels plus cross-browser scenario proof; Wordgard's implementation is compact but has one Chromium runner and multiple browser workarounds without a matrix. | Keep Plite's behavior and proof corpus. Simplify controllers only after the new commit law removes timing/impact work; do not port Wordgard input wholesale. |
| React integration | **Plite superior** | Wordgard has none. Plite targets React 19.2, external-store selectors, semantic node subscriptions, runtime IDs, providers, editable components, and compiler-aware rendering. | Keep package and public React APIs; make them consumers of immutable snapshots and `DocumentChange`, never engine owners. |
| Subscription model | **Plite superior** | Plite exposes snapshots, commit/source subscriptions, node/runtime-ID selectors, and `useSyncExternalStore`. Wordgard has update listeners and plugins but no comparable fine-grained React contract. | Preserve selector-first subscriptions. Replace eager commit flags with lazy change/identity queries. |
| Hidden/virtualized/projected DOM | **Plite superior** | Plite explicitly models DOM coverage, virtualized roots, hidden anchors, projections, selection materialization, and native affordance bridges. Wordgard assumes one materially present tile tree. | Preserve the entire coverage law and browser scenarios. The new position model must prove hidden/virtualized selection before migration. |
| Multi-root DOM editing | **Plite superior** | Plite owns root-scoped runtime views, DOM selection policy, navigation, history, and browser harness support. Wordgard has one editable content root. | Preserve root ownership and focus/navigation rules; change only the coordinate/delta substrate. |
| Pagination/layout | **Plite superior** | `plite-layout` separates derived geometry, page projections, mount plans, virtualization, and React rendering (`packages/plite-layout/README.md:1-32`). Wordgard has orientation metadata and one continuous tile view, not a page-layout subsystem. | Keep layout out of core truth. Rebase projections and mount invalidation on changed ranges/anchors. |

## History, collaboration, packaging, and proof

| Surface | Rating | Why | Rewrite verdict |
| --- | --- | --- | --- |
| History architecture | **Wordgard superior** | History stores inverse `ChangeSet`s/effects, maps through excluded transactions, composes adjacent changes, and serializes in about 380 lines (`../wordgard/src/history/history.ts:57-94`, `:172-352`). Plite manually owns operation inversion/replay/root filtering/state patches across 1,609 production lines. | Store inverse root-aware changes, starting selection, and inverted mapped effects. Preserve Plite grouping/root/state policies as annotations/effects. |
| Collaboration product | **Plite superior** | Wordgard's 182-line collab module is a basic central-authority OT client with versions and unconfirmed changes (`../wordgard/src/collab/collab.ts:90-171`). Plite/Yjs covers provider lifecycle, offline CRDT behavior, awareness, relative selections, split history, and undo-manager adapters. | Keep Yjs. Lower canonical changes to Yjs deltas and map Yjs changes back to `DocumentChange`; retain provider/awareness/history behavior. Add OT only as an optional adapter. |
| Tables | **Wordgard superior in bundled capability, inferior in boundary** | Wordgard includes table map, collision correction, cell selection, rectangular paste, commands, and menu. Plite core intentionally has no table product model; Plate owns it. | Pull custom-selection and correction primitives into Plite; keep table schema, commands, paste, and UI in Plate. |
| Built-in rich-text schema | **Incomparable** | Wordgard ships paragraphs, headings, lists, links, images, colors, tables, and dialogs in the same package. Plite is a substrate below Plate plugins. More bundled behavior is not a better substrate. | Use Wordgard types as schema/correction acceptance tests. Do not add product nodes to Plite. |
| Panels, menus, dialogs, tooltips, phrases | **Incomparable** | Wordgard bundles a complete imperative editor UI and i18n. Plate already owns React UI/plugin composition. Moving these into Plite would invert the package boundary. | No Plite adoption. Potential Plate inspiration is a separate product-layer plan. |
| Fixture construction | **Plite superior** | `plite-hyperscript` creates normal JSON/editor/selection fixtures and has a broad imported fixture corpus. Wordgard uses bespoke test generators and constructors. | Keep hyperscript, teach it new selection kinds/anchors/schema values, and remove operation-era fixture assumptions. |
| Package boundaries | **Plite superior** | Plite separates core, DOM, React, history, layout, browser proof, hyperscript, and Yjs. Wordgard exposes subpaths but ships model, view, tables, product schema, menus, dialogs, and phrases as one package. | Preserve Plite packages and dependency direction. Add no `table`, menu, schema bundle, or React concern to core. |
| Dependency footprint | **Plite superior at the substrate boundary** | `@platejs/plite`, history, and hyperscript have no runtime dependencies; DOM/React/layout add host-specific deps. Wordgard has three runtime dependencies in its single package (`../wordgard/package.json:31-35`). | Keep zero-dependency core and host-specific dependencies outside it. |
| Core behavior tests | **Plite superior in breadth; Wordgard superior in algebraic focus** | Wordgard has 26 tests/5,708 lines with concentrated change/facet/history/collab laws. Plite's scoped package/app trees contain far more behavior fixtures and regressions. | Keep the Plite corpus and add Wordgard-style property/fuzz laws for apply/compose/invert/transform/map/correct. |
| Browser proof | **Plite superior** | Wordgard's headless runner finds one Chromium binary and dumps DOM after a 15-second budget (`../wordgard/bin/test-headless.ts:11-35`). Plite has Chromium, Firefox, mobile viewport, and Darwin WebKit projects with traces/screenshots/retries (`apps/plite/playwright.config.ts:21-74`). | Preserve `check:plite` and the closure browser matrix. Add dual-engine behavior rows before hard cut. |
| Benchmarks | **Plite superior; runtime performance otherwise incomparable** | Wordgard has no benchmark suite. Plite has core, normalization, history, selection, React, huge-document, layout, clipboard, and Yjs runners. Code size cannot prove runtime speed. | Build a fair Wordgard-inspired prototype benchmark before choosing the final token/index representation. Block architecture adoption on correctness first and non-regression thresholds second. |
| Documentation/architecture contract | **Plite superior** | Wordgard has concise generated module docs and a minimal README. Plite has a detailed architecture/proof/migration corpus, including an explicit admission that the retrofit engine is not the from-zero choice (`docs/plite/references/architecture-contract.md:109-150`). | Replace operation-truth doctrine only in the accepted implementation slice, with rationale and new invariants. Keep docs source-first and current-state only. |
| Semantic density/maintainability | **Wordgard superior in the core; performance incomparable** | Wordgard's 22,611 production lines include core, view, history, collab, tables, schema, and UI. The Plite family has 115,140 production lines, including 35,942 core and 46,897 React. The crucial cause is visible duplication: one change is reinterpreted for refs, dirty paths, commits, stores, history, DOM, and Yjs. | Use deletion as a gate: every adopted change/anchor law must retire an old transformer/impact path. Do not layer the algebra beside current machinery. |
| Non-React portability | **Plite superior in layering; Wordgard superior in ready-made view** | Plite core is dependency-free and DOM/React are separate, but it lacks a first-party imperative renderer. Wordgard's browser view works without React but lives in the same package family as product UI. | Keep the layered core. Consider an optional thin `plite-dom/view` projector only after React/Yjs parity; it must consume the same snapshots/changes. |

## Net result

Wordgard wins the parts that determine whether an editor engine is coherent:
schema law, one canonical change algebra, native immutable transactions,
selection extensibility, fields/facets/effects, changed-range correction,
history, and direct view invalidation.

Plite wins the parts that determine whether that engine can carry Plate:
plain JSON, stable runtime identity, typed `read`/`update` extension DX,
multi-root behavior, React, hidden/virtualized DOM, layout, Yjs, package
boundaries, browser proof, benchmarks, and the existing behavior corpus.

The rewrite should therefore **not** turn Plite into Wordgard. It should replace
Plite's mutable path-operation engine with a Wordgard-inspired immutable
change engine, then keep Plite's stronger host/runtime ecosystem around it.
