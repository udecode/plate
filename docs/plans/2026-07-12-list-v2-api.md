Decision brief:
| Field | Decision |
|-------|----------|
| Principles | Plite owns editor substrate; Plate owns List product behavior; runtime and types tell the same truth; one feature portal, one transaction, no compatibility layer; explicit app configuration overrides implicit defaults deterministically |
| Drivers | Current free List commands conflict with Plite update/tx, List depends on Indent without a typed graph, public barrels leak internals, docs/registry teach false APIs, one normalization invariant fails, and three tests assert Slate rather than Plite merge identity |
| Viable option A | Keep free commands and string dependencies, add wrappers/casts, and require apps to install Indent explicitly |
| Viable option B | Move List behavior into Plite or duplicate Indent mechanics inside List |
| Chosen option | Keep List policy in Plate; hard-cut free editor-bound reads/writes; add a typed automatic Core dependency graph; expose scoped List reads/updates over one active Plite tx; retain legitimate domain queries; internalize/delete mutation mechanics; migrate docs/registry/release contract in one packet |
| Rejected alternatives | A preserves duplicate APIs, unsound composition, and redundant setup; B pollutes Plite or forks Indent; aliases, shims, private bridges, force normalization, wildcard barrels, and array-order dependency precedence are also rejected |
| Consequences | Core and List receive major changesets; AI migrates one declaration; List-only setup becomes valid; configured Indent remains authoritative; toggle location starts working; no Yjs/Plite runtime change; execution must close the graph/type/history/replay/export/docs/Browser gates before release |
