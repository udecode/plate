# Undo finds what each node was

Status: executed
Playbook: plan

## Brief

### What will change?

Undoing an Editing edit that also pressed Enter at a block's start no longer brings back a rejected value, because undo follows each piece of text back through joins and merges. It landed on next with the Editing format work.

### What could go wrong?

Undo still brings back a wrong value in a few cases, such as the text of a block the edit wrapped. Some splits still lose a peer's typing, as on next. The Close says where the proof stops.

## Teach

When Carol undoes an Editing edit, the undo puts back what history saved, and her tag comes off. A value under it that Alice rejected meanwhile could then come back untagged. So after an undo, the editor sets each property the undo changed to what rejecting Carol's tag gives now.

It must know which node each one was before the undo. Before this change the repair paired nodes in order, and paired none when the counts differed. Enter at a block's start in the same commit makes two blocks where the undo has one, so the rejected red stayed.

Now the repair matches each node through what the undo kept of it: text through its kept characters, a block through its kept opening. Text joined from pieces that undo differently splits where they meet, and characters with nothing kept keep what the undo put back. Separately, a split that also formatted its right half lost that format on other clients.

## Main changes

- `findSplitText` in `yjs/core/canonical-split.ts` still finds a split as 3df0bada7a does. One leaf's text must be the left half's last leaf plus the right half's first, and everything else must be unchanged. When the right half's first text has other properties than the original leaf, it records the right half's text group as `rightLeaves`. `applyCanonicalSplitToYjs` then writes them onto the runs it moved, in place, with `rewriteTextRuns`, new in `text-runs.ts`, and an encoder made with `createYjsRunEncoder` for the new block. `rewriteTextRuns` compares the new leaves with the attributes the moved runs store, not with an encoding of the old leaves. So a set-valued property that the new block reads as plain loses its member keys. Before it compares, it merges stored runs with equal attributes across the moved Yjs texts, so a run spread over many Yjs texts finds its place in the chain once. It passes the stored attributes to `writeTextRuns` as the encoder for the old runs. `writeTextRuns` walks the chain forward while it formats a run, instead of finding each Yjs text from the start, so recoloring 2,000 one-letter texts reads the chain 4,001 times instead of 2,003,000. It also finds leaves with forward cursors instead of scanning from the first leaf for each run, so a split that colors the first of 2,000 alternating moved leaves makes 19,996 leaf lookups instead of 8,008,000. When the right half starts with no Yjs text, as before an inline element, the split inserts a text chain for the empty leaf, which carries its properties. Before, a commit that split a block and set a property on the right half moved the old Yjs runs into the new block without it, so the other client never got the property. This happens on next with no authored plugin, at offsets 0 and 2. `CanonicalSplit.textProperties` and `rightText`, which nothing reads, go.
- `keptRunsOf(change, from, to)` in `core/change/root-change.ts`, beside `mapRootChangePositionBackward`, returns the input token runs a change keeps for output tokens `from` to `to`, in order. It walks only the sections that reach the range, through the private `sectionEndsOf` and `firstSectionEnding`.
- `applyIndexed` in `root-change.ts` merges a pure insertion with the replacement that starts where it ends into one replacement. A split repair puts back a leaf edge the replay removed, so the commit's change holds that pair, `[1181,-1, 0,2, 2,0, 5,-1]` at 100 blocks. Before, the localized apply refused it as an ambiguous replacement position and rebuilt every token of the root, and history's redo record then indexed the whole root. The property-only fast path now also needs the inserted opening to be the same kind of node as the one it replaces. Without that check, the merged pair turned a text's opening into a link's and kept its letters, which the token reference refuses. `compose` is unchanged.
- Admission's historic block builds one sparse repair change per root. Each node in the replay's changed ranges takes its sources from the before-nodes its kept tokens came from. A text leaf has one source per run of kept characters, and an element or an empty text has its kept opening. Each source gives `repairKeys(before, after, reading)`, which `settle.ts` now exports. When the sources agree and cover every token that decides the node, the repair is one property section at the node's opening. Otherwise the repair replaces the leaf with leaves split at the run edges. Characters no run kept keep the replayed properties, and equal neighbours merge. A node with no kept token, and a leaf with text but no kept character, get no repair. The before index comes from `rootOf` instead of `valueRootIndex`.
- `pairsInPlace` and `keptIn` in `admission.ts`, and `repairReplayedFormats`, `nodeAt`, `replaceAt` and the repair's root copy in `settle.ts` go. They paired nodes by order within a range, which kept rejected values on split, joined and merged text. The kept runs replace them, and the review's R1 to R14 tests keep passing.
- Admission's second pass reads the first pass's change, which only writes values and takes no tag off, so `repairKeys` finds no tag that left and the loop ends.

### Performance

- applicability: applied. The repair's work per undo changes, a root copy goes, and the core's localized apply changes for one change shape.
- questions answered: cohorts, repeated unit and deterministic work. Interaction latency is N/A, because undo runs once per gesture and no typing path changes. Memory and DOM do not change. Native behavior is the table above.
- repeated unit: a node in an undo's changed ranges, and a kept run per text leaf.
- scale variables: document size, 100 and 2,000 blocks, and the feature's state, one kept run per leaf (R1), two before-nodes into one (B2) and two kept runs in one leaf (the joined leaf).
- cohorts: normal at 100 blocks and large at 2,000, each with the R1, B2 and joined-leaf undos. Stress and pathological are N/A.
