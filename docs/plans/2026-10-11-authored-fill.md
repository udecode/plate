# Authored: one fill for an emptied element

Status: executed: closed 2026-10-12 with T6 and T7 partial; the parent plan's Phase 2 cutover is next
Playbook: plan

**Pursue.** Today accepting a suggestion can fail outright on content the schema allows. A required header with no room for text, an inline default with a bounded maximum, and a row whose property default depends on its parent each make the decision return `invalid` on the current tree, and suggesting the deletion of a required title throws. Three code paths fill an emptied element by three rules, and none matches normal editing in every case. Normal editing is not consistent either. It decides how to complete an element by reading whichever child survives, so deleting a text's characters and removing the text node leave different results, and it commits inline defaults without their spacer texts. The design bakeoff's three runners converged on one answer, and this plan takes it. Plite core gets one completion that decides an element's empty form from its schema and its site alone, and an empty line carries no formatting. Normal editing, element construction, document loading and the review tree all call it. Editing completes after each transaction, so what it builds depends on the order of changes. The review tree therefore completes each suggestion as it is recorded, against the document Editing would hold with every pending change applied, and keeps what that builds. Where Editing builds an element of the same type in the place a deleted element left, the suggestion keeps the deleted element with its content struck. Accepting every suggestion then gives what Editing gives step by step, and every decision order ends the same way. One case stays narrower. The decision, not the suggestion, builds an element Editing appends at another place inside content with a maximum. This iteration continues `docs/plans/2026-10-08-authored-review.md`, whose Phase 2 cutover waits on it, and takes the redesign iteration's Open work item "The fill" (`docs/plans/2026-10-11-authored-redesign.md`).

## Brief

### What will change?

Built and tested in Chrome. Accepting every suggestion now ends where normal editing would, except in two rare cases. Accepting no longer fails on valid schemas. The suggestions docs page stays on the old system until the switch-over.

### What could go wrong?

Two rare bugs stay open, each with a written fix. The final review caught a bug that lost typed text, and I removed its cause. An empty line forgets bold once you leave it. Review warnings are in the Close.

## Teach

When a suggestion or a decision empties something, like a paragraph whose only text got deleted, it should end up as normal editing leaves it. But normal editing isn't consistent today. Deleting the letters leaves an empty line, while removing the text node can leave nothing. So the suggestion code guesses, and some guesses fail.

The fix makes normal editing follow the schema alone. An emptied element that can hold text keeps one plain empty line, and the bold you were typing stays with the cursor.

Normal editing fills after every change, so the order of changes matters. Delete one of two required cells, then dissolve their group, and the filler cell stays; dissolve first, and there's none. Each suggestion records what normal editing would add at that moment, so accepting everything gives the same result. Suggesting to delete a required title keeps the title and crosses out its text, because normal editing would leave a fresh empty title there.

## Public API

No call shape changes. Three public calls give different nodes. Two do so for content that allows text but requires none, and the loader does for any stored shape that is not canonical. The schema fit report gains one repair code.

`schema.create` builds an element in its canonical empty form, at the site its caller names.

```ts before
// content/docs/(guides)/schema.mdx

```

```ts after
// content/docs/(guides)/schema.mdx

// { type: 'cell', children: [{ text: '' }] }
```

## Hard cuts and app migration

These cuts follow from the Pursue on a review the owner asked for, so each is a `look` Defaults row rather than an open question.

- An element whose content admits text stops holding no children. Completion gives it one empty text, and the loader gives a stored `[]` one when the editor is created. Plate's text blocks require a text (`schema.element.textBlock()`, `core/schema-definition.ts:1215-1263`), so they never held `[]`. The spike of this one rule changed one test across every plitejs and platejs partition (`authored-tree-decisions.test.ts:447`). The plan's other core changes are unmeasured on platejs until C8. An external change that leaves `[]` in a part it touches is refused with the typed refusal.
- A line anchor or inline spacer stops storing formatting. Editing that empties a bold text leaves a plain empty text and puts `bold` into the selection's pending marks while the caret is in it, so typing there stays bold, as it does today. Once the caret leaves, or the document reloads, the empty line is plain. A stored empty bold line loads plain. A void's empty child keeps its properties, because a markable void such as Plate's mention stores its formatting there (`packages/platejs/src/features/mention/lib/BaseMentionPlugin.ts:42`, `packages/plitejs/src/editor/add-mark.ts:81-90`). A mark toggle on a collapsed caret already sets pending marks rather than an empty text (`packages/plitejs/src/editor/add-mark.ts:103-125`); C8 counts every test that pins a formatted empty text.
- The loader canonicalizes every initial value, as the Yjs bridge already does for each root it initializes (`packages/plitejs/src/yjs/core/plugin.ts:159-182`). Probe 9's stored shapes, adjacent texts with equal properties and an inline element without spacer texts, load merged and spaced. C8 counts every test that loads a stored shape that is not canonical.
- Mixed content whose default is an element no longer builds that element when the emptied element's empty text meets the minimum, whichever gesture emptied it; the default is built only past the empty text. No production schema mixes text with an element default (`answer-editing.md` lookup 4).
- A content declaration whose minimum has no canonical realization within its maximum, such as `schema.content.text({ min: 2 })` or an inline default at `min: 2, max: 2`, stops compiling. No production schema declares one; C6 counts the test schemas it refuses.
- The review tree's hoist of a container left below its minimum goes. The container keeps its live children, and completion adds what it lacks, as Editing does. Plate's column group, which requires two columns, is the production case. Suggesting the deletion of the second of two columns now keeps that column with its content struck, as Editing leaves an empty column there, and accepting it keeps the group; the decision's own update runs Plate's width corrections as it does today. `authored-tree-resolve.test.ts` lines 188, 213, 312 and 443 assert the hoist. This replaces a rule of the parent plan's Main changes.
- Prefix displacement leaves canonical form. Editing's own deletion of a required title still builds a fresh title and keeps the next heading where it was. Undo, remote changes and the external check apply whatever document they carry when it is canonical. No caller relies on undo throwing. A decision never moves a node the start did not hold into a prefix slot it empties, so no decision promotes the next heading into the title. No Plate package declares a prefix; the Plite forced-layout example does (`apps/www/src/app/(app)/examples/plite/_examples/forced-layout.tsx:24-27`).
- A suggested deletion that Editing answers with an element of the same type at the same place shows that element with its content struck, not a struck element. Examples are a required title, the last cell a group's minimum keeps, and the only paragraph. The reviewer types the replacement into it, where Editing's caret lands in the fresh element.
- The parent plan's law that accepting everything gives what Editing gives, step by step, holds with two named exceptions, R1 and J1. Under R1, an element Editing appends at another place inside content with a maximum, such as a cell in `type('cell', { min: 2, max: 2 })` after its first cell is deleted, cannot sit in the review tree beside the struck cell. The decision builds it instead, so a later change in the same history that made it unnecessary falls back to completing once. T6 counts R1's cases and requires none outside content with a maximum. Under J1, neither the recorder nor the decision reads a pending join into a text block whose content needs more than one child or a prefix. Each completes the text block without the joined content, and a block with a pending join completes as its own host. The recorder can also take an emptied inline element of the text block for the join's target and drop it from the children it completes. Accepting everything can then hold a fill Editing would not build, and accepting the deletion before the join can differ from accepting both. No Plate package declares such content; the only production minimum above one is the column group's, which holds no text (a search of `packages/*/src` for content minimums above one, 2026-10-12).
- A partial decision set that Editing refuses keeps the review tree's own canonical result. Accepting a paragraph inserted before a required title while rejecting the heading inserted above it gives a fresh title before the paragraph, where Editing refuses the paragraph's insertion alone (T0, case 6a). T6 counts each such set.
- The recorder's `defaultChildOf` and `filledElement`, the resolver's two-branch fill and hoist, and its use of `canonicalizeElementChildren` go; they are internal.

## Main changes

- New `core/content-completion.ts` owns completion as one pure function of an element's children, its compiled content program, its site (root and ancestors, nearest first) and the prefix slots its caller says were vacated. It classifies content from the program and canonicalizes each inline run between blocks on its own, instead of reading the first surviving child (`hasInlineContent`, `core/representation.ts:153-167`). After the prefix, an empty stretch that admits a text holds one empty text, the anchor; the anchor counts toward the minimum, so an element default is built only past it. Completion adds defaults one canonical unit at a time until the minimum holds. An inline default therefore arrives with its spacer texts, and an empty text that a block makes redundant does not count. Running completion twice changes nothing. It returns the completed children and each element it built, with its index and the prefix slot it fills, so the recorder can keep what Editing builds.
- `replaceCanonicalChildWindow`, `canonicalizeDirectChildren` and `createDeclarativeAndFill` call that completion; `completeRequiredContent`'s raw count and the first-child classification go.
- Prefix displacement becomes the vacated-slot input. Editing's local transaction pass derives it as `wasDisplaced` does today, by node identity against the transaction's own before (`representation.ts:1069-1080`), so replacing a whole value still keeps the new first heading. The external canonical check, which undo, remote changes and decisions go through, passes none, so it reads the document alone.
- A line anchor or inline spacer keeps only the properties completion builds for a text at its site and the review tree's `authored` marks. When Editing's pass drops any other property from an emptied text and the selection the transaction ends with is a collapsed caret in it, the pass moves those properties into the selection's pending marks, which typing already applies (`editor/insert-text.ts:88-120`). A void's empty child is neither, so it keeps its properties. Decisions, loading and the external check leave the same plain empty line, so the parity and rejection laws compare documents exactly.
- `createEditor` canonicalizes every root of its initial value through the same pass before the first snapshot, as the Yjs bridge does for each root it initializes (`yjs/core/plugin.ts:159-182`).
- The schema compiler refuses content whose minimum has no canonical realization within its maximum.
- `assertCanonical` raises a typed refusal, a subclass of `EditorSchemaValidationError`, which `decide` already maps to `invalid`.
- New `authored/tree/proposed.ts` reads proposed children, the children Editing would hold with every pending change applied, one element at a time. `proposedHost` walks up from a review element through pending unwraps to the element its children belong to once every pending change is accepted, and returns null for a struck element with no live content, which Editing has already removed. `proposedChildren` yields that host's proposed children left to right. It lifts pending unwraps, drops struck nodes with no live content and folds pending joins inside the host, and stops once the minimum and the prefix candidates are known. Past the host's end it reads only up to the first block that stays: a pending join on that block removes the host's empty last text block, as the resolver's join does, unless an element that stays and does not unwrap encloses the joining block. A law test holds it equal to the full projection's children of the same element.
- New `authored/tree/record-completion.ts` runs after `recordAuthoredSteps`. A transaction that removes no proposed child, such as typing, Enter or a mark, does no work there. For each host whose proposed children the change removed, it reads the proposed children after the change, takes as vacated each prefix slot whose occupant before the change the change removed, and runs the core completion. For each element completion builds, a removed element of the same type stays in place only when keeping it there, emptied, gives exactly the children Editing's completion gives; T0 showed an index rule keeps `[a, xi, b]` where Editing leaves `['ab', xi, '']`. The change drops its own delete mark on that element, strikes its live content, and records format tags where its declared properties differ from the built element. Any other built element is inserted with the change's insert mark and the insert marks of the host's ancestors, so rejecting a pending insertion of the host also removes it. When the removed element was the author's own pending insertion, which the change withdraws rather than strikes, nothing stays in place, and the built element is inserted. An element the review tree cannot hold beside the struck content, R1, is deferred, and the decision builds it. A fill carries an insertion of each other pending change it rests on. A fill outside the prefix rests on every other change that deletes one of the host's children. A prefix fill rests on none. A check once bounded which deletions it rests on, but it lost a replacement title and its typed text, so the lead reverted it after the decision-trail review. Rejecting another change's deletion of the slot's old occupant therefore keeps both elements and all their text, as Editing does. The recorder slot's canonical pass then runs on the raw review tree and must build nothing, which a law asserts.
- `resolveAuthoredChildren` resolves structure first. A second pass walks the resolved tree top-down with each node's final ancestors. Every element whose children or properties a decision changed goes through the core canonical form there, as `canonical()` does today (`resolve.ts:124-133`), and completion builds whatever that form lacks. A prefix slot counts as vacated when its resolved candidate is neither the slot's start occupant nor an inserted or built node, so a heading after a deleted title never becomes the title, which Editing never does either. The pass records the origin of each element it rebuilds with completed children, so `resolvedOf` and fragment reads follow it. They do not follow a node the canonical pass rewrites, such as a row given its new site's default, so a fragment read reports that node as deleted; `projectAuthoredFragment` has no caller outside tests. The hoist and the two-branch fill go. With the recorder keeping Editing's fills, this pass builds only for partial decision sets, such as accepting a title's deletion while rejecting a heading inserted above it.
- A decision that makes the resolver build waits on every pending change whose outcome changes what it builds. These are the element's own pending structural changes and deletion; its children's pending `join`, `split`, `wrap`, `unwrap` and type changes; its ancestors' structural changes, since a built element's properties can read any ancestor; and, for a prefix slot, the pending insertions between the slot and its start occupant, each tested against both outcomes. Pending insertions and deletions of its children do not block an append, so probe 8's orders apply. Accepting everything never waits, because the recorder already holds every fill it needs.
- The recorder's filler for a struck element whose own inserted children are all withdrawn calls the core completion at the element's site and carries the element's marks, as today; `defaultChildOf` and `filledElement` go.

## Failures, blast radius and rollback

Six realistic failures:

1. The program-based classification changes a shape some caller relied on, such as content that mixes text and blocks. C2's law runs every gesture on generated shapes, and C8 runs every plitejs and platejs partition against the frozen base and lists each changed test with its reason.
2. A waiting rule misses a pending change that alters a completion, and decisions stop commuting, or it waits on one that cannot, and schedules block for nothing. T6's commutation law runs the shapes and schedules panel rounds 1 to 3 named, states each mandatory schedule's exact statuses, and fails a mutant that drops each wait.
3. Per-keystroke cost grows. The prototype passed the frozen rule twice on a quiet host. Its pre2 typing p95 rise did not repeat in pre3, where it matched the base at 0.25, 2.17 and 9.55 ms against 0.24, 2.16 and 11.3 ms, and a planted slowdown of three transactions per keystroke failed every typing line. Its 20,000-block typing p95 still reached 20 to 30 ms in three of six packets, against at most 15.3 ms on the base; that tail is not significant and unexplained, and C9 profiles it on the real code.
4. An empty line loses its bold once the caret leaves it, and a stored formatted empty line loads plain; a void's empty child keeps its formatting. Typing straight after deleting keeps bold through pending marks (C10); C8 counts the tests that pinned a formatted empty text.
5. A peer on an older build writes `[]` or a formatted empty line into Yjs. The full-root import fits each remote root through the canonical pass (`yjs/core/controller.ts:1170-1200`), but the event import applies a translated change directly and skips node fitting when the schema declares content roots (`controller.ts:366`, `936`, `1457`), so the external check would refuse it. C5 makes the event import fit on both routes; this build then shows the plain anchor where the older peer shows its own shape.
6. The recorder's completion keeps a shell or inserts an element where Editing builds something else, or its proposed children drift from the projection. T6 runs the step-by-step oracle over generated shapes, mixed content included, and the proposed-children law; T7 counts the recorder's reads; and Phase 2 reverts as one unit.
