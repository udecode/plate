# Second audit of Plate agent workflows

Task owns execution. Technical Writing owns prose. Auto selects and supervises
the relevant domain methods. Docs Creator, Auto's 1,111-line quality controller,
and Task's duplicate engineering controller are removed. Their necessary
domain recipes remain with the owners that actually use them.

Plate Plan and Plite Plan remain separate. Their recent sessions demonstrate
different planning jobs. `next` remains the deliberately breaking v2 beta
redesign; stable-release readiness is conditional on an actual release task.

Objective:
Repair instruction ownership and loading against full useful pstack methods,
official Astra guidance, current source and actual user history.

Completion threshold:
All installed skill entries receive an ownership assessment. Changed local
sources and templates regenerate exactly. Representative documentation and
file-plan trials pass, affected helpers pass, and evidence limits are explicit.

Verification surface:
`.agents/AGENTS.md`, `.agents/rules`, both installed skill mirrors,
`docs/plans/templates`, and this audit's artifacts.

Constraints:
Use the current checkout. Preserve protected skills, all Next dev loop copies,
domain laws, negative type proofs, immutable doctrine and package attestations.
No native goal, product repair, shared-source edit or publication is authorized.

Boundaries:
This is a workflow source audit with selected executable trials. It is not a
full app verification run, independent model evaluation or release certification.

Blocked condition:
An unresolved local ownership contradiction or failing affected helper prevents
closeout. Inaccessible external sources and unexecuted product surfaces must be
identified without pretending they were verified.

## Alternatives and decision

Scores are a comparative judgment, not measured model performance. Each column
uses 0 = fails, 1 = partial, 2 = satisfies the stated criterion. A fatal loss of
domain or authority law rejects a design regardless of its other scores.

| Candidate | Clear owner | Preserves needed method | Loads by actual need | Fits runtime and authority | Keeps required proof | Decision |
| --- | --- | --- | --- | --- | --- | --- |
| Keep controllers, shorten their prose | 0 | 2 | 0 | 1 | 2 | Reject: competing writing and lifecycle owners remain. |
| Move all controllers into references | 1 | 2 | 0 | 1 | 2 | Reject: mandatory references preserve the same loading cost and conflicts. |
| Delete specialists and use generic pstack alone | 2 | 0 | 2 | 1 | 0 | Reject: loses public API, native input, adoption and receipt laws. |
| One Task lifecycle, conditional domain methods, shared prose owner | 2 | 2 | 2 | 2 | 2 | Implement: removes the competing controllers while retaining concrete jobs. |

The decisive evidence is structural. Docs Creator independently prescribed
voice, anti-slop editing and a writing lifecycle already owned by Technical
Writing. Auto required its full quality loop for broad work, even when the
actual question belonged to one existing domain owner. Task engineering added
another branch, browser and review sequence, including another project's PR
conventions. Shortening those paragraphs would preserve the wrong owners.

The selected architecture has executable evidence below. It does not earn a
97/100 or claim superior model behavior from a self-assigned rubric.

Actual session messages, not generated plan boilerplate, establish these jobs:

- **Yjs public entrypoints, August 23.** The user asked which findings deserved
  Plite Plan. The answer selected the substrate/public-boundary decision and
  excluded unrelated docs and release gates. The user then requested planning
  and later said `go`. The plan connected dependency-honest exports to adopter,
  packed Node, NodeNext/Bundler and affected browser proof.
- **Registry delivery, August 24.** The user explicitly invoked
  `plate-plan --standard`, inspected before/after snippet shapes and then said
  `ok go`. This decided authored registry composition versus app-owned generated
  contracts. It was a Plate delivery job, not an editor-kernel design job.
- **External text and render hooks, September 3.** The user said that cutting
  hooks needs a replacement, then requested a single way to carry architecture
  cleanup. The resulting plan has three implementation phases, editor history
  and selection laws, a view protocol, and a frozen 30-cell benchmark receipt.
  Auto can supervise that accepted work without asking the user to reinvoke
  every technical owner.

`01a066be-d905-7e63-95f3-b80aa9b303af`, archived in the September 3 local session

## Forward trials and corrections

The serial trials used the real installed helpers and local source. They were
informed authoring trials, not blind model experiments.

| Trial | Actual outcome and limit |
| --- | --- |
| Small documentation | Rewrote `docs/development/agent-skills.md`; its four local links resolve. Includes complete Auto argument navigation and release-command mappings. |
| Richer MDX/API authoring | Wrote a local DndRoot lifecycle how-to from current source and its existing feature page. MDX compiles, one TSX fence parses, and an unclosed MDX component is rejected. |
| Ordinary and Auto file plans with docs | First attempts exposed an invalid gate table and a docs pack whose section names the helper ignored. Corrected the templates and reran. |
| Ten domain templates with `--with docs` | Each materializes the actual docs pack and exactly one accurate metadata section. Removed stale prefilled metadata from the templates. |
| Completion boundaries | Three intentionally unfinished plans return incomplete. The completed draft-only authoring plan returns complete. No native goal was created. |
| Release sync dry run | The actual helper exits successfully and prints simulated commands. It does not fetch, switch, commit or push in this mode; its simulated commit count is not a live remote-readiness finding. |

MDX/TSX parsing does not prove TypeScript inference, rendered docs, dragging or
native input. The draft was not inserted into the public app. No product claim
uses these authoring results as runtime proof.

The template trials found a shared-helper issue: `insertCompositionMetadata`
returns early when prefilled metadata exists, even if a selected pack changes
the actual composition. The ten local templates now let the helper write the
metadata. The shared repair proposal is recorded separately; protected helper
source remains unchanged.

Editor Test Harvester's `>= 0.92` weighted score and per-dimension cutoffs were
also removed. Its concrete evidence requirements remain: exact inventory and
test names, full relevant reads, owner searches, provenance/license, negative
controls, placement, downstream proof or explicit deferment, and no uncertain
rows. This removes arbitrary scoring without weakening the acceptance facts.

## Agent Native Reviewer and decision trail

Applied the full method locally: checked discovery, source ownership, actual
helper availability, inputs/outputs, stop authority, evidence survival and
native/runtime limits. Fixed issue-posting authority, Slate AR discovery,
release shortcut reachability, docs composition and repeated review gates.

There was no independent model-family or blind review. Repo mapping required
sequential execution, and Task prohibits Autoreview on `next`. Those limits do
not prevent inspecting and fixing concrete defects.

The current session transcript was checked against the receipts. Its initial
decision-log row was timely; later decisions were reconstructed at closeout
and explicitly marked retrospective. The trail is useful but was not maintained
at every checkpoint. Source reads, failed trials and corrective reruns remain
in the transcript and artifact directory. No latency claim is justified.

sync targets. No Dotai edits or multi-repo propagation were performed here.
