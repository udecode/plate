# Plite core architecture review

Objective:
Audit `plite-core` as one architecture, covering runtime, state, extension
composition (`schema`) and commands. Record a source-backed value verdict for
each question and recommend one next owner overall.

Completion threshold:
Four expected questions, four recorded verdicts, no silently omitted consumer
class. Compare current composition, owner/API changes, new primitives,
delete/merge/inline and replacement. Name the strongest justified cut, retained
jobs, regression risks and exact proof limits. Persist immutable records and
the current decision; regenerate and check the ledger.

Verification surface:
Declared ledger owners/consumers/proof, relevant public types and current
examples. Run focused package contracts or bounded probes when they resolve a
material question. No browser behavior or performance claim without that proof.

Constraints:
Assessment only. No product edits, downstream implementation plan, publication
or feature-wide expansion beyond these four questions. Preserve the separate
Plite view and Plate core review jobs and all immutable history. The user
requires a substantial group audit; one local defect does not close it.

Boundaries:
Review artifacts, source manifests, current decision, per-question index state
and immutable review records. Existing model/reads/transaction decisions supply
context, not substitute verdicts. Historical schema assessment is reconsidered.

Blocked condition:
A decisive source, consumer or executable boundary remains unavailable after
safe local investigation. Record Defer with the exact observation needed;
continue the other questions. Native goal blockage follows its repeated rule.
