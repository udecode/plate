# Suggested tasks

This file says how to offer, track, card, and close suggested tasks in the project's ledger. A card session works from `chips brief <id>` and reads this file only to offer or drop another task. Edit its shared source in `udecode/ustack`.

- **Suggested tasks.** A suggested task tracks side work outside the current run's target (or a measurement that cannot fit the one-hour time budget). A finding that pivots the run never becomes a suggested task. Every session works in its own worktree, while the live ledger lives in the main checkout's `docs/plans/artifacts/suggested-tasks.decisions.tsv` (git-ignored). `decisions-check.mjs` runs ledger commands from the main checkout automatically, and `setup.mjs` + `append` keep the ledger synced with `refs/pstack/ledger` on origin (or the companion repo's origin). Conflicting rows move to `suggested-tasks.refused.tsv`; check it before landing work from a pending local row.
  - **Commands.** Use `node .agents/pstack/decisions-check.mjs`:
    - `chips [--fetch] [--session <id>]` prints Ready, Started, Waiting, and Unmigrated tasks in priority order plus the next Do-list pass (withdrawals, ledger rows, then cards). Exits 1 on blocking problems.
    - `chips all --session <id> [--sessions <file>]` lists all priorities and claims unowned or archived-owner tasks.
    - `chips sync [--session <id>]` updates ledger state and withdraws invalid cards without offering new cards.
    - `chips stale`, `chips groups`, `chips id`, `chips brief <id>`, and `chips cleanup --sessions <file> [--session <id>]`.
  - **Title and effort.** Use an imperative phrase with no priority prefix or `Now:`/`After:`. Append ` (xhigh)` only for `kind: decide` tasks or bugs/slowness whose cause is not located yet; all other tasks run at `high`, capped by `maxEffort` in `.agents/pstack.json`. Add `fast: yes` only for a `high`-effort `kind: fix` task with a known change, failing check, and no public API change.
  - **Priority and ordering.**
    - `P0`: broken base check (`owns:`), regression (`regressed: <sha>`), or major bug with `repro:`.
    - `P1`: release ship-list item (`ship: <id>`) or user-visible bug with `repro:`.
    - `P2`: non-blocking product work, docs fixes, or bugs without repro yet (needs `via:`).
    - `P3`: workflow, repo, or agent tooling and measurements (needs `via:`).
    - Valid `via:` values for P2/P3 offers: `verdict`, `babysit`, `time`, `hook`, `panel`, `stale`. Tasks blocking a higher-priority offered task inherit that priority.
    - When configured in `.agents/pstack.json`, `chips.tiers`, `triage.experimental` (`review-scope:` + `regression:`), and `chips.deferred` control ordering within each priority.
  - **Offering a task.** Run `chips` first. If an uncarded offered task already covers the same topic/question, append a `folded` row instead of a new offer. Otherwise append phase `chip`, decision `<id> <title>`, evidence tokens separated by `; `, and result `offered`. Required tokens: `writes: <paths>`, `topic: <kebab-case>`, `priority: P0|P1|P2|P3` (unless `owns:`), plus `kind:` (`decide`, `review`, or `fix`), `waits:` (`pr:<N>`, `task:<id>`, `run:<plan>`), `owns:`, `repro:`/`regressed:`/`ship:`, `via:` (for P2/P3), `review-scope:`, and `session: <id>` (or `session: none` for findings outside this run's domain, which only `/chips all` cards).
  - **Owner, cards, and limits.** Each non-ship-list task belongs to the session that offered or first carded it. Plain `/chips` cards only this session's own tasks; `/chips all` handles unowned, archived-owner, and ship-list tasks. Card only Ready tasks (up to 10 pending cards per session), using `chips brief <id>` verbatim as the prompt and its first line as the title. Judge real dependencies first (`task:` or `run:` waits; log `apart` before adding a `task:` wait inside the same topic). Log `carded` with `card:` and `session:`. To withdraw a card, dismiss it via the tool and log `started`, `dismissed declined`, or `uncarded`. Without a suggest tool, list Ready tasks in `## Open work` or the reply.
  - **Card session lifecycle.** Print `chips brief <id>`, verify the task is Ready or Started, log `started` with `session:`, and re-read `chips brief <id>`. Log an extra `started` row with added `writes:` before editing unlisted paths.
  - **Card landing.** Land through `node .agents/pstack/land.mjs`, log `landed` with `commit:`, fix workflow friction hit in-session, run Close on any tasks offered, merge run directories into the main checkout's `docs/plans/artifacts/`, run `scan.mjs --landed <worktree>` (locking the worktree if it fails), and title the session `⏳ <name>` only if nothing waits on the owner (otherwise `🟠 <name>`); never self-settle.
  - **Base branch.** A decision row blaming a pre-existing failure names `base-red: <check>`, which requires an open ledger task owning that check (`owns: <check>`).
  - **Fast review.** Landed `fast` tasks stay owed review until a `reviewed` row; a `kind: review` task in topic `fast-review` panels their combined diff.
  - **Close.** At a run's final hand-back (after delivery and closing the plan), check `chips brief <id>` for each task this run offered inside its domain, card the Ready non-deferred ones (logging `carded`), and add one closing line above the links reporting how many tasks were offered, carded, waiting, or left to `/chips all`.
