# Worktrees and landing

This file says how a task works in its own worktree and lands on `next` in `trunk` delivery. The pstack block in `AGENTS.md` points here. Edit its shared source in `udecode/dotai`.

- **Worktrees.** Each task works in its own worktree cut from `origin/next` when it first needs to run or edit project files, not at intake. Never edit or commit in the main checkout while it is on `next` or `main`, except under `docs/plans/artifacts/` (git-ignored, holding the suggested-task ledger and run directories). Keep temporary build/benchmark checkouts in a temp folder and remove them when done. After landing, finish any owed reflect, ask reread, and `chips` Close, merge run directories into the main checkout, and run `scan.mjs --landed <worktree>` (leaving the worktree for cleanup after a quiet day, or locking it if the scan fails). `setup.mjs --hook` on SessionStart copies untracked `.env`/`.env.local` files, runs `--install` in new worktrees, syncs `refs/pstack/ledger`, and fast-forwards the main checkout when safe.
- **Landing.** After writing passes and proof, land with `node .agents/pstack/land.mjs --message <file> [--check <command>]...`. Run with `--dry` in the foreground first to validate the message and `landChecks`, then run the real land in the background with a 60-minute timeout (ending with `land.mjs` itself so the exit code is preserved).
  - **Commit message.** One Conventional Commit (`feat|fix|docs|refactor|test|chore|perf(scope): subject`, imperative, no trailing period), short `Why` body describing final behavior, plus required lines `Beyond the ask:`, `Picks:`, and `Not checked:` (`none` when empty). A `fix` commit also requires `Introduced-by: <sha>` (or `none`). Never put closing keywords (`close`, `fix`, `resolve`) before `#<N>`, `<owner>/<repo>#<N>`, `GH-<N>`, or issue URLs; cite `<repo>#<N>` instead.
  - **Execution.** `land.mjs` squashes the worktree into one commit, rebases onto `origin/next` (rebuilding `generated` entries on conflict or when marked `always`), runs `pnpm lint:task --allow-ignored`, `landChecks`, and each `--check`, and delivers per `git config pstack.delivery`. In `push` mode it pushes `next` (retrying up to 3 branch moves and backing off on GH006/network errors; exit 75 means retry up to 3 times with no `--message`). Without `push`, it pushes a topic branch, opens a PR (rendering `plan-page.mjs --pr` if one dated plan changed, else requiring `## Why` and `## Verification`), and arms GitHub auto-merge.
  - **Closing plans and signing.** In `push` mode, write `## Close`, tick completed boxes, and set the final `Status:` before the last `land.mjs` run; never name a commit's own SHA inside the plan. If GPG signing fails due to a locked signer, ask the owner once to unlock it and rerun `land.mjs`.
  - **Guard.** `guard.mjs` blocks force-push/delete of `next`/`main`, direct `git push` to `next` (unless `--dry-run` or `PSTACK_RELEASE=1`), `gh pr create` into `next`, workflow run approvals, and edits in the main checkout outside `docs/plans/artifacts/`.
- **Companion repository.** When `.agents/pstack.json` configures `companion`, a second repo at `companion.dir` tracks `companion.list` files in the same folder (`git --git-dir=<companion.dir> --work-tree=.`). `land.mjs` rebases and checks both halves together, pushes `next` first, then pushes the companion commit with `Lands-With: <sha>`. Stage intentional companion deletions with `rm --cached`. `guard.mjs` blocks `git clean -x/-X`, `git clean` via `companion.dir`, and moving to commits lacking `companion.list`.
- **Other people's PRs.** Fix another person's PR in a detached worktree at its head and push `HEAD:<head branch>` if the remote head matches. Keep your PR description (or latest comment on someone else's PR) true to the pushed diff. If maintainer edits are disabled, carry their commits into one commit with `Co-authored-by:` lines, land it, and close their PR linking the replacement.
- **Review.** `land.mjs` appends `Session:`, `Plan:` (when one dated plan changed), and `Lead:` trailers. Review unreviewed commits with `node .agents/pstack/review.mjs` (`--tier internal|all`, `--net <session>`, `--done <session>`, `--mark`, `--revert <session> [--stage]`). List every commit landed this session in the closing reply's link list. Commits must cite a source (repo/companion issue `<repo>#<N>`, card id `t_...`, or `Plan:` path) unless the GitHub user is in `sourceless`.
