# Codex workers

This file says when a Claude Code lead hands Codex a task or a slice of one, and how it reviews what Codex wrote. The pstack block in `AGENTS.md` points here. The `sync-pstack` skill renders this file from its shared source in `udecode/dotai`, so change it there.

- **Codex workers.** In Claude Code, on the owner's word, such as "have Codex do it", the lead hands a task or a slice of one to Codex itself instead of asking the owner to prompt Codex. In a long run it also hands Codex, without that word, a mechanical slice that a command proves done: a rename or codemod across packages, a benchmark protocol run, or a fix loop that ends when typecheck or lint passes. A protocol run's `--timeout` fits the Time budget rule, so one that cannot fit goes to a suggested task instead. After a worker times out, the lead diffs what it wrote before going on. Such a worker never writes or changes a test, a doc or a changeset; the lead writes those (owner's word, 2026-10-15). A Claude session that has located a fix's cause or settled a design, and planned the change, also hands Codex the coding without that word when the change is more than a few lines or needs its own test loop. It writes the change itself when the brief would be longer than the diff. That worker writes the change's regression tests too, while docs and changesets stay the session's (owner's word, 2026-10-16). UI design, layout, styling and every judgment made from a screenshot, such as a pixel match, stay in the Claude session (owner's word, 2026-10-16). So a change judged by how it looks never goes to Codex, though the logic inside a UI component may. The session fills `.agents/pstack/codex-build.md` with the task, the cause or design, the planned change, the files and the checks. It saves the brief in its own working tree under `codex/<task id>/` in the plans artifacts folder, which git ignores, and runs `cross.mjs` from that tree with `--effort xhigh --timeout 21600`, writing the output to `codex.log` beside the brief. A coding run may take up to six hours, because stopping a long fix wastes its work, and `cross.mjs` accepts that under `--bypass`. The session waits for the run to exit. Then it reads the whole diff and each caller of every changed symbol, checks that each new test fails without the change and passes with it, and reviews every test against the Tests rule, rewriting or cutting each one that falls short. The session sends a diff that fails review back to Codex once with its findings, then finishes it itself. The writing passes, the proof and the landing run as usual. `/chips codex`, or `"chips": { "codex": "always" }` in `.agents/pstack.json`, forces the handoff on a card whatever the size of its change, a design question's or an `(xhigh)` fix's included, once its session has found the cause or settled the design. On a forced card the session reads the diff and runs the checks, and rewrites only a test that does not fail before the change or asserts nothing. A card session fixes the workflow friction it hit once its task lands, as chips.md's Landing says, and the session that carded it fixes only an item its report leaves unsettled. It writes the brief to a file in the run directory and runs `node .agents/pstack/cross.mjs --to codex --bypass --timeout <seconds> --prompt-file <file>` from the project root in the background. `--bypass` starts a new `codex exec` run with the owner's Codex config, hooks, connectors and web search, and with no sandbox or approvals. The worker searches, runs commands and writes files as the owner's Codex CLI does. The project's rules and skills limit what it writes, as they limit the lead. The owner's word also gives the worker any judgment the task needs, such as a research verdict, as an exception to the Extraction rule. The lead reviews what the worker wrote as it reviews a subagent's work before it hands back. The brief says the lead delivers, so the worker commits and pushes nothing, whatever the project's delivery rule says.
