# Long runs

This file says how a long or multi-slice run keeps going, hands off and rereads its rules. The pstack block in `AGENTS.md` points here. The `sync-pstack` skill renders this file from its shared source in `udecode/dotai`, so change it there.

- **Long runs.** Use pstack's Autonomous run playbook with a checkable exit condition. When the run narrows that condition itself, even through a logged scope decision or a Defaults row, the plan's `Status:` stays partial and each part it dropped goes to `## Open work` with its `owner:` and `stop:`. Only the owner's own words make a narrower condition count as done. The block's Time budget rule counts as those words for a long measurement it hands to a suggested task. `Status: executed` after the run's own narrowing claims work the run did not do. To redo a prior run at a higher effort or on a stronger model, treating its plan as a draft, load the `redo` skill. Claude Code keeps going with `/loop`; Codex uses its native `/goal`. On "pause", run pstack's Pause safely playbook without its `wip:` commit; the checkpoint stays local, and the Delivery rule decides every commit. Automatic continuation or compaction never resumes paused work. In Codex, read an existing goal before creating one, mark a goal blocked only when a model the models sheet names cannot run, as the Autopilot rule says, or when the goal tool's own repeated-blocking threshold is met and no useful progress remains, never for budget or difficulty, and mark it complete only when its exit condition holds and the plan's checks pass, never just to stop. "go" after a plan, or after a review that proposes one, runs every remaining slice without pausing between slices; it adds no commit authority beyond the Delivery rule. In Claude Code, a plan that says each of its phases lands as its own commit builds one phase per session, because each call in a long session re-reads its whole context (owner's word, 2026-10-19). The session ticks the phase's box in the plan before it lands, so the landed commit carries the tick. Once the phase has landed on the branch, the session ends any `/loop` it armed and runs `.agents/pstack/rules/land.md`'s close stop, before another session can publish the page. Only the session that lands the last phase also runs its playbook's close. Every other phase's session then starts the next phase's session itself, as "go" asked, in its own worktree with a fresh context. The brief names the plan, that phase, the playbook that builds it and the owner's "go". It says to run pstack's Session pickup playbook first, through its pushed-branch fallback with the committed plan as the trail rather than this session's transcript, then that playbook's steps for the phase, and it asks for no report back here. The session closes its "go" todo as handed to that session, detaches it and stops. When `land.mjs` opens a PR instead of pushing, or the runtime refuses the start, the session ends its reply with that brief, for the owner to start once the phase is on the branch. Report each reversible call with the word that reverses it. Before each gate, such as a panel launch, a writing pass, the trail review or the close, and after every wakeup, the lead re-reads `AGENTS.md`, the models sheet and the pstack plugin pin from disk when any of them changed since its last read, and rewrites its open gates from the new text. After every compaction, the lead's first todo is to re-read them from disk whatever changed. Any injected copy of an instruction file, after a compaction, a resume or a reminder, can be older than disk; when one disagrees with disk or with the run's own edits, disk wins. It compares each file with its last-read copy sentence by sentence, never through a diff cut at a column, and makes each changed rule its own todo. The lead makes that comparison with `node .agents/pstack/reread.mjs --dir docs/plans/artifacts/reread/<session id> AGENTS.md ~/.claude/pstack-models.md .claude/settings.json` in Claude Code, or with `~/.codex/pstack-models.md ~/.codex/config.toml` as the last two files in Codex, where any directory the session keeps for itself under `docs/plans/artifacts/reread/` serves. It prints each sentence that changed since its last snapshot in full. Outside `--hook`, a call without `--dir` and a file prints only its usage. A project's SessionStart hook can run it with `--hook`, which keeps the session's snapshots and prints the directory to pass as `--dir`. A sync or `apply` the lead ran itself counts as such a change. After a pin change it reloads each pstack skill it still uses and takes reference paths from the newest base directory that skill prints. After it edits a skill whose mode it is running, it reloads that skill through the Skill tool before its next step. Claude Code's compaction restores only the first 20,000 characters of each skill. After one, `reread.mjs --hook` names the longer skills on its `reload:` line, and the lead reloads each of those whose mode it is running the same way. A mid-run sync reaches the lead only through a later read.
