# Long runs

This file says how a long or multi-slice run keeps going, hands off and rereads its rules. The pstack block in `AGENTS.md` points here. The `sync-pstack` skill renders this file from its shared source in `udecode/dotai`, so change it there.

- **Long runs.** Use pstack's Autonomous run playbook with a checkable exit condition. To redo a prior run at a higher effort or on a stronger model, treating its plan as a draft, load the `redo` skill. Claude Code keeps going with `/loop`; Codex uses its native `/goal`. On "pause", run pstack's Pause safely playbook without its `wip:` commit; the checkpoint stays local, and the Delivery rule decides every commit. Automatic continuation or compaction never resumes paused work. In Codex, read an existing goal before creating one, mark a goal blocked only when the goal tool's own repeated-blocking threshold is met and no useful progress remains, never for budget or difficulty, and mark it complete only when its exit condition holds and the plan's checks pass, never just to stop. "go" after a plan, or after a review that proposes one, runs every remaining slice without pausing between slices; it adds no commit authority beyond the Delivery rule. Report each reversible call with the word that reverses it. Before each gate, such as a panel launch, a writing pass, the trail review or the close, and after every wakeup, the lead re-reads `AGENTS.md`, the models sheet and the pstack plugin pin from disk when any of them changed since its last read, and rewrites its open gates from the new text. After every compaction, the lead's first todo is to re-read them from disk whatever changed. Any injected copy of an instruction file, after a compaction, a resume or a reminder, can be older than disk; when one disagrees with disk or with the run's own edits, disk wins. It compares each file with its last-read copy sentence by sentence, never through a diff cut at a column, and makes each changed rule its own todo. The lead makes that comparison with `node .agents/pstack/reread.mjs --dir <directory> <files>`, which prints each sentence that changed since its last snapshot in full. A project's SessionStart hook can run it with `--hook`, which keeps the session's snapshots and prints the directory to pass as `--dir`. A sync or `apply` the lead ran itself counts as such a change. After a pin change it reloads each pstack skill it still uses and takes reference paths from the newest base directory that skill prints. After a compaction, or after it edits a skill whose mode it is running, it reloads that skill through the Skill tool before its next step. `reread.mjs --hook` prints a `reload:` line naming each skill loaded before the compaction. A mid-run sync reaches the lead only through a later read.
