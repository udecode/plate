# Plans and trails

This file says where plans and decision logs live and what their rows and proofs must show. The pstack block in `AGENTS.md` points here. Edit its shared source in `udecode/ustack`.

- **Plans and trails.** Keep a dated plan (`docs/plans/<date>-<slug>.md`) and decision log (`docs/plans/<date>-<slug>.decisions.tsv`) in the repository when work spans sessions, goes into a PR, accepts a narrower proof, or a project playbook requires one. Other runs keep their log in the run directory (`docs/plans/artifacts/<slug>/`, git-ignored) and hand back in the reply. Store all durable run artifacts (pre-edit copies, seat answers, proof logs, worker rosters) in the run directory; never commit screenshots or run artifacts, and never rely on temporary scratch that restarts can wipe.
  - **Decision-log rows.** Append 6-column TSV rows (`ts`, `phase`, `decision`, `why`, `evidence`, `result`) directly to `<log>` in batches with UTC timestamps. Start every result with a clear status word (`fixed`, `verified`, `proven`, `partial`, `open`, `decided`, `applied`, `dismissed`, `deferred`, `recorded`, `superseded`, `reverted`, `blocked`, `gap`, `inconclusive`, `accepted`), include `scope:` in evidence on proven rows, and log cheaper stand-ins as `partial` with the gap stated. Use stage phases (`architect`, `panel`, `build`, `writing`, `verify`, `delivery`, `reflect`); reserve `review*` for hand-off reviewers.
  - **Closing plans.** Mark a plan Done only when no unchecked boxes, TODO/TBD/FIXME, or blank gate cells remain, every closed box cites its artifact or `skip: <reason>`, and every deferred or `## Open work` item names a real `owner:` (person or scheduled run, never a skill) and observable `stop:`.
  - **Proof hygiene.** Run routine verification commands directly and verify their command output and exit code (do not wrap routine proofs in `node .agents/pstack/proof.mjs`; reserve `proof.mjs` for scripts like `land.mjs` or Local CI that call it, or long suites needing core-pool coordination and immutable attempt logs). Pair proofs with a control or must-fail case so a no-op launch cannot pass, and assert expected failure text on non-zero exits. Under `pipefail`, write bounded output to a file before piping to early-exiting consumers (`head`, `grep -m`).
  - **Honest claims.** Every count, absence, impossibility, or external capability claim names the check that could falsify it (or says it is inferred); verify runtime claims by running the real path, not only reading types or docs. When a claim narrows or a proof is superseded, log a `superseded` row and update every plan step, Close, subject file, commit body, and PR text that cites it. An approved plan change gets a deviation row, keeps the approved wording visible, and opens `## Close` as a reversal. Save background subagent reports to the run directory when they arrive so compaction cannot lose them.
