# Panel review and Review

This file says how a panel or arena runs and how a panel reviews a diff. The pstack block in `AGENTS.md` points here. Edit its shared source in `udecode/ustack`.

- **Panel review.** Panels follow an empirical-and-formal-first standard: routine builds run 1 plan round (when triggered) and 0 diff panels. Intermediate steps rely on empirical tests (`verify`, Playwright, unit tests) and formal verification skills. Run a panel only for (a) `api-plan`, contested designs, or irreversible hard cuts (1 plan round before build), (b) external PRs, and (c) final close of major public-API or core-invariant builds (or when `reviews` or the user asks). Write the prompt once to a file in the run directory (using absolute paths for ignored run-directory files) and share it across seats. Until every seat answers or fails, do not edit files the seats read.
  - **Prompt and severities.** Frame panel prompts neutrally as code review to verify correctness and edge cases; avoid security-triggering words (`attack`, `adversarial`, `bypass`, `exploit`) so provider cyber-risk filters do not refuse normal code reviews. Quote the user's asks verbatim and list the invariants to check, tagging each as `[ask]`, law, or lead premise. Require a concrete code trace or failing repro for every finding; reject doc, ledger, or style nitpicks. Ask seats to tag findings `critical` (bugs, data loss, security, broken behavior), `warning` (maintainability or latent risk), or `nit` (minor improvement). A review-only panel (such as another person's PR) returns findings directly in the reply with no plan or decision log.
  - **Logging.** Log each round under phase `panel`: open with a `seats` row naming each model and effort (plus `missing` or `skipped`) and the reviewed commit or patch, then log each critical finding as `applied`, `dismissed`, `recorded`, or `open`, and group warnings/nits in one row. Log a finding's row only after its fix, proof, or dismissal trace has run.
  - **Dispositions.** Apply real critical findings, or pivot when the adopted design cannot meet the case. Dismiss a critical finding only with a concrete code trace or proof that the case is no defect (citing law when applicable) or is rare on real data. Leave a critical finding `open` only when it already fails the same way on the base commit, breaks no user ask, and violates no requirement of the new design; state the limit in any affected docs or law lines. A critical finding in code no user can reach yet may be logged `recorded` with its repro file and the step that fixes it before that code becomes reachable.
  - **Rounds and scope.** Routine builds get at most 1 plan round and 0 diff panels. Intermediate build steps skip diff panels and verify with empirical tests and formal verification skills; a diff panel runs at final close only for major public-API or core-invariant builds, on external PRs, or when `reviews` or the user asks (max 1 diff round, plus one re-review round on the fixes only if a round applied three or more critical findings, or `maxRounds` in `.agents/pstack.json`). At the cap, settle open findings and move on; do not loop indefinitely. If a second fix on the same mechanism draws another critical finding, write down the shared premise and test it directly (`pstack:principle-attack-the-premise`) before patching again. Changes to agent prose alone skip panels, `architect`, and arenas unless asked or listed in `reviews`.
  - **Running seats.** In T3 Code, launch all panel seats together via `delegate_task` (`mode: "async"`) using T3's active provider instances (`claudeAgent` / `claude-fable-5-2 @high`, `codex` / `gpt-6.2-sol @xhigh`, and the active Antigravity instance / `gemini-4-neon @high`) so seats reuse live T3 auth, avoid CLI quota collisions, and avoid shell timeouts. Reserve `seats.mjs`/`cross.mjs` (`node .agents/pstack/seats.mjs --dir <round dir> --prompt-file <file> <name>=<claude|codex|agy>:<model>@<effort>...`, with `--read-dir` for extra folders) for non-T3 runtimes (Claude Code or Codex CLI) where `delegate_task` is absent: `cross.mjs` runs `claude` in plan mode, `codex` with `--reach` in a scratch folder, and `agy` from a scratch folder without GitHub tokens or push access, capping effort at `maxEffort` with hooks off and a 1,200 s idle cap. Never use `t3_thread_launch` for panels, arenas, or review seats.
  - **Failures and fallbacks.** Never silently substitute another model when a configured seat fails. If a sheet entry names a fallback after `or`, pass it to `seats.mjs` (`<primary>|<fallback>`); Sol has no fallback and is skipped when Codex is unavailable. A failed, unavailable, security-refused (`refused: security`), or usage-limited Codex seat, or a failed/filtered `agy` seat, is reported `skipped` and the round continues with the answering seats (marking the round same-family if only one model family answered). Any other failed seat gets one rerun on the same model; if it still fails, stop under Needs you with the error and options to fix the account, change the sheet, or continue without that seat.
  - **Arena and `architect`.** `architect` sketches two shapes and picks one; large or contested designs run an arena. Code arenas run slots on the session's model; cross-judges read anonymized `cand-1`..`cand-n` copies. Project playbooks naming `pstack:interrogate`, `pstack:arena`, or `pstack:architect` cite `(reviews: <id>)`.
- **Review.** Judge a diff by what the code gates, not only the lines touched. Review the worktree's diff against `origin/next`, including uncommitted work, before `land.mjs` pushes it. Review a PR's branch diff against its base. Include every caller or entry-point file the change can break. Verify every critical finding against real code or output before logging it, fix real defects, and rerun each fixed finding's repro so it fails before and passes after.
