# Browser drives

This file says how an agent's browser tools deliver input, draw frames and handle the clipboard, so a drive reaches the page as a person's keyboard and screen would. The pstack block in `AGENTS.md` points here. The `sync-pstack` skill renders this file from its shared source in `udecode/dotai`, so change it there.

- **Typing.** Type key by key whenever the result depends on what typing triggers, such as a keyboard shortcut, a mention or slash menu, autocomplete, an input mask or editor autoformat. Setting a value or inserting a whole string skips those handlers. The key-by-key operation is `pressSequentially` in Codex's browser, `type` in Claude in Chrome, and `key` with one space-separated token per character in Claude Code's built-in browser, such as `# space h i`. The built-in browser's `type` inserts the whole string as one `insertText` with no key events. Send a shifted character as itself, such as `*`, `A` or `@`. For `shift+8` the built-in browser inserts nothing and Claude in Chrome inserts `8`. Claude in Chrome takes keys only after one real click into the page; script focus alone delivers none. After the input, read back the state the claim is about, because a tool that reports the keys as pressed does not show they arrived.
- **Frames.** An agent's browser can throttle a page nobody is looking at. A hidden Claude Code built-in pane runs one or two animation frames a second while `document.visibilityState` still says `visible`. A Claude in Chrome tab that reports `hidden` runs none and fires no `IntersectionObserver` callbacks either. Before a claim that depends on frames or observers, such as virtualization, lazy loading, scroll anchoring, a floating element's position, drag autoscroll or an animation, count `requestAnimationFrame` callbacks over one second in the page, whichever browser drives it. Below 30, that browser cannot prove the claim. Where the project's rules allow it, prove it with a test the project's own browser suite already runs, whose Playwright Chromium launches without background throttling. Otherwise ask the owner to show the browser and keep other work going until they do. Cmd+Shift+B shows the built-in pane, and Chrome needs its window in front. Never start an ad hoc browser driver for the claim; without either proof it stays open.
- **Stalls.** After `navigate` in an existing tab, Claude Code's built-in pane can leave a page stuck on its first loading frame, most often while the pane is hidden. Before recording that a page hangs or does not show something, open the same URL in a fresh tab with `preview_start` and its `url`, and read the page there. A finding that clears in the fresh tab is a browser stall, not a product finding. The pane holds a limited number of tabs, so close each spent tab with `tabs_close`.
- **Clipboard.** Claude Code's built-in browser has no native clipboard, and Cmd+C and Cmd+V fire no `copy` or `paste` event there. Drive a native copy or paste in Claude in Chrome after one real click, or through the project's clipboard test.
