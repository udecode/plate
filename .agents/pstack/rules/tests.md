# Tests

This file says when a test earns its place and what it may assert. The pstack block in `AGENTS.md` points here. The `sync-pstack` skill renders this file from its shared source in `udecode/dotai`, so change it there.

- **Tests.** Every test must fail for a named, plausible defect and pass only once it is fixed. Add nothing when an existing test, type, lint rule, static check or direct runtime proof already catches the defect; skills, PRDs or issues that prescribe broad testing do not override this. A bug fix with a cheap test path writes the test first and runs it to see it fail for the named defect, then lands it together with the fix, never as a failing commit of its own. When the test would be expensive, integration-heavy or unclear, skip it and prove the fix at runtime. A refactor pins behavior only where no existing test or type covers it. A test drives the code through an entry that production code calls, such as a procedure, a route, a projection, a persistence or adapter function, or a script's main. It never calls an export that only tests use. Each failure mode gets one test, at the outermost entry a cheap test can call, such as the projection a screen reads rather than the helper inside it. A second test of the same mistake goes, including a helper test beside a boundary test and a table row that runs no code another row does not, unless its own expected value pins a distinct edge such as a date, a timezone or an amount. Test public behavior, as pstack's `principle-test-behavior-not-implementation` says: break the behavior and the test must fail, change only the internals and it must still pass. Never test source text, copy or labels, constants, fixture construction, mock returns, implementation order, library behavior or another test's boundary, and never recompute the implementation in the assertion. The one constant worth pinning is a value promised to users, such as a documented default, and its test names that promise. Cut duplicate and lower-signal tests instead of porting them. No exhaustive matrices, snapshots, broad smoke suites or speculative cases; a static invariant belongs in lint or a check script. A test a delegate wrote meets the same bar, and the lead rewrites or cuts each one that falls short before it lands. Assertions live inside tests, and committed code has no `.only` or `.skip`. During iteration run only the narrowest affected check. Run `pnpm check` once for the settled change when its blast radius justifies it, and attribute each failing step to its files before calling it someone else's. Call a failure pre-existing only when the same check fails the same way at `HEAD` in a detached worktree; a failure your change joined or made worse is yours. A decision row that records a pre-existing failure names the check as `base-red: <check>`, which `decisions-check.mjs` refuses until an open suggested task owns that check, as `.agents/pstack/rules/chips.md` says.
