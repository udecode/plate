# Tests

This file says when a test earns its place and what it may assert. The pstack block in `AGENTS.md` points here. The `sync-pstack` skill renders this file from its shared source in `udecode/ustack`, so change it there.

- **Tests.** Never write autonomous post-hoc unit tests after writing code. Every test must fail for a named, plausible user defect and pass only once it is fixed. Add nothing when an existing test, type, lint rule, static check or direct runtime proof already catches the defect; skills, PRDs or issues that prescribe broad testing do not override this. Work down this ladder in order and stop at the first rung that catches the defect: 1. Architecture, stronger types or a lint rule (`pstack:correct`) so the bug class cannot exist. 2. An E2E test (`verify` or the project's driver skill) or a public boundary or golden round-trip test. 3. A zero-baseline property or differential invariant: fast, deterministic, with no known-bad baseline snapshot. 4. An isolated failing-first unit test (`pstack:tdd`) only when the defect cannot be cheaply reproduced at the boundary and the test fails for the named defect before the fix, then lands together with the fix, never as a failing commit of its own. When the test path is expensive, integration-heavy or unclear, skip the unit test and prove the fix at runtime. A refactor pins behavior only where no existing test or type covers it.
- **Separate grader.** A fix never weakens or deletes an existing E2E, boundary or invariant assertion unless the user-facing contract explicitly changed and the commit or plan cites the evidence for that change.
- **Shape and scope.** Drive code through an entry that production code calls (a public API, route, projection, persistence adapter or script entry), never an export that only tests use. Keep one test per failure mode at the outermost cheap entry, and cut duplicate or lower-signal tests instead of porting them. Follow pstack's `principle-test-behavior-not-implementation`: breaking public behavior must fail the test, and changing internals alone must keep it passing. Never test source text, copy or labels, constants (except a value promised to users, with that promise named), fixture construction, mock returns, internal call order, library behavior or another test's boundary, and never recompute the implementation in the assertion. No exhaustive matrices, snapshots, broad smoke suites, wall-clock bounds outside benchmarks or speculative cases; static invariants belong in types, lint or a check script. A test a delegate wrote meets the same bar, and the lead rewrites or cuts each one that falls short before it lands.
- **Running and attribution.** Assertions live inside tests, and committed code has no `.only` or `.skip`. During iteration run only the narrowest affected check. Run `pnpm check` once for the settled change when its blast radius justifies it, and attribute each failing step to its files before calling it someone else's. Call a failure pre-existing only when the same check fails the same way at `HEAD` in a detached worktree; a failure your change joined or made worse is yours. A decision row that records a pre-existing failure names the check as `base-red: <check>`, which `decisions-check.mjs` refuses until an open suggested task owns that check, as `.agents/pstack/rules/chips.md` says.
