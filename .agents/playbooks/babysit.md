# Babysit

Finishes started work and never starts the next feature. Any owner request starting this playbook on a PR (e.g. "finish PR <number>") carries the same authority as "babysit".

- **Before** "Declare the mode in your first line, before any poll": `"review PR <number or URL>"` on someone else's PR is review-only (reviews: external-pr). Run the panel on its diff briefed with PR body, linked issue and any `docs/plans` plan, judging whether it should exist, design and code. Reply with findings and stop (no plan, log, edits, pushes, comments or review submissions).
- **Before** "Declare the mode in your first line, before any poll": resolve the PR (`gh` / `pull_request_*`) or current worktree diff. Lead with a candid verdict and strongest cut (`verdict` if API/architecture changes it); repair at the owner (Bug fix / Refactoring) so callers, docs, examples, registry output, changesets and barrels end coherent; prove with `verify`. Current-tree cleanup skips PR Babysit steps except code-quality review below.
  - **Untrusted-author security gate:** before installing, running or pushing code from any PR whose author is not on `team` in `.agents/pstack.json` (and on every new author commit), run `pstack:thermo-nuclear-review` on every added line. Stop for owner word on author edits to workflows, package scripts, build/test configs, lockfiles, dependencies, or lines reading secrets/tokens/env or calling the network.
  - **Reservation:** an assignment held by someone other than the PR author (on PR or linked issue) reserves it; stop and leave open.
  - **Push vs carry/fold:** own PRs use `make-pr-easy-to-review`; others' PRs keep one concise Markdown comment. Push repairs to the PR's head branch (unless `main`/`next`). If maintainer edits are disabled or push fails, carry/fold on a fresh branch from base into one commit with `Co-authored-by:` for every author (author's own assignment does not reserve a carry; push only after verdict + security read cover the folded diff; never put closing keywords before `plate#<N>`). Re-read author head right before close/land and fold new commits via `git range-diff`. Into `next`: deliver via `land.mjs`, then close original PR linking the commit. Into `main`: check commit message via `writing-check.mjs`, open our PR with plain public Markdown (keeping `auto-release` box, stripping internal lines), close original PR with a plain link comment, and babysit our PR (polling closed PR comments until merged). "babysit" authorizes that close and link comment; other public comments, thread replies and history rewrites stay drafts.
- **Before** "Owner approval is a wait. Babysitting never authorizes merging.": run `pstack:thermo-nuclear-code-quality-review` on the diff (`.agents/playbooks/refactoring.md` split law overrides size-based split advice). Fix/answer every introduced defect; defer pre-existing findings with `owner:`.
- **Before** "Owner approval is a wait. Babysitting never authorizes merging.": PR babysits run `drive` and merge once green ("babysit" authorizes merging and `main` push/deploy; skipped only for review-only, issue PRs and `next` carries via `land.mjs`). Mark green drafts ready (`gh pr ready`). Stop only if verdict rejects whole PR, author code/assignment holds it, an irreversible call has no clear pick, or repair cannot be pushed/carried. Use `--merge` into `next`, `--squash` into `main` (subject `<title> (#<number>)`, never `[skip release]`; checked `auto-release` publishes pending changesets). Check `gh api user --jq .login`:
  - **`zbeyens`:** once checks are green and only `review-required`, draft or settled threads remain, run `gh pr merge <N> --admin --match-head-commit <headRefOid>` (pass `--body-file` to preserve `Co-authored-by:` on carried PRs) and verify merged state on base. Never merge over failed checks.
  - **Other users:** once only `review-required` remains, arm `gh pr merge <N> --auto` and stop. `"merge it"` merges at once.

## PR specializations

- **Issue PRs (`next`):** PRs naming a `udecode/plate` or `udecode/plate-private` issue run as `triage fix #<N>` / `triage fix plate-private#<N>` (`triage.md` Fix) with PR diff as candidate (taking PR author's holds). Prove red on `next`, green at PR head; trace non-owner edits and untouched owner files; cherry-pick onto `origin/next` worktree; add tests per record miss classes; land via `land.mjs` with `Co-authored-by:`; record/comment per Fix step 4; close PR linking commit.
- **Main-line PRs (`main`):** govern with this repo's rules, taking only repo facts from `../plate` (`pnpm test -- <dir>`, `pnpm test:slow -- <dir>`, `pnpm check`, `pnpm brl`). Work in a detached worktree of `../plate` outside this checkout (`../plate-worktrees/<slug>`), install with `pnpm install --frozen-lockfile --prefer-offline` (never `setup.mjs`; `--no-frozen-lockfile` only after lockfile gate, never committing lockfile), build workspace deps (`pnpm turbo run build --filter=<pkg>...`) before slow tests, and verify global git author matches `gh api user` before pushing. Fix red `main` in its own PR first, then `gh pr update-branch`. Re-read `headRefOid`, body and comments each round.
- **Next coverage & Main sync ledger:** before verdict on a `main` PR, run `review-comment` step 2 to log `covered` (v2 proof replaying Beta issue repros), `moot` (v2 removed job), or `gap` (after `main` merges, build and land v2 fix on `next` via `land.mjs` with `Co-authored-by:`, using `verdict` if API/architecture). Run `node tooling/scripts/main-sync.mjs` (`docs/plans/main-sync.tsv`) first on every non-review-only `main` babysit, report unsynced rows, and mark `--set '#<N>' synced` once covered/moot/landed (or `gap` + reason).
- **Linked issue & After the session:** after a `main` PR merges, settle named issues: Beta `gap` records via `next` Triage Fix; `moot` closes `not planned` citing law; others close `completed` naming PR/release. If ending before merge (e.g. `--auto`), record the PR, Next coverage, linked issues, remaining steps and `"babysit"` date in the reply's Open work.
- **Plan & feedback sweeps:** repair babysits keep plans in this repo's `docs/plans`. Objective low-ambiguity review feedback triggers Bug fix Pokayoke audit; taste/API comments go to decision/pushback or `best-api`.

## Current-tree closure

Clean means: zero unresolved verified in-scope findings; required reviews passed or N/A; accepted code-shape findings fixed via Refactoring, rejected or routed; coherence audit clean (no stale patches, fake aliases, docs/API drift, orphan tests, stale generated output, missing changesets or Slate/Plate boundary breaks); material public API diffs passed `best-api review` with P0/P1 resolved or rejected; focused proof passed after last patch with generated outputs synced in the current checkout. Sweep review comments only where they generalize in one sentence; relocate `isOutdated` threads by source text before deciding.
