# Bug fix

- **In** "Reproduce it yourself on the matching surface via the driver skill": attached screenshots and recordings are the report; transcribe a recording with `video-transcripts` and keep the reporter's exact route, input and expected result. "Regression vs main" means reproducing on `main` in a detached worktree as the baseline, then on the current checkout, and naming the change that broke it.
- **In** "Binary-search the cause": before the first hypothesis, read the area's page in `docs/research/sources/plate-notes/` for failure modes already diagnosed there. Tighten the loop first, to seconds rather than minutes, asserting the specific symptom, with time pinned and randomness seeded; raise a flaky bug's reproduction rate until it can be debugged. Each hypothesis states a falsifiable prediction ("if X is the cause, changing Y makes the bug disappear"), and each probe tests one prediction by changing one variable at a time with targeted boundary logs, never log-everything.
- **After** "Binary-search the cause": `diagnose` stops here with the cause and its evidence.
- **In** "Plan the fix": fix at the owning layer. Plite owns substrate behavior, and Plate owns product and plugin policy. Repair the violated invariant and what let it escape, per Pokayoke below, never with a caller workaround. The same value added at many callers only to fill a required input, such as one placeholder ID in every demo, is that workaround, so decide at the owning API, through `best-api`, whether the input should be required.
- **In** "Plan the fix": a sweep find, an issue from a hands-on round that `verify`'s [tester pass](../rules/verify/references/tester-pass.md) prepares, gets its test at the lowest layer that sees the bug. Read the published issue first and tag only a test that checks all of it; the tag is the issue's `[plate#N]` in the test's title, beside any `[EDIT-…]` tag. A Plate browser test goes in `apps/www/tests/browser/regressions/`. Once the fix passes, write `covered-by:` on the find's recheck in the round's plan: the test's path, its title and the hash `pnpm kb plate#N` prints.
- **After** "Verify on the same surface": a fix that changes what a browser shows runs `verify`'s Hand drive on the fix's files after its last edit, and the plan's Completion Gates table gets a Hand drive row whose evidence is the `hand-drive.mjs check` log. A drift the drive finds is a finding of this fix.
- **After** "Verify on the same surface": a fix already reported as done, locally or publicly, that then fails its exact replay or final verification, or that the reporter contradicts, is a failed fix; the expected red before a fix is not one. A case that first fails a stability run after an exact green gets the same freeze and classification below before another product attempt. The reporter assertion must run before a failure counts: a proof host that crashes or fails before the assertion is repaired at its own owner, and the same product attempt restarts. Before another product attempt: revoke the earlier green and completion claims, leaving public corrections to the authorized public coordinator. Freeze the product bytes, rerun the failing assertion and name what made it red: product nondeterminism, interaction delivery, host readiness or oracle sampling; repeated passes without that answer do not resume product edits. For native selection, focus, popup or toolbar focus, mounted keyboard or semantic commands, or an exact route, apply `verify`'s [failed native diagnostics](../rules/verify/references/regression-oracles.md#failed-native-diagnostics) first. Name why the earlier proof passed (the product invariant, test boundary, runner, served source or completion decision) and repair that gap at its owner, preferring an assertion that rejects the escaped case over new instructions. When an existing gate already rejects the failed packet, record no change with that gate's passing evidence; never reword an enforced instruction just to produce a diff, and a defer cannot close a required gap. Then restart from exact reproduction with every still-applicable acceptance item; an outcome inferred during the failed attempt does not carry forward. On the second failed fix, or at once when the fix compensates across layers, duplicates a live identity, adds per-node hot work, depends on a timer for focus correctness or repairs substrate state from UI, run `pstack:recall` on the bug and its owner with no time window, then run `verdict` on the owner before another attempt. The lead adds the recall brief to verdict's history reconciliation, so the review starts from earlier sessions' attempts, reverted fixes and still-open reports. Repair authority continues through that review. The review compares deleting or merging the implicated owners before adding compensation, and its Stop may keep the existing owner with a stated reason.
- **After** "Verify on the same surface": tag every debug probe with a unique prefix, then grep-remove them all and delete throwaway harnesses before done. A published package edit requires its applicable changeset per `changeset`.
- **Replace** "Stage the commits so the failing repro lands before the fix": a test written first lands together with the fix, never as a failing commit of its own, per `AGENTS.md`'s Tests rule; the owner commits, per the Delivery rule.
- **Replace** "Run **Opening a PR**": open a PR only when the user asks, per the Delivery rule.
- Corpus, harness, rewrite-closure or repeated regression work runs through this playbook one case at a time. Discover the cases each run from runner listings, test titles and live issues, and keep any ordering table in the plan, never in a registry. Record each case's root cause, red and green commands, architecture verdict and caveat in the plan, and end each case keep, revert, quarantine, defer with its owner and revisit trigger, or block with the missing authority or evidence. Already-applied work called candidate-local, kept or completed is the first intake target: run its affected cases before restoring baseline bytes or editing source, and a red intake is a failed fix as above.
- A public GitHub issue or PR is triaged by `maintainer` first; once `maintainer` routes a confirmed local bug here, this playbook fixes it.
- **Pokayoke.** Repair the violated invariant and the mechanism that let it escape. Prefer one canonical owner, an impossible invalid state, or a reusable assertion over caller workarounds and more instructions. This playbook owns the focused repair and failed-fix recovery; `verify` owns evidence. A recurring invariant failure or growing workaround chain triggers Verdict before another fix. A green proxy never closes a failing or unexecuted reporter interaction. Preserve that gap and continue authorized diagnosis. This reduces repeat defects; it does not promise bug-free software. One confirmed violation opens an audit of its whole governed area beyond the current diff, package or directory: record the exact rule and enumerate every applicable file, consumer and parallel implementation before calling that audit complete. Read each candidate in context, because a similar spelling does not prove the same defect, and fix every confirmed instance the request authorizes repairing; an authority, access or proof blocker leaves that scope recorded as incomplete. A compliance claim covers only the files enumerated and read; a clean sample or grep does not prove the governed set complies.
- **Blockers with a working reference.** Before declaring an environment, provider, migration or missing-input blocker on a path that has a reportedly working reference, trace that reference operation through its caller, effective configuration, request, response and result, and compare the target at the same boundaries. One rejected request does not prove the destination, account or integration unusable. Withdraw an overbroad blocker in the active plan as soon as contrary evidence appears, keep the original failure and the next executable check, and continue independent authorized work.
