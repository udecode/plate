# Build

Executes an accepted plan (without reopening its design) or a hard cut. Name this playbook on the todo list's first line so resumes reload it.

- **Replace** "Trace the affected subsystem.": reread the plan and live source, fix stale claims, and record authority. Reproduce planned guards/refusals through the public entry first; log unreachable ones as deviations. A new check that already fails at base (detached worktree) lands with a shrink-only baseline (`AGENTS.md` Corrections), never dropped. Copy every triggered Before/After gate into the plan's Completion Gates table (`pending` -> artifact or `skip: <reason>`). Refuse plans with `Status: Done`, `work_kind: design`, or a superseding plan (build the owning plan as a Defaults row).
- **Replace** "`architect` for the shape.": skip (Plan settled the target). A slice that cannot follow the plan or replaces a mechanism returns to Plan (time/effort never shrinks a slice; changed/dropped approved proofs become `look` Defaults with a saved patch; substitutions/reverts log deviation rows; behavior-dependent agent prose changes need a trial before landing).
- **Before** "Delegate code-writing to a subagent": run `pstack:blast-radius` when the plan changes a public API so callers outside the plan are known before edits start.
- **In** "Delegate code-writing to a subagent": start ready slices immediately (`long-runs.md`). Freshly load every skill named by a step or gate (`benchmark`, `verify`, `research`, etc.) after any compaction; a prior-session load or `git grep` stand-in counts as `partial`. Brief delegates for focused proof first and surgical edits; port shared-primitive improvements to all consumers.
- **After** "Verify on the matching surface":
  - Hard-cut rejected surfaces per `.agents/playbooks/references/architecture.md` Hard cut and sweep callers, exports, tests, docs, examples, browser proof and benchmarks. Run `best-api repair` after reusable public API changes (plan stays open while worker skills still teach the rejected shape).
  - Rerun scale-sensitive contracts on the final production path via `benchmark` after the last panel fix (after lint fix if rewriting tracked results).
  - Run `plate-docs` (including example coverage audit) on every affected public docs page; record open gaps with owners.
  - Browser-visible builds run `verify` Hand drive after the last edit and `pnpm lint:task` (`node tooling/scripts/hand-drive.mjs check <plan files>` log in Completion Gates; drift is a build finding).
  - If `node tooling/scripts/playtest.mjs scope <plan files>` names a catalog (or the build adds an editor feature without one), write any missing catalog and run the playtest spec runner after slice fixes and before final close (`specs-a<N>.md` in Completion Gates; all feature spec failures, including pre-existing ones, are build findings; parity/out-of-domain findings go to Open work).
  - Run affected `pnpm check <step>` gates before expensive acceptance or benchmark runs.
- **Replace** "Rebase into small, ordered commits": land via `node .agents/pstack/land.mjs` (one commit, or per-step/per-phase when planned). Intermediate steps skip diff panels and rely on empirical tests (`verify`, Playwright, unit tests) and formal verification skills; run a diff panel only at final close for major public-API or core-invariant builds (or when `reviews` or the user asks). Fixes in unreachable feature code land with the step (using `fix` + `Introduced-by:` if fixing an earlier landed step). Fixes in user-reachable shared code land first in their own worktree cut from `origin/next` as `step <N>a` (keeping approved step numbers intact). Steps that expose user-reachable features (`reach:` in `built:` row) run playtest specs and Hand drive before landing; later page edits rerun Hand drive.
- **Replace** "Run **Opening a PR**": run a final close diff panel only for major public-API or core-invariant builds (or if `reviews` or the user asks), then deliver via `land.mjs`.

## Review, pivots and close

- **Review discipline:** fix every review and code-quality defect the slice introduced in-slice (except unreachable-code findings logged under `panel.md` reach rule). Pre-existing P0/P1 findings go to Open work (or main checkout's `docs/plans/artifacts/queue.tsv` with repro); lower priorities go to Open work with `owner:`. Run `pnpm exec oxlint --type-aware --format=default` on lintable files before any diff panel (`pnpm lint:fix` stays last code edit); panel fixes land a cheap regression test in the same round. `/pstack:correct` fixes land separately; behavior-preserving plans follow `refactoring.md` packet law; published package edits need `changeset`.
- **Phases & pivots:** when a phase lands, expand the next phase's paragraph in the same plan (no `architect`). A panel fix needing a new owner or stored shape pivots via `architect` + new plan (a second pivot stops per `long-runs.md`). Other approach changes revise the same plan (`verdict` first for Plate/Plite API/architecture or after two failed fixes on one mechanism).
- **Close (last landing only):** pass `node tooling/scripts/check-plate-feature.mjs <plan>` for feature-delivery plans, finish `## Close`, writing passes and any diff panel. Set a landed `Status:` (`work_kind: implementation` or `workflow` adopts `review_basis` Pursue) only when Close cites every `review_inputs` path, then pass `node tooling/scripts/review-ledger.mjs check <plan>` (follow `verdict.md` Never leave a verdict unwritten on refusal). Fold executed deltas into the topic file (or write `Public API`/`Main changes` for one-off plans), pass `node .agents/pstack/plan-page.mjs <plan> --check`, tick boxes and set final `Status:` in the final `land.mjs` commit, verify the ledger post-land, and reply per `pages.md`.
