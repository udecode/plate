# Plan

The plan is the deliverable; this playbook implements nothing.

- **Before** "Settle open questions by prototype before you write": pick API/architecture targets per Architecture decisions below. Public API changes run `pstack:architect` (reviews: api-plan), then a panel on the finished plan with challenge delta, and pass `best-api` and `.agents/playbooks/references/architecture.md` Hard cut gates.
- **Replace** "Write the plan file. Open with what changes": write `docs/plans/<date>-<slug>.md` (or `<issue>-<slug>.md`).
  - **Frontmatter (reviewed features):** `review_scopes` (every affected scope ID once, owning scope first; `Topic:` only outside ledger), `review_basis` (governing review file/legacy ID, else `[]`), `work_kind` (`implementation` if buildable, never `design`; or `research`/`workflow`/`verification`), `review_commit` (40-char SHA), `review_inputs` (tracked paths only), plus `Status:` and `Playbook: plan`.
  - **Architecture/API plans:** read `.agents/playbooks/references/architecture.md` in full, keep its decision ledger and applicable Page sections (`## What other editors do` first; topic files stay current until build close). Add Vision and worker-skill adoption rows (`plate-plugins`, `plate-ui`, `plate-docs`, `plate-next`); not ready while any worker teaches a rejected shape.
  - **Docs & templates:** publicly visible changes name affected `content/docs` pages and add a `plate-docs` step (example coverage audit, registered demos, Chinese twin, checks/preview). Copy `.agents/rules/plate-plugins/references/feature/template.md` for registry features and `.agents/rules/benchmark/templates/benchmark.md` for benchmarks (templates only where a checker parses them). Other plans include `Status:`, Outcome, Scope, Decisions, `- [ ]` Steps naming proofs, Proof, and `Defaults`/`Open questions` (`pages.md`).
  - **Proof & writing:** load `verify` (and `benchmark` for scale gates) via Skill tool before writing proofs/phase exits. Draft with `pstack:technical-writing` (how-to body, explanation/reference appendices) + one `unslop` pass.
- **Before** "Hand back the plan path and stop.": check against `architecture.md` Ready (or verify every step names its proof and zero decision-changing questions remain), resolve Start Gates at `HEAD` (never by another plan's `Status:`), load `verify`, and run each step's cheapest base control in a detached worktree, rewriting any step whose control disagrees.
- **In** "Hand back the plan path and stop.": name Build as execution playbook, record challenge delta and any reversed conversation claims. Plan panels attack whether each phase beats incumbent + earlier phases. Plan-only requests stop and reply per `pages.md`; Pursue/Autopilot routes continue into Build unless stopped ("go" accepts defaults and starts Build).

## Architecture decisions

State the ideal target before compatibility constrains it (compatibility/difficulty alter phase order, never target). Before `pstack:architect` or `arena` (or picking a target), read `pnpm kb <scope>` + `docs/research/sources/`; reuse fresh governing-verdict OSS research when it covers the design choices, otherwise run a `research` discovery pass (`pnpm kb discover` + source reads, promoted to `docs/research/sources/`) for any new public API, runtime mechanism or browser behavior (exempt pure deletions and internal wiring). `## What other editors do` must cite grounded external sources. Compare >=2 materially different targets (ownership, lifetime, data model, public call shape or runtime strategy) + no-new-artifact control. Public API changes run `pstack:architect` (reviews: api-plan), using an arena only when large or contested; other architecture plans run `pstack:architect` on pstack's trigger (reviews: api-plan) or compare in a table. Wait for the arena judge before build briefs; list losing-candidate cases before grafting; verify existing-code premises via `pstack:blast-radius` run-it; resolve must-answer probes before panel round 1; re-score after cuts; record challenge delta (`unchanged`, `improved`, `replaced`).

- **Removals:** every removed hook, adapter, owner or public noun names behavior, replacement or runtime-proven redundancy (same input on old and new path including read-only/authored policy; typecheck is not proof) and regression proof.
- **Phasing (max 3 phases):** each phase is independently valuable and ends keep/revert/quarantine (revert by step SHAs in one `land.mjs` commit, never `review.mjs --revert`). Phase 1 is the thinnest drivable path. Number steps continuously across phases; each step builds one provable unit and lands via `land.mjs` (or per-phase if specified). Order: phase acceptance proof -> user-reach step (`reach:` in `built:`) -> `plate-docs`.
- **Scope & budgets:** write steps/gates only for the next phase; later phases are one paragraph (template tables still span the feature and tag each row's closing phase). State claimed cohorts/peers/modes/engines, limits and appetite (`Defaults`). Run `benchmark` pre-acceptance and hardest-case stored-shape probes before picking the target; other budgets join their cohort's phase. Checkers, rigs and formal models are steps inside the phase they prove. Move non-essential work to Open work; answer "missed member X" by narrowing the claim. Log post-approval or post-arena edits as deviation rows for panel re-review.
