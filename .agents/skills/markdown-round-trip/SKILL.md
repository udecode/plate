# Markdown round trips and streamed parses

Handle $ARGUMENTS. `check`, or no argument, runs the gate bound. `deep` runs `--inline=3 --part=round-trip` and `--blocks=3` and compares their failures with Findings. `lower` runs `--lower` after a fix removes a known finding. `case <identity>` runs `--case=<identity>` to print one case's full detail. `update` brings the verification in line with changed code, as Coverage record says.

**The property.** Two rules hold for every source up to the bound. A source that `editor.api.markdown.parse` accepts serializes, and the serialized Markdown parses to the same document. A streamed parse with `parseSlice` that continues a previous preview of the same source gives the result a fresh `parseSlice` of that prefix gives, at every chunking. `docs/vision/plate.md` says streaming continues the prior result with `previous`, and that the Markdown runtime owns reuse and invalidation so consumers keep no parse cache. Reuse that changed the result would break that promise.

Three more rules judge the preview of each prefix of a streamed source. The text a preview shows starts the text of the next longer preview and of the final document, so text a reader saw never changes. A preview hides at most three arrived characters of the final text. A preview shows the text that a strict parse of the same prefix shows, block by block. It may leave out only a marker that a later character can still pair, or one backslash that ends the prefix. Today's codec breaks the first two rules on the sources that Findings counts. The baseline holds each of those sources once per finding, so a repair lowers a source's count and no change may raise one.

A fourth rule judges a preview that shows half-typed bold, italic or strikethrough as it will read once it closes. Such a preview hides the opening markers on a guess. When the stream shows that the run never closes, the markers come back, so the preview takes text back once. The rule files that take-back apart from the first rule's and allows a source as many as its final text leaves runs of markers open. It keeps no baseline. Today's codec guesses 8 times at the gate, each within its source's ceiling, so the rule finds nothing.

**The harm.** A round trip that changes the document loses content each time a user saves and reopens Markdown, or each time an AI reply goes through the codec. A streamed preview that differs from a fresh parse shows the user a document that changes when the stream ends, or a final document that differs from the source. A preview that takes text back makes an AI reply flicker while it streams. One that hides arrived text looks stalled, and one that drops or adds a character shows text the document never holds. Each Markdown fix before this check, such as e1fb01295e, covered only the cases someone had already found.

## What it checks

`packages/platejs/scripts/markdown-round-trip.ts` runs the real codec of `createTestEditor` in `packages/platejs/src/markdown/lib/__tests__/createTestEditor.tsx`, with `BaseIndentPlugin` given the indent targets of `apps/www/src/registry/components/editor/indent-static.tsx`. That editor has the plugins the Markdown stress cases use and `RawHtmlPlugin`, as the shipped kit does, so a parse marks the raw HTML that export writes back. Its remark plugins are math, GFM, the two CJK-friendly plugins and emoji. A block that the parse indents keeps its indent as it does in the shipped kit. The script checks the TypeScript code itself, not a model of it.

1. **Inline contents.** Every string of up to `--inline` tokens from 22 tokens: `a`, a space, `*`, `**`, `_`, a backtick, `~~`, `[a](b)`, `<br/>`, `<u>`, `</u>`, a backslash, a newline, `$`, `!`, `#`, `<`, `&`, `https://a.b`, `[^1]`, `|` and `:+1:`.
2. **Block forms.** 21 forms: paragraph, ATX heading, setext heading, quote, bullet, ordered and task items, table, fenced and indented code, math, div, callout, link reference, link definition, footnote definition, a lazy list item, thematic break, bold, link and a trailing break. 15 forms take every inline content. The setext heading, lazy list item, thematic break, bold, link and trailing break are fixed sources. Eight more fixed sources hold a URL that cannot stay a bare URL or that the parse keeps as text. `https://a.b.\na` and `https://a.b)\na` put a bare URL before a line break, and `<https://a.b'> a`, `<https://a.b"> a` and `<https://a.b;> a` end a URL in a character that GFM trims from a bare URL. The link plugin refuses the URL of `<https://a.b]> a`, so the parse keeps it as text. The parse also keeps `<div>www.a.b </div>` and `<div>a@b.cd </div>` as text. Each must parse again as text, though GFM finds an autolink literal in it. They run alone and join no sequence, because as block forms they would almost double the 902 round-trip sequences. Seven more fixed sources hold emphasis whose reading depends on the CJK plugins. `这是**重点。**然后`, `日本語の**「強調」**です`, `这是~~删除。~~文字`, `这是*斜体。*文字` and `한국어 **강조.**다음` end bold, strike or italic in punctuation beside a CJK letter, which CommonMark alone keeps as text. `这是\*\*重点。\*\*然后` escapes its asterisks and `a**"b"**c` holds no CJK character, so both parse as text and must parse again as text. No inline token holds a CJK character, so these seven are fixed sources, and they run alone for the reason the URL sources do. Forty-three more fixed sources are whole files whose first line is `---` or `+++`, or whose Markdown starts like one. 22 open with a YAML or TOML front matter block, such as `---\ntitle: Hello\ntags: [a, b]\n---\n\n# Body\n\nText.\n`, an empty block, a block after a byte order mark and a YAML block that closes on `...`. 21 must stay CommonMark, such as a `---` line over a heading, a list, a quote or a paragraph, as in `---\n\n# Introduction\n\nBody text.\n\n---\n\n# Next\n`, a block with no closing line, a block that holds only a comment, a lone surrogate or TOML table brackets that do not pair, and a file whose first line is blank. Each source names the block its document parse must store in `meta['markdown.frontmatter']`, or none. Only a document parse reads a front matter block, so these sources join no streamed sequence, and they run alone for the reason the URL sources do. `---\n---\n` is also CommonMark example 98, so the gate counts 42 of them. Thirty-four more fixed sources are README shapes from `packages/platejs/src/markdown/lib/RawHtmlPlugin.spec.ts`, such as the centered header `<p align="center">\n  <img src="logo.png" width="200">\n</p>\n\n# Project\n`, two HTML blocks a blank line apart, a comment block on its own line, in a quote and in a list item, and raw HTML beside an image, a break or a table cell. Each must parse again to the same document, its raw HTML marks included. They run alone for the reason the URL sources do. That spec's six other rows change on save with or without the plugin, so they wait for the Markdown writer's fix. Four, such as `<abbr> &#10;\n` and `- <abbr> <br>\n`, lose a space before a trailing break. `| a |\n| - |\n| x <!-- c --> |\n` loses the space at its cell's end, and `*a ![x](a.png)*<div> tail\n` reads back with emphasis's trailing space outside it. Two more forms leave a tag open that a count of tag names reads as closed, `<callout>` with `</callout>` in a code span and `</callout> <callout>`. They join only the streamed sequences. So do five forms whose half-typed syntax a preview shows before it closes: `*a*`, a code span, `~~a~~`, `![a](b)` and a table of two columns. The spec examples cover their round trips.
3. **Sequences.** Every list of up to `--blocks` forms, each holding `a`, joined by one or two newlines. The round trip runs 902 sequences at the gate and the stream 1,595. 47 more sources stream alone, because as block forms they would more than double the sequences. On 41 of them, such as `[a](b c) d`, `a**b**` and `**a\n\nb`, a repair of half-typed syntax can hide text that has arrived, take text back or change a block before the one still arriving. Two hold a line of no-break spaces, which is not blank, so it ends no paragraph and closes no fence. Four hold what a repair must keep. `**a \* b` holds an escaped marker and ``**a `b*c` d`` a marker inside a code span. `a &#xE000;` and `**a &#57344;` write the stand-in character U+E000 as a character reference. A repair may read an open paragraph again with that character after it. 28 more sources stream alone at every chunking, judged only by the two continuation rules, because each continued parse once differed from a fresh one. 21 hold an HTML block whose end the segment scan once read where the parse does not, such as `<pre></script>` or `<!-->`. One ends in a line of digits that the next chunk turns into a list marker. The rest hold a carriage return, a byte order mark, a half-typed tag after an unclosed one or diagnostics from two segments. The preview rules skip them, because their previews take back and hide text the way the sources Findings counts do.
4. **Prefix sources.** The `prefix` part puts each of seven inline forms, `**a**`, `*a*`, a code span, `~~a~~`, `[a](b)`, `![a](b)` and `a<br/>`, in each of the 15 block forms that take an inline content, such as a bold run in a table cell. The stream part already runs 7 of those 105 sources, so the part runs 98. It streams each one character at a time, as the `spec-stream` part does, not at every chunking.
5. **Spec examples.** Every example of CommonMark 0.31.2, read from the `commonmark-spec` package with each `→` as a tab, and the 41 examples of GFM 0.29.0.gfm.13 that CommonMark lacks, kept in `packages/platejs/scripts/markdown-round-trip-gfm.ts`. Each example runs the round trip at every bound. The `spec-stream` part also streams each one as `a\n\n<example>\n\na`, one character at a time. It continues the preview of each prefix to the next character, as a preview and as a strict parse, and compares each with a fresh parse of that prefix. The preview rules of item 8 read the same fresh previews. A finding's detail starts with its example, such as `CommonMark 0.31.2 example 218`. A preview rule's detail counts the characters of the streamed source, so a prefix there is 3 characters longer than the same prefix of the example.
6. **Round trip.** Each form with each inline content, each sequence and each spec example goes through parse, serialize and parse again under the default policy. A parse that refuses the source counts in the summary's `refused` and is not a failure. The script compares documents after `nameDocumentListIds`, because each parse gives every list a new id. A source that holds a line ending is also parsed with each one written as CRLF and then as CR, and each parse must give the document of the LF form. The documents these steps compare include their `meta`, so a front matter block must survive each of them. A front matter source also fails when its first parse stores another block than the one it names. A parse that drops part of the source drops it before any document exists, so the round trip also reads the code fences of the source and of the serialized Markdown with remark-parse and GFM alone. Each fence with a language or meta in the source must come back with both, unless the first parse reported a diagnostic. A fence with neither has nothing to lose. That parser also lacks the test editor's math and tag plugins, so it can read a callout's or a math block's body as such a fence.
7. **Streaming.** For each sequence, and each source that streams alone, the script parses every prefix fresh, as a preview (`lossPolicy: 'allow', partial: true`) and as a strict parse. Then it continues each reachable preview to its own prefix and every longer one, as a preview and as a strict parse, and compares each with the fresh result. A continuation reads its previous result through the runtime's checkpoint. Every stored state is a preview of a prefix of the same source, so the checkpoint's editor, formats, limits, policy and source test are the same for all of them, and each segment's nodes, diagnostics and last root follow from the segment ends. So the script records each checkpoint, merges previews whose segment ends match, and still covers every chunking without walking each chain. A failed preview merges with a checkpoint that has no segments, because neither reuses anything. When a preview has no recorded checkpoint, or a segment has no whole-number end, the script exits 2, because it can no longer read `markdownCheckpoints` in `packages/platejs/src/markdown/lib/internal/markdownConversion.ts`.
8. **Previews.** For each source of the stream, `spec-stream` and `prefix` parts, the script reads the fresh preview of every prefix, from one character to the whole source, and runs five rules on them. A spec example files its take-backs, hidden runs and lossless findings under rules of their own, so the spec examples have their own baseline entries and the counts of the other sources stay as they were. Its guesses past the ceiling go to `markdown-stream-guess`, as every source's do. `markdown-stream` holds a continued preview equal to the fresh one, so a finding of these rules shows at every chunking that delivers its prefixes.
   - **Visible text.** The first two rules read a preview as the text it shows. Inline children join directly and blocks join with a newline. A void or an image counts as one object character, an equation shows its formula, and trailing empty blocks drop, such as a padded empty table cell.
   - **Take-backs.** Each preview's text must start with the text of the preview one character shorter, and the strict parse of the whole source must start with the last preview's text. A preview that the parse refuses is a finding too. A take-back is excused when the prefix ends inside a link or footnote definition, as remark parses that prefix. The text taken back is then the definition's own, which the document never shows. The excuse holds only when the later preview shows the text of the strict parse of its own prefix, without the half-typed tag. So a take-back that the preview's closed copy makes next to a definition still counts. A footnote definition shows its body, so its excuse ends where the body starts. The summary counts these in `excused`, 216 at the gate.
   - **Guesses.** A take-back is a guess when three things hold, each on the visible text as the take-back rule compares it, with its line endings and object characters. The earlier preview is the strict parse of its own prefix with only `*`, `_`, `~` or backslash characters left out. That strict parse is the one the lossless rule reads, without the half-typed tag and under `lossPolicy: 'allow'`. The text that takes it back, the next preview's or the final document's, starts with that strict parse's text. So does the strict parse of the whole source without each link or footnote definition that starts after the earlier preview's prefix, because a definition that arrives later changes the blocks before it. Every other take-back stays a `markdown-stream-prefix` finding. A source's ceiling is the number of runs of one marker, `*`, `_` or `~`, that the strict parse of the whole source shows as plain text, outside code, formulas and objects. A source with more guesses than its ceiling gets one `markdown-stream-guess` finding per guess, and a source within its ceiling gets none.
   - **Hidden text.** A character of the final text has arrived once the prefix holds the source character it comes from, the latest equal one that keeps the text's order. A separator, an object or a character the source spells another way arrives with the character after it. The rule counts the arrived characters, other than whitespace and objects, that a preview does not show in order, and each code point counts as one character. So 👍 counts once, while an emoji built from several code points, such as 👍🏽, counts once for each. A run of previews in a row that each hide more than three is one finding. The rule skips a source whose strict parse is refused.
   - **Lossless text.** The script cuts the half-typed tag from the prefix with `trimIncompleteMarkdownTag`, as the preview does before it parses, and parses the rest without `partial` under `lossPolicy: 'allow'`, the preview's own policy. It skips a prefix whose preview or strict parse is refused. It reads both results as blocks, each block that holds text or is one object, in document order, and compares their text. A block of the preview must equal the strict parse's block with nothing added or changed, and it may leave out only two kinds of character. One is a `*`, `_` or `~` that the strict parse shows as text outside code and that the source wrote unescaped. To tell, the script parses the prefix again with every escaped marker and every character reference to a marker spelled as another character, and the marker must still show at the same place. The other is one unescaped backslash that ends both the prefix and the last block. The preview may hold one block fewer than the strict parse, the last, when every character of that block may be left out. A preview with more blocks fails, and so does one that shows more stand-in characters, U+E000, than the strict parse.
   - **`parse` and `parseInline`.** The script also parses each prefix with a partial `parse` and compares its blocks with the partial `parseSlice` of that prefix by block type, mark value and text. When `parse` stores a front matter block, `parseSlice` reads the prefix with that block blanked, because `parseSlice` reads no front matter. Where `parseSlice` shows one paragraph, a partial `parseInline` must show that paragraph's text and mark values, past leading whitespace.
9. **Rules.** A case records its first failure per rule, except under the last seven rules, which record every finding:
   - `markdown-fence-info`: a source whose code fence language or meta the serialized Markdown leaves out, though the parse reports nothing.
   - `markdown-front-matter`: a front matter source whose document parse stores another block than the one the check names for it.
   - `markdown-line-endings`: a source whose CRLF or CR line endings parse to another document than its LF line endings.
   - `markdown-round-trip`: a source whose parse, serialized and parsed again, gives another document.
   - `markdown-serialize`: a parsed document that does not serialize, or whose Markdown does not parse.
   - `markdown-stream`: a preview that continues an earlier preview and differs from a fresh preview.
   - `markdown-stream-final`: a strict parse that continues a preview and differs from a fresh strict parse.
   - `markdown-throws`: a parse or serialize that throws.
   - `markdown-stream-parse`: a partial `parse` or `parseInline` that shows other blocks, text or mark values than the partial `parseSlice` of the same prefix. It records the first such prefix of each source.
   - `markdown-stream-guess`: a guess, on a source with more guesses than its ceiling.
   - `markdown-stream-hidden`: a run of previews that each hide more than three arrived characters.
   - `markdown-stream-lossless`: a preview that shows other text than the strict parse of the same prefix, beyond a marker or a trailing backslash it may leave out.
   - `markdown-stream-prefix`: a preview that takes back text the preview before it showed, other than a guess, or that the parse refuses.
   - `markdown-spec-stream-hidden`: a `markdown-stream-hidden` finding on a streamed spec example.
   - `markdown-spec-stream-lossless`: a `markdown-stream-lossless` finding on a streamed spec example.
   - `markdown-spec-stream-prefix`: a `markdown-stream-prefix` finding on a streamed spec example.
10. It compares the findings with `packages/platejs/scripts/markdown-round-trip-baseline.json` through `tooling/scripts/finding-baseline.mjs`. Every finding is filed under `packages/platejs/src/markdown/lib`. An identity is the source alone, and the detail names the chunking, because which chain first reaches a state changes whenever the codec's segments do. Under the six hidden, lossless and prefix rules the baseline holds a source once per finding, and the detail names the prefix and the texts. So the baseline counts each source's take-backs, and a take-back that moves to another prefix keeps its entry. The guess and `markdown-stream-parse` rules have no baseline entry, so any finding of either fails the gate.

It compares 11,643 cases: 9,182 round trips, 679 of them spec examples that parse and 42 front matter sources, 1,670 streamed sources, 693 streamed spec examples and 98 prefix sources. On a loaded machine, it took 11 to 43 s and 141 to 170 CPU-s. It prints one JSON summary line, then each finding the baseline does not list. `pnpm check markdown-round-trip` runs the same step through the check runner, and Local CI runs it on next after each landing.
- `pnpm check markdown-round-trip --light` is the run a session makes before a diff panel, and it runs the whole step. The gate is its own light run, because its 90th-percentile time is under a minute. It took 74 s through the check runner at a load average near 125.
- The summary line also holds six counts that no rule limits. `guesses` counts every guess, within its source's ceiling or not. `closedTakeBacks` counts the `markdown-stream-prefix` take-backs, without the refused previews, of the closed sources, those with a ceiling of 0. It is 1,967 at the gate, down from 2,446 before the preview styled open runs, and a change to how it styles them must not raise it. `differingPreviews` counts the previews whose blocks hold other text than the strict parse of their own prefix, as the lossless rule reads both. It is 1,168 at the gate, each a preview that leaves out markers or a trailing backslash the strict parse shows. `unmarkingPreviews` counts the previews that show a character without a mark that the preview one character shorter showed it with. It reads a mark set to `undefined`, `null` or `false` as no mark. It is 182 at the gate. 60 of them, down from 178, are such as `**a* b*`, whose bold `a` turns italic when the `b` arrives. The other 122 take the raw HTML mark off a block while a closing tag arrives, as the preview of `<div>a` marks it and the preview of `<div>a</di` does not, because the block with the half-typed tag fails the safety check. To compare two previews, the script reads each character of the earlier one at its first place in the later one after the character before it, and skips a character the later one dropped. `closedCopiesRun` counts the fresh previews of the stream, `spec-stream` and `prefix` parts for which the partial parse read a closed copy of its open tail. `closedCopiesKept` counts those whose text differs from the same preview parsed again with each copy's tree emptied. An empty copy makes the preview show the received parse. They are 8,650 and 1,966 at the gate. With `RawHtmlPlugin`, import also reads the Markdown that export writes, through the same remark plugins, and the probe counts that read as a copy too, so `closedCopiesRun` rose from 5,226 when the test editor installed the plugin. The script sees and empties the copies through a remark plugin it adds to the test editor. The other four counts and `excused` read the stream and `prefix` parts alone, so the spec examples' preview rules left every count as it was.
- `--inline` and `--blocks` raise one part of the bound, and `--part=round-trip`, `--part=stream`, `--part=spec-stream` or `--part=prefix` runs one part. `--inline=3 --part=round-trip` compares 166,999 cases in 439 CPU-s on a loaded machine, and `--blocks=3` compares 136,237 cases in 4,350 CPU-s on a loaded machine. Its stream half, `--blocks=3 --part=stream`, holds 89,338 of them. A bound other than the gate's, `--part` or `--case` skips the baseline and exits 1 on any failure.
- `--case='<identity or part of one>'` prints the full diff and stack of each failure whose identity contains it, such as `--case='"<br/><br/>"'`.
- `bun test ./packages/platejs/scripts/markdown-round-trip-previews.spec.ts` runs the cases that say which take-back is a guess. The `markdown-round-trip` step of `pnpm check` runs it after the gate, because no test suite collects a spec under `packages/platejs/scripts/`.
- `--jobs=<n>` sets the number of worker processes. It defaults to `CHECK_CORES`, the cores the check runner reserves for the step, and otherwise to the machine's cores up to 16. Findings do not depend on it.
- Exit 0 is a pass and exit 1 a finding. Exit 2 is a bad flag, a crashed worker or a checkpoint the script cannot read. A gate run that excuses no take-back inside a definition exits 2 as well, because `completesDefinition` in `packages/platejs/scripts/markdown-round-trip-previews.ts` then excuses nothing, so either it broke or the codec no longer needs it. At the gate the run also fails when it compares other than 11,643 cases, the `GATE_CASES` constant, so a change that makes parse refuse more sources cannot shrink the gate while the baseline still matches. Update the constant only with the reason the count moved.
- After a fix removes a known finding, the gate fails until you run `pnpm check:markdown-round-trip --lower`. The baseline never grows past the base commit's copy. `--init` seeds only a rule the baseline lacks and never the guess rule. `--lower` and `--init` write nothing when the case count misses `GATE_CASES` or a source passes its guess ceiling.

## Read a failure

A finding prints its rule, identity and the first line of its detail:

```text
markdown-round-trip "<br/><br/>"
  serialized "<br />\n<br />\n"; the parse again differs at .children.0.children.0.text: "\n\n\n", not "\n\n"

markdown-stream "1. a\na\n\n1. a"
  chunked at 1,9,10, the continued result differs at .slice.content.1.listId: "b", not "a"
```

The first is a known finding, two breaks in a row that come back as three line endings. The second is what the gate prints when `findMarkdownSegmentBoundaries` stops keeping a list open, as What a pass proves says. The preview of the first 9 characters ends in `1`, which is not a list marker yet. So the segment scanner commits a boundary after the lazy line, and the continuation splits one list in two. Run `--case` on the identity for the full documents.

The preview rules name the prefix and the texts:

```text
markdown-stream-prefix "**a**"
  the preview of the first 4 characters shows "*a" after "**a"

markdown-stream-hidden "<callout>\n\n`</callout>`"
  the previews of the first 16 to 21 characters hide up to 9 arrived characters of "</callout>"; at 16 the preview shows "`"

markdown-stream-lossless "**a `b*c` d"
  the preview of the first 9 characters shows "**a bc" in block 1, not "**a b*c", as the strict parse of "**a `b*c`" shows

markdown-stream-guess "**a\n\nb"
  the strict parse of the whole source shows "**a\nb" after "a\nb", one of 2 guesses against a ceiling of 1
```

The first two are known findings. In the first, the preview shows the opening stars as text and takes one back when the first closing star arrives. The third is what the gate prints when a partial parse drops a star inside a code span. The fourth is what it prints when previews hide the stars of `**a` twice and the stream shows them again twice, though the final text leaves one run open. The run prints both guesses. A source that the baseline lists prints only its identity when it gains a finding, as `markdown-stream-prefix packages/platejs/src/markdown/lib: "\"a**b**\""`, because the baseline holds fewer entries for that source than the run found. Run `--case` on the source to print each of its findings, and compare them with the same run on the base commit.

Tell a real bug from a modeling error before you change code:

- **Real bug.** A user can write the source, or a stream can deliver that chunking, and the codec breaks a rule. Fix the codec, then run `--lower`.
- **A take-back that moved.** A repair that shows half-typed syntax differently can trade one take-back for another on the same source. The count decides. A source may never gain a finding, and a change that lowers one source's count while it raises another's still fails.
- **Modeling error.** The script compares something the codec does not promise, such as a list id. Fix the script with the reason.
- **Intended change.** A change to what the codec keeps, such as a new syntax it refuses, changes the rule too. Change the rule and `docs/vision/plate.md` together. Never weaken a rule or add a baseline entry to get green.

## Findings

The gate finds 2,577: 17 `markdown-round-trip`, 1 `markdown-throws`, 1,981 `markdown-stream-prefix`, 72 `markdown-stream-hidden`, 471 `markdown-spec-stream-prefix` and 35 `markdown-spec-stream-hidden`. Installing `RawHtmlPlugin` in the test editor cleared 51: 42 round trips of a div that holds an emoji shortcode, which now writes back as HTML, and 9 preview entries on HTML comments, HTML tables and a source of two divs. The first two numbered 157 at `fix(markdown): round-trip every CommonMark and GFM spec example`. Measured on 7bc3175013, the lockfile's move from mdast-util-to-markdown 2.1.2 to 2.2.3 cleared 79 round-trip entries, 42 headings and 37 callouts whose text starts or ends with a break. The CJK plugins' writer cleared 6 more, a break before a bare URL in a paragraph, a quote, a list item or a footnote definition. Read by their examples, the round-trip entries that remain fall into these classes. No log proves that each class has a single cause:

- **An emoji shortcode inside a div that fails the safety check.** `<div>:+1:<</div>` comes back with the emoji glyph and escaped tags.
- **A bare URL before a shortcode.** `https://a.b:+1:` comes back as text that holds the emoji glyph in place of the shortcode.
- **A bare URL before a trailing break.** `# https://a.b<br/>` serializes the break as `&#xA;`, which the parse again reads into the URL, and so does a callout that holds `https://a.b<br/>`.
- **A break before a bare URL in a callout.** `<callout>\n<br/>https://a.b\n</callout>` serializes the break as a space.
- **An unclosed `<u>`.** The serializer closes it around the text after it, as in `[<u> ]` and a table cell that holds `<u> `.

The other entry has one cause:

- **A footnote definition in a quote.** `> [^1]:+1:` throws `Markdown node mapping "blockquote" expected block content.` during serialize. 1 `markdown-throws` entry.

## What it does not cover

- HTML round trips and the HTML codec.
- Streaming of inline contents at every chunking. The stream part runs only the block sequences, where each form holds `a`, and the sources that stream alone. The `spec-stream` and `prefix` parts continue each source one character at a time, so other chunkings of inline syntax go unchecked.
- A partial `parse` or `parseInline` in an editor unlike the test editor, such as one with `ElementIdPlugin` or a custom paragraph decoder. `markdown-stream-parse` compares the three entry points only in the test editor, and `markdownOpenTail.spec.ts` tests the closed copy in those editors.
- Marks and block types in a preview. The lossless rule compares each block's text, so a preview that shows the right characters with a wrong mark, or in a block of another type, passes it. `markdown-stream` still compares whole documents, continued against fresh.
- A preview whose strict parse is refused under `lossPolicy: 'allow'`. The lossless rule skips that prefix, and the prefix rule still reads the preview.
- Hidden whitespace. The hidden rule counts no space, line ending or object, and it allows three hidden characters at every prefix.
- A take-back inside a link or footnote definition, which the prefix rule excuses.
- A guess that the repair should never have made. The ceiling counts the runs a source leaves open, so a guess on `2*3` costs what a guess that a blank line ends costs.
- A mark that a preview takes off text the preview before showed with it. The summary counts those previews in `unmarkingPreviews`, and no rule limits them.
- A spec example's expected HTML. The check compares Plate documents, so a parse that differs from the spec's HTML still passes when it round-trips.
- Sources longer than the bound, other than the spec examples, and containers nested inside one another.
- Plugins outside the test editor and the kit's indent, MDX components and custom rules.
- An editor without `RawHtmlPlugin`. The test editor installs it, so the gate never reads raw HTML as the plain text such an editor keeps. The specs that pass `{ rawHtml: false }` to `createTestEditor`, such as `markdownContinuation.spec.ts`, run that editor.
- A serialized form that is not the source the user wrote. The check compares documents, and of the Markdown text only each fence's info string.
- What a CJK source parses to. An editor without the CJK plugins reads the CJK sources as text and still round-trips them, so `packages/platejs/src/markdown/lib/cjkEmphasis.spec.ts` asserts their marks and exported bytes.
- A round trip of the two unbalanced tag forms. Their round trips find one bug: under CR-only line endings, `<callout>\r    a` loses its indented text. That bug is in the `markdown` subject's Open work. A round trip of these forms joins the gate once that bug is fixed.
- A second failure on a known source under the first eight rules. A case records its first failure per rule, and its identity names only the source, so a known source that starts to fail in a new way, or on another chunking, still matches its baseline entry. The six hidden, lossless and prefix rules count a source's findings, so there a known source that trades one finding for another still matches.
- Front matter in a streamed parse. `parseSlice` reads no front matter block, so the front matter sources join no streamed sequence.
- An app's `remark-frontmatter` in a streamed parse. With it, or any remark plugin that adds block syntax other than a math block, a GFM table and a GFM footnote definition, a continued parse reads the whole source. The test editor adds no such plugin, so the gate never runs that whole read, and `markdownContinuation.spec.ts` covers it.
- Whether a front matter block holds valid YAML or TOML. The codec stores the block's text without reading its settings, and the check compares that text.
- A parse that refuses a source under the default policy. Such a source counts in `refused` and gets no round trip.
- The editor surface: pasting, AI streaming into a document, and the browser.
