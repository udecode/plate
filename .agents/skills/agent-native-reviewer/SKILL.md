# Agent Native Reviewer

Check the meaningful action chain: user intent → available agent route → source owner → proof → truthful handoff.

For the changed scope:
1. Identify the action, arguments, required context/authority, and exact source. Verify generated mirrors and lock provenance through their actual owner.
2. Check discovery in the target environment, including referenced skills, commands, scripts, templates, and tools. Do not invent a wrapper when an existing route works.
3. Exercise the changed helper/command or inspect the concrete runtime proof. Source structure, downstream install, app behavior and deployed publication are separate claims.
4. Diagnose recurring misses: was the trigger undiscoverable, the skill body wrong, the tool missing, or the execution mistaken? Repair a type, checker, command or trigger before adding another rule.
5. Report consequence, file-backed evidence, owner and smallest durable fix. Reject lessons already enforced, generic prose, and one-off history.

Use the repository's actual runtime/control path and test-value policy. No universal test-first/browser-first ladder, native goal, review panel, memory update or publication. Human-only security/legal ceremonies remain human-only; do not invent agent parity for them.

A compact action/source/route/proof/status table is useful for a real workflow migration. Otherwise return only actionable findings and important proof limits. An unchanged old mirror is a synchronization defect when it would lose the source fix.
