### Refactoring

**You own the contract. The structure changes; the behavior does not.** For "refactor", "rename", "extract", "inline", "dedupe", "restructure", "move this module", "tidy up this area". Distinct from Feature, which adds behavior, and Bug fix, which corrects it.

A refactor that smuggles in a behavior change loses its safety net. If the cleanup reveals a missing feature or a real bug, make the scope decision explicit and verify each behavior separately. A redesign is allowed, but name it and route to Feature. Use **figure-it-out** when no existing playbook or accepted plan fits the work; a large caller set alone does not require another planning method.

1. Pin the behavior contract first. Use **how** when the affected subsystem, owner, or contract is unclear. Identify the existing characterization test, snapshot, equivalence harness, or recorded operation that captures current behavior before any structure moves. Follow the project's testing policy before adding a missing proof. The pin makes "refactor" a checkable claim (**principle-prove-it-works**); type check and lint alone do not prove runtime equivalence.
2. Name the structure the code is missing per **principle-model-the-domain**: a state machine over scattered booleans, a table or registry over spread-out branching, a typed model over repeated shape assumptions, a reducer over ad hoc mutations. Boring code stays when the shape is already clear and local; the reshape must delete branches or invalid states, not add indirection.
3. Name the target shape. State what the module layout, types, and call graph should be if built today (**principle-foundational-thinking**, **principle-redesign-from-first-principles**). Use **architect** while consequential choices about public contract, ownership, lifetime, or data model remain unresolved. Reuse the accepted target; crossing a function boundary alone does not require competing designs.
4. Subtract before you add. Delete dead weight, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape (**principle-subtract-before-you-add**). The smallest change that reaches the target shape ships (**principle-laziness-protocol**). A speculative cleanup that "might help" gets reverted, not left to ride.
5. Move in small behavior-preserving steps, each keeping the pin green. For API reshapes, migrate every caller and delete the old API in the same wave (**principle-migrate-callers-then-delete-legacy-apis**). No compatibility shims, no parallel old-and-new paths. Spot-check every rename against the actual files; renames silently miss usages in strings, prose, and back-references. Implement directly or delegate permitted independent mechanical edits using your configured available refactoring model (default `inherit-parent`) with a specific scope (file paths, names being moved, behavior to hold); inspect the diff yourself.
6. Prove behavior is unchanged on the real artifact, not "it compiles" (**principle-prove-it-works**). For larger reshapes, run an equivalence check: a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or a smoke run on the matching surface via the relevant control skill. Own the verification yourself; do not trust a delegate's "looks good" summary.
7. Confirm the change earns its place. The success measure is reduced reader load (**principle-minimize-reader-load**): fewer layers between question and answer, less hidden state, fewer indirections without a second consumer. If the diff does not lower reader load somewhere, revert it.
8. Keep each behavior-preserving slice green before the next (**sequence-verifiable-units**). When commits are authorized, follow the user's staging and history policy; an independent subtraction, reshape, or follow-on cleanup can form a useful unit without rewriting existing history. Run **Opening a PR** only when publication is authorized; otherwise finish the local handoff.

**Reply:** the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta, what shipped and what got reverted. No new behavior.
