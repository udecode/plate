# Codex runtime adapter

Select methods by the unresolved decision, not by task size or a keyword. Known-owner changes and accepted plans use direct implementation plus affected proof. How resolves unclear source flow; Architect/Arena resolve consequential unsettled contracts or designs; Interrogate addresses a contested design. Explicit invocations retain their requested scope. Read a selected method, playbook or leaf in full once, preserving its procedures, examples and prompts; do not recursively load every linked method.

These selection rules also govern broad triggers inside preserved upstream playbooks. Mentioning a principle is not an invocation. Reuse source-grounded maps, decisions and already-read methods until a relevant source or assumption changes. Recovery reads the existing checkpoint and affected owners, without restarting intake.

The active user and runtime instructions govern authority and tools. Repo-specific scope, testing, generated-source ownership, runtime control, and delivery rules belong to the project. Preserve them without removing the pstack method. A mode does not create a second Task owner.

## Tool mapping

| Upstream instruction | Codex execution |
| --- | --- |
| Read, Grep, Glob, Shell | Read through the available filesystem/exec tool; use bounded rg searches and exact source paths. |
| TodoWrite / todolist | Write the selected steps into the existing task plan/checklist, preserving step order and explicit skip reasons. A file plan is not a native goal. |
| AskQuestion | Use the available user-input tool for missing preferences or constraints. Continue independent authorized work while waiting. Do not ask the user to answer an observable fact. |
| Task / generalPurpose / poteto-agent | When delegation is permitted, use the native collaboration spawn tool for a bounded task. Put the appropriate full worker prompt, source pointers, scope, and expected artifact in its message. There is no Cursor subagent_type parameter. |
| Comment Sicko | Use the full [reviewer prompt](agents/comment-sicko.md) for the requested comment review. The parent verifies findings and applies authorized edits. |
| poteto-agent wrapper | Use the [worker instructions](agents/poteto-agent.md), with the same runtime mapping. It is a prompt, not a registered Codex agent type. |
| run_in_background | Start through the native spawn mechanism; it already returns control. Collect actual results before claiming completion. |
| wait / resume / interrupt | Use native wait, follow-up, message, and interrupt tools with returned IDs. Respect current tool limits. Do not invent IDs or lose the scope during resume. |
| readonly: false to obtain MCP access | Codex has no equivalent flag. State permitted operations in the worker's task; a research worker remains read-only even if tools can write. |
| create-skill | Use the installed Codex skill-creator. Edit the real source and regenerate any installed mirrors. |
| control-ui / control-cli | Read the owning project's verification/control skill. Use actual browser, native app, PTY, or CLI tools. A screenshot, source check, or mock is not automatically equivalent to the requested proof. |
| Cursor /loop | Continue the current authorized task. Native goals follow a direct or applicable standing user request through Autogoal; scheduled continuation requires its own explicit request. Preserve each tool's contract. |
| Agent store | Use the current task's durable plan and artifact directory. A project supervisor keeps its existing canonical run store. |

Resolve paths relative to the loaded skill directory, not a guessed installation. An example beginning pstack/skills refers to the matching installed skill. Do not install Cursor tooling to make an example runnable. Missing control or source access is a stated capability limit, not permission to invent proof.

## Models and independent work

Read the project's .agents/pstack-models.md if present. Setup Pstack owns that optional role configuration. Without an explicit configured choice, inherit the parent model and omit model overrides; upstream provider/model strings are examples, not entitled models.

Preserve role distinctions and independent prompts. A panel list specifies separate workers, not repeated self-review. Use only models and reasoning options actually exposed by the current spawn tool. Do not guess entitlement or silently substitute a different model. A configured choice must still pass current availability checks.

Different variants of one provider's model are not evidence of different provider/model-family review. When a method requires a different family and none is callable, keep the requirement visible and report the unavailable independent-family check. Do the remaining useful source/artifact checks, but never label the gap passed.

Respect the current concurrency ceiling. Queue work in bounded batches; do not drop features or candidate arms to fit the first batch. Each worker gets a distinct question or unit and clear write boundaries. Use isolated scratch directories for independent prototypes when that suffices. Creating another task or checkout follows the active user's instructions and tool contract. If delegation is unavailable or prohibited, retain the same questions and source coverage sequentially and report that independence was not achieved.

## Scope and authority

Proceed with authorized reversible work. Existing user authorization survives plan changes, compaction, and retry limits. Ask only for an actual missing decision, access, or authority.

Team chat, email, customer messages, tracker submissions, publication, deployments, force-pushes, and destructive cleanup obey the active request. References to automatic posting, shipping, or skill PRs do not create authority. A useful local result is not a published result.

A named audit diagnoses and records findings; it does not silently grant product repair. A skill maintainer edits owned sources only. Protected vendor/package skills and generated mirrors remain untouched. Use the owning generator or targeted installer.

Use one lifecycle. In a project with Task, Task owns intake, scope, implementation, and delivery. Poteto Mode and Figure It Out supply the engineering method. In a project with Auto, Auto owns its existing typed multi-unit supervision. Do not install the upstream orch store as a parallel controller.

Native goal tools have their own request, status, and budget rules. Honor a direct or applicable standing user goal request without asking again; measurable acceptance alone supplies no authority. For long work, preserve applicable obligations once in the existing plan under Autogoal's checklist-retention method; linked ledgers keep their own detailed rows. A method index does not make every possible leaf applicable. Short work checks its requirements directly. Do not mark a goal complete or blocked merely to stop working. An automatic compaction is not a pause request.
