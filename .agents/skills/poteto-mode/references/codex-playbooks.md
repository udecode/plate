## PR status and delivery

Use gh and the existing project's PR/status tools. The upstream watch-pr helper is not installed. Inspect the actual head/base and fresh CI/check runs; separate stale-base failures, transport failures, and real candidate defects before retrying.

Shipping preserves exact-candidate verification and bottom-up contiguous stack order. Follow current user Git scope and publication authority. A same patch ID on a changed base is not proof of unchanged runtime behavior.

Opening a PR obeys the active user's staging and checkout instructions. Do not automatically create a worktree, isolate only selected files, force-push, reset, or stash to imitate an upstream example. Use the actual project PR-closeout review owner and its existing budget.
