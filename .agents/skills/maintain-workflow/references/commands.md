# Command execution

Start from the known owner or artifact. Discover filenames before printing broad matches, exclude generated output unless it is the target, and write large evidence sets to a scoped artifact. A truncated dump is not a full source read.

Query large JSON manifests by the needed keys instead of printing embedded diffs, payloads or encoded media. Use explicit file paths for a single-file test; with Bun, prefix the path with `./` so it is a file rather than a repository-wide name filter. Check the actual matched files before treating failures as product regressions. Do not widen the run to diagnose an incorrect command target.

Use structured arguments where available. Shell commands are code: use single-quoted literal searches or `rg -F` for Markdown, backticks and dollar signs. JSON encoding is not shell escaping. Read an artifact's schema/header before querying fields. Stop and correct a failed command shape instead of trying broader variants.

Separate independent reads from dependent mutations. Reuse the actual package/runtime runner and its preparation contract; do not invent an alternate wrapper or unconditional rebuild. Preserve failure output and verify the corrected command once.

For provider setup, inspect the current environment loader and existing authorized source settings before opening login flows or proposing new accounts/resources. Match needed variable names and aliases, then make the smallest read-only native request to verify the account, resource and capability. Map only needed settings into the destination; preserve its database, app/auth identity and unrelated values. Existing credentials establish access, not wider write authority. Reuse authorized resources with scoped object/key ownership where sufficient; create separate infrastructure only for a demonstrated requirement. Keep values out of logs and plans, and report the actual failed operation when access remains blocked.
