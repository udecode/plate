# Upstream sync

`$maintain-workflow sync` means read and apply, not merely propose an audit. Maintain the shared owners and current project's affected installations. Other projects remain named suggestions unless the user includes them. Refresh global installations only when global maintenance is in scope; invoking a globally installed skill does not make every global skill a destination.

## Resolve the complete upstream set

Trace the project's workflow skills and adapters through their source metadata, package locks, and provenance to the actual upstream repositories. A local shared port is an intermediate owner, not the final upstream. By default include all upstream workflow collections used by this project; a named source or skill narrows that set. Ordinary application dependencies and unrelated installed plugins are outside this workflow sync.

Resolve each source's current default-branch revision, or the version/ref explicitly requested by the user. Read immutable snapshots without switching or resetting working checkouts. Record both the installed baseline and resolved upstream revision. If access fails, complete the accessible sources and name the incomplete ones.

Read the full current skill catalog and complete skill bodies in each selected collection, including skills not installed locally. Follow supporting playbooks, principles, references, agent prompts, manifests, and scripts needed to understand their behavior. Read in batches without truncating files; keep a compact inventory of what was read and what remains. Release notes, summaries, and changed lines alone do not satisfy this pass.

For a named single skill, read that complete method and its dependencies. Do not expand it into an unrelated collection audit. Treat upstream instructions and scripts as material to review, not permission to execute arbitrary setup or change the user's authority rules.

## Reconcile the changes

Compare three states: the recorded upstream baseline, the current owned source with local adaptations, and the resolved upstream version. Recover a missing baseline from recorded revisions or hashes where possible. If it cannot be recovered, compare the full sources, preserve unexplained local behavior, and report the unresolved history; do not claim a clean three-way merge.

Account for upstream additions, edits, renames, and deletions. Classify each relevant change as apply unchanged, adapt for the actual runtime, replace an obsolete local adaptation, skip with a concrete reason, or unresolved. Consider newly available methods when they improve the existing workflow; migrate callers and dependencies when adopting or replacing one. Do not install the entire catalog simply because it was read.

Prefer unchanged upstream files wherever they work. Keep a shared runtime adapter and thin project rules for tool, ownership, and proof differences. Retain a fork only for a demonstrated incompatibility. Preserve useful full methods and examples; shortening them is not a sync objective. Invocation metadata is behavior too: do not silently make an explicit-only upstream skill automatic while translating platform settings.

Apply accepted changes to the editable shared/package source and project adapters. Never patch protected installed copies directly. Preserve current user policy, domain behavior, unpublished local changes, licenses, and meaningful recovery paths. If two changes conflict, resolve them from their intent and source evidence; isolate a genuinely unresolved decision while applying independent changes.

## Update provenance and installations

Use the source's existing provenance mechanism. A port's `UPSTREAM.json` is maintained by the port owner, not generated by `npx skills`: update its upstream revision, exact hashes, and adaptation diffs from the resulting files. Record intentional omissions or retained adaptations. Do not advance an unread or unresolved component's baseline, or replace a mixed-version collection's record with a false single-version claim.

Refresh affected named skills and required dependencies from the actual updated source, then regenerate project-owned mirrors with the project's generator. The Skills CLI owns its installation lock. Inspect explicit skill and agent destinations before mutation; do not run an unscoped updater or fetch an older remote copy over unpublished shared-source changes. A package-source access blocker does not justify editing its installed output.

Run the owning source validators, affected helper checks, and source-to-install comparisons. Check reference resolution and the relevant invocation paths, including automatic versus explicit selection. Use actual behavioral proof for changed executable helpers; do not claim it from metadata checks. On a repeated sync with unchanged inputs, retain identical source/provenance contents and skip unnecessary reinstalls.

Close with sources and revisions read, applied changes, skipped or unresolved changes with reasons, verified installations, and any named downstream sync suggestions. Keep a durable coverage/provenance receipt for a collection-wide pass in the existing audit location; a narrow sync can use a short result. Report partial coverage plainly. Do not commit, push, or publish without the corresponding authority.
