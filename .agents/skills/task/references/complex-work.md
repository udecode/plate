# Complex decisions

Use this for architecture, framework comparison, migration or a substantial
proposal. Task's workflow owns the lifecycle. Poteto supplies the full matched
engineering method; Technical Writing shapes the decision document.

State the decision, existing owner, hard laws, alternatives and evidence that
would change the recommendation. Reuse the active plan. The `task-complex`
template and relevant packs are optional aids, not another controller.

## Choose the technical owner

- Public call shape: Best API before target lock, followed by Plate Plan or
  Plite Plan for adoption. Test deletion, merge, inline and reuse of the owner
  above each proposed abstraction before local improvement.
- Broad source cleanup: Architecture Cleanup supplies the ranked cuts.
- Editor-framework comparison: Editor Audit supplies the source-accounted
  comparison and rejected machinery. For other frameworks inspect local
  clones, then official sources for unsettled version-sensitive facts.
- Performance: Benchmark establishes comparable source/workload identity,
  causal ownership, correctness and actual metrics before an architecture
  conclusion. Benchmark's review method supplies the repeated-work and degradation lens.
- Spec or proposal review: inspect coherence, feasibility, scope, product fit,
  strongest objection and proof gaps. Use Grill With Docs only for the requested
  adversarial document pass. An unresolved observable fact needs evidence;
  a missing product decision may need the user.

## Scale-sensitive targets

When retaining or changing caches, indexes, projections, stores, subscriptions,
schedulers, geometry or repeated-unit fan-out, run Benchmark's embedded
pre-acceptance probe against the current owner and a disposable target when
needed. Freeze the workload, budget, source identity and correctness oracle.
Asymptotics, a design score and a promise to measure later cannot accept the
target. An inconclusive probe leaves the target provisional.

An accepted migration names adoption order, operational/ecosystem impact,
rollback, blast radius and proof. Compatibility affects adoption order, not
the ideal target. Continue authorized implementation through the owning plan
without a new checkpoint approval. Return scale claims to Benchmark for the
exact production-path rerun.

Report the recommendation, evidence, rejected material alternatives, what
would change it and remaining uncertainty. Ordinary docs and small refactors
do not load this method.
