# External methods in Plate

Read the full selected external skill. This reference maps its generic
defaults to current Plate owners; it does not shorten or replace the method.
The Plate workflow governs authority, native goals, review budget, current
checkout and proof claims. Installed vendor files remain protected.

## Pstack and Codex

Poteto Mode's Codex adapter owns tool and model mapping. Use actual available
capabilities and disclose when a requested independent model family is
unavailable. Full playbooks, examples, worker prompts, references and all 21
principles remain installed. Apply them to the concrete engineering decision.

Create Verification Skill targets the owned `.agents/rules/verify-plate.mdc`
and its resources. Maintain Verification Skill uses that source and the
existing package, example-registry, CLI and proof inventories. Runtime
verification repairs the verifier within scope; product fixes need their own
Task authority. Neither creates a competing feature map.

No Comments must preserve public JSDoc and intentional `@ts-expect-error`
assertions that prove invalid public calls are rejected. Remove stale or
redundant prose without deleting meaningful negative type proofs. TypeScript
Best Practices supplements the installed advanced-type reference and Plate's
descriptor-derived inference law; it does not replace those owners.

Show Me Your Work keeps long-running decisions reviewable. Show Me is a visual
explanation tool, while Walkthrough presents final visual evidence. These jobs
are distinct; a decision trail is not a reason to replay a verified browser
journey. Technical Writing contains the prose-editing method, pattern catalog and
preservation checks. TDD stays with its existing shared owner and Plate Testing's value gate.

## Protected package references

- Diagnosing Bugs supplies its complete hypothesis and causal diagnosis loop.
  For live UI, use Verify Plate's permitted Browser/Chrome controls; an absent
  `improve-codebase-architecture` tool maps to Architecture Cleanup when code
  shape actually needs attention. Do not invent unavailable browser tools.
- Grill with Docs resolves uncertainty against sources. Durable Plate law
  remains in `VISION.md`, scoped `docs/vision/` and the owning plan; do not
  create parallel CONTEXT/ADR owners merely because the generic recipe names
  them. Existing execution authorization remains valid after a decision.
- Prototype may build a disposable experiment to answer an unresolved
  question. Keep it in the authorized scratch or proof surface; a generic
  example of route variants does not authorize a new product API or checkout.
- Vercel React and composition guidance can improve implementation within
  Plate UI's component, prop and render-function contracts. Generic compound
  contexts never justify an overlapping public component model.
- Shadcn and TanStack Virtual retain their package-specific mechanics. Sync
  Shadcn, Plate UI and Benchmark own local adoption, composition and measured
  performance decisions respectively.

## Shared owners and optional tools

Agent Native Reviewer checks source discovery, runtime capability and proof
parity. Resolve PR Feedback keeps the full feedback method, but external
replies/resolutions need explicit message authority and its final review uses
Task's existing budget. Video Transcripts and Walkthrough preserve actual
source evidence and identify capability gaps.

Orchestrator is an explicitly selected durable-task coordination tool. Use its
current native task tools and preserve explicit task-creation, checkout and
publication authority. Plate does not inherit another project's main-branch
or mandatory-worktree policy. Autogoal manages a native goal requested directly
or through the user's standing long-running-work instruction; reuse Task's plan.
