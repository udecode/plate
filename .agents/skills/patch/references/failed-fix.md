# Failed Claimed Fix

Load this reference when a claimed candidate fails exact replay/final verification
or receives a fresh reporter contradiction. It applies to one ordinary report
as well as an explicit corpus. Reuse the current Patch/Task plan or handoff; do
not require a corpus template, full oracle matrix, receipt helper or delegation
unless the active task already uses that schema. Record the applicable fields
below once. In corpus mode, use the existing `Failed fix history`, reporter
inventory and architecture rows.

A failed fix is not the expected red test. It is an attempted fix already
claimed `candidate-local`, `kept`, or `completed` that fails exact replay/final
verification, or a fresh reporter contradiction.

The reporter assertion must execute before a process failure becomes a product
failed-fix attempt. A pre-assertion proof-host failure requires repair at that
host's owner, then restarts the same product attempt.

Record one explicit failure kind: `reporter-contradiction`, `exact-replay`, or
`final-verification`. Every failed fix preserves `base-acceptance`, required or
explicitly superseded with authority. Only a reporter contradiction requires a
`latest-reporter-delta`; exact replay and final verification failures have no
reporter delta unless one actually exists. In corpus mode these remain the
validator’s evidence rows; otherwise record them in the existing case evidence.

An `exact-replay` or `final-verification` failure must record
`diagnostic: <unchanged-bytes phase/result>` in its resume state before another
Patch. Run the actual failing assertion on frozen product bytes and name
whether product nondeterminism, interaction delivery, host readiness, or oracle
sampling caused the red. Repeated green runs without a phase/result diagnostic
cannot resume product edits.

When the failure involves native selection, focus state, popup/toolbar focus,
mounted keyboard/semantic commands, or an exact route, load the matching
[failed native diagnostics](../../verify-plate/references/regression-oracles.md#failed-native-diagnostics)
and its referenced domain section before another product attempt. Preserve the
required traces/tags in the resume evidence; domain proof does not widen the
single-report workflow into corpus work.

Before another product attempt:

1. Revoke the prior green, receipt, local completion, and public completion
   authority. Record the failure in current case evidence (`Failed fix history`
   in corpus mode). Public corrections remain with the authorized public
   coordinator; this method supplies no external mutation authority.
2. Diagnose the escape before another product attempt: product invariant, test
   boundary, runner, served source, or completion decision. Preserve the
   failing action and all still-applicable acceptance.
3. Repair the demonstrated gap at its canonical owner. Use Maintain Workflow
   for a demonstrated reusable workflow gap and record `repair-now` with
   focused proof. Prefer a rejecting executable assertion or shared helper
   over an added warning. If
   an existing gate already rejects the failed packet, record `no-change`
   with that owner and passing rejection evidence. Do not reword an enforced
   instruction merely to produce a diff; `defer` cannot close a required gap.
4. Run the affected owner checks. Regenerate and review agent sources only
   when instructions changed. A product/test correction does not require a
   workflow rewrite; the escaped path still needs executable prevention.
5. Rebuild the cumulative reporter evidence inventory and restart the reporter
   case from exact reproduction with attempt N+1. Every still-applicable base
   acceptance and latest delta needs a phase-specific executable oracle.
   Re-resolve the expected-outcome authority; an inferred target from the
   failed attempt cannot carry forward. Where the active method uses proof
   receipts, the new receipt must use that attempt number; invalidated proof
   cannot carry forward.

On the second failed fix, or immediately when any architecture trigger applies,
assess the target with `best-api-review` before another Patch:

- `cross-layer-compensation`;
- `duplicated-live-identity`;
- `per-node-hot-work`;
- `timer-focus-correctness`;
- `ui-repairs-substrate`;
- `second-failed-fix`.

The existing case evidence (architecture row in corpus mode) records the
verdict and evidence. Stop may retain the existing owner with a reason; Pursue
routes through Best API and the owning
Plite/Plate plan when design or adoption is needed. Compare deleting or merging
the implicated owners before adding compensation. Existing repair authority
continues; a review is not a handoff back to the user.
