Plate 插件是传给 `Plate` 组件 [plugins](/docs/api/core/plate-components#plugins) 属性的描述符。已安装插件的 API 会按插件 key 推断到 `editor.api`。当通用代码需要精确的插件 API、update 命令、类型或实时 options 时，将描述符传给 `editor.plugin(MyPlugin)`；React 组件通过 `usePluginOption` 或 `usePluginOptions` 订阅变化。

## 插件属性

<API name="Properties">
<APIAttributes>
<APIItem name="key" type="C['key']" required>
Plate 用于通过 `editor.plugin(MyPlugin)` 解析描述符的唯一标识符。
</APIItem>

<APIItem name="targetPluginKeys" type="readonly string[]">
插件的 schema 声明和注入行为所针对的插件 key。

- **默认值:** `[]`
</APIItem>

<APIItem name="api" type="Record<string, Function>">
  插件拥有的 API 函数，可通过 `editor.api[MyPlugin.key]` 和精确的
  `editor.plugin(MyPlugin).api` portal 访问。两个路径引用同一个不可变 API
  对象。互相独立的方法放进 constructor；只有方法需要前一阶段类型或正在适配
  import/prebuilt descriptor 时才使用 `.extend({ api })`。真正面向整个编辑器的能力属于
  `extension` 贡献。
</APIItem>

<APIItem name="tx" type="Record<string, Function>">
  插件提供的事务命令。通过 `editor.plugin(MyPlugin).update.method()`
  执行单个命令， 或在 `editor.update((tx) => tx[key].method())` 中组合命令。
</APIItem>

<APIItem name="options" type="Record<string, any>">
插件拥有的值，用于 schema 工厂、parser、codec 与运行时行为。包作者通过
`create*Plugin()` 声明互相独立的默认值；应用用户通过一次最终
`.configure({ options: { ... } })` 设置描述符值；通过
`editor.plugin(MyPlugin).getOptions()`、`.setOption()` 或 `.setOptions()`
读取或更新实时值。更新 options 不会重新编译 schema。
</APIItem>

<APIItem name="component" type="NodeComponent" optional>
插件普通节点使用的 React 组件。在 `createPlatePlugin({ component })` 中声明；
已有 Plate descriptor 使用一次最终 `.configure({ component })` 绑定。静态
consumer 直接使用 `BasePlugin.configure({ component })` 绑定已有 Base
descriptor。
</APIItem>

<APIItem name="handlers" type="{ onChange?: (editor: PlateEditor) => void } & Record<string, Function>">
各种编辑器事件的事件处理器。

<APISubList>
<APISubListItem parent="handlers" name="onChange" type="(editor: PlateEditor) => void" optional>
每当编辑器内容更改时调用。
</APISubListItem>
<APISubListItem parent="handlers" name="onNodeChange" type="OnNodeChange" optional>
每当发生节点操作时调用（插入、删除、设置、合并、拆分、移动）。

```ts
type OnNodeChange = (
  ctx: PlatePluginContext & {
    node: Descendant;
    operation: NodeOperation;
    prevNode: Descendant;
  }
) => HandlerReturnType;
```

**参数：**

- `node`：操作后的节点
- `operation`：发生的节点操作
- `prevNode`：操作前的节点

**注意：** 对于 `insert_node` 和 `remove_node` 操作，`node` 和 `prevNode` 包含相同的值以避免空值情况。

</APISubListItem>
<APISubListItem parent="handlers" name="onTextChange" type="OnTextChange" optional>
每当发生文本操作时调用（插入或删除文本）。

```ts
type OnTextChange = (
  ctx: PlatePluginContext & {
    node: Descendant;
    operation: TextOperation;
    prevText: string;
    text: string;
  }
) => HandlerReturnType;
```

**参数：**

- `node`：包含已更改文本的父节点
- `operation`：发生的文本操作（`insert_text` 或 `remove_text`）
- `prevText`：操作前的文本内容
- `text`：操作后的文本内容
</APISubListItem>
</APISubList>
</APIItem>

<APIItem name="type" type="string">
插件拥有的已解析文档类型或属性 key。通过 `own.elementProperty(...)` 或
`own.textProperty(...)` 创建的 schema 声明、注入的节点 props 和插件命令都使用
同一个 key。当存储 key 需要与 `plugin.key` 不同时配置 `type`，不要添加第二个
存储 key 选项。

- **默认值:** `plugin.key`
</APIItem>

<APIItem name="schema" type="PluginSchema<C> | null">
通过 `element`、`mark`、`properties` 和 `contentRoots` 字段声明插件的 Plite
模型。工厂通过 `contentRoots: [own.contentRoot(...)]` 声明元素拥有的根。
Schema 工厂接收已解析的插件 `type`、`options` 快照和已安装插件类型的类型化
helper。
布尔文本属性使用 `property.boolean({ default: false, omitDefault: true })`。
</APIItem>

<APIItem name="rules" type="object">
定义插件编译后的 schema 类型的编辑行为。

<APISubList>
<APISubListItem parent="rules" name="selection.affinity" type="'default' | 'directional' | 'outward' | 'hard'" optional>
定义节点边界的选区行为。参见 [插件规则](/docs/plugin-rules#rulesselection)。

- `'default'`: 使用 Plite 的默认行为
- `'directional'`: 选区亲和性由光标移动方向决定。根据接近方向保持向内或向外亲和性
- `'outward'`: 强制向外亲和性。在标记边缘输入不会将标记应用到新文本
- `'hard'`: 创建需要两次按键才能跨越的"硬"边缘。使用基于偏移的导航

- **默认值:** `undefined` (Plite 的默认行为)

</APISubListItem>

<APISubListItem parent="rules" name="break.empty" type="'default' | 'deleteExit' | 'exit' | 'lift' | 'reset'" optional>
在空块中按下 Enter 时的动作。参见 [插件规则](/docs/plugin-rules)。

- `'default'`: 默认行为
- `'reset'`: 重置块为默认段落类型
- `'exit'`: 退出当前块
- `'lift'`: 将当前块从最近匹配的祖先中提升出来
- `'deleteExit'`: 向后删除然后退出

</APISubListItem>

<APIItem name="editOnly" type="boolean | EditOnlyConfig" optional>
配置哪些插件功能仅在编辑器非只读时激活。

可以是布尔值或对象配置：

```ts
type EditOnlyConfig = {
  render?: boolean; // 默认: true
  handlers?: boolean; // 默认: true
  inject?: boolean; // 默认: true
  transformInitialValue?: boolean; // 默认: false
};
```

当设置为 `true`（布尔值）时：

- `render`、`handlers` 和 `inject.nodeProps` 仅在编辑器非只读时激活
- `transformInitialValue` 无论只读状态如何都保持激活

当设置为对象时：

- 每个属性可以单独配置
- 属性默认是仅编辑的（`true`），除了 `transformInitialValue` 默认始终激活（`false`）
- 将属性设置为 `false` 使其始终激活，无论只读状态如何
- 对于 `transformInitialValue`，设置为 `true` 使其仅在编辑时激活

示例：

```ts
// 所有功能（除 transformInitialValue 外）都是仅编辑的
editOnly: true;

// transformInitialValue 是仅编辑的，其他保持默认行为
editOnly: {
  transformInitialValue: true;
}

// render 始终激活，其他遵循默认行为
editOnly: {
  render: false;
}
```

</APIItem>
</APIAttributes>
</API>

## 插件方法

<API name="Methods">
<APIMethods>
<APIItem name="configure" type="(config: PlatePluginConfig | ((ctx: PlatePluginContext) => Partial<Pick<PlatePluginConfig, 'options' | 'handlers' | 'render' | 'shortcuts'>>)) => ConfiguredPlatePlugin">
应用一次最终用户配置，并返回不能再次配置或扩展的描述符。对象形式用于定义字段；
回调形式可根据已解析编辑器上下文生成已有的 `options`、`handlers`、`render` 或
`shortcuts`。此前声明的运行时扩展可以读取配置值，重叠字段最终仍以用户配置为准。

```ts
H1Plugin.configure({
  shortcuts: { toggle: { keys: 'mod+alt+1' } },
});
```

</APIItem>

<APIItem name="extend" type="(config: Partial<PlatePlugin> | ((ctx: PlatePluginContext) => Partial<PlatePlugin>)) => PlatePlugin">
向 import/prebuilt descriptor 添加贡献，使用 constructor 无法访问的 shared
factory，或使用前一阶段新增类型。
互相独立的字段直接放进 `createBasePlugin()` 或 `createPlatePlugin()`。所有
`.extend()` 调用必须在用户 `.configure()` 之前完成。

```ts
type PluginContribution = {
  api?: Record<string, Function>;
  read?: Record<string, Function>;
  selectors?: Record<string, Function>;
  update?: (context: { tx: EditorUpdateTransaction }) => Record<string, Function>;
  extension?: PlateEditorExtensionInput;
  codecs?: PluginCodecMapDeclaration;
};

<TContract extends PluginContribution>(
  extendConfig: (
    context: PlatePluginContext<C> & {
      defineCodecs: DefinePluginCodecs<C>;
      defineEditorExtension: DefineEditorExtension<C>;
    }
  ) => TContract
) => PlatePlugin;
```

贡献字段各自拥有明确职责：

- `api`：插件作用域内的不可变服务
- `read`：快照或事务内读取
- `selectors`：派生 option 值
- `update`：插件作用域内、绑定事务的变更
- `extension`：Plite 运行时能力和真正的编辑器级分组；inline object 无需
  helper 即可获得 contextual typing
- `codecs`：context-bound `defineCodecs` 返回的 declaration

抽取后可复用的 editor-extension factory 接收 plugin context，并返回
`context.defineEditorExtension({ ... })`。这个 identity helper 保留无法从
`extension` return field 反向流入的嵌套 command、input、state、transaction 和
dependency inference。它不会增加另一个 builder stage。从 `@platejs/plite`
import 的同名函数用于 standalone Plite extension。

Self/product codec 使用 `defineCodecs(map)`；foreign codec 使用
`defineCodecs(TargetPlugin, map)`，helper 会注入 foreign target。Map 保持
MIME-keyed；`'text/html'` 接受单个 schema-aware rule 或非空有序 rule tuple。
`defineCodecs` 是唯一的 inline inference anchor；不要直接声明 codec map，
也不要手动添加 `target`。

`createBasePlugin()` / `createPlatePlugin()` 拥有所有互相独立的 declaration
字段，包括 `api`、`read`、`selectors`、`update`、`extension` 和 `codecs`。

</APIItem>
</APIMethods>
</API>

      `key`、`options`、`api`、`tx`、selectors、dependencies 和 schema 推断。

使用示例：

```typescript
type MyPluginConfig = PluginConfig<
  "myPlugin",
  { customOption: boolean },
  { getData: () => string },
  { myPlugin: { run: () => void } }
>;

const MyPlugin = createPlatePlugin<MyPluginConfig>({
  key: "myPlugin",
  // 插件实现
});
```
