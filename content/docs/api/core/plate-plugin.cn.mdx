Plate 插件是传入 `createEditor` 或 `useCreateEditor` 的 `plugins` 数组的描述符。
已安装插件的 API 会按插件名称推断到 `editor.api`。将描述符传给
`editor.plugin(MyPlugin)`，即可访问精确的 API、read、update 命令、schema 标识
和编辑器内状态。React 组件通过 `useEditor().plugin(MyPlugin)` 获取 portal，
通过 `usePluginStore` 订阅状态。

## 编写插件的上下文

插件 constructor、plugin、configuration、event、codec 和 injection
callback 在其契约支持时会接收当前插件的 context：

```ts
import { definePlugin, schema } from 'platejs/react';

export type UploadPluginState = {
  active: boolean;
};

const uploadInitialState: UploadPluginState = {
  active: false,
};

export const UploadPlugin = definePlugin("upload", {
  schema: {
    element: {
      content: schema.content.text({ default: 'text', min: 1 }),
    },
  },
  initialState: uploadInitialState,
  api: ({ store }) => ({
    isActive: () => store.get('active'),
  }),
  read: ({ state }) => ({
    isReady: () => !!state.selection(),
  }),
  update: ({ tx, schema }) => ({
    insert: () => tx.nodes.insert({ children: [{ text: "" }], type: schema.type }),
  }),
});
```

当前插件直接使用 `store`、`api`、`read`、`update`、`name`、`plugin` 和
`installed`。编辑器级操作、其他插件，或 scoped `update` 无法表达的事务
metadata 才使用 `editor`。shortcut handler 和 input rule 等特殊 callback
可能只接收 `editor`；这种情况使用精确的 typed plugin portal。

## 插件属性

<API name="Properties">
<APIAttributes>
<APIItem name="name" type="D['name']" required>
Plate 用于通过 `editor.plugin(MyPlugin)` 解析描述符的唯一标识符。
</APIItem>

<APIItem name="targetPlugins" type="readonly (PluginReference | string)[]">
插件的 schema 声明和注入行为所针对的插件描述符或动态 name。

- **默认值:** `[]`
</APIItem>

<APIItem name="api" type="(context: PluginContext<D>) => InferOwnApi<D>">
  插件拥有的 API 函数，可通过 `editor.api[MyPlugin.name]` 和精确的
  `editor.plugin(MyPlugin).api` portal 访问。两个路径引用同一个不可变 API
  对象。即使不需要 context，`api` 也必须声明为 factory。Factory 接收一个包含
  普通 Plate plugin context 的对象；不要使用 positional `editor, context`
  参数。互相独立的方法放进 constructor；只有方法需要前一阶段类型或正在适配
  import/prebuilt descriptor 时才使用 `.extend({api})`。真正面向整个
  编辑器的能力也使用根级 `api` 字段；Plate 会按插件 name 投影它。
</APIItem>

<APIItem
  name="read"
  type="(context: PluginContext<D> & { state: PluginReadState<D> }) => InferOwnRead<D>"
>
  插件拥有的 state-bound read。Plate 会将它发布到
  `editor.read[name]`，也可通过 `editor.plugin(MyPlugin).read` 访问。
  即使返回的方法不需要 authoring context，也必须把 `read` 声明为 factory。
</APIItem>

<APIItem name="selectors" type="PluginSelectors<InferPluginStoreState<D>>">
  基于插件 editor-local store 的纯 state-first derivation。React consumer 通过
  `usePluginStore` 订阅。
</APIItem>

<APIItem
  name="update"
  type="(context: PluginContext<D> & { context: EditorUpdateContext; tx: PluginTransaction<D> }) => InferOwnUpdate<D>"
>
  插件提供的事务命令。通过 `editor.plugin(MyPlugin).update.method()`
  执行单个命令，或在 `editor.update((tx) => tx.plugin(MyPlugin).method())`
  中组合命令。当调用方不应依赖 descriptor 所在的 package 时，改为传入
  `MyPlugin.name`。`update` 只能使用 factory：从 callback 返回 command object，
  不要声明静态对象。
</APIItem>

<APIItem name="initialState" type="Partial<InferPluginStoreState<D>> | ((context: PluginContext<D>) => InferPluginStoreState<D>)">
当前插件可变 editor-local store 的初始值。导出的插件应同时导出命名的
`*PluginState`，并通过带类型的常量或显式 factory 返回类型检查默认值。当 seed
依赖已解析 plugin context 时使用 callback 形式。应用用户通过一次最终
`.configure({ initialState: { ... } })` 覆盖初始值。运行时代码通过
`editor.plugin(MyPlugin).store` 读取和更新已安装的 store。
</APIItem>

<APIItem name="component" type="NodeComponent | keyof HTMLElementTagNameMap" optional>
  插件普通节点使用的组件或原生 HTML 标签。在 `definePlugin(name, { component })` 或
  `definePlugin(name, { component })` 中声明，可用于 static/RSC 和 live rendering；
  使用一次最终 `.configure({component})` 替换。Base `.extend()` 不接受该字段。
  `toReactPlugin()` 只在所属 React adapter 中发布可复用 Plate-layer descriptor
  或添加 Plate-only authoring；terminal consumer 不为设置 `component` 而转换。
</APIItem>

<APIItem
  name="codecs"
  type="PluginCodecMapDeclaration | ((context: PluginContext<D>) => PluginCodecMapDeclaration)"
>
  Schema-aware product 和 foreign format mapping。Self/product codec 使用
  contextual `defineCodecs(map)`；foreign contribution 使用
  `defineCodecs(TargetPlugin, map)`。
</APIItem>

<APIItem name="schema" type="PluginSchema<D> | null">
通过 `element`、`mark`、键控 `properties` 和 `contentRoots` 字段声明插件的 Plate
模型。Schema 工厂接收插件 `name`、配置后的 `initialState`、`targetElementTypes`
和 Plate 关系 helper。`name` 只标识能力。已安装的 AST identity 通过插件 callback
和 portal 的 `schema.type`（element 插件）或 `schema.key`（primary mark 插件）
发布。Author callback 还可以通过 `schema.properties.&lt;localId&gt;` 访问额外声明的
property；consumer portal 不公开该映射。Behavior 和 aggregate-property portal
不包含 `schema`。
布尔文本属性使用 `property.boolean({ default: false, omitDefault: true })`。
在 `update` 中，`tx.nodes.set(props, options)` 接受 typed property patch，
`unset(key, options)` 删除 exact property。Alias 在 computed patch 中使用精确的
authored property handle key。Prefix family 和 cross-node behavior 使用语义
update method。
</APIItem>

<APIItem name="rules" type="object">
定义插件编译后的 schema 类型的编辑行为。

<APISubList>
<APISubListItem parent="rules" name="selection.affinity" type="'default' | 'directional' | 'outward' | 'hard'" optional>
定义节点边界的选区行为。参见 [插件规则](/docs/plugin-rules#rulesselection)。

- `'default'`: 使用 Plate 的默认行为
- `'directional'`: 选区亲和性由光标移动方向决定。根据接近方向保持向内或向外亲和性

- **默认值:** `undefined` (Plate 的默认行为)

<APIItem name="render" type="object">
定义主 `component` 和 mounted view 的渲染行为。

<APISubList>
<APISubListItem parent="render" name="contentAttributes" type="DecorationAttributes | null" optional>
为现有 `EditorContent` 或 `EditorStatic` 根节点添加渲染安全的属性。
接受 `className`、`style` 以及值为基本类型的 `data-*` 或 `aria-*`。
功能可以直接配置内容样式，无需包裹节点：

```tsx
import { SuggestionPlugin } from 'platejs/suggestion/react';

SuggestionPlugin.configure({
  render: {
    contentAttributes: {
      className: '[&_[data-editor-retained=delete]]:line-through',
    },
  },
});
```

已启用的 plugin 按顺序组合。类名拼接，style 浅合并，后面的属性覆盖前面的值。
内容组件显式传入的属性优先；core 管理的身份、编辑控制、事件、ref 和 children
仍由内容组件负责。使用 `null` 清除继承的配置。此字段是静态属性对象；行为通过
plugin 事件处理器配置。
`editOnly.render` 会在只读 view 和静态渲染中排除此配置。
</APISubListItem>
<APISubListItem parent="render" name="attributes" type="NodeProps" optional>
在交互和静态渲染中，为主 element、leaf 或 text renderer 添加可信 DOM attribute。
函数值是纯 per-node render callback，不能调用 React hook。
</APISubListItem>
<APISubListItem parent="render" name="useViewElementAttributes" type="UseViewElementAttributes<D>" optional>
为每个 mounted Plate content view 中启用的当前 plugin 创建一个 React hook host。
callback 通过 `view` 获取当前 Plate root，并返回作用于整个 element host 的稀疏
`{ key, attributes }[]`。没有目标 element 时返回空数组。

```tsx
import { definePlugin, usePluginStore } from "platejs/react";

const ActiveFirstBlockPlugin = definePlugin("activeFirstBlock", {
  initialState: { active: false },
  render: {
    useViewElementAttributes({ editor, plugin, view }) {
      const active = usePluginStore(plugin, (state) => state.active, {
        id: editor.id,
      });
      const key = view.key([0]);

      return active && key
        ? [{ attributes: { "data-active": "true" }, key }]
        : [];
    },
  },
});
```

attribute 仅支持 `className`、`placeholder`、`style`，以及 primitive
`aria-*` 或 `data-*` 值；ref 和 event handler 会被拒绝。Plate 按 compiled
plugin order 合并 source，随 mounted view 清理，并把 publication 与 per-key
subscription 保持为私有实现。inline text range 使用 `decorate`，结构使用
component 或 slot。
</APISubListItem>
<APISubListItem parent="render" name="mark" type="object" optional>
控制 schema mark 的主 `component` 渲染位置。`placement: 'leaf'` 包裹每个 active leaf，
也是默认值。`placement: 'text'` 只包裹一次 text node，并允许使用 `leafComponent`
作为第二个 active-leaf renderer。`leafAttributes` 和 `textAttributes` 为对应 host
添加可信 attribute。
</APISubListItem>
</APISubList>
</APIItem>

<APIItem name="activate" type="PluginDefinitionInput['activate']">
  在早期运行并管理同步资源。需要最终文档候选值的验证或资源初始化，通过
  `context.beforePublish(callback)` 注册，其签名为
  `beforePublish: (callback: () => void) => void`。回调在编辑器构造和动态插件
  变更中、发布不可回退之前执行。它必须同步运行，且不能写入文档。
  抛出异常会否决发布并回滚候选值。

  通过 `context.onCleanup(...)` 注册资源清理，包括在 `beforePublish` 中获取的
  资源。清理由 activation 管理，在回滚、移除或替换时执行。

  `context.afterPublish(...)` 用于不抛出异常的发布后观察。回调错误会被报告，
  不能否决或回滚发布。
</APIItem>

<APIItem name="validate" type="PluginDefinitionInput['validate']">
  在 activation 前检查已组装的 detached candidate。此早期检查无法观察完成
  初始化的最终文档；需要该文档的检查在 `activate` 中通过 `beforePublish` 注册。
</APIItem>

<APIItem name="enabled" type="boolean" optional>
  启用或禁用插件。Plate 使用此属性决定是否使用该插件。
</APIItem>

<APIItem name="decorate" type="Decorate<D>" optional>
  `read({ entry, ...context })` 返回带 key 的临时范围。
  `observe({ refresh, ...context })` 管理失效通知与清理；静态渲染只读取来源，不订阅。

  `attributes` 接受 `DecorationAttributes` 对象、纯函数，或用于清除继承样式的
  `null`。回调接收推断的插件上下文，以及 `entry` 和 `decoration`。
  已有装饰来源可单独配置 `attributes`，无需重复 `read` 或 `observe`；新来源必须提供 `read`。

  展示类名与语义类名拼接，style 浅合并，其他提供的属性覆盖 reader 的对应属性。
  使用 `className`、`style`、`data-*` 和 `aria-*`；行内结构与事件处理器属于组件。
  回调在每次来源读取后运行，不增加订阅。外部输入的变化由来源的 `observe` 负责通知。
</APIItem>

<APIItem name="editOnly" type="boolean | EditOnlyConfig" optional>
配置哪些插件功能仅在编辑器非只读时激活。

可以是布尔值或对象配置：

```ts
type EditOnlyConfig = {
  render?: boolean; // 默认: true
  on?: boolean; // 默认: true
  inject?: boolean; // 默认: true
};
```

当设置为 `true`（布尔值）时：

- `render`、`on` 和 `inject.nodeProps` 仅在编辑器非只读时激活

当设置为对象时：

- 每个属性可以单独配置
- 属性默认是仅编辑的（`true`）
- 将属性设置为 `false` 使其始终激活，无论只读状态如何

示例：

```ts
// 所有受支持的功能都是仅编辑的
editOnly: true;

// render 始终激活，其他遵循默认行为
editOnly: {
  render: false;
}
```

</APIItem>
</APIAttributes>
</API>

<APIItem name="extend" type="<TPlugin extends PluginExtendInput<D>>(plugin: TPlugin) => Plugin">
向 import/prebuilt descriptor 添加贡献，使用 constructor 无法访问的 shared
factory，或使用前一阶段新增类型。
互相独立的字段直接放进 `definePlugin()` 或 `definePlugin()`。所有
`.extend()` 调用必须在用户 `.configure()` 之前完成。返回的 `Plugin`
保留 contribution 推断出的 capabilities。

贡献字段各自拥有明确职责：

- `api`：插件作用域内的不可变服务
- `read`：快照或事务内读取
- `selectors`：基于 editor-local state 的纯派生值
- `update`：插件作用域内、绑定事务的变更
- `readMiddleware`、`commands`、`corrections`、`stateFields`、
  `effectTypes`、`contributions`、
  `on`、`activate` 和 `validate`：直接声明在插件上的编辑器能力
- `codecs`：context-bound `defineCodecs` 返回的 declaration

独立复用的 standalone Plate descriptor 使用从 `platejs` import 的
`definePlugin`。Plate 插件在根级声明相同的原生能力。

Self/product codec 使用 `defineCodecs(map)`；foreign codec 使用
`defineCodecs(TargetPlugin, map)`，helper 会注入 foreign target。Map 保持
MIME-keyed；`'text/html'` 接受单个 schema-aware rule 或非空有序 rule tuple。
`defineCodecs` 是唯一的 inline inference anchor；不要直接声明 codec map，
也不要手动添加 `target`。

`definePlugin()` / `definePlugin()` 拥有所有互相独立的 declaration
字段，包括 `api`、`read`、`selectors`、`update`、编辑器字段和 `codecs`。

</APIItem>
</APIMethods>
</API>

## 泛型类型

使用 `DefinitionOf<typeof Plugin>` 提取 descriptor 的 inferred definition。
这是唯一的 public extractor。

<API name="GenericTypes">
  <APIAttributes>
    <APIItem name="D" type="BasePluginDefinition">
      表示插件契约，包括
      `name`、`initialState`、`api`、`read`、`update`、selectors、dependencies
      和 schema 推断。
    </APIItem>
  </APIAttributes>
</API>

使用示例：

```typescript
export type MyPluginState = {
  customOption: boolean;
};

export const MyPlugin = definePlugin("myPlugin", {
  initialState: {
    customOption: false,
  } satisfies MyPluginState,
  api: ({ store }) => ({
    getData: () => String(store.get("customOption")),
  }),
  update: ({ tx }) => ({
    run: () => tx.selection.collapse(),
  }),
});

type MyDefinition = DefinitionOf<typeof MyPlugin>;
```
