---
title: Plate Plugin
description: API reference for Plate plugins.
---

Plate plugins are descriptors passed in the `plugins` array of `createEditor`
or `useCreateEditor`. Installed plugin APIs are inferred on `editor.api` under
the plugin name. Pass the descriptor to `editor.plugin(MyPlugin)` for its exact
API, reads, update commands, schema identity, editor-local state, and per-view
state. React components use `useEditor().plugin(MyPlugin)` for the portal,
`usePluginStore` for state subscriptions, and `useViewStore` for view state
subscriptions.

## Authoring context

Plugin constructor, plugin, configuration, event, codec, and injection
callbacks receive the current plugin context when their callback contract
supports it:

```ts
import { definePlugin, schema } from 'platejs/react';

export type UploadPluginState = {
  active: boolean;
};

const uploadInitialState: UploadPluginState = {
  active: false,
};

export const UploadPlugin = definePlugin("upload", {
  schema: {
    element: {
      content: schema.content.text({ default: 'text', min: 1 }),
    },
  },
  initialState: uploadInitialState,
  api: ({ store }) => ({
    isActive: () => store.get('active'),
  }),
  read: ({ state }) => ({
    isReady: () => !!state.selection(),
  }),
  update: ({ tx, schema }) => ({
    insert: () => tx.nodes.insert({ children: [{ text: "" }], type: schema.type }),
  }),
});
```

Use `store`, `api`, `read`, `update`, `name`, `plugin`, and `installed`
directly for the current plugin. Use `editor` for editor-wide operations,
another plugin, or transaction metadata unavailable on the scoped `update`
facade. Specialized callbacks such as shortcut handlers and input rules may
only receive `editor`; use an exact typed plugin portal there.

## Plugin properties

<API name="Properties">
<APIAttributes>
<APIItem name="name" type="D['name']" required>
Unique identifier Plate uses to resolve the descriptor through `editor.plugin(MyPlugin)`.
</APIItem>

<APIItem name="targetPlugins" type="readonly (PluginReference | string)[]">
Plugin descriptors or dynamic names targeted by the plugin's schema contributions and injected behavior.

- **Default:** `[]`
</APIItem>

<APIItem name="api" type="(context: PluginContext<D>) => InferOwnApi<D>">
  Plugin-owned API functions exposed through `editor.api[MyPlugin.name]` and the
  exact `editor.plugin(MyPlugin).api` portal. Both paths reference the same
  immutable API object. Declare `api` as a factory even when it needs no
  context. The factory receives one object containing the normal Plate plugin
  context; it never receives positional `editor, context` arguments. Authors
  declare independent methods in the constructor and use `.extend({api})` only
  when they need an earlier-stage type or are adapting an imported/prebuilt
  descriptor. Genuinely editor-wide capabilities use the same root `api` field;
  Plate projects it under the plugin name. The factory also receives
  `viewStore`, this plugin's state in the view the API is built for.
</APIItem>

<APIItem
  name="read"
  type="(context: PluginContext<D> & { state: PluginReadState<D> }) => InferOwnRead<D>"
>
  State-bound reads owned by the plugin. Plate publishes them under
  `editor.read[name]` and through `editor.plugin(MyPlugin).read`. Declare
  `read` as a factory, even when the returned methods need no authoring context.
  Plate constructs the namespace once per plugin configuration. Return methods
  or nested method records; compute document values when a method runs. Stable
  constants and host services belong in `api`.
</APIItem>

<APIItem name="selectors" type="PluginSelectors<InferPluginStoreState<D>>">
  Pure state-first derivations over the plugin's editor-local store. React
  consumers subscribe to them through `usePluginStore`.
</APIItem>

<APIItem
  name="update"
  type="(context: PluginContext<D> & { context: EditorUpdateContext; tx: PluginTransaction<D> }) => InferOwnUpdate<D>"
>
  Transaction commands provided by the plugin. Call one through
  `editor.plugin(MyPlugin).update.method()` or compose it inside
  `editor.update((tx) => tx.plugin(MyPlugin).method())`. Pass `MyPlugin.name`
  instead when the caller should not depend on the descriptor's package.
  `update` is factory-only: return the command object from the callback instead
  of declaring a static object.
</APIItem>

<APIItem name="initialState" type="Partial<InferPluginStoreState<D>> | ((context: PluginContext<D>) => InferPluginStoreState<D>)">
The seed for this plugin's mutable editor-local store. Package authors declare
an exported `*PluginState` beside an exported plugin and check its defaults
through a typed constant or explicit factory return type. Use the callback form
when the seed depends on the resolved plugin context. App consumers override
the seed with one final `.configure({ initialState: { ... } })`. Runtime code
reads and updates the installed store through `editor.plugin(MyPlugin).store`.
</APIItem>

<APIItem name="initialViewState" type="() => InferPluginViewState<D>">
Creates this plugin's state for one view. Plate keeps one copy for each view
of the editor and one for the base editor. Use it for state that belongs to
what one view shows, such as which sections are collapsed; state that every
view shares stays in `initialState`. The `api` factory and the plugin portal
read and write it through `viewStore`, `.extend` callbacks through
`viewStoreOf(state)` and `viewStoreOf(tx)`, and React components through
`useViewStore`. See [View state](/docs/plugin-context#view-state).

```ts
initialViewState: (): BaseDetailsViewState => ({
  openKeys: new Set(),
}),
```
</APIItem>

<APIItem name="component" type="NodeComponent | keyof HTMLElementTagNameMap" optional>
  The ordinary component or intrinsic HTML tag for this plugin's node. Declare it in
  `definePlugin(name, { component })` or
  `definePlugin(name, { component })` for
  static/RSC and live rendering. Replace it with one terminal
  `.configure({component})`. Base `.extend()` does not accept it. Use
  `toReactPlugin()` at the owning React adapter to publish a reusable
  Plate-layer descriptor or add Plate-only authoring; a terminal consumer does
  not convert merely to set `component`.
</APIItem>

<APIItem
  name="formats"
  type="PluginFormatMapDeclaration | ((context: PluginFormatAuthoringContext<D>) => PluginFormatMapDeclaration)"
>
  Schema-aware HTML, Markdown, and plain-text node mappings. The authoring
  context exposes `defineFormats` and static schema bindings. Use
  `defineFormats(map)` for self mappings or
  `defineFormats(TargetPlugin, map)` for foreign contributions.
</APIItem>

<APIItem name="schema" type="PluginSchema<D> | null">
Declares the plugin's Plate model through its `element`, `mark`, keyed
`properties`, and `contentRoots` fields. A schema factory receives the plugin
`name`, its configured `initialState`, `targetElementTypes`, and Plate
relationship helpers. `name` identifies the capability only. Installed AST
identity is published through `schema.type` for an element plugin and
`schema.key` for a primary-mark plugin. Author callbacks may also use
`schema.properties.&lt;localId&gt;` for additional declared properties; consumer
portals do not expose that map. Behavior and aggregate-property portals omit
`schema`.
Boolean text properties use
`property.boolean({ default: false, omitDefault: true })`.
An element property's `landing` option, `'preserve' | 'rebase' | 'adopt'`
with `preserve` by default, says whether where content lands may change it;
a text drag that moves may change only `rebase` and `adopt` properties, and
`editorReads.transfer.adopt` may set only `adopt` ones.
Inside `update`, `tx.nodes.set(props, options)` accepts a typed property patch,
while `unset(key, options)` removes exact properties. Aliases use the exact
authored property handle's key in a computed patch. Prefix families and
cross-node behavior use semantic update methods.
</APIItem>

<APIItem name="rules" type="object">
Defines editing behavior for the plugin's compiled schema identity. Each
structural leaf accepts either its action directly or a resolver of the form
`(context) => action | undefined`. A returned action is final, including
`false`; `undefined` delegates that exact leaf to the next contributor and then
to the plugin compiled for the node type.

<APISubList>
<APISubListItem parent="rules" name="selection.affinity" type="'default' | 'directional' | 'outward' | 'hard'" optional>
Defines the selection behavior at the boundaries of nodes. See [Plugin Rules](/docs/plugin-rules#rulesselection).

- `'default'`: Uses Plate's default behavior
- `'directional'`: Selection affinity is determined by the direction of cursor movement. Maintains inward or outward affinity based on approach
- `'outward'`: Forces outward affinity. Typing at the edge of a mark will not apply the mark to new text
- `'hard'`: Creates a 'hard' edge that requires two key presses to move across. Uses offset-based navigation

- **Default:** `undefined` (Plate's default behavior)

</APISubListItem>

<APISubListItem parent="rules" name="break.empty" type="RuleDecision<'default' | 'deleteExit' | 'exit' | 'lift' | 'none' | 'reset'>" optional>
Action when Enter is pressed in an empty block. See [Plugin Rules](/docs/plugin-rules).

- `'default'`: Default behavior
- `'reset'`: Reset block to default paragraph type
- `'exit'`: Exit the current block
- `'lift'`: Lift the current block out of the nearest matching ancestor
- `'deleteExit'`: Delete backward then exit
- `'none'`: Handle Enter without changing the document

</APISubListItem>

<APISubListItem parent="rules" name="break.emptyLineEnd" type="RuleDecision<'default' | 'deleteExit' | 'exit'>" optional>
Action when Enter is pressed at the end of an empty line. This is typically used with `rules.break.default: 'lineBreak'`. See [Plugin Rules](/docs/plugin-rules).

- `'default'`: Default behavior
- `'exit'`: Exit the current block
- `'deleteExit'`: Delete backward then exit

</APISubListItem>

<APISubListItem parent="rules" name="break.default" type="RuleDecision<'default' | 'deleteExit' | 'exit' | 'lineBreak' | 'none'>" optional>
Default action when Enter is pressed. Defaults to splitting the block. See [Plugin Rules](/docs/plugin-rules).

- `'default'`: Default behavior
- `'exit'`: Exit the current block
- `'lineBreak'`: Insert newline character
- `'deleteExit'`: Delete backward then exit
- `'none'`: Handle Enter without changing the document

</APISubListItem>

<APISubListItem parent="rules" name="break.splitReset" type="RuleDecision<boolean>" optional>
If true, the new block after splitting will be reset to the default type. See [Plugin Rules](/docs/plugin-rules).
</APISubListItem>
<APISubListItem parent="rules" name="delete.start" type="RuleDecision<'default' | 'lift' | 'reset'>" optional>
Action when Backspace is pressed at the start of the block. This applies whether the block is empty or not. See [Plugin Rules](/docs/plugin-rules).

- `'default'`: Default behavior
- `'lift'`: Lift the current block out of the nearest matching ancestor
- `'reset'`: Reset block to default paragraph type

</APISubListItem>

<APISubListItem parent="rules" name="delete.empty" type="RuleDecision<'default' | 'reset'>" optional>
Action when Backspace is pressed and the block is empty. See [Plugin Rules](/docs/plugin-rules).

- `'default'`: Default behavior
- `'reset'`: Reset block to default paragraph type

</APISubListItem>
<APISubListItem parent="rules" name="merge.removeEmpty" type="RuleDecision<boolean>" optional>
Whether to remove the node when it's empty during merge operations. See [Plugin Rules](/docs/plugin-rules).

- **Default:** `false`

</APISubListItem>

<APISubListItem parent="rules" name="normalize.removeEmpty" type="RuleDecision<boolean>" optional>
Whether to remove nodes with empty text during normalization. See [Plugin Rules](/docs/plugin-rules).

- **Default:** `false`

</APISubListItem>
</APISubList>
</APIItem>

<APIItem name="override" type="Record<string, BasePluginOverride>">
Weakly adapts already-installed foreign plugins by name. Each key is a target
plugin name. Missing targets are ignored. Values cannot define `name`,
`dependencies`, `schema`, or another `override`. Contributors resolve by
priority then source order, and direct target `.configure()` values remain
authoritative. A peer may replace the target `component`; use
`{ enabled: false }` when a package plugin must disable an optional installed
target.
</APIItem>

<APIItem name="render" type="object">
Defines rendering for the plugin's primary `component` and mounted views.

<APISubList>
<APISubListItem parent="render" name="contentAttributes" type="DecorationAttributes | null" optional>
Adds render-safe attributes to the existing `EditorContent` or `EditorStatic`
root. Accepts `className`, `style`, and primitive `data-*` or `aria-*` values.
Use this field for feature-owned content styling without a wrapper:

```tsx
import { SuggestionPlugin } from 'platejs/suggestion/react';

SuggestionPlugin.configure({
  render: {
    contentAttributes: {
      className: '[&_[data-editor-authored-kind~=delete]]:line-through',
    },
  },
});
```

Enabled plugins compose in plugin order. Class names concatenate, styles merge
shallowly, and later attributes win. Explicit content component props take
precedence; core-owned identity, editing controls, events, refs, and children
remain with the content component. Set `null` to clear inherited configuration.
This field is a static attribute object; use plugin event handlers for behavior.
`editOnly.render` excludes the contribution from read-only views and static rendering.
</APISubListItem>
<APISubListItem parent="render" name="attributes" type="NodeProps" optional>
Adds trusted DOM attributes to the primary element, leaf, or text renderer in
interactive and static rendering. A function value is a pure per-node render
callback and cannot call React hooks.
</APISubListItem>
<APISubListItem parent="render" name="readsDocument" type="boolean" optional>
Whether rendering the plugin's element reads content after the element, such as
a table of contents listing every heading. Static rendering reuses a block
while it and every block before it are unchanged; an element that reads later
content renders again whenever the document changes.
</APISubListItem>
<APISubListItem parent="render" name="useViewElementAttributes" type="UseViewElementAttributes<D>" optional>
Plate mounts one React hook host for this enabled plugin in each content view.
The callback receives the exact Plate root as `view` and returns sparse
`{ key, attributes }[]` entries for whole element hosts. Return an empty array
when no element needs attributes.

```tsx
import { definePlugin, usePluginStore } from "platejs/react";

const ActiveFirstBlockPlugin = definePlugin("activeFirstBlock", {
  initialState: { active: false },
  render: {
    useViewElementAttributes({ editor, plugin, view }) {
      const active = usePluginStore(plugin, (state) => state.active, {
        id: editor.id,
      });
      const key = view.key([0]);

      return active && key
        ? [{ attributes: { "data-active": "true" }, key }]
        : [];
    },
  },
});
```

Attributes may contain `className`, `placeholder`, `style`, and primitive
`aria-*` or `data-*` values. Refs and event handlers are rejected. Plate merges
sources in compiled plugin order, cleans them up with the mounted view, and
keeps publication and per-key subscriptions private. Use `decorate` for inline
text ranges and components or slots for structure.
</APISubListItem>
<APISubListItem parent="render" name="mark" type="object" optional>
Controls where a schema mark's primary `component` renders. `placement: 'leaf'`
wraps every active leaf and is the default. `placement: 'text'` wraps the text
node once and permits `leafComponent` as a secondary active-leaf renderer. In a
paged editor, `placement: 'text'` wraps each piece of the text once. A piece is
a measured run of the text on a drawn page, the lines of a page not drawn yet,
or a whole text that no layout measures. One line can hold more than one run of
the same text. Its props carry `piece: { index }`, the piece's
position among the text's pieces, and attributes with no `data-editor-node`,
path, key or `ref`. Render an extra that must appear once per
text from the element component, or from `leafComponent` on the text's last
leaf, the one whose `leafPosition` is missing or has `isLast`.
`leafAttributes` and `textAttributes` add trusted attributes to their matching
hosts.
</APISubListItem>
</APISubList>
</APIItem>

<APIItem name="readMiddleware" type="PluginReadMiddlewareFactory">
  Typed middleware over declared Plate `editorReads` descriptors.

  `editorReads.slice.landing` shapes what a paste lands after command handlers
  delegate to the default replacement. Its `state` reads the command's current
  draft in the root the paste lands in, so a path in `target.block` resolves
  there. Its input has the handlers' slice as
  `source`, what fits `maxLength` as `slice`, the `target` the editor
  resolved, and an `intent` of `copy` for a paste or a copied text drop, or
  `move` for a text drag that moves. A move refuses with `lossy` when the read
  changes the moved text or marks, or the type or properties of a block the
  move carries, except properties declared `landing: 'rebase'` or `'adopt'`.
  It does not check the block the moved text joins at the drop point or the
  blocks that contain it, and it checks every other block the move carries, an
  empty last block included. A closed block, such as a title, joins nothing, and
  in an empty block the moved block may take properties from the block it
  replaces.
  The text the paste replaces does not count toward the limit. A
  target is `empty` for a caret in an empty block, or `context` with the block
  where the paste starts. When the paste replaces selected blocks whole, that
  is the innermost block where the first selected block starts, such as a
  quote's first paragraph. The read returns the `slice` to fit. The
  editor cuts it the same way, to what fits `maxLength` after crediting the
  replaced text. The read may also add `replaceEmpty`, whole blocks
  that replace an `empty` target. The editor checks that proposal against the schema and
  `maxLength`, and fits `slice` when the proposal does not fit. The first
  replacing block keeps all of the target's properties when its type matches,
  what the schema allows when it is a text block of another type, and none when
  it is an object or void. It never keeps `omitTargetProperties`. The
  [Clipboard guide](/docs/clipboard#where-a-paste-lands) has an example. A middleware
  that rewrites `slice` must rewrite or drop `replaceEmpty`. A terminal handler
  bypasses this read. Raw `tx.slice.replace`, `tx.fragment.replace`, and
  `state.slice.fit` do not run it. Import the descriptor and the
  `SliceLanding`, `SliceLandingInput` and `SliceLandingTarget` types from
  `platejs`.

  `editorReads.transfer.adopt` returns the properties a block copy or move
  takes where it lands, as `TransferPatch` entries; the
  [Drag and drop page](/docs/dnd#shape-dropped-blocks) has an example. Its
  `TransferAdoptInput` and `TransferPatch` types also come from `platejs`.
</APIItem>

<APIItem name="activate" type="PluginDefinitionInput['activate']">
  Runs early and owns synchronous in-memory resources. Register
  `context.beforePublish(callback)` for validation that needs the final
  document candidate. Its signature is
  `beforePublish: (callback: () => void) => void`. The callback runs before
  publication becomes permanent, during both editor construction and dynamic
  plugin changes. It must be synchronous and must not write to the document.
  Throwing vetoes publication and rolls back the candidate.

  Take a resource outside the editor, such as a listener on a shared document,
  with `context.acquire(take)`. Its signature is
  `acquire: (take: () => (context: { reason: 'remove' | 'replace' | 'rollback' }) => void) => void`.
  `take` runs after every plugin's `beforePublish` passes and returns the
  function that lets the resource go. A throwing `take` rolls back the
  candidate. An editor from `useCreateEditor` takes nothing until React
  commits its component, because a render can be thrown away.

  Register in-memory cleanup with `context.onCleanup(...)`. Cleanup belongs to
  the activation and runs on rollback, removal, or replacement, after the
  activation's releases. `editor.destroy()` releases and cleans up every
  plugin.

  Use `context.afterPublish(...)` for nonthrowing observation of published
  state. Callback errors are reported; they cannot veto or roll back publication.
</APIItem>

<APIItem name="validate" type="PluginDefinitionInput['validate']">
  Checks the assembled detached candidate before activation. This early check
  does not observe the final initialized document. Register checks that need
  that document through `beforePublish` inside `activate`.
</APIItem>

<APIItem name="enabled" type="boolean" optional>
  Enables or disables the plugin. Used by Plate to determine if the plugin
  should be used.
</APIItem>

<APIItem name="decorate" type="Decorate<D>" optional>
  Supplies transient keyed ranges through `read({ entry, ...context })`.
  `observe({ refresh, ...context })` owns source invalidation and cleanup;
  static rendering reads the source without subscribing. A read depends on
  its entry, the nodes inside it and observed state, so an element entry may
  return ranges for its descendants.

  `attributes` accepts a `DecorationAttributes` object, a pure callback
  receiving the inferred plugin context plus `entry` and `decoration`, or
  `null` to clear inherited presentation. Configure an existing source's
  attributes without repeating its reader or observer. A new source requires
  `read`.

  Presentation classes concatenate with semantic classes, styles merge
  shallowly, and other supplied attributes override the reader's attributes.
  Use `className`, `style`, `data-*`, and `aria-*`; inline markup and event
  handlers belong to components. Callbacks run after each source read and
  add no subscription. Changes to external inputs require the source's
  `observe` contract.
</APIItem>

<APIItem name="editOnly" type="boolean | EditOnlyConfig" optional>
Configures which plugin functionalities should only be active when the editor is not read-only.

Can be either a boolean or an object configuration:

```ts
type EditOnlyConfig = {
  render?: boolean; // default: true
  on?: boolean; // default: true
  inject?: boolean; // default: true
};
```

When set to `true` (boolean):

- `render`, `on`, and `inject.nodeProps` are only active when editor is not read-only

When set to an object:

- Each property can be individually configured
- Properties default to being edit-only (`true`)
- Set a property to `false` to make it always active regardless of read-only state

Examples:

```ts
// All supported features are edit-only
editOnly: true;

// render is always active, others follow default behavior
editOnly: {
  render: false;
}
```

</APIItem>
</APIAttributes>
</API>

## Plugin methods

<API name="Methods">
<APIMethods>
<APIItem name="configure" type="(config: PluginConfiguration<D> | ((context: PluginContext<D>) => PluginConfiguration<D>)) => ConfiguredPlugin<D>">
Applies one terminal consumer configuration and returns a descriptor that
cannot be configured or extended again. Use the object form for definition
fields. The callback form can derive existing `initialState`, `on`, `render`,
or `shortcuts` from the resolved editor context. Contextual plugins
declared before this call read the configured values, while the configuration
remains the final override.

```ts
HeadingPlugin.configure({
  rules: { break: { empty: 'reset' } },
});
```

</APIItem>

<APIItem name="extend" type="<TPlugin extends PluginExtendInput<D>>(plugin: TPlugin) => Plugin">
Adds a contribution to an imported/prebuilt descriptor, a shared factory the
constructor cannot access, or types introduced by an earlier contribution. Put independent
fields directly in `definePlugin()`. Complete
every `.extend()` call before applying consumer `.configure()`. The returned
`Plugin` carries the contribution's inferred capabilities.

The contribution fields have distinct owners:

- `api`: plugin-scoped immutable services
- `read`: snapshot or transaction-local reads
- `selectors`: pure projections of editor-local plugin state
- `update`: plugin-scoped transaction-bound mutations
- `readMiddleware`, `commands`, `corrections`, `stateFields`, `effectTypes`,
  `contributions`, `on`, `activate`, and
  `validate`: editor capabilities declared directly on the plugin
- `formats`: the declaration returned by context-bound `defineFormats`

Independently reusable standalone Plate descriptors use
`definePlugin` from `platejs`. Plate plugins declare the same
native capabilities at their root.

Use `defineFormats(map)` for self mappings and
`defineFormats(TargetPlugin, map)` for foreign mappings. The helper injects the
foreign target. The semantic keys are `html`, `markdown`, and `plainText`;
`html` accepts one schema-aware rule or a non-empty ordered rule tuple.
Whole-payload MIME handling belongs to `dataTransferFormats`. Do not author
direct maps, add a manual `target`, or annotate mapping callback parameters.

`definePlugin()` / `definePlugin()` own every independent declaration
field, including `api`, `read`, `selectors`, `update`, editor fields, and
`formats`.

</APIItem>
</APIMethods>
</API>

## Plugin context

<API name="Context">
  <APIAttributes>
    <APIItem name="editor" type="Editor">
      The current editor instance.
    </APIItem>
    <APIItem name="plugin" type="PluginContext<D>['plugin']">
      The current plugin supplied by the callback. Let the constructor or
      plugin infer it. Consumer code obtains its portal by passing the
      descriptor to `editor.plugin(MyPlugin)` or `useEditor().plugin(MyPlugin)`.
    </APIItem>
    <APIItem name="store" type="PluginStore<D>">
      Reads, updates, and subscribes to the current plugin's editor-local state.
      Named selectors are pure functions of that state.
    </APIItem>
    <APIItem name="viewStore" type="PluginViewStore<D>">
      Reads, updates, and subscribes to the current plugin's state in one view.
      The `api` factory and the plugin portal receive it, bound to the view
      they are built for.
    </APIItem>
    <APIItem name="viewStoreOf" type="PluginViewStoreOf<D>">
      Returns the current plugin's state in the view a read state or
      transaction runs in: a reader for a read `state`, a writer for a `tx`.
      `.extend` callbacks receive it instead of `viewStore`, because one plugin
      definition serves every view. It does not accept an editor.
    </APIItem>
  </APIAttributes>
</API>

The `formats` callback receives `PluginFormatAuthoringContext<D>` instead of
the general plugin context. It contains `defineFormats` and `schema`; it does
not expose `editor`, `store`, selection, metadata, or fields. Runtime mapping
callbacks receive frozen plugin state and the operation-specific registry,
schema, model, and diagnostic context.

For more detailed information on specific aspects of Plate plugins, refer to the individual guides on [Plugin Configuration](/docs/plugin), [Plugin Methods](/docs/plugin-methods), [Plugin Context](/docs/plugin-context), [Plugin Components](/docs/plugin-components), and [Plugin Shortcuts](/docs/plugin-shortcuts).

## Generic types

Use `DefinitionOf<typeof Plugin>` as the sole public way to extract a
descriptor's inferred definition.

<API name="GenericTypes">
  <APIAttributes>
    <APIItem name="D" type="BasePluginDefinition">
      The inferred definition contract, including `name`, `initialState`,
      `initialViewState`, `api`, `read`, `update`, selectors, dependencies, and
      schema inference.
    </APIItem>
  </APIAttributes>
</API>

Usage example:

```typescript
export type MyPluginState = {
  customOption: boolean;
};

export const MyPlugin = definePlugin("myPlugin", {
  initialState: {
    customOption: false,
  } satisfies MyPluginState,
  api: ({ store }) => ({
    getData: () => String(store.get("customOption")),
  }),
  update: ({ tx }) => ({
    run: () => tx.selection.collapse(),
  }),
});

type MyDefinition = DefinitionOf<typeof MyPlugin>;
```
