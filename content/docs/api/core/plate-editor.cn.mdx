`Editor` 是 `createEditor` 和 `useCreateEditor` 返回的编辑器类型。导入路径决定它是
无 React 依赖的编辑器还是 React 编辑器。两者都提供类型化插件 portal、`api`、
`editor.update()` 事务和编辑器内插件状态。

## 所有权

| 表面               | 所有者                | 说明                                                                                     |
| ------------------ | --------------------- | ---------------------------------------------------------------------------------------- |
| `Editor`      | `platejs/react` | React 编辑器类型，包含 Plate 插件 API、事务组、lifecycle/DOM 事件、render 和 hooks。     |
| `Editor`       | `platejs`       | 非 React 编辑器类型，用于服务端和静态编辑器路径。                                        |
| Plite primitives   | `platejs`      | `read`、核心 `api` 和事务/update 运行时。 |
| Core plugins       | `platejs`       | debug、HTML 解析、product codecs、length、node id、history、input rules 和基础段落行为。 |
| React core plugins | `platejs/react` | React 扩展、DOM 集成、event editor、navigation feedback 和 React paragraph plugin。      |

从与构造器相同的入口导入 `Editor` 类型。

## 编辑器形状

编辑器仍然是 Plite 编辑器。Plate 在这个形状上增加类型化插件访问、DOM service 和少量 Plate runtime 状态。

<API name="Editor">
  <APIAttributes>
    <APIItem name="id" type="string">
      编辑器实例 id。`createEditor` 会使用传入的 `id`、已有编辑器 id，或调用
      `nanoid()`。
    </APIItem>
    <APIItem name="read" type="Editor['read']">
      通过 `editor.read.children()` 读取当前文档子节点，通过
      `editor.read.selection()` 读取选区，通过 `editor.read.lastCommit()`
      读取最近发布的 commit。
    </APIItem>
    <APIItem name="api" type="Editor['api']">
      Core Plite API、显式编辑器级 API，以及按插件 name 推断的已安装插件 API。
    </APIItem>
    <APIItem name="update" type="Editor['update']">
      文档、选择、历史和插件命令的事务入口。
    </APIItem>
    <APIItem
      name="plugin"
      type="Editor['plugin']"
    >
      返回精确插件 descriptor 对应的 portal，用于访问插件
      API、read、update、schema 标识和 store。描述符提供推断类型。
    </APIItem>
    <APIItem name="runtime" type="Editor['runtime']">
      Plate 对外公开的 identity 和 lifecycle 状态。已编译插件注册表由 Plate
      私有管理。
    </APIItem>
  </APIAttributes>
</API>

## 运行时状态

React 和 DOM 运行时状态通过 Plite runtime API 读取。`editor.runtime` 只公开编辑器 identity 和 lifecycle 字段；已编译插件注册表属于 Plate 私有实现。

| 状态        | 读取路径                                                           | 设置者                                               |
| ----------- | ------------------------------------------------------------------ | ---------------------------------------------------- |
| composition | `editor.api.react.isComposing()`                                   | Plite React composition runtime。                    |
| focus       | `editor.api.react.isFocused()`                                     | Plite React focus runtime。                          |
| read-only   | `editor.read.view.isReadOnly()` 或 `editor.api.react.isReadOnly()` | `createEditor`、`<Plate>` 和 `<PlateContent>`。 |

| 字段            | 类型                          | 说明                                                 |
| --------------- | ----------------------------- | ---------------------------------------------------- |
| `userId`        | `string \| null \| undefined` | 通过编辑器选项传入的协作身份。                       |
| `isNormalizing` | `boolean \| undefined`        | Plate 执行 initial-value normalization 时为 `true`。 |

## 插件访问

将已安装的描述符传给 `editor.plugin(Plugin)`。TypeScript 会推断该插件的 API、
read、update 命令、schema 标识和编辑器内状态。在调用处保留描述符的推断类型。

```ts title="插件 API 和状态"
import { createEditor, defineBasePlugin } from 'platejs';

const PanelPlugin = defineBasePlugin('panel', {
  initialState: { open: false },
  api: ({ store }) => ({
    isOpen: () => store.get('open'),
  }),
});

const editor = createEditor({ plugins: [PanelPlugin] });
const panel = editor.plugin(PanelPlugin);

const open = panel.store.get('open');
const sameApi = editor.api.panel === panel.api;
```

`editor.api.panel` 和 `panel.api` 引用同一个不可变 API 对象。在具体编辑器中，
通过 `editor.read.<name>` 执行插件查询；需要描述符提供精确契约时，使用
`editor.plugin(Plugin).read`。

| 访问路径 | 用途 |
| --- | --- |
| `editor.plugin(Plugin).installed` | 插件可选时，先检查安装状态，再读取其他字段。 |
| `editor.plugin(Plugin).api` | 调用从描述符推断的插件服务。 |
| `editor.plugin(Plugin).read` | 针对当前编辑器状态执行插件查询。 |
| `editor.plugin(Plugin).update` | 执行插件拥有的事务命令。 |
| `editor.plugin(Plugin).store.get(key, ...args)` | 读取状态字段或命名 selector 的结果。 |
| `editor.plugin(Plugin).store.get()` | 读取完整的当前插件状态。 |
| `editor.plugin(Plugin).schema.type` | 读取元素描述符安装后的节点类型。 |
| `editor.plugin(Plugin).schema.key` | 读取主 mark 描述符安装后的属性键。 |

仅提供行为的描述符不公开 consumer `schema`。描述符查找会同时检查描述符家族和名称。

在 React 中，从 `platejs/react` 导入 `useEditorPlugin` 和 `usePluginStore`。
`useEditorPlugin(Plugin)` 提供推断的 portal。`usePluginStore(Plugin, key)` 或
`usePluginStore(Plugin, selector)` 让组件订阅插件状态。

### 运行时名称

名称仅在运行时确定时，使用 `editor.plugin(name)` 或 `useEditorPlugin(name)`。
这些查找用于安装检查、schema 标识读取和运行时查询分发。让 TypeScript 推断返回值。

允许插件缺失时，先检查 `.installed`。调用方明确需要元素插件时才读取
`.schema.type`，需要主 mark 时才读取 `.schema.key`。Schema 种类不匹配会抛出错误。
名称不能证明描述符家族，也不提供其精确的 API、update 和 store 类型契约；
调用方需要这些能力时，请传入描述符。

## 初始化

`useCreateEditor` 缓存 React 入口的 `createEditor` 构造结果。React 入口从
`initialState` 创建每个插件的编辑器内 store，并在用户插件前安装 React core plugins。

```tsx title="Create a typed editor"
import { useCreateEditor } from "platejs/react";
import { BoldPlugin } from "platejs/react";

export function useBasicEditor() {
  return useCreateEditor({
    plugins: [BoldPlugin],
    initialValue: [
      {
        type: "paragraph",
        children: [{ text: "Bold text is ready." }],
      },
    ],
  });
}
```

`createEditor` 做更底层的设置：

| 步骤                | 行为                                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Runtime 状态        | 保留 Plite `editor.id`，并初始化 `runtime.userId`。                                                                            |
| 插件访问            | 将已安装 API 发布到 `editor.api[name]`，并安装 descriptor 或 name 的 `plugin(...)` portal。                                |
| Core plugins        | 解析 core plugins，用相同 name 的自定义插件替换 core plugins，并解析 root plugin。                                             |
| Components          | 将 `components` 合并到 root-plugin component overrides。                                                                       |
| Normalization guard | 包装 `normalizeNode`，让 `editor.api.shouldNormalizeNode(entry)` 可以跳过一次 normalization。                                  |
| 初始值              | 除非 `skipInitialization` 为 `true`，否则通过运行时 update 路径初始化 value 和 selection。                                     |

`initialValue` 接受 Plate value 或同步返回 value 的函数。远程数据应在创建编辑器前加载。解码器需要已编译的插件模型时，使用回调形式。

## Core API

核心插件在用户插件之前解析。导航反馈是 React 编辑器的默认插件，可通过
`navigationFeedback: false` 禁用。其 API 使用 `useEditor()` 或
`useEditorPlugin()` 返回的已挂载编辑器。

<API name="Core plugin APIs">
  <APIMethods>
    <APIItem
      name="editor.api.debug.log"
      type="(message: string, type?: DebugErrorType, details?: any) => void"
    >
      debug logging 启用时记录 debug 消息。
    </APIItem>
    <APIItem
      name="editor.api.debug.info"
      type="(message: string, type?: DebugErrorType, details?: any) => void"
    >
      当前 log level 允许时记录 info 消息。
    </APIItem>
    <APIItem
      name="editor.api.debug.warn"
      type="(message: string, type?: DebugErrorType, details?: any) => void"
    >
      当前 log level 允许时记录 warning。
    </APIItem>
    <APIItem
      name="editor.api.debug.error"
      type="(message: unknown, type?: DebugErrorType, details?: any) => void"
    >
      开发环境默认抛出 `PlateError`。用 `DebugPlugin` 配置 logging 或
      `throwErrors`。
    </APIItem>
    <APIItem
      name="editor.api.html.deserialize"
      type="(options: { element: HTMLElement | string; collapseWhiteSpace?: boolean; defaultElementPlugin?: WithRequiredName }) => Descendant[]"
    >
      将 HTML 反序列化为 Plate nodes。HTML parser 插件会在 `text/html` paste
      路径调用它。
    </APIItem>
    <APIItem
      name="editor.api.navigation.flashTarget"
      type="(options: NavigationFlashTargetOptions) => boolean"
    >
      在发起调用的已挂载 React 视图中高亮元素，不修改文档或选择。
    </APIItem>
    <APIItem name="editor.api.navigation.clear" type="() => boolean">
      清除当前已挂载视图的反馈，并返回是否存在活动目标。
    </APIItem>
  </APIMethods>
</API>

## Core 事务

mutation 通过 `editor.update` 执行。Core Plite 命令位于 transaction 对象上；
插件通过 constructor 的 `update` 字段添加 key 对应的命令。

<API name="Core transactions">
  <APITransforms>
    <APIItem
      name="editor.update(policy).value.replace(input)"
      type="(input: SnapshotInput) => void"
    >
      通过一次配置后的 Plite update 替换主 children、命名 roots、持久化 meta，
      并可同时设置 selection。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.nodes.insert(node, options))"
      type="(node: Node, options?: NodeInsertNodesOptions) => void"
    >
      通过 Plite node transaction group 插入一个 node 或 fragment。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.nodes.set(props, options))"
      type="(props: Partial<Node>, options?: NodeSetNodesOptions) => void"
    >
      通过 Plite node transaction group 更新匹配节点。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.marks.toggle(key, value))"
      type="(key: string, value?: unknown) => void"
    >
      通过 Plite mark transaction group 切换 inline mark。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.selection.select(location))"
      type="(location: Location) => void"
    >
      通过 Plite selection transaction group 更新当前 selection。
    </APIItem>
  </APITransforms>
</API>
