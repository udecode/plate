`Editor` 是 `createEditor` 和 `useCreateEditor` 返回的 React 编辑器类型。它在基础 Plite 编辑器之上添加类型化插件 portal、类型化 `api`、类型化 `editor.update()` 事务、DOM service 和 editor-local plugin store。

## 所有权

| 表面               | 所有者                | 说明                                                                                     |
| ------------------ | --------------------- | ---------------------------------------------------------------------------------------- |
| `Editor`      | `platejs/react` | React 编辑器类型，包含 Plate 插件 API、事务组、lifecycle/DOM 事件、render 和 hooks。     |
| `Editor`       | `platejs`       | 非 React 编辑器类型，用于服务端和静态编辑器路径。                                        |
| Plite primitives   | `platejs`      | `children`、`selection`、`operations`、核心 `api` 和事务/update 运行时。                 |
| Core plugins       | `platejs`       | debug、HTML 解析、product codecs、length、node id、history、input rules 和基础段落行为。 |
| React core plugins | `platejs/react` | React 扩展、DOM 集成、event editor、navigation feedback 和 React paragraph plugin。      |

React 页面或组件中使用 `Editor`。需要 headless 编辑器时，从 `createEditor` 使用 `Editor`。

## 编辑器形状

编辑器仍然是 Plite 编辑器。Plate 在这个形状上增加类型化插件访问、DOM service 和少量 Plate runtime 状态。

<API name="Editor">
  <APIAttributes>
    <APIItem name="id" type="string">

      `nanoid()`。
    </APIItem>
    <APIItem name="children" type="Value">
      当前文档值。
    </APIItem>
    <APIItem name="selection" type="Range | null">

    </APIItem>
    <APIItem name="operations" type="Operation[]">

    </APIItem>
    <APIItem name="api" type="Editor['api'] & CorePluginApi">

    </APIItem>
    <APIItem name="update" type="Editor['update']">
      文档、选择、历史和插件命令的事务入口。
    </APIItem>

## 运行时状态

React 和 DOM 运行时状态通过 Plite runtime API 读取。`editor.runtime` 只公开编辑器 identity 和 lifecycle 字段；已编译插件注册表属于 Plate 私有实现。

| 状态        | 读取路径                                                           | 设置者                                               |
| ----------- | ------------------------------------------------------------------ | ---------------------------------------------------- |
| composition | `editor.api.react.isComposing()`                                   | Plite React composition runtime。                    |
| focus       | `editor.api.react.isFocused()`                                     | Plite React focus runtime。                          |
| read-only   | `editor.read.view.isReadOnly()` 或 `editor.api.react.isReadOnly()` | `createEditor`、`<Plate>` 和 `<PlateContent>`。 |

| 字段            | 类型                          | 说明                                                 |
| --------------- | ----------------------------- | ---------------------------------------------------- |
| `userId`        | `string \| null \| undefined` | 通过编辑器选项传入的协作身份。                       |
| `isNormalizing` | `boolean \| undefined`        | Plate 执行 initial-value normalization 时为 `true`。 |

## 插件访问

在具体编辑器中，通过 `editor.api.<name>` 调用已安装插件的 query 和 service。
当通用代码需要精确的插件 API、read、update 命令、name 或 store 时，将描述符传给
`editor.plugin(plugin)`。根路径和作用域路径引用同一个不可变 API 对象。

```ts title="Plugin API access"
editor.api.table.getColumnCount();

// 使用精确描述符的通用包代码：
editor.plugin(TablePlugin).api.getColumnCount();
```

```ts title="Plugin state access"
import { definePlatePlugin } from 'platejs/react';

const PanelPlugin = definePlatePlugin('panel', {
  initialState: { open: false },
});
const panel = editor.plugin(PanelPlugin);

const open = panel.store.get('open');
panel.store.set({ open: !open });
```

下表中的 `P` 是精确插件 descriptor type，`DefinitionOf<P>` 是其 normalized
public definition。

| Helper                                   | 类型                                                                                           | 用途                                                                       |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `api[name]`                              | `InferOwnApi<DefinitionOf<P>>`                                                                 | 从具体推断编辑器调用已安装插件的 query 和 service。                        |
| `plugin(plugin)`                         | `<P extends AnyBasePlugin & PluginReference>(plugin: P) => BasePluginPortal<DefinitionOf<P>>`  | 打开精确插件 descriptor 的类型化 consumer portal。                         |
| `plugin(plugin).installed`               | `boolean`                                                                                      | 插件可选时，先检查是否已安装，再读取其他 portal 字段。                     |
| `plugin(plugin).api`                     | `InferOwnApi<DefinitionOf<P>>`                                                                 | 从通用代码或精确 descriptor 调用同一个插件 API。                           |
| `plugin(plugin).read`                    | `InferOwnRead<DefinitionOf<P>>`                                                                | 针对当前编辑器状态运行一个插件拥有的 read。                                |
| `plugin(plugin).update`                  | `InferOwnUpdate<DefinitionOf<P>>`                                                              | 执行一个插件拥有的 update 命令。                                           |
| `plugin(plugin).store.get(key, ...args)` | `(key, ...args) => value`                                                                      | 读取一个 state 字段或命名 selector 结果。                                  |
| `plugin(plugin).store.get()`             | `() => InferPluginStoreState<DefinitionOf<P>>`                                                 | 读取完整的当前插件 state。                                                 |
| `plugin(plugin).store.set(partial)`      | `(partial) => void`                                                                            | 合并 state 字段。                                                          |
| `plugin(plugin).store.set(recipe)`       | `(draft) => void`                                                                              | 通过 draft recipe 更新 state。                                             |
| `plugin(plugin).name`、`.inject`、`.render`、`.initialState` | 已解析的 descriptor 字段 | 直接读取 override 和配置后的 compiled descriptor 字段。                   |
| `plugin(plugin)`                         | `(plugin: PluginReference \| string) => AnyBasePluginPortal`                                    | 为 descriptor 或动态 name 打开擦除类型的 portal；具体 descriptor 使用上方精确 overload。 |

React 组件使用 `usePluginStore(plugin, key)` 或
`usePluginStore(plugin, selector)` 订阅变化，不要在 render 中直接读取 portal。
`useEditorPlugin` 接受相同的 descriptor 或运行时 name 输入。运行时 name 适用于动态值，或接受任意同名已安装 descriptor 的 family-agnostic 插件槽。它返回擦除类型的 portal；允许插件缺失时，读取其他字段前先检查 `.installed`。

## 初始化

`createEditor` 用 React 默认配置包装 `createEditor`。它从 `initialState` 创建每个插件的
editor-local store，并把 React core plugins 插入到用户插件前面。

```tsx title="Create a typed editor"
import { useCreateEditor } from "platejs/react";
import { BoldPlugin } from "platejs/react";

export function useBasicEditor() {
  return useCreateEditor({
    plugins: [BoldPlugin],
    initialValue: [
      {
        type: "paragraph",
        children: [{ text: "Bold text is ready." }],
      },
    ],
  });
}
```

`createEditor` 做更底层的设置：

| 步骤                | 行为                                                                                                                           |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Runtime 状态        | 保留 Plite `editor.id`，并初始化 `runtime.userId`。                                                                            |
| 插件访问            | 将已安装 API 发布到 `editor.api[name]`，并安装 descriptor 或 name 的 `plugin(...)` portal。                                |
| Core plugins        | 解析 core plugins，用相同 name 的自定义插件替换 core plugins，并解析 root plugin。                                             |
| Components          | 将 `components` 合并到 root-plugin component overrides。                                                                       |
| Normalization guard | 包装 `normalizeNode`，让 `editor.api.shouldNormalizeNode(entry)` 可以跳过一次 normalization。                                  |
| 初始值              | 除非 `skipInitialization` 为 `true`，否则通过运行时 update 路径初始化 value 和 selection。                                     |

`initialValue` 接受 Plate value 或同步返回 value 的函数。远程数据应在创建编辑器前加载。解码器需要已编译的插件模型时，使用回调形式。

## Core API

这些 API 存在于每个 Plate editor 上，因为 core plugins 总是在用户插件之前解析。

<API name="Core plugin APIs">
  <APIMethods>
    <APIItem
      name="editor.api.debug.log"
      type="(message: string, type?: DebugErrorType, details?: any) => void"
    >
      debug logging 启用时记录 debug 消息。
    </APIItem>
    <APIItem
      name="editor.api.debug.info"
      type="(message: string, type?: DebugErrorType, details?: any) => void"
    >
      当前 log level 允许时记录 info 消息。
    </APIItem>
    <APIItem
      name="editor.api.debug.warn"
      type="(message: string, type?: DebugErrorType, details?: any) => void"
    >
      当前 log level 允许时记录 warning。
    </APIItem>
    <APIItem
      name="editor.api.debug.error"
      type="(message: unknown, type?: DebugErrorType, details?: any) => void"
    >
      开发环境默认抛出 `PlateError`。用 `DebugPlugin` 配置 logging 或
      `throwErrors`。
    </APIItem>
    <APIItem
      name="editor.api.html.deserialize"
      type="(options: { element: HTMLElement | string; collapseWhiteSpace?: boolean; defaultElementPlugin?: WithRequiredName }) => Descendant[]"
    >
      将 HTML 反序列化为 Plate nodes。HTML parser 插件会在 `text/html` paste
      路径调用它。
    </APIItem>
    <APIItem
      name="editor.api.react.refreshDecorations"
      type="(options?: PliteProjectionStoreRefreshOptions) => void"
    >
      外部状态变更后刷新 React decorations。
    </APIItem>
    <APIItem
      name="editor.api.navigation.activeTarget"
      type="() => NavigationFeedbackTarget | null"
    >
      读取当前 navigation feedback target；如果存储的 target
      已无法解析，会清空它。
    </APIItem>
    <APIItem name="editor.api.navigation.clear" type="() => void">
      清空当前 navigation feedback target。
    </APIItem>
    <APIItem
      name="editor.api.navigation.isTarget"
      type="(path: Path) => boolean"
    >
      检查 path 是否匹配当前 navigation feedback target。
    </APIItem>
  </APIMethods>
</API>

## Core 事务

mutation 通过 `editor.update` 执行。Core Plite 命令位于 transaction 对象上；
插件通过 constructor 的 `update` 字段添加 key 对应的命令。

<API name="Core transactions">
  <APITransforms>
    <APIItem
      name="editor.update(policy).value.replace(input)"
      type="(input: SnapshotInput) => void"
    >
      通过一次配置后的 Plite update 替换主 children、命名 roots、持久化 meta，
      并可同时设置 selection。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.nodes.insert(node, options))"
      type="(node: Node, options?: NodeInsertNodesOptions) => void"
    >
      通过 Plite node transaction group 插入一个 node 或 fragment。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.nodes.set(props, options))"
      type="(props: Partial<Node>, options?: NodeSetNodesOptions) => void"
    >
      通过 Plite node transaction group 更新匹配节点。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.marks.toggle(key, value))"
      type="(key: string, value?: unknown) => void"
    >
      通过 Plite mark transaction group 切换 inline mark。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.selection.select(location))"
      type="(location: Location) => void"
    >
      通过 Plite selection transaction group 更新当前 selection。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.navigation.clear())"
      type="() => void"
    >
      清空 navigation feedback state。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.navigation.flashTarget(options))"
      type="(options: NavigationFlashTargetOptions) => boolean"
    >
      暂存一个 target，让组件渲染 navigation feedback。
    </APIItem>
    <APIItem
      name="editor.update((tx) => tx.navigation.navigate(options))"
      type="(options: NavigationNavigateOptions) => boolean"
    >
      导航到 target，并通过 navigation feedback 插件闪烁目标。
    </APIItem>
  </APITransforms>
</API>
