### `EditorApplicationSchema`

定义应用拥有的 schema policy。可选字段包括：

- `root`：带有显式正整数 `min` 的主 root `SchemaContent`。描述符来源必须匹配已安装的
  插件系列。`schema.content.elements` 的第一个来源是默认值。
- `overrides`：针对已安装元素 schema 和现有属性目标的最终应用覆盖。
- `properties`：应用拥有的 schema 属性。
- `id` 和 `version`：成对出现的持久化谱系；必须同时提供或同时省略。

省略 `root` 时保留 Plate 标准的最少一个段落语法。Root 语法参与编译指纹和生成的值
合约。

### `defineDocumentMigrations`

为命名应用 schema 定义一条目标版本迁移链。每个数字 key 表示对应步骤生成的 schema
版本。

```ts
import { defineDocumentMigrations } from 'platejs/migrations';

import { fingerprint as v1Fingerprint } from './migrations/v2-add-section/from';
import { fingerprint as v2Fingerprint } from './migrations/v3-add-caption/from';

const migrations = defineDocumentMigrations(EditorSchema, {
  sourceFingerprints: {
    1: v1Fingerprint,
    2: v2Fingerprint,
  },
  steps: {
    2: migrateDocumentV2,
    3: migrateDocumentV3,
  },
  unversioned: 1,
});
```

`sourceFingerprints` 将每个受支持的历史 envelope 版本绑定到生成的 schema 指纹。
`unversioned` 为没有持久化 schema 身份的原始文档指定显式源版本。缺失中间步骤或历史
身份漂移都会报错。

### `migrateDocument`

对一个完整文档运行所有必需迁移步骤，但不将结果发布到编辑器。编辑器运行时加载和
`plate migrate run` 使用同一个 runner。

```ts
import { migrateDocument } from 'platejs/migrations';

const result = migrateDocument(persisted, {
  editor,
  migrations: EditorMigrations,
});
```

结果包含 `document`、映射后的 `selection`、`source`、`target` 和升序 `applied` 版本
列表。schema 谱系不同、源版本更新或指纹漂移都会报错。

## 核心插件

### `DebugPlugin`

提供具有可配置日志级别和错误处理功能的调试功能。

查看[调试](/docs/debugging)了解更多详情。

### `ElementIdPlugin`

为所有 block 和 inline 元素添加持久化字符串 ID。该插件是可选的，不会为文本
节点生成 ID。

```ts
const editor = createPlateEditor({
  plugins: [ElementIdPlugin],
});

const elementId = editor.plugin(ElementIdPlugin);
const key = editor.key(element);
const id = elementId.read.id(key);
const entry = id ? elementId.read.entry(id) : undefined;
```

通过 `initialState.generateId` 替换默认的完整长度 `nanoid()` 生成器。已存储输入
缺少 ID、包含旧数字 ID，或需要通过 `sourceKey` 规范化旧属性时，使用
`migrateElementIds(value, options)`。

### `ElementStatePlugin`

在 Plite 之上扩展 Plate 编辑器行为。

`ElementStatePlugin` 提供
`editor.plugin(ElementStatePlugin).api.isEmpty(element)`。它检查元素自身的属性状态，而不是文本内容。默认只忽略
`type` 和通过 `role: "metadata"`
声明的已编译元素属性；任何其他属性都表示该元素带有状态。`ElementIdPlugin`
将持久化元素 ID 属性声明为元数据。

```tsx
const elementState = editor.plugin(ElementStatePlugin);

elementState.api.isEmpty({
  children: [{ text: "" }],
  type: "paragraph",
}); // true

elementState.api.isEmpty({
  children: [{ text: "" }],
  listType: "bulleted",
  type: "paragraph",
}); // false

const CustomMetadataPlugin = defineBasePlugin("customMetadata", {
  schema: {
    properties: {
      customId: schema.elementProperty(property.string(), {
        role: "metadata",
        target: target.group("block"),
      }),
    },
  },
});
```
