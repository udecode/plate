应用代码通过 `editor.update` 修改文档。序列化 `commit.changes`，并通过
`tx.changes.apply` 导入规范 `DocumentChange`。

## 适配外部内容

解析后的内容用 `ContentSlice` 表示。单次更新会运行已安装的粘贴命令策略。

```ts
import { ContentSlice } from 'platejs';

editor.update.slice.replace(ContentSlice.closed([
  { type: 'paragraph', children: [{ text: 'Paste' }] },
]));
```

`editor.read.slice.fit(slice, options)` 返回未发布的 `TransactionSpec` 或
`false`。它与回调中的 `tx.slice.replace`、`tx.fragment.replace` 一样，
直接进行规范适配，不运行命令处理器或粘贴落点读取。

## 规范变更

```ts
import { DocumentChange } from 'platejs';

const change = DocumentChange.fromJSON(message.change);
editor.update({ tags: 'remote-import' }, (tx) => {
  tx.changes.apply(change);
});
```

| 方法 | 用途 |
| --- | --- |
| `apply(value)` | 将变更应用到原始文档。 |
| `compose(other)` | 组合顺序变更。 |
| `invert(value)` | 计算精确逆变更。 |
| `mapPosition(position, options)` | 映射位置及方向关联（解码后的 v4 变更需传 `base`）。 |
| `iterChangedRanges(visit, options)` | 遍历所有受影响根中的范围（解码后的 v4 变更需传 `base`）。 |
| `toJSON()` / `fromJSON(json)` | 序列化与解码版本 4 JSON。 |

主文档的根标识为 `null`；具名根使用字符串。版本 4 JSON 使用可选的
`steps`（按元素 ID 寻址的步骤）和 `records` 字段。提交中的 `changes`、`inverseChanges`、`effects`、
`tags`、`selectionBefore`、`selectionAfter` 和 `changed` 共同描述原子更新。

更新的每个步骤都会在提交发布前调用插件的 `on.transactionChange` 处理器。
`changed.removed(root)` 列出该步骤从文档根中移除的节点：`key`、步骤前的 `node`，以及节点在步骤结果中留下的空位 `path`。
移动、拆分或包裹会保留节点的 key，被解包或合并的节点的子节点也会保留。
每个步骤只报告自己的移除；整个提交新增或移除的 key 用 `commit.changed.nodeKeys("presence")` 查询。

`commit.changed.anchors()` 返回本次提交改变了存储值的持久锚点（包含撤销与重做恢复），但不包含在提交监听器运行前已释放的锚点；视图提交返回存储提交的锚点列表。
`commit.changed.rootPlacements()` 返回 `read.roots()` 中位置发生变化的具名根：所有者发生变化的根（例如删除画板或交换 `childRoots`），以及 `top` 移入另一顶层页面块的根（例如画板移入容器块）。仅在所有者上方插入或删除、只平移路径时不会列出任何根。

适配器在同一更新中导入变更与共享 effect。运行时 `NodeKey` 不作为远程
身份；并发、传输、持久化与在线状态由[协作适配器](/docs/yjs)负责。
