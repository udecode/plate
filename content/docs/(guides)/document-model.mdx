---
title: Plate Document Model
description: The canonical JSON contract for Plate documents, nodes, schemas, migrations, and format adapters.
---

Plate stores editor-native JSON. Plate owns the tree contract; Plate plugins add schema-checked properties and format mappings project documents to external formats.

## Core tree

~~~ts
type Text = { text: string };

type Element = {
  type: string;
  children: Array<Element | Text>;
};

type EditorDocumentValue = {
  children: Element[];
  roots?: Record<string, Element[]>;
  meta?: Record<string, unknown>;
};
~~~

Feature properties stay flat on their owning node. Runtime NodeKey values are editor state and are never serialized.

A document's top level holds only `children`, `roots`, `meta` and `records`. `records` holds the keyed record sets plugins declare, such as review records. Every load path refuses any other top-level field, so store application data in `meta`.

## Application schema

Persistence uses a named envelope:

~~~ts
type PersistedDocumentInput = {
  document: EditorDocumentValue;
  schema: { id: string; version: number; fingerprint: string };
  selection?: Selection | 'start' | 'end';
};
~~~

The application schema decides which element types, marks, properties, content, and roots are valid. Omit `root` for Plate's standard nonempty paragraph grammar. Declare a custom primary root with the existing descriptor-aware content builders:

~~~ts
const EditorSchema = {
  root: schema.content.element(SectionPlugin, { min: 1 }),
} as const;
~~~

The minimum is required and must be a positive integer. The descriptor must match an installed plugin, and the first descriptor in `schema.content.elements` is the default. Root grammar participates in the schema fingerprint and generated `Value`; cardinality remains runtime validation law.

`defineDocumentMigrations` binds an ascending chain to the application schema. Runtime loading and the CLI call the same `migrateDocument` runner before schema fitting. Increment a named schema's version and migrate stored documents when its root grammar changes. A step's document holds only `children`, `roots`, `meta` and `records`. Any other stored top-level field arrives in the step's `legacy` record, the step lifts it into `meta`, and `migrateDocument` refuses a field no step lifted.

`migrateV54` converts the frozen v53.3.6 profile to v54, including the final AST contracts and one newline-bearing text child per code block. Links and media whose stored URL the current schema rejects keep their label, caption, alt text or file name as ordinary content. Stored mention, emoji, slash and footnote inputs become their trigger and typed query as ordinary text. A line height stored as text becomes a number, so `"107%"` becomes `1.07` and `"150%"` or `"1.5em"` becomes `1.5`. The step drops a stored `"normal"`, a length such as `"12pt"`, zero, a negative number and unreadable text without a report, so those blocks follow the theme. Pending v53 suggestions become review changes. The step refuses a document when the target schema reshapes a suggested node, or when the document with every pending change rejected would not fit the target, such as a suggestion that removed a property the target does not declare. Accept or reject those suggestions in Plate v53 before you upgrade.

`migrateListIdentity` gives each list item a stored `listId`, one per run of adjacent items, so documents saved without list ids keep their numbers. Register it under the first schema version that includes the list plugin's `listId` and `listLevels`.

### Saved font weights

Bold owns font weight, and Plate has no weight mark. `migrateV54` converts no
saved `fontWeight`, because v53 drew a saved weight on top of bold. A target
schema without a `fontWeight` text property refuses each saved weight with
`Unknown text property "fontWeight" in closed editor schema.`, on a text leaf,
in a saved selection's marks and in a pending suggestion that sets or removes a
weight.

An app with saved weights takes one of two ways out:

- Declare its own `fontWeight` text property. Every value loads unchanged, and
  the app owns that second record of weight beside `bold`.
- Strip the weights before `migrateDocument`. The pre-pass below keeps whether
  v53 drew the text bold. `bold`, `bolder` and 600 to 1000 become `bold`, in any
  letter case, and `normal`, `lighter` and 1 to 599 drop both. It refuses a
  weight it cannot read, such as `inherit`, a CSS variable or `0x2bc`. In a raw
  v53 value it refuses a light weight inside `h1` to `h6` or `th`, because v53
  drew that text lighter than the block's bold. It also refuses a
  weighted leaf with a pending format change, and any pending change to the
  weight itself, because either one, once converted, would erase the drawn bold
  when someone rejects it.

~~~ts
type Json = Record<string, unknown>;

const readWeight = (weight: unknown) => {
  const value = String(weight).trim().toLowerCase();

  if (value === 'bold' || value === 'bolder') return 'heavy';
  if (value === 'normal' || value === 'lighter') return 'light';
  if (!/^\+?(\d+|\d*\.\d+)(e[+-]?\d+)?$/.test(value)) return null;

  const number = Number(value);

  if (number >= 1 && number <= 1000) return number >= 600 ? 'heavy' : 'light';

  return null;
};

const boldBlocks = new Set(['h1', 'h2', 'h3', 'h4', 'h5', 'h6', 'th']);

const touchesWeight = (change: Json) =>
  change.key === 'fontWeight' ||
  ['properties', 'newProperties'].some((key) =>
    Object.hasOwn(change[key] ?? {}, 'fontWeight')
  );

const stripLeaf = (node: Json, mayDrawBold: boolean): Json => {
  const pending = [
    ...Object.entries(node)
      .filter(([key]) => key.startsWith('suggestion_'))
      .map(([, value]) => value as Json)
      .filter((value) => value?.type === 'update'),
    ...((Array.isArray(node.authored) ? node.authored : []) as Json[]).filter(
      (mark) => mark?.kind === 'format'
    ),
  ];

  if (
    pending.length > 0 &&
    (Object.hasOwn(node, 'fontWeight') || pending.some(touchesWeight))
  ) {
    throw new Error(
      'Settle format changes on weighted text before the upgrade.'
    );
  }
  if (!Object.hasOwn(node, 'fontWeight')) return node;

  const { bold: _bold, fontWeight, ...rest } = node;
  const weight = readWeight(fontWeight);

  if (!weight || (weight === 'light' && mayDrawBold)) {
    throw new Error('Bold cannot keep how v53 drew this font weight.');
  }

  return weight === 'heavy' ? { ...rest, bold: true } : rest;
};

const stripTree = (node: Json, mayDrawBold: boolean): Json => {
  if (typeof node.text === 'string') return stripLeaf(node, mayDrawBold);

  const inside = mayDrawBold || boldBlocks.has(node.type as string);
  const next = { ...node };

  for (const key of ['children', 'caption']) {
    if (Array.isArray(node[key])) {
      next[key] = (node[key] as Json[]).map((child) =>
        stripTree(child, inside)
      );
    }
  }

  return next;
};

const stripNode = (node: Json) => stripTree(node, false);

migrateDocument(value.map(stripNode), { migrations, source: 53 });
~~~

A raw v53 value takes `source: 53`. A persisted envelope maps
`document.children`, each array in `document.roots` and the saved selection's
`marks`, keeps `document.meta` and every other field as stored, and omits
`source`. The envelope form refuses every light weight, the saved selection's
included, because an app built from v2 source names its own block types and the
pre-pass cannot tell which of them draw bold:

~~~ts
const stripEnvelope = (stored: Json): Json => {
  const document = { ...(stored.document as Json) };
  const selection = stored.selection as Json | null | undefined;

  const strip = (node: Json) => stripTree(node, true);

  document.children = (document.children as Json[]).map(strip);
  if (document.roots) {
    document.roots = Object.fromEntries(
      Object.entries(document.roots as Record<string, Json[]>).map(
        ([name, children]) => [name, children.map(strip)]
      )
    );
  }

  return {
    ...stored,
    document,
    ...(selection?.marks
      ? {
          selection: {
            ...selection,
            marks: stripLeaf(selection.marks as Json, true),
          },
        }
      : {}),
  };
};

migrateDocument(stripEnvelope(stored) as PersistedDocumentInput, {
  migrations,
});
~~~

A weighted leaf inside a pending insertion or removal converts, because
accepting or rejecting it keeps whether v53 drew it bold.

Markdown can hold weights too, as `<span style="font-weight: bold;">` spans.
No plugin claims a weight span. In an editor with a style plugin, a span that
holds only a weight refuses the parse, and a weight beside another style drops
without a report. Rewrite those spans before parsing, or keep an app plugin that
declares `fontWeight` with its Markdown mapping.

## Representative feature shapes

Plate packages own local node shapes; the consuming application's plugin tuple and schema determine its complete grammar. Use `plate generate` when an application needs an exact committed `Value` type.

~~~ts
type HeadingElement = {
  type: 'heading';
  level: 1 | 2 | 3 | 4 | 5 | 6;
  children: Text[];
};

type CodeBlockElement = {
  type: 'codeBlock';
  language?: string;
  children: [Text];
};

type TableElement = {
  type: 'table';
  columnWidths?: Array<number | null>;
  marginLeft?: number;
  children: TableRowElement[];
};

type TableRowElement = {
  type: 'tableRow';
  height?: number;
  children: TableCellElement[];
};

type TableCellElement = {
  type: 'tableCell';
  backgroundColor?: string;
  borders?: Partial<Record<
    'top' | 'right' | 'bottom' | 'left',
    { color?: string; style?: string; width?: number }
  >>;
  colSpan?: number;
  rowSpan?: number;
  header?: boolean;
  children: Element[];
};

type ListItemProperties = {
  listType: 'bulleted' | 'numbered' | 'task';
  listStyle?: string;
  listStart?: number;
  listRestart?: number;
  checked?: boolean;
  indent?: number;
};

type DateElement = {
  type: 'date';
  value: string;
  children: Text[];
};

type MentionElement = {
  type: 'mention';
  ref: string;
  label?: string;
  children: Text[];
};

type FootnoteReferenceElement = {
  type: 'footnoteReference';
  ref: string;
  children: Text[];
};

type EquationElement = {
  type: 'equation' | 'inlineEquation';
  latex: string;
  children: Text[];
};

type ImageElement = {
  type: 'image';
  url: string;
  naturalWidth?: number;
  naturalHeight?: number;
  children: Text[];
};

type VideoElement = {
  type: 'video';
  url: string;
  provider?: string;
  children: Text[];
};
~~~

listStart is conditional author intent: it applies only while the item is first in its numbered sequence and remains stored while ignored. listRestart forces a new sequence at that item. editor.read.list.ordinal(element) derives display numbers; ordinary edits do not rewrite following nodes.

List starts and restarts are signed safe integers. Element `id` identifies one persisted node occurrence; `ref` associates nodes or external entities; live runtime identity remains `NodeKey`.

Table column width has one owner: TableElement.columnWidths. HTML cell widths normalize into that array during import; `null` records an unknown imported width without pretending the column is zero pixels wide.

Image naturalWidth and naturalHeight store source-image geometry; media width stores the user-selected rendered width. Media captions are direct children. An upload draft persists `{ type: 'upload', kind, children }` in Plate JSON; its `File`, task, progress, and failure remain editor state. Completion stores the durable URL on an ordinary media node. External HTML, Markdown, and static output omit unresolved drafts.

## Standards relationship

| Model | Plate relationship |
| --- | --- |
| Slate | Same practical descendant shape: text leaves and elements with children. Plate adds a compiled application schema. |
| ProseMirror | Same schema-first discipline. Plate keeps flat editor-native JSON. |
| UNIST | Conceptual tree vocabulary only. Plate does not require position or data fields. |
| MDAST | External Markdown AST. Format mappings map `heading.level` to `depth` and `codeBlock.language` to `lang`. |
| Portable Text | A portability reference, not Plate storage. Plate keeps nested editor nodes and live selection semantics. |
| Block Protocol | A block embedding protocol, not a rich-text AST contract. |

Format mappings and format-owned adapters map this document contract to external syntax.

## Structural constraints

Roots contain blocks. An element contains block children or inline/text children;
its compiled schema chooses the allowed grammar. An element whose content admits
text is never left empty, so an emptied line keeps one empty text as its
anchor, and a void keeps the empty text inside it. Content that admits only
blocks may be empty. Adjacent text leaves with the same properties merge, and
text spacing around inline nodes supplies valid caret positions.

An empty line stores no formatting. Marks for text typed at an empty caret come
from the selection's pending marks, so typing in an emptied bold line stays bold
while the caret is there. Once the caret leaves or the document reloads, the line
is plain.
`createEditor` loads its initial value in this canonical form, merging, spacing
and anchoring texts as an edit would.

Marks are schema-declared properties on text nodes. Decorations can split a text
node into rendered leaf segments without changing those persisted properties.
Use [Schema](/docs/schema) for validation and fitting, and
[Editing Behavior](/docs/editing-behavior#normalize-behavior) for semantic
corrections after schema-valid writes.

## Helper namespaces

Import `NodeApi`, `ElementApi`, `TextApi`, `PathApi`, `PointApi`, `RangeApi`, or
`SelectionApi` from `platejs` for pure tree checks and location math. Inside
editor callbacks, grouped `state` and `tx` methods also understand the active
root, schema, and draft.

```ts
import { ElementApi, NodeApi } from 'platejs';

const label = NodeApi.string(element);
const isElement = ElementApi.isElement(value);
const link = editor.read.nodes.above({ type: 'link' });
```

Use a live node directly as a supported `at` target when a component already
owns it. Use [anchors](/docs/api/anchor) when a position must follow later edits.
