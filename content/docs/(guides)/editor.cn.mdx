本指南涵盖Plate编辑器的配置选项，包括基础设置、插件管理和高级配置技巧。

## 基础编辑器配置

创建基础Plate编辑器可以使用`createPlateEditor`函数，或在React组件中使用`usePlateEditor`：

```ts
import { createPlateEditor } from 'platejs/react';

const editor = createPlateEditor({
  plugins: [H1Plugin],
});
```

### 初始值

设置编辑器的初始内容：

```ts
const editor = createPlateEditor({
  initialValue: [
    {
      type: 'paragraph',
      children: [{ text: '你好，Plate!' }],
    },
  ],
});
```

当一个编辑器拥有内容根或其他命名区域时，传入包含 `children`、`roots` 和持久化
`meta` 的 `EditorDocumentValue`。Plate 通过 `onValueChange` 返回同一完整结构。

也可以使用HTML字符串和关联插件初始化编辑器：

```ts
const editor = createPlateEditor({
  plugins: [HtmlPlugin, BoldPlugin, ItalicPlugin],
  initialValue: ({ editor }) =>
    editor.api.html.deserialize({
      element: '<p>这是<b>加粗</b>和<i>斜体</i>文本！</p>',
    }),
});
```

支持HTML字符串反序列化的完整插件列表，请参阅[插件反序列化规则](/docs/html#plugin-deserialization-rules)部分。

### Schema 身份

Plate 根据已安装插件编译文档 schema。普通编辑器省略 `schemaIdentity` 即可。
`editor.read.schema.identity()` 返回带有精确编译指纹的派生身份：

```ts
const editor = createPlateEditor({
  plugins: [H1Plugin],
});

editor.read.schema.identity();
// { kind: 'derived', fingerprint: '...' }
```

当文档用于持久化、历史序列化、schema 迁移或协作节点协商时，传入
`schemaIdentity: { id, version }`。这会创建命名谱系，而指纹仍只取决于编译后的
schema：

```ts
const editor = createPlateEditor({
  plugins: [H1Plugin],
  schemaIdentity: { id: 'acme-document', version: 3 },
});

editor.read.schema.identity();
// { kind: 'named', id: 'acme-document', version: 3, fingerprint: '...' }
```

命名谱系的 schema 语义变化时递增 `version`。同一 ID 和版本对应不同指纹时，
Plate 会将其视为身份不匹配。

### 异步初始值

如果需要异步获取初始值（例如从 API），可以使用 `skipInitialization` 选项，并在数据就绪后用一次 `editor.update(...)` 初始化内容：

```tsx
function AsyncEditor() {
  const [initialValue, setInitialValue] = React.useState();
  const [loading, setLoading] = React.useState(true);
  const editor = usePlateEditor({
    skipInitialization: true,
  });

  React.useEffect(() => {
    // 模拟异步获取
    setTimeout(() => {
      setInitialValue([
        {
          type: 'paragraph',
          children: [{ text: '异步加载的值！' }],
        },
      ]);
      setLoading(false);
    }, 1000);
  }, []);

  React.useEffect(() => {
    if (!loading && initialValue) {
      editor.update((tx) => {
        tx.value.replace({ children: initialValue });
        const end = tx.points.end([]);

        if (end) tx.selection.set(end);
      });
    }
  }, [loading, initialValue, editor]);

  if (loading) return <div>加载中…</div>;

  return (
    <Plate editor={editor}>
      <EditorContainer>
        <Editor />
      </EditorContainer>
    </Plate>
  );
}
```

这种模式适用于需要等待数据才能初始化编辑器的情况，例如从服务器或数据库加载内容时。

### 添加插件

通过`plugins`数组添加插件：

```ts
const editor = createPlateEditor({
  plugins: [H1Plugin, ListPlugin],
});
```

### 精确的生成编辑器类型

原始插件数组会推断插件 API、read、update、store 和单个元素结构。当应用还需要
整个插件图对应的精确递归 `Value` 时，使用生成的编辑器 contract。

在一个源文件中定义封闭的应用编辑器：

```tsx title="src/editor/editor-definition.tsx"
import { H1Plugin } from '@platejs/basic-nodes/react';
import { TablePlugin } from '@platejs/table/react';
import { defineEditor, property, schema, target } from 'platejs';

export default defineEditor('app', {
  plugins: [H1Plugin, TablePlugin] as const,
  schema: {
    overrides: [
      schema.override(H1Plugin, {
        element: { type: 'headingOne' },
      }),
    ],
    properties: {
      reviewState: schema.elementProperty(
        property.enum(['draft', 'approved'] as const),
        { target: target.element(H1Plugin) }
      ),
    },
  },
  schemaIdentity: { id: 'app-document', version: 1 },
});
```

只有闭合的 editor definition 可以覆盖 schema 关系。它可以重映射 element type、
content、groups 或现有 property 的 target，也可以添加应用拥有的 property。插件拥有的
property key 和 value law 保持固定；更改它们需要新字段和显式 migration。

已安装代码从 schema handle 读取最终 identity：

```ts
editor.plugin(H1Plugin).schema.type; // 'headingOne'
EditorKit.schema.properties.reviewState.key; // 'reviewState'
```

生成并提交 TypeScript 和 JSON contract：

```bash
pnpm add -D @platejs/cli
pnpm exec plate generate src/editor/editor-definition.tsx
```

生成模块会导出 kit 及其精确的 editor/value 类型，无需显式 editor 泛型：

```tsx title="src/editor/document-editor.tsx"
import { Plate, usePlateEditor } from 'platejs/react';

import {
  EditorKit,
  type Value,
} from './editor.generated';

export function DocumentEditor({ initialValue }: { initialValue: Value }) {
  const editor = usePlateEditor({ plugins: EditorKit, initialValue });

  editor.update.h1.insert();
  editor.update.table.set({ marginLeft: 24 });

  return <Plate editor={editor} />;
}
```

在 CI 中使用同一命令并加上 `--check`。Plate 会在发布 editor 前比较生成指纹和
已安装的运行时 schema；过期 contract 会直接失败，而不会提供错误的 `Value`。

需要处理已存储文档的 schema 变更使用显式 scaffold：

```bash
pnpm exec plate migrate new src/editor/editor-definition.tsx add-caption
```

scaffold 包含带类型的 `FromValue`、`ToValue` 快照和结构 diff。应用的存储或协作
代码决定何时以及如何运行这个纯迁移；Plate 不会自动应用它。

### 最大长度

设置编辑器的最大长度：

```ts
const editor = createPlateEditor({
  maxLength: 100,
});
```

## 高级配置

### 编辑器ID

为编辑器设置自定义ID：

```ts
const editor = createPlateEditor({
  id: 'my-custom-editor-id',
});
```

当 controller-aware hook 需要选择特定的已挂载 editor 时，传入同一个 ID，
例如 `useEditor({ id: 'my-custom-editor-id' })`。

### 节点ID

Plate内置了为节点自动分配唯一ID的系统，这对于某些插件和依赖稳定标识符的数据持久化策略至关重要。

此功能默认启用。可以通过`nodeId`选项自定义其行为或完全禁用。

#### 配置

创建编辑器时，向`nodeId`属性传递对象来配置节点ID行为：

```ts
const editor = usePlateEditor({
  // ... 其他插件和选项
  nodeId: {
    // 生成ID的函数（默认：nanoid(10)）
    idCreator: () => uuidv4(),

    // 排除内联元素获取ID（默认：true）
    filterInline: true, 

    // 排除文本节点获取ID（默认：true）
    filterText: true,

    // 粘贴时重用目标文档中不存在的源ID（默认：false）
    reuseId: false,

    // 控制初始值中的 ID 分配（默认：'if-needed'）
    // 使用 'always' 为初始值中的所有缺失 ID 补齐
    initialValueIds: 'always',
    // 始终生成新 ID，而不是复用不冲突的来源 ID（默认：false）
    disableInsertOverrides: true,

    // 进一步限制经过上述过滤器后的候选节点（默认：全部）
    match: (_node, path) => path.length === 1,
  },
});
```

<Callout type="note">
  `NodeIdPlugin`（处理此功能）是核心插件的一部分，已自动包含。只有在需要自定义其默认行为时才需要指定`nodeId`选项。
</Callout>

#### 禁用节点ID

如果不需要自动节点ID，可以禁用此功能：

```ts
const editor = usePlateEditor({
  // ... 其他插件和选项
  nodeId: false, // 这将禁用NodeIdPlugin
});
```

禁用后，依赖节点ID的某些插件将无法正常工作。以下插件需要块ID才能工作：

- **[块选择](/docs/block-selection)** - 需要ID来跟踪选中的块
- **[块菜单](/docs/block-menu)** - 需要ID显示特定块的上下文菜单  
- **[拖放](/docs/dnd)** - 使用ID在拖拽操作中识别块
- **[表格](/docs/table)** - 依赖ID进行单元格选择
- **[目录](/docs/toc)** - 需要标题ID进行导航和滚动
- **[折叠](/docs/toggle)** - 使用ID跟踪哪些折叠项是打开/关闭的

### 规范化

控制编辑器是否在初始化时规范化其内容：

```ts
const editor = createPlateEditor({
  shouldNormalizeEditor: true,
});
```

注意，对于大型文档（如playground值），规范化可能需要几十毫秒。

### 自动选择

配置编辑器自动选择范围：

```ts
const editor = createPlateEditor({
  autoSelect: 'end', // 或 'start'，或 true
});
```

这与自动聚焦不同：可以在不聚焦编辑器的情况下选择文本。

### 组件覆盖

覆盖插件的默认组件：

```ts
const editor = createPlateEditor({
  plugins: [H1Plugin],
  components: {
    paragraph: CustomParagraphComponent,
    h1: CustomHeadingComponent,
  },
});
```

### 配置插件

应用直接导入目标插件时，请配置该描述符：

```ts
const AppLinkPlugin = LinkPlugin.configure({
  initialState: {
    allowedSchemes: ['http', 'https'],
  },
});

const editor = createPlateEditor({
  plugins: [AppLinkPlugin],
});
```

### 弱对等覆盖

包插件可能需要适配另一个已安装的包，但不能导入它，也不能控制使用者的编辑器 kit：

```ts
import { PLUGINS } from 'platejs';
import { definePlatePlugin } from 'platejs/react';

const SingleBlockPlugin = definePlatePlugin(PLUGINS.singleBlock, {
  override: {
    plugins: {
      [PLUGINS.trailingBlock]: {
        enabled: false,
      },
    },
  },
});
```

仅当目标已安装时才应用覆盖；目标不存在时忽略。它不能修改 `name`、`dependencies`，
也不能嵌套另一个 `override`。目标描述符的直接配置优先。

### 替换依赖默认定义

完整的显式描述符可以替换具有相同名称的低优先级 core 或 dependency 定义。在同一
插件数组内，从同一个已创作插件派生的终端配置会按顺序组合，后面定义的值优先。无关
的插件和分叉的创作分支不能共享同一个名称。

```ts
const AppParagraphPlugin = ParagraphPlugin.configure({
  component: AppParagraphElement,
});

const editor = createPlateEditor({
  plugins: [AppParagraphPlugin],
});
```

## 类型化编辑器

`createPlateEditor` 会根据安装的插件元组派生文档值和插件 API。
`initialValue` 会根据该 schema 派生的值进行检查。

### 插件类型

```ts
const AppKit = [TablePlugin, LinkPlugin] as const;
const editor = createPlateEditor({
  plugins: AppKit,
});

// 使用
editor.update((tx) => {
  tx.table.insertRow();
});
```

### 值类型

当其他模块需要编辑器类型时，使用 `PlateEditor<typeof Kit>`；当命名值类型能提高
可读性时，使用 `ValueOf<MyEditor>`。不要用手写元素接口重复 schema。

```ts
import type { ValueOf } from 'platejs';
import { type PlateEditor, useEditor } from 'platejs/react';

const AppKit = [TablePlugin, LinkPlugin] as const;

export type MyEditor = PlateEditor<typeof AppKit>;
export type MyValue = ValueOf<MyEditor>;

export const useMyEditor = () => useEditor<MyEditor>();

const value: MyValue = [{
  type: 'paragraph',
  children: [{ text: '你好，Plate!' }],
}];

const editor = createPlateEditor({
  plugins: AppKit,
  initialValue: value,
});
```
