---
title: Plugin Methods
description: Author and configure Plate plugins.
---

Plugin authors put independent fields in the plugin constructor. Apps and
registries finish a descriptor with one terminal `.configure()` call, including
`component` when it renders an ordinary node.

## Method Map

| Method | Use it for | Type behavior |
| --- | --- | --- |
| `.extend()` | Adapt an imported/prebuilt descriptor, use a constructor-inaccessible shared factory, or consume an earlier-stage type. | Widens the plugin type. |
| `.configure()` | Override existing fields for one consumer. | Terminal and non-widening. |
| `.clone()` | Copy a plugin definition. | Returns a new plugin object. |

`createBasePlugin()` and `createPlatePlugin()` own every independent author
contribution:

| Field | Owns |
| --- | --- |
| `initialState` | The seed for this plugin's editor-local store. |
| `api` | Immutable plugin-scoped services and queries. |
| `read` | Snapshot or transaction-local reads. |
| `selectors` | Pure state-first derivations, including React subscriptions. |
| `update` | Transaction-bound plugin mutations. |
| `extension` | Plite runtime capabilities, including editor-wide groups. |
| `codecs` | Plugin-owned format decoding and encoding. |

Callbacks receive the inferred [Plugin Context](/docs/plugin-context), including
`editor`, `plugin`, `api`, `read`, `defineCodecs`, `store`, and the active `tx`
inside update contributions.

## Use Constructor Context

Put independent fields and their context callbacks in the constructor. Use
`.extend()` for an imported/prebuilt declaration or types introduced by an
earlier stage.

```tsx title="counter-plugin.tsx" showLineNumbers
import { createPlatePlugin, usePluginStore } from 'platejs/react';

export type CounterPluginState = {
  value: number;
};

type CounterApi = {
  isEmpty: () => boolean;
};

type CounterUpdate = {
  insertLabel: () => void;
};

const initialState: CounterPluginState = {
  value: 0,
};

export const CounterPlugin = createPlatePlugin({
  api: ({ store }): CounterApi => ({
    isEmpty: () => store.get('value') === 0,
  }),
  initialState,
  key: 'counter',
  selectors: {
    doubled: (state, factor: number) => state.value * factor,
    isEven: (state) => state.value % 2 === 0,
  },
  update: ({ store, tx }): CounterUpdate => ({
    insertLabel: () => {
      tx.text.insert(`Count: ${store.get('value')}`);
    },
  }),
});

export function CounterValue() {
  const doubled = usePluginStore(CounterPlugin, 'doubled', 2);
  const isEven = usePluginStore(CounterPlugin, 'isEven');

  return (
    <span>
      {doubled} / {isEven ? 'even' : 'odd'}
    </span>
  );
}
```

Optional return annotations describe each contributed field. For `update`, the
annotation is the command object returned by the callback, not the callback
itself. Omit it when the full contract is inferred.

After resolution, concrete editors expose the plugin API on its readable key.
Generic package code uses the typed portal.

```ts
editor.api.counter.isEmpty();
editor.plugin(CounterPlugin).api.isEmpty();
editor.plugin(CounterPlugin).update.insertLabel();
```

Inside a later update contribution, reuse an earlier update through the active
transaction group:

```ts
.extend(({ plugin }) => ({
  update: ({ tx }) => ({
    insertPair: () => {
      tx[plugin.key].insertLabel();
      tx[plugin.key].insertLabel();
    },
  }),
}))
```

Calling a portal one-shot update there would open a nested transaction.

## Install Plite Capabilities

Put generic editor substrate under the `extension` field: schema facts, state,
commands, corrections, query middleware, and runtime services. Raw extension
options without `name` inherit the plugin key.

```ts title="single-line-plugin.ts" showLineNumbers
import { createBasePlugin, editorCommands } from 'platejs';

export const SingleLinePlugin = createBasePlugin({
  extension: {
    commands: ({ handle }) => [
      handle(editorCommands.insertBreak, ({ state }) =>
        state.transaction(() => {})
      ),
    ],
  },
  key: 'singleLine',
});
```

Plate context-dependent extension callbacks stay inside the `extension` field,
where commands, inputs, state, transactions, dependencies, and plugin state are
contextually typed. Extract domain logic instead of passing the plugin context
through a typing factory:

```ts title="trigger-plugin.ts" showLineNumbers
import { createBasePlugin, editorCommands } from 'platejs';

const shouldHandleTrigger = (enabled: boolean) => enabled;

export const TriggerPlugin = createBasePlugin({
  initialState: { enabled: true },
  key: 'trigger',
  extension: ({ store }) => ({
    commands: ({ handle }) => [
      handle(editorCommands.insertBreak, ({ state }) => {
        if (!shouldHandleTrigger(store.get('enabled'))) return false;

        return state.transaction(() => {});
      }),
    ],
  }),
});
```

For an independently reusable Plite descriptor, import
`defineEditorExtension` from `@platejs/plite` and pass the descriptor to the
plugin's `extension` field.

A genuinely unkeyed editor-wide capability also belongs under `extension`.
Plugin-specific API stays under `api`; do not publish the same implementation
twice.

## Declare Product Codecs

Build the MIME-keyed map with the callback's `defineCodecs`. This is the one
inline inference anchor for codec callbacks.

```ts title="records-plugin.ts" showLineNumbers
import { ContentSlice } from '@platejs/plite';
import { createBasePlugin } from 'platejs';

export const RecordsPlugin = createBasePlugin({
  codecs: ({ defineCodecs }) =>
    defineCodecs({
      'application/json': {
        scope: 'document',
        decode: ({ data }) => ContentSlice.fromJSON(JSON.parse(data)),
        encode: ({ slice }) => JSON.stringify(slice),
      },
    }),
  key: 'records',
});
```

Use document scope only when the format represents the complete document.
Use `defineCodecs(map)` for self and product codecs. Use
`defineCodecs(TargetPlugin, map)` for a foreign codec; the helper injects the
target into every HTML rule. The map's `'text/html'` value accepts one
schema-aware rule or a non-empty ordered rule tuple when the plugin owns
multiple HTML representations. Keep that tuple in the same map. Do not author
a direct codec map or add `target` manually.

## Bind A Component

Bind an ordinary node component in the same terminal `.configure()` call as
the descriptor's other consumer overrides.

```tsx title="plugins.tsx" showLineNumbers
import { ParagraphPlugin } from 'platejs/react';

import { ParagraphElement } from '@/components/ui/paragraph-node';

export const AppParagraphPlugin = ParagraphPlugin.configure({
  component: ParagraphElement,
  shortcuts: {
    toggle: { keys: 'mod+alt+0' },
  },
});
```

Component binding preserves the plugin type. Do not assign the node component
through a renderer registry field.

## Configure Existing Fields

Use `.configure()` once, where an app or registry installs a plugin, to change
fields already declared by the author.

```tsx title="plugins.tsx" showLineNumbers
import { H1Plugin } from '@platejs/basic-nodes/react';

export const AppH1Plugin = H1Plugin.configure({
  initialState: {
    levels: [1, 2],
  },
  shortcuts: {
    toggle: { keys: 'mod+alt+1' },
  },
});
```

Object configs use Plate's merge rules: objects merge deeply, arrays replace,
and `initialState` shallow-merges. `.configure()` cannot publish a new capability and
must be the final call.

## Configure Related Plugins

Configure a required dependency on its own descriptor and place that complete
descriptor beside the owner in the app or registry plugin array.

```ts
type CellPluginState = {
  padding: number;
};

const initialState: CellPluginState = {
  padding: 12,
};

const CellPlugin = createPlatePlugin({
  initialState,
  key: 'cell',
});

const GridPlugin = createPlatePlugin({
  key: 'grid',
  dependencies: [CellPlugin],
});

export const AppGridPlugins = [
  GridPlugin,
  CellPlugin.configure({ initialState: { padding: 8 } }),
];
```

Optional capabilities are ordinary array entries. Two explicit descriptors
with the same key are an error; array order is not an override mechanism.

## Convert Plite Plugins

Use `toPlatePlugin()` for a semantic base whose remaining work is React-only.

```tsx title="mention-plugin.tsx" showLineNumbers
import { createBasePlugin, schema } from 'platejs';
import { toPlatePlugin } from 'platejs/react';

import { MentionElement } from '@/components/ui/mention-node';

const BaseMentionPlugin = createBasePlugin({
  key: 'mention',
  schema: {
    element: {
      content: schema.content.text({ default: 'text', min: 1 }),
      inline: true,
    },
  },
});

export const MentionPlugin =
  toPlatePlugin(BaseMentionPlugin).configure({ component: MentionElement });
```

The converted plugin keeps the same authoring model: initial behavior in the
constructor, imported or staged work in `.extend()`, then one terminal
`.configure({ component })`.
