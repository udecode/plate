Plate plugins are highly configurable, allowing you to customize their behavior to suit your needs. This guide will walk you through the most common configuration options and how to use them.

- [Getting Started: Components](/docs/installation#components) - Instructions for adding plugins to your editor
- [PlatePlugin API](/docs/api/core/plate-plugin) - The complete API reference for creating plugins

## Basic Plugin Configuration

### New Plugin

The most basic plugin configuration requires only a `key`:

```ts
const MyPlugin = createPlatePlugin({
  key: "minimal",
});
```

While this plugin doesn't do anything yet, it's a starting point for more complex configurations.

### Existing Plugin

The `.configure` method allows you to configure an existing plugin:

```ts
const ConfiguredPlugin = MyPlugin.configure({
  options: {
    myOption: "new value",
  },
});
```

## Schema Plugins

Schema plugins declare document types at the top level and model behavior under
`schema`. React rendering stays under `render`.

### Elements

Declare a new element with `schema.element`:

```ts
import { schema } from "platejs";

const ParagraphPlugin = createPlatePlugin({
  key: "p",
  type: "p",
  schema: {
    element: { content: schema.content.text({ default: "text", min: 1 }) },
  },
});
```

You can associate a component with your element. See [Plugin Components](/docs/plugin-components) for more information.

```ts
import { schema } from "platejs";

const ParagraphPlugin = createPlatePlugin({
  key: "p",
  type: "p",
  schema: {
    element: { content: schema.content.text({ default: "text", min: 1 }) },
  },
  render: { node: ParagraphElement },
});
```

### Inline, Void, and Text Properties

Element behavior lives inside `schema.element`. Declare a boolean text property
with a property descriptor under `schema.mark`:

```ts
import { property, schema } from "platejs";

const LinkPlugin = createPlatePlugin({
  key: "link",
  type: "a",
  schema: {
    element: {
      content: schema.content.text({ default: "text", min: 1 }),
      inline: true,
    },
  },
});

const ImagePlugin = createPlatePlugin({
  key: "image",
  type: "img",
  schema: { element: { void: "block" } },
});

const BoldPlugin = createPlatePlugin({
  key: "bold",
  schema: {
    mark: property.boolean({ default: false, omitDefault: true }),
  },
});
```

## Behavioral Plugins

Rather than declare an element or text property, you may want to customize the behavior of your editor. Various plugin options are available to modify the behavior of Plate.

### Plugin Rules

The `rules` property allows you to configure common editing behaviors like breaking, deleting, and merging nodes without overriding editor methods. This is a powerful way to define intuitive interactions for your custom elements.

For example, you can define what happens when a user presses `Enter` in an empty heading, or `Backspace` at the start of a blockquote.

```ts
import { H1Plugin } from "@platejs/heading/react";

H1Plugin.configure({
  rules: {
    break: { empty: "reset" },
  },
});
```

See the [Plugin Rules guide](/docs/plugin-rules) for a complete list of available rules and actions.

### Event Handlers

The recommended way to respond to user-generated events from inside a plugin is with the `handlers` plugin option. A handler should be a function that takes a `PlatePluginContext & { event }` object.

The `onChange` handler, which is called when the editor value changes, is an exception to this rule; the context object includes the changed `value` instead of `event`.

```ts showLineNumbers
const ExamplePlugin = createPlatePlugin({
  key: "example",
  handlers: {
    onChange: ({ editor, value })  => {
      console.info(editor, value);
    },
    onKeyDown: ({ editor, event }) => {
      console.info(`You pressed ${event.key}`);
    },
  },
});
```

### Inject Props

You may want to inject a class name or CSS property into any node having a certain property. For example, the following plugin sets the `textAlign` CSS property on paragraphs with an `align` property.

```ts showLineNumbers
import { KEYS, property, target } from 'platejs';

const TextAlignPlugin = createPlatePlugin({
  key: "align",
  schema: ({ own, plugins, targetPluginKeys }) => ({
    properties: [
      own.elementProperty(property.string(), {
        target: target.types(plugins.elementTypesByKey(targetPluginKeys)),
        typeChange: 'preserve-if-allowed',
      }),
    ],
  }),
  inject: {
    isBlock: true,
    nodeProps: {
      defaultNodeValue: "start",
      styleKey: "textAlign",
      validNodeValues: ["start", "left", "center", "right", "end", "justify"],
    },
  },
  targetPluginKeys: [KEYS.p],
}).extendHtmlCodec(() => ({
  decode: ({ element }) => element.style.textAlign || undefined,
  encode: ({ value }) => ({ style: { textAlign: value } }),
  match: [
    {
      style: {
        textAlign: ['start', 'left', 'center', 'right', 'end', 'justify'],
      },
    },
  ],
}));
```

`inject.nodeProps` owns rendering, while `.extendHtmlCodec()` owns the
bidirectional HTML claim. Both use the plugin's resolved `type`, so terminal
`.configure({ type })` changes the stored property without duplicating a key in
the codec.

A paragraph node affected by the plugin looks like this:

```ts showLineNumbers {3}
{
  type: 'p',
  align: 'right',
  children: [{ text: 'This paragraph is aligned to the right!' }],
}
```

### Add APIs and Transaction Commands

Use `.extendApi()` or `.extendEditorApi()` for reads and services. Put document mutations in `.extendTx()` or `.extendTxGroup()` so callers run them through `editor.update`.

```ts
type CustomConfig = PluginConfig<"custom", { prefix: string }>;

const CustomPlugin = createPlatePlugin<CustomConfig>({
  key: "custom",
  options: { prefix: "Note: " },
})
  .extendApi(({ getOptions }) => ({
    getPrefix: () => getOptions().prefix,
  }))
  .extendTx(({ getOptions }) => (tx) => ({
    insertPrefix: () => {
      tx.text.insert(getOptions().prefix);
    },
  }));
```

After the plugin resolves, concrete editors infer its reads on the root API and one-shot writes use the keyed update helper:

```ts
editor.api.custom.getPrefix();
editor.update.custom.insertPrefix();
```

Generic package code can reach the same immutable API object through
`editor.plugin(CustomPlugin).api.getPrefix()`.

### Install Plite Extensions (Advanced)

Use `.extendExtension()` when a Plate plugin needs to install Plite substrate behavior: schema facts, state groups, tx groups, corrections, commands, query middleware, or runtime services.

```ts showLineNumbers
import { defineEditorExtension } from "platejs";
import { createPlatePlugin } from "platejs/react";

const customState = defineEditorExtension({
  name: "custom-state",
  state: {
    customState() {
      return {
        enabled: () => true,
      };
    },
  },
});

const CustomStatePlugin = createPlatePlugin({
  key: "customState",
}).extendExtension(customState);
```

<Callout type="info" title="Extensions, APIs, and commands">
  Use `.extendExtension()` for Plite substrate behavior, `.extendApi()` or
  `.extendEditorApi()` for reads and services, and `.extendTx()` or
  `.extendTxGroup()` for mutations.
</Callout>

## Advanced Plugin Configuration

### Plugin Store

Each plugin has its own store, which can be used to manage plugin-specific state.

```ts
const MyPlugin = createPlatePlugin({
  key: "myPlugin",
  options: {
    count: 0,
  },
}).extend(({ editor, plugin, setOption }) => ({
  handlers: {
    onClick: () => {
      setOption("count", 1);
    },
  },
}));
```

You can access and update the store using the following methods:

```ts
// Get the current value
const count = editor.plugin(MyPlugin).getOption("count");

// Set a new value
editor.plugin(MyPlugin).setOption("count", 5);

// Update the value based on the previous state
editor.plugin(MyPlugin).setOption("count", (prev) => prev + 1);
```

In React components, you can use the `usePluginOption` or `usePluginOptions` hook to subscribe to store changes:

```tsx
const MyComponent = () => {
  const count = usePluginOption(MyPlugin, "count");
  return <div>Count: {count}</div>;
};
```

See more in [Plugin Context](/docs/plugin-context) and [Editor Methods](/docs/editor-methods) guides.

### Dependencies

Declare required plugins with their plugin objects. Plate installs the dependency graph recursively, deduplicates plugins by key, and loads dependencies before their dependents.

```ts
const MyPlugin = createPlatePlugin({
  key: "myPlugin",
  dependencies: [ParagraphPlugin, ListPlugin],
});
```

### Enabled Flag

The `enabled` property allows you to conditionally enable or disable a plugin:

```ts
const MyPlugin = createPlatePlugin({
  key: "myPlugin",
  enabled: true, // or false to disable
});
```

### Optional Capabilities

Keep optional capabilities as ordinary plugins in the consumer's plugin array.
When an enhancement needs a host, the enhancement depends on the host:

```ts
const CodeHighlightPlugin = createPlatePlugin({
  key: "codeHighlight",
  dependencies: [CodeBlockPlugin],
});

const plugins = [CodeBlockPlugin, CodeHighlightPlugin];
```

Omit `CodeHighlightPlugin` for plain code blocks. The host does not install
optional enhancements.

### Plugin Priority

The `priority` property determines the order in which plugins are registered and executed. Plugins with higher priority values are processed first:

```ts
const HighPriorityPlugin = createPlatePlugin({
  key: "highPriority",
  priority: 100,
});

const LowPriorityPlugin = createPlatePlugin({
  key: "lowPriority",
  priority: 50,
});
```

This is particularly useful when you need to ensure certain plugins are initialized or run before others.

### HTML Input Hooks

Use the flat hooks under `parsers.html` to decide whether a plugin participates
in an HTML input, transform the source string, or transform the decoded
fragment.

```ts
const HtmlCleanupPlugin = createPlatePlugin({
  key: 'htmlCleanup',
  parsers: {
    html: {
      query: ({ data, format }) =>
        format === 'text/html' && data.includes('<!--StartFragment-->'),
      transformData: ({ data }) =>
        data.replaceAll(/<!--(?:Start|End)Fragment-->/g, ''),
    },
  },
});
```

`query`, `transformData`, and `transformFragment` are siblings under
`parsers.html`. Node-level HTML conversion remains separate from these
whole-input hooks.

## Typed Plugins

Using above methods, plugin types are automatically inferred from the given configuration.

If you need to pass an explicit type as generic, you can use `createPlatePlugin`.

### Using createPlatePlugin

The `createPlatePlugin` function allows you to create a typed plugin:

```ts
type CodeBlockConfig = PluginConfig<
  // key
  "codeBlock",
  // options
  { language: string; syntax: boolean; syntaxPopularFirst: boolean },
  // api
  {
    codeBlock: {
      getLanguage: () => string;
      getSyntaxState: () => boolean;
    };
  },
  // tx
  {
    insert: {
      codeBlock: () => void;
    };
  },
  // selectors
  {}
>;

const CodeBlockPlugin = createPlatePlugin<CodeBlockConfig>({
  key: 'codeBlock',
  type: 'code_block',
  options: {
    language: 'typescript',
    syntax: true,
    syntaxPopularFirst: false,
  },
}).extendEditorApi<CodeBlockConfig['api']>(({ getOptions }) => ({
  codeBlock: {
    getLanguage: () => getOptions().language,
    getSyntaxState: () => getOptions().syntax,
  },
})).extendTxGroup('insert', ({ getOptions }) => (tx) => ({
  codeBlock: () => {
    tx.nodes.insert({
      type: 'code_block',
      language: getOptions().language,
      children: [{ text: '' }],
    });
  },
}));
```

### Using Typed Plugins

When using typed plugins, you get full type checking and autocompletion ✨

```ts
const editor = createPlateEditor({
  plugins: [CodeBlockPlugin],
});

// Type-safe access to options
const options = editor.plugin(CodeBlockPlugin).getOptions();
options.language;
options.syntax;
options.syntaxPopularFirst;

// Type-safe API
editor.api.codeBlock.getSyntaxState();
editor.api.codeBlock.getLanguage();

// Type-safe transactions
editor.update((tx) => tx.insert.codeBlock());
```
