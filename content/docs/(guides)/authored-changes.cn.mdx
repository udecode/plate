Authored changes 在一个保存的文档中维护已接受内容、待处理 proposal 和稳定的 change identity。常用的编辑和建议模式请使用[建议](/docs/suggestion)。本指南介绍底层 view、读取、决定和格式。

## 选择合适的接口

| 需求                       | 接口                                                                   |
| -------------------------- | ---------------------------------------------------------------------- |
| 在编辑和建议模式之间切换   | `platejs/suggestion/react` 的 `SuggestionPlugin`                       |
| 添加复制的高亮和审阅卡片   | [SuggestionKit](/docs/suggestion) 和 [DiscussionKit](/docs/discussion) |
| 以编辑器的用户记录 change  | `platejs/authored` 的 `AuthoredPlugin`                                 |
| 读取和决定 change 或卡片   | 已安装的 authored plugin portal                                        |
| 附加对话                   | 使用 `{ type: 'change', id }` target 的 `CommentsPlugin`               |

Suggestion 是 authored change 上的行为和展示层。它不会定义另一套 change record、决定结果或持久化格式。

## 安装 authored changes

`AuthoredPlugin` 在每个 transaction 中从 Plate editor 的 `userId` 解析一次作者：

```tsx title="editor.ts" showLineNumbers
import { BaseParagraphPlugin, createEditor } from "platejs";
import { AuthoredPlugin } from "platejs/authored";

const editor = createEditor({
  plugins: [BaseParagraphPlugin, AuthoredPlugin],
  initialValue: [
    { type: "paragraph", children: [{ text: "Review this sentence." }] },
  ],
  userId: "alice",
});

const authored = editor.plugin(AuthoredPlugin);
```

没有 `userId` 的编辑器以本地用户 `'local'` 写入，因此单人编辑器无需任何设置，AI 建议也一样。多人编辑同一文档时，请传入经过认证且稳定的用户 ID。

## 捕获 change

Editing view 按原样应用普通更新。要创建 proposal，请先在 transaction 中开始 proposal，再应用文档修改：

```tsx
let changeId = "";

editor.update((tx) => {
  changeId = tx.authored.propose();
  tx.text.insert(" reviewed", {
    at: { offset: 8, path: [0, 0] },
  });
});
```

传入 `{ changeId }` 可以为 proposal 命名，或把该 transaction 的写入加入具有该 ID 的待处理 change。若该 ID 的 change 已被决定，则开始一个新 change。以 `~edit:` 开头的 ID 属于 Editing，会被拒绝。

## 导入比较得到的版本

将固定草稿与已接受文档比较，然后把其 canonical change 发布为一个原生 proposal：

```tsx
import { proposeAuthoredComparison } from "platejs/authored";
import { compare } from "platejs/diff";

const incomingDraft = [
  { type: "paragraph", children: [{ text: "Revised sentence." }] },
];
const comparison = await compare({
  before: editor.read.value(),
  after: incomingDraft,
  schema: editor.read.schema,
});
const imported = proposeAuthoredComparison(editor, { comparison });
```

`groupIds` 选择比较 group，并包含它们必需的依赖。结果把选中的 group ID 映射到原生 change ID。导入会在写入前检查 schema、已接受内容和 authored frontier；处理 `stale`、`blocked`、`invalid` 和 `unavailable` 时，不要把它们当作已应用的 proposal。比较必须是针对当前已接受文档的双向比较。

## 配置 view

在 `EditorRoot` 上设置初始 intent：

```tsx
import { AuthoredPlugin } from "platejs/authored";
import { EditorContent, EditorRoot, useCreateEditor } from "platejs/react";

export function SuggestionEditor() {
  const editor = useCreateEditor({
    plugins: [AuthoredPlugin],
    userId: "alice",
  });

  return (
    <EditorRoot editor={editor} authored={{ intent: "propose" }}>
      <EditorContent />
    </EditorRoot>
  );
}
```

编辑器必须安装 authored plugin，可以直接安装，也可以通过 `SuggestionPlugin` 安装。修改 `authored` prop 会更新这个 view。以等价值重新渲染时，会保留之后通过已挂载 view 的 portal 做出的模式修改。

交互式模式控件请让 `SuggestionPlugin` 修改 intent：

```tsx
import { SuggestionPlugin } from "platejs/suggestion/react";

editor.plugin(SuggestionPlugin).api.setMode("suggesting");
```

要以所有待处理 change 都已决定的状态阅读文档，请把 view 切换为 preview：

```tsx
const authored = editor.plugin(AuthoredPlugin);

authored.api.setView({ preview: "proposed" });
```

| View                      | 可见内容                         | 写入                         |
| ------------------------- | -------------------------------- | ---------------------------- |
| `{ intent: 'edit' }`      | 存储内容，以及待处理的插入和删除 | 按原样应用                   |
| `{ intent: 'propose' }`   | 存储内容，以及待处理的插入和删除 | 记录为当前作者的 proposal    |
| `{ preview: 'proposed' }` | 接受全部待处理 change 后的内容   | 普通编辑会抛出错误，见下文     |
| `{ preview: 'accepted' }` | 拒绝全部待处理 change 后的内容   | 普通编辑会抛出错误，见下文     |

Preview 遇到普通编辑会抛出错误，但部分其他写入仍会修改存储文档，例如带决定的 update、撤销和重做，以及远程协作变更。

在被划掉的文本中输入时，待处理删除会在新文本两侧拆开。`edit` view 按原样应用这段文本，`propose` view 把它记录为插入。`propose` view 会拒绝无法记录为 proposal 的写入，例如表格内的修改，并将其回滚；`api.subscribeRefusals(listener)` 会报告每次拒绝。

在只生成 text 属性的 schema 下，或者生成的属性都是具有精确键、值不是集合、target 不取决于元素位置、角色不是 `content` 的 element 属性时（例如 `ElementIdPlugin` 的 `id`），`propose` view 和两种 preview 都可以使用。`content` 是默认角色，因此请声明 `role: 'metadata'`。建议会在记录时生成之后构建所需的元素值。建议的 Enter 把新元素的 id 存放在该元素上。决定可能移除容器子元素（例如删除引用块中唯一的一行）或改变容器类型的建议，还会把该决定将在那里构建的 block 作为备用 block 存放在文档的审阅 mark 和 `records` 中。之后 preview、projection 和决定都显示这些已存储的值，不调用 element 属性的生成器。当已存储的 block（例如建议之后写入的 block）重复备用 block 所持的唯一值时，构建该备用 block 的决定会给它一个新值，与 preview 显示的值不同。在其他生成属性下，或在同时生成 element 属性和 text 属性的 schema 下，`setView` 保留当前 view，proposal 不写入任何内容，两者都报告拒绝代码 `generated-values`。

在 `propose` view 中删除一个拥有 [content root](/cn/docs/roots#content-roots) 的 block 时，该 block 会被划掉，root 的内容保持原样且不带审阅标记，因此请在 block 的组件中把 root 显示为已删除。在该 root 中输入或粘贴不会写入任何内容，直到有人决定这个删除。接受删除会移除该 block 及其 root；若 root 中有另一个待处理 change 插入的文本，结果为 `blocked`。拒绝删除会保留两者。拒绝一个拥有 content root 的待处理插入 block 时，root 也会一并移除。`propose` view 仍会拒绝删除没有任何元素拥有的 named root。

待处理的合并可能让一个段落显示在其存储位置之外。`proposed` preview 会把从被合并行拆出的段落，或插入到合并两半之间的段落，显示在被合并行之后。`edit` view 和 `propose` view 会把跨越被移动段落边缘的 Backspace 或 Delete，以及跨越被移动段落的删除，记录为它们造成的合并。当被移动的行包含某个 content root 的 owner 时，`propose` view 会拒绝这次 Backspace，因为提议的合并会让该 root 有两个 owner；`edit` view 会记录它。全选会覆盖 preview 显示的每个段落，包括被移动的最后一个段落。两种 view 都会拒绝以下编辑，并给出所列原因：

- 在被移动段落与相邻内容的交界处按 Enter 或插入新段落，原因为 `crosses`。
- 在所在行中更早的断点之后按 Enter，例如在后面跟着被移动段落的被合并行末尾按 Enter，原因为 `reordered`。
- Preview 在选区两端之间没有显示任何被选中的字母、却在别处显示了其中一些字母的编辑，原因为 `crosses`。若 preview 隐藏了被选中的字母，例如被划掉的文本，选区则会变成光标。
- 起点或终点位于被移动段落与相邻内容交界处某个文本内部的格式，以及在那里开启 mark 后输入的字母，原因为 `crosses`，因为它们都会在断点处拆分该文本。若断点位于两个文本之间，例如在链接旁，带 mark 的字母会被应用。
- 被合并行及其 follower 旁的全选删除、输入或粘贴，无论位于顶层还是 quote 中，原因为 `crosses`。

移动段落旁的格式命令会格式化 `proposed` preview 在选区两端之间显示的内容，因此它可能格式化选区之外的已保存文本，或让选区内被移动的段落保持原样。编辑器不会因自带位置的命令（例如在给定位置插入链接的命令）开始时的选区而拒绝它。当该命令同时在选区处编辑时，它可能修改选区之外的文本。它在所指定位置上的编辑仍会像上面那样被拒绝。在被合并行内部的光标处输入仍会应用。被拒绝的编辑不会应用任何内容，`subscribeRefusals` 会以 code `unrepresentable` 和上面所列的原因报告它。包含 content root owner 的那次 Backspace 不带原因。

View 的 policy 属于该精确 view。Selection、clipboard input、command 和 anchor 使用该 view 的坐标。同一个文档的两个已挂载 view 可以使用不同 policy。

## 审阅 change

读取一页待处理 change，然后决定读到的记录：

```tsx
const authored = editor.plugin(AuthoredPlugin);
const page = authored.read.changes({ authorId: "alice", limit: 50 });
const result = authored.update.decide({
  action: "accept",
  changes: page.items,
});
```

使用 `action: 'reject'` 拒绝 change。`changes(query)` 按文档顺序读取待处理 change，默认每页 50 条，最多 200 条。传入非空的页 `cursor` 可读取下一页；若 cursor 对应的 change 都已离开，会以 stale 抛出。用 `at` 把一页限定到某个位置，用 `authorId` 限定到某位作者，或用 `group` 限定到某张卡片。

`at` 指的是 view 所显示文档中的位置。没有 preview 时就是存储文档，`at` 接受 node key、path、point 或 range。在 preview 上，`at` 接受 preview 所显示的 node（block 或其中某个文本）的 key 或 path。读取结果是该 node 所显示的存储内容上的 change，包括 preview 隐藏在其中的内容，以及 preview 去掉的每个外层元素上的 change，例如 preview 应用了待处理解除包裹的 quote。Preview 隐藏在 block 中两个文本之间的内容只出现在该 block 的读取结果中，不出现在任一文本的读取结果中。在 preview 上传入 point 或 range 会抛出 `platejs/authored` 导出的 `AuthoredPlaceError`，preview 中不存在的 key 什么也读不到。在 preview 省略的 content root 的 view 上，任何 key 和 path 都读不到内容。被合并的行会读取其两半之间的隐藏 block。除此之外，被 preview 隐藏的顶层 block，其 change 不会被任何 block 读到；要查看并决定这些 change，请切换到 `edit` 或 `propose` view。Preview 为补全文档而添加的顶层 block（例如唯一的 block 被删除时）什么也读不到。它在容器内添加的 block（例如 quote 中唯一的段落被删除时）可能读取它所替代的隐藏段落。一个 block 绝不会读取 view 仍然显示的外层元素的 change，例如 view 仍显示的 quote 的待处理解除包裹。带 `at` 的读取返回的页 `cursor` 只在 root 和 preview 相同的 view 上有效。

每个 `AuthoredChange` 都有 `id`、`authorId`、`createdAt`、`kind`、当前 `ranges`，以及 `revision`；它随 change 的 mark 以及每类 mark 所覆盖的内容而变化，见下文。`ranges` 和 `details` 中的位置在每个 view 上都始终是存储文档中的位置。用 `change(id)` 读取单个 change。

除了顶层 block 内部的拆分或合并，revision 都不包含 change 所在的位置，因此在它之前的编辑不会改变 revision。它的 `ranges` 可能在 revision 不变时移动，因此每次文档变更后请重新读取。合并、拆分、包裹或解除包裹的 revision 不包含其内部的文本和 leaf，因此在其中输入不会改变它；它随元素自身字段以及其内部元素的顺序和形状而变化。在顶层 block（例如 quote）内部，拆分或合并的 revision 还包含它在该 block 中的索引，因为决定会把它所在的行合并到前一个 block 中。索引只计算 block 的数量，不记录该行之前是哪一个 block。当它之前的 block 改变顺序，或其中一个被替换或改变类型后，之前读取的决定仍然有效，并会把该行合并进现在位于它之前的 block。落入顶层拆分或合并两半之间的 block 也不会改变 revision，之前读取的决定会把该行合并进这个 block。

决定会按读取时的状态指名 change；读取后 revision 已变化的 change 返回 `stale`。接受一个 change 可能需要同时接受其他 change，拒绝一个 change 可能需要同时拒绝依赖它的 change。此时结果为 `blocked`，`with` 列出所需的 change，且不会应用任何内容。编辑器绝不会决定你未指名的 change。一次调用中的多个决定会一起决定：

```tsx
if (result.status === "blocked") {
  const related = result.with.flatMap((id) => authored.read.change(id) ?? []);

  authored.update.decide([
    { action: "accept", changes: page.items },
    { action: "accept", changes: related },
  ]);
}
```

审阅者打开一条 change 时，再读取其语义详情：

```tsx
const details = authored.read.details(changeId);

for (const part of details?.parts ?? []) {
  // 在审阅 UI 中渲染 content、boundary、enclosure 或 property part。
}
```

`details(id)` 返回该 change 及其 part。Content part 包含修改前后的 slice；boundary part 区分段落拆分和合并；enclosure part 指明包裹和解除包裹；property part 保留准确的前后值。

### 审阅卡片

审阅卡片把同一作者的相邻待处理 change 归为一组，例如一个删除和替换它的插入：

```tsx
const [card] = authored.read.groups({ at: [0] });

if (card) {
  const firstChanges = authored.read.changes({ group: card.id, limit: 20 });
  const decided = authored.update.decide({ action: "accept", groups: [card] });
}
```

`groups({ at })` 按文档顺序返回与 view 所显示文档某个位置相交的卡片摘要：`id`、`authorId`、`createdAt`、`changeCount` 和 `revision`。卡片 ID 是其中最早的 change，因此每个 peer 和每次重新加载都会给出相同的 ID。卡片拆分或合并时，或该 change 离开卡片时，ID 会改变。`groupOf(changeId)` 返回包含某个 change 的卡片。

决定一张卡片会决定它在那一刻包含的所有 change。卡片的 ID 或 revision 变化后，该决定会返回 `stale`，因此重试前请用 `groupOf` 重新读取卡片。

### 决定结果

始终检查 `decide` 的结果：

| 状态        | 含义                                           |
| ----------- | ---------------------------------------------- |
| `applied`   | 决定已应用到返回的 ID。                        |
| `unchanged` | 无需修改。                                     |
| `stale`     | 读取后 change 或卡片已变化。请重新读取。       |
| `blocked`   | 需与 `with` 列出的 change 一起决定。未应用任何内容。 |
| `invalid`   | 多个决定互相矛盾，或 schema 拒绝决定结果。     |

## 保存文档

保存 `editor.read.value()` 的完整结果。它包含内容及每个 node 上的待处理审阅 mark，以及文档 `records` 中的审阅记录。只保存 node 数组会丢失这些记录。

```tsx
const savedDocument = editor.read.value();

const restored = createEditor({
  plugins: [BaseParagraphPlugin, AuthoredPlugin],
  initialValue: savedDocument,
  userId: "alice",
});
```

用相同的内容插件和 schema 将版本加载到新 editor。加载过程会在发布 value 前验证审阅 mark、审阅记录和 document schema。`authored` node 属性和审阅记录交由编辑器管理。本地 undo 从空开始。

如果安装了[评论](/docs/comment)，请将 `editor.plugin(CommentsPlugin).api.toJSON()` 与文档、应用版本和对话代次一起原子保存。验证关联后，在新 editor 中用 `CommentsPlugin.configure({ initialState: { initialComments } })` 加载保存的 `CommentsJSON`。实时 thread target 只包含语义身份，通过 `attachment(id)` 读取位置。接受、拒绝和撤销建议决定都会保留讨论；解决或重新打开 thread 不进入文档 undo。

历史预览和恢复保留当前对话，并只使用所选版本可验证的目标。参阅[评论的历史版本](/cn/docs/comment#历史版本)。

## 导出显式投影

使用 `accepted` 或 `proposed` 得到 clean document；格式能够保留审阅记录时使用 `review`。Clean projection 省略待处理工作时会返回 diagnostic。每个 helper 都接收或捕获完整 document，包括 named root 和 metadata。Clean projection 省略某个 content root 的 owner 时，也会按 [content root](/cn/docs/roots#content-roots) 的归属规则省略该 root。

对含有待处理 change 的 document 执行 HTML、Markdown、plain text 与 static HTML 导出时，`projection` 必须是 `accepted` 或 `proposed`，否则抛出 `TypeError`。没有待处理 change 的 document 不需要 projection。DOCX export 始终需要 projection。

每个导出都通过 editor 的 schema 进行投影，因此被决定清空的容器（例如待处理删除移除了唯一一行的引用）会得到默认内容。editor 拒绝该投影时，导出会抛出带有拒绝消息的 `EditorSchemaValidationError`。

### JSON

把 `editor.read.value()` 保存为 JSON 即可保留审阅。需要 clean document 时，先投影：

```tsx
import { projectAuthoredDocument } from "platejs/authored";

const accepted = projectAuthoredDocument(editor.read.value(), {
  projection: "accepted",
});
```

`projectAuthoredDocument` 返回投影后的 `document`、其 `diagnostics`，以及它决定的待处理 change 数量 `pending`。把保存的 JSON 加载到 editor 时，会执行已安装的 application schema 和审阅检查。

### Plain text 与 Markdown

```tsx
import { serializePlainText } from "platejs";

const text = serializePlainText(editor, { projection: "accepted" }).data;
const markdown = editor.api.markdown.serialize({ projection: "proposed" });

if (markdown.ok) downloadMarkdown(markdown.data);
```

Plain text 与 Markdown 只携带可见 content。Feature 自己拥有的 format mapping 会保留可表示的结构，并报告省略的 root、metadata、待处理工作与不支持的 node。Markdown 不包含隐藏 Plate document，也不能恢复完整审阅状态。

### HTML 与 DOCX

```tsx
import { exportDocx } from "platejs/docx/export";
import { renderStaticHtml } from "platejs/static";
import { BaseEditorKit } from "@/components/editor/plugins-static";

const semanticHtml = editor.api.html.serialize({ projection: "proposed" });
const styledHtml = await renderStaticHtml(editor, {
  presentation: BaseEditorKit,
  projection: "proposed",
});
const docx = await exportDocx(editor, {
  presentation: BaseEditorKit,
  projection: "review",
});
```

`renderStaticHtml` 与 `exportDocx` 用作为 `presentation` 传入的 static kit 绘制，因为 live editor 的组件是编辑 UI。Semantic HTML 使用 feature mapping，不含应用样式。两种 HTML 都只携带可见的 accepted 或 proposed content。成功的 DOCX result 在 `docx.blob` 中返回 `Blob`。每个 serializer 都返回结构化 `diagnostics`。

| 格式 | Accepted 或 proposed | Review |
| ---- | -------------------- | ------ |
| JSON | Plain projected document | 保存的 editor value |
| Plain text | Structural text | 不支持 |
| Markdown | Plain Markdown | 不支持；保存 authored JSON |
| Semantic HTML | Feature-mapped HTML | 不支持；保存 authored JSON |
| Static HTML | Component-rendered HTML | 不支持；保存 authored JSON |
| DOCX | Projected Word document | Word revision，并在 custom XML part 中保存 Plate 的审阅 block 和记录 |

DOCX review 文件显示 Word revision，同时在 custom XML part 中保存每个被审阅的 block 及其审阅记录，并绑定到该 block 的 Word 段落。导入该文件时，Word 未修改段落的 block 会被恢复；被编辑的段落按其 Word revision 导入。Named root 和 document metadata 不进入文件，需要保留时请把 authored JSON 与文件一起保存。Word 无法表达 native construct 时，DOCX review 导出会报告 `lossy-content` 或 `unsupported-content`。

## 协作

每个 peer 都安装 authored plugin 和 Yjs，并使用匹配的 document 与 schema identity。Plate 默认提供本地 History。

Yjs binding 在一个 remote transaction 中应用 content、审阅 mark 和审阅记录。

设置请参阅[协作](/docs/yjs)。

## API 参考

### `AuthoredPlugin`

从 `platejs/authored` 导入标准描述符。它以 Plate editor 的 `userId` 记录每个 change；编辑器没有 `userId` 时，以本地用户 `'local'` 记录。它不接受选项。`SuggestionPlugin` 和 `AIChatPlugin` 依赖此描述符。

### Transaction、读取和更新

执行 `const authored = editor.plugin(AuthoredPlugin)` 后，可使用以下方法：

| 接口                                       | 用途                                                                   |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| `tx.authored.propose(options?)`            | 把该 transaction 的写入记录为 proposal；`{ changeId }` 为其命名或扩展已有 change。 |
| `authored.read.view()`                     | 读取该 view 的 `{ intent }` 或 `{ preview }`。                         |
| `authored.read.change(id)`                 | 读取一个待处理 change；不存在时返回 `null`。                           |
| `authored.read.details(id)`                | 读取一个 change 及其语义 part；不存在时返回 `null`。                   |
| `authored.read.changes(query?)`            | 按文档顺序分页读取待处理 change。                                      |
| `authored.read.groups({ at })`             | 读取与 view 所显示文档某个位置相交的卡片摘要。                         |
| `authored.read.groupOf(changeId)`          | 读取包含某个 change 的卡片；不存在时返回 `null`。                      |
| `authored.read.reviewOf(node)`             | 读取存储 node 的待处理 mark，以及这些 mark 所格式化属性的已接受值。    |
| `authored.update.decide(decision)`         | 接受或拒绝 change 或卡片；决定数组会一起决定。                         |
| `authored.api.setView(view)`               | 修改该精确 view 的 policy。                                            |
| `authored.api.subscribeChanges(listener)`  | 每次改变审阅的 commit 都会收到一个共享 delta。                         |
| `authored.api.subscribeRefusals(listener)` | 接收编辑器拒绝的每个 proposal 写入或 view 切换。                       |

`subscribeChanges` 传入 `{ blocks, changed, groups, removed }`：卡片或 change 读取结果可能不同的 view 顶层 block、开始或 revision 变化的 change、摘要变化、开始或结束的卡片，以及不再待处理的 change。`blocks` 包含 change 进入或离开的每个 block，以及其中有 change 的卡片 ID 发生变化的每个 block；在 preview 下，它们是 preview 所显示的 block。仅卡片摘要变化不会指名任何 block，因此 block 上卡片的 `changeCount` 或 `revision` 可能落后，直到它再次读取。它是底层集成 hook；suggestion UI 改用 `useSuggestionChanges(path)` 和 `useSuggestionGroups(blockKey)`。

### 类型和格式辅助函数

`platejs/authored` 导出 authored plugin 描述符，`AuthoredPlaceError`，change、卡片、query、page、delta、decision 和 result 类型，`proposeAuthoredComparison`，以及下面的格式辅助函数。

`projectAuthoredDocument(document, { projection })` 为 `accepted` 或 `proposed` projection 返回 `{ ok, document, diagnostics, pending }`。它是纯 document operation：不会构造、激活或订阅 editor runtime。同时传入 `editor` 时，会用该 editor 的 schema 补全结果，因此被决定清空的容器会得到默认内容。传入 `editor` 时，若 schema 的生成属性会让 `propose` view 拒绝，含有待处理 change 的 document 会改为返回代码为 `authored-generated-values` 的 `AuthoredProjectionRefusal`。若 projection 需要构建一个带生成值的元素，而 document 没有为它存储备用 block（例如由其他工具写入的 document），也会返回代码为 `authored-uncovered` 的拒绝。

`projectAuthoredRange(document, projected, range)` 把存储文档的 range 映射到它的某个 projection；若 projection 不保留其中任何内容，则返回 `null`。
