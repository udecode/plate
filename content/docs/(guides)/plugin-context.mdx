---
title: Plugin Context
description: Use editor, plugin, store, API, and transaction context inside Plate plugins.
---

Plugin context is the object Plate passes to plugin configuration callbacks,
handlers, extensions, transaction commands, and render components. It gives you
the resolved editor, current plugin, node type, `api`, and plugin store
without reaching through global state. Use it inside plugin-owned code; use
editor methods or React hooks when code runs outside a plugin callback.

## Context Shape

`PlatePluginContext` extends the shared plugin context with a React
`PlateEditor`. The same helper names are available in headless Plite plugins,
but the editor type is `BaseEditor`.

| Property | Use for |
| --- | --- |
| `editor` | The resolved editor instance. |
| `plugin` | The resolved plugin configuration for the current plugin. |
| `type` | The plugin document type, available as `plugin.type`. |
| `api` | API owned by the current plugin. |
| `read` | State-bound reads owned by the current plugin. |
| `update` | One-shot updates owned by the current plugin. |
| `store` | Read, update, or subscribe to the current plugin's editor-local state. |
| `defineCodecs(map)` | Bind a self/product codec map to this plugin's inferred schema. |
| `defineCodecs(TargetPlugin, map)` | Bind a foreign codec map to an exact descriptor and inject its target. |

## Plugin Methods

Handlers receive context plus the event or payload for that handler. Use the
context helpers instead of closing over editor state.

```ts title="counter-plugin.ts" showLineNumbers
import { createPlatePlugin } from 'platejs/react';

export type CounterPluginState = {
  count: number;
  enabled: boolean;
};

const initialState: CounterPluginState = {
  count: 0,
  enabled: true,
};

export const CounterPlugin = createPlatePlugin({
  initialState,
  key: 'counter',
  handlers: {
    onKeyDown: ({ event, store, type }) => {
      if (!store.get('enabled')) return;

      if (event.key === '+') {
        store.set((state) => {
          state.count += 1;
        });
        console.info(`${type} count incremented`);
      }
    },
  },
});
```

`store` is scoped to `CounterPlugin` in this example.

## Extension Callbacks

Configuration, extension, selector, API, transaction, and editor override
callbacks also receive plugin context.

```ts title="counter-plugin.ts" showLineNumbers
import { createPlatePlugin } from 'platejs/react';

export type CounterPluginState = {
  count: number;
};

const initialState: CounterPluginState = {
  count: 0,
};

export const CounterPlugin = createPlatePlugin({
  initialState,
  key: 'counter',
  api: ({ store }) => ({
    isEmpty: () => store.get('count') === 0,
  }),
  selectors: {
    label: (state) => `Count: ${state.count}`,
  },
});
```

Selectors are readable through `store.get` and subscribable through
`usePluginStore`. They are pure state-first functions and cannot read the
editor or another plugin.

## Extension Inference

Return plain extension objects from constructor and `.extend()` callbacks.
Keep Plate context capture inside those callbacks so nested commands, inputs,
state, transactions, dependencies, and plugin state stay contextually typed.
Extract domain inputs instead of the Plate plugin context.

Use `defineEditorExtension` from `@platejs/plite` only for independently
reusable standalone Plite descriptors. See
[Plugin Methods](/docs/plugin-methods#install-plite-capabilities).

## Codec Inference

Use `defineCodecs` in the constructor's `codecs` callback. It is the codec
map's single inference anchor:

```ts title="strong-plugin.ts" showLineNumbers
import { createBasePlugin, property } from 'platejs';

export const StrongPlugin = createBasePlugin({
  codecs: ({ defineCodecs }) =>
    defineCodecs({
      'text/html': {
        decode: () => true,
        decodeOnly: true,
        match: [{ tag: 'strong' }],
      },
    }),
  key: 'strong',
  schema: { mark: property.boolean() },
});
```

The one-argument form owns self and product maps. For a foreign contribution,
call `defineCodecs(TargetPlugin, map)`; Plate injects the target into every HTML
rule. Keep the map MIME-keyed, and use either one `'text/html'` rule or a
non-empty ordered rule tuple. Do not author direct codec maps or annotate the
callbacks.

## Another Plugin

Use `getBasePlugin(editor, Plugin)` when plugin-owned code needs another
plugin's context. The editor argument is required.

```ts title="link-aware-plugin.ts" showLineNumbers
import { LinkPlugin } from '@platejs/link/react';
import { createPlatePlugin, getBasePlugin } from 'platejs/react';

export const LinkAwarePlugin = createPlatePlugin({
  key: 'linkAware',
  handlers: {
    onKeyDown: ({ editor, event }) => {
      if (event.key !== 'Enter') return;

      const link = getBasePlugin(editor, LinkPlugin);

      console.info(`Link node type: ${link.type}`);
    },
  },
});
```

Use this for cross-plugin reads. Keep cross-plugin writes rare; they couple two
plugins tightly.

## React Components

Use `useEditorPlugin` inside a component rendered under `<Plate>`. It returns
the same plugin context.

```tsx title="counter-badge.tsx" showLineNumbers
import { useEditorPlugin, usePluginStore } from 'platejs/react';

import { CounterPlugin } from './counter-plugin';

export function CounterBadge() {
  const { type } = useEditorPlugin(CounterPlugin);
  const count = usePluginStore(CounterPlugin, 'count');
  const label = usePluginStore(CounterPlugin, 'label');

  return (
    <span data-plugin-type={type}>
      {label} ({count})
    </span>
  );
}
```

Use a selector callback when a component needs a derived value from several
state fields.

```tsx title="counter-badge.tsx" showLineNumbers
import { usePluginStore } from 'platejs/react';

import { CounterPlugin } from './counter-plugin';

export function CounterStatus() {
  const status = usePluginStore(CounterPlugin, (state) =>
    state.count === 0 ? 'empty' : 'active'
  );

  return <span>{status}</span>;
}
```

For code outside the nearest `<Plate>` provider, pass an editor explicitly with
`useEditorPluginStore`.

## Store State

Plugin state is stored per editor. Updating one editor's plugin store does not
update another editor.

```ts title="counter-plugin.ts" showLineNumbers
export const CounterPluginWithInitialCount = CounterPlugin.extend(
  ({ store }) => ({
    initialState: {
      count: store.get().count + 1,
    },
  })
);
```

`store.set` accepts either a partial object or a draft callback.

```ts title="counter-actions.ts" showLineNumbers
import { getBasePlugin, type PlateEditor } from 'platejs/react';

import { CounterPlugin } from './counter-plugin';

export function resetCounter(editor: PlateEditor) {
  const { store } = getBasePlugin(editor, CounterPlugin);

  store.set({
    count: 1,
  });

  store.set((draft) => {
    draft.count += 1;
  });
}
```

Plate throws when `store.get` or `usePluginStore` targets a missing state field
or selector.

Always pass the plugin descriptor to `usePluginStore` and
`useEditorPluginStore`. A key-only object has no state contract for TypeScript
to infer.

## API Reference

| Helper | Scope | Notes |
| --- | --- | --- |
| `getBasePlugin(editor, plugin)` | Any editor code. | Returns plugin context for the given editor and plugin. |
| `useEditorPlugin(plugin, id?)` | React under `<Plate>`. | Returns plugin context plus `store`. |
| `usePluginStore(plugin, key, ...args)` | React under `<Plate>`. | Subscribes to one state field or named selector. |
| `usePluginStore(plugin, selector, options?)` | React under `<Plate>`. | Subscribes to a value derived from plugin state. |
| `useEditorPluginStore(editor, plugin, key, ...args)` | React with explicit editor. | Use outside the closest editor provider. |
| `useEditorPluginStore(editor, plugin, selector, options?)` | React with explicit editor. | Explicit-editor variant of `usePluginStore`. |

For plugin extension methods, see [Plugin Methods](/docs/plugin-methods). For
plugin configuration, see [Plugin](/docs/plugin).
