Plite is a JSON editor runtime for building product-specific rich text editors. This docs section covers the Plite packages, their React renderer, their browser proof harness, and the boundaries that keep the runtime verifiable. Start here when you want the current package shape, not upstream Slate 0.x compatibility notes.

## Install

Install the React editor path first:

```bash
npm install plitejs react react-dom
```

Add optional packages only when the editor imports them:

```bash
npm install platejs @tanstack/react-virtual diff-match-patch-ts yjs
```

`@platejs/test` is Plate's test distribution. Its Node-safe root owns headless
fixtures; explicit subpaths own React, DOM, Playwright, and proof helpers. Use
it only in tests and proof harnesses.

## Core Shape

Plite gives you a document model, an explicit runtime, and React rendering hooks.

| Layer          | What it owns                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Document model | nested JSON nodes, paths, points, ranges, immutable snapshots, primary `children`, extra `roots`, and document `state`          |
| Runtime        | `editor.read.<group>.<method>()`, `editor.update.<group>.<method>()`, grouped read/update callbacks, transactions, canonical changes, commits, correction, anchors, history integration, and extension groups |
| React          | `<Plite>`, `<Editable>`, render functions, editor hooks, DOM repair, selection sync, overlays, and root-aware chrome            |
| Proof          | browser tests that check model state, rendered DOM, native selection where observable, focus, replay, and follow-up typing      |

The first editor usually looks like this:

```tsx
import { Editable, Plite, useEditor } from "plitejs/react";

const initialValue = [
  {
    type: "paragraph",
    children: [{ text: "A line of text." }],
  },
];

export function Editor() {
  const editor = useEditor({ initialValue });

  return (
    <Plite editor={editor}>
      <Editable placeholder="Start typing..." />
    </Plite>
  );
}
```

One-shot reads stay explicit:

```tsx
const value = editor.read.value();
```

One-shot writes stay explicit:

```tsx
editor.update.text.insert("Hello");
```

Use `editor.read((state) => ...)` and `editor.update((tx) => ...)` when a
command needs grouped reads, grouped writes, extension namespaces, update tags,
or post-commit hooks.

## Package Map

| Package                                                     | Read when                                                                                            |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| [`plitejs`](libraries/plite)                         | You need the editor runtime, document model, helper APIs, transactions, extensions, or state fields. |
| [`plitejs/dom`](libraries/plite-dom)                 | You need DOM conversion, clipboard helpers, hotkeys, or browser environment helpers.                 |
| [`plitejs/react`](libraries/plite-react)             | You render editors with React, use `<Editable>`, read editor state in components, or build overlays. |
| [`plitejs/history`](libraries/plite-history)         | You need undo/redo and history state.                                                                |
| [`plitejs/hyperscript`](libraries/plite-hyperscript) | You write JSX editor fixtures for tests.                                                             |
| [`platejs/yjs`](libraries/plite-yjs)                       | You connect a Plite editor to Yjs document meta and awareness.                                      |
| [`plitejs/page-layout`](libraries/plite-layout)           | You build page-layout proof surfaces or paged editor experiments.                                    |
| [`@platejs/test`](/docs/unit-testing)                    | You write headless, React, DOM, Playwright, or release-proof tests.                                   |

## Proof Boundary

This package set is unpublished beta documentation. Treat the runtime as current, but do not treat every adjacent editor problem as solved.

| Area                       | Claim                                                                                    |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| Desktop editor behavior    | Claimed when package tests and browser proof cover the behavior.                         |
| Raw mobile device behavior | Deferred until real device proof exists.                                                 |
| Pagination                 | Kept in `plitejs/page-layout` and example lanes; not the core editor promise.          |
| Collaboration              | `platejs/yjs` owns Plite/Yjs mapping. Apps own providers, auth, persistence, and rooms. |
| Upstream identity          | This is Plite package set, not an official upstream Slate release.               |

Read [Why This Fork](why-this-fork) for the maintenance philosophy and hard boundaries.
