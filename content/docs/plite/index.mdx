Plite is a JSON editor runtime for building product-specific rich text editors.
This section documents `plitejs`, its React renderer, its subpath modules, and
its runtime contracts. Start here for the current API; see
[From Slate 0.x](/docs/plite/migration) if you are migrating from upstream
Slate, or [To Plate](/docs/plite/to-plate) to move up to Plate's plugin
framework.

## Install

Install `plitejs` with React:

```bash
npm install plitejs react react-dom
```

Add optional peer dependencies only for the subpaths you import:

```bash
npm install @chenglou/pretext @tanstack/react-virtual diff-match-patch-ts yjs
```

| Optional peer | Required by |
| --- | --- |
| `@chenglou/pretext` | `plitejs/pagination` |
| `@tanstack/react-virtual` | `plitejs/react/virtualized` |
| `diff-match-patch-ts` | `plitejs/diff`, `plitejs/yjs` |
| `yjs` | `plitejs/yjs`, `plitejs/yjs/react` |

## Core shape

Plite gives you a document model, an explicit runtime, and React rendering hooks.

| Layer          | What it owns                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Document model | nested JSON nodes, paths, points, ranges, immutable snapshots, primary `children`, extra `roots`, persistent `meta`, and keyed `records`          |
| Runtime        | `editor.read.<group>.<method>()`, `editor.update.<group>.<method>()`, grouped read/update callbacks, transactions, canonical changes, commits, correction, anchors, history integration, and plugin groups |
| React          | `<EditorRoot>`, `<EditorContent>`, render functions, editor hooks, DOM repair, selection sync, overlays, and root-aware chrome            |
| Proof          | browser tests that check model state, rendered DOM, native selection where observable, focus, replay, and follow-up typing      |

The first editor usually looks like this:

```tsx
import { EditorContent, EditorRoot, useCreateEditor } from "plitejs/react";

const initialValue = [
  {
    type: "paragraph",
    children: [{ text: "A line of text." }],
  },
];

export function Editor() {
  const editor = useCreateEditor({ initialValue });

  return (
    <EditorRoot editor={editor}>
      <EditorContent placeholder="Start typing..." />
    </EditorRoot>
  );
}
```

One-shot reads stay explicit:

```tsx
const value = editor.read.value();
```

One-shot writes stay explicit:

```tsx
editor.update.text.insert("Hello");
```

Use `editor.read((state) => ...)` and `editor.update((tx) => ...)` when a
command needs grouped reads, grouped writes, plugin namespaces, update tags,
or post-commit hooks.

## Subpath map

| Subpath                                                          | Read when                                                                                            |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| [`plitejs`](/docs/plite/libraries/plite)                         | You need the editor runtime, document model, helper APIs, transactions, plugins, or state fields.    |
| [`plitejs/dom`](/docs/plite/libraries/plite-dom)                 | You need DOM conversion, clipboard helpers, hotkeys, or browser environment helpers.                 |
| [`plitejs/react`](/docs/plite/libraries/plite-react)             | You render editors with React, use `<EditorContent>`, read editor state in components, or build overlays. |
| [`plitejs/react/virtualized`](/docs/plite/libraries/plite-react/virtualized-rendering) | You render large documents with virtualized block windows.                             |
| [`plitejs/history`](/docs/plite/libraries/plite-history)         | You need undo/redo and history state.                                                                |
| [`plitejs/authored`](/docs/plite/libraries/plite-authored)       | You track attributed suggestions and accepted/proposed previews.                                     |
| [`plitejs/diff`](/docs/plite/libraries/plite-diff)               | You compare two immutable documents for structural diffs.                                            |
| [`plitejs/pagination`](/docs/plite/libraries/plite-pagination)   | You measure document geometry and render paged editor surfaces.                                      |
| [`plitejs/yjs`](/docs/plite/libraries/plite-yjs)                 | You connect a Plite editor to Yjs document state and awareness.                                      |
| [`plitejs/hyperscript`](/docs/plite/libraries/plite-hyperscript) | You write JSX editor fixtures for tests.                                                             |
| [`plitejs/testing`](/docs/plite/libraries/plite-testing)         | You build headless test editors, `DataTransfer` stubs, or browser-handle assertions.                 |

## Support scope

| Area                       | Scope                                                                                    |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| Desktop editor behavior    | Covered by package tests and Chromium/Firefox/WebKit browser suites.                     |
| Mobile device behavior     | Verified separately on real devices; do not infer from desktop viewport runs alone.      |
| Pagination                 | Lives in `plitejs/pagination` and `plitejs/pagination/react`.                            |
| Collaboration              | `plitejs/yjs` owns Plite/Yjs mapping. Apps own providers, auth, persistence, and rooms.  |
| Upstream identity          | `plitejs` is maintained in the Plate repository, not an upstream Slate release.          |

Read [Why Plite](/docs/plite/why-this-fork) for the architecture rationale and boundaries.
