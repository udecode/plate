---
title: "Plite Component"
description: "Provide one editor to Editable, toolbars, sidebars, projection sources, and change callbacks."
---

`Plite` provides a React context for one editor. Render it above `Editable`,
toolbars, sidebars, and any component that needs editor state.

## Minimal Usage

```tsx
<Plite editor={editor} onCommit={handleCommit}>
  <Toolbar />
  <Editable />
</Plite>
```

## Props

```typescript
type PliteBaseProps = {
  annotationStore?: PliteAnnotationStore | null;
  children: React.ReactNode;
  decorationSources?: readonly PliteDecorationSource[] | null;
  onCommit?: (context: PliteCommitContext) => void;
  onSelectionChange?: (context: PliteSelectionChangeContext) => void;
  onValueChange?: (context: PliteValueChangeContext) => void;
  readOnly?: boolean;
};

type PliteProps =
  | (PliteBaseProps & { editor: ReactEditor; root?: never })
  | (PliteBaseProps & { editor?: never; root: string });

type PliteCommitContext = {
  commit: EditorCommit;
  editor: ReactEditor;
  snapshot: EditorSnapshot;
};

type PliteSelectionChangeContext = PliteCommitContext & {
  selection: Selection;
};

type PliteValueChangeContext = PliteCommitContext & {
  value: Descendant[];
};
```

All three callbacks receive the same canonical commit context. `onValueChange`
and `onSelectionChange` add the current provider-root value or selection only
for commits that changed that fact.

Pass `editor` for the top-level provider. Use the `root`-only form only inside
an existing Plite runtime, when a nested provider should bind its callbacks and
context to another root.

### `editor`

Pass the editor created with `usePliteEditor`.

```tsx
const MyEditor = () => {
  const editor = usePliteEditor<CustomValue>({ initialValue });

  return <Plite editor={editor}>...</Plite>;
};
```

Seed the editor with `initialValue` when the editor is created. `<Plite>` does
not take an `initialValue` prop.

Use `createReactEditor` when an editor must be created outside a React
component or inside a custom hook that owns the same one-shot lifetime.

Use editor APIs for later document replacement. `initialValue` is not a
controlled value prop.

### `children`

Render `Editable` and any editor UI inside the provider.

```tsx
<Plite editor={editor}>
  <Toolbar />
  <Editable />
</Plite>
```

### `onCommit`

Use `onCommit` when React UI needs every published commit. The provider owns
the subscription for its full lifetime, so the callback works even when no
`Editable` is mounted beneath it.

```tsx
<Plite
  editor={editor}
  onCommit={({ commit, editor, snapshot }) => {
    if (
      commit.changed.has("document") ||
      commit.dirtyStateKeys.length > 0
    ) {
      saveDocument(editor.read.value());
    }

    reportCommit(commit, snapshot.version);
  }}
>
  <Editable />
</Plite>
```

Use `editor.subscribeCommit(...)` for infrastructure outside React provider
ownership, such as sync adapters, canonical change export, and instrumentation.

Use `onValueChange` when a React component only cares about provider-root value
changes.

```tsx
<Plite
  editor={editor}
  onValueChange={({ value }) => updateCurrentRootPreview(value)}
>
  <Editable />
</Plite>
```

### Saving Mounted Root Changes

Use `onValueChange` when you only need committed changes for the mounted root's
block array. This is the single-root shortcut, not the full document
persistence path.

```tsx
<Plite
  editor={editor}
  onValueChange={({ value }) => {
    localStorage.setItem("plite.children", JSON.stringify(value));
  }}
>
  <Editable />
</Plite>
```

The `value` argument is a root value, not the full persisted document. Use
`editor.subscribe(...)` and `editor.read.value()` when
you need named roots or persistent meta fields.

```tsx
useEffect(() => {
  return editor.subscribe((_snapshot, change) => {
    if (!change) return;

    if (!change.changed.has("document") && change.dirtyStateKeys.length === 0) {
      return;
    }

    const documentValue = editor.read.value();

    localStorage.setItem("plite.document", JSON.stringify(documentValue));
  });
}, [editor]);
```

See [Document Meta](../../concepts/14-document-state) for the full
persistence shape.

### Selection Changes

Use `onSelectionChange` when React UI only cares about model selection changes.

```tsx
<Plite
  editor={editor}
  onSelectionChange={({ selection }) => updateToolbar(selection)}
>
  <Editable />
</Plite>
```

### `decorationSources`

Decoration sources publish transient render-time ranges such as search matches,
diagnostics, and code highlights.

```tsx
const searchSource = usePliteDecorationSource(editor, {
  id: "search",
  read: ({ snapshot }) => findSearchMatches(snapshot, query),
});

<Plite decorationSources={[searchSource]} editor={editor}>
  <Editable renderSegment={renderSearchMatch} />
</Plite>;
```

Use provider-owned `decorationSources` so every `Editable` and overlay UI reads
from the same projection source. Use `Editable.decorate` for a simple
editor-local decoration callback.

### `annotationStore`

The annotation store publishes anchor-backed annotations to text rendering and annotation UI hooks.

```tsx
const annotations = comments.map((comment) => ({
  anchor: comment.anchor,
  data: comment,
  id: comment.id,
  projection: {
    status: comment.status,
    tone: comment.tone,
  },
}));

const annotationStore = usePliteAnnotationStore(editor, annotations);

<Plite annotationStore={annotationStore} editor={editor}>
  <Editable renderSegment={renderCommentSegment} />
  <CommentsSidebar />
</Plite>;
```

Widget stores are hook-owned. Create them with `usePliteWidgetStore` and pass
the store directly to `usePliteWidgets` or `usePliteWidget`; `Plite` does not
take a `widgetStore` prop.
