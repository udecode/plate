---
title: "Plite Component"
description: "Provide one editor to Editable, toolbars, sidebars, decorations, and change callbacks."
---

`EditorRoot` provides a React context for one editor. Render it above `Editable`,
toolbars, sidebars, and any component that needs editor state.

## Minimal usage

`Toolbar` is an application component.

```tsx
<EditorRoot editor={editor} onCommit={handleCommit}>
  <Toolbar />
  <Editable />
</EditorRoot>
```

## Props

```typescript
type EditorRootProps = {
  editor: Editor;
  root?: string;
  children: React.ReactNode;
  decorations?: readonly DecorationSource[] | null;
  onCommit?: (context: CommitContext) => void;
  onSelectionChange?: (context: SelectionChangeContext) => void;
  onValueChange?: (context: ValueChangeContext) => void;
  readOnly?: boolean;
};

type CommitContext = {
  commit: EditorCommit;
  editor: Editor;
  snapshot: EditorSnapshot;
};

type SelectionChangeContext = CommitContext & {
  selection: Selection;
};

type ValueChangeContext = CommitContext & {
  value: Descendant[];
};
```

All three callbacks receive the same canonical commit context. `onValueChange`
and `onSelectionChange` add the current provider-root value or selection only
for commits that changed that fact.

Pass `editor` to every provider. Add `root` when the provider should bind its
callbacks and context to a named secondary root; omit it for the primary root.

### `editor`

Pass the editor created with `useEditor`.

```tsx
const MyEditor = () => {
  const editor = useEditor({ initialValue });

  return <EditorRoot editor={editor}>...</EditorRoot>;
};
```

`EditorRoot` binds one editor runtime for its mounted lifetime. Passing a
different editor remounts everything below it, so it needs no `key`. A
named-root change keeps the same runtime.

Seed the editor with `initialValue` when the editor is created. `<EditorRoot>` does
not take an `initialValue` prop.

Use `createEditor` when an editor must be created outside a React
component. It is live when it returns, and `editor.destroy()` ends it.

Use editor APIs for later document replacement. `initialValue` is not a
controlled value prop.

### `children`

Render `Editable` and any editor UI inside the provider.

```tsx
<EditorRoot editor={editor}>
  <Toolbar />
  <Editable />
</EditorRoot>
```

### `onCommit`

Use `onCommit` when React UI needs every published commit. The provider owns
the subscription for its full lifetime, so the callback works even when no
`Editable` is mounted beneath it.

```tsx
<EditorRoot
  editor={editor}
  onCommit={({ commit, editor, snapshot }) => {
    if (
      commit.changed.has("document") ||
      commit.dirtyStateKeys.length > 0
    ) {
      saveDocument(editor.read.value());
    }

    reportCommit(commit, snapshot.version);
  }}
>
  <Editable />
</EditorRoot>
```

Use `editor.subscribeCommit(...)` for infrastructure outside React provider
ownership, such as sync adapters, canonical change export, and instrumentation.

Use `onValueChange` when a React component only cares about provider-root value
changes.

```tsx
<EditorRoot
  editor={editor}
  onValueChange={({ value }) => updateCurrentRootPreview(value)}
>
  <Editable />
</EditorRoot>
```

### Saving mounted root changes

Use `onValueChange` when you only need committed changes for the mounted root's
block array. This is the single-root shortcut, not the full document
persistence path.

```tsx
<EditorRoot
  editor={editor}
  onValueChange={({ value }) => {
    localStorage.setItem("plite.children", JSON.stringify(value));
  }}
>
  <Editable />
</EditorRoot>
```

The `value` argument is a root value, not the full persisted document. Use
`editor.subscribeCommit(...)` and `editor.read.value()` when
you need named roots or persistent meta fields.

```tsx
import { useEffect } from "react";

useEffect(() => {
  return editor.subscribeCommit((change) => {

    if (!change.changed.has("document") && change.dirtyStateKeys.length === 0) {
      return;
    }

    const documentValue = editor.read.value();

    localStorage.setItem("plite.document", JSON.stringify(documentValue));
  });
}, [editor]);
```

See [Document Meta](../../concepts/14-document-state) for the full
persistence shape.

### Selection changes

Use `onSelectionChange` when React UI only cares about model selection changes.

```tsx
<EditorRoot
  editor={editor}
  onSelectionChange={({ selection }) => updateToolbar(selection)}
>
  <Editable />
</EditorRoot>
```

### `decorations`

Decoration sources publish transient text attributes for search matches,
diagnostics, code highlights, comments, and remote cursors.

```tsx
import { useMemo } from "react";

const searchDecorations = useMemo(
  () =>
    ({
      id: "search",
      read: ({ entry: [node, path] }) => {
        if (!TextApi.isText(node)) return [];

        return findMatches(node.text, query).map(({ end, start }, index) => ({
          attributes: { className: "search-match" },
          key: `search:${path.join(".")}:${index}`,
          range: {
            anchor: { path, offset: start },
            focus: { path, offset: end },
          },
        }));
      },
    }) satisfies DecorationSource<typeof editor>,
  [editor, query]
);

<EditorRoot decorations={[searchDecorations]} editor={editor}>
  <Editable />
</EditorRoot>;
```

`read` runs once per indexed node when the source is installed and only for
affected input node keys after document edits. Every decoration needs a stable
key, a range, and render-safe attributes. Plite merges overlapping sources and
wakes only text nodes whose merged attributes changed.

Use `observe` when an external store can name the affected node keys.

```tsx
const diagnostics = {
  id: "diagnostics",
  observe: ({ refresh }) =>
    diagnosticsStore.subscribe(({ nodeKeys }) => refresh({ nodeKeys })),
  read: ({ entry }) => diagnosticsStore.read(entry),
} satisfies DecorationSource<typeof editor>;
```

Pass `{ nodeKeys: "all" }` only when the source cannot identify affected
inputs. The provider subscribes once per source; rendered text subscribes by
node key.

### Annotation providers

Pass the annotation store directly to `useAnnotation(store, id)` and
`useAnnotations(store)` in sidebars and other consumers. Add a decoration source
only when an annotation also needs inline paint.

`CommentsSidebar` is an application component that accepts the store and calls
`useAnnotations(store)` to read it.

```tsx
const annotations = comments.map((comment) => ({
  anchor: comment.anchor,
  data: comment,
  id: comment.id,
}));

const annotationStore = useAnnotationStore(editor, annotations);

<EditorRoot decorations={[commentDecorations]} editor={editor}>
  <Editable />
  <CommentsSidebar store={annotationStore} />
</EditorRoot>;
```
