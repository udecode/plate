title: "Annotations"
description: "Attach durable range identities to editor text with anchors and read them from React UI."

Annotations attach durable ranges to editor text and publish them to sidebars
and other React UI.
Use [Decorations, annotations, and widgets](../../concepts/18-decorations-annotations-widgets) for the
broader choice between decorations, retained anchors, and projected text
rendering.

## When to use annotations

Use anchored annotations when a range has identity beyond a single render pass:
review comments, issue markers, tracked external diagnostics, resolved threads,
or other application-owned ranges.

Use decorations for transient paint such as search matches. Render app-owned UI
for nodes, selections, or annotations.

## Local anchors

Use `editor.anchor` when the anchor belongs to the local editor runtime.

```tsx
const anchor = editor.anchor(
  {
    anchor: { path: [0, 0], offset: 3 },
    focus: { path: [0, 0], offset: 18 },
  },
  { association: "inward", deletion: "nearest" }
);
```

Use `nearest` for durable annotations. A range whose text is deleted still
spans the place where the text was.
[`editor.read.ranges.isEmpty`](../../api/locations/range#editor-reads) tells whether it
still covers anything, and saved undo and redo restore its exact endpoints.

Resolve each anchor against the exact view reading it (`anchor.resolve(editor)`).
Subscribe to `editor.subscribeCommit` and check `commit.changed.anchors()` to
update your feature store and refresh only the affected text nodes on its
`DecorationSource`.

```tsx
const commentDecorations: DecorationSource<typeof editor> = {
  id: "comments",
  observe: ({ refresh }) =>
    commentsStore.subscribe(({ nodeKeys }) => refresh({ nodeKeys })),
  read: ({ editor: view, entry: [node, path] }) =>
    commentsStore.readDecorations(view, node, path),
};
```

Inline paint is a separate `DecorationSource`. The feature that owns the
visual states converts resolved ranges into keyed decoration attributes.

```tsx
<EditorRoot decorations={[commentDecorations]} editor={editor}>
  <EditorContent />
  <CommentsSidebar />
</EditorRoot>;
```

Release anchors when the app removes the annotation.

```tsx
anchor.release();
```

## External comment stores

Comment bodies, permissions, resolved state, and audit events belong to the app
or sync service. The Plite document value owns document content.
Use [Document Meta](../../concepts/14-document-state) for document metadata
and settings that should persist with the document.

## Comment channels

Use separate channels for the document and the comments.

```tsx
// Writer lane: document channel.
writerEditor.update((tx) => {
  tx.text.insert("hello", { at });
});

// Reviewer lane: annotation channel.
commentsMap.set(threadId, {
  anchor,
  body,
  status: "open",
});
```

A read-only reviewer can select text, create a comment anchor, and update a
thread without document-write permission. The feature resolves the anchor
against the current document snapshot for rendering.

The `comment-mode` example renders this as two panes:

- edit mode on the left, editable document channel
- comment mode on the right, read-only document with writable comments
- shared external comment state
- same resolved anchors rendered in both panes

The comment-mode controls do not call `editor.update` or mutate the
document.

## Widgets

Render app-owned UI from resolved anchor ranges in the target view (for example,
via `useEditorSelector((view) => anchor.resolve(view))`).
Use `useSelectionGeometry({ editableRef })` for selection-positioned UI in one
exact `EditorContent`.

## External anchor adapter

An external adapter can keep the document and comments in separate stores.

```ts
type ExternalAnnotationAnchor = {
  release(): void;
  resolve(): Range | null;
};

const anchor = externalAnnotationAdapter.anchorFromPliteRange(editor, range);

commentChannel.set(threadId, {
  anchor,
  body,
  status: "open",
});
```

The adapter owns mapping, drift recovery, deletion policy, and permissions.

## Document-embedded ids

Document-embedded ids are useful when the product wants comments to copy, paste,
serialize, or travel with document content.

Use this as an adapter strategy, not as the default storage model for comment
bodies or permissions. The document may store a lightweight id; the comment
thread still belongs to the app or sync service.

## Performance rules

Check `commit.changed.anchors()` in `editor.subscribeCommit` so edits re-resolve
only anchors that moved. Call `refresh({ nodeKeys })` with exact affected node
keys when external state changes. Decoration subscribers wake only when merged
text attributes change.
