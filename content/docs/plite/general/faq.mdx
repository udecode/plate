These answers describe `plitejs`.

## Why is pasted content plain text?

Plite does not know your product schema. It cannot safely turn arbitrary HTML into your nodes without an app-owned policy.

Paste first tries an internal Plite fragment, then registered DataTransfer
formats, and finally plain text. Intercept `domCommands.insertData`
through plugin `commands` when the app wants to consume `DataTransfer` HTML,
files, or custom MIME data. Return a transaction spec when the interceptor owns
the paste, or `next()` to continue the default import path.

Use [DOM](../libraries/plite-dom), [Event Handling](../libraries/plite-react/event-handling), and the [Paste HTML example](/examples/plite/paste-html) as the starting points.

## What browsers and devices does Plite support?

Desktop browser behavior is claimed only where tests and browser proof cover it.

The test suites target current Chromium, Firefox, Safari/WebKit, and mobile viewport rows through Playwright. Raw mobile-device behavior is verified separately on real devices and should not be inferred from a desktop browser run.

If a behavior depends on native selection, IME, clipboard, drag/drop, hidden DOM, or huge documents, verify it in a browser before treating it as supported.

## Is this the official Slate release?

No. `plitejs` is maintained in the Plate repository. It keeps a plain JSON document model, but its canonical change engine, runtime, package exports, and public API are independent of upstream Slate.

Read [Why Plite](../why-this-fork) for the architecture rationale and boundaries.
