讨论是可复制的 UI，用于在一个锚定浮动面板中打开每个区块的评论和文档建议。Comments 管理线程记录与映射范围；Suggestion 管理文档修改建议。

## 所有权

| 所有者 | 职责 |
| --- | --- |
| `platejs/comments` 和 `platejs/comments/react` | 管理评论记录、操作、映射范围、高亮和激活状态 |
| 复制的 `comment` 项 | 渲染富文本表单与评论卡片，并通过 `CommentKit` 提供默认样式 |
| `SuggestionPlugin` | 在文档中存储建议，并负责接受或拒绝建议 |
| 复制的 `discussion` 项 | 一次性索引两种记录，然后渲染每个区块的触发器和 Floating Discussion |

应用负责获取和保存评论记录，并提供用户、权限与当前文档。Comments 插件管理已加载的数据和范围映射。建议数据位于编辑器节点中，因为接受或拒绝建议会修改文档。

## 安装

安装组合视图和评论工具栏操作。Discussion 项会安装它依赖的 Comment 与 Suggestion UI。

```bash
npx shadcn@latest add https://platejs.org/r/discussion.json https://platejs.org/r/comment-toolbar-button.json
```

## 用法

安装 `DiscussionKit`，并把获取的评论记录传给 `CommentsPlugin`。该插件集包含评论样式、共享索引、区块触发器和 Floating Discussion。每个编辑器会在内部绑定自己的原生范围。

```tsx title="components/editor/discussion-editor.tsx" showLineNumbers
"use client";

import type { CommentThread, CommentUser } from "platejs/comments";
import type { EditorValueInput } from "platejs";
import { CommentsPlugin } from "platejs/comments/react";
import { Plate, useCreateEditor } from "platejs/react";

import { DiscussionKit } from "@/components/editor/discussion";
import { Editor, EditorContainer } from "@/components/editor/editor";
import { EditorKit } from "@/components/editor/plugins";

export function DiscussionEditor({
  initialValue,
  initialThreads,
  users,
  currentUserId,
}: {
  initialValue: EditorValueInput;
  initialThreads: readonly CommentThread[];
  users: Record<string, CommentUser>;
  currentUserId: string;
}) {
  const editor = useCreateEditor({
    plugins: [
      ...EditorKit,
      ...DiscussionKit,
      CommentsPlugin.configure({
        initialState: { initialThreads, users, currentUserId },
      }),
    ],
    initialValue,
  });

  return (
    <Plate editor={editor}>
      <EditorContainer>
        <Editor />
      </EditorContainer>
    </Plate>
  );
}
```

`EditorKit` 包含复制的 `SuggestionKit`。如果编辑器使用更小的插件集，请加入 `DiscussionSlots` 所读取的同一个 `suggestionPlugin` 导出。

## 审阅模型

Discussion 会一次性索引未解决记录，按区块排列，并在每个区块内按时间排序：

- 根评论线程显示为评论卡片；
- 文档建议显示为带有接受和拒绝操作的审阅卡片；
- 目标指向建议的线程显示在对应建议卡片内；
- 解决评论线程会移除它的锚点高亮；
- 接受或拒绝建议会隐藏其卡片和回复；撤销会恢复它们，不改变线程的解决状态。

区块触发器只订阅各自的键控摘要。编辑评论正文不会重建编辑器装饰、重新计算索引或唤醒无关区块。

## Floating Discussion

区块触发器会打开该区块的全部评论和建议。点击行内注解文本会打开该位置的确切项目。两个入口共用同一组插件记录、建议和操作。

当评论范围重叠时，点击共享文本会按来源顺序打开该位置的所有线程。点击没有标记的编辑器内容会清除当前激活项。

如果编辑删除了评论范围内的全部字符，文档中不会显示行内高亮。区块触发器仍可
打开该线程，Floating Discussion 会锚定到这个触发器；撤销后会恢复精确的文本范围。

## 建议评论

Discussion 通过建议 ID 关联回复。建议本身提供回复的位置和文档生命周期。

```ts
editor.plugin(CommentsPlugin).api.createThread({
  body,
  excerpt: "insert suggestion",
  target: { id: suggestionId, type: "suggestion" },
});
```

回复使用建议的位置，无需创建评论锚点。建议消失时，应用记录保留正文和显式解决状态。如果撤销或文档更新恢复同一个建议 ID，其未解决的回复会再次显示。`SuggestionPlugin` 负责文档修改；Discussion 组合审阅卡片和应用回复。

## 只读与静态渲染

将相同的序列化记录及其匹配的文档值传给各个编辑器。只读 React 编辑器使用 `CommentsPlugin`；`EditorStatic` 使用 `BaseCommentsPlugin` 和复制的静态评论样式。包会为每个编辑器绑定独立的原生范围；评论卡片由复制的 UI 渲染。

保存时，将 `editor.plugin(CommentsPlugin).api.getThreads()` 与 `editor.read.value()` 一起持久化。记录加载、保存与操作请参阅[评论](/docs/comment)，建议转换请参阅[建议](/docs/suggestion)。

## API 参考

### `DiscussionKit`

将它加入编辑器的插件列表。它包含 `CommentKit` 和完整的 `DiscussionSlots` 组合。

### `DiscussionSlots`

自定义组合时，把完整值传给 `CommentsPlugin.configure({ slots: DiscussionSlots })`。它一起安装共享索引、区块触发器和 Floating Discussion；不要单独安装其中的插槽。
