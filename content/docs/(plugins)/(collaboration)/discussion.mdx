Discussion is copied UI that opens each block's comments and document suggestions in one anchored popover. Comments owns thread records and mapped ranges; Suggestion owns proposed document edits.

## Ownership

| Owner | Responsibility |
| --- | --- |
| `platejs/comments` and `platejs/comments/react` | Own comment records, actions, mapped ranges, decoration, and activation |
| Copied `comment` item | Render rich comment forms and cards, and supply presentation defaults through `CommentKit` |
| `SuggestionPlugin` | Store proposed edits in the document and accept or reject them |
| Copied `discussion` item | Index both record types once, then render per-block triggers and Floating Discussion |

The application fetches and saves comment records, provides users and permissions, and supplies the current document. The Comments plugin owns the loaded data and range mapping. Suggestion data stays in editor nodes because accepting or rejecting a suggestion mutates the document.

## Installation

Install the combined view and the comment toolbar action. The Discussion item installs its Comment and Suggestion UI dependencies.

```bash
npx shadcn@latest add https://platejs.org/r/discussion.json https://platejs.org/r/comment-toolbar-button.json
```

## Usage

Install `DiscussionKit` and pass fetched comment records to `CommentsPlugin`. The kit includes comment styling, the shared index, per-block triggers, and Floating Discussion. Each editor binds its own native ranges internally.

```tsx title="components/editor/discussion-editor.tsx" showLineNumbers
"use client";

import type { CommentThread, CommentUser } from "platejs/comments";
import type { EditorValueInput } from "platejs";
import { CommentsPlugin } from "platejs/comments/react";
import { Plate, useCreateEditor } from "platejs/react";

import { DiscussionKit } from "@/components/editor/discussion";
import { Editor, EditorContainer } from "@/components/editor/editor";
import { EditorKit } from "@/components/editor/plugins";

export function DiscussionEditor({
  initialValue,
  initialThreads,
  users,
  currentUserId,
}: {
  initialValue: EditorValueInput;
  initialThreads: readonly CommentThread[];
  users: Record<string, CommentUser>;
  currentUserId: string;
}) {
  const editor = useCreateEditor({
    plugins: [
      ...EditorKit,
      ...DiscussionKit,
      CommentsPlugin.configure({
        initialState: { initialThreads, users, currentUserId },
      }),
    ],
    initialValue,
  });

  return (
    <Plate editor={editor}>
      <EditorContainer>
        <Editor />
      </EditorContainer>
    </Plate>
  );
}
```

`EditorKit` includes the copied `SuggestionKit`. If your editor uses a smaller kit, include the same exported `suggestionPlugin` that `DiscussionSlots` reads.

## Review model

Discussion indexes unresolved records once, orders them by block, and sorts each block chronologically:

- root comment threads appear as comment cards;
- document suggestions appear as review cards with Accept and Reject actions;
- threads whose target is a suggestion appear inside that suggestion card;
- resolving a thread removes its anchor decoration;
- accepting or rejecting a suggestion hides its card and replies; undo restores them without changing thread resolution.

Discussion reads ranges and changed IDs from the same Annotation projection that paints comments. Block triggers subscribe only to their keyed summaries; same-block range movement leaves those summaries unchanged. Editing a comment body does not rebuild editor decorations, recompute the index, or wake unrelated blocks.

## Floating discussion

A block trigger opens every comment and suggestion attached to that block. Clicking inline annotation text opens the exact items at that point. Both entry points use the same plugin records, suggestions, and actions.

When comment ranges overlap, clicking the shared text opens every thread at that point in source order. The selected ID group survives edits and source reordering until another activation or thread removal changes it. Clicking unmarked editor content clears the active review.

If an edit deletes every character in a comment range, no inline text remains
to highlight. The block trigger keeps the thread reachable, and Floating
Discussion anchors to that trigger until undo restores the exact text range.

## Suggestion comments

Discussion attaches replies to the suggestion ID. The suggestion supplies their location and document lifecycle.

```ts
editor.plugin(CommentsPlugin).api.createThread({
  body,
  excerpt: "insert suggestion",
  target: { id: suggestionId, type: "suggestion" },
});
```

Replies use the suggestion's location without allocating a comment anchor. Comment records retain their bodies and explicit resolution when the suggestion disappears. If undo or a document update restores that suggestion ID, its unresolved replies appear again. `SuggestionPlugin` owns document mutation; Discussion composes the review card and comment replies.

## Read-only and static rendering

Pass the same serialized records to each editor with its matching document value. Use `CommentsPlugin` for a read-only React editor and `BaseCommentsPlugin` with copied static comment styling for `EditorStatic`. The package binds independent native ranges for each editor; thread cards remain copied UI.

Save `editor.plugin(CommentsPlugin).api.getThreads()` alongside `editor.read.value()`. See [Comments](/docs/comment) for record loading, saving, and actions, and [Suggestion](/docs/suggestion) for suggestion transforms.

## API Reference

### `DiscussionKit`

Install the kit in the editor plugin list. It includes `CommentKit` and the complete `DiscussionSlots` composition.

### `DiscussionSlots`

For custom composition, pass the complete value to `CommentsPlugin.configure({ slots: DiscussionSlots })`. It owns the shared index, per-block trigger, and Floating Discussion together; do not install its slots separately.
