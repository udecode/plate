线程行保存在应用自己的表中，评论范围随每个文档版本一起保存。包负责记录、评论操作、订阅和范围映射；应用负责存储、授权与持久化。

<PackageInfo>

## 功能

- 包含富文本消息、ISO 时间戳和解决状态的语义线程记录
- 线程行存于应用自己的表，普通范围随每个文档版本保存
- 随编辑、撤销和重做更新的范围
- 成功创建本地线程后，与正文共享顺序的会话撤销和重做
- 有序重叠高亮与每个编辑器独立的激活状态
- 用于打开、已解决和目标不可用对话的文档级发现入口
- 按记录、待提交输入和线程列表分别订阅
- 通过复制的 Discussion UI 审阅评论和建议
- 线程和消息上的应用数据
- 以其他作者身份评论，例如 AI

</PackageInfo>

### 添加 Kit

从应用的表读取线程行，与匹配文档版本保存的范围一起加载：

```tsx title="components/editor/comments-editor.tsx" showLineNumbers
"use client";

import type { EditorValueInput } from "platejs";
import type { CommentRanges, CommentThread, CommentUser } from "platejs/comments";
import { CommentsPlugin } from "platejs/comments/react";
import { EditorRoot, useCreateEditor } from "platejs/react";

import { BasicBlocksKit } from "@/components/editor/basic-blocks";
import { AllCommentsButton, CommentToolbarButton } from "@/components/editor/comment-toolbar-button";
import { DiscussionKit } from "@/components/editor/discussion";
import { Editor, EditorContainer } from "@/components/editor/editor";
import { LinkKit } from "@/components/editor/link";
import { Toolbar } from "@/components/editor/toolbar";

export function CommentsEditor({ value, ranges, threads, users, userId }: {
  value: EditorValueInput;
  ranges: CommentRanges;
  threads: readonly CommentThread[];
  users: Record<string, CommentUser>;
  userId: string;
}) {
  const editor = useCreateEditor({
    plugins: [
      ...BasicBlocksKit,
      ...LinkKit,
      ...DiscussionKit,
      CommentsPlugin.configure({
        initialState: {
          initialComments: { ranges, threads },
          users,
        },
      }),
    ],
    initialValue: value,
    userId,
  });

  return (
    <EditorRoot editor={editor}>
      <EditorContainer>
        <Toolbar>
          <CommentToolbarButton />
          <AllCommentsButton />
        </Toolbar>
        <Editor />
      </EditorContainer>
    </EditorRoot>
  );
}
```

`initialComments` 只在每个编辑器初始化时读取一次。传入与 `value` 一起保存的范围，不要使用其他版本的范围。加载另一个版本时，用对应文档和范围创建新编辑器；修改初始属性不会替换当前记录。

</Steps>

## 应用数据

`CommentThread` 保存对话数据和语义目标：`{ type: 'range' }` 或 `{ type: 'change', id }`。实时记录不包含映射后的 `Range`。消息正文使用 Plate `Value`，时间戳使用 ISO 8601 字符串。未解决线程的 `resolution` 为 `null`；已解决线程的值为 `{ resolvedAt: string | null, userId: string | null }`。

线程记录和私有锚点属于共享编辑器模型。每个视图读取自己的位置：同一线程在不同投影中可以有不同范围或不可用，无需复制记录或锚点。

通过使用坐标的精确视图读取插件 API。此例中的 `editor` 是消费返回坐标的视图；React UI 可通过 `useEditor()` 获取已挂载的编辑器：

```ts
import { CommentsPlugin } from "platejs/comments/react";

const comments = editor.plugin(CommentsPlugin).api;
const thread = comments.getThread(threadId);
const attachment = comments.attachment(threadId);

if (attachment?.type === "range" && attachment.status === "attached") {
  editor.update.selection.set(attachment.range);
}
```

`attachment(id)` 返回以下值之一：

| 值 | 含义 |
| --- | --- |
| `{ type: 'range', status: 'attached', range }` | 当前映射范围可用 |
| `{ type: 'range', status: 'unavailable' }` | 当前文档投影没有可显示的范围 |
| `{ type: 'change', id }` | 通过 Authored 定位稳定的 change ID |
| `null` | 线程不存在 |

`unavailable` 不能证明文本已被删除；投影隐藏目标或历史版本缺少目标也会导致此状态。**所有评论**会保留线程和原始摘录，只有附着位置可用时才显示行内高亮和区块计数。

建议不再待处理后，其上的线程仍保留 `{ type: 'change', id }` 目标。读取 `editor.plugin(AuthoredPlugin).read.outcome(id)` 可判断该 change 仍待处理、已被接受、已被拒绝或两者兼有，还是没有裁决地离开了审阅，见 [Authored Changes](/cn/docs/authored-changes#change-如何离开审阅)。

线程可以位于命名根中，例如[白板](/docs/board)便签的文字。页面视图读取它时，范围的两端都带有便签的根。便签视图会把其他根中的线程（包括页面中的线程）读取为 `unavailable`。

### 附加应用数据

线程及其每条消息都可以带 `data`，即应用自有的 JSON 对象，例如表情回应或生成评论的模型。Comments 只检查它是 JSON，随记录保存一份冻结副本，从不读取其中的键。创建线程或回复时设置它，之后用 `setData` 修改：

```ts
import { CommentsPlugin } from "platejs/comments/react";

const comments = editor.plugin(CommentsPlugin).api;

await comments.createThread({ body, data: { priority: "high" }, target });
await comments.reply(threadId, body, { data: { reactions: [] } });
await comments.setData(threadId, { priority: "low" });
await comments.setData(threadId, { reactions: ["+1"] }, { messageId });
await comments.setData(threadId, null);
```

传给 `createThread` 或 `createDraft` 的 `data` 属于线程，第一条消息不带数据。`setData` 替换已发布线程的数据；传入 `messageId` 时替换该消息的数据；传入 `null` 时删除数据。它经过 `mutate`，操作名为 `'setData'`，不进入文档历史。回复、编辑消息和解决线程都保留记录已有的数据。不是 JSON 对象的值返回 `invalid`，`createDraft` 对它返回 `null`。已保存行或 `mutate` 返回的记录带 `data: null` 时（例如可为空的 JSON 列），按没有数据读取。已保存行的 `data` 是其他非 JSON 对象的值时，该行不加载，并产生 `'invalid-thread'` 问题。

### 发现对话

编辑器安装 Comments 时，在工具栏中渲染 `AllCommentsButton`。它按需打开分页 dialog，无需文档选区，也可用于只读视图或未安装 Suggestions 的编辑器。**全部**、**打开**和**已解决**按对话状态筛选；目标是否可用不会移除记录。

每一行都会标注其目标。当前视图能显示的目标显示 **已附着到文档**，无法显示的范围显示 **此视图中目标不可用**。建议不再待处理后，其上的线程会说明审阅的结果：**建议已接受**、**建议已拒绝**、同时带有两种裁决时显示 **建议已接受并已拒绝**，没有裁决地离开审阅时显示 **建议已删除**，例如接受被划掉的表格时把它一起带走。重新加载后这些标签不变。在 preview 下，待处理建议显示 **此视图中目标不可用**，因为它的范围指向存储文档中的位置。

只有当前挂载页会解析目标。**在文档中显示**只对已附着的目标可用。点击时和下一帧它都会重新读取目标，然后选择并滚动到当前视图中的精确范围。对于白板便签中的线程，它会选中便签文字、聚焦便签，并在便签有部分位于视野外时平移白板。有未保存的回复或编辑内容，或操作仍在等待时，dialog 会保留当前页，并阻止关闭、筛选、翻页、导航和破坏性删除，直到操作成功或用户明确取消。

### 保存和加载

Comments 把每个对话分成两部分。线程行保存人们写下的内容，存于应用自己的表，并通过 `mutate` 修改。范围记录线程在文本中的位置，随文档变化。每个文档版本都一起保存 `api.ranges()`：

```ts
import { CommentsPlugin } from "platejs/comments/react";

const revision = {
  commentRanges: editor.plugin(CommentsPlugin).api.ranges(),
  document: editor.read.value(),
  revisionId,
};

await repository.put(revision, { ifMatch: previousRevision });
```

此例中的 `repository` 是应用的存储适配器，它在提交前检查预期版本。

`ranges()` 返回 `CommentRanges`：以线程 ID 为键、值为普通 `Range` 的记录。它包含已发布线程、仍在等待 `mutate` 的创建和草稿发布、发布时抛出错误的草稿，以及孤立范围。其他本地草稿、不可用的范围和建议上的线程没有条目；建议线程的记录保存 change ID。范围只与保存时的文档版本对应。

命名根中的范围（例如白板便签文字中的范围）在两端都带有该根，页面范围不带根：

```ts
editor.plugin(CommentsPlugin).api.ranges();
// {
//   t1: {
//     anchor: { path: [0, 0], offset: 0 },
//     focus: { path: [0, 0], offset: 5 },
//   },
//   t2: {
//     anchor: { path: [0, 0, 0], offset: 0, root: "board:demo" },
//     focus: { path: [0, 0, 0], offset: 4, root: "board:demo" },
//   },
// }
```

加载时，用 `revision.document` 和相同的内容插件创建新编辑器，把 `{ threads, ranges: revision.commentRanges }` 传给 `initialComments`，其中 `threads` 从应用的表读取。这对数据的类型是 `SavedComments`。

文档 schema 升级时，把版本的范围作为 `ranges` 传给迁移该文档的同一次 `migrateDocument` 调用，并保存结果中的范围，参见[迁移评论范围](/cn/docs/editor#迁移评论范围)。

#### 加载问题

Comments 逐行接收数据。格式错误或未发布的线程、重复的线程 ID，以及超出文档的范围各自单独丢弃。`getSnapshot().issues` 以 `CommentsLoadIssue` 值 `{ code, id }` 列出它们，并为每个当前孤立范围列出一条 `'orphan-range'`：

| `code` | 含义 |
| --- | --- |
| `'invalid-thread'` | 线程行格式错误或未发布，未加载 |
| `'duplicate-thread'` | 后一行重复使用线程 ID；第一行已加载 |
| `'invalid-range'` | 范围格式错误、超出文档、跨越两个根，或属于建议上的线程 |
| `'orphan-range'` | 保存的范围没有已加载的线程；孤立范围重新附着或被丢弃后，它离开 `issues` |

只有 `threads` 不是数组或 `ranges` 不是记录时，加载才会抛出错误。Comments 无法识别坐标恰好有效的其他文档。

#### 孤立范围

孤立范围是没有已加载线程的保存范围。它随文档映射，`ranges()` 会再次保存它，但它不绘制任何高亮。某次加载缺少的线程（例如查询失败）会以这种方式保留范围，`mutate` 抛出错误的创建也是如此。线程通过 `replace` 或已提交的创建加载后，孤立范围会重新附着。

服务端确认线程已被拒绝或删除时，调用 `api.discardOrphan(id)`。它返回 `'discarded'`；该 ID 没有孤立范围时返回 `'not-orphan'`。`mutate` 抛出错误时，创建的范围保留为孤立范围，因为服务端可能已经保存了该创建。孤立范围就是该创建自己的范围，所以恢复其文字的撤销也会恢复保存的范围。被 `mutate` 拒绝的创建只丢弃这次尝试添加的范围。更早一次尝试保留的孤立范围不受影响，所以服务端因已保存该线程而拒绝的重试会保留其范围。

发布时抛出错误的草稿在仍是草稿期间，其范围保留在 `ranges()` 中。丢弃发布已抛出错误或仍在等待 `mutate` 的草稿时，其范围变为孤立范围。如果那次等待中的发布随后被拒绝，或从未调用 `mutate`，该孤立范围随之移除，除非该草稿更早的一次发布抛出了错误。服务端可能已经保存了那次更早的发布，所以其范围会保留。某个 ID 持有孤立范围时，`createDraft` 返回 `null`，因此一个 ID 不会有两个保存的范围。

#### 变更时保存

创建评论不会改变文档值，因此只靠 `EditorRoot` 的 `onValueChange` 会漏掉它。自动保存的应用还要从 `api.subscribeRanges(listener)` 安排保存。线程获得、失去或改存另一个范围时监听器运行，文档映射不会触发它：

```tsx
import { CommentsPlugin } from "platejs/comments/react";
import * as React from "react";

React.useEffect(
  () => editor.plugin(CommentsPlugin).api.subscribeRanges(scheduleSave),
  [editor, scheduleSave]
);
```

#### 卸载时保存

编辑器卸载时，范围在每个 React layout 和 passive effect 清理函数中仍可读取。编辑器销毁后 `ranges()` 会抛出错误。卸载后才运行的排队保存，必须在清理函数中捕获版本：

```tsx
React.useEffect(
  () => () => {
    queueSave({
      commentRanges: editor.plugin(CommentsPlugin).api.ranges(),
      document: editor.read.value(),
    });
  },
  [editor]
);
```

`scheduleSave` 和 `queueSave` 是应用的保存函数。普通范围评论仍不要求 Authored。普通重新加载从空的本地撤销栈开始。`getThreads()` 读取实时线程记录；应用的表保存它们的持久副本。

### 授权和提交操作

通过 `CommentsPlugin.configure({ initialState: { mutate } })` 配置应用适配器。回调接收结构有效的 `CommentMutationRequest`，同步或异步返回 `CommentMutationDecision`：

```ts showLineNumbers
import type { Range } from "platejs";
import type { CommentOperation, CommentThread } from "platejs/comments";

export type CommentMutationRequest = Readonly<{
  mutationId: string;
  operation: CommentOperation;
  previous: CommentThread | null;
  proposed: CommentThread | null;
  range?: Range;
}>;

export type CommentMutationDecision =
  | Readonly<{ status: 'commit'; thread: CommentThread | null }>
  | Readonly<{ code?: string; status: 'reject' }>;
```

服务端验证身份、授权并持久化后，返回 `{ status: 'commit', thread }`，其中 `thread` 是规范记录；删除时为 `null`。提交的记录保留提案中的线程 ID 和目标身份。拒绝写入时返回 `{ status: 'reject' }`，可附带 `code`。创建和草稿发布还会收到 `range`，即 `ranges()` 为它保存的范围。用 `mutationId` 保证重试幂等，并在存储层执行跨客户端的比较并交换检查。

Comments 只在提交后发布记录。拒绝或抛出错误时，保留原记录和输入。操作按线程串行执行；等待期间编辑器或线程失效时，可返回 `stale`。默认适配器在本地提交。隐藏控件或设置文档 `readOnly` 不能替代评论授权。

### 以其他作者身份评论

Comments 把每个线程、草稿、回复和解决记录为操作所经过的编辑器或视图的作者。要以编辑器用户之外的身份评论，例如 AI，就通过指定该作者的视图执行操作：

```ts
import { createEditorView } from "platejs";
import { CommentsPlugin } from "platejs/comments/react";

const ai = createEditorView(editor, { authorId: "ai" });

await ai.plugin(CommentsPlugin).api.createThread({
  body,
  target: { range, type: "range" },
});
```

新线程及其第一条消息的 `userId` 为 `'ai'`。编辑器本身和没有 `authorId` 的视图仍使用编辑器用户。把该作者加入 `users`，评论 UI 才能显示其名称。视图的作者只是客户端的声明。`mutate` 会在提议的记录中收到它，请在那里检查当前登录用户能否以该作者身份写入。

## 手动用法

无界面插件提供相同的数据与附着位置 API，不依赖 React。此例加载纯段落文档版本，线程行来自应用的表；更丰富的文档需要安装匹配的内容插件：

```bash
npm install platejs
```

```ts
import { BaseParagraphPlugin, createEditor } from "platejs";
import { BaseCommentsPlugin } from "platejs/comments";

const editor = createEditor({
  plugins: [BaseParagraphPlugin, BaseCommentsPlugin.configure({
    initialState: {
      initialComments: { ranges: revision.commentRanges, threads },
    },
  })],
  initialValue: revision.document,
  userId: "alice",
});
```

## 编辑与历史

Comments 在内部使用向内关联的 `nearest` 锚点。范围内插入文本会扩大范围，删除文本会缩小范围；边界处插入的文本保持在范围之外。

没有可显示的范围时，`attachment(id)` 返回 `unavailable`。讨论面板保留线程与摘录，不会高亮相邻文本。同一会话中的撤销和重做恢复映射后的范围，包括反向范围和重叠范围。

成功创建的本地线程会进入与正文编辑相同的会话撤销顺序。History 会先等待配置的 mutation adapter，再移动分支。撤销仅删除仍未变化且只有首条消息的线程；重做恢复其已保存的目标和规范线程。若线程已有回复、编辑、解决状态或服务端规范替换，或者 mutation 被拒绝、存储失败，本次回放会阻塞并停留在当前历史头，不会跳过线程而继续撤销下一条正文操作。通过只读视图创建的线程不进入撤销顺序，因为该视图无法提交。

解决与重新打开线程更新对话元数据，不进入文档撤销历史。回复、编辑消息、显式删除消息或线程也不会被文档撤销。撤销文本删除可以恢复高亮，但不会重建已显式删除的对话。

接受或拒绝建议属于可撤销的文档操作。决定及其撤销保留讨论正文和解决状态；建议再次可见时，线程仍关联同一个 Authored change ID。

### 历史版本

只读版本预览加载当前线程行，以及该历史文档版本保存的范围。此例从应用的表读取 `currentThreads`：

```ts
import type { SavedComments } from "platejs/comments";

const initialComments: SavedComments = {
  ranges: revision.commentRanges,
  threads: currentThreads,
};
```

用 `revision.document` 和此 `initialComments` 创建新的只读编辑器。没有保存范围的新线程显示不可用。线程已被删除的保存范围作为孤立范围加载，不绘制高亮。只有该历史 Authored 文档包含对应 ID 时，change 目标才可定位。

恢复历史版本时，在文档头版本检查下创建新的应用版本，保留当前线程行，只加载所选版本的范围。随后创建本地历史为空的新编辑器。本地线程创建的撤销记录只属于当前会话，不会从保存的范围或 `History.toJSON()` 恢复。参阅 [History](/docs/history)。

## 协作与只读审阅

独立编辑器可以加载同一保存版本，并绑定各自的附着位置。此持久化 API 不提供实时远程评论同步；操作适配器只向发起操作的编辑器返回规范记录。

保存的范围目标不支持恢复到已变化的 Yjs 房间基线。状态向量本身不能映射缺失的编辑，Yjs 接入也不支持恢复已持久化的本地撤销栈。应用必须先确认目标对应的精确保存基线。

只读视图应同时在 `EditorRoot` 和 `Editor` 上设置 `readOnly`。静态渲染使用 `BaseCommentsPlugin`，并配置复制的 `comment-static` 项提供的 `commentDecorationAttributes`。线程卡片仍属于复制的应用 UI。

## 旧文档迁移

加载包含 `comment`、`comment_*`、`comment_draft` 或 `commentTransient` 属性的文档前，运行 `extractLegacyCommentRanges`，并把它返回的文档和范围传给同一次 `migrateDocument` 调用：

```ts
import {
  extractLegacyCommentRanges,
  migrateDocument,
} from "platejs/migrations";

const {
  document: cleanDocument,
  ranges,
  report,
} = extractLegacyCommentRanges(legacyDocument, {
  threadIds: storedThreads.map((thread) => thread.id),
});
const migrated = migrateDocument(cleanDocument, {
  migrations: EditorMigrations,
  ranges,
  source: 53,
});

console.table(report);
```

检查每一行报告后，保存 `migrated.output`，并把 `migrated.ranges` 中非 `null` 的条目作为它的 `commentRanges`。被没有该标记的可见文字拆开的线程没有范围，会以 `split-group` 报告，其中列出每一段的范围。提取器不会编造缺失的线程 ID。请离线运行迁移；运行时插件不提供旧格式回退。参见[迁移评论范围](/cn/docs/editor#迁移评论范围)。

## API 参考

### 数据与范围

| 方法 | 用途 |
| --- | --- |
| `api.getThreads()` | 读取不可变的语义线程记录 |
| `api.getThread(id)` | 读取稳定的单条记录；不存在时返回 `undefined` |
| `api.ranges()` | 读取随该文档版本保存的 `CommentRanges`；编辑器销毁后抛出错误 |
| `api.getSnapshot()` | 读取稳定的线程 ID、可见 ID、草稿 ID、待提交输入与 `issues` |
| `api.discardOrphan(id)` | 删除没有已加载线程的保存范围；返回 `'discarded'` 或 `'not-orphan'` |
| `api.attachment(id)` | 读取调用视图中的 `CommentAttachment`；线程不存在时返回 `null` |
| `api.idsAt(location)` | 按记录顺序读取调用视图中该位置未解决的重叠评论 ID；未指定根的位置属于该视图的根 |
| `api.setActive(ids)` | 选择有序 ID 组；`[]` 清空选择 |
| `api.subscribeAttachments(listener)` | 观察调用视图中的附着位置映射和投影变化 |
| `api.subscribeRanges(listener)` | 观察线程获得、失去或替换保存的范围 |

### 评论操作

| 方法 | 用途 |
| --- | --- |
| `api.begin(range?)` | 在调用视图中捕获输入；光标位置扩展为所在文本区块 |
| `api.pendingRange()` | 读取调用视图中待提交输入映射后的范围 |
| `api.cancel()` | 关闭待提交输入并释放范围。已经发出的 `create` 仍会完成 |
| `api.create(body)` | 发布待提交线程；等待 `CommentMutationResult<string>` |
| `api.createThread(input)` | 发布范围或建议线程；等待 `CommentMutationResult<string>` |
| `api.reply(id, body, options?)` | 向未解决线程追加消息；`{ data }` 设置新消息的应用数据 |
| `api.edit(id, messageId, body)` | 在适配器授权下编辑消息 |
| `api.removeMessage(id, messageId)` | 删除消息；没有消息时删除线程 |
| `api.removeThread(id)` | 在适配器授权下删除线程 |
| `api.setData(id, data, options?)` | 替换已发布线程的应用数据，或用 `{ messageId }` 替换某条消息的数据；`null` 删除数据 |
| `api.resolve(id)` | 记录规范的解决人和时间 |
| `api.reopen(id)` | 清空解决状态元数据 |
| `api.publishDraft(id)` | 通过操作适配器提交本地草稿 |
| `api.createDraft(input)` | 创建本地未发布草稿；同步返回 `string` 或 `null` |
| `api.discardDraft(id)` | 删除本地未发布草稿；同步返回 `boolean` |

`createThread` 与 `createDraft` 接收 `CreateCommentThreadInput`：

```ts showLineNumbers
import type { Range, Value } from "platejs";
import type { CommentData } from "platejs/comments";

export type CreateCommentThreadInput = Readonly<{
  body: Value;
  data?: CommentData;
  excerpt?: string;
  id?: string;
  target:
    | Readonly<{ range: Range; type: 'range' }>
    | Readonly<{ id: string; type: 'change' }>;
}>;
```

`CommentData` 是由 `CommentDataValue` 组成的 JSON 对象：字符串、有限数字、布尔值、`null`、数组和嵌套对象。创建需要当前用户和非空正文。范围目标必须是同一个根中的非折叠范围。Comments 生成身份与时间戳，或接受适配器返回的规范值。

传给 `begin`、`createThread` 和 `createDraft` 的范围必须来自调用视图。未指定根的范围属于该视图的根；页面视图也接受指明便签根的范围，即 `ranges()` 返回的形式。锚点会在该视图中捕获坐标。通过消费坐标的视图读取 `pendingRange()` 和 `attachment(id)`，不要复用其他投影中的坐标。

`create` 和 `createThread` 返回 `Promise<CommentMutationResult<string>>`。其他持久化操作返回 `Promise<CommentMutationResult<undefined>>`。`begin`、`cancel`、`createDraft` 和 `discardDraft` 仅在本地执行。

```ts
export type CommentMutationResult<T = undefined> =
  | Readonly<{ status: 'applied'; value: T }>
  | Readonly<{ status: 'invalid' }>
  | Readonly<{ code?: string; status: 'rejected' }>
  | Readonly<{ status: 'stale' }>;
```

等待结果后再清空输入或更新选区：

```ts
const result = await comments.create(body);

if (result.status === "applied") {
  comments.setActive([result.value]);
}
```

遇到 `invalid`、`rejected`、`stale` 或异常时保留输入。AI 集成将已完成的生成评论直接发布为普通线程，不显示批准提示；本地草稿操作不要求额外批准步骤。

### 订阅

`subscribeThread(id, listener)` 观察一条共享语义记录，`subscribeThreads(listener)` 只为语义记录变化报告 `{ ids }`。文档编辑映射附着位置或视图切换投影时，不重写线程，也不通知语义订阅者。

通过精确视图的 API 调用 `subscribeAttachments(listener)`，观察该视图的位置变化。装饰也在同一视图中读取和观察。切换其他视图的投影不会切换此订阅的视图。取消订阅会释放视图观察，不会释放共享对话目标。

`subscribeVisibleThreadIds`、`subscribeDraftThreadIds` 和 `subscribePending` 分别观察对应快照。线程 ID 进入或离开 `ranges()`、某个 ID 保存的范围被另一个替换（例如在其他文字上重试的创建），以及 `issues` 中的孤立范围变化时，`subscribeRanges` 运行。创建或草稿发布在提交时、`mutate` 结束之前触发它；拒绝、删除、`discardOrphan` 和 `replace` 也会触发它。文档映射不会触发它。各方法均返回取消订阅函数。

监听器在操作结果确定之后运行，只有创建或草稿发布触发的 `subscribeRanges` 监听器例外，它在 `mutate` 之前运行。操作随后再次检查：该监听器销毁了编辑器或使线程失效时，不会调用 `mutate`，操作返回 `stale`；`request.range` 在监听器之后读取，所以监听器所做的编辑会让范围跟随文字移动。任何监听器都可以抛出错误或调用任何操作。同步抛出的错误发送到编辑器的 `lifecycleErrorSink`，后续监听器仍会运行，操作仍返回实际保存的结果。通知只表示“需要重新读取”，因为嵌套操作可能已经改变了状态，所以通过 `getThread`、`getSnapshot` 和 `attachment` 读取当前状态。由 Comments 操作唤醒的附着位置监听器或装饰监听器在所有视图刷新之后才运行，所以每个视图向它提供相同的位置。通知期间添加的监听器从下一次通知开始运行，通知期间移除的监听器会被跳过。

### `CommentComposer`

`onSubmit(body)` 返回 `Promise<CommentMutationResult<string | undefined>>`。返回等待后的持久化操作结果；输入框只在 `status: 'applied'` 时清空，在保存期间保留富文本并阻止重复提交，失败时保留草稿并显示重试提示。
