The demo starts in Suggestion mode with a proposed insertion and deletion. Open a paragraph's discussion button to accept or reject its card, then try undo and redo. Switch to Editing to keep the pending changes visible while ordinary edits apply directly, or type in Suggestion mode to propose an edit.

Typing inside struck text splits the pending deletion around the new text. In Suggestion mode the new text is a proposed insertion of its own; in Editing mode it applies directly. Deleting struck text in Editing mode leaves it to its pending deletion.

<PackageInfo>

## Features

- Switch a mounted editor view between editing and suggesting
- Decorate proposed text, formatting, and structural edits
- Keep the active card local to each mounted view
- Read native authored changes and review cards for custom review UI
- Save pending changes with the complete document
- Add review cards and comment replies through copied registry UI

</PackageInfo>

## Kit Usage

<Steps>

### Installation

Start with an [Editor](/docs/editor), then install the suggestion and discussion UI:

```bash
npx shadcn@latest add https://platejs.org/r/basic-blocks.json https://platejs.org/r/suggestion.json https://platejs.org/r/discussion.json https://platejs.org/r/suggestion-toolbar-button.json https://platejs.org/r/history-toolbar-button.json
```

<ComponentSource name="suggestion" />

`SuggestionKit` configures the package `SuggestionPlugin` with `render.contentAttributes` for its default styles. The package supplies suggestion modes, semantic attributes, active-card behavior, and authored-change hooks. Core applies the kit's classes to the existing content root, including when you render `EditorContent` directly. `DiscussionKit` adds block buttons, Accept and Reject cards, and comment replies.

### Add the kits

```tsx title="components/editor/suggestion-editor.tsx" showLineNumbers
'use client';

import { CommentsPlugin } from 'platejs/comments/react';
import { EditorRoot, useCreateEditor } from 'platejs/react';

import { BasicBlocksKit } from '@/components/editor/basic-blocks';
import { DiscussionKit } from '@/components/editor/discussion';
import { Editor, EditorContainer } from '@/components/editor/editor';
import {
  RedoToolbarButton,
  UndoToolbarButton,
} from '@/components/editor/history-toolbar-button';
import { SuggestionKit } from '@/components/editor/suggestion';
import { SuggestionToolbarButton } from '@/components/editor/suggestion-toolbar-button';
import { Toolbar } from '@/components/editor/toolbar';

export function SuggestionEditor() {
  const editor = useCreateEditor({
    plugins: [
      ...BasicBlocksKit,
      ...SuggestionKit,
      ...DiscussionKit,
      CommentsPlugin.configure({
        initialState: {
          users: { alice: { id: 'alice', name: 'Alice' } },
        },
      }),
    ],
    initialValue: [
      { type: 'paragraph', children: [{ text: 'Edit this sentence.' }] },
    ],
    userId: 'alice',
  });

  return (
    <EditorRoot editor={editor} authored={{ intent: 'propose' }}>
      <EditorContainer>
        <Toolbar>
          <UndoToolbarButton />
          <RedoToolbarButton />
          <SuggestionToolbarButton />
        </Toolbar>
        <Editor />
      </EditorContainer>
    </EditorRoot>
  );
}
```

Replace `'alice'` with the authenticated user's ID. The editor's `userId` attributes document changes and comments, and `users` supplies names and optional avatars. A solo editor can omit `userId`; it then suggests and comments as the local user, `'local'`.

`SuggestionPlugin` depends on `AuthoredPlugin`, which reads the editor's `userId` once per write transaction. Do not install a second authored descriptor alongside the kit.

</Steps>

## Set the mode

Set the starting view with `EditorRoot authored={{ intent: 'propose' }}` as in the example above. Changing the value updates that view. Rerendering with an equivalent value preserves mode changes made by its controls.

For an interactive mode control, call the `SuggestionPlugin` portal from the mounted editor view:

```tsx
import { SuggestionPlugin, useSuggestionMode } from 'platejs/suggestion/react';
import { useEditor } from 'platejs/react';

export function SuggestionModeButton() {
  const editor = useEditor();
  const mode = useSuggestionMode();
  const suggestion = editor.plugin(SuggestionPlugin);

  return (
    <button
      onClick={() =>
        suggestion.api.setMode(
          mode === 'suggesting' ? 'editing' : 'suggesting'
        )
      }
    >
      {mode === 'suggesting' ? 'Stop suggesting' : 'Suggest edits'}
    </button>
  );
}
```

`setMode` sets the view's input intent: `'suggesting'` sets `{ intent: 'propose' }` and `'editing'` sets `{ intent: 'edit' }`. Both show the pending insertions and deletions. In Editing mode, ordinary edits apply directly; in Suggestion mode, they become proposals by the current author.

Mode belongs to the exact mounted view. Two views over one document can use different modes without changing each other.

Changing the mode affects only subsequent input. It does not accept, reject, delete, or hide pending changes, and it does not add an undo step.

To read the document with every pending change accepted or rejected, switch the view to a preview:

```tsx
import { AuthoredPlugin } from 'platejs/authored';

const authored = editor.plugin(AuthoredPlugin);

authored.api.setView({ preview: 'proposed' });
```

A preview takes no writes, and `read.mode()` reports it as `'editing'`. Switching to a preview does not accept or reject changes. Coordinates can differ between views, so read selections and apply edits through the view that produced them. Call `setMode` to leave the preview.

## Read view state

The React entrypoint exposes focused hooks for custom controls and review UI:

```tsx
import {
  useActiveSuggestion,
  useSuggestionChanges,
  useSuggestionGroups,
  useSuggestionMode,
} from 'platejs/suggestion/react';

const mode = useSuggestionMode();
const changes = useSuggestionChanges(path);
const cards = useSuggestionGroups(blockKey);
const { activeId, setActiveId } = useActiveSuggestion();
```

`useSuggestionChanges(path)` returns the native `AuthoredChange` records touching that block. It keeps its result stable while those records are unchanged.

`useSuggestionGroups(blockKey)` returns the review cards touching the top-level block with that key, as `read.groups` summaries. It rereads when the block redraws and when a change in the block moves to another card. An edit to the same card in another block does neither, so a summary's `changeCount` or `revision` can trail; read `editor.plugin(AuthoredPlugin).read.groupOf(card.id)` when a control needs the current one. Read a card's changes a page at a time with `read.changes({ group: card.id })`.

In the current view, clicking a marked element activates the first card its `data-editor-authored-groups` attribute names. Clicking unmarked editor content clears it. Unmounting the view, switching it to another intent or preview, or deciding the card also clears stale active state. Use `setActiveId` when a custom card or control needs to activate a card directly.

The first proposal makes a sentence bold; the second inserts a paragraph. Open each block's discussion button to accept or reject it. Select text and use **Bold**, or press Enter to propose another paragraph.

A `propose` view refuses a write it cannot record as a proposal and rolls it back; see [Authored Changes](/docs/authored-changes#configure-a-view).

### Accepted, proposed, and markup

Switch views to compare accepted content, the proposed result, and the markup view that shows pending insertions and deletions. The proposals stay pending in all three views.

<ComponentPreview name="suggestion-view-demo" height="400px" />

The Accepted and Proposed controls set a `preview` view; Markup sets `{ intent: 'edit' }`. This example sets `readOnly` on both `EditorRoot` and `Editor`, so no view takes document input. The application still owns authorization for review actions and remote writes.

### Save proposals and replies

Open a change's discussion button and add a reply, then save a snapshot. Accept or reject that change, or type another proposal, and reload the snapshot.

<ComponentPreview name="suggestion-persistence-demo" height="440px" />

The snapshot stays in memory and disappears when the page reloads. **Reload snapshot** creates a fresh editor from the saved document and `CommentsJSON`, discarding unsaved work and starting an empty local undo stack. Pending changes belong to the document; conversations persist separately from document undo.

## Create and decide changes

Suggesting mode turns ordinary input and editor commands into native proposals. A headless or explicit transaction can begin a proposal with `tx.authored.propose()`:

```tsx
let changeId = '';

editor.update((tx) => {
  changeId = tx.authored.propose();
  tx.text.insert(' proposed', {
    at: { offset: 4, path: [0, 0] },
  });
});
```

Pass `{ changeId }` to add the transaction's writes to the pending change with that ID. Use separate proposing transactions when reviewers need to decide the edits independently.

Authored owns review decisions and their structured results. Read the change, then decide the record you read:

```tsx
import { AuthoredPlugin } from 'platejs/authored';

const authored = editor.plugin(AuthoredPlugin);
const change = authored.read.change(changeId);

if (change) {
  const result = authored.update.decide({
    action: 'accept',
    changes: [change],
  });
}
```

Use `action: 'reject'` to reject the change. Inspect `result.status`: another edit can make the change `stale`, and a decision that needs other changes decided with it returns `blocked`. To decide a whole card, pass `{ action, groups: [card] }`. [Authored Changes](/docs/authored-changes#review-changes) covers paging, cards, previews, and result handling.

## Save and reload

Save the complete value returned by `editor.read.value()`. Pending review marks live in each node's `authored` property and review records in the document's `records`; leave both to the editor.

```tsx
const savedDocument = editor.read.value();
const savedComments = editor.plugin(CommentsPlugin).api.toJSON();
```

Persist the document and `CommentsJSON` atomically for the same application revision and conversation generation. Verify that association before loading, and use the same content plugins. Saving only `children` discards the review records.

Create a fresh editor with the saved document as `initialValue` and `CommentsPlugin.configure({ initialState: { initialComments: savedComments } })`. Local undo starts empty. The document preserves each change's author and ID, so replies can locate the same suggestions. Set `userId` to the current author; loading another author's suggestions does not require changing it or replaying their edits. For historical previews and restores, [join current conversations with the selected revision's targets](/docs/comment#document-history-and-versions).

Choose an explicit [export projection](/docs/authored-changes#export-explicit-projections).
HTML and Markdown carry visible `accepted` or `proposed` content only. Save
authored JSON when Plate must recover the review, or use DOCX `review` export
for Word revisions.

## Headless usage

Use `BaseSuggestionPlugin` for suggestion modes and semantic decorations without React, Comments, or copied UI:

```tsx title="suggestion-editor.ts" showLineNumbers
import { BaseParagraphPlugin, createEditor } from 'platejs';
import { BaseSuggestionPlugin } from 'platejs/suggestion';

const editor = createEditor({
  plugins: [BaseParagraphPlugin, BaseSuggestionPlugin],
  initialValue: [
    { type: 'paragraph', children: [{ text: 'Edit this sentence.' }] },
  ],
  userId: 'alice',
});

editor.plugin(BaseSuggestionPlugin).api.setMode('suggesting');
```

Marked text and elements expose `data-editor-authored-change`, `data-editor-authored-kind`, `data-editor-authored-author`, `data-editor-authored-groups`, and `data-editor-authored-color`. Each holds a space-separated list, except `color`, which holds the palette slot, 0 to 6, of the card the element paints. A pending deletion has `delete` in its `kind`. Add application styles against these attributes through the plugin's `render.contentAttributes`. Static presets can configure `BaseSuggestionPlugin` with a server-safe attribute object; `SuggestionKit` supplies the live default styles.

## Discussion review

Add [DiscussionKit](/docs/discussion) for Accept and Reject cards and replies attached to a change. It composes optional Comments data with native authored changes; review presentation remains copied application code.

To attach a conversation programmatically, target the authored change ID:

```tsx
import { CommentsPlugin } from 'platejs/comments/react';

const comments = editor.plugin(CommentsPlugin).api;
const result = await comments.createThread({
  body: [
    { type: 'paragraph', children: [{ text: 'Can we explain this edit?' }] },
  ],
  target: { type: 'change', id: changeId },
});

if (result.status === 'applied') {
  comments.setActive([result.value]);
}
```

Preserve input for non-applied results and thrown errors. Comments authorizes durable writes through `initialState.mutate` and publishes only the canonical committed record. Accepting or rejecting a change is a document action that can be undone; it hides the review card without deleting or resolving its discussion. Undo restores the pending change with its messages and resolution intact. Resolving or reopening the thread stays outside document undo.

## API Reference

### `BaseSuggestionPlugin`

Import from `platejs/suggestion`. It supplies the two suggestion modes and CSS-free semantic decorations, and depends on `AuthoredPlugin` for change records and identity.

### `SuggestionPlugin`

Import from `platejs/suggestion/react`. It extends `BaseSuggestionPlugin` with exact-view active state and click activation.

### `suggestion.api.setMode(mode)`

Set whether subsequent input proposes or directly edits through `editor.plugin(SuggestionPlugin)` or `editor.plugin(BaseSuggestionPlugin)`. It sets the view's intent, `'propose'` or `'edit'`; both show pending insertions and deletions.

### `suggestion.read.mode()`

Read `'suggesting'` for a `propose` view, and `'editing'` for an `edit` view or a preview.

### React hooks

| Hook | Result |
| --- | --- |
| `useSuggestionMode()` | The exact mounted view's `'suggesting' \| 'editing'` mode. |
| `useSuggestionChanges(path)` | Native `AuthoredChange` records touching the block at `path`. |
| `useSuggestionGroups(blockKey)` | Summaries of the review cards touching the top-level block with that key. |
| `useActiveSuggestion()` | The view-local active card's `activeId` and the `setActiveId` function. |

### `SuggestionKit`

The copied registry kit configures `SuggestionPlugin` with content-root styles. Generic editor components remain independent of suggestions. Review cards, Comments integration, toolbars, and popovers remain in registry code.
