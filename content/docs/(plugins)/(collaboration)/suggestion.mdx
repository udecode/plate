Suggestions record proposed document edits. They remain document data because accepting or rejecting one mutates editor content; [Comments](/docs/comment) stay outside the document, and [Discussion](/docs/discussion) presents both in one review view.

<PackageInfo>

## Features

- **Text Suggestions:** Add suggestions as text marks with inline annotations
- **Block Suggestions:** Create suggestions for entire blocks of content
- **State Tracking:** Track suggestion state and user interactions
- **Undo/Redo Support:** Full undo/redo support for suggestion changes
- **Combined Review:** Accept, reject, and discuss suggestions in the copied Discussion UI

</PackageInfo>

## Kit usage

<Steps>

### Installation

The fastest way to add suggestion functionality is with the `SuggestionKit`, which includes pre-configured `SuggestionPlugin` and related components along with their [Plate UI](/docs/installation/plate-ui) components.

<ComponentSource name="suggestion" />

- [`SuggestionLeaf`](/docs/components/suggestion): Renders suggestion text marks
- `VoidRemoveSuggestionOverlay`: Renders removed block suggestions
- [`SuggestionLineBreak`](/docs/components/suggestion): Handles line breaks in suggestions

### Add kit

```tsx
import { createEditor } from 'platejs/react';
import { SuggestionKit } from '@/components/editor/suggestion';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    ...SuggestionKit,
  ],
});
```

</Steps>

## Manual usage

<Steps>

### Installation

```bash
npm install platejs @tanstack/react-virtual
```

### Extend suggestion plugin

Create the suggestion plugin with extended configuration for state management:

```tsx
import { SuggestionPlugin } from 'platejs/suggestion/react';
import {
  SuggestionLeaf,
  SuggestionLineBreak,
  VoidRemoveSuggestionOverlay,
} from '@/components/editor/suggestion';

export const suggestionPlugin = SuggestionPlugin.configure({
  component: SuggestionLeaf,
  initialState: {
    currentUserId: 'alice',
  },
  slots: {
    afterNodeChildren: VoidRemoveSuggestionOverlay,
    wrapNodeChildren: SuggestionLineBreak,
  },
});
```

- `SuggestionPlugin` owns the active and hovered suggestion state used by renderers
- `initialState.currentUserId`: ID of the current user creating suggestions
- `.configure({ component: SuggestionLeaf })`: Renders suggestion text marks with
  [`SuggestionLeaf`](/docs/components/suggestion)
- `slots.afterNodeChildren`: Renders the remove overlay for block suggestions
- `slots.wrapNodeChildren`: Renders suggested line breaks

### Add plugins

```tsx
import { createEditor } from 'platejs/react';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    suggestionPlugin,
  ],
});
```

### Enable suggestion mode

Use the plugin's API to control suggestion mode:

```tsx
import { useEditor, usePluginStore } from 'platejs/react';

function SuggestionToolbar() {
  const editor = useEditor();
  const isSuggesting = usePluginStore(suggestionPlugin, 'isSuggesting');

  const toggleSuggesting = () => {
    editor
      .plugin(suggestionPlugin)
      .store.set({ isSuggesting: !isSuggesting });
  };

  return (
    <button onClick={toggleSuggesting}>
      {isSuggesting ? 'Stop Suggesting' : 'Start Suggesting'}
    </button>
  );
}
```

### Add toolbar button

You can add [`SuggestionToolbarButton`](/docs/components/suggestion-toolbar-button) to your [Toolbar](/docs/toolbar) to toggle suggestion mode in the editor.

</Steps>

## Discussion review

The copied Discussion UI reads suggestions from the editor and renders one card per current suggestion. Each card shows the author, timestamp, proposed add/delete/replace/update operation, Accept and Reject actions, and application-owned comment threads attached to that suggestion.

Install the combined view from the [Discussion guide](/docs/discussion). `editor.update.suggestion.accept` and `editor.update.suggestion.reject` remain the only document mutation owners; the Discussion UI only calls those updates and renders their current state.

## Plugins

### `SuggestionPlugin`

Plugin for creating and managing text and block suggestions with state tracking.

## Plugin API

Suggestion queries and value helpers live on the installed plugin. This keeps
the editor type, plugin state, and schema in the inference path.

```tsx
const { api, read } = editor.plugin(BaseSuggestionPlugin);
const suggestions = read.nodes();
const reviews = read.reviews();
```

| Method | Description |
| --- | --- |
| `read.reviews()` | Returns current groups with IDs, operation kinds, ranges, and typed changes. |
| `api.createFragment(fragment, identity)` | Adds explicit insertion suggestion identity to a fragment. |
| `api.createIdentity(options?)` | Creates a suggestion ID and timestamp. |
| `api.dataList(node)` | Returns every inline suggestion record on a text node. |
| `read.findIdentity(options)` | Finds an existing suggestion identity. |
| `api.getProps(node, options?)` | Builds suggestion properties for a node. |
| `api.inlineData(node)` | Returns the active inline suggestion record. |
| `api.isBlockSuggestion(node)` | Narrows a node to a block suggestion. |
| `api.isCurrentUser(node)` | Checks suggestion ownership against `currentUserId`. |
| `api.isTracking(tags)` | Checks whether suggestion middleware tracks an update. |
| `api.key(id?)` / `api.keyId(node)` / `api.keys(node)` | Reads and builds inline suggestion keys. |
| `read.node(options?)` / `read.nodes(options?)` | Finds one or all suggestion entries. |
| `read.nodeEntries(id, options?)` | Finds inline entries for a suggestion ID. |
| `api.id(node)` | Returns a node's suggestion ID. |
| `api.skipDeletes(node)` | Returns text without removed suggestions. |
| `api.suggestionData(node)` | Returns direct suggestion data, with text-child inheritance for inline elements. |
| `api.untracked(fn)` | Runs synchronous work without recursively creating suggestions. |
| `api.userId(node)` / `api.userIds(node)` | Returns suggestion author IDs. |

## Review data

`read.reviews()` returns `SuggestionReview` records with `id`, `createdAt` (a
numeric timestamp), `userId`, `type`, `range`, and `changes`. Each change contains
its current `node`, `path`, and serialized suggestion `data`. Operation kinds
include `insert`, `remove`, `replace`, and `update`, including empty suggestions.

React views can read the same groups with `useSuggestionReviews` from
`platejs/suggestion/react`. The hook refreshes relevant document changes and
shares the feature's snapshot between readers. Format labels and dates in the
view. The copied kit keeps its active card ID in its own plugin state.

## Updates

Accept and reject take a suggestion ID and resolve its current document data:

```tsx
editor.update.suggestion.accept(id);
editor.update.suggestion.reject(id);
```

| Update | Description |
| --- | --- |
| `editor.update.suggestion.accept(id)` | Applies the proposed change. |
| `editor.update.suggestion.reject(id)` | Discards the proposed change. |
| `editor.update.suggestion.addMark(key, value)` | Adds a mark as a suggestion. |
| `editor.update.suggestion.removeMark(key, previousValue?)` | Removes a mark as a suggestion. |
| `editor.update.suggestion.delete(at, options?)` | Records a range deletion. |
| `editor.update.suggestion.deleteFragment(options?)` | Records deletion of the active selection. |
| `editor.update.suggestion.insertFragment(fragment, insertContent?)` | Inserts a suggested fragment. |
| `editor.update.suggestion.insertText(text)` | Inserts suggested text. |
| `editor.update.suggestion.removeNodes(nodes)` | Records node removals. |
| `editor.update.suggestion.setNodes(options?)` | Records node property updates. |

## Update policies

### `SuggestionUpdatePolicy.skip`

Runs an update without creating suggestion marks. Use the package-owned preset
for direct or atomic updates.

```tsx
import { SuggestionUpdatePolicy } from 'platejs/suggestion';

editor.update(SuggestionUpdatePolicy.skip, (tx) => {
  tx.text.insert('Accepted text');
});
```

<APIAttributes>
