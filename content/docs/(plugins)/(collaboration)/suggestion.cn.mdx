示例默认使用建议模式，并包含一条插入建议和一条删除建议。打开段落旁的讨论按钮来接受或拒绝其卡片，或在模式菜单中选择 **Accept all suggestions** 或 **Reject all suggestions**，再尝试撤销和重做。切换到编辑模式后，待处理修改仍然可见，而普通编辑会直接应用；在建议模式下输入可提议修改。

在被划掉的文本中输入或粘贴时，新文本落在待处理删除之后；用输入法确认的词则会把待处理删除拆到它的两侧。建议模式下，新文本是一条独立的插入建议；编辑模式下，它直接应用。在编辑模式下删除被划掉的文本时，这些文本仍归属于其待处理删除。

<PackageInfo>

## 功能

- 在编辑和建议模式之间切换一个已挂载的 editor view
- 装饰拟议的文本、格式和结构修改
- 让每个已挂载 view 独立维护活动卡片
- 为自定义审阅 UI 读取原生 authored change 和审阅卡片
- 将待处理 change 保存在完整文档中
- 通过复制的 registry UI 添加审阅卡片和评论回复

</PackageInfo>

## 套件用法

<Steps>

### 安装

先创建一个[编辑器](/docs/editor)，再安装建议和讨论 UI：

```bash
npx shadcn@latest add https://platejs.org/r/basic-blocks.json https://platejs.org/r/suggestion.json https://platejs.org/r/discussion.json https://platejs.org/r/suggestion-toolbar-button.json https://platejs.org/r/history-toolbar-button.json
```

<ComponentSource name="suggestion" />

`SuggestionKit` 通过 `render.contentAttributes` 配置包中 `SuggestionPlugin` 的默认样式。包负责建议模式、语义属性、活动卡片行为和 authored-change hooks。Core 将 kit 的类名应用到现有内容根节点，直接使用 `EditorContent` 时也适用。`DiscussionKit` 添加区块按钮、接受和拒绝卡片以及评论回复。

### 添加套件

```tsx title="components/editor/suggestion-editor.tsx" showLineNumbers
'use client';

import { CommentsPlugin } from 'platejs/comments/react';
import { EditorRoot, useCreateEditor } from 'platejs/react';

import { BasicBlocksKit } from '@/components/editor/basic-blocks';
import { DiscussionKit } from '@/components/editor/discussion';
import { Editor, EditorContainer } from '@/components/editor/editor';
import {
  RedoToolbarButton,
  UndoToolbarButton,
} from '@/components/editor/history-toolbar-button';
import { SuggestionKit } from '@/components/editor/suggestion';
import { SuggestionToolbarButton } from '@/components/editor/suggestion-toolbar-button';
import { Toolbar } from '@/components/editor/toolbar';

export function SuggestionEditor() {
  const editor = useCreateEditor({
    plugins: [
      ...BasicBlocksKit,
      ...SuggestionKit,
      ...DiscussionKit,
      CommentsPlugin.configure({
        initialState: {
          users: { alice: { id: 'alice', name: 'Alice' } },
        },
      }),
    ],
    initialValue: [
      { type: 'paragraph', children: [{ text: 'Edit this sentence.' }] },
    ],
    userId: 'alice',
  });

  return (
    <EditorRoot editor={editor} authored={{ intent: 'propose' }}>
      <EditorContainer>
        <Toolbar>
          <UndoToolbarButton />
          <RedoToolbarButton />
          <SuggestionToolbarButton />
        </Toolbar>
        <Editor />
      </EditorContainer>
    </EditorRoot>
  );
}
```

将 `'alice'` 替换为已认证用户的 ID。编辑器的 `userId` 记录文档修改和评论的作者；`users` 提供姓名和可选头像。单人编辑器可以省略 `userId`，此时以本地用户 `'local'` 提出建议和评论。

`SuggestionPlugin` 依赖 `AuthoredPlugin`，后者在每个写入 transaction 中读取一次 editor 的 `userId`。不要在套件旁安装第二个 authored 描述符。

</Steps>

## 设置模式

如上例所示，用 `EditorRoot authored={{ intent: 'propose' }}` 设置初始 view。修改该值会更新这个 view。以等价值重新渲染时，会保留其控件做出的模式修改。

交互式模式控件请从已挂载的 editor view 调用 `SuggestionPlugin` portal：

```tsx
import { SuggestionPlugin, useSuggestionMode } from 'platejs/suggestion/react';
import { useEditor } from 'platejs/react';

export function SuggestionModeButton() {
  const editor = useEditor();
  const mode = useSuggestionMode();
  const suggestion = editor.plugin(SuggestionPlugin);

  return (
    <button
      onClick={() =>
        suggestion.api.setMode(
          mode === 'suggesting' ? 'editing' : 'suggesting'
        )
      }
    >
      {mode === 'suggesting' ? '停止建议' : '建议修改'}
    </button>
  );
}
```

`setMode` 设置 view 的输入 intent：`'suggesting'` 设置 `{ intent: 'propose' }`，`'editing'` 设置 `{ intent: 'edit' }`。两者都显示待处理的插入和删除。编辑模式下，普通编辑直接应用；建议模式下，它们成为当前作者的 proposal。

模式属于精确的已挂载 view。同一个文档的两个 view 可以使用不同模式，互不影响。

改变模式只影响后续输入。它不会接受、拒绝、删除或隐藏待处理 change，也不会新增撤销步骤。

要以所有待处理 change 都已接受或已拒绝的状态阅读文档，请把 view 切换为 preview：

```tsx
import { AuthoredPlugin } from 'platejs/authored';

const authored = editor.plugin(AuthoredPlugin);

authored.api.setView({ preview: 'proposed' });
```

Preview 遇到普通编辑会抛出错误，但部分其他写入仍会修改文档，例如带决定的 update、撤销和重做，以及远程协作变更；`read.mode()` 把它报告为 `'editing'`。切换到 preview 不会接受或拒绝 change。不同 view 的坐标可能不同，因此请通过产生 selection 的 view 读取 selection 并应用编辑。调用 `setMode` 可离开 preview。

在 preview 下，每个区块读取它所显示的存储内容上的卡片和 change，包括 preview 隐藏在其中的内容，以及 preview 去掉的外层元素上的卡片和 change，例如 preview 应用了待处理解除包裹的 quote。Preview 只按 node 的 key 或 path 读取它们，下面的 hook 就是这样读取的；传入 point 或 range 会抛出 `platejs/authored` 导出的 `AuthoredPlaceError`。被 preview 隐藏的顶层区块，其卡片不会显示在任何区块上；要查看并决定这些卡片，请切换到编辑模式。例外是被合并的行，它会显示其两半之间被隐藏区块的卡片。Preview 为补全文档而添加的顶层区块，例如某个建议删除了唯一区块时 preview 显示的空段落，不显示任何卡片。它在容器内添加的区块，例如某个建议删除了 quote 中唯一的段落时，可能显示它所替代的隐藏段落的卡片。在 preview 下，复制的 discussion 会把建议或 change 讨论的弹出层锚定在最后按下触发按钮的段落上，并且只在该段落显示该讨论时才打开它。

## 读取 view 状态

React 入口提供用于自定义控件和审阅 UI 的 hooks：

```tsx
import {
  useActiveSuggestion,
  useSuggestionChanges,
  useSuggestionGroups,
  useSuggestionMode,
} from 'platejs/suggestion/react';

const mode = useSuggestionMode();
const changes = useSuggestionChanges(path);
const cards = useSuggestionGroups(blockKey);
const { activeId, setActiveId } = useActiveSuggestion();
```

`useSuggestionChanges(path)` 返回已挂载 view 中该 path 处区块的原生 `AuthoredChange` 记录。嵌套区块的 path 返回它自己的 change，以及 preview 去掉的外层容器的 change。它绝不返回 view 仍然显示的外层容器的待处理包裹或解除包裹，那由该容器自己的 path 返回。每个改变文档或其状态的 commit，以及指名该 path 顶层区块的审阅 delta，都会让它重新读取；这些记录未变化时，结果保持稳定。Change 的 `ranges` 在每个 view 上都仍是存储文档中的位置。

`useSuggestionGroups(blockKey)` 以 `read.groups` 摘要的形式，返回该 key 对应区块的审阅卡片。嵌套区块的 key 读取该区块自己的卡片。调用它的组件重新渲染时，以及审阅 delta 指名该区块时，它会重新读取：某个 change 进入或离开了该区块，或它的某个 change 移到了另一张卡片。delta 只指名顶层区块，因此对嵌套区块的 key，它只在该组件重新渲染时重新读取。同一张卡片在其他区块中的编辑两者都不会引发，因此摘要中的 `changeCount` 或 `revision` 可能滞后；控件需要当前摘要时，请读取 `editor.plugin(AuthoredPlugin).read.groupOf(card.id)`。用 `read.changes({ group: card.id })` 逐页读取卡片中的 change。

点击带标记的元素会在当前 view 中激活其 `data-editor-authored-groups` 属性列出的第一张卡片。点击未标记的编辑器内容会清除活动项。卸载 view、把它切换到其他 intent 或 preview，或决定该卡片时，也会清除失效的活动状态。自定义卡片或控件可调用 `setActiveId` 直接激活卡片。

## 示例

### 格式和区块

第一条 proposal 将句子加粗，第二条插入段落。打开每个区块的讨论按钮来接受或拒绝修改。选择文本并使用**加粗**，或按 Enter 提议另一个段落。

<ComponentPreview name="suggestion-format-demo" height="360px" />

为编辑器支持的文本格式添加[基础标记](/docs/basic-marks)。View 处于建议模式时，编辑器命令会将文本、mark 和 node 操作记录为 proposal。`propose` view 会拒绝无法记录为 proposal 的写入并将其回滚，两种模式也都会拒绝某些位于段落旁的编辑，这些段落被待处理的合并显示在其存储位置之外；参阅 [Authored Changes](/cn/docs/authored-changes#配置-view)。在编辑模式下对待处理的格式 suggestion 再设置格式会直接应用，并保留该 suggestion 待处理，因此之后拒绝它仍会保留这次直接编辑。如果协作者在这次编辑同步期间决定或撤回该 suggestion，这次直接编辑可能丢失。

### Accepted、proposed 和 markup

切换 view，比较已接受内容、拟议结果，以及显示待处理插入和删除的 markup view。三个 view 中的 proposal 都保持待处理状态。

<ComponentPreview name="suggestion-view-demo" height="400px" />

Accepted 和 Proposed 控件设置 `preview` view；Markup 设置 `{ intent: 'edit' }`。此示例在 `EditorRoot` 和 `Editor` 上都设置 `readOnly`，因此任何 view 都不接受文档输入。应用仍负责审阅操作和远程写入的授权。

### 保存 proposal 和回复

打开 change 的讨论按钮并添加回复，然后保存 snapshot。接受或拒绝该 change，或输入另一条 proposal，再重新加载 snapshot。

<ComponentPreview name="suggestion-persistence-demo" height="440px" />

Snapshot 仅保存在内存中，页面重新加载后会消失。**Reload snapshot** 会从已保存的文档和 `CommentsJSON` 创建新 editor，丢弃未保存的工作，并从空的本地 undo stack 开始。待处理 change 属于文档；对话独立于文档 undo 保存。

## 创建和决定 change

建议模式会把普通输入和编辑器命令转换为原生 proposal。无 UI 或显式 transaction 可以通过 `tx.authored.propose()` 开始 proposal：

```tsx
let changeId = '';

editor.update((tx) => {
  changeId = tx.authored.propose();
  tx.text.insert(' proposed', {
    at: { offset: 4, path: [0, 0] },
  });
});
```

传入 `{ changeId }` 可把该 transaction 的写入加入具有该 ID 的待处理 change。当审阅者需要独立决定每项编辑时，请使用不同的 proposing transaction。

Authored 管理审阅决定和结构化结果。先读取 change，再决定读到的记录：

```tsx
import { AuthoredPlugin } from 'platejs/authored';

const authored = editor.plugin(AuthoredPlugin);
const change = authored.read.change(changeId);

if (change) {
  const result = authored.update.decide({
    action: 'accept',
    changes: [change],
  });
}
```

使用 `action: 'reject'` 拒绝 change。请检查 `result.status`：其他编辑可能使 change 变为 `stale`；需要同时决定其他 change 的决定返回 `blocked`。要决定整张卡片，请传入 `{ action, groups: [card] }`。[Authored Changes](/cn/docs/authored-changes#审阅-change)介绍分页、卡片、预览和结果处理。

### 决定全部建议

要接受或拒绝全部待处理建议，请读取 change 的每一页，然后在一次调用中决定它们：

```tsx
import { type AuthoredChange, AuthoredPlugin } from 'platejs/authored';

const authored = editor.plugin(AuthoredPlugin);
const changes: AuthoredChange[] = [];

for (let cursor: string | undefined; ; ) {
  const page = authored.read.changes({ cursor, limit: 200 });

  changes.push(...page.items);
  if (!page.cursor) break;
  ({ cursor } = page);
}

const result = authored.update.decide({ action: 'accept', changes });
```

一次调用会同时决定所有 change，因此不会返回 `blocked`。应用成功时，它得到的文档与按任意顺序逐个决定这些 change 相同，其中每个返回 `blocked` 的步骤都会加入其 `with` 列出的 change。一次撤销会恢复它决定的每个 change。请在同一个事件处理函数中读取并决定，因为两者之间的编辑可能使 change 变为 `stale`。当 schema 拒绝决定后的文档时，结果为 `invalid`，且不会有任何修改。复制的 `ModeToolbarButton` 在其菜单中以 **Accept all suggestions** 和 **Reject all suggestions** 提供此操作。

## 保存和重新加载

保存 `editor.read.value()` 返回的完整值。待处理审阅 mark 位于每个 node 的 `authored` 属性中，审阅记录位于文档的 `records` 中；两者都交由编辑器管理。

```tsx
const savedDocument = editor.read.value();
const savedComments = editor.plugin(CommentsPlugin).api.toJSON();
```

按同一个应用版本和对话代次原子保存文档与 `CommentsJSON`。加载前验证关联，并使用相同的内容插件。只保存 `children` 会丢失审阅记录。

创建新 editor，将文档传给 `initialValue`，并配置 `CommentsPlugin.configure({ initialState: { initialComments: savedComments } })`。本地 undo stack 从空开始。文档保留每个 change 的作者和 ID，使回复仍可定位同一建议。将 `userId` 设置为当前作者；加载其他作者的建议不需要切换身份或重放编辑。历史预览和恢复请参阅[当前对话与历史目标的关联](/cn/docs/comment#历史版本)。

选择显式的[导出投影](/cn/docs/authored-changes#导出显式投影)。HTML 与 Markdown 只携带可见的 `accepted` 或 `proposed` content。Plate 需要恢复审阅时保存 authored JSON；需要 Word revision 时使用 DOCX `review` export。

## Headless 用法

使用 `BaseSuggestionPlugin` 可在不安装 React、Comments 或复制 UI 的情况下获得建议模式和语义 decoration：

```tsx title="suggestion-editor.ts" showLineNumbers
import { BaseParagraphPlugin, createEditor } from 'platejs';
import { BaseSuggestionPlugin } from 'platejs/suggestion';

const editor = createEditor({
  plugins: [BaseParagraphPlugin, BaseSuggestionPlugin],
  initialValue: [
    { type: 'paragraph', children: [{ text: 'Edit this sentence.' }] },
  ],
  userId: 'alice',
});

editor.plugin(BaseSuggestionPlugin).api.setMode('suggesting');
```

带标记的文本和元素提供 `data-editor-authored-change`、`data-editor-authored-kind`、`data-editor-authored-author`、`data-editor-authored-groups` 和 `data-editor-authored-color`。除 `color` 外，每个属性都是以空格分隔的列表；`color` 是该元素所绘制卡片的调色板槽位，取值 0 到 6。待处理删除的 `kind` 包含 `delete`。通过 plugin 的 `render.contentAttributes` 为这些属性配置样式。静态 preset 可以为 `BaseSuggestionPlugin` 配置服务端安全的属性对象；`SuggestionKit` 提供交互编辑器的默认样式。

## Discussion 审阅

添加 [DiscussionKit](/docs/discussion) 可获得接受和拒绝卡片，以及附加到 change 的回复。它将可选 Comments 数据与原生 authored change 组合；审阅展示仍是复制的应用代码。

以 authored change ID 为 target，即可通过编程方式附加对话：

```tsx
import { CommentsPlugin } from 'platejs/comments/react';

const comments = editor.plugin(CommentsPlugin).api;
const result = await comments.createThread({
  body: [
    { type: 'paragraph', children: [{ text: 'Can we explain this edit?' }] },
  ],
  target: { type: 'change', id: changeId },
});

if (result.status === 'applied') {
  comments.setActive([result.value]);
}
```

结果不是 `applied` 或抛出异常时保留输入。Comments 通过 `initialState.mutate` 授权持久化写入，只发布已提交的规范记录。接受或拒绝 change 是可撤销的文档操作；它隐藏审阅卡片，但不删除或解决讨论。Undo 恢复待处理 change，并保留消息与解决状态。解决或重新打开 thread 不进入文档 undo。

## API 参考

### `BaseSuggestionPlugin`

从 `platejs/suggestion` 导入。它提供两个建议模式和无 CSS 的语义 decoration，并依赖 `AuthoredPlugin` 管理 change record 和身份。

### `SuggestionPlugin`

从 `platejs/suggestion/react` 导入。它在 `BaseSuggestionPlugin` 上添加精确 view 的活动状态和点击激活。

### `suggestion.api.setMode(mode)`

通过 `editor.plugin(SuggestionPlugin)` 或 `editor.plugin(BaseSuggestionPlugin)` 设置后续输入是 proposal 还是直接编辑。它设置 view 的 intent，即 `'propose'` 或 `'edit'`；两者都显示待处理的插入和删除。

### `suggestion.read.mode()`

`propose` view 读取为 `'suggesting'`，`edit` view 或 preview 读取为 `'editing'`。

### React hooks

| Hook | 结果 |
| --- | --- |
| `useSuggestionMode()` | 精确挂载 view 的 `'suggesting' \| 'editing'` 模式。 |
| `useSuggestionChanges(path)` | `path` 处区块的原生 `AuthoredChange` 记录。 |
| `useSuggestionGroups(blockKey)` | 该 key 对应区块的审阅卡片摘要。 |
| `useActiveSuggestion()` | View 局部活动卡片的 `activeId` 和 `setActiveId` 函数。 |

### `SuggestionKit`

复制的 registry kit 为 `SuggestionPlugin` 配置内容根节点样式。通用 editor 组件与建议功能保持独立。审阅卡片、Comments 集成、工具栏和 popover 保留在 registry 代码中。
