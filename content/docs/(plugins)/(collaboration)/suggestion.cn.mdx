示例默认使用建议模式，并包含一条插入建议和一条删除建议。打开段落旁的讨论按钮来接受或拒绝修改，再尝试撤销和重做。切换到编辑模式后，待处理修改仍然可见，而普通编辑会直接发布；在建议模式下输入可提议修改。

<PackageInfo>

## 功能

- 在编辑和建议模式之间切换一个已挂载的 editor view
- 装饰拟议的文本、格式、结构修改和保留内容
- 让每个已挂载 view 独立维护活动建议
- 为自定义审阅 UI 读取稳定的原生 authored change
- 将待处理 change 和决定保存在完整文档中
- 通过复制的 registry UI 添加审阅卡片和评论回复

</PackageInfo>

## 套件用法

<Steps>

### 安装

先创建一个[编辑器](/docs/editor)，再安装建议和讨论 UI：

```bash
npx shadcn@latest add https://platejs.org/r/basic-blocks.json https://platejs.org/r/suggestion.json https://platejs.org/r/discussion.json https://platejs.org/r/suggestion-toolbar-button.json https://platejs.org/r/history-toolbar-button.json
```

<ComponentSource name="suggestion" />

`SuggestionKit` 通过 `render.contentAttributes` 配置包中 `SuggestionPlugin` 的默认样式。包负责建议模式、语义属性、活动 change 行为和 authored-change hooks。Core 将 kit 的类名应用到现有内容根节点，直接使用 `EditorContent` 时也适用。`DiscussionKit` 添加区块按钮、接受和拒绝卡片以及评论回复。

### 添加套件

```tsx title="components/editor/suggestion-editor.tsx" showLineNumbers
'use client';

import { CommentsPlugin } from 'platejs/comments/react';
import { EditorRoot, useCreateEditor } from 'platejs/react';

import { BasicBlocksKit } from '@/components/editor/basic-blocks';
import { DiscussionKit } from '@/components/editor/discussion';
import { Editor, EditorContainer } from '@/components/editor/editor';
import {
  RedoToolbarButton,
  UndoToolbarButton,
} from '@/components/editor/history-toolbar-button';
import { SuggestionKit } from '@/components/editor/suggestion';
import { SuggestionToolbarButton } from '@/components/editor/suggestion-toolbar-button';
import { Toolbar } from '@/components/editor/toolbar';

export function SuggestionEditor() {
  const editor = useCreateEditor({
    plugins: [
      ...BasicBlocksKit,
      ...SuggestionKit,
      ...DiscussionKit,
      CommentsPlugin.configure({
        initialState: {
          currentUserId: 'alice',
          users: { alice: { id: 'alice', name: 'Alice' } },
        },
      }),
    ],
    initialValue: [
      { type: 'paragraph', children: [{ text: 'Edit this sentence.' }] },
    ],
    userId: 'alice',
  });

  return (
    <EditorRoot
      editor={editor}
      authored={{ intent: 'propose', projection: 'markup' }}
    >
      <EditorContainer>
        <Toolbar>
          <UndoToolbarButton />
          <RedoToolbarButton />
          <SuggestionToolbarButton />
        </Toolbar>
        <Editor />
      </EditorContainer>
    </EditorRoot>
  );
}
```

将 `userId` 和 Comments 的 `currentUserId` 中的 `'alice'` 替换为已认证用户的 ID。`userId` 记录文档修改的作者；`currentUserId` 标识回复作者；`users` 提供姓名和可选头像。

`SuggestionPlugin` 依赖 `DefaultAuthoredPlugin`，后者在每个 transaction 中读取一次 editor 的 `userId`。缺少身份时，受追踪的文档写入会被拒绝。不要在套件旁安装另一个 `authored(...)` 描述符。

</Steps>

## 设置模式

从已挂载的 editor view 调用 `SuggestionPlugin` portal：

```tsx
import { SuggestionPlugin, useSuggestionMode } from 'platejs/suggestion/react';
import { useEditor } from 'platejs/react';

export function SuggestionModeButton() {
  const editor = useEditor();
  const mode = useSuggestionMode();
  const suggestion = editor.plugin(SuggestionPlugin);

  return (
    <button
      onClick={() =>
        suggestion.api.setMode(
          mode === 'suggesting' ? 'editing' : 'suggesting'
        )
      }
    >
      {mode === 'suggesting' ? '停止建议' : '建议修改'}
    </button>
  );
}
```

切换模式会更新输入 intent，并保留当前 projection：

| 模式 | Intent | Projection |
| --- | --- | --- |
| `'suggesting'` | `'propose'` | 保留 `markup` 或 `proposed`。`accepted` view 会切换到 `markup`，以便显示新 proposal。 |
| `'editing'` | `'edit'` | 保留 `accepted`、`proposed` 或 `markup`。 |

编辑模式下的 markup view 会显示待处理 change，同时把对 accepted content 的普通编辑直接发布。完整包含待处理 change 的 replacement 会在同一个可撤销事务中解决这些 change，并直接发布 replacement。其他依赖待处理 content 的编辑仍可审阅，并归属于当前作者。只有需要隐藏待处理 content 时才使用 accepted projection。

模式属于精确的已挂载 view。同一个文档的两个 view 可以使用不同模式，互不影响。

改变模式只影响后续输入。它不会接受、拒绝、删除或隐藏待处理 change，也不会新增撤销步骤。编辑模式会直接修改 accepted 内容。跨 pending content 的 replacement 只有在 selection 完整包含所有相关 change 和依赖时才直接应用。部分命中的 retained change 或依赖跨出 selection 时保持受保护。需要主动创建或修订 proposal 时，请切换到建议模式。

如需只显示已接受内容，请直接为 authored view 设置 `{ intent: 'edit', projection: 'accepted' }`。

如需显示不含保留审阅片段的 proposed 内容，请直接设置高级 authored view：

```tsx
import { DefaultAuthoredPlugin } from 'platejs/authored';

const authored = editor.plugin(DefaultAuthoredPlugin);

authored.api.setView({
  intent: 'propose',
  projection: 'proposed',
});
```

改变 projection 不会接受或拒绝 change。不同 projection 的坐标可能不同，因此请通过产生 selection 的 view 读取 selection 并应用编辑。

## 读取 view 状态

React 入口提供用于自定义控件和审阅 UI 的 hooks：

```tsx
import {
  useActiveSuggestion,
  useSuggestionChanges,
  useSuggestionMode,
} from 'platejs/suggestion/react';

const mode = useSuggestionMode();
const changes = useSuggestionChanges(path);
const { activeId, setActiveId } = useActiveSuggestion();
```

`useSuggestionChanges(path)` 返回接触该区块的原生 `AuthoredChange` 记录。文档、authored state 或 projection 变化时它会更新；可见记录未变化时，结果保持稳定。

点击带有 `data-editor-authored-change` 的元素会激活当前 view 中的 change。点击未标记的编辑器内容会清除活动项。卸载 view、改变 projection 或决定 change 时，也会清除失效的活动状态。自定义卡片或控件可调用 `setActiveId` 直接激活 change。

## 示例

### 格式和区块

第一条 proposal 将句子加粗，第二条插入段落。打开每个区块的讨论按钮来接受或拒绝修改。选择文本并使用**加粗**，或按 Enter 提议另一个段落。

<ComponentPreview name="suggestion-format-demo" height="360px" />

为编辑器支持的文本格式添加[基础标记](/docs/basic-marks)。View 处于建议模式时，普通编辑器命令会将文本、mark 和 node 操作记录为 proposal。

### Accepted、proposed 和 markup

切换 projection，比较已接受内容、拟议结果和保留的审阅片段。三个 view 中的 proposal 都保持待处理状态。

<ComponentPreview name="suggestion-view-demo" height="400px" />

此示例在 `EditorRoot` 和 `Editor` 上都设置 `readOnly`。Projection 控件选择可见内容；read-only 阻止文档输入。应用仍负责审阅操作和远程写入的授权。

### 保存 proposal 和回复

打开 change 的讨论按钮并添加回复，然后保存 snapshot。接受或拒绝该 change，或输入另一条 proposal，再重新加载 snapshot。

<ComponentPreview name="suggestion-persistence-demo" height="440px" />

Snapshot 仅保存在内存中，页面重新加载后会消失。**Reload snapshot** 会从已保存的文档和 `CommentsJSON` 创建新 editor，丢弃未保存的工作，并从空的本地 undo stack 开始。待处理 change 和决定属于文档；对话独立于文档 undo 保存。

## 创建和决定 change

建议模式会把普通输入和编辑器命令转换为原生 proposal。无 UI 或显式 transaction 可以通过 `tx.authored.propose()` 开始 proposal：

```tsx
let changeId = '';

editor.update((tx) => {
  changeId = tx.authored.propose();
  tx.text.insert(' proposed', {
    at: { offset: 4, path: [0, 0] },
  });
});
```

传入 `{ changeId }` 可以修订当前作者拥有的待处理贡献。当审阅者需要独立决定每项编辑时，请使用不同的 proposing transaction。

Authored 管理审阅决定和结构化结果：

```tsx
import { DefaultAuthoredPlugin } from 'platejs/authored';

const authored = editor.plugin(DefaultAuthoredPlugin);
const selection = authored.read.select({ ids: [changeId] });
const result = authored.update.decide({
  action: 'accept',
  selection,
});
```

使用 `action: 'reject'` 拒绝 change。请检查 `result.status`：其他编辑可能使 selection 变为 `stale`，依赖或冲突可能使其变为 `blocked`。[Authored Changes](/docs/authored-changes#审阅-change)介绍查询、预览、批量决定和结果处理。

## 保存和重新加载

保存 `editor.read.value()` 返回的完整值。`meta.authored` 由文档 codec 管理；不要编辑它，也不要把 proposal metadata 复制到 node 中。

```tsx
const savedDocument = editor.read.value();
const savedComments = editor.plugin(CommentsPlugin).api.toJSON();
```

按同一个应用版本和对话代次原子保存文档与 `CommentsJSON`。加载前验证关联，并使用相同的内容插件。只保存 `children` 会丢失 authored record。

创建新 editor，将文档传给 `initialValue`，并配置 `CommentsPlugin.configure({ initialState: { initialComments: savedComments } })`。本地 undo stack 从空开始。文档保留每个 change 的作者和 ID，使回复仍可定位同一建议。将 `userId` 设置为当前作者；加载其他作者的建议不需要切换身份或重放编辑。历史预览和恢复请参阅[当前对话与历史目标的关联](/docs/comment#历史版本)。

对于 JSON、Markdown、HTML 或 DOCX，请选择显式的[导出投影](/docs/authored-changes#导出显式投影)。Accepted 和 proposed 导出会省略审阅记录；当保存格式需要保留记录时，使用 `review`。

## Headless 用法

使用 `BaseSuggestionPlugin` 可在不安装 React、Comments 或复制 UI 的情况下获得建议模式和语义 decoration：

```tsx title="suggestion-editor.ts" showLineNumbers
import { BaseParagraphPlugin, createEditor } from 'platejs';
import { BaseSuggestionPlugin } from 'platejs/suggestion';

const editor = createEditor({
  plugins: [BaseParagraphPlugin, BaseSuggestionPlugin],
  initialValue: [
    { type: 'paragraph', children: [{ text: 'Edit this sentence.' }] },
  ],
  userId: 'alice',
});

editor.plugin(BaseSuggestionPlugin).api.setMode('suggesting');
```

普通建议 range 提供 `data-editor-authored-change`、`data-editor-authored-kind` 和 `data-editor-authored-status`。保留片段提供 `data-editor-authored-change` 和 `data-editor-retained`。通过 plugin 的 `render.contentAttributes` 为这些属性配置样式。静态 preset 可以为 `BaseSuggestionPlugin` 配置服务端安全的属性对象；`SuggestionKit` 提供交互编辑器的默认样式。

## Discussion 审阅

添加 [DiscussionKit](/docs/discussion) 可获得接受和拒绝卡片，以及附加到 change 的回复。它将可选 Comments 数据与原生 authored change 组合；审阅展示仍是复制的应用代码。

以 authored change ID 为 target，即可通过编程方式附加对话：

```tsx
import { CommentsPlugin } from 'platejs/comments/react';

const comments = editor.plugin(CommentsPlugin).api;
const result = await comments.createThread({
  body: [
    { type: 'paragraph', children: [{ text: 'Can we explain this edit?' }] },
  ],
  target: { type: 'change', id: changeId },
});

if (result.status === 'applied') {
  comments.setActive([result.value]);
}
```

结果不是 `applied` 或抛出异常时保留输入。Comments 通过 `initialState.mutate` 授权持久化写入，只发布已提交的规范记录。接受或拒绝 change 是可撤销的文档操作；它隐藏审阅卡片，但不删除或解决讨论。Undo 恢复待处理 change，并保留消息与解决状态。解决或重新打开 thread 不进入文档 undo。

## API 参考

### `BaseSuggestionPlugin`

从 `platejs/suggestion` 导入。它提供两个建议模式和无 CSS 的语义 decoration，并依赖 `DefaultAuthoredPlugin` 管理 change record 和身份。

### `SuggestionPlugin`

从 `platejs/suggestion/react` 导入。它在 `BaseSuggestionPlugin` 上添加精确 view 的活动状态和点击激活。

### `suggestion.api.setMode(mode)`

通过 `editor.plugin(SuggestionPlugin)` 或 `editor.plugin(BaseSuggestionPlugin)` 设置后续输入是 proposal 还是直接编辑。两个模式都保留 markup projection 及其待处理审阅 UI。

### `suggestion.read.mode()`

读取该 editor view 的 `'suggesting'` 或 `'editing'` 模式。

### React hooks

| Hook | 结果 |
| --- | --- |
| `useSuggestionMode()` | 精确挂载 view 的 `'suggesting' \| 'editing'` 模式。 |
| `useSuggestionChanges(path)` | 接触 `path` 处区块的原生 `AuthoredChange` 记录。 |
| `useActiveSuggestion()` | View 局部的 `activeId` 和 `setActiveId` 函数。 |

### `SuggestionKit`

复制的 registry kit 为 `SuggestionPlugin` 配置内容根节点样式。通用 editor 组件与建议功能保持独立。审阅卡片、Comments 集成、工具栏和 popover 保留在 registry 代码中。
