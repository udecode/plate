Pass fetched comment records to `CommentsPlugin`. The package owns the records, comment actions, subscriptions, and range mapping. Your application loads and saves the data.

<PackageInfo>

## Features

- Serializable thread records with rich-text messages and ISO timestamps
- Ranges that track edits, undo, and redo
- Ordered overlapping highlights and editor-local activation
- Keyed subscriptions for messages, pending input, and thread lists
- Comment and suggestion review through copied Discussion UI

</PackageInfo>

## Kit Usage

<Steps>

### Installation

```bash
npx shadcn@latest add https://platejs.org/r/discussion.json https://platejs.org/r/comment-toolbar-button.json
```

`DiscussionKit` includes Comment styling, the shared discussion index, block triggers, and Floating Discussion. The copied `comment` item supplies `CommentKit`, rich thread cards, and the composer. The toolbar button starts a comment from the selection; `Mod+Shift+M` provides the same action.

### Add Kit

Pass records fetched with the matching document to `initialThreads`:

```tsx title="components/editor/comments-editor.tsx" showLineNumbers {23-30}
"use client";

import type { EditorValueInput } from "platejs";
import type { CommentThread, CommentUser } from "platejs/comments";
import { CommentsPlugin } from "platejs/comments/react";
import { Plate, useCreateEditor } from "platejs/react";

import { DiscussionKit } from "@/components/editor/discussion";
import { Editor, EditorContainer } from "@/components/editor/editor";
import { EditorKit } from "@/components/editor/plugins";

export function CommentsEditor({ value, threads, users, currentUserId }: {
  value: EditorValueInput;
  threads: readonly CommentThread[];
  users: Record<string, CommentUser>;
  currentUserId: string;
}) {
  const editor = useCreateEditor({
    plugins: [
      ...EditorKit,
      ...DiscussionKit,
      CommentsPlugin.configure({
        initialState: {
          initialThreads: threads,
          users,
          currentUserId,
        },
      }),
    ],
    initialValue: value,
  });

  return (
    <Plate editor={editor}>
      <EditorContainer>
        <Editor />
      </EditorContainer>
    </Plate>
  );
}
```

`initialThreads` seeds each editor once. Use `api.setThreads(records)` for an explicit refetch. Updating the component's initial props does not replace the editor's current records.

</Steps>

## Application data

Store complete `CommentThread` records. Message bodies use Plate `Value`; timestamps use ISO 8601 strings. Range targets contain plain document coordinates:

```ts
import type { CommentThread } from "platejs/comments";

const threads: CommentThread[] = [{
  id: "review-1",
  userId: "alice",
  createdAt: "2026-09-09T12:00:00.000Z",
  excerpt: "Selected text",
  resolved: false,
  status: "published",
  target: {
    type: "range",
    range: {
      anchor: { path: [0, 0], offset: 0 },
      focus: { path: [0, 0], offset: 13 },
    },
  },
  messages: [{
    id: "message-1",
    userId: "alice",
    createdAt: "2026-09-09T12:00:00.000Z",
    body: [{ type: "paragraph", children: [{ text: "Please review this." }] }],
  }],
}];
```

`{ type: "suggestion", id }` attaches a thread to a suggestion. A range target with `range: null` represents a detached thread.

Read current mapped ranges when saving, together with the same document revision:

```ts
import { CommentsPlugin } from "platejs/comments/react";

const comments = editor.plugin(CommentsPlugin);
const snapshot = {
  document: editor.read.value(),
  threads: comments.api.getThreads(),
};
```

`api.subscribeThreads(listener)` reports `{ ids, reason }`, where `reason` is `"data"` or `"document"`. Use it to observe changes for your persistence layer. Database requests, collaboration transport, and server authorization belong to the application.

`api.setThreads(records)` replaces complete records together and preserves the current user and pending composer. It copies incoming data and rejects duplicate thread IDs, invalid timestamps, and invalid ranges before replacing existing records. Ranges address the primary document; named secondary roots are unsupported. `api.setThreads([])` clears the records. Read snapshots are immutable; use the API to change them.

## Manual Usage

The headless plugin provides the same data and range API without React. This example loads the records above:

```bash
npm install platejs
```

```ts
import { createEditor } from "platejs";
import { BaseCommentsPlugin } from "platejs/comments";

const editor = createEditor({
  plugins: [BaseCommentsPlugin.configure({
    initialState: { initialThreads: threads, currentUserId: "alice" },
  })],
  initialValue: [{ type: "paragraph", children: [{ text: "Selected text" }] }],
});
```

## Ownership

| Owner | Responsibility |
| --- | --- |
| `platejs/comments` | Own records, actions, subscriptions, and private native range handles |
| `platejs/comments/react` | Add selection commands, shortcuts, and highlight clicks |
| Copied `comment` and `discussion` items | Style highlights and render forms, cards, block triggers, and popovers |
| Your application | Supply users and fetched records; persist data and authorize remote writes |

Comment messages remain separate from document nodes and marks. A message edit notifies that thread's subscribers without resolving anchors or refreshing editor decorations. `users` and `currentUserId` use the plugin store; subscribe with `usePluginStore` and update them through `store.set`.

## Editing and history

Comments use inward-associated `nearest` anchors internally. Inserting text inside a range expands it; deleting text contracts it. Text inserted at either boundary stays outside the range.

When all annotated text is deleted, the range collapses at a valid document position. Its block trigger keeps the thread reachable without highlighting neighboring text. Undo and redo restore the mapped range, including backward direction and overlaps.

## Collaboration and read-only review

Pass the same serialized records to independent editors when their documents match. Each editor creates its own native handles and activation state. If document revisions differ, load ranges for each revision; plain coordinates cannot identify edits that happened elsewhere.

For a read-only view, set `readOnly` on both `Plate` and `Editor`. For static rendering, use `BaseCommentsPlugin` and configure `commentDecorationAttributes` from the copied `comment-static` item. Thread cards remain copied application UI.

## Legacy document migration

Run `extractLegacyCommentRanges` before loading documents that contain `comment`, `comment_*`, `comment_draft`, or `commentTransient` properties.

```ts
import { extractLegacyCommentRanges } from "platejs/migrations";

const {
  comments,
  diagnostics,
  document: cleanDocument,
} = extractLegacyCommentRanges(document, {
  threadIds: storedThreads.map((thread) => thread.id),
});

console.table(diagnostics);
```

Persist `cleanDocument` and import `comments` through your storage layer after reviewing every diagnostic. The extractor never invents missing thread IDs. Run it offline; the runtime plugin has no legacy fallback.

## Plugins

- `BaseCommentsPlugin` from `platejs/comments` owns headless data and range behavior.
- `CommentsPlugin` from `platejs/comments/react` adds React view interactions.

## API Reference

### Data and ranges

| Method | Purpose |
| --- | --- |
| `api.getThreads()` | Read complete records with current mapped ranges for persistence |
| `api.getThread(id)` | Read one stable record, or `undefined` |
| `api.setThreads(records)` | Replace all records from a fetch |
| `api.getSnapshot()` | Read stable thread IDs, visible IDs, draft IDs, and pending input |
| `api.range(id)` | Read a range target's current `Range`, or `null` |
| `api.idsAt(location)` | Read overlapping unresolved IDs in record order |
| `api.setActive(ids)` | Select an ordered group; use `[]` to clear it |
| `api.subscribe(listener)` | Observe canonical range projection changes |

### Comment actions

| Method | Purpose |
| --- | --- |
| `api.begin(range?)` | Start pending input; a caret expands to its text block |
| `api.pendingRange()` | Read the pending input's mapped range |
| `api.cancel()` | Cancel pending input and release its range |
| `api.create(body)` | Complete the pending thread |
| `api.createThread({ body, target, ... })` | Create a range or suggestion thread; accepts `id`, `excerpt`, `status`, and `userId` |
| `api.reply(id, body)` | Append a message to an unresolved thread |
| `api.edit(id, messageId, body)` | Edit the current user's message |
| `api.removeMessage(id, messageId)` | Remove the current user's message; remove its thread when no messages remain |
| `api.removeThread(id)` | Remove a thread owned by the current user |
| `api.resolve(id, resolved?)` | Resolve or reopen a thread owned by the current user; defaults to `true` |
| `api.publishDraft(id)` | Publish an AI draft |
| `api.discardDraft(id)` | Remove an AI draft |

Creation requires a user ID and a nonempty body. Failed creation returns `null`; rejected boolean actions return `false`. `create`, `createThread`, `reply`, and `edit` allow asynchronous API overrides, so callers can await their results.

### Subscriptions

`subscribeThread(id, listener)` observes one record. `subscribeVisibleThreadIds`, `subscribeDraftThreadIds`, and `subscribePending` observe their respective snapshots. `subscribeThreads` observes persisted data changes, including mapped ranges. Each method returns an unsubscribe function.

### `CommentComposer`

`onSubmit(body)` returns a thread ID or `true` after success, or `null` or `false` after rejection. It can return a promise. The composer preserves rich input while saving, blocks duplicate submissions, and clears only on success. Rejection or a thrown error retains the draft and displays a retry message.
