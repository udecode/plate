## 功能特性

- 确保编辑器中可聚焦元素之间的标签顺序一致
- 管理空元素与外部DOM元素之间的焦点切换

</PackageInfo>

## 套件使用

<Steps>

### 安装

最快捷的方式是使用 `TabbableKit`。该套件会保留 Indent，但关闭其 Tab 和 Shift+Tab 快捷键，因此在段落中按 Tab 会移动焦点而不是缩进。它的 `query` 在列表项、代码块和表格中不接管 Tab，由这些功能自行处理。

<ComponentSource name="tabbable" />

### 添加套件

```tsx
import { createEditor } from 'platejs/react';
import { TabbableKit } from '@/components/editor/tabbable';

const editor = createEditor({
  plugins: [
    // ...其他插件,
    ...TabbableKit,
  ],
});
```

</Steps>

## 手动配置

<Steps>

### 安装

```bash
npm install platejs tabbable
```

### 添加插件

```tsx
import { TabbablePlugin } from 'platejs/tabbable/react';
import { createEditor } from 'platejs/react';

const editor = createEditor({
  plugins: [
    // ...其他插件,
    TabbablePlugin,
  ],
});
```

### 配置插件

```tsx
import { TabbablePlugin } from 'platejs/tabbable/react';
import { BaseCodeBlockPlugin } from 'platejs';
import { createEditor } from 'platejs/react';

const editor = createEditor({
  plugins: [
    // ...其他插件,
    TabbablePlugin.configure({
      initialState: {
        query: ({ editor }) => {
          const codeBlock = editor.plugin(BaseCodeBlockPlugin);

          return (
            !codeBlock.installed ||
            !editor.read.nodes.some({ type: codeBlock.schema.type })
          );
        },
        globalEventListener: true,
        isTabbable: ({ editor, entry }) =>
          editor.read.schema.isVoid(entry.slateNode),
      },
    }),
  ],
});
```

- `initialState.query`: 决定 Tabbable 是否处理一次 Tab。在 Tabbable 接受的停靠点上按下的 Tab 会跳过 `query`，总是按标签顺序移动。停靠点是插入的 entry，或 `isTabbable` 接受的编辑器内可聚焦元素
- `initialState.globalEventListener`: 为`true`时，将事件监听器添加到document而非编辑器
- `initialState.isTabbable`: 判断哪些元素应包含在标签顺序中的函数

每个回调都会收到 Tabbable 所在视图的编辑器。请从这个 `editor` 读取光标，而不是从 `.configure` 中捕获的编辑器读取，后者可能不持有该视图的光标。

</Steps>

## 高级用法

### 与其他插件的冲突

Tabbable 在任何编辑器快捷键之前处理 Tab。当 `query` 不接管，或光标之后没有可停靠的位置时，其他功能才会收到该按键。列表、代码块、表格和缩进插件都会使用 Tab。即使关闭了 Indent 的快捷键，列表也会自行处理列表项上的 Tab 和 Shift+Tab。

使用`query`选项，在`Tab`键应由其他功能处理时不接管：

```tsx
TabbablePlugin.configure({
  initialState: {
    query: ({ editor }) => {
      const codeBlock = editor.plugin(BaseCodeBlockPlugin);

      return (
        !codeBlock.installed ||
        !editor.read.nodes.some({ type: codeBlock.schema.type })
      );
    },
  },
});
```

如果编辑器中还有其他使用 Tab 的功能，例如 Copilot 建议或打开的组合框，请扩展 `query`。`TabbableKit` 只在列表项、代码块和表格中不接管。

如果使用缩进插件，可以仅在选中特定类型节点(如void节点)时启用Tabbable插件：

```tsx
query: ({ editor }) =>
  editor.read.nodes.some({
    match: (node) => editor.read.schema.isVoid(node),
  }),
```

### 非空Plate节点

将为编辑器中的每个可聚焦DOM元素创建一个`TabbableEntry`，使用[tabbable](https://www.npmjs.com/package/tabbable) NPM包确定。然后使用`isTabbable`过滤可聚焦列表。

默认情况下，`isTabbable`仅对void Plate节点内的entry返回true。可以覆盖`isTabbable`以支持其他类型Plate节点中包含的DOM元素：

```tsx
// 启用CUSTOM_ELEMENT内的可聚焦DOM元素
isTabbable: ({ editor, entry }) =>
  entry.slateNode.type === CUSTOM_ELEMENT ||
  editor.read.schema.isVoid(entry.slateNode),
```

### 编辑器外部的DOM元素

某些情况下，可能需要允许用户从编辑器切换到外部渲染的DOM元素(如交互式弹出框)。

为此，覆盖`insertTabbableEntries`返回`TabbableEntry`对象数组，每个对象对应一个要包含在可聚焦列表中的外部DOM元素。`TabbableEntry`的`slateNode`和`path`应引用当DOM元素可聚焦时用户光标所在的Plate节点。

将`globalEventListener`选项设为`true`以确保Tabbable插件能将用户焦点返回到编辑器。

例如，如果DOM元素在选中链接时出现，`slateNode`和`path`应为该链接的节点。

```tsx
// 将.my-popover内的按钮添加到可聚焦列表
globalEventListener: true,
insertTabbableEntries: ({ editor }) => {
  const selectedEntry = editor.read.nodes.above();

  if (!selectedEntry) return [];

  const [selectedNode, selectedNodePath] = selectedEntry;

  return [
    ...document.querySelectorAll('.my-popover > button'),
  ].map((domNode) => ({
    domNode,
    slateNode: selectedNode,
    path: selectedNodePath,
  }));
},
```

## 插件

### TabbablePlugin

管理可聚焦元素间标签顺序的插件。

<API name="TabbablePlugin">
<APIOptions>
  <APIItem name="query" type="(context: TabbableEventContext) => boolean" optional>
    决定 Tabbable 是否处理一次 Tab。在 Tabbable 接受的停靠点上按下的 Tab 会跳过 `query`，总是按标签顺序移动。停靠点是插入的 entry，或 `isTabbable` 接受的编辑器内可聚焦元素。
    - **默认值:** `() => true`
  </APIItem>
  <APIItem name="globalEventListener" type="boolean" optional>
    将事件监听器添加到document而非编辑器。
    - **默认值:** `false`
  </APIItem>
  <APIItem name="insertTabbableEntries" type="(context: TabbableEventContext) => TabbableEntry[]" optional>
    添加编辑器外的额外可聚焦entry。
    - **默认值:** `() => []`
  </APIItem>
  <APIItem name="isTabbable" type="(context: TabbableEventContext & { entry: TabbableEntry }) => boolean" optional>
    判断元素是否应可聚焦。
    - **默认值:** `({ editor, entry }) => editor.read.schema.isVoid(entry.slateNode)`
  </APIItem>
</APIOptions>
</API>

## 类型

### TabbableEventContext

每个回调收到的上下文。

<API name="TabbableEventContext">
<APIAttributes>
  <APIItem name="editor" type="Editor">
    Tabbable 所在视图的编辑器，持有该视图的光标。
  </APIItem>
  <APIItem name="event" type="KeyboardEvent">
    Tab 的 keydown 事件。
  </APIItem>
</APIAttributes>
</API>

### TabbableEntry

定义可聚焦entry的属性。

<API name="TabbableEntry">
<APIAttributes>
  <APIItem name="domNode" type="FocusableElement">
    表示可聚焦 entry 的 HTML 或 SVG 元素。
  </APIItem>
  <APIItem name="slateNode" type="Node">
    对应的Plate节点。
  </APIItem>
  <APIItem name="path" type="Path">
    文档中Plate节点的路径。
  </APIItem>
</APIAttributes>
</API>
