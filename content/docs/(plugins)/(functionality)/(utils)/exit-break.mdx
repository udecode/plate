## Features

- Exit from nested block structures (like code blocks, tables, columns) using keyboard shortcuts.
- Leaves only the nearest structure, so Mod+Enter in a code block, callout, image or divider inside a column inserts the new block in that column.
- Inserts the block the surrounding container declares as its default, such as a paragraph in a column.

</PackageInfo>

## Kit usage

<Steps>

### Installation

The fastest way to add exit break functionality is with the `ExitBreakKit`, which includes pre-configured `ExitBreakPlugin` with keyboard shortcuts.

### Add kit

```tsx
import { createEditor } from 'platejs/react';
import { ExitBreakKit } from '@/components/editor/exit-break';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    ...ExitBreakKit,
  ],
});
```

## Manual usage

<Steps>

### Add plugin

```tsx
import { ExitBreakPlugin } from 'platejs';
import { createEditor } from 'platejs/react';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    ExitBreakPlugin,
  ],
});
```

### Configure plugin

```tsx
import { ExitBreakPlugin } from 'platejs';
import { createEditor } from 'platejs/react';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    ExitBreakPlugin.configure({
      shortcuts: {
        insert: { keys: 'mod+enter' },
        insertBefore: { keys: 'mod+shift+enter' },
      },
    }),
  ],
});
```

- `shortcuts.insert`: Defines a keyboard [shortcut](/docs/plugin-shortcuts) to exit and insert block after.
- `shortcuts.insertBefore`: Defines a keyboard [shortcut](/docs/plugin-shortcuts) to exit and insert block before.

</Steps>

## How exit break works

Exit break leaves the nearest structure around the caret. A code block,
callout, image or divider is a structure of its own, so exit inserts the new
block right after it, inside the same container. From any other block, exit
leaves the nearest container that can take a paragraph beside it: a paragraph
in a quote leaves the quote, and a paragraph in a column leaves the whole
column group, because the group holds only columns. The new block is the
default that the structure's parent declares.

### Exit point determination

When you trigger exit break:

1. Starts from the block that holds the caret
2. Stops at that block when it owns its exit: a void such as a divider, an object such as an image, or a text block that declares `ownsExit`, such as a code block or a callout
3. Otherwise walks up its ancestors and stops at the first one that sits directly in the document, or whose parent can hold a text block such as a paragraph
4. Inserts that parent's default block next to the exit point and moves the caret into it

Exit passes over a block that owns its exit, and leaves the container instead, when its parent cannot put a plain text block beside it. That happens when the parent has no room or no default block, or when its default needs a property nothing supplies, holds no text, or owns its exit too. Below the top level, the walk also passes a container whose default would put the caret back into a container of the same type.

Once exit stops at a container, it never climbs further. When that container's parent declares no default block, has no room for another one, or has a default that needs a property nothing supplies or holds no text, nothing changes.

### Examples

**Code Block:**
```tsx
<codeBlock>                              // ← Exit point (top-level block)
  code|                                  // ← Starting position
</codeBlock>
<paragraph>|</paragraph>                 // ← New paragraph inserted here
```

**Code Block in Column (stays in the column):**
```tsx
<columnGroup>
  <column>
    <codeBlock>                          // ← Exit point (owns its exit)
      code|                              // ← Starting position
    </codeBlock>
    <paragraph>|</paragraph>             // ← New paragraph inserted here
  </column>
</columnGroup>
```

**Image or Divider in Column:**
```tsx
<columnGroup>
  <column>
    <image url="...">caption|</image>    // ← Exit point and starting position
    <paragraph>|</paragraph>             // ← New paragraph inserted here
  </column>
</columnGroup>
```

**Paragraph in Column (leaves the column group):**
```tsx
<columnGroup>                            // ← Exit point (top-level block)
  <column>                               // group allows columns only
    <paragraph>content|</paragraph>      // ← Starting position
  </column>
</columnGroup>
<paragraph>|</paragraph>                 // ← New paragraph inserted here
```

**Table in Column (exits at table level):**
```tsx
// First exit
<columnGroup>
  <column>                               
    <table>                              // ← Exit point (column allows blocks)
      <tableRow>                         // table allows rows only
        <tableCell>                      // row allows cells only
          <paragraph>content|</paragraph>// ← Starting position
        </tableCell>
      </tableRow>
    </table>
    <paragraph>|</paragraph>             // ← New paragraph inserted here
  </column>
</columnGroup>

// Second exit
<columnGroup>                            // ← Exit point (top-level block)
  <column>                               // group allows columns only
    <table>                              
      <tableRow>
        <tableCell>
          <paragraph>content</paragraph>
        </tableCell>
      </tableRow>
    </table>
    <paragraph>|</paragraph>             // ← Starting position
  </column>
</columnGroup>
<paragraph>|</paragraph>                 // ← New paragraph inserted here
```

### Custom plugin configuration

Declare each custom element's allowed child content and its default. An exit passes ancestors whose parent cannot hold a paragraph, such as a cell in a row, and inserts the default that the landing parent declares:

```tsx
import { definePlugin, schema } from 'platejs';

// Table structure
const CustomTablePlugin = definePlugin('table', {
  schema: {
    element: {
      content: schema.content.type('tr', { min: 1 }),
    },
  },
});

const CustomTableRowPlugin = definePlugin('tr', {
  schema: {
    element: {
      content: schema.content.types(['td', 'th'], {
        default: { type: 'td' },
        min: 1,
      }),
    },
  },
});

const CustomTableCellPlugin = definePlugin('td', {
  schema: {
    element: {
      content: schema.content.group('block', {
        default: { type: 'paragraph' },
        min: 1,
      }),
    },
  },
});
```

A text block that exit should leave before its container, such as a custom code-like block or a callout whose Enter rule exits, declares `ownsExit`. Without it, the block behaves like a paragraph and exit leaves its container:

```tsx
import { definePlugin, schema } from 'platejs';

const NoticePlugin = definePlugin('notice', {
  rules: { break: { emptyLineEnd: 'deleteExit' } },
  schema: {
    element: schema.element.textBlock({ ownsExit: true }),
  },
});
```

Only a text block can declare `ownsExit`. Voids and objects always own their exit.
