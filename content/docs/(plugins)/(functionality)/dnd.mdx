## Features

- Drag a block by its handle. The selected blocks, or a list item with its nested items, move together.
- Each view paints one drop indicator at the edge where the drop lands.
- A drag moves blocks within one document and copies them into another editor. Hold Option on macOS, or Ctrl elsewhere, to copy instead.
- Click a handle for Move up, Move down and Cut. `Mod+Shift+ArrowUp` and `Mod+Shift+ArrowDown` move the blocks around the caret.
- A block drops wherever its schema allows, such as inside a blockquote, a details body, a column or a table cell. Table rows, columns, lists, the details summary and uploads keep their own rules, so the indicator only shows edges the drop can use.
- Dropped files become uploads when `UploadPlugin` accepts native drops.

</PackageInfo>

## Kit usage

<Steps>

### Installation

`DndKit` adds a handle to each selectable block at any depth, such as blocks inside blockquotes, details, columns and table cells, and shows only the handle of the innermost hovered block. Rows, cells, column items and the details summary get none. It also paints the drop indicator and binds the keyboard moves. Drag and drop uses the browser's native events; it needs no provider or extra dependency.

<ComponentSource name="dnd" />

### Add kit

```tsx
import { createEditor } from 'platejs/react';
import { DndKit } from '@/components/editor/dnd';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    ...DndKit,
  ],
});
```

</Steps>

## Examples

### Multiple editors

<ComponentPreview name="dnd-multi-editor-demo" />

Two `EditorRoot`s over one editor are two views of one document, so a drag between them moves the block. Mount the second view with `suppressInstanceWarning`. A drop into another editor copies, and the source keeps its blocks.

### Tables and columns

<ComponentPreview name="dnd-table-demo" />

The copied `table` and `column` components add their own row and column handles. Rows land only beside rows of the same table, and the table refuses a drop that would split a merged cell. Columns reorder within their group. Other blocks can drop into a cell or a column.

### File drops

The React `UploadPlugin` places dropped files when `nativeDrop` is `true`; the copied [Upload](/docs/upload) kit enables it. A file drop shows the same indicator and lands only where one upload block per file can go. A browser that hides the file count while dragging gets an indicator checked for one block. The drop itself checks every file. A refused drop inserts nothing.

## Custom drag handle

The editor resolves every `dragover` and `drop` itself. It finds the landing, publishes the indicator and runs the transfer. A handle only starts the drag, and a component paints the indicator.

```tsx
import {
  definePlugin,
  type RenderNodeWrapperProps,
  useDropIndicator,
} from 'platejs/react';

function DragHandle({ children, editor, element }: RenderNodeWrapperProps) {
  return (
    <div className="relative [&>[data-editor-dragging]]:opacity-50">
      <button
        aria-label="Drag block"
        className="absolute -left-6 cursor-grab"
        contentEditable={false}
        draggable
        type="button"
        onDragStart={(event) => {
          if (!editor.api.dom.drag.start(event.nativeEvent, { node: element })) {
            event.preventDefault();
          }
        }}
      >
        ⠿
      </button>
      {children}
    </div>
  );
}

function DropIndicator() {
  const indicator = useDropIndicator();

  if (!indicator) return null;

  const { line } = indicator;

  return (
    <div
      aria-hidden
      className="pointer-events-none fixed top-0 left-0 h-0.5 bg-blue-500"
      style={{
        transform: `translate(${line.x}px, ${line.y - 1}px)`,
        width: line.width,
      }}
    />
  );
}

export const DragHandlePlugin = definePlugin('dragHandle', {
  slots: {
    afterEditable: DropIndicator,
    wrapNode: {
      component: DragHandle,
      match: ({ editor, element }) =>
        editor.read.schema.isBlockContent(element) &&
        editor.read.nodes.isSelectable(element),
    },
  },
});
```

The match gives every selectable block a handle, at any depth; match `renderPath.length === 1` for top-level blocks only. `drag.start` returns `null` when nothing can be dragged, such as a removed block. While the drag runs, every dragged block carries `data-editor-dragging`, which the wrapper above dims. A read-only view starts a copy-only drag.

The indicator moves on every `dragover`, so position it with `transform`, which skips layout. Column items lay out horizontally, so their indicator has `axis: 'x'`. Paint a vertical line from `line.x`, `line.y` and `line.height`.

### Drag image

`drag.start` also returns inert clones of the dragged blocks and the pointer's offset from the first one. The kit's `startBlockDrag` places them over the dragged block and hands them to the browser as the drag image:

```tsx
onDragStart={(event) => {
  const drag = editor.api.dom.drag.start(event.nativeEvent, { node: element });

  if (!drag) {
    event.preventDefault();
    return;
  }

  const rect = editor.api.dom.resolveDOMNode(element)?.getBoundingClientRect();
  const image = document.createElement('div');

  image.style.cssText = `position:fixed;pointer-events:none;left:${rect?.left ?? 0}px;top:${rect?.top ?? 0}px;width:${rect?.width ?? 0}px;`;
  image.append(...drag.previews);
  document.body.append(image);
  event.dataTransfer.setDragImage(image, drag.origin.x, drag.origin.y);
  // The browser snapshots the image during dragstart.
  requestAnimationFrame(() => image.remove());
}}
```

## Move blocks programmatically

`editor.api.transfer` runs the same rules as a drop. Each call is one undo step and returns its outcome.

```tsx
const outcome = editor.api.transfer.move({
  nodes: [editor.key(element)],
  to: { edge: 'after', key: editor.key(target) },
});

if (outcome.status === 'refused') {
  console.warn(outcome.reason);
}
```

`to` also accepts `'next'` and `'previous'`, which step the blocks past their nearest sibling inside their parent and keep the selection; blocks under different parents refuse with `policy`. Without `nodes`, the transfer carries the blocks `editor.read.transfer.nodes()` returns. Pass `announce` to give screen readers a message when the move lands:

```tsx
editor.api.transfer.move({ announce: 'Moved down', to: 'next' });
```

Pass `from` with another editor to move or copy from it. Between independent editors a move always copies.

### Refuse a landing

A block lands wherever the target's schema accepts it. A plugin refuses what its schema allows but the feature does not, such as a row in another table, with a `transferVeto` contribution. It runs on the final edge for every drag, keyboard move and `editor.api.transfer` call, after features such as lists have adjusted it.

```tsx
import { transferVeto } from 'platejs';
import { definePlugin } from 'platejs/react';

export const PinnedPlugin = definePlugin('pinned', {
  contributions: [
    transferVeto.of(({ edge, target: [node] }) => edge === 'before' && node.pinned === true),
  ],
});
```

The input also carries the source view (`from`), the `intent` (`move` or `copy`), the `payload` and the documents' `relation`. The second argument is the target view.

To move an edge instead, such as past a list item's nested items, wrap `editorReads.transfer.landing` in read middleware and return another edge, or `next()` to keep it. A moved edge must map to itself; the schema and the vetoes then check the final edge.

## API reference

### `editor.api.transfer.move`

<API name="move">
<APIParameters>
  <APIItem name="input" type="TransferInput">
    <APISubList>
      <APISubListItem parent="input" name="to" type="{ key: NodeKey; edge: 'before' | 'after' } | { point: Point } | 'next' | 'previous'">
        Where the payload lands: beside a block, at a text point, or one step past a sibling.
      </APISubListItem>
      <APISubListItem parent="input" name="nodes" type="NodeKey[]" optional>
        Blocks to move, by key in `from`. **Default:** the selected blocks, or the blocks containing the selection.
      </APISubListItem>
      <APISubListItem parent="input" name="range" type="Range" optional>
        Text to move instead of blocks.
      </APISubListItem>
      <APISubListItem parent="input" name="from" type="Editor" optional>
        Source editor or view. **Default:** the editor running the transfer.
      </APISubListItem>
      <APISubListItem parent="input" name="announce" type="string" optional>
        Screen-reader message announced when the transfer lands.
      </APISubListItem>
    </APISubList>
  </APIItem>
</APIParameters>

<APIReturns type="TransferOutcome">
  <APIItem name="status" type="'moved' | 'copied' | 'refused'">
    `moved` and `copied` include the landed selection as `at`. `copied` gives its `reason`, such as `independent` for another editor. `refused` gives a `reason`: `inside-source`, `lossy`, `no-op`, `policy`, `read-only-target`, `schema` or `source-missing`.
  </APIItem>
</APIReturns>
</API>

### `editor.api.transfer.copy`

Takes the same input as `move` and keeps the source.

### `editor.read.transfer.nodes`

`editor.read.transfer.nodes(options?: { node?: Element | NodeKey }): NodeKey[]` returns the blocks a transfer carries, such as a list item with its nested items. With `node`, it returns a handle's blocks: the selected blocks when the selection holds `node`, else `node` alone. Without it, it returns the selected blocks, or the blocks containing the selection. Pass the result as `nodes` to `editor.api.transfer.move`.

### `useDropIndicator`

`useDropIndicator(): DropIndicator | null` reads the current view's drop indicator.

<API name="DropIndicator">
<APIAttributes>
  <APIItem name="key" type="NodeKey">
    Block beside which the drop lands.
  </APIItem>
  <APIItem name="edge" type="'before' | 'after'">
    Side of that block.
  </APIItem>
  <APIItem name="axis" type="'x' | 'y'">
    `y` for stacked blocks, `x` for side-by-side items such as columns.
  </APIItem>
  <APIItem name="line" type="{ x: number; y: number; width: number; height: number }">
    Viewport rectangle of the edge, with zero height on `y` and zero width on `x`.
  </APIItem>
</APIAttributes>
</API>

### DOM drag API

[`editor.api.dom.drag.start`](/docs/api/dom#drag-and-drop), `editor.api.dom.drag.indicate` and `editor.api.dom.resolveDropTarget` drive a drag from code, such as a custom handle that is not a native draggable.
