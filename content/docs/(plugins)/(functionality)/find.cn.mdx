## 功能

- 在主编辑器或嵌套 Editable（例如白板便签）中通过查找按钮或 `Mod+F` 打开，并从当前活动视图的文本选择填充查询。
- 按文档阅读顺序搜索主文档和所有命名内容根（named content root）。
- 按挂载视图使用临时装饰高亮结果，不向文档或历史记录写入标记。
- 匹配项可以跨越同一块内的文本叶和行内元素。
- 使用 `Enter`、`Shift+Enter` 或按钮切换结果，并自动滚动或平移显示视口外的目标（例如视口外的白板便签）。
- 文档变化后更新结果。在块内输入或设置格式只重新搜索该根中发生变化的块，并且只重绘受影响根中高亮有变化的文本。
- 编辑时让当前结果跟随其匹配项。
- 每个挂载的编辑器呈现（presentation）独立打开搜索栏，并通过 `useFind` 支持自定义控件。

</PackageInfo>

## 安装

```bash
npx shadcn@latest add @plate/find
```

## 使用

把 `FindKit` 加入编辑器插件：

```tsx
import { createEditor } from 'platejs/react';

import { FindKit } from '@/components/editor/find';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    ...FindKit,
  ],
});
```

`BaseFindPlugin` 管理查询、匹配结果、导航和临时装饰数据。`FindKit` 提供查找按钮、
快捷键、延迟输入和可访问的搜索栏。按钮位于搜索栏打开的位置，
没有 `Mod+F` 的触屏设备可以用它打开查找。打开的搜索栏会取代按钮。`FindKit` 还通过 `decorate.attributes` 配置普通与当前匹配项的高亮样式。查询状态位于文档和
历史记录之外。每个 Editable 独立管理搜索栏的开关、输入草稿、焦点和滚动请求。
同一编辑器的视图共享已提交的查询和结果，但打开一个搜索栏不会打开另一个。
没有待处理草稿的搜索栏会跟随共享查询；只有获得焦点的搜索栏会滚动其视图。
卸载视图不会清除共享搜索。

## 搜索 API

`platejs/find` 的 `BaseFindPlugin` 管理查询、匹配项、导航、替换与临时装饰数据。

```ts
import { createEditor } from 'platejs';
import { BaseFindPlugin } from 'platejs/find';

const editor = createEditor({ plugins: [BaseFindPlugin] });
const find = editor.plugin(BaseFindPlugin);

find.api.search('example', { caseSensitive: true, wholeWord: true });
find.api.move(1);
find.api.matches();
find.store.get('activeMatch');
find.update.select();
find.update.replace('sample');
find.update.replaceAll('sample');
```

`api.search(query, options?)` 按文档阅读顺序在主文档和每个命名内容根中执行搜索（将每个命名根的结果并入其首个拥有者的位置），空字符串清除结果。`FindOptions`（`caseSensitive`、`wholeWord`、`regexp`）中省略的选项默认值为 `false`。主根匹配项保持无 `root` 的范围坐标，命名根匹配项在 `anchor` 和 `focus` 上携带 `root`。行内空节点（inline void）会分段文本，匹配不会跨越行内空节点。

`api.move(1 | -1)` 在当前结果中循环切换，不会重新搜索；`api.setActiveIndex(index)` 按从零开始的全局阅读顺序索引切换当前结果（越界时返回 `false`）。`api.matches(options?)` 返回按阅读顺序排列（或指定 `{ root }`）的只读匹配数组，`api.matchAt(point)` 返回覆盖 `point`（含范围端点）的匹配项及其全局索引。

每次更改主文档或任意命名根的提交都会更新结果，即使没有挂载视图，并且只重新搜索受影响根中包含更改的最小块，仅通知受影响根的装饰观察者。不改变任何根内容的提交（例如只更改选区），仅在 schema 改变或抛出错误的更新中搜索后重新搜索。`api.search` 在命名根视图中调用时同样会搜索所有根。

`update.select()` 可以从任意视图在其所属根中选择当前匹配范围并返回是否已选择，视图焦点由调用方负责。`update.replace(replacement)` 以字面文本替换当前匹配项（未设置历史标签时作为单独撤销步骤），并将当前匹配项推进到替换结果之后。`update.replaceAll(replacement)` 在各根内按逆序替换所有可写且属于正文内容的匹配项（作为单次撤销步骤），返回实际修改的数量。两者均拒绝只读视图，并跳过锁定区域、行内空节点与非正文文本叶（例如已删除的建议文本）。

当前结果会跟随其匹配项经过编辑：只要搜索仍在原处找到同一段文本，它就停留在该匹配项上；编辑破坏该匹配项后，它移到在旧匹配项起点之后结束的第一个匹配项，没有则回到第一个匹配项。新查询从第一个匹配项开始。

`FindPluginState` 保存标量字段 `query`、`caseSensitive`、`wholeWord`、`regexp`、`activeIndex`、`error` 和 `version`。`count` 和 `activeMatch` 为只读 store 选择器，从插件私有索引读取。每个 `FindMatch` 包含范围与在无关编辑和块移动后保持稳定的不透明 ID。不改变匹配项、当前结果和 `error` 的提交不会通知 store 订阅者。`FindKit` 通过 `decorate.attributes` 为 `data-find-match` 和 `data-find-active` 属性提供样式。

## 自定义控件

`FindKit` 已在每个 Editable 中显示查找按钮。如需其他打开控件，在对应 Editable 的 `beforeEditable` 或 `afterEditable` 插槽组件中使用
`useFind`。`FindKit` 通过 `wrapRoot` 提供上下文，使控件只操作一个挂载视图，
无需订阅搜索结果：

```tsx
import { useFind } from '@/components/editor/find';

export function FindButton() {
  const { open } = useFind();

  return (
    <button onClick={() => open()} type="button">
      查找
    </button>
  );
}
```

在复制的 `FindKit` 配置中，将 `beforeEditable: FindButton` 添加到
`wrapRoot: FindRoot` 旁边。位于这些插槽之外的 `<Editor>` 同级组件无法获取
该视图的 Find 上下文。

`open(query?)` 打开并聚焦当前视图的搜索栏。指定查询时以该文本作为输入，
否则使用已提交的查询。`close()` 关闭当前视图的搜索栏，清除共享查询，
并将焦点交还当前视图的编辑器。输入草稿保留在本地，直到搜索栏执行延迟查询。

搜索控件直接使用 `editor.plugin(BaseFindPlugin)`。显示结果的控件可以通过
`usePluginStore(BaseFindPlugin, 'count')`、`'activeIndex'` 或 `'error'` 订阅状态。
仅用于打开搜索栏的控件无需订阅结果。

在 Editable 插槽组件中，使用选择和 DOM 命令选择当前结果并聚焦对应视图：

```tsx
import { BaseFindPlugin } from 'platejs/find';
import { useEditor } from 'platejs/react';

const editor = useEditor();

const selectMatch = () => {
  if (editor.plugin(BaseFindPlugin).update.select()) {
    editor.api.dom.focus();
  }
};
```

## 键盘行为

| 按键 | 行为 |
| --- | --- |
| `Mod+F` | 在主编辑器或嵌套 Editable 中打开查找；当前活动视图展开的文本选择会成为初始查询。 |
| `Enter` | 按阅读顺序移到下一个结果并在当前聚焦的呈现内滚动定位。 |
| `Shift+Enter` | 按阅读顺序移到上一个结果并在当前聚焦的呈现内滚动定位。 |
| `Escape` | 关闭查找并把焦点交还仍在文档中的来源编辑器。 |
