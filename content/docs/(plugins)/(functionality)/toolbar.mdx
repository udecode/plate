## Features

- **Fixed Toolbar**: Persistent toolbar above the editor's scrollable content
- **Floating Toolbar**: Contextual toolbar that appears on text selection, docked above the keyboard on touch screens
- **Customizable Buttons**: Add, remove, and reorder toolbar buttons
- **Responsive Design**: Adapts to different screen sizes and content
- **Plugin Integration**: Uses Plate plugins and copied UI components

</PackageInfo>

## Kit usage

<Steps>

### Installation

The fastest way to add toolbar functionality is with the `FixedToolbarKit` and `FloatingToolbarKit`, which include pre-configured toolbar plugins along with their [Plate UI](/docs/installation/plate-ui) components.

<ComponentSource name="fixed-toolbar" />
<ComponentSource name="floating-toolbar" />

- [`FixedToolbar`](/docs/components/fixed-toolbar): Renders a persistent toolbar above the editor
- [`FixedToolbarButtons`](/docs/components/fixed-toolbar): Pre-configured button set for the fixed toolbar
- [`FloatingToolbar`](/docs/components/floating-toolbar): Renders a contextual toolbar on text selection
- [`FloatingToolbarButtons`](/docs/components/floating-toolbar): Pre-configured button set for the floating toolbar

### Add kit

```tsx
import { createEditor } from 'platejs/react';
import { FixedToolbarKit } from '@/components/editor/fixed-toolbar';
import { FloatingToolbarKit } from '@/components/editor/floating-toolbar';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    ...FixedToolbarKit,
    ...FloatingToolbarKit,
  ],
});
```

</Steps>

## Manual usage

<Steps>

### Create plugins

```tsx
import { definePlugin } from 'platejs/react';
import { FixedToolbar } from '@/components/editor/fixed-toolbar';
import { FixedToolbarButtons } from '@/components/editor/fixed-toolbar';
import { FloatingToolbar } from '@/components/editor/floating-toolbar';

const fixedToolbarPlugin = definePlugin('fixedToolbar', {
  slots: {
    beforeContainer: () => (
      <FixedToolbar>
        <FixedToolbarButtons />
      </FixedToolbar>
    ),
  },
});

const floatingToolbarPlugin = definePlugin('floatingToolbar', {
  slots: {
    caret: () => <FloatingToolbar />,
  },
});

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    fixedToolbarPlugin,
    floatingToolbarPlugin,
  ],
});
```

- `slots.beforeContainer`: Renders [`FixedToolbar`](/docs/components/fixed-toolbar) before the editor scroll container
- `slots.caret`: Renders [`FloatingToolbar`](/docs/components/floating-toolbar) as an overlay after the editor, on the view that holds the caret

Place the editor container in an `EditorFrame`. The fixed toolbar and scroll
container then occupy separate rows inside the same bounded layout.

```tsx
<EditorFrame className="h-[650px]">
  <EditorContainer>
    <Editor />
  </EditorContainer>
</EditorFrame>
```

The floating toolbar hides when its text scrolls out of view in the window or
in a scroll area that clips the toolbar, and shows again when the text scrolls
back. A scroll area that does not clip the toolbar does not hide it, such as a
wide code block or a static scroll panel when the toolbar is positioned against
an element outside the panel.

On a touch screen, the floating toolbar docks as a bar along the bottom of the
visible page, above the on-screen keyboard, and shows while the editor has
focus. A phone opens its own Copy and Paste menu above the selection, and a page
cannot move that menu, so a toolbar at the selection and that menu would cover
each other. When the bar would cover the caret, it scrolls the caret above itself. A
screen counts as touch when its primary pointer is coarse, as the
`(pointer: coarse)` media query reports; a mouse or trackpad screen keeps the
floating toolbar at any width.

### Act where the caret is

A nested view, such as the text of a [board](/docs/board) note, is an Editable
of its own inside the page's Editable. Where a toolbar renders decides the view
it acts on:

- Outside every editing area, such as in `beforeContainer` where the fixed
  toolbar renders, `useEditor()` returns the editor of the root that holds the
  caret. With the caret in a note, the copied fixed toolbar's mark buttons
  change the note.
- A plugin's `caret` slot renders after the Editable and follows the caret into
  the views mounted inside its editing area. The copied floating toolbar, link
  toolbar and AI menu render there, so they open beside selected note text.
- Inside an editing area, every other slot, such as `afterEditable`, keeps that
  area's view.

```tsx
import { definePlugin } from 'platejs/react';

const FloatingToolbarPlugin = definePlugin('floatingToolbar', {
  slots: { caret: () => <FloatingToolbar /> },
});
```

In the `caret` slot, `useEditor()`, `useEditableRef()`, `useEditorFocused()`
and `useFocusedLast()` answer for the view that holds the caret while that view
is mounted inside the slot's editing area, and for the slot's own view
otherwise. So a header `EditorContent`'s floating toolbar stays on the header
while the caret is in the body.

### Creating custom button

This example shows a button that inserts custom text into the editor.

```tsx
import { useEditor } from 'platejs/react';
import { CustomIcon } from 'lucide-react';
import { ToolbarButton } from '@/components/editor/toolbar';

export function CustomToolbarButton() {
  const editor = useEditor();

  return (
    <ToolbarButton
      onClick={() => {
        // Custom action
        editor.update((tx) => {
          tx.text.insert('Custom text');
        });
      }}
      tooltip="Custom Action"
    >
      <CustomIcon />
    </ToolbarButton>
  );
}
```

### Creating mark button

For toggling marks like bold or italic, you can use the [`MarkToolbarButton`](/docs/components/mark-toolbar-button) component. It simplifies the process by handling the toggle state and action automatically.

This example creates a "Bold" button.

```tsx
import { BoldIcon } from 'lucide-react';
import { BoldPlugin } from 'platejs/react';

import { MarkToolbarButton } from '@/components/editor/mark-toolbar-button';

export function BoldToolbarButton() {
  return (
    <MarkToolbarButton plugin={BoldPlugin} tooltip="Bold">
      <BoldIcon />
    </MarkToolbarButton>
  );
}
```

- `plugin`: Specifies the mark plugin to toggle (for example, `BoldPlugin`).
- `tooltip`: Provides a helpful tooltip for the button.
- `MarkToolbarButton` adds the plugin's own shortcut to the tooltip, such as
  `Bold (⌘B)` on a Mac and `Bold (Ctrl+B)` elsewhere, and sets
  `aria-keyshortcuts` from it. A rebound shortcut shows its new keys.
- `MarkToolbarButton` reads mark state and handles toggling directly in the component.

### Turn into toolbar button

The [`TurnIntoToolbarButton`](/docs/components/turn-into-toolbar-button) provides a dropdown menu for leaf formats and structural block actions.

<ComponentSource name="turn-into-toolbar-button" />

Each item calls its feature directly. Keep mutually exclusive text, heading, and list formats in the radio group. Render wrappers and layouts as separate actions with their own selection checks.

```tsx
const quote = editor.plugin(BaseBlockquotePlugin);

if (quote.installed) {
  editor.update((tx) => {
    tx.plugin(BaseBlockquotePlugin).toggle();
  });
}
```

### Insert toolbar button

The [`InsertToolbarButton`](/docs/components/insert-toolbar-button) provides a dropdown menu to insert various elements (blocks, lists, media, inline elements).

<ComponentSource name="insert-toolbar-button" />

To add an insertable item, define its typed operation in `getGroups`. The local `value` identifies the menu item; it does not dispatch the edit.

```tsx
{
  icon: <Heading2Icon />,
  label: 'Heading 2',
  value: 'heading-2',
  onSelect: () => {
    const heading = editor.plugin(BaseHeadingPlugin);

    if (!heading.installed || editor.read.view.isReadOnly()) return;

    editor.update((tx) => {
      insertBlock(tx, {
        matches: (block) =>
          !block.listType &&
          block.type === heading.schema.type &&
          block.level === 2,
        insert: (options) => {
          tx.plugin(BaseHeadingPlugin).insert({ level: 2 }, options);
        },
      });
    });
  },
}
```

## Plugins

### `FixedToolbarKit`

Plugin that renders a fixed toolbar before the editor scroll container.

<API name="FixedToolbarKit">
<APIOptions>
  <APIItem name="slots.beforeContainer" type="ContainerSiblingComponent">
    Renders the fixed toolbar before the editor scroll container. Contains FixedToolbarButtons by default.
  </APIItem>
</APIOptions>
</API>

### `FloatingToolbarKit`

Plugin that renders a floating toolbar that appears on text selection, or a bar above the keyboard on touch screens.

<API name="FloatingToolbarKit">
<APIOptions>
  <APIItem name="slots.caret" type="EditableSiblingComponent">
    Renders the floating toolbar as an overlay after the editor, on the view that holds the caret. Contains FloatingToolbarButtons by default.
  </APIItem>
</APIOptions>
</API>
