## Features

- Opens with `Mod+F` and seeds the query from an expanded editor selection.
- Highlights every match without writing marks into the document or history.
- Finds a match that runs across text leaves and inline elements within one
  block. Find searches text placed directly beside a block on its own.
- Moves between results with `Enter`, `Shift+Enter`, or the arrow buttons.
- Updates the results after each document change. Typing or formatting inside a
  block searches only that block again, and only text whose highlights changed
  repaints.
- Keeps the active result on its match through edits.
- Opens independently in each mounted editor view, with `useFind` for custom controls.

</PackageInfo>

## Installation

```bash
npx shadcn@latest add @plate/find
```

## Usage

Install `FindKit` with the rest of your editor plugins:

```tsx
import { createEditor } from 'platejs/react';

import { FindKit } from '@/components/editor/find';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    ...FindKit,
  ],
});
```

`BaseFindPlugin` owns the current query, matches, navigation and transient
decoration data. `FindKit` supplies the shortcut, deferred input and accessible
search bar. Its configured `decorate.attributes` supplies ordinary and active
match styling. Each mounted Editable owns its open bar, draft, focus and scroll
requests. Views of the same editor share committed queries and results; opening
one bar does not open another. Open bars follow the committed query when they
have no pending draft. Only the focused bar scrolls its view. Detaching a view
preserves the shared search. Search state stays outside the document and history.

## Search API

Use the headless feature for search without the copied bar:

```ts
import { createEditor } from 'platejs';
import { BaseFindPlugin } from 'platejs/find';

const editor = createEditor({ plugins: [BaseFindPlugin] });
const find = editor.plugin(BaseFindPlugin);

find.api.search('example');
find.api.move(1);
find.store.get('matches');
find.store.get('activeMatch');
find.update.select();
```

`api.search(query)` applies a case-insensitive literal query. An empty query
clears the results. `api.move(1 | -1)` wraps through the current results without
searching again. Every commit that changes the main document updates the
results, including when no view is mounted. It searches again only the smallest
part of the document that holds its changes, such as the paragraph the user
types in. Adding or removing a top-level block, or changing two top-level blocks in
one update, searches the whole document. A commit that leaves the main document
unchanged, such as a selection change or an edit in a named root, searches only
when the results went stale: after a schema change, after the app writes
`matches` to the store, or after a search inside an update that threw. The
query changes only through `api.search`; a `query` written to the store starts
no search. `api.search` searches the main document, even inside the `update` of
a named root's view. `update.select()` selects the current range in the main
document and returns whether it did. It returns `false` when no result exists or
when a named root's view calls it, because matches are main-document ranges.
View focus remains the caller's responsibility.

The active result follows its match through edits. It stays on that match while
the search still finds the same text there. When an edit breaks the match, the
active result moves to the first match that ends after where the old one
started, or wraps to the first match. A new query starts on its first match.
Writing `activeIndex` to the store picks the active result as `api.move` does,
and the pick follows its match through later edits. An active result picked or
searched for inside `editor.update` jumps to a new match typed right before it
in a later commit. Inside an `editor.update` that has already changed the
document, a write that picks another result applies its index to the results
Find publishes when that update commits. A store write that leaves the active
result as it was, such as one that sets only `error`, keeps it on its match.

`FindPluginState` contains `query`, immutable `matches`, `activeIndex` and
`error`. The `count` and `activeMatch` store selectors derive current results.
Each `FindMatch` contains a range and an opaque ID that stays the same when a
block moves above the match. A commit that leaves every match, the active result
and `error` as they were notifies no store subscriber and keeps the same
`matches` array. Match data is transient and never stored as document marks.
Custom renderers can style `data-find-match` and `data-find-active` attributes.

## Custom controls

Use `useFind` in a component rendered by that Editable's `beforeEditable` or
`afterEditable` slot. `FindKit` supplies the context through `wrapRoot`, so a
custom control addresses one mounted view without subscribing to search results:

```tsx
import { useFind } from '@/components/editor/find';

export function FindButton() {
  const { open } = useFind();

  return (
    <button onClick={() => open()} type="button">
      Find
    </button>
  );
}
```

In the copied `FindKit` configuration, add `beforeEditable: FindButton` alongside
`wrapRoot: FindRoot`. A sibling of `<Editor>` outside those slots does not have
the exact view's Find context.

`open(query?)` opens and focuses this view's bar. An explicit query becomes its
input; otherwise it uses the committed search query. `close()` closes this
view's bar, clears the shared query and returns focus to this view's editor.
Typing stays local until the bar applies its deferred query.

Search controls use `editor.plugin(BaseFindPlugin)` directly. Controls that
display results can subscribe with `usePluginStore(BaseFindPlugin, 'count')`,
`'activeIndex'`, or `'error'`. Opening controls do not need these subscriptions.

To select a result and focus the current view from an Editable slot, call the
existing selection and DOM commands:

```tsx
import { BaseFindPlugin } from 'platejs/find';
import { useEditor } from 'platejs/react';

const editor = useEditor();

const selectMatch = () => {
  if (editor.plugin(BaseFindPlugin).update.select()) {
    editor.api.dom.focus();
  }
};
```

## Keyboard behavior

| Key | Behavior |
| --- | --- |
| `Mod+F` | Open Find. An expanded selection becomes the initial query. |
| `Enter` | Move to the next result. |
| `Shift+Enter` | Move to the previous result. |
| `Escape` | Close Find and return focus to the editor. |

Find searches text. Document replacement belongs to an app command with its own
selection, history, and collaboration policy.
