## Drafts and acceptance

AI output is a draft until the user accepts it. Streaming does not change the
editor document, selection, or undo history. The copied UI renders insert
previews and edit suggestions at their original targets. Chat generation uses
the review panel.

The operation captures exact selected block identities or the text range.
Unselected blocks between discrete targets remain independent. If a target is
edited or deleted, acceptance reports a conflict. Retry retains the original
target and creates a fresh request identity.

Accept writes the generated content in one history batch. One Undo restores
the preceding document and selection; one Redo reapplies the accepted change.
Discard drops the draft and preserves existing redo history. Stop retains a
partial draft for review and rejects subsequent frames from that request.

## Kit usage

Install the copied AI UI and its configured plugins:

<ComponentSource name="ai" />

```tsx
import { createEditor } from 'platejs/react';
import { AIKit } from '@/components/editor/ai';

const editor = createEditor({
  plugins: [/* your document plugins, */ ...AIKit],
});
```

`AIChatPlugin` supplies request state and acceptance. `MarkdownPlugin` owns
Markdown and MDX conversion. `SuggestionPlugin` supplies edit projections.
`AIPlugin` defines the optional AI text mark.

The kit's `useEditorChat` connects the real AI SDK transport. Each request
carries `requestId` and `ctx`; text, tool, table, comment, and error frames are
bound to that request. Text parts accumulate in stream order. The final frame
is applied before the operation becomes ready.

### Server endpoint

Provide an AI SDK UI message stream from your server:

<ComponentSource name="ai-api" />

The request context contains document children, selection, exact node selection,
block references, table cell references, and the requested tool. Named-root
requests use that root's local document paths. The client retains runtime keys;
the model receives request-local references.

Configure the copied transport with an endpoint and provider settings:

```tsx
import { AIChatTransportPlugin } from '@/components/editor/use-chat';

editor.plugin(AIChatTransportPlugin).store.set({
  chatOptions: {
    api: '/api/ai/command',
    body: { model: 'openai/gpt-4o-mini' },
    demo: false,
  },
});
```

Keep credentials in server environment variables. HTTP and stream errors are
visible failures. A local demonstration can explicitly set `demo: true` to
use the copied sample transport.

## Custom transport

Use cumulative raw source as the input. Never reconstruct it by serializing
preview nodes. The installed Markdown parser and codecs determine the draft.
Complete block prefixes can be retained; syntax with backward dependencies or
unknown remark transforms uses complete parsing.

```tsx
import { AIChatPlugin } from 'platejs/ai/react';

const ai = editor.plugin(AIChatPlugin);
const requestId = ai.api.start({ mode: 'insert', toolName: 'generate' });
ai.api.receive(requestId, 'Hello');
ai.api.receive(requestId, 'Hello **world**');
ai.api.finish(requestId, 'Hello **world**!');

// Call from the user's review actions.
ai.api.accept();
```

`receive` accepts a replacement source snapshot as well as an appended source.
Duplicate snapshots do no work. Frames for stopped, discarded, replaced, or
finished operations are ignored. Report transport failures with
`ai.api.error(requestId, error)`.

## Prompt Templates

### Client Prompting

- `aiChat.api.submit` accepts an `EditorPrompt`: a string, a
  `default`/`selecting`/`nodeSelecting` object, or a function receiving
  `{ editor, isSelecting, isNodeSelecting }`.
- `isSelecting` reports whether the representative range is expanded.
  `isNodeSelecting` reports exact node membership and remains true for selected
  empty nodes whose representative range is collapsed. `nodeSelecting` takes
  precedence over `selecting`.
- `aiChat.read.prompt` resolves that input for the current snapshot.
- `aiChat.read.resolvePlaceholders` expands `{editor}`, `{block}`,
  `{nodeSelection}`, and `{prompt}` with snapshot Markdown.

```tsx
const aiChat = editor.plugin(AIChatPlugin);
const template = aiChat.read.resolvePlaceholders(
  'Rewrite {nodeSelection} using a friendly tone.'
);

aiChat.api.submit('Improve tone', {
  prompt: template,
  toolName: 'generate',
});
```

### Server Prompting

The demo backend in `apps/www/src/app/api/ai/command` reconstructs the editor from `ctx` and builds structured prompts:

- `getChooseToolPrompt` decides whether the request is `generate`, `edit`, or `comment`.
- `getGeneratePrompt`, `getEditPrompt`, and `getCommentPrompt` transform the current editor state into instructions tailored to each mode.
- Server prompt helpers serialize explicit editor snapshots through
  `editor.api.markdown.serialize` and assemble selections, block IDs, and MDX
  tags with `buildStructuredPrompt`.

Augment the payload you send from the client to fine-tune server prompts:

```ts
editor.plugin(aiChatPlugin).store.set({
  chatOptions: {
    api: '/api/ai/command',
    body: {
      model: 'openai/gpt-4o-mini',
      tone: 'playful',
      temperature: 0.4,
    },
  },
});
```

Use `chatOptions.body` for provider settings. Request identity and the captured editor context belong to the operation. Keep provider secrets on the server.

## Operation API

```tsx
const ai = editor.plugin(AIChatPlugin);
const operation = ai.store.get('operation');

ai.api.submit('Rewrite clearly', { mode: 'chat', toolName: 'edit' });
ai.api.stop();
ai.api.retry();
ai.api.accept({ placement: 'below' });
ai.api.discard();
```

| API | Purpose |
| --- | --- |
| `submit(input, { mode?, toolName?, prompt?, options? })` | Capture request context and send through the stored chat adapter. Returns the request identity. |
| `start({ mode?, toolName? })` | Capture targets for a custom text transport. Returns the request identity. |
| `receive(id, source)` | Parse a cumulative raw Markdown source snapshot into the detached draft. |
| `receiveTool(id, toolName)` | Set the request's interpretation to generate, edit, or comment. |
| `receiveTable(id, { ref, content })` | Stage Markdown content for a request-local table cell reference. |
| `receiveComment(id, { id, blockRef, content, comment })` | Stage feedback on the quoted text in a referenced block. |
| `finish(id, source?)` | Apply the optional final snapshot and mark the draft ready. |
| `error(id, error)` | Expose a failure for the matching active request. |
| `stop()` | Stop transport and retain the partial draft. |
| `retry()` | Regenerate against the retained target with a fresh identity. |
| `accept({ placement? })` | Commit a ready draft once. `placement` is `replace` or `below`; insert mode appends after a nonempty target. Returns success. |
| `discard()` | Close review and release the draft. |
| `show()`, `hide()`, `reset()` | Control the menu and clear pending state. |

`operation` is null or a read-only snapshot with `id`, `status`, `source`,
`value`, `preview`, `targets`, `root`, `partial`, `comments`, and optional
`error`. `value` contains generated blocks; `preview` contains presentation
nodes, including edit suggestions. Use `status` (`streaming`, `ready`, or
`error`) for loading and review controls.

Render `operation.preview` with `PlateStatic` and an explicit static renderer
configuration. The editor supplies installed schema and codec behavior; the
immutable `value` prop supplies displayed content. See [Static rendering](/docs/static).

### Tables and comments

Table responses address request-local cell references and stage cell children.
Acceptance validates those cells and preserves other cells. Comment responses
stage ranges and feedback without writing document marks or discussion records.
Acceptance writes comment marks in the editor batch, then invokes
`onCommentsAccepted` with the accepted comments. The copied discussion owner
stores those records. Document Undo removes the marks; discussion storage has
its own persistence lifecycle.

### Prompt reads and selectors

`ai.read.markdown`, `commentRange`, `prompt`, and `resolvePlaceholders` read
current editor context. `ai.selectors.lastAssistantMessage` reads the stored
chat adapter. Use `createAIChatAdapter` to bridge AI SDK helpers to that adapter.
