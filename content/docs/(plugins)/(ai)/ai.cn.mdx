## 草稿与接受

AI 输出在用户接受之前属于独立草稿。流式预览不修改编辑器正文、选区或撤销历史。复制的 UI 在原目标位置显示插入预览和编辑建议；聊天生成结果显示在审阅面板中。

操作保存精确的区块身份或文本范围。离散选区之间未选中的区块保持独立。目标被修改或删除时，接受操作报告冲突。重试保留原目标，并创建新的请求标识。

接受通过一个历史批次写入生成内容。一次撤销恢复此前的正文和选区，一次重做重新应用结果。丢弃只清除草稿，保留已有重做历史。停止保留可审阅的部分结果，并忽略该请求后续到达的数据。

## 使用套件

<ComponentSource name="ai" />

```tsx
import { createEditor } from 'platejs/react';
import { AIKit } from '@/components/editor/ai';

const editor = createEditor({
  plugins: [/* 文档插件，*/ ...AIKit],
});
```

`AIChatPlugin` 管理请求状态和接受操作。`MarkdownPlugin` 负责 Markdown 与 MDX 转换。`SuggestionPlugin` 提供编辑建议投影。`AIPlugin` 定义可选的 AI 文本标记。

套件中的 `useEditorChat` 连接真实 AI SDK 传输。请求携带 `requestId` 和 `ctx`；文本、工具、表格、评论和错误数据都绑定到对应请求。多个文本部分按流中顺序累积。最后的数据应用完成后，操作才进入可接受状态。

服务端返回 AI SDK UI 消息流：

请求上下文包含正文、文本选区、精确区块选区、区块引用、表格单元格引用和工具名称。命名根请求使用该根内的局部路径。客户端保留运行时身份，模型只接收请求内引用。

```tsx
import { AIChatTransportPlugin } from '@/components/editor/use-chat';

editor.plugin(AIChatTransportPlugin).store.set({
  chatOptions: {
    api: '/api/ai/command',
    body: { model: 'openai/gpt-4o-mini' },
    demo: false,
  },
});
```

密钥保存在服务端环境变量中。HTTP 和流错误会显示为失败。仅本地演示需要样例传输时，显式配置 `demo: true`。

## 自定义传输

传入累积的原始 Markdown 文本，不要通过序列化预览节点重建输入。草稿沿用已安装的 Markdown 解析器与编解码器。完整区块前缀可被保留；存在向前引用依赖或未知 remark 转换时使用完整解析。

```tsx
import { AIChatPlugin } from 'platejs/ai/react';

const ai = editor.plugin(AIChatPlugin);
const requestId = ai.api.start({ mode: 'insert', toolName: 'generate' });
ai.api.receive(requestId, 'Hello');
ai.api.receive(requestId, 'Hello **world**');
ai.api.finish(requestId, 'Hello **world**!');

// 在用户接受结果时调用。
ai.api.accept();
```

`receive` 支持追加与替换源快照。重复快照不产生工作。停止、丢弃、替换或完成的操作会忽略迟到数据。通过 `ai.api.error(requestId, error)` 报告传输失败。

## 提示词

`submit` 接受字符串、`default` / `selecting` / `nodeSelecting` 配置，或接收 `{ editor, isSelecting, isNodeSelecting }` 的函数。精确区块选区优先匹配 `nodeSelecting`，包括内容为空的选中区块。

```tsx
editor.plugin(AIChatPlugin).api.submit('', {
  prompt: {
    default: 'Continue after {block}',
    selecting: 'Rewrite {selection} clearly',
    nodeSelecting: 'Rewrite {nodeSelection} clearly',
  },
  toolName: 'generate',
});
```

`ai.read.prompt` 根据当前选区选择提示词。`ai.read.resolvePlaceholders` 用 Markdown 展开 `{editor}`、`{block}`、`{nodeSelection}` 和 `{prompt}`。服务端参考复制的 `ai-api`，根据请求上下文选择生成、编辑或评论工具。

## 操作 API

| API | 用途 |
| --- | --- |
| `submit(input, { mode?, toolName?, prompt?, options? })` | 保存上下文，通过聊天适配器发送请求并返回请求标识。 |
| `start({ mode?, toolName? })` | 为自定义文本传输保存目标并返回请求标识。 |
| `receive(id, source)` | 将累积源快照解析为独立草稿。 |
| `receiveTool(id, toolName)` | 指定生成、编辑或评论工具。 |
| `receiveTable(id, { ref, content })` | 暂存引用单元格的 Markdown 内容。 |
| `receiveComment(id, { id, blockRef, content, comment })` | 暂存引用区块中指定文本的评论。 |
| `finish(id, source?)` | 应用可选的最终快照，进入可接受状态。 |
| `error(id, error)` | 显示匹配请求的错误。 |
| `stop()` | 停止传输并保留部分草稿。 |
| `retry()` | 保留原目标，以新标识重新生成。 |
| `accept({ placement? })` | 接受一次草稿并返回是否成功。位置为 `replace` 或 `below`；插入模式在非空目标后追加。 |
| `discard()` | 关闭审阅并释放草稿。 |
| `show()`、`hide()`、`reset()` | 控制菜单并清除待处理状态。 |

`ai.store.get('operation')` 返回 null 或只读快照，包含 `id`、`status`、`source`、`value`、`preview`、`targets`、`root`、`partial`、`comments` 及可选的 `error`。`value` 是生成区块，`preview` 是包含编辑建议的展示节点。`status` 为 `streaming`、`ready` 或 `error`。

使用 `PlateStatic` 的不可变 `value` 与显式静态渲染配置展示草稿。编辑器提供已安装的 schema 与编解码行为。参见[静态渲染](/docs/static)。

### 表格与评论

表格结果通过请求内引用暂存单元格子节点。接受时验证目标单元格，并保留其他单元格。评论先暂存范围与反馈，不写入正文标记或讨论记录。接受在编辑器批次中写入评论标记，然后调用 `onCommentsAccepted`。复制的讨论组件负责存储记录；正文撤销会移除标记，讨论存储拥有独立的持久化生命周期。

### 读取与选择器

`ai.read.markdown`、`commentRange`、`prompt` 和 `resolvePlaceholders` 读取当前编辑器上下文。`ai.selectors.lastAssistantMessage` 读取聊天适配器。使用 `createAIChatAdapter` 连接 AI SDK 辅助对象。
