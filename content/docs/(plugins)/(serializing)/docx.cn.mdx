## 功能

- 规范化从 Microsoft Word 粘贴的 HTML 和 RTF
- 将受限的 DOCX 包导入为完整的编辑器文档
- 将支持的 Word 修订和批注范围保留为结构化数据
- 将编辑器的一次快照导出为 accepted、proposed 或 review DOCX

## 从 Word 粘贴

`WordPastePlugin` 在已安装的 Plate codec 解码内容前内联 CSS，并规范化 Word HTML 和 RTF。

```tsx title="components/editor/editor.tsx"
import { WordPastePlugin } from "platejs/docx/paste";
import { createEditor } from "platejs/react";

const editor = createEditor({
  plugins: [WordPastePlugin],
});
```

剪贴板粘贴不会上传嵌入图片，也不会保留 Word 表格布局。请在对应的媒体和表格功能中配置目标策略。

## 导入 DOCX 文件

`importDocx` 读取 `Blob` 或 `ArrayBuffer`，但不会修改编辑器。导入成功后替换完整编辑器值，以保持文档元数据、命名根和 authored review 状态一致。

在已挂载的 React 控件中，使用 `useModelEditor()` 获取完整编辑器。
`useEditor()` 返回 provider 选中的已挂载命令视图，其根和 authored view 属于该视图。

```bash
npm install platejs jszip mammoth validator
```

```tsx title="components/editor/import-docx.tsx"
import { importDocx } from "platejs/docx/import";
import { createEditor } from "platejs/react";
import { BaseEditorKit } from "@/components/editor/plugins-static";

const editor = createEditor({
  plugins: BaseEditorKit,
});

export async function importFile(file: File) {
  const result = await importDocx(file, {
    plugins: BaseEditorKit,
  });

  if (!result.ok) {
    return { diagnostics: result.diagnostics };
  }

  editor.update.value.replace(result.document);

  return {
    comments: result.comments,
    diagnostics: result.diagnostics,
  };
}
```

文件、包、限制或解码的预期失败返回 `{ ok: false, diagnostics }`，且不包含文档。中止操作以 signal 的 reason 拒绝。无效选项和内部不变量错误会抛出异常。

### 有损文件

`importDocx` 默认拒绝内容损失。导入会省略图片、脚注、尾注、含有内容的页眉和页脚，以及没有已安装 HTML mapping 解码的复选框的方框。文本框只有在文件同时以转换器能读取的 VML 绘制它时才保留文字，且两种情况都会报告。上述每种损失都会使导入失败并返回错误 diagnostic，结果为 `ok: false`。HTML 清理器连同读者可见内容一起移除的标记、没有完整范围的批注，以及已安装插件无法保留的修订也是如此。设置 `lossPolicy: "allow"` 可以导入文件的其余内容，并以警告形式接收相同的损失：

```tsx
const result = await importDocx(file, {
  lossPolicy: "allow",
  plugins: BaseEditorKit,
});
```

HTML mapping 丢失的属性或样式在两种策略下都只返回警告，不会使导入失败。它返回一个 `property-dropped` 警告，其 `feature` 指出丢失了什么，例如 `data-list-type`，`count` 是丢失它的 run、段落或单元格数量。mapping 未指明属性的损失按消息计数，因此目标地址不同的被拒链接各自发出一个警告。清理器拒绝链接的目标地址时，链接会保留文字。除非该地址可能运行脚本，否则链接会以同样方式发出警告。例如，未安装列表插件时导入的 Word 编号列表会以段落保留文字，并以这种方式报告其列表属性。如果两个已安装的 mark 不能用于同一段文字，schema 适配会保留其中一个，并改为返回有损的 `schema-repair` diagnostic，它遵循损失策略。

```tsx
for (const diagnostic of result.diagnostics) {
  if (diagnostic.code === "property-dropped") {
    console.warn(diagnostic.feature, diagnostic.count);
  }
}
```

每个 `unsupported-content` diagnostic 都声明 `impact`。`lossless` 的 diagnostic 不会使导入失败。它报告导入移除或展开、但保留了读者可见内容的标记，例如智能标记、内容控件、可能运行脚本的链接目标地址，或 mapping 添加的 `<style>` 元素。有一种 `lossless` 报告仍会丢失内容。导入会省略自定义 XML 元素中的文字。

导入既不保留也不报告以下内容：

- 转换器不读取的格式，无论是直接格式还是来自 Word 样式，例如下划线、文字颜色和背景色、突出显示、对齐方式、字号、字体和行高；
- 隐藏文字，会作为普通文字导入；
- 名称不以 `word/header` 或 `word/footer` 开头的页眉或页脚部件；
- 未安装对应插件时导入的标题、链接和表格，会变成纯文字。

带有自定义标记的脚注或尾注引用，例如 `*`，会把该标记留在文字中。导入只对它报告的注释种类从文字中省略注释。它只根据名为 `word/footnotes.xml` 或 `word/endnotes.xml` 的部件报告该种类。其他名称部件中的注释会连同标记留在文字中，且不会报告。如果文件中还有同一种类、含有注释的默认名称部件，导入也会省略重命名部件中的注释，并归入默认名称部件的报告。对于名称以 `word/header` 或 `word/footer` 开头但不是 XML 的文件条目，例如图片，导入会将其报告为丢失的页眉或页脚。空的页眉或页脚段落只要设置了边框、底纹或编号，就算作内容。该设置可以来自段落本身、其样式或文档默认值，即使它不绘制任何内容也算，例如值为 `none` 的边框。复选框还会丢失 Word 存放在与方框同一个 `w:t` 元素中的标签文字，归入同一条报告。

转换器自身的消息，例如关于无法转换的符号的消息，以 `converter-message` 警告返回，不会使导入失败。

### 保留源文件用于后续导出

同一个编辑器需要导入、编辑并导出 Word 文件时，请设置 `retainSource: true`。导入成功后会返回 `source`：精确导出可以原样返回该包时为 `DocxSource`，否则为 `null`，同时返回 `source-unavailable` 警告，指出第一个无法接纳的部件。应用负责保存 source，将它传给 `exportDocx`，并在文档关闭或被其他文件替换时调用 `dispose()`。

```tsx title="components/editor/docx-roundtrip.tsx" showLineNumbers
import { exportDocx } from "platejs/docx/export";
import { importDocx } from "platejs/docx/import";

const imported = await importDocx(file, {
  plugins: BaseEditorKit,
  retainSource: true,
});

if (!imported.ok) return imported.diagnostics;

editor.update.value.replace(imported.document);

const exported = await exportDocx(editor, {
  projection: "review",
  source: imported.source,
});

imported.source?.dispose();
```

精确导出只接纳一组封闭的被动包内容：

- 位于 `word/document.xml` 的主文档，以及样式、设置、编号、字体和主题；
- 页眉、页脚、脚注、尾注和批注；
- 核心、扩展和自定义文档属性，以及缩略图；
- 通过内部关系引用的 AVIF、BMP、GIF、JPEG、PNG 和 WebP 图片；
- 目标为绝对地址且满足导航下限的超链接。

`PAGE` 是唯一可识别的字段指令。其他任何部件、关系、标记命名空间、字段指令或 XML 处理指令都会使 `source` 为 `null`，包括不安全或相对的超链接、其他外部关系、宏、ActiveX 控件、OLE 对象、导入的 HTML 块、外部模板、Plate 审阅部件以外的自定义 XML 数据，以及 SVG 或 EMF 图片。`source` 为 `null` 并不表示导入丢失了内容；没有 source 时，导出会从编辑器内容生成文档。

`DocxSource` 保留已通过检查的压缩包，以及不可变的文档、批注、schema 和限制对应关系。它不会保留展开后的 ZIP 条目或编辑器引用。`dispose()` 可重复调用。已经取得 source 的导出可以在释放后完成；后续导出会返回 `source-unavailable` diagnostic，并从编辑器内容生成新的 DOCX。

### 导入批注

导入器返回批注格式事实，但不会写入应用的批注存储。`DocxComment` 可以包含富文本 Plate `body`、指向返回文档的精确 `target.range`、Word 作者与日期、durable ID、parent ID 和 resolved 状态。应用需要显式映射自己的用户和批注 ID。

### 导入修订

要保留 Word 修订，请在 `plugins` 中包含 `platejs/authored` 的 `AuthoredPlugin`。支持的插入、删除、移动、run property 和 paragraph property 修订随后会成为待处理的 authored change。每个 change 以 `docx-<id>` 形式使用其 Word 修订的 ID，并使用其作者和日期。作者缺失或日期无效时返回 `lossy-content` 警告，日期无效时以时间 0 导入。

未安装 `AuthoredPlugin`，或修订无法映射到已安装 schema 时，导入器会把修订展平为 proposed 文档，并返回 `lossy-content` 警告。

Plate 为审阅导出的文件还包含 Plate 的审阅部件。导入器会恢复导出后 Word 段落未变化的每个被审阅 block，并保留其原始 change ID 和文档的审阅记录。段落在 Word 中被编辑过的 block 按其 Word 修订导入，并返回警告。

### 导入列表编号

Word 中带编号和项目符号的段落会转换为列表项，每项加入其 Word 编号定义对应的列表。Word 将同一定义的所有实例在每个层级按同一序列计数，因此列表会跨过其他段落和实例继续编号，不同定义的交错列表各自保持编号。某层级在其 `lvlRestart` 指定的层级或更浅层级的段落之后重新编号，默认是紧邻的上一层级。实例的起始值覆盖只在该实例于该层级的第一个段落处重置一次该层级。该项导入时以覆盖值作为 `listRestart`，其后的项在此基础上继续计数，因此插入的项会像 Word 一样为后续项重新编号。每项的 `listLevels` 包含其定义的层级起始值、`lvlRestart` 规则和层级文本，并应用其实例对格式和层级文本的覆盖。Word 会忽略层级覆盖中的起始值和 `lvlRestart`，导入也是如此。若段落的实例将其层级显示为项目符号，该段落导入为项目符号项且不参与计数。

## 导出 DOCX 文件

`exportDocx` 在异步渲染前只捕获一次编辑器。必须显式传入可见投影。

```bash
npm install platejs color-name html-to-vdom jszip juice katex@0.16.22 mime-types virtual-dom xmlbuilder2
```

```tsx title="components/editor/export-docx.tsx"
import { exportDocx } from "platejs/docx/export";
import { createEditor } from "platejs/react";
import { BaseEditorKit } from "@/components/editor/plugins-static";
import { DOCX_EXPORT_STYLES } from "@/components/editor/docx-export";

const editor = createEditor({ plugins: BaseEditorKit });

export async function downloadEditorDocx() {
  const result = await exportDocx(editor, {
    orientation: "portrait",
    projection: "proposed",
    stylesheet: DOCX_EXPORT_STYLES,
    title: "Document",
  });

  if (!result.ok) return result.diagnostics;

  const url = URL.createObjectURL(result.blob);
  const link = document.createElement("a");
  link.href = url;
  link.download = "document.docx";
  document.body.append(link);
  link.click();
  link.remove();
  URL.revokeObjectURL(url);

  return result.diagnostics;
}
```

`accepted` 忽略待定变更，`proposed` 应用待定变更，`review` 写入 Word tracked-change 标记。Accepted 与 proposed 导出会警告它们决定的待处理 change。

Review 文件包含 Word 显示的内容：文本、批注，以及带作者信息的修订。它还会在 custom XML part 中保存每个含有待处理 change 的顶层 block 以及文档的审阅记录，并用书签把每个 block 绑定到其 Word 段落。导入该文件时，Word 未修改的 block 会被恢复，详见[导入修订](#导入修订)。命名根和文档元数据不会写入文件。需要保留它们时，按 [Serializing](/docs/serializing) 所述，把 `editor.read.value()` 以 JSON 形式与文件一起保存。

### 内容损失

`exportDocx` 默认拒绝内容损失。图片无法嵌入、传入的批注没有可表示的范围，或节点在 `presentation` 中没有绘制方式时，结果为 `ok: false`，并以错误 diagnostic 报告该损失。设置 `lossPolicy: "allow"` 可以下载文件，并以警告形式接收相同的损失：

```tsx
const result = await exportDocx(editor, {
  comments,
  lossPolicy: "allow",
  projection: "review",
});
```

命名根、文档元数据、被移除的链接目标，以及 DOCX 无法表示的其他属性，在两种策略下都只返回警告。`accepted` 导出会省略所标注内容全部被该投影排除的批注，并返回警告；这与 Word 拒绝被批注的修订建议时的行为一致。

### 列表

每个 Plate 列表导出为一个 Word 列表。它的 `listLevels` 提供列表各层级的起始值、`lvlRestart` 规则和层级文本。设置了 `listRestart` 的项，或 Word 在该位置无法得出其编号的项，会得到一个只属于它的编号实例，覆盖该层级的起始值，与 Word 的“重新编号”写法一致。其后的项在列表自身的实例中继续计数。这样 Word 和再次导入后显示的编号与编辑器一致，重新编号也保留在该项上。Word 每个列表层级只绘制一种标记样式，因此 `listStyle` 与该层级第一项不同的项会沿用第一项的样式，并在两种策略下都返回 `list-marker` 警告。Word 列表的每个层级随其第一项为编号或无序，且导出器为每个列表只写入一组层级规则。项目符号和任务项共用无序层级，每个任务项都使用文档共享的任务编号。因此位于无序层级的编号项，或位于编号层级的无序项，在 Word 中不属于其列表，`listLevels` 与列表第一项不同的项会沿用第一项的规则。类型不一致会返回 `list-structure` 警告；`listLevels` 与列表中第一个编号项或任务项不同的编号项或任务项也会返回该警告，并在 `lossPolicy: 'reject'` 下使导出失败。Markdown 和 AI 输出的项目符号没有 `listId`，这样的项目符号不参与类型检查，因为 Markdown 的项目符号列表不会和编号列表共用一个列表。Word 没有仅在项开启其层级时才生效的起始值，每个层级的起始值取自列表第一项，默认为 1。编号项或任务项的 `listStart` 若与列表中第一个编号项或任务项给出的该层级起始值不同，会导出其显示的编号，并在两种策略下都返回 `list-start` 警告。项目符号不参与层级规则和起始值的检查，因此位于列表开头的项目符号会把它的层级规则和起始值交给 Word，而不给出警告。

作为列表项的标题或引用块保留其标题样式和书签或引用边框，编号和缩进取自所在列表层级。表格单元格中的区块按正文的方式导出，嵌套表格及其图片的宽度不超过所在单元格。

### 链接和图片

只有目标为绝对地址且满足导航下限（例如 `https:` 或 `mailto:`）时，导出才会写入链接目标；`#introduction` 这类书签链接会写成 Word 锚点。不安全的目标，以及在 Word 文件中没有文档基址的相对链接，会保留文本，但不写入目标。

图片以 PNG、JPEG、GIF 或 BMP 格式嵌入。设置 `allowRemoteImages: true` 可以在导出时获取 HTTP(S) 图片。以下图片会被省略，并保留其 alt 文本：

- 来源不安全、为相对地址或为 blob 的图片；
- `allowRemoteImages` 关闭时的远程图片；
- 无法获取的图片；
- 其他格式的图片。

返回生成的文件前，导出会使用与保留 source 相同的被动词汇检查写出的包；超出该范围的输出会被拒绝，并返回 `invalid-package` 错误。未变更的 source-aware 导出直接返回保留的文件，该文件在导入时已通过同一检查。

### 使用源文件导出

传入有效 `source` 时，未改动的 `review` 导出会逐字节返回导入的文件。精确复用要求使用同一个编译 schema、review 文档未改动、批注未传入或完全相同，并且没有传入 `title`、`margins`、`orientation`、`pageSize`、`stylesheet` 或 `fontFamily`。该路径不会重新生成内容，因此 `component` 和 `presentation` 不起作用。

精确检查不通过时，`exportDocx` 会重新生成完整正文。内部关系闭合、可达且无名称冲突时，会保留下列 source 单元：

- 单节文档的页眉和页脚，以及它们引用的图片和超链接；
- 自定义文档属性。

重新生成的包带有自己的核心文档属性，并省略 source 正文 XML、只由正文引用的部件（例如脚注和正文图片）、多节文档的页眉和页脚，以及 source 的核心属性、扩展属性和包缩略图：作者、标题和创建日期等核心属性，统计页数和字数、也包含公司名称等信息的扩展属性，以及展示正文的缩略图。Diagnostic 会说明 source 被重写的原因，并标识每个被省略的 source 部件。链接到正文文本的自定义属性会保留 source 文件中缓存的值，即使编辑已改变该文本。

需要重新生成时，省略 `comments` 表示不生成批注。编辑后若要保留批注，请显式传入应用持有的当前批注。导入的批注范围不会自动重定位。

### 导出批注

传入范围指向编辑器存储文档（即 `editor.read.value()` 返回的值）的批注。导出会在渲染前把这些范围映射到 accepted 或 proposed 输出：

```tsx
const result = await exportDocx(editor, {
  comments,
  projection: "review",
});
```

主文档和富文本批注正文使用同一套静态渲染器。在默认 `lossPolicy` 下，范围不完整的批注会使导出失败；设置 `lossPolicy: "allow"` 时，导出会省略该批注并返回警告。

### Static rendering 与样式

DOCX 包拥有 code block、column、equation、callout、heading 和目录的语义
static mapping。除了元素自身的值（例如 callout 的颜色），它们不设置颜色、
字体或字号。这些由应用的 `stylesheet` 设置，它可以选中：

- `editor-<插件名>`，每个绘制元素上的 class，例如 `.editor-codeBlock`；
- callout 里的 `table > tbody > tr > td`，第一个单元格放图标；
- `[data-docx-preserve-whitespace]`，code block 的文本；
- `[data-empty]`，空公式或空目录的占位文字。

段落、标题等绘制为单个 Word 段落的块，其上下外边距（`pt` 或 `px`）设置它在
Word 中的段前和段后间距。列表、列表项和表格自身的外边距不会写入文件。没有设置
外边距时，由 Word 的段落和标题样式决定间距。

需要不同 wrapper 时可以传入自定义 root `component`。`DOCX_EXPORT_STYLES` 是
registry 可复制的展示预设。

公式导出为由 KaTeX MathML 生成的 Word 公式。转换器尚不支持的写法（如矩阵），会把
TeX 作为文本放进一个 Word 公式里导出。任务列表项，即带 `data-checked` 的
`li`，导出时带 ☑ 或 ☐ 列表符号；导入时把以 ☐、☑ 或 ☒ 绘制的项目符号层级读成任务项，
并保留勾选状态。

live editor 的组件是编辑 UI。把应用的 static kit 作为 `presentation` 传入，
正文和每条批注正文都会用同名插件的 static 组件绘制。没有 static 版本的
插件，其内容会不带组件或 wrapper 导出，并报告一条
`missing-static-presentation` diagnostic；在 `lossPolicy` 下它算作内容损失。

## 格式支持

| 内容                                          | 行为                                                                       |
| --------------------------------------------- | -------------------------------------------------------------------------- |
| 段落、标题、支持的 mark 和 property           | 通过已安装的 HTML mapping 解码，并通过配置的静态渲染器导出                 |
| 列表、链接、书签、行、单元格和 span           | 保留支持的语义结构；省略 Word 布局细节并返回 diagnostic                    |
| Tracked revision                              | `plugins` 包含 `AuthoredPlugin` 时保留支持的 insert、delete、move、run-property 和 paragraph-property change；否则展平并返回 `lossy-content` 警告 |
| 主文档批注                                    | 存在时保留富文本正文、范围、作者/日期、durable ID、回复和 resolved 状态    |
| 导入中的嵌入图片                              | 省略资源并返回 `resource-omitted` diagnostic                               |
| 导出中的链接和图片                            | 写入绝对且满足导航下限的链接，以及 PNG、JPEG、GIF 或 BMP 图片；报告被移除的目标和被省略的图片 |
| 单节文档的页眉和页脚                          | 使用 source 导出时保留安全且闭合的子图，但不映射到编辑器文档。导入时把含有内容的页眉或页脚报告为丢失的内容 |
| 多节页眉和页脚、脚注和尾注                    | 检查并限制对应包部件；编辑 source 后省略并返回 diagnostic。导入时报告为丢失的内容，不绘制任何内容的部件除外，例如只含 Word 分隔线注释或只含一个空的带样式段落的部件 |
| 字段、文本框、形状、图表、SmartArt 和嵌入对象 | 转换可访问时保留纯文本，否则报告不支持或省略的内容                         |
| Plate 命名根和元数据                          | Word 输出会省略并返回 `lossy-content` 警告；保存在 authored JSON 中 |
| 公式                                          | 导出为 Word 公式；转换器不支持该写法时，把 TeX 放进 Word 公式。导入时把 Word 公式读成 `equation` 和 `inlineEquation` 节点，TeX 由公式结构重建；未安装这两个插件时读成 TeX 文本。与批注、修订或文字同处一段，或位于列表项、缩进段落中的行间公式读成行内公式 |
| 任务列表                                      | 以带 `data-checked` 的 `li` 绘制的项导出时带 ☑ 或 ☐ 列表符号；导入时把以 ☐、☑ 或 ☒ 绘制的项目符号层级读成任务项并保留勾选状态 |
| 自定义 Plate、emoji 和媒体节点                | 使用已配置的静态序列化器；不支持的输出返回 diagnostic                      |

## API 参考

### 入口

| API                       | 导入路径              |
| ------------------------- | --------------------- |
| `WordPastePlugin`         | `platejs/docx/paste`  |
| `importDocx` 和导入类型   | `platejs/docx/import` |
| `exportDocx` 和导出类型 | `platejs/docx/export` |

### `importDocx`

```ts
importDocx(
  source: ArrayBuffer | Blob,
  options: DocxImportOptions
): Promise<DocxImportResult>
```

`DocxImportOptions` 必须包含 `plugins`，并可包含 `schema`、
协作式 `signal`、`lossPolicy`、部分 `limits` 覆盖和 `retainSource`。Import 会在
第一次 await 前捕获 detached target，之后不会读取 live editor 或 mutable plugin
store。每个限制都必须是正的安全整数。字面量 `retainSource: true` 会在成功结果中
加入 `source: DocxSource | null`；省略或传入字面量 `false` 时没有该字段。

| 默认限制           |      值 |
| ------------------ | ------: |
| `maxInputBytes`    |  32 MiB |
| `maxEntries`       |   1,024 |
| `maxEntryBytes`    |  32 MiB |
| `maxExpandedBytes` | 128 MiB |
| `maxRelationships` |   4,096 |
| `maxRevisions`     |   2,000 |
| `maxComments`      |   5,000 |
| `maxXmlDepth`      |     128 |
| `maxXmlNodes`      | 500,000 |

成功结果包含 `document`、`comments` 和结构化 `diagnostics`。保留 source 的成功结果还包含 `source`；精确导出无法接纳该包时为 `null`。失败结果只包含 `diagnostics`。

### `DocxSource`

```ts
class DocxSource {
  private constructor();
  dispose(): void;
}
```

只有 `importDocx` 可以创建 `DocxSource`。该对象只能在当前进程中使用，不能序列化或重新绑定。应用重新加载后如需继续使用 source 导出，请保存原始文件并再次导入。

### `exportDocx`

```ts
exportDocx(
  editor: Editor,
  options: DocxExportOptions
): Promise<DocxExportResult>
```

| 选项                    | 类型                                     | 说明                             |
| ----------------------- | ---------------------------------------- | -------------------------------- |
| `projection`            | `'accepted' \| 'proposed' \| 'review'`   | 必填的可见文档投影               |
| `comments`              | `readonly DocxComment[]`                 | 范围指向存储文档的批注记录 |
| `allowRemoteImages`     | `boolean`                                | 获取远程 HTTP(S) 图片并嵌入；默认 `false` |
| `component`             | `React.ComponentType<EditorStaticProps>` | 可选 static editor wrapper       |
| `fontFamily`            | `string`                                 | 文档正文字体；会重新生成未改动的 `source` |
| `lossPolicy`            | `'allow' \| 'reject'`                    | 内容被省略时失败，或以警告返回；默认 `'reject'` |
| `margins`               | `Margins`                                | 以二十分之一磅为单位的页边距     |
| `orientation`           | `'landscape' \| 'portrait'`              | 页面方向                         |
| `pageSize`              | `PageSize`                               | 以二十分之一磅为单位的页面尺寸   |
| `presentation`          | `readonly BasePluginInput[]`             | 绘制正文和批注正文的 static 插件，按插件名匹配 |
| `signal`                | `AbortSignal`                            | 协作式取消信号                   |
| `source`                | `DocxSource \| null`                     | 用于精确或安全导出的 source 对应关系 |
| `stylesheet`            | `string`                                 | 设置 Word 外观的 CSS；会重新生成未改动的 `source` |
| `title`                 | `string`                                 | 文档元数据标题                   |

成功结果包含 `blob` 和结构化 `diagnostics`。失败结果只包含 `diagnostics`。

编辑器的 accepted、proposed 和 review 投影请参阅 [Authored Changes](/docs/authored-changes)。
