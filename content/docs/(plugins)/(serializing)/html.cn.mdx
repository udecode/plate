---
title: HTML
description: 将 semantic HTML 解析为 Plate document 或 slice，并把 Plate document 序列化为 HTML。
---

HTML 转换包含两个方向：

- 将 semantic HTML 解析为完整的 `EditorDocumentValue`，或用于插入的闭合 `ContentSlice`。
- 将 schema-valid Plate document 序列化为 semantic HTML。

浏览器使用 `platejs/html`。Node.js 解析 HTML 时使用
`platejs/html/server`。通过 React component 生成展示 HTML 属于
[`platejs/static`](/docs/static)，不是 semantic interchange。

## 解析 HTML

### 已安装的 editor

安装 `HtmlPlugin` 后，editor API 会复用已编译的 plugin、schema 与 plugin state。

```ts
import { HtmlPlugin } from 'platejs/html';
import { createEditor } from 'platejs';

const editor = createEditor({
  plugins: [BaseParagraphPlugin, BaseBoldPlugin, HtmlPlugin],
});

const result = editor.api.html.parse('<p>Hello <strong>world</strong>.</p>');

if (!result.ok) throw new Error(result.diagnostics[0].message);

editor.update((tx) => tx.value.replace(result.document));
```

`parse` 读取一份完整 HTML document。source 中恰好有一个
`[data-editor="true"]` 元素时，Plate 读取它的 children；没有 marker 时读取
`body`；多个 marker 会返回错误。

插入内容使用 `parseSlice`。它返回闭合、无 root 的 `ContentSlice`，不会把
editor marker 当成完整 document 的权限。

```ts
const result = editor.api.html.parseSlice('<p>Paste me</p>');

if (result.ok) {
  editor.update.slice.replace(result.slice);
  showDiagnostics(result.diagnostics);
}
```

只有 insertion destination 已知后，插入 owner 才会 fit slice。直接解析 HTML
不会虚构 open edge 或 detached root。

### 浏览器中的 detached 转换

没有配置好的 editor 时，直接调用 standalone function，并传入拥有 document
schema 与 HTML mapping 的 plugin。

```ts
import { parseHtml, parseHtmlSlice } from 'platejs/html';

const documentResult = parseHtml(source, { plugins: EditorKit });
const sliceResult = parseHtmlSlice(fragment, {
  plugins: EditorKit,
  lossPolicy: 'allow',
});
```

Standalone function 只为本次调用编译 declaration，完成后丢弃临时 target。它
不会激活 handler、effect 或 React hook。

### Node.js

Node.js 通过 server entrypoint 使用同一棵 parse5 tree 与同一套诊断：

```ts
import { parseHtml } from 'platejs/html/server';

const result = parseHtml(source, { plugins: EditorKit });
```

Node 进程需要解析 HTML 时，安装可选 server DOM peer：

```bash
npm install platejs linkedom
```

不要在 Node.js 中从 `platejs/html` 调用浏览器 parser；该入口会抛出指向
`platejs/html/server` 的环境错误。server entrypoint 只提供 ESM。

浏览器与 server parser 都是 inert 的。Plate 不执行 script、不挂载 tree、不加载
resource、不应用 CSS，也不安装全局 DOM。安全策略会在 feature mapping 之前处理
可执行元素、event attribute、不安全 URL、外部 resource attribute、CSS resource
load 与不安全 foreign content。

## 序列化 HTML

### 已安装的 editor

```ts
const result = editor.api.html.serialize({ projection: 'proposed' });

showDiagnostics(result.diagnostics);
if (result.ok) downloadHtml(result.data);
```

要通过已安装 target 序列化已捕获的 document，请传入 `document`：

```ts
const result = editor.api.html.serialize({
  document: editor.read.value(),
  projection: 'accepted',
});
```

Detached document 使用 standalone function：

```ts
import { serializeHtml } from 'platejs/html';

const result = serializeHtml(document, {
  plugins: EditorKit,
  projection: 'accepted',
});
```

序列化会 assert 输入 document 与选中的 authored projection。无效 model data
属于 programmer 或 persistence boundary 错误，会直接抛出。预期内的格式表达损失
通过 result diagnostics 返回。

`lossPolicy` 默认为 `'reject'`。无法表示的可见内容会返回
`{ ok: false, diagnostics }`，且不包含 `data`。只有调用方明确接受带诊断的 drop、
replacement 或 unwrap 时，才使用 `lossPolicy: 'allow'`。

## Authored content

Semantic HTML 只支持可见的 `accepted` 与 `proposed` projection。它不会嵌入隐藏
Plate document，也不会从 HTML 恢复 review state。

完整 proposal、decision、root 与 metadata 使用 authored JSON 持久化。需要 Word
revision 时使用 DOCX review export。参阅
[Authored Changes](/docs/authored-changes)。

## 定义 HTML mapping

Feature mapping 声明在拥有 node 或 mark 的 plugin 上。constructor 的 `formats`
callback 只接收 `defineFormats` 与静态 schema binding。运行时 mapping callback
接收冻结的 operation state、registry/schema view 与 HTML 专用 `report`，不会接收
live editor 或 store。

```ts
import { definePlugin } from 'platejs';

const CalloutPlugin = definePlugin('callout', {
  formats: ({ defineFormats, schema: { type } }) =>
    defineFormats({
      html: {
        decode: ({ element }) => ({
          type: element.dataset.type ?? 'info',
        }),
        encode: ({ node }) => ({
          attributes: { 'data-type': node.type },
          tag: 'aside',
        }),
        match: { tag: 'aside' },
      },
    }),
});
```

当前 plugin 自己的 mapping 使用 `defineFormats(map)`；foreign target 使用
`defineFormats(TargetPlugin, map)`。语义 key 是 `html`，MIME negotiation 不属于
这张 map。

需要拥有完整 `text/html` browser payload 时，通过 `dataTransferFormats` 注册
`DataTransferFormat`。该 owner 可以检查完整 payload、调用 `parseHtmlSlice`，再
返回带诊断的 slice。参阅 [Clipboard](/docs/clipboard)。

## Result 与 diagnostics

Parse success 只包含 warning diagnostics，并且只包含一个 carrier。Serialize
success 包含 `data`；failure 不包含。配置错误、mapping bug 与无效 model input
会抛出。source 错误、resource limit、schema recovery、安全处理与预期格式损失
通过 diagnostics 返回。

默认解析限制：

| 限制 | 默认值 |
| --- | --- |
| UTF-8 source bytes | `5 * 1024 * 1024` |
| Tree nodes | `100_000` |
| Tree depth | `256` |

通过 `limits` 覆盖默认值。Plate 在解析前检查 byte limit，并在 parse5 构建 tree
时检查 node/depth limit。

## API Reference

| API | Import | 用途 |
| --- | --- | --- |
| `parseHtml(source, options)` | `platejs/html` | 在浏览器解析完整 document。 |
| `parseHtmlSlice(source, options)` | `platejs/html` | 在浏览器解析闭合 insertion slice。 |
| `serializeHtml(document, options)` | `platejs/html` | 序列化 detached document。 |
| `parseHtml(source, options)` | `platejs/html/server` | 在 Node.js 解析完整 document。 |
| `parseHtmlSlice(source, options)` | `platejs/html/server` | 在 Node.js 解析闭合 insertion slice。 |
| `editor.api.html.parse(source, options?)` | `HtmlPlugin` | 使用已安装 target 解析 document。 |
| `editor.api.html.parseSlice(source, options?)` | `HtmlPlugin` | 使用已安装 target 解析 slice。 |
| `editor.api.html.serialize(options?)` | `HtmlPlugin` | 序列化当前或指定 document。 |

直接 parse 的 options 必须包含 `plugins`，并可包含 `schema`、`limits`、
`lossPolicy` 与 `collapseWhitespace`。直接 serialize 的 options 必须包含
`plugins`，并可包含 `schema`、`projection` 与 `lossPolicy`。editor method 从
editor 捕获 plugins 与 schema，因此不接受这两个选项。
