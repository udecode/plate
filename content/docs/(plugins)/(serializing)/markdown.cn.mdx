Markdown 转换包含两个方向：

- 把完整 Markdown file、闭合 insertion slice 或 inline content 解析为 Plate。
- 把 schema-valid Plate document 序列化为 Markdown。

Editor 内转换使用 `MarkdownPlugin`。detached browser、server、worker 与 CLI
转换使用 `platejs/markdown` 的 standalone function。

## 解析 Markdown

### 已安装的 editor

```ts
import { MarkdownPlugin } from 'platejs/markdown';
import { createEditor } from 'platejs';

const editor = createEditor({
  plugins: [BaseParagraphPlugin, BaseHeadingPlugin, BaseBoldPlugin, MarkdownPlugin],
});

const result = editor.api.markdown.parse('# Hello\n\n**Plate** document');

if (result.ok) {
  editor.update((tx) => tx.value.replace(result.document));
}
showDiagnostics(result.diagnostics);
```

`parse` 返回完整 `EditorDocumentValue`，包括 Markdown 能表示的 root 与 metadata。
Block insertion 使用 `parseSlice`，inline insertion 使用 `parseInline`。两者都返回
闭合、无 root 的 `ContentSlice`。

```ts
const blocks = editor.api.markdown.parseSlice('- One\n- Two');
const inline = editor.api.markdown.parseInline('Hello **world**');

if (blocks.ok) editor.update.slice.replace(blocks.slice);
if (inline.ok) editor.update.slice.replace(inline.slice);
```

`parseInline` 只接受一个 paragraph 的内容；block content 会以
`markdown-inline-blocks` 失败。直接语法解析不保留任意 open edge 或 detached
root。这些 native transfer 属性由 `DataTransferFormat` 拥有。

### Detached 转换

```ts
import { parseMarkdown } from 'platejs/markdown';

const result = parseMarkdown(source, { plugins: EditorKit });
```

Standalone function 为一次 operation 编译传入的 plugin declaration。它不会激活
editor runtime、handler、effect 或 React hook。Slice 与 inline content 通过已安装
的 editor 解析。

## 序列化 Markdown

### 已安装的 editor

```ts
const result = editor.api.markdown.serialize({ projection: 'proposed' });

showDiagnostics(result.diagnostics);
if (result.ok) downloadMarkdown(result.data);
```

要避免读取当前 value，请传入已捕获的 document：

```ts
const result = editor.api.markdown.serialize({
  document: editor.read.value(),
  projection: 'accepted',
});
```

### Detached 转换

```ts
import { serializeMarkdown } from 'platejs/markdown';

const result = serializeMarkdown(document, {
  plugins: EditorKit,
  projection: 'accepted',
});
```

序列化会 assert document 与选中的 authored projection。无效 model data 与
mapping bug 会抛出。预期内的格式表达损失通过带诊断的 result 返回。

`lossPolicy` 默认为 `'reject'`。不支持的可见内容会返回
`{ ok: false, diagnostics }`，且不包含 `data`。只有格式把 drop、replacement 或
unwrap 报告为 warning 时，`lossPolicy: 'allow'` 才能发布输出。保留内容的损失（例如
[table cell](#table-cell) 中折叠为 `<br/>` 的 paragraph 边界）在任何策略下都是
warning。

## 语法

Plate 读写 CommonMark，以及已安装 feature plugin 注册的 tag。GFM、math 与 emoji
来自 `MarkdownPlugin` 上配置的 [remark plugin](#remark-plugin)。注册 tag 的写法
类似 HTML，但只有注册过的名称才是 tag，且不会执行任何内容。

### 注册 tag

| Tag | Feature |
| --- | --- |
| `<callout icon="💡">…</callout>` | [Callout](/docs/callout) |
| `<columnGroup>`、`<column width="50%">` | [Column](/docs/column) |
| `<details>`、`<summary>` | [Details](/docs/details) |
| `<toc />` | [Table of Contents](/docs/toc) |
| `<date value="2025-01-01" />` | [Date](/docs/date) |
| `<img>`、带 `<figcaption>` 的 `<figure>` | [Image](/docs/media) |
| `<video src="…" />`、`<audio>`、`<file>`、`<mediaEmbed>` | [Media](/docs/media) |
| `<u>`、`<kbd>`、`<mark>`、`<sub>`、`<sup>`、`<del>` | [Basic marks](/docs/basic-marks) |
| `<span style="color: red;">` | [Font](/docs/font) 颜色、字体、字号与字重 |

只有对应 feature plugin 已安装时，tag 才会注册。Element tag 使用 schema type，
因此应用重命名 type 时也会重命名对应 tag。

### 写出格式

```md
<callout icon="💡">Remember to save.</callout>

<details>

<summary>Title</summary>

Body text.

</details>

Due <date value="2025-01-01" />, ask [Jane](mention:user_123).
```

- Block tag 与其内容之间用空行分隔，不缩进。
- 只包含一个单行 paragraph 的 block 保持在一行内。
- Attribute value 使用双引号。`&` 写为 `&amp;`，`"` 写为 `&quot;`，换行写为
  `&#10;`，`|` 写为 `&#124;`。
- CommonMark 会合并的 footnote label（例如 `A` 与 `a`）会写成不同的 label。

### 读取规则

- 任意字符串都能解析。没有 mapping 接受的 raw HTML 保留为字面文本，并在任何策略下
  报告无损的 `markdown-unsupported-node` warning。
- HTML comment 会被丢弃并报告无损 warning。
- `<br>`、`<br/>` 与 `<br />` 读取为换行。
- 只包含一个注册 block tag 的行是 block，即使紧邻 paragraph 文本。出现在
  paragraph、heading 或 table cell 其他位置的 block tag 保留为文本。
- Tag 在同一个 container（例如 paragraph、list item 或 block quote）内配对。
  未闭合的 tag 在 container 末尾闭合，未匹配的闭合 tag 保留为文本。每次修复都会
  报告 `markdown-tag-repair` warning，`reason` 为
  `'unclosed' | 'unmatched' | 'misplaced'`。
- 在 Plate block tag 内，只有 fenced code 是代码。缩进行按 Markdown 读取，因此
  缩进的 tag 内容与未缩进时解析结果相同。写成 `name={…}` 的 attribute value
  按原始文本读取。
- Reference-style link 与 image（`[text][ref]` 加 `[ref]: url` definition）解析为
  普通 link 与 image。
- 任何 reader 或页面都不应执行的 destination 会在 mapping 读取之前被移除。Link
  保留其 label，并在任何策略下报告 `markdown-unsafe-content` warning：destination
  可能执行 script（例如 `javascript:` 或 `data:`）时为无损，否则（例如协议相对或
  格式错误的 URL）为有损。source 无法加载的 image 保留 alt text，并报告有损的同类
  diagnostic；script source 从未渲染，因此移除它是无损的。Link 的
  `allowedSchemes` 在该下限之上收窄或放宽 link scheme；被其拒绝的 link 保留
  label，并报告有损的 `markdown-unsupported-node` warning。

### Table cell

GFM 的一行只能写在一行内，因此 Plate 把 table cell 中的 block 以 inline 形式写在这一行：

```md
| Plan |
| ---- |
| Intro<ul><li><input type="checkbox" checked disabled /> ship</li></ul><ol start="3"><li>step</li></ol> |
```

- Plate 把 list paragraph 写为 `<ul>`、`<ol start="n">` 与 `<li>` HTML，task item
  以 disabled checkbox 开头。安装 [List](/docs/list) 时，解析把这些 HTML 读取回
  list paragraph；未安装时 HTML 保留为字面文本。
- Plate 用 `<br/>` 连接其他 paragraph。解析把它们读取回一个带换行的 paragraph，
  因此序列化会把折叠的边界报告为有损 warning。
- Heading 或 quote 保留其 inline content，code 或 math block 保留其文本，各自报告
  有损 warning。序列化会丢弃其他 block（例如 horizontal rule 或带 caption 的
  image），并按 `lossPolicy` 报告。
- Plate 把合并的 cell 写在其第一个 slot，在被覆盖的 slot 写空 cell。每个 span 报告
  `markdown-property-omitted`。
- 换行与 `|` 都不会提前结束 cell。在 inline math 中，序列化把 `|` 写为 `\vert`，
  把 `\|` 写为 `\Vert`。在 `\text{…}` 等 text-mode group 中，`|` 写为
  `\textbar{}`。`\verb` 的 `|` 分隔符换成其他分隔符。若 inline math 中的 `|` 或
  `\|` 无法安全改写（例如位于其他命令的参数、array 列格式或 `\verb` 文本中），
  整个 inline math 写为文本。序列化在 autolink destination 中把 `|` 写为 `%7C`，
  在 raw HTML 中写为 `&#124;`；把 inline math 或 raw HTML 中的换行写为空格；把
  包含 `\|` 的 inline code 写为文本。每个 cell 中每种改写报告一次有损 warning。

### Mention

Mention 是 URL 为 `mention:` 的 link。单独的 `@jane` 文本保留为文本。

```md
Hello [Jane Smith](mention:user_123).
```

参阅 [Mention](/docs/mention#markdown)。

### Block ID

Markdown 不携带 element ID，序列化也不会写出 ID。解析时会读取包裹单个 block 的
`<block id="…">`：安装 `ElementIdPlugin` 时，该 block 保留这个 `id`；否则移除
wrapper 并报告 `markdown-unsupported-node` warning。Mapping 不能占用 `block` tag。

## 流式预览

用 `partial: true` 与上一次 result 解析每个未完成的 stream prefix，然后用同一个
hint 严格解析完整 source：

```ts
const preview = editor.api.markdown.parseSlice(accumulated, {
  lossPolicy: 'allow',
  partial: true,
  previous,
});
previous = preview.ok ? preview : undefined;

// Stream 结束或用户停止时：
const result = editor.api.markdown.parseSlice(accumulated, { previous });
previous = undefined;
```

`partial: true` 会隐藏尚未完整到达的末尾 tag（例如 `Before <callo`），也不会报告
source 末尾仍未闭合的 tag。`lossPolicy: 'allow'` 让 stream 未完成时不支持的内容以
文本形式可见。`previous` 必须来自同一 editor 的同一 method。当 source 在上一次 result 的
source 之后继续增长，且 plugin 与 limits 未变时，它已完成的 block 保留其 node object，只
重新转换其后的文本；其他 hint 都会解析整个 source。在另一个 `lossPolicy` 下的解析（例如
严格的最终解析）只保留未报告任何 diagnostic 的已完成 block。包含链接引用定义或脚注定义
（`[id]: url`、`[^1]: note`）的 source 总是完整解析，因为定义会改变它之前的 block。

只读 preview 以解析得到的 block 组成的文档来渲染；editor 提供插件，本身不会被编辑：

```tsx
<EditorStatic editor={editor} document={{ children: nodes }} />
```

若要在可编辑的 editor 中显示 stream，则在 undo history 之外发布每个 result。只替换第一个
变化的 block 之后的 block；没有保持不变的开头 block 时替换整个 value：

```ts
let start = 0;

while (start < nodes.length && published[start] === nodes[start]) start += 1;

if (start === 0) {
  editor.update({ history: 'skip' }).value.replace({ children: nodes });
} else {
  editor.update({ history: 'skip' }, (tx) => {
    tx.nodes.replaceChildren(nodes.slice(start), { at: [], index: start });
  });
}
published = nodes;
```

启用 authored changes 的 editor 会把每次 node 写入记录为 authored change，因此启用
authored changes 的可编辑 preview 总是替换整个 value。

Source、abort signal、hint 与 preview 节奏由调用方负责：

- 第一个 chunk 立即发布，之后最多每 32 ms 发布一次最新的累计 source。
- 只把最新的 partial result 保留为 `previous`；stream 完成、被取消或替换、或卸载
  时丢弃它。
- Stream 完成或用户停止时，不带 `partial` 解析当前 source 一次，并延续最新的
  preview。最终解析失败会清空 preview。
- 取消、替换与卸载会中止 stream，并丢弃待发布的 preview，不做最终解析。

AI chat preview 遵循相同规则；参阅 [AI 流式传输](/docs/ai#streaming)。

## Authored content

Markdown 表示可见的 `accepted` 或 `proposed` content。它不会附加隐藏 Plate
document，也不能恢复完整 review state。

```ts
const proposed = editor.api.markdown.serialize({ projection: 'proposed' });
const accepted = editor.api.markdown.serialize({ projection: 'accepted' });
```

完整 proposal、decision、root 与 metadata 使用 authored JSON。需要 Word
revision 时使用 DOCX review export。参阅
[Authored Changes](/docs/authored-changes#export-explicit-projections)。

## 定义 Markdown mapping

Mapping 声明在拥有 node 或 mark 的 plugin 上。大多数 mapping 只是声明：Plate
根据 plugin 的 schema 构建 node、转换其 property，并读写其 children。

```ts
import { definePlugin, property, schema } from 'platejs';

const CalloutPlugin = definePlugin('callout', {
  schema: {
    element: schema.element.textBlock({
      properties: { tone: property.string() },
    }),
  },
  formats: ({ defineFormats, schema: { type } }) =>
    defineFormats({ markdown: { tag: type } }),
});
```

这个 mapping 读写 `<callout tone="info">Text</callout>`。

- `tag` 注册 Plate tag。Element 使用其 schema `type`，因此应用重命名 type 时，
  tag 也随之改名。
- Element 的 content model 决定 children：void element 没有 children；text block
  包含一个 inline content paragraph，仅在非空时写出；其他 block 包含 block。
- Attribute 携带 element 的非 metadata property：先按 schema 顺序写出 plugin
  自己的 property，再按 key 写出其他 plugin 的 property（例如 `textAlign`）。List
  property 永远不会成为 attribute，因为包裹 element 的 Markdown list 已经携带它们。
  带有未省略 default 的 property 在 attribute 缺失时会补上 default。
- `attributes` 为 plugin 自己的 property 指定 wire name：

```ts
markdown: { tag: type, attributes: { url: 'src' } }
```

- Attribute value 按 property kind 解码，并由其 schema validator 检查。无效值会被
  省略并报告 `markdown-property-omitted` warning。必需的值无效时（例如不安全的
  `src`），element 会被移除，其内容保留；script URL 则报告无损的
  `markdown-unsafe-content` warning。

### Mark

Schema 声明 `mark` 的 plugin 映射一个 mark。其声明说明 mark 从哪里读取、如何写出：

```ts
// 标准 Markdown container。
markdown: { node: 'strong' }

// Tag：`<kbd>` 读取为 `true`，值为 `true` 的 mark 写出 `<kbd>`。
markdown: { tag: 'kbd' }

// Enum mark 的每个值对应一个 tag。
markdown: [
  { tag: 'sub', value: 'sub' },
  { tag: 'sup', value: 'sup' },
]

// CSS 值 mark：`<span style="color: red;">` 读取为 `'red'`。
markdown: { tag: 'span', style: 'color' }
```

- `node` 接受 `'strong'`、`'emphasis'`、`'delete'` 与 `'inlineCode'`。
- Mark 由 `value` 匹配的第一个声明写出，因此同一值的后续声明只负责读取，例如与
  `{ node: 'delete' }` 并列的 `<del>`。
- 同一 tag 上的每个 mark mapping 都会参与，因此
  `<span style="color: red; background-color: yellow;">` 会同时设置两个 mark。
  没有任何 mark mapping 读取的 tag 保留其 source text。
- 没有 mapping 写出的 text property 保留文本，并报告 `markdown-property-omitted`
  warning。

### 自定义 callback

真实的格式差异使用 `decode` 与 `encode`。Image 在 `![alt](src)`、`<img>` 与
`<figure>` 之间选择；Date 把无法规范化的值写为文本。

```ts
markdown: {
  node: 'heading',
  decode: ({ decode, marks, node }) => ({
    children: decode(node.children, marks),
    level: node.depth,
    type,
  }),
  encode: ({ encodePhrasing, node, preserve }) => {
    preserve('level');

    return {
      children: encodePhrasing(node.children),
      depth: node.level,
      type: 'heading',
    };
  },
}
```

- `node` 选择标准 Markdown node kind，例如 `'blockquote'`、`'link'` 或
  `'image'`。`node` 与 `tag` 只能选择一个。`nestedTags` 声明只在该 tag 内读取的
  tag，例如 Image 的 `figcaption`。
- `decode` 返回 `undefined` 表示放弃该 node；同一 source 的下一个 mapping 按
  `priority` 从高到低运行。Mention 以这种方式先于 Link 解码 `mention:` link。
- `marks` 包含继承的持久化文本 mark。嵌套内容需要保留这些 mark 时，把它传给
  `decode` 或 `decodeNodes`。
- `previousSibling` 是当前 node 之前的 Markdown node。List 用它把紧跟在另一个
  list 之后的 list 读取为重新开始编号。
- `readTagAttributes(tag?)` 返回 `{ attributes, properties }`：按原样写出的全部
  attribute，以及按声明式 tag 的规则解码的 node property。
- `refuse(message)` 把 feature 无法表示的内容报告为 `markdown-unsupported-node`。
  被拒绝的 tag 保留其 source text。
- `report({ action, kind, message, nodeType })` 报告 mapping 自行处理的损失。
  `kind: 'property'` 表示保留内容的损失（例如 editor 不允许的 link destination），
  在任何策略下都是 warning；默认的 `kind: 'element'` 遵循 loss policy。
- `caption(children)` 在 `children` 是一个 paragraph 时返回 inline content，否则
  返回 `null`。
- `preserve(...keys)` 声明返回的输出携带 plugin 的这些 property。Node 上其他
  content property 会报告为 `markdown-property-omitted`。只有 `encode` 返回输出时
  声明才生效。
- `encodeNodeAttributes()` 按声明式 tag 的规则写出 node 的 attribute 并声明它们。
  `encodeAttributes(properties)` 写出给定的 property 值，并声明返回输出中保留了其
  attribute 的每个 property。
- `encodeLine(children)` 把 block children 写在一行内，与 Plate 写出
  [table cell](#table-cell) 的方式相同；`encodePhrasing(children)` 写出 inline
  children。`decodeLine(children, marks?)` 把这一行读取回 block。

传入数组可以为一个 plugin 声明多个 mapping。Self mapping 使用
`defineFormats(map)`；foreign target 使用 `defineFormats(TargetPlugin, map)`。
Plugin 的 `formats` 只接受 `html`、`markdown` 和 `plainText` key；MIME payload
属于 `dataTransferFormats`。

## Remark plugin

在 `MarkdownPlugin` 上配置一次 remark plugin。该 editor 的每次 parse 与 serialize
operation 都会使用它们。`MarkdownKit` 启用 GFM、math 与 emoji：

<ComponentSource name="markdown" />

```ts
import { MarkdownPlugin } from 'platejs/markdown';
import remarkGfm from 'remark-gfm';

const plugins = [
  ...BasicBlocksKit,
  MarkdownPlugin.configure({
    initialState: { remarkPlugins: [remarkGfm] },
  }),
];
```

Standalone function 从 `plugins` 中读取已配置的 `MarkdownPlugin`。Remark plugin
必须是同步的。Attacher 或 transformer 返回 Promise 属于配置错误，会直接抛出。
同步 function 不会返回 `Result | Promise<Result>`。

## Result 与 diagnostics

Parse success 包含 warning 与唯一 carrier。Failure 包含非空、error-first 的
diagnostic tuple，且不包含 carrier。Serialization 对 `data` 使用同一规则。

```ts
if (!result.ok) {
  reportImportFailure(result.diagnostics);
  return;
}

useDocument(result.document);
reportWarnings(result.diagnostics);
```

| Code | Severity | 报告内容 |
| --- | --- | --- |
| `markdown-unsupported-node` | `lossless` 或内容保留时为 warning；其他 `lossy` 遵循 `lossPolicy` | 没有 mapping 接受的内容、被拒绝的内容，或导出时丢弃的 node（`lossy`）。保留为文本的 raw HTML、HTML comment 与被移除的 `<block>` wrapper 为 `lossless`。[Table cell](#table-cell) 中折叠的 paragraph 边界或被折叠的 block 保留内容并报告 warning。 |
| `markdown-unsafe-content` | `lossless` 时为 warning；`lossy` 遵循 `lossPolicy` | 被移除的 link 或 image destination。 |
| `markdown-tag-repair` | Warning | `unclosed`、`unmatched` 或 `misplaced` 的注册 tag。 |
| `markdown-property-omitted` | Warning | 导出时 Markdown 无法携带的 property 或 mark（例如 paragraph 的 `textAlign`），或导入时无效的 tag attribute value。 |
| `markdown-limit-exceeded` | Error | Source byte、node 数量或深度超过 `limits`。 |
| `markdown-inline-blocks` | Error | `parseInline` 输入产生了 block。 |
| `markdown-schema-repair` | Warning；`'reject'` 下有损时为 error | 对解析结果应用的 schema repair。 |
| `markdown-schema-invalid` | Error | Schema 拒绝的解析内容。 |
| `markdown-unsupported-root`、`markdown-unsupported-metadata` | Warning | 导出时省略的 named root 或 document metadata。 |

Authored projection diagnostics 使用同一种 result。配置错误与 mapping contract
violation 会抛出。

默认限制为 5 MiB UTF-8 source、100,000 个 mdast node 与 depth 256。Markdown
在解析前检查 byte limit；由于 mdast parser 没有 bounded construction hook，
node/depth admission 在 parser 返回后执行。

## API Reference

| API | Result |
| --- | --- |
| `parseMarkdown(source, options)` | 完整 `EditorDocumentValue`。 |
| `serializeMarkdown(document, options)` | `data` 中的 Markdown string。 |
| `editor.api.markdown.parse(source, options?)` | 使用已安装 target 解析完整 document。 |
| `editor.api.markdown.parseSlice(source, options?)` | 闭合、无 root 的 block `ContentSlice`。 |
| `editor.api.markdown.parseInline(source, options?)` | 闭合、无 root 的 inline `ContentSlice`。 |
| `editor.api.markdown.serialize(options?)` | 使用已安装 target 序列化当前或指定 document。 |

`MarkdownPlugin`、standalone function 及其 result、diagnostic 与 option type 从
`platejs/markdown` import。

| Parse option | 用途 |
| --- | --- |
| `limits` | 覆盖 `maxBytes`、`maxNodes` 或 `maxDepth`。 |
| `lossPolicy` | `'reject'`（默认）或 `'allow'`。 |
| `partial` | 为 preview 解析未完成的 stream prefix。 |
| `previous` | 仅 `editor.api.markdown.parseSlice`：要延续的增长中 source 的上一次 result。 |

| Serialize option | 用途 |
| --- | --- |
| `document` | 仅 editor method：要序列化的 document，类型为该 editor 的 value。默认为当前 value。 |
| `lossPolicy` | `'reject'`（默认）或 `'allow'`。 |
| `plainMarks` | 以纯文本写出、不带 Markdown 格式的 mark key。 |
| `preserveEmptyParagraphs` | 保留空 paragraph。默认为 `true`。 |
| `projection` | `'accepted'` 或 `'proposed'`。Authored document 必须提供。 |
| `remarkStringifyOptions` | 传给 `remark-stringify` 的 options。 |
| `spread` | 写出 loose list。默认为 `false`。 |

Standalone function 还必须包含 `plugins`，并可包含 `schema`。editor method 从
editor 捕获 plugins 与 schema，因此不接受这两个选项。`MarkdownPlugin` state 包含
`remarkPlugins`、`remarkStringifyOptions` 与 `plainMarks`。
