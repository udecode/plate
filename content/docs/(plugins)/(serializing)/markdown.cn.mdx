title: Markdown
description: 解析 Markdown document、slice 与 inline content，并把 Plate document 序列化为 Markdown。

Markdown 转换包含两个方向：

- 把完整 Markdown file、闭合 insertion slice 或 inline content 解析为 Plate。
- 把 schema-valid Plate document 序列化为 Markdown。

Editor 内转换使用 `MarkdownPlugin`。detached browser、server、worker 与 CLI
转换使用 `platejs/markdown` 的 standalone function。

## 解析 Markdown

### 已安装的 editor

```ts
import { MarkdownPlugin } from 'platejs/markdown';
import { createEditor } from 'platejs';

const editor = createEditor({
  plugins: [BaseParagraphPlugin, BaseHeadingPlugin, BaseBoldPlugin, MarkdownPlugin],
});

const result = editor.api.markdown.parse('# Hello\n\n**Plate** document');

if (result.ok) {
  editor.update((tx) => tx.value.replace(result.document));
}
showDiagnostics(result.diagnostics);
```

`parse` 返回完整 `EditorDocumentValue`，包括 Markdown 能表示的 root 与 metadata。
Block insertion 使用 `parseSlice`，inline insertion 使用 `parseInline`。两者都返回
闭合、无 root 的 `ContentSlice`。

```ts
const blocks = editor.api.markdown.parseSlice('- One\n- Two');
const inline = editor.api.markdown.parseInline('Hello **world**');

if (blocks.ok) editor.update.slice.replace(blocks.slice);
if (inline.ok) editor.update.slice.replace(inline.slice);
```

直接语法解析不保留任意 open edge 或 detached root。这些 native transfer 属性由
`DataTransferFormat` 拥有。

### Detached 转换

```ts
import {
  parseMarkdown,
  parseMarkdownInline,
  parseMarkdownSlice,
} from 'platejs/markdown';

const document = parseMarkdown(source, { plugins: EditorKit });
const blocks = parseMarkdownSlice(source, { plugins: EditorKit });
const inline = parseMarkdownInline(source, { plugins: EditorKit });
```

Standalone function 为一次 operation 编译传入的 plugin declaration。它不会激活
editor runtime、handler、effect 或 React hook。

## 序列化 Markdown

### 已安装的 editor

```ts
const result = editor.api.markdown.serialize({ projection: 'proposed' });

showDiagnostics(result.diagnostics);
if (result.ok) downloadMarkdown(result.data);
```

要避免读取当前 value，请传入已捕获的 document：

```ts
const result = editor.api.markdown.serialize({
  document: editor.read.value(),
  projection: 'accepted',
});
```

Detached document 使用 standalone function：

```ts
import { serializeMarkdown } from 'platejs/markdown';

const result = serializeMarkdown(document, {
  plugins: EditorKit,
  projection: 'accepted',
});
```

序列化会 assert document 与选中的 authored projection。无效 model data 与
mapping bug 会抛出。预期内的格式表达损失通过带诊断的 result 返回。

`lossPolicy` 默认为 `'reject'`。不支持的可见内容会返回
`{ ok: false, diagnostics }`，且不包含 `data`。只有格式把 drop、replacement 或
unwrap 报告为 warning 时，`lossPolicy: 'allow'` 才能发布输出。

## Authored content

Markdown 表示可见的 `accepted` 或 `proposed` content。它不会附加隐藏 Plate
document，也不能恢复完整 review state。

完整 proposal、decision、root 与 metadata 使用 authored JSON。需要 Word
revision 时使用 DOCX review export。参阅
[Authored Changes](/docs/authored-changes)。

## 定义 Markdown mapping

Mapping 声明在拥有 node 或 mark 的 plugin 上。`formats` authoring callback
只接收 `defineFormats` 与静态 schema binding。运行时 mapping callback 接收冻结
plugin state、registry/schema view、encode 时的 model location，以及 Markdown
专用 `report`。它不会接收 live editor 或 store。

```ts
import { definePlugin } from 'platejs';

const CalloutPlugin = definePlugin('callout', {
  formats: ({ defineFormats, schema: { type } }) =>
    defineFormats({
      markdown: {
        decode: ({ node }) => ({ children: [], type }),
        encode: ({ node }) => ({
          attributes: [
            { name: 'tone', type: 'mdxJsxAttribute', value: node.tone },
          ],
          children: [],
          name: 'Callout',
          type: 'mdxJsxFlowElement',
        }),
      },
    }),
});
```

Self mapping 使用 `defineFormats(map)`；foreign target 使用
`defineFormats(TargetPlugin, map)`。语义 key 是 `markdown`，MIME declaration
不属于这张 map。

## Remark plugin

`remarkPlugins` 为单次 parse 或 serialize operation 接受同步 unified plugin。

```ts
const result = parseMarkdown(source, {
  plugins: EditorKit,
  remarkPlugins: [remarkGfm, [remarkMdx, { acorn: true }]],
});
```

Attacher 或 transformer 返回 Promise 属于配置错误，会直接抛出。同步 function
不会返回 `Result | Promise<Result>`。

## Result 与 diagnostics

Parse success 包含 warning 与唯一 carrier。Failure 包含非空、error-first 的
diagnostic tuple，且不包含 carrier。Serialization 对 `data` 使用同一规则。

Diagnostics 覆盖无效 source、resource limit、filter、不支持的 node/root、
incomplete-stream fallback、schema recovery 与 authored projection。配置错误与
mapping contract violation 会抛出。

默认限制为 5 MiB UTF-8 source、100,000 个 mdast node 与 depth 256。Markdown
在解析前检查 byte limit；由于 mdast parser 没有 bounded construction hook，
node/depth admission 在 parser 返回后执行。

## API Reference

| API | Result |
| --- | --- |
| `parseMarkdown(source, options)` | 完整 `EditorDocumentValue`。 |
| `parseMarkdownSlice(source, options)` | 闭合、无 root 的 block `ContentSlice`。 |
| `parseMarkdownInline(source, options)` | 闭合、无 root 的 inline `ContentSlice`。 |
| `serializeMarkdown(document, options)` | `data` 中的 Markdown string。 |
| `editor.api.markdown.parse(source, options?)` | 使用已安装 target 解析完整 document。 |
| `editor.api.markdown.parseSlice(source, options?)` | 使用已安装 target 解析 block slice。 |
| `editor.api.markdown.parseInline(source, options?)` | 使用已安装 target 解析 inline slice。 |
| `editor.api.markdown.serialize(options?)` | 使用已安装 target 序列化当前或指定 document。 |

Standalone function 与 type 从 `platejs/markdown` import。直接调用的 options
必须包含 `plugins`，并可包含 `schema`、`limits`、`lossPolicy`、同步
`remarkPlugins`、filter、MDX/line-break policy 与 preservation policy。
Serialization 还接受 `projection`、stringify options、block-ID policy、
plain-mark policy 与 list spread。editor method 从 editor 捕获 plugins 与 schema，
因此不接受这两个选项。
