`@platejs/markdown` 将 Markdown 转换为 Plate 文档，也可将 Plate 文档转换回 Markdown。

<ComponentPreview name="markdown-demo" />

<PackageInfo>

## 特性

- **Markdown 转 Plate JSON：** 将 Markdown 字符串转换为 Plate 可编辑格式（`deserialize` 方法）。
- **Plate JSON 转 Markdown：** 将 Plate 内容重新序列化为 Markdown 字符串（`serialize` 方法）。
- **默认安全：** 转换过程不使用 `dangerouslySetInnerHTML`，安全可靠。
- **功能自有 codec：** 已安装的功能插件提供各自的 Markdown 转换，包括 MDX 节点。
- **高度可扩展：** 通过 `remarkPlugins` 添加 [remark 插件](https://github.com/remarkjs/remark/blob/main/doc/plugins.md#list-of-plugins)。
- **标准兼容：** 支持 CommonMark，支持通过 [`remark-gfm`](https://github.com/remarkjs/remark-gfm) 启用 GFM（GitHub 风格 Markdown 扩展）。
- **循环序列化：** 通过 MDX 语法保证自定义元素可逆转换。

</PackageInfo>

## 为什么选择 Plate Markdown？

与 `react-markdown` 等库仅将 Markdown 渲染成 React 元素不同，`@platejs/markdown` 深度集成 Plate 体系，带来如下优势：

- **富文本编辑能力：** 支持将 Markdown 转为结构化 Plate 内容，实现高级编辑能力。
- **所见即所得（WYSIWYG）：** 支持富文本视图编辑，一键回转为 Markdown。
- **自定义元素与数据支持：** 复杂自定义元素（如提及、嵌入等）可通过 MDX 双向转换。
- **可扩展性：** 充分利用 Plate 插件系统与 unified/remark 生态的能力。

<Callout type="note">
  如果你只需将 Markdown 显示为 HTML，无需自定义元素和富编辑，`react-markdown` 可能已足够。但如需 Markdown 导入/导出、富文本及自定义内容，`@platejs/markdown` 则是最佳集成方案。
</Callout>

## 手动集成用法

<Steps>

### 安装

```bash
npm install platejs @platejs/markdown
```

### 引用插件

```tsx
import { MarkdownPlugin } from '@platejs/markdown';
import { createPlateEditor } from 'platejs/react';

const editor = createPlateEditor({
  plugins: [
    // ...其它插件,
  MarkdownPlugin,
  ],
  });
```

### 配置插件

通过 `MarkdownPlugin.initialState` 配置共享语法插件、过滤策略和字符串化
选项。已安装的功能插件会自动提供各自的 Markdown 节点 codec。Markdown API
以及插件的 `text/markdown` 和 `text/plain` 文档 codec 共享这组 state。

```tsx title="lib/plate-editor.ts"
import { createPlateEditor } from 'platejs/react';
import {
  MarkdownPlugin,
  remarkMention,
  remarkMdx,
  } from '@platejs/markdown';
import remarkGfm from 'remark-gfm';
import remarkMath from 'remark-math';

const editor = createPlateEditor({
  plugins: [
    // ...其它 Plate 插件
    MarkdownPlugin.configure({
      initialState: {
        // 通过 remarkPlugins 添加语法扩展（如 GFM、数学、MDX）
        remarkPlugins: [remarkMath,
  remarkGfm,
  remarkMdx,
  remarkMention],
  },
  }),
  ],
  });
```

<Callout type="info">
  `MarkdownPlugin` 通过 `editor.api.markdown` 提供转换。插件 state 仍通过
  `editor.plugin(MarkdownPlugin)` 访问。添加或删除功能插件，也会添加或删除其
  Markdown 转换。
</Callout>

<Callout type="warning" title="仅表示主内容">
  Markdown 只表示 `document.children`，不会保留命名 roots 或 slice
  的开放边缘。需要精确保留 roots、`openStart` 和 `openEnd` 时，剪贴板传输使用
  `application/x-plite-fragment`。
</Callout>

### Markdown 转 Plate（反序列化）

使用 `editor.api.markdown.deserialize` 将 Markdown 字符串转换为
`EditorDocumentValue`。媒体标题直接存储为媒体元素的块级 children。

```tsx title="components/my-editor.tsx"
import { createPlateEditor } from 'platejs/react';
import { MarkdownPlugin } from '@platejs/markdown';
import { ItalicPlugin } from '@platejs/basic-nodes/react';
import { BasicBlocksKit } from '@/components/editor/plugins/basic-blocks-kit';
// ...还需引入其它用于渲染的 Plate 插件

const markdownString = '# Hello, *Plate*!';

const editor = createPlateEditor({
  plugins: [
    // 必须包含 MarkdownPlugin
    MarkdownPlugin,
    ...BasicBlocksKit,
    ItalicPlugin,
  ],
  // 初始内容通过反序列化生成
  initialValue: ({ editor }) =>
    editor.api.markdown.deserialize(markdownString),
});
```

<Callout type="warning" title="插件依赖提醒">
  你需要在 `plugins` 中包含渲染 Markdown 反序列化结果所需的所有 Plate 插件（例如渲染 `#` 需 `H1Plugin`，渲染表格需 `TablePlugin`）。
</Callout>

### Plate 转 Markdown（序列化）

使用 `editor.api.markdown.serialize` 将当前编辑器文档或指定的 `EditorDocumentValue` 转回 Markdown 字符串。

序列化只读取文档的主 `children`。命名 roots 不属于 Markdown 表示。

**序列化当前编辑器内容：**

```tsx
// 假设 editor 已有内容
const markdownOutput = editor.api.markdown.serialize();
console.info(markdownOutput);
```

**序列化指定文档：**

```tsx
const specificNodes = [
  { type: 'paragraph',
  children: [{ text: '仅序列化这一段。' }] },
  { type: 'h1',
  children: [{ text: '以及这个标题。' }] },
  ];

// 假设 editor 是你的 Plate 实例
const partialMarkdownOutput = editor.api.markdown.serialize({
  value: { children: specificNodes },
  });
console.info(partialMarkdownOutput);
```

Markdown 图片的 alt 文本映射到图片的一个段落 child。富 MDX 媒体子内容
直接映射到媒体元素的块级 children。

### 循环序列化：自定义元素（MDX）

核心特性之一是支持无标准 Markdown 语法的自定义 Plate 元素（如下划线、提及等），`@platejs/markdown` 会在序列化时转为 [MDX][github-mdx] 元素，并可无损还原。

**示例：处理自定义 `date` 元素**

**Plate 节点结构：**

```ts
{
  type: 'paragraph',
  children: [
    { text: 'Today is ' },
  { type: 'date',
  date: '2025-03-31',
  children: [{ text: '' }] } // 叶节点需有 text
  ],
  }
```

**功能插件 codec：**

`@platejs/core` 内置 Markdown codec 编写类型。功能插件无需导入可选的
Markdown 运行时即可声明 codec。
同一插件同时拥有 HTML 和 Markdown codec 时，在一个 `defineCodecs`
对象中声明两个格式键。每种格式都会保留基于 schema 的类型推断。

```tsx title="lib/plate-editor.ts"
import { defineBasePlugin } from '@platejs/core';
import { property } from '@platejs/plite';

export const BaseDatePlugin = defineBasePlugin('date',
  {
  codecs: ({ defineCodecs }) =>
    defineCodecs({
      'text/html': {
        decode: ({ element }) => ({ date: element.dataset.date }),
  encode: ({ node }) => ({
          attributes: { 'data-date': node.date },
  tag: 'span',
  }),
  match: [{ attributes: { 'data-date': true },
  tag: 'span' }],
  },
  'text/markdown': {
        decode: ({ node,
  name,
  parseAttributes }) => ({
          children: [{ text: '' }],
  date: String(parseAttributes(node.attributes).value ?? ''),
  type,
  }),
  encode: ({ node,
  propsToAttributes }) => ({
          attributes: propsToAttributes({ value: node.date }),
  children: [],
  name: 'date',
  type: 'mdxJsxTextElement',
  }),
  from: 'date',
  kind: 'node',
  },
  }),
  schema: {
    element: {
      properties: { date: property.string() },
  void: 'inline',
  },
  },
  });
```

**转换流程说明：**

1.  **序列化（Plate → Markdown）：** Plate 的 `date` 节点写为 `<date value="2025-03-31" />`。
2.  **反序列化（Markdown → Plate）：** `<date value="2025-03-31" />` 和 `<date>2025-03-31</date>` 都会还原为 Plate `date` 节点。

</Steps>

## API 参考

### `MarkdownPluginState`

通过 `MarkdownPlugin.configure({ initialState })` 传入 Markdown 转换行为。

<API name="MarkdownPluginState">
  <APIOptions type="MarkdownPluginState">
    <APIItem name="allowedNodes" type="MarkdownNodeName[] | null">
      白名单方式，指定允许哪些节点类型（包括 Plate 元素类型及 Markdown AST 类型，如 `strong`）。不能与 `disallowedNodes` 一起使用。如果设置，仅处理列表内的类型。默认值：`null`（全部允许）。
    </APIItem>
    <APIItem name="disallowedNodes" type="MarkdownNodeName[] | null">
      黑名单方式，指定过滤掉哪些节点类型。不能和 `allowedNodes` 一起使用。默认值：`null`。
    </APIItem>
    <APIItem name="allowNode" type="AllowNodeConfig">
      使用自定义函数进行更细粒度的节点过滤，该函数会在 `allowedNodes`/`disallowedNodes` 之后应用。- `deserialize?: (mdastNode: any) => boolean`：Markdown → Plate 的过滤，返回 `true` 保留节点。- `serialize?: (slateNode: any) => boolean`：Plate → Markdown 的过滤，返回 `true` 保留节点。
    </APIItem>
    <APIItem name="remarkPlugins" type="Pluggable[]">
      [remark 插件](https://github.com/remarkjs/remark/blob/main/doc/plugins.md#list-of-plugins)数组
      （如 `remark-gfm`、`remark-math`、`remark-mdx` 等）。对 Markdown AST (`mdast`) 生效。默认值：`[]`。
    </APIItem>
    <APIItem name="remarkStringifyOptions" type="RemarkStringifyOptions | null">
      传给 `remark-stringify` 的选项。默认值：`null`。
    </APIItem>
    <APIItem name="plainMarks" type="MarkdownNodeName[] | null">
      按纯文本序列化、不应用 Markdown 格式的 mark。默认值：`null`。
    </APIItem>
  </APIOptions>
</API>

### `MarkdownPlugin`

`MarkdownPlugin` 通过 `editor.api.markdown` 提供转换方法，并声明以下
product codecs：

| 格式 | 解码 | 编码 | 表示 |
| --- | --- | --- | --- |
| `text/markdown` | 是 | 是 | 闭合的主内容 slice |
| `text/plain` | 是 | 否 | 闭合的主内容 slice |

通用剪贴板管线优先使用 `application/x-plite-fragment` 表示精确的 Plate
slice，并在需要时回退到这些外部格式。

### 使用 Remark 插件（GFM）

为编辑器增加 GitHub Flavored Markdown（GFM）支持，包括表格、删除线、任务列表和自动链接。

**插件配置：**

```tsx title="lib/plate-editor.ts"
import { createPlateEditor } from 'platejs/react';
import { MarkdownPlugin } from '@platejs/markdown';
import remarkGfm from 'remark-gfm';
// 导入 GFM 相关 Plate 插件
import { TablePlugin } from '@platejs/table/react';
import { TodoListPlugin } from '@platejs/list-classic/react'; // 对应任务列表的 List 插件
import { StrikethroughPlugin } from '@platejs/basic-nodes/react';
import { LinkPlugin } from '@platejs/link/react';

const editor = createPlateEditor({
  plugins: [
    // ...其他插件
    TablePlugin,
  TodoListPlugin,
  // 或你当前使用的任务列表插件
    StrikethroughPlugin,
  LinkPlugin,
  MarkdownPlugin.configure({
      initialState: {
        remarkPlugins: [remarkGfm],
  },
  }),
  ],
  });
```

**用法示例：**

```tsx
const markdown = `
A table:

| a | b |
| - | - |

~~Strikethrough~~

- [x] Task list item

Visit https://platejs.org
`;

// 假设 `editor` 是已配置好的 Plate 编辑器实例
const document = editor.api.markdown.deserialize(markdown);
editor.update((tx) => {
  tx.value.replace(document);
});

const markdownOutput = editor.api.markdown.serialize();
// markdownOutput 将包含 GFM 语法
```

### 自定义渲染（语法高亮）

本例展示两种方式：一种是自定义渲染组件（适合 UI 层变更），另一种是单次转换覆盖（适合一次性改变 Plate 数据结构）。

**背景说明：**

- `@platejs/markdown` 会将 Markdown 的代码块（如 \`\`\`js ... \`\`\`）转换为 Plate 的 `codeBlock` 元素，子元素为 `codeLine`。
- Plate 的 `CodeBlockElement`（通常来自 `@platejs/code-block/react`）负责渲染这一结构。
- 语法高亮由 `CodeHighlightPlugin` 和 `lowlight` 提供。详见 [代码块插件文档](/docs/plugins/code-block)。

**方式一：自定义渲染组件（推荐 UI 层改动时使用）**

自定义 `codeBlock` 插件的渲染组件即可更改代码块的外观。

```tsx title="components/my-editor.tsx"
import { createPlateEditor } from 'platejs/react';
import {
  CodeBlockPlugin,
  CodeHighlightPlugin,
  CodeLinePlugin,
  } from '@platejs/code-block/react';
import { MarkdownPlugin } from '@platejs/markdown';
import { MyCustomCodeBlockElement } from './my-custom-code-block'; // 你的自定义组件

const editor = createPlateEditor({
  plugins: [
    CodeBlockPlugin.configure({ component: MyCustomCodeBlockElement }),
  // 基础插件 + 自定义渲染
    CodeLinePlugin.configure({ component: MyCustomCodeLineElement }),
  CodeHighlightPlugin.configure({ component: MyCustomCodeSyntaxElement }),
  MarkdownPlugin,
  // 用于 Markdown 转换
    // ... 其他插件
  ],
  });

// MyCustomCodeBlockElement.tsx 内实现自定义渲染（如用 react-syntax-highlighter），并消费 PlateElement 的 props。
```

完整用法详见 [代码块插件文档](/docs/plugins/code-block)。

**方式二：单次转换覆盖（高级用法）**

如果只需在一次导入中改变 Plate JSON，可为该次操作传入 `rules`。可复用的
代码块行为应由代码块功能插件的 `text/markdown` codec 持有。

```tsx title="lib/plate-editor.ts"

const value = editor.api.markdown.deserialize(markdown, {
  rules: {
    ['codeBlock']: {
      deserialize: (mdastNode) => ({
        children: [{ text: '' }],
        lang: mdastNode.lang ?? undefined,
        rawCode: mdastNode.value || '',
        type: 'codeBlock',
      }),
    },
  },
});

const output = editor.api.markdown.serialize({
  value,
  rules: {
    ['codeBlock']: {
      serialize: (node) => ({
        lang: node.lang,
        type: 'code',
        value: node.rawCode,
      }),
    },
  },
});
```

可根据需求选择 UI 层调整（方式一）或底层数据结构调整（方式二）。

### 支持数学（`remark-math`）

支持 TeX 数学语法（如 `$行内$`、`$$块级$$`）。

**插件配置：**

```tsx title="lib/plate-editor.ts"
import { createPlateEditor } from 'platejs/react';
import { MarkdownPlugin } from '@platejs/markdown';
import remarkMath from 'remark-math';
// Plate 数学渲染相关插件
import { MathPlugin } from '@platejs/math/react'; // 主 Math 插件

const editor = createPlateEditor({
  plugins: [
    // ...其他插件
    MathPlugin, // 渲染块级与行内公式
    MarkdownPlugin.configure({
      initialState: {
        remarkPlugins: [remarkMath],
        // 已安装的数学插件持有 `math` 与 `inlineMath` codec。
      },
    }),
  ],
});
```

**用法示例：**

```tsx
const markdown = `
Inline math: $E=mc^2$

Block math:
$$
\\int_a^b f(x) dx = F(b) - F(a)
$$
`;

// 假设 `editor` 为已配置 Plate 编辑器实例
const document = editor.api.markdown.deserialize(markdown);
// document.children 包含 'inlineEquation' 及 'equation' 节点

const markdownOutput = editor.api.markdown.serialize({ value: document });
// 输出 Markdown 字符串包含 $...$ 和 $$...$$ 语法
```


**支持的 Markdown 格式：**

```tsx
const markdown = `
```

## Remark 插件生态（Remark Plugins）

`@platejs/markdown` 基于 [unified][github-unified] 与 [remark][github-remark] 生态。通过 `remarkPlugins` option 添加 remark 插件。这些插件对 [mdast（Markdown 抽象语法树）][github-mdast] 进行操作。

**插件查找指南：**

- [remark 官方插件列表][github-remark-plugins]
- [GitHub 上的 `remark-plugin` 主题][github-topic-remark-plugin]
- [Awesome Remark][github-awesome-remark]

**常见用途：**

- **语法扩展：** 如 `remark-gfm`（表格等）、`remark-math`（TeX）、`remark-frontmatter`、`remark-mdx`
- **Lint/格式化：** 如 `remark-lint`（通常作为独立工具链）
- **自定义转换：** 编写自定义插件以变更 mdast

<Callout type="info" title="Remark 与 Rehype 对比">
  Plate 组件（如 `TableElement`、`CodeBlockElement`）渲染 Plate JSON。
  `remarkPlugins` 作用于 Markdown AST。与部分渲染器不同，
  Plate 一般不需要 `rehypePlugins`（HTML AST 处理），除非需要更复杂的 HTML 处理（如 `rehype-raw`）。
</Callout>

## 架构概览

`@platejs/markdown` 基于 unified/remark，将 Markdown 字符串与 Plate 编辑器格式进行互转。

```
                                             @platejs/markdown
          +--------------------------------------------------------------------------------------------+
          |                                                                                            |
          |  +-----------+        +----------------+        +---------------+      +-----------+       |
          |  |           |        |                |        |               |      |           |       |
 markdown-+->+ remark    +-mdast->+ remark plugins +-mdast->+ mdast-to-plate+----->+   nodes   +-plate-+->react elements
          |  |           |        |                |        |               |      |           |       |
          |  +-----------+        +----------------+        +---------------+      +-----------+       |
          |       ^                                                                      |             |
          |       |                                                                      v             |
          |  +-----------+        +----------------+        +---------------+      +-----------+       |
          |  |           |        |                |        |               |      |           |       |
          |  | stringify |<-mdast-+ remark plugins |<-mdast-+ plate-to-mdast+<-----+ serialize |       |
          |  |           |        |                |        |               |      |           |       |
          |  +-----------+        +----------------+        +---------------+      +-----------+       |
          |                                                                                            |
          +--------------------------------------------------------------------------------------------+
```

**关键流程：**

1.  **解析（反序列化）：**
    - Markdown 字符串 → `remark-parse` → mdast
    - `remarkPlugins` 变换 mdast（如 `remark-gfm`）
    - Markdown 编译内在规则和已安装功能插件提供的 codec，再将 mdast 转为 Plate 节点
    - Plate 组件系统渲染节点
2.  **序列化：**
    - Plate 节点 → 已编译的功能 codec → mdast
    - `remarkPlugins` 变换 mdast
    - `remark-stringify` 输出为 Markdown 字符串

<Callout type="note" title="与 react-markdown 对比">
  - **节点直出渲染：** Plate 直接渲染自己的节点组件，而 `react-markdown` 往往转为 HTML AST 后再生成 React 元素
  - **双向处理：** Plate 的 Markdown 处理是完整双向的
  - **富文本集成：** 节点与 Plate 编辑功能紧密集成
  - **插件系统：** 节点组件受插件管理
</Callout>

## 从 `react-markdown` 迁移

迁移时需将 `react-markdown` 的概念映射到 Plate 体系。

**主要区别：**

1.  **渲染流程：** `react-markdown`（MD → mdast → hast → React） VS `@platejs/markdown`（MD ↔ mdast ↔ Plate JSON，Plate 组件直接渲染 Plate 节点）
2.  **组件定制方式：**
    - `react-markdown`：`components` 属性替换 HTML 节点渲染
    - Plate：
      - 功能插件 `codecs`：定义可复用的 mdast ↔ Plate JSON 转换
      - 操作 `rules`：只覆盖一次 API 调用的转换
      - `createPlateEditor` 的 `components` 配置 Plate 节点的渲染组件（详见[附录C](#appendix-c-components)）
3.  **插件生态系统：** `@platejs/markdown` 使用 `remarkPlugins`；`rehypePlugins` 不属于其转换管线

**对照表：**

Options 示例使用 `import { MarkdownPlugin } from '@platejs/markdown'`。

| `react-markdown` 属性           | `@platejs/markdown` 等价项/概念                                                                       | 备注                                                                |
| :------------------------------ | :---------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------- |
| `children` (字符串)             | 传递给 `editor.api.markdown.deserialize(string)`                                                      | 通常在 `createPlateEditor` 的 `initialValue` 配置                   |
| `remarkPlugins`                 | `MarkdownPlugin.configure({ initialState: { remarkPlugins: [...] } })`                                                | 在 mdast 层操作                                                      |
| `rehypePlugins`                 | 不属于 `MarkdownPlugin` 转换管线                                                                     | 将 Markdown 或 Plate 节点交给 Plate 前，单独运行 HTML 管线            |
| `components={{ h1: MyH1 }}`     | `createPlateEditor({ components: { h1: MyH1 } })`                                                    | 设置已安装 `H1Plugin` 键对应的渲染组件                               |
| `components={{ code: MyCode }}` | 功能插件的 `text/markdown` codec 加 `components: { ['codeBlock']: MyCode }` | codec 负责 mdast ↔ Plate；component 负责渲染 |
| `allowedElements`               | `MarkdownPlugin.configure({ initialState: { allowedNodes: [...] } })`                                                 | 转换时过滤 mdast/Plate 节点                                          |
| `disallowedElements`            | `MarkdownPlugin.configure({ initialState: { disallowedNodes: [...] } })`                                              | 转换时过滤不支持节点                                                 |
| `unwrapDisallowed`              | 无直接等价项，默认过滤节点                                      | 可通过单次 `rules` 覆盖实现展开逻辑                                 |
| `skipHtml`                      | 默认会移除大部分 HTML                                                                   | 调用 `editor.api.markdown.deserialize` 前清理或转换原始 HTML          |
| `urlTransform`                  | 配置链接功能 codec，或传入单次 `rules` 覆盖                     | 可复用策略属于链接功能                                               |
| `allowElement`                  | `MarkdownPlugin.configure({ initialState: { allowNode: { ... } } })`                                                  | 转换时用函数过滤节点                                                 |

## 附录A：Markdown中的HTML

默认情况下，`@platejs/markdown` **不会**处理原始 HTML 标签。标准 Markdown 语法仍会转换为 Plate 节点；字面量 HTML（如 `<div>`）需在 Plate 外部处理，或建模为 MDX / 自定义节点。

`MarkdownPlugin` 运行 `remark-parse`、已配置的 `remarkPlugins` 与 Plate 转换规则。它没有 rehype HTML 阶段，因此 `rehype-raw` 和 `rehype-sanitize` 都不是 `MarkdownPlugin` 配置项。

受信任来源的原始 HTML 应在调用 Plate 前由应用自己的内容管线转换。不受信任的输入必须先按严格的元素与属性白名单清理，再调用 `editor.api.markdown.deserialize`。

```tsx
const safeMarkdown = await sanitizeMarkdownBeforePlate(untrustedMarkdown);

const value = editor.api.markdown.deserialize(safeMarkdown);
```

对于应用控制的类 HTML 自定义节点，使用 `remarkMdx` 和持有该节点的功能插件
codec，让转换始终留在 Plate 支持的 Markdown 管线内。

<Callout type="destructive" title="安全警告">
  原始 HTML 可能携带 XSS payload。来源不受信任时，必须先按严格的元素与属性白名单清理，再交给 Plate。
</Callout>

## 附录B：转换所有权

可复用转换由持有该功能的插件通过 `codecs['text/markdown']` 提供。
`MarkdownPlugin` 编译已安装插件的 codec，因此删除功能也会删除其转换。只有
当一次 `deserialize` 或 `serialize` 操作需要不同结果时，才传入 `rules`。

- **插件 decode：** `from` 指定 mdast 节点类型或 MDX 标签。`decode` 接收类型化
  节点，以及 children、attributes、captions 和所属插件 name 的 helper。
- **插件 encode：** `encode` 接收由 schema 推断出的 Plate 节点，以及保证
  phrasing、block 或 flow 内容合法的 helper。
- **操作覆盖：** `rules` 在编码时使用 Plate 插件 name，在解码时使用已解析的
  转换 key。

**示例：覆盖一次链接反序列化**

```tsx title="lib/plate-editor.ts"
import { convertChildrenDeserialize } from '@platejs/markdown';

editor.api.markdown.deserialize(markdown, {
  rules: {
    link: {
      deserialize: (node, decoration, options) => ({
        children: convertChildrenDeserialize(
          node.children,
          decoration,
          options
        ),
        customProp: 'this import only',
        title: node.title,
        type: 'link',
        url: node.url,
      }),
    },
  },
});
```

**已安装的功能 codec：**

| 持有包 | Markdown 节点 |

| `@platejs/markdown` | 段落、文本、换行、原始 HTML |

| `@platejs/list`、`@platejs/list-classic` | 缩进列表和经典列表 |

## 附录D：`PlateMarkdown` 只读展示组件

如果需要类似 `react-markdown` 的只读渲染组件，可以参考下方示例：

```tsx title="components/plate-markdown.tsx"
import React, { useEffect } from 'react';
import { Plate, PlateContent, usePlateEditor } from 'platejs/react';
import { MarkdownPlugin } from '@platejs/markdown';
// 导入各类常用的 Plate 插件
import { BasicBlocksKit } from '@/components/editor/plugins/basic-blocks-kit';
// ... 还可以按需引入 BlockquotePlugin、CodeBlockPlugin、ListPlugin等
// ... 以及粗体、斜体等标记插件

export interface PlateMarkdownProps {
  children: string; // Markdown 内容
  components?: Record<string, React.ComponentType<any>>; // Plate 渲染组件（可选）
  className?: string;
}

export function PlateMarkdown({
  children,
  components = {},
  className,
}: PlateMarkdownProps) {
  const editor = usePlateEditor({
    plugins: [
      // 加入渲染 Markdown 所需的所有插件
      ...BasicBlocksKit,
      MarkdownPlugin,
    ],
    components, // 传递自定义渲染组件
  });

  useEffect(() => {
    editor.update((tx) => {
      tx.value.replace(editor.api.markdown.deserialize(children));
    });
  }, [children, editor]); // Markdown 内容变化时重新反序列化

  return (
    <Plate editor={editor}>
      <PlateContent readOnly className={className} />
    </Plate>
  );
}

// 使用示例：
// const markdownString = "# Hello\nThis is *Markdown*.";
// <PlateMarkdown className="prose dark:prose-invert">
//   {markdownString}
// </PlateMarkdown>
```

<Callout type="info" title="初始值">
  该 `PlateMarkdown` 组件用于**只读**展示。如果需要完整的编辑体验，请参阅[安装指南](/docs/installation)。
</Callout>

## 安全性注意事项

`@platejs/markdown` 优先保证渲染安全，会把 Markdown 转换成结构化的 Plate 格式，避免直接渲染 HTML。但安全性依赖于：

- **功能 codec 和操作覆盖：** 保证自定义 `decode` 或 `deserialize` 不会引入不安全数据。
- **`remarkPlugins`：** 谨慎甄别使用的第三方 remark 插件，注意其安全性隐患。
- **原始 HTML 处理：** 如使用 `rehype-raw`，必须在来源不可信时联合 [`rehype-sanitize`][github-rehype-sanitize] 进行清洗。
- **插件安全责任：** 如链接元素需进行有效性验证，可参见 LinkPlugin 的 [`isUrl`](/docs/plugins/link#linkplugin) 说明，或媒体插件的 [`parseMediaUrl`](/docs/plugins/media#parsemediaurl)。

**建议：** 对于不可信的 Markdown 输入务必格外谨慎。如果开放复杂扩展或原始 HTML 功能，请做好输入清洗。
