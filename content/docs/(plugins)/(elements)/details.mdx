Details adds semantic disclosure blocks with one editable Summary and any number of direct body blocks. Open state belongs to the editor session, so HTML, Markdown, saved values, collaboration, and undo keep only document content.

<PackageInfo>

## Features

- Native `details` and `summary` HTML serialization.
- Nested Details with direct block children.
- Transient open state keyed by node identity.
- Wrap, unwrap, and insert transforms.
- Keyboard behavior for entering, exiting, and unwrapping Details.

</PackageInfo>

## Document model

A Details node always starts with exactly one Summary. Every following child is a direct body block:

```tsx
const value = [
  {
    type: 'details',
    children: [
      { type: 'summary', children: [{ text: 'Shipping details' }] },
      { type: 'paragraph', children: [{ text: 'Ships in 2–3 days.' }] },
    ],
  },
];
```

The Details schema enforces this shape. Turning a title into Quote, Callout or Columns, or typing three dashes in it, changes nothing. Code and List still convert a title and remove its Details. When Enter, paste or Duplicate creates a block after the title, that block is a body paragraph. A value with a Summary out of place, or with two, fails to load.

`open` and `name` are not document properties. Use the plugin state when the application needs to expand or collapse a Details node.

## Heading titles

Set `level` from `1` to `6` on a Summary to render it as a heading. Omit `level` for a plain title. The Summary stays the first child; the heading commands below never move its text into the body.

With `HeadingPlugin` installed, choose a heading in the formatting or slash menu, use the heading keyboard shortcuts, or type a Markdown heading prefix in the title. Text in the same menus removes the level. The headless equivalent is:

```tsx
import { BaseHeadingPlugin } from 'platejs';

editor.plugin(BaseHeadingPlugin).update.setLevel(2);
editor.update.blocks.reset({ unset: ['level'] });
```

`setLevel` gives every selected block the level: a Summary keeps its type and other blocks become headings. It returns `false` and changes nothing when the schema refuses any of them. `reset` with `unset: ['level']` turns each selected block into its parent's default, so a title stays a title without its level. `toggle({ level })` removes the level when a selected block already has it and sets it otherwise. Use these operations instead of changing a Summary's `type` directly.

## Kit usage

### Convert a title to another block

Heading and Text choices keep the Details structure. List choices turn the selected title into a list item and put its body one level deeper under it. Tab, Shift+Tab, drag and Cut move that item together with its body. The Code Block command turns the title into a code block and leaves the body as the blocks after it. Both conversions remove only the selected Details layer and keep an enclosing Details.

With the Code Block kit installed, use `mod+alt+8` for the code conversion. Turn into disables Code when the selection holds the title and more blocks. Undo restores the Details and its disclosure state. A list conversion changes nothing when a body block cannot take an indent. Other selected blocks stay unchanged too. `IndentKit` lists the block types that can, so a custom setup adds its body block types to Indent's `targetPlugins`.

A block inserted from a closed Details title lands after the whole Details, whether it comes from the slash menu, an insert command, a pasted file or AI. From an open title it lands at the start of the body. Heading and Text slash choices format the existing title instead.

## Manual usage

<Steps>

### Installation

```bash
npm install platejs
```

### Add plugins

Configure both node components. `DetailsPlugin` owns the container behavior; `DetailsSummaryPlugin` owns the editable first child.

```tsx title="editor.tsx"
import {
  DetailsPlugin,
  DetailsSummaryPlugin,
} from 'platejs/details/react';
import { createEditor } from 'platejs/react';
import {
  DetailsElement,
  DetailsSummaryElement,
} from '@/components/editor/details';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    DetailsSummaryPlugin.configure({ component: DetailsSummaryElement }),
    DetailsPlugin.configure({ component: DetailsElement }),
  ],
});
```

### Add headless support

Server transforms and serialization only need `BaseDetailsPlugin`:

```ts
import { createEditor } from 'platejs';
import { BaseDetailsPlugin } from 'platejs/details';

const editor = createEditor({
  plugins: [BaseDetailsPlugin],
});
```

</Steps>

## Transforms

### `editor.plugin(BaseDetailsPlugin).update.insert`

Insert an open Details node with an empty Summary and body paragraph after the
current block. Pass `select: true` to place the selection in the Summary and
`replaceEmpty: true` to replace an empty source in the same history step.
An explicit `at` keeps node-insertion placement; `after` identifies the source block.

```tsx
editor.plugin(BaseDetailsPlugin).update.insert({}, { select: true });
```

### `editor.plugin(BaseDetailsPlugin).update.wrap`

Wrap selected sibling blocks. The first text block becomes the Summary; structural first blocks get an empty Summary before them.

```tsx
editor.plugin(BaseDetailsPlugin).update.wrap();
```

### `editor.plugin(BaseDetailsPlugin).update.unwrap`

Unwrap the selected Details nodes. A heading Summary becomes a Heading of the same level when the Heading plugin is installed. Other summaries become Paragraphs before the body blocks.

```tsx
editor.plugin(BaseDetailsPlugin).update.unwrap();
```

## Open state

Read and update disclosure state through `BaseDetailsPlugin`. The state uses `NodeKey`, not a serialized element property.

```tsx
const details = editor.plugin(BaseDetailsPlugin);
const key = editor.key(detailsElement);

if (key !== undefined) {
  details.api.setOpen(key, true);
  const open = details.store.get('isOpen', key);
}
```

Closing a Details node moves the closing editor's selection out of its body to the end of its Summary. A read-only view moves the owning editor's selection instead. Undo restores a removed Details node with its open state.

## Serialization

HTML uses fixed `<details>` and `<summary>` tags. Markdown uses the same registered tags, including for nested Details:

```md
<details>

<summary>Title</summary>

Body text.

</details>
```

Decoding ignores `open` and `name`, and encoding never writes them.

A heading title uses `<summary><h2>Title</h2></summary>` in HTML and `<summary level="2">Title</summary>` in Markdown. Both preserve inline formatting. HTML reads the level only when the heading is the summary's only child.

HTML follows the browser's rule for the title. The first `<summary>` child is the title wherever it sits, and each later `<summary>` becomes a body block that keeps its formatting: a paragraph, or the heading it holds. Markdown is stricter. A `<details>` whose `<summary>` is not first, or that holds two, fails to parse.

## Plugins

### `BaseDetailsPlugin`

Headless schema, format mappings, transient state, transforms, and Enter, Backspace, and Delete behavior for `details` nodes.

### `BaseDetailsSummaryPlugin`

Headless text-block schema and format mappings for the persisted `summary` node type.

### `DetailsPlugin`

React adapter for Details rendering.

### `DetailsSummaryPlugin`

React adapter for Summary rendering.
