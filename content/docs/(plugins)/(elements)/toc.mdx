## Features

- Automatically generates a table of contents from document headings
- Indents each entry by its heading level, 1 to 6
- Smooth scrolling to headings
- Keyboard-accessible heading navigation with `Enter` and `Space`

TOC tracks headings with editor-scoped `NodeKey` values. It does not require
persisted element IDs or install `ElementIdPlugin`.

</PackageInfo>

## Kit usage

<Steps>

### Installation

The fastest way to add table of contents functionality is with the `TocKit`, which includes pre-configured `TocPlugin` with the [Plate UI](/docs/installation/plate-ui) component.

<ComponentSource name="toc" />

- [`TocElement`](/docs/components/toc): Renders table of contents elements.

### Add kit

Add the kit to your plugins:

```tsx
import { createEditor } from 'platejs/react';
import { TocKit } from '@/components/editor/toc';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    ...TocKit,
  ],
});
```

</Steps>

## Manual usage

<Steps>

### Installation

```bash
npm install platejs
```

### Add plugins

Include `TocPlugin` and `HeadingPlugin` in your Plate plugins array when creating the editor.

```tsx
import { TocPlugin } from 'platejs/toc/react';
import { HeadingPlugin } from 'platejs/react';
import { createEditor } from 'platejs/react';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    HeadingPlugin,
    TocPlugin,
  ],
});
```

### Configure plugin

Configure the `TocPlugin` with custom component and scroll options.

```tsx
import { TocPlugin } from 'platejs/toc/react';
import { HeadingPlugin } from 'platejs/react';
import { createEditor } from 'platejs/react';
import { TocElement } from '@/components/editor/toc';
import { HeadingElement } from '@/components/editor/heading';

const editor = createEditor({
  plugins: [
    // ...otherPlugins,
    HeadingPlugin.configure({ component: HeadingElement }),
    TocPlugin.configure({
      component: (props) => <TocElement {...props} topOffset={80} isScroll />,
    }),
  ],
});
```

- `.configure({ component })`: Assigns [`TocElement`](/docs/components/toc) to render table of contents elements.
- `TocElement.topOffset`: Sets the top offset when scrolling to headings.
- `TocElement.isScroll`: Enables scrolling behavior to headings.

### Insert toolbar button

You can add this item to the [Insert Toolbar Button](/docs/toolbar#insert-toolbar-button) to insert table of contents elements:

```tsx
{
  icon: <TableOfContentsIcon />,
  label: 'Table of contents',
  value: PLUGINS.toc,
}
```

### Scroll container setup

Use [EditorContainer](/docs/components/editor) for the editor's scrolling region.
For a custom layout, render `EditorContainer` inside `<EditorRoot>` and apply your
scrolling styles to it. `EditorContainer` registers that region with the editor.

```tsx
import { EditorContainer, EditorContent } from 'platejs/react';

function Layout() {
  return (
    <EditorContainer className="h-[600px] overflow-y-auto">
      <EditorContent />
    </EditorContainer>
  );
}
```

</Steps>

## Custom heading list

The copied `TocElement`, the static `TocElementStatic` and Word export all
render the plugin's [`read.headings()`](#editorplugintocpluginreadheadings). To
change which headings they list, extend the plugin's read and filter
[`readTocHeadings`](#readtocheadings), the plugin's own heading finder. One app
plugin then serves the live kit, the static kit and Word export. Keep it in a
module that imports only `platejs/toc`, so the server-rendered static kit can
import it.

```ts title="components/editor/app-toc-plugin.ts"
import { BaseTocPlugin, readTocHeadings } from 'platejs/toc';

export const AppTocPlugin = BaseTocPlugin.extend({
  read: ({ editor, state }) => ({
    headings: () =>
      readTocHeadings({ editor, state }).filter((heading) => heading.level <= 3),
  }),
});
```

Install it in place of `TocPlugin` in the client `toc` file:

```tsx title="components/editor/toc.tsx"
import { toReactPlugin } from 'platejs/react';
import { AppTocPlugin } from '@/components/editor/app-toc-plugin';

export const TocKit = [
  toReactPlugin(AppTocPlugin).configure({ component: TocElement }),
];
```

Install it in place of `BaseTocPlugin` in `toc-static`:

```tsx title="components/editor/toc-static.tsx"
import { AppTocPlugin } from '@/components/editor/app-toc-plugin';

export const BaseTocKit = [
  AppTocPlugin.configure({ component: TocElementStatic }),
];
```

Pass the read's own `editor` and `state` to `readTocHeadings`, so a static
render or a document view lists its own headings. The finder walks `state` but
reads each level through `editor`'s heading plugin, so both must come from the
same read.

## Plugins

### `TocPlugin`

Plugin for the table of contents element. It has no options; its
[`read.headings()`](#editorplugintocpluginreadheadings) lists the headings, and
a [read override](#custom-heading-list) changes them.

### `TocElement`

Scroll options belong to the copied view. The heading list belongs to `TocPlugin`.

<API name="TocElement">
<APIOptions>
  <APIItem name="isScroll" type="boolean" optional>
    Enable scrolling behavior.
    - **Default:** `true`
  </APIItem>
  <APIItem name="topOffset" type="number" optional>
    Top offset when scrolling to heading.
    - **Default:** `80`
  </APIItem>
</APIOptions>
</API>

## API Reference

### `editor.plugin(TocPlugin).read.headings`

Lists the document's headings in document order. The copied TOC renders this
list, and the static TOC and Word export read it through `BaseTocPlugin`.

<API name="editor.plugin(TocPlugin).read.headings">
<APIReturns type="Heading[]">
  One entry per heading with text.
</APIReturns>
</API>

### `readTocHeadings`

The plugin's own heading finder, exported so a read override can filter it. It
returns `[]` when no heading plugin is installed and skips headings with no
text.

```ts
import { readTocHeadings } from 'platejs/toc';
```

<API name="readTocHeadings">
<APIParameters>
  <APIItem name="editor" type="Editor">
    The editor whose heading plugin reads each level, from the same read as
    `state`.
  </APIItem>
  <APIItem name="state" type="EditorStateView">
    The document to walk, which is the `state` a plugin read receives.
  </APIItem>
</APIParameters>
<APIReturns type="Heading[]">
  One entry per heading with text, in document order.
</APIReturns>
</API>

### `Heading`

One table of contents entry.

<API name="Heading">
<APIAttributes>
  <APIItem name="key" type="NodeKey">
    The heading's editor-scoped key. It is never saved with the document.
  </APIItem>
  <APIItem name="level" type="HeadingLevel">
    The heading level, `1` to `6`.
  </APIItem>
  <APIItem name="title" type="string">
    The heading's text.
  </APIItem>
</APIAttributes>
</API>

## Transforms

```ts
import { BaseTocPlugin } from 'platejs/toc';

editor.plugin(BaseTocPlugin).update.insert();
```

<API name="editor.plugin(BaseTocPlugin).update.insert">

  </APIItem>
</APIParameters>
</API>

## Registry UI

The copied [`toc`](/docs/components/toc) component owns scrolling and
navigation feedback. Keep those product-facing interaction choices beside the
renderer; the package plugin owns heading discovery through
`editor.plugin(TocPlugin).read.headings()`.
