This example runs two independent Plate editors through an app-owned local Yjs
room. Plate renders the editor surfaces. The app owns the provider, transport,
persistence, authentication, room name, and cursor data.

## Source

The demo creates two provider endpoints, two editor `Y.Doc` instances, and one
central room document. The room seeds its document before either endpoint
attaches, so both editor bindings omit `seed`. The provider is credential-free
and development-only.

## Runtime shape

| Piece                 | Owner                               | Notes                                                                                                       |
| --------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `CollaborationPlugin` | Copied `remote-cursor-overlay` file | Binds an explicit document and readiness source, then adds selection highlights, carets, and labels.        |
| Provider endpoints    | App infrastructure                  | Own connection state, transport, persistence, and cleanup outside the editor plugin.                        |
| Local room            | Registry example                    | Preseeds one central document, then exchanges document and awareness updates between two independent peers. |
| Production room state | App                                 | Keep room ids, auth tokens, persistence, and provider URLs outside Plate packages.                          |
| Provider controls     | App                                 | Clear selection, then disconnect the provider; reconnect it directly, then synchronize selection.           |
| Admission state       | `editor.api.yjs`                    | Gate editing on waiting, ready, or error independently from provider status.                                |
| Undo and redo         | `platejs/history`                   | Replay canonical editor changes through the same Yjs bridge.                                                |

Use the full [Yjs guide](/docs/yjs) when wiring a real provider.

## Remote cursors

Remote cursor UI belongs at the app edge. The reusable registry component is
`remote-cursor-overlay`.

<ComponentSource name="remote-cursor-overlay" />

Call `CollaborationPlugin.create()` from the copied file with `doc`,
`initialReady`, and awareness from your app-owned provider. It styles remote
selections and installs the caret overlay beside the Editable. Edit this file to
customize colors, opacity, and labels.

The overlay reads cursor state and DOM geometry from `platejs/yjs/react`,
excludes the local cursor, and ignores unresolved ranges.

## Try it

Type in either editor to see remote document and cursor updates. Disconnect one
peer to queue local work, reconnect it, then use the standard history controls
to undo or redo only that peer's local change. Each card reports provider and
admission status separately. The schema controls show a rejected incompatible
join and a compatible recovery without replacing either editor.
