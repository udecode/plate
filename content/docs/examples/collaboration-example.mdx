This example runs two independent Plate editors through an app-owned local Yjs
room. Plate renders the editor surfaces. The app owns the provider, transport,
persistence, authentication, room name, and cursor data.

## Runtime Shape

| Piece | Owner | Notes |
| --- | --- | --- |
| `YjsPlugin` | `@platejs/yjs/react` | Installs the Yjs adapter in a Plate editor and binds the configured document and providers. |
| Provider wrapper | App infrastructure | Wrap Hocuspocus, WebRTC, IndexedDB, or custom transport as `YjsProviderLike`. |
| Local room | Registry example | Exchanges document and awareness updates between two independent peers. |
| Production room state | App | Keep room ids, auth tokens, persistence, and provider URLs outside Plate packages. |
| Connection commands | `tx.yjs` | Connect, disconnect, reconnect, publish selection, and clear selection. |
| Connection reads | `state.yjs` | Read connected, synced, and provider status from `editor.read`. |
| Undo and redo | `@platejs/plite-history` | Replay canonical editor changes through the same Yjs bridge. |

Use the full [Yjs guide](/docs/yjs) when wiring a real provider.

## Remote Cursors

Remote cursor UI belongs at the app edge. The reusable registry component is
`remote-cursor-overlay`.

<ComponentSource name="remote-cursor-overlay" />

Render it inside a positioned editor container. It reads cursor state and DOM
geometry from `@platejs/yjs/react`, excludes the local cursor, and ignores
unresolved ranges.

## Try It

Type in either editor to see remote document and cursor updates. Disconnect one
peer to queue local work, reconnect it, then use the standard history controls
to undo or redo only that peer's local change. The schema controls show a
rejected incompatible join and a compatible recovery without replacing either
editor.
