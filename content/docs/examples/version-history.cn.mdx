## Runtime 结构

| 部分 | 所有者 | 用途 |
| --- | --- | --- |
| `authored({ retainHistory: true })` | `platejs/authored` | 用稳定的作者和 change identity 捕获已接受编辑，并保留其编辑内容。 |
| `authorId` callback | 应用 | 每个 transaction 解析一次当前选择的已认证作者。 |
| `read.authored.changes(...)` | 原生 authored read | 以分页 `AuthoredChange` record 返回已接受历史。 |
| `update.authored.revert(...)` | 原生 authored update | 为选中的 retained change 创建补偿贡献。 |
| `compare(...)` | `platejs/diff` | 比较两个不可变的已保存版本，不修改 editor。 |
| `Diff` | 复制的 Plate UI | 显示比较分组、效果、筛选和导航。 |
| `BasicMarksKit` | 复制的 Plate UI | 为可编辑文档提供普通富文本 mark。 |

## Retained history 流程

1. Editor 安装 `authored`，并启用 `retainHistory: true`。
2. 作者选择器修改后续 transaction 使用的身份。
3. 普通 accepted edit 创建带作者身份的 record。
4. 历史列表按稳定 ID 和 revision 读取 accepted change。
5. **Revert** 捕获绑定快照的 selection，并调用 `update.authored.revert(...)`。
6. 新的补偿 change 归属于当前作者；原 record 保持不变。

后续依赖工作可能让 revert 返回 `blocked`；所需保留内容过期时返回 `unavailable`。本地 undo 和 redo 仍属于独立的交互历史。接受或拒绝 pending review proposal 时使用原生 `decide(...)`。

## 比较保存的版本

演示会先捕获初始快照。编辑文档后点击 **Save revision**，即可比较最近两个快照。再次保存会开始新的比较，并取消过时的比较。比较结果只供读取。如需将通过校验的比较结果转成待审 proposal，使用 [`proposeAuthoredComparison(...)`](/docs/authored-changes)。

## 持久化历史

把 `editor.read.value()` 作为一个文档保存。Authored envelope 包含 accepted content、causal record、decision，以及 retention policy 选择保留的内容。

```tsx
const saved = editor.read.value();

const reloaded = createEditor({
  plugins: [
    authored({
      authorId: () => session.user.id,
      retainHistory: true,
    }),
  ],
  initialValue: saved,
});
```

新 editor 从空的本地 undo 和 redo stack 开始；保留的 authored contribution 仍在保存的文档中。如果文档包含评论，用 `comments.toJSON()` 将 `CommentsJSON` 与同一版本保存，通过 `initialComments` 加载；文档 undo 不会回退讨论。

Review view、decision result、协作和 format projection 请参阅 [Authored Changes](/docs/authored-changes)。
