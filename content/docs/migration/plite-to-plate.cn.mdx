---
title: 从 Plite 迁移到 Plate
description: 学习如何从 Plite 迁移到 Plate。
---

Plate 构建于 Plite 之上，因此从纯 Plite 实现迁移到 Plate 相对简单。本指南将帮助您将基于 Plite 的编辑器过渡到 Plate。

## 1. 安装 Plate

首先，安装必要的 Plate 包。如果您是 Plate 的新用户，可以先阅读[介绍](/docs/installation)了解库的概况。

```bash
npm install platejs
```

## 2. 替换 Plite 导入

将您的 Plite 导入替换为 Plate 导入。Plate 重新导出了大多数 Plite 类型和函数：

```ts
// 之前
import { EditorRoot, Editable, useCreateEditor } from 'plitejs/react';
```

```ts
// 之后
import { EditorRoot, EditorContent, useCreateEditor } from 'platejs/react';
```

Plate 以相同的绑定重新导出 Plite 的文档模型。除第 11 节列出的值之外，只需修改导入路径：`plitejs` 改为 `platejs`，`plitejs/<entrypoint>` 改为 `platejs/<entrypoint>`。`editor.read`、`editor.update`、`tx`、`NodeApi` 和其余文档 API 的用法不变。`platejs/diff`、`platejs/hyperscript`、`platejs/pagination`、`platejs/testing`、`platejs/yjs` 和 `platejs/yjs/react` 完整重新导出对应的 Plite 入口。

`useCreateEditor`、`useEditor()` 和 `useOptionalEditor()` 在 Plite 和 Plate 中使用相同的名称和语义；Plate 版本接受 Plate 插件与选项，并返回 Plate 的 React `Editor`。

## 3. 创建 Plate 编辑器

在 React 组件中，从 `platejs/react` 导入 `useCreateEditor` 并传入 Plate 插件：

```ts
// 之前
const editor = useCreateEditor({ initialValue: value });
```

```ts
// 之后
const editor = useCreateEditor({
  initialValue: value,
  plugins: [
    // 在此处添加其他插件
  ],
});
```

有关编辑器配置的更多详情，请查看[编辑器配置指南](/docs/editor)。

## 4. 替换 Plite 和 Editable 组件

将 `EditorRoot` 和 `Editable` 组件替换为 Plate 的 `EditorRoot` 组件：

```tsx
// 之前
<EditorRoot editor={editor}>
  <Editable className="p-4" />
</EditorRoot>

// 之后
<EditorRoot editor={editor}>
  <EditorContent className="p-4" />
</EditorRoot>
```

## 5. 转换自定义元素和叶子

对于自定义元素和叶子，创建 Plate 插件：

```tsx
// 之前
const renderElement = useCallback(({ attributes, children, element }) => {
  switch (element.type) {
    case 'paragraph':
      return <p {...attributes}>{children}</p>;
    // ... 其他情况
  }
}, []);

// 之后
import { schema } from 'platejs';
import { definePlugin, EditorElement, type EditorElementProps } from 'platejs/react';
import { cn } from '@/lib/utils';

export function ParagraphElement(
  props: EditorElementProps<typeof ParagraphPlugin>
) {
  return (
    <EditorElement {...props} className="m-0 px-0 py-1">
      {props.children}
    </EditorElement>
  );
}

const ParagraphPlugin = definePlugin('p', {
  type: 'paragraph',
  schema: {
    element: { content: schema.content.text({ default: 'text', min: 1 }) },
  },
}).configure({ component: ParagraphElement });
```

在[插件配置指南](/docs/plugin)和[插件组件指南](/docs/plugin-components)中了解更多关于创建插件的信息。

## 6. 将 Plite 插件转换为 Plate 插件

如果自定义行为需要可复用的文档命令，把它放在插件的 `update` 贡献中。命令会出现在
`editor.update(...)` 的事务对象上：

```ts
const SignaturePlugin = definePlugin('signature', {
  update: ({ tx }) => ({
    insert() {
      tx.text.insert(' - Signed');
    },
  }),
});

editor.update((tx) => {
  tx.signature.insert();
});
```

插件 portal 已经拥有插件名，因此方法应保持扁平并直接描述任务：

```ts
const CalloutPlugin = definePlugin('callout', {
  update: ({ tx }) => ({
    insertCallout() {
      tx.nodes.insert({
        children: [{ text: '' }],
        type: 'callout',
      });
    },
  }),
});

editor.update((tx) => {
  tx.callout.insertCallout();
});
```

插件专属的不可变服务放在 `api`，快照内查询放在 `read`，command、correction、
read middleware、lifecycle、activation、validation 等底层行为使用根级原生 Plite
字段。互相独立的字段放进 constructor。只有 import/prebuilt declaration、constructor 无法访问的
shared factory 或前一阶段类型需要 `.extend()`。Codec declaration 通过 constructor 的
`formats: ({ defineFormats }) => defineFormats(map)` 构建；foreign mapping 使用
`defineFormats(TargetPlugin, map)`。

有关插件上下文的更多信息，请参阅[插件上下文指南](/docs/plugin-context)。

## 7. 更新事件处理程序

更新您的事件处理程序以使用 Plate 的插件系统：

```ts
// 之前
const onKeyDown = (event) => {
  if (event.key === 'Tab') {
    // 处理 Tab 键
  }
};

// 之后
const TabPlugin = definePlugin('tab', {
  on: {
    keyDown: ({ editor, event }) => {
      if (event.key === 'Tab') {
        // 处理 Tab 键
      }
    },
  },
});
```

或者，您可以使用 Plate 强大的快捷键系统：

```ts
const TabPlugin = definePlugin('tab', {
  shortcuts: {
    indent: {
      handler: ({ editor }) => {
        // 处理 Tab 键
      },
      keys: ['Tab'],
    },
  },
});
```

有关使用快捷键的更多详情，请查看[插件快捷键指南](/docs/plugin-shortcuts)。

## 8. 适应 Plate 的 API

Plate 将读取和写入分开。用 `editor.read(...)` 读取编辑器状态，用
`editor.update(...)` 修改文档。`editor.api.*` 适合插件服务和宿主运行时
API，不适合作为文档修改命令。

```ts
const text = editor.read((state) => state.text.string([]));

editor.update((tx) => {
  tx.marks.toggle('bold');
  tx.text.insert('Hello');
});

editor.api.debug.log(text);
```

有关编辑器方法的完整列表，请参阅[编辑器方法指南](/docs/editor-methods)。

## 9. 利用 Plate 的内置插件

Plate 提供了许多内置插件，您可以在侧边栏中查看。使用它们快速添加功能：

```ts
import {
  BoldPlugin,
  ItalicPlugin,
  UnderlinePlugin,
  useCreateEditor,
} from 'platejs/react';

const plugins = [
  BoldPlugin,
  ItalicPlugin,
  UnderlinePlugin,
  // ... 其他插件
];

const editor = useCreateEditor({
  plugins,
});
```

## 10. 测试和优化

迁移完成后，彻底测试您的编辑器以确保所有功能按预期工作。使用 Plate 的功能和最佳实践进行优化。

有关调试技巧和策略，请查看我们的[调试指南](/docs/debugging)。

## 11. 重命名和移除的名称

下表列出 Plate 移除、重命名或以同名但不同约定导出的每个 Plite 值，以及应用随之导入的类型。其余值保持相同的绑定，只需修改导入路径。

### 编辑器和插件

| Plite | Plate | 说明 |
| --- | --- | --- |
| `useCreateEditor(options, deps)` | `useCreateEditor(options, deps)` | 接受 Plate 插件和选项，与 `platejs/react` 的 `createEditor` 一样支持 `clipboardFormatKey`。 |
| `useEditor()` | `useEditor()` | 返回当前编辑区域或光标所在根的 Plate React `Editor`，传入任何参数都会抛出错误。 |
| `useOptionalEditor()` | `useOptionalEditor()` | 在提供者之外返回 `null`，否则返回 Plate React `Editor`，传入任何参数都会抛出错误。 |
| `useEditorContext()` | `useEditor()` | Plate 移除了 `useEditorContext()`。 |
| `useOptionalEditorContext()` | `useOptionalEditor()` | Plate 移除了 `useOptionalEditorContext()`。 |
| `createEditor(options)` | 来自 `platejs` 的 `createEditor(options)`，React 中来自 `platejs/react` | 来自 `platejs/react` 的 `createEditor` 和 `useCreateEditor` 接受 `clipboardFormatKey`；根入口 `platejs` 的 `createEditor` 拒绝该选项，与 Plite 一致。 |
| `definePlugin(name, definition)` | 来自 `platejs` 的 `definePlugin(name, definition)`，React 中来自 `platejs/react` | 定义字段相同，且 `PluginDefinitionInput` 不含 `name`。结果是带 `.configure()` 和 `.extend()` 的 Plate 插件；定义中的 `name` 键会抛出错误。每个 Plate 插件声明单个节点，因此需把多元素的 `schema.elements` 拆分为每个节点一个插件并使用 `schema.element`；除 `contentRoots`、`element`、`mark` 和 `properties` 之外的 `schema` 键在编译期和运行期都会被拒绝。Plate 插件应传给 `createEditor({ plugins })`，运行时标志通过 `store.set({ readOnly: false })` 切换，不要把 Plate 插件传给 `editor.install`、`tx.plugins.reconfigure` 或 `definePluginSlot().of()`。Plate 在解析插件的 `.extend()` 阶段时运行 `api` 工厂，因此该工厂拿不到 `getContributions`。请在 `validate` 中读取 contributions。 |
| `useCommand(command, options)` | `editor.update.command(command, input)`，编辑器来自 `useEditor()` | Plate 的命令没有 `root` 或 `focus` 选项。 |

### 渲染

| Plite | Plate | 说明 |
| --- | --- | --- |
| `Editable` | `EditorContent` | 把 `renderElement`、`renderLeaf`、`renderText`、`renderPlaceholder` 和 `renderVoid` 移到插件组件中，其余属性不变。 |
| 来自 `plitejs/pagination/react` 的 `PagedEditable` | 来自 `platejs/pagination/react` 的 `PagedEditorContent` | 渲染属性移到插件组件中，与 `EditorContent` 相同。 |
| 来自 `plitejs/react/virtualized` 的 `VirtualizedEditable` | 来自 `platejs/react/virtualized` 的 `VirtualizedEditorContent` | 渲染属性移到插件组件中，与 `EditorContent` 相同。 |
| `EditorPlaceholder` | `EditorContent` 的 `placeholder`，空块使用 `BlockPlaceholderPlugin` | Plate 没有 `renderPlaceholder`。 |
| `EditorRoot` | `EditorRoot` | `onValueChange` 收到完整的文档值 `{ children, ... }`，而不是子节点数组。Plate 的 `EditorRoot` 没有 `authorId`、`decorations`、`document` 或 `root` 属性。把 `userId` 传给 `createEditor`，通过插件的 `decorate` 装饰，并在 `EditorContent` 上设置 `root`。要渲染另一份文档，用 `createEditor({ initialValue })` 为它创建一个编辑器。 |
| `EditorElement`、`EditorLeaf`、`EditorText` | `EditorElement`、`EditorLeaf`、`EditorText` | Plate 的版本接收插件组件得到的属性，需要展开传入：`<EditorElement {...props}>`。Plite 的版本从上下文读取节点。 |
| `EditorReadOnlyProvider` | `EditorRoot` 或 `EditorContent` 上的 `readOnly` | |
| `useClaimEditableDOMCommit`、`setDOMTextSyncRendererCapability`、`setRetainedTextFlowRendererCapability` | 无 | Plate 的渲染器会为每个插件组件调用它们。 |

### Hooks

| Plite | Plate | 说明 |
| --- | --- | --- |
| `useEditorSelector(selector, options)` | `useEditorSelector(selector, options)` | 选项只有 `dependsOn` 和 `equalityFn`。该 hook 跟随光标所在根的编辑器。 |
| `useEditorState(selector, options)` | `useEditorState(selector, options)` | 没有 `deferred` 选项。 |
| `useEditorSelection`、`useEditorFocused`、`useEditorComposing`、`useEditorReadOnly` | 同名 | 调用方式相同。Plate 读取当前选中的编辑区域。 |
| `useStateFieldValue(field, options)`、`useSetStateField(field)` | 同名 | 绑定到 Plate 的 `useEditor()`，支持被动 `EditorProvider` 目标。 |
| `useOptionalEditorReadOnly()` | `useEditorReadOnly()` | Plate 总是返回布尔值。 |
| `useEditorHistory(options)` | `useEditorHistory(options)` | 选项相同。 |
| `useElement<MyElement>()` | `useElement(MyPlugin)` | 不带参数的 `useElement()` 仍返回最近的元素，在元素组件之外会抛出错误。 |
| `useOptionalElement()` | 无 | 在元素插件的组件中调用 `useElement()`。 |
| `useNodeSelector(selector)` | 在元素组件中使用 `useElementSelector(selector)` | 选择器收到元素。Plate 没有按 key 选择节点的 hook。 |
| `useTextSelector(selector)` | 无 | 文本插件组件从属性中收到 `text`。 |
| `useEditorEditableElement()` | `useEditableRef()` | 挂载前 ref 为 `null`，元素挂载时不会重新渲染。`useEditorMounted()` 返回布尔值。 |
| `useRootEditor(options)` | `useRootEditor(options)` | 返回该根对应的 Plate React `Editor`。 |

### 类型

| Plite | Plate | 说明 |
| --- | --- | --- |
| `EditableProps` | `EditorContentProps` | Plate 不导出 `EditableProps`。 |
| `RenderElementProps`、`RenderLeafProps`、`RenderTextProps`、`RenderTextHostProps`、`RenderTextPieceProps` | 来自 `platejs/react` 的同名类型 | 根入口 `platejs` 不再导出渲染属性类型。`StaticRenderLeafProps` 和 `RenderStaticNodeWrapper*` 请从 `platejs/static` 导入。 |
| `EditableHandlerContext`、`EditableInputEventContext`、`EditableDOMBeforeInputContext`、`EditableDOMBeforeInputHandler`、`EditableKeyDownHandler`、`EditablePointerSelectionEndHandler` | 来自 `platejs/react` 的同名类型 | `context.editor` 为 Plate 的 React `Editor`。 |
| `PagedEditableProps`、`VirtualizedEditableProps` | `PagedEditorContentProps`、`VirtualizedEditorContentProps` | |
| `CreateEditorOptions` | 来自 `platejs` 或 `platejs/react` 的 `CreateEditorOptions` | 接受 Plate 插件与选项；`platejs/react` 的版本额外支持 `clipboardFormatKey`。 |
| `EditorSelectorOptions`、`EditorStateSelectorOptions`、`EditorRuntimeSelectorOptions` | `UseEditorSelectorOptions`、`UseEditorStateOptions` | |
| `UseStateFieldValueOptions` | 来自 `platejs/react` 的 `UseStateFieldValueOptions` | Plate 的 `UseStateFieldValueOptions` 省略了 Plite 的 `deferred` 选项。 |
| `EditorRootProps`、`CommitContext`、`SelectionChangeContext`、`ValueChangeContext` | 同名 | `CommitContext`、`SelectionChangeContext` 和 `ValueChangeContext` 中的 `editor` 为 Plate 的 `Editor`，`value` 是完整的文档值。 |

### DOM

`platejs/dom` 保留 `ariaKeyShortcuts`、`dataTransferFormats`、`domCommands`、`DOMResolutionError`、`isHotkey`、`usesAppleDOMHotkeys`、`writeDataTransferFragment`，以及 `DOMApi` 和 `useDropIndicator` 使用的拖拽与几何类型。其他 `plitejs/dom` 导出对应如下。

| Plite | Plate | 说明 |
| --- | --- | --- |
| `DOMEditor.focus(editor)` 和其他 `DOMEditor` 方法 | `editor.api.dom.focus()` 和其他 `editor.api.dom` 方法 | 去掉编辑器参数。 |
| `getEditorDOMRoot(editor)` | `editor.api.dom.root()` | |
| `dom`、`DOMEditorOptions`、`DOMPlugin`、`DOMPluginTypes` | 无 | Plate 会自动安装核心 DOM 插件；在来自 `platejs/react` 的 `createEditor` 或 `useCreateEditor` 中配置 `clipboardFormatKey`。 |
| `getDOMClipboardFormatKey`、`writeDOMFragmentData`、`writeDOMRangeData`、`cleanDOMClipboardContents`、`DOMClipboardInsertDataHandler`、`DOMEditorClipboardCapability`、`DOMFragmentDataHtml`、`DOMFragmentDataPayload` | `editor.api.dom.clipboard` 和插件的 `dataTransferFormats` | |
| `Hotkeys` | 来自 `platejs` 的 `Hotkeys` | Plate 的集合成员不同。 |
| `createCompiledHotkeyMatcher`、`Key` | `isHotkey`，或插件的 `shortcuts` | |
| `readDOMSelectionRange`、`writeDOMSelection`、`DOMSelectionPoints` | 无 | `EditorContent` 负责读写 DOM 选区。 |
| `isEditor`、`isElement`、`isLeaf`、`isNode`、`isString`、`isText`、`isVoid`、`getElements`、`getNodeDataAttributeKeys`、`keyToDataAttribute` | 无 | 它们读取 Plite 的 DOM 数据属性。来自 `platejs` 的 `isEditor` 是另一个函数，用于检查编辑器对象。 |
| `getSelection`、`getActiveElement`、`getDefaultView`、`isDOMNode`、`isDOMElement`、`isDOMText`、`isDOMSelection`、`hasShadowRoot`、`closestShadowAware`、`containsShadowAware`、`isAfter`、`isBefore`、`normalizeDOMPoint`、`isPlainTextOnlyPaste`、`CAN_USE_DOM`、`isGeckoDOMHost`、`TRIPLE_CLICK` | 无 | 使用 DOM API。 |
| `DOMCoverage`、`DOMCoverageBoundary`、`DOMCoverageBoundaryAnchor`、`DOMCoverageBoundaryEdge`、`DOMCoverageBoundaryState`、`DOMCoverageCopyPolicy`、`DOMCoverageMaterializeHandler`、`DOMCoverageMaterializeRangeRole`、`DOMCoverageMaterializeReason`、`DOMCoverageMaterializeResult`、`DOMCoveragePathRange`、`DOMCoveragePointResult`、`DOMCoverageReason`、`DOMCoverageRuntimeRange`、`DOMCoverageSelectionPolicy`、`DOMCoverageSession`、`isTrackedMutation`、`applyStringDiff`、`mergeStringDiffs`、`normalizeStringDiff`、`normalizePoint`、`normalizeRange`、`targetRange`、`verifyDiffState`、`StringDiff`、`TextDiff` | 无 | `EditorContent` 负责 DOM 覆盖、变更跟踪和 Android 输入差异。 |

### 历史记录

`platejs/history` 按原样重新导出 `History` 和历史记录数据类型。Plate 默认安装 `HistoryPlugin`，因此 `platejs/history` 移除了原生 Plite 插件工厂及其插件专用类型。

| Plite | Plate | 说明 |
| --- | --- | --- |
| 来自 `plitejs/history` 的 `history(options)` | 来自 `platejs` 的 `HistoryPlugin.configure({ initialState: { maxDepth, newBatchDelay } })` | 通过 `HistoryPlugin.configure({ enabled: false })` 关闭历史记录。关闭后运行时不再安装历史插件，但编辑器类型仍保留 `api.history`。 |
| `HistoryOptions` | 来自 `platejs` 的 `HistoryPluginState` | 通过 `HistoryPlugin.configure({ initialState })` 传入。 |
| 来自 `plitejs/history` 的 `HistoryPlugin`、`HistoryPluginTypes`、`HistoryPluginTypeProvider` | 来自 `platejs` 的 `typeof HistoryPlugin` | Plate 的 `HistoryPlugin` 是核心插件描述符。 |

### 审阅和批注

| Plite | Plate | 说明 |
| --- | --- | --- |
| 来自 `plitejs/authored` 的 `authored({ authorId })` | 把来自 `platejs/authored` 的 `AuthoredPlugin` 加入 `plugins` | 作者是编辑器的 `userId`，或 `createEditorView` 创建的视图的 `authorId`。 |
| `authoredRecords` | 无 | `AuthoredPlugin` 会安装它。 |
| `createAuthoredPlugin`、`AuthoredTestOptions` | 无 | 它是 Plite 的测试辅助函数（使用固定的 id 和时钟）及其选项类型。 |
| `AuthoredPlugin` 类型 | `typeof AuthoredPlugin` | Plate 的 `AuthoredPlugin` 是插件值。 |
| 来自 `plitejs/annotations` 的 `createAnnotationStore` | 来自 `platejs/react` 的 `useAnnotationStore(editor, annotations, options)` | Plate 没有无头批注存储。批注类型改从 `platejs/react` 导入。 |
