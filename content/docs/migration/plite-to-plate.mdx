---
title: From Plite to Plate
description: Move a Plite React editor to Plate's editor, plugin, and rendering model.
---

Plate keeps Plite's document model and moves editor setup, rendering, events,
and command wiring into plugins. Run the automated codemod first to rewrite
imports, shell components, and safe plugin options, then move custom rendering
and behavior into plugins.

## Automated Codemod

Preview changes across your source folder without writing files:

```bash
npx @platejs/cli@beta codemod plite-to-plate ./src --dry --print
```

Apply the migration in place:

```bash
npx @platejs/cli@beta codemod plite-to-plate ./src
```

Use `@platejs/cli@beta` while Plate v2 ships on the `beta` tag. The codemod:

- Rewrites `plitejs` and `plitejs/*` imports to `platejs` and `platejs/*`, merging into existing `platejs` imports and preserving type imports and aliases.
- Renames `useEditorContext`, `useOptionalEditorContext`, `ReactPlugin`, and older Plite beta names (`Editable`, `PagedEditable`, `VirtualizedEditable`, `EditorSelectorOptions`, and their companion props types).
- Rewrites safe older `DOMEditor.*` and `DOMEditor.clipboard.*` calls to `editor.api.dom.*` and `editor.api.dom.clipboard.*`.
- Converts bare `history()`, static `history({ enabled, maxDepth, newBatchDelay })`, React `dom({ clipboardFormatKey })`, static `authored({ authorId })`, and `authoredRecords` into Plate options and plugins.
- Moves `root` from `<EditorRoot>` onto a sole direct `<EditorContent>` when `<EditorRoot>` has no observers or spreads and `<EditorContent>` has no spreads.
- Adds `platejs` to `package.json`, and removes `plitejs` once no file in the package imports `plitejs`.
- Inserts `TODO(plate-codemod:...)` comments for manual steps such as `renderElement`, `renderLeaf`, `readOnly` overrides on `<EditorContent>`, `defineEditorSchema`, and `<EditorRoot decorations>`, and prints console diagnostics or warnings for Plite-only hooks, unlifted `root` props, spread props on `<EditorContent>`, and multi-root `useEditorContext`.

Useful flags: `--dry`, `--print`, `--force` (bypass the clean git working tree check), `--no-install`, and `--no-package-json`. After converting custom schemas into Plate plugins, run `npx @platejs/cli@beta generate` to generate exact editor types.

## Manual Install

If you migrate without the codemod, install `platejs` directly:

```bash
npm install platejs
```

Use feature packages only for the nodes, marks, or behavior you add to the
editor. Plate UI users should start with [Plate UI](/docs/installation/plate-ui)
instead of rebuilding every component by hand.

## Unchanged Imports

Plate re-exports Plite's document model with the same bindings. Unless
[Renamed And Dropped Names](#renamed-and-dropped-names) lists a value, change
only its import path: `plitejs` becomes `platejs`, and `plitejs/<entrypoint>`
becomes `platejs/<entrypoint>`. `editor.read`, `editor.update`, `tx`, `NodeApi`
and the rest of the document API work as before. `platejs/diff`,
`platejs/hyperscript`, `platejs/pagination`, `platejs/testing`, `platejs/yjs`
and `platejs/yjs/react` re-export their Plite entrypoint whole.

## Migration Map

| Plite surface | Plate surface |
| --- | --- |
| `useCreateEditor(options)` / `useEditor()` / `useOptionalEditor()` | The same hook names and jobs from `platejs/react`, with Plate plugins and options. |
| `<EditorRoot>` plus `<EditorContent>` | The same shell components from `platejs/react`, wired through plugins instead of render props. |
| `renderElement` / `renderLeaf` switch statements | Plugin components through `.configure({ component })`. |
| Plite plugins | Constructor `api`, `read`, `selectors`, `update`, native Plite fields, and format mappings built by `defineFormats`. |
| Top-level event handlers on `EditorContent` | Plugin `on` or `shortcuts`. |
| `editor.update(...)` | Keep the transaction boundary; add plugin-owned commands through `update`. |
| `editor.read(...)` | Keep the read boundary; add plugin-owned queries through `read`. |

## Editor Shell

Move the editor value into the editor creation call and render the editable with `EditorContent`.

```tsx title="components/editor.tsx" showLineNumbers
'use client';

import { EditorRoot, EditorContent, useCreateEditor } from 'platejs/react';

const initialValue = [
  {
    children: [{ text: 'Hello world.' }],
    type: 'paragraph',
  },
];

export function Editor() {
  const editor = useCreateEditor({
    initialValue,
  });

  return (
    <EditorRoot editor={editor}>
      <EditorContent className="p-4" />
    </EditorRoot>
  );
}
```

Use `createEditor({ ... })` when the editor is created outside React memoization.

```ts title="lib/create-editor.ts"
import { createEditor } from 'platejs/react';

export const editor = createEditor({
  initialValue: [
    {
      children: [{ text: 'Draft' }],
      type: 'paragraph',
    },
  ],
});
```

## Custom Elements

Replace `renderElement` branches with node plugins. Use `.configure({ component })` when the only change is the React component.

```tsx title="components/editor/paragraph-plugin.tsx" showLineNumbers
import {
  ParagraphPlugin,
  EditorElement,
  type EditorElementProps,
} from 'platejs/react';

export function ParagraphElement({
  children,
  ...props
}: EditorElementProps<typeof ParagraphPlugin>) {
  return (
    <EditorElement className="m-0 px-0 py-1" {...props}>
      {children}
    </EditorElement>
  );
}

export const AppParagraphPlugin = ParagraphPlugin.configure({ component: ParagraphElement });
```

If an existing document uses a different persisted type, remap that element in
the closed editor schema. Plugin configuration cannot rewrite schema identity.

```tsx title="components/editor/document-editor.tsx" showLineNumbers
import { schema } from 'platejs';
import { createEditor } from 'platejs/react';

const editor = createEditor({
  plugins: [AppParagraphPlugin],
  schema: {
    overrides: [
      schema.override(AppParagraphPlugin, {
        element: { type: 'p' },
      }),
    ],
  },
});
```

## Custom Behavior

Put a reusable document command under the plugin's `update` contribution. The
command is available inside `editor.update(...)` under the plugin name.

```tsx title="components/editor/signature-plugin.tsx" showLineNumbers
import { definePlugin } from 'platejs/react';

export const SignaturePlugin = definePlugin('signature', {
  update: ({ tx }) => ({
    insert() {
      tx.text.insert(' - Signed');
    },
  }),
});
```

Call it from a shortcut, toolbar, menu item, or test:

```ts title="commands.ts"
editor.update((tx) => {
  tx.signature.insert();
});
```

Element plugins already receive schema-inferred `insert`, `set`, and `remove`
updates. Do not wrap those generic operations in a feature method.

```tsx title="components/editor/callout-plugin.tsx" showLineNumbers
import { schema } from 'platejs';
import { definePlugin } from 'platejs/react';

export const CalloutPlugin = definePlugin('callout', {
  schema: {
    element: schema.element.textBlock(),
  },
});
```

```ts title="commands.ts"
editor.plugin(CalloutPlugin).update.insert();
```

Add a custom update only when it performs behavior beyond those generic node
operations. Keep that method flat and task-shaped; the portal already owns the
plugin noun.

Use `api` for plugin-scoped immutable services, `read` for snapshot-local
queries, and the root native Plite fields for commands, corrections, read
middleware, lifecycle, activation, validation, and other substrate behavior.
Combine independent fields in the constructor. Use `.extend()` only for an
imported/prebuilt declaration, a shared factory the constructor cannot access,
or an earlier-stage type dependency.

## Events And Shortcuts

Move editor events into the plugin that owns the behavior.

```tsx title="components/editor/tab-plugin.tsx" showLineNumbers
import { definePlugin } from 'platejs/react';

export const TabPlugin = definePlugin('tab', {
  on: {
    keyDown: ({ event }) => {
      if (event.key !== 'Tab') return false;

      event.preventDefault();

      return true;
    },
  },
});
```

Use `shortcuts` when the key combination should call a plugin API, transform, or explicit handler.

```tsx title="components/editor/save-plugin.tsx" showLineNumbers
import { definePlugin } from 'platejs/react';

export const SavePlugin = definePlugin('save', {
  shortcuts: {
    draft: {
      keys: 'mod+s',
      handler: ({ event }) => {
        event.preventDefault();

        return true;
      },
    },
  },
});
```

## API Calls

Plate keeps reads and writes separate. Read editor state with `editor.read(...)`.
Mutate the document with `editor.update(...)`. Use `editor.api.*` for plugin
services and host/runtime APIs, not document mutations.

```ts title="editor-commands.ts"
const text = editor.read((state) => state.text.string([]));

editor.update((tx) => {
  tx.marks.toggle('bold');
  tx.text.insert('Hello');
});

editor.api.debug.log(text);
```

## Headless Code

Use `createEditor` from `platejs` for non-React importers, serializers, transforms, and tests.

```ts title="lib/headless-editor.ts"
import { createEditor } from 'platejs';

export const editor = createEditor({
  initialValue: [
    {
      children: [{ text: 'Headless document.' }],
      type: 'paragraph',
    },
  ],
});
```

## Renamed And Dropped Names

These tables list each Plite value that Plate drops, renames, or exports under
the same name with a different contract, and the types an app imports with
them. Every other value keeps its binding, as
[Unchanged Imports](#unchanged-imports) says.

### Editor And Plugins

| Plite | Plate | Notes |
| --- | --- | --- |
| `useCreateEditor(options, deps)` | `useCreateEditor(options, deps)` | Takes Plate plugins and options, and accepts `clipboardFormatKey` like `platejs/react`'s `createEditor`. |
| `useEditor()` | `useEditor()` | Returns Plate's React `Editor` for the editing area or active caret root, and throws if passed an argument. |
| `useOptionalEditor()` | `useOptionalEditor()` | Returns Plate's React `Editor` or `null` outside a provider, and throws if passed an argument. |
| `useEditorContext()` | `useEditor()` or `useRootEditor(root)` | Plate drops `useEditorContext()`. Use `useEditor()` for the editing area or active caret root, or `useRootEditor(root)` to stay bound to one root in a multi-root tree. |
| `useOptionalEditorContext()` | `useOptionalEditor()` | Plate drops `useOptionalEditorContext()`. |
| `createEditor(options)` | `createEditor(options)` from `platejs`, or from `platejs/react` in React | `platejs/react`'s `createEditor` and `useCreateEditor` accept `clipboardFormatKey`; root `platejs`'s `createEditor` refuses it, matching Plite. |
| `definePlugin(name, definition)` | `definePlugin(name, definition)` from `platejs`, or from `platejs/react` in React | The definition fields are the same, and `PluginDefinitionInput` has no `name`. The result is a Plate plugin with `.configure()` and `.extend()`, and a `name` key inside the definition throws. A Plate plugin declares one node, so rewrite a multi-element `schema.elements` plugin into one plugin per node with `schema.element`; `schema` keys other than `contentRoots`, `element`, `mark`, and `properties` fail at compile time and throw at runtime. Pass Plate plugins to `createEditor({ plugins })` and toggle runtime flags with `store.set({ readOnly: false })` instead of passing Plate plugins to `editor.install`, `tx.plugins.reconfigure`, or `definePluginSlot().of()`. Plate runs the `api` factory while it resolves the plugin's `.extend()` stages, so the factory gets no `getContributions`. Read contributions in `validate`. |
| `useCommand(command, options)` | `editor.update.command(command, input)`, with the editor from `useEditor()` | Plate has no `root` or `focus` option for a command. |

### Rendering

| Plite | Plate | Notes |
| --- | --- | --- |
| `EditorContent` | `EditorContent` | Move `renderElement`, `renderLeaf`, `renderText`, `renderPlaceholder` and `renderVoid` into plugin components. Plate lets `<EditorContent readOnly={false}>` override `<EditorRoot readOnly>`, whereas Plite keeps root `readOnly` locked; Plate also returns `null` when `children.length === 0`. |
| `PagedEditorContent` from `plitejs/pagination/react` | `PagedEditorContent` from `platejs/pagination/react` | The render props move into plugin components, and the same `readOnly` and empty-document rules apply as on `EditorContent`. |
| `VirtualizedEditorContent` from `plitejs/react/virtualized` | `VirtualizedEditorContent` from `platejs/react/virtualized` | The render props move into plugin components, and the same `readOnly` and empty-document rules apply as on `EditorContent`. |
| `EditorPlaceholder` | `placeholder` on `EditorContent`, or `BlockPlaceholderPlugin` for empty blocks | Plate has no `renderPlaceholder`. |
| `EditorRoot` | `EditorRoot` | Plate's `EditorRoot` has no `decorations` or `root` prop. Decorate through a plugin's `decorate`, and set `root` on `EditorContent`. |
| `EditorReadOnlyProvider` | `readOnly` on `EditorRoot` or `EditorContent` | |
| `useClaimEditableDOMCommit`, `setDOMTextSyncRendererCapability`, `setRetainedTextFlowRendererCapability` | None | Plate's renderers call them for every plugin component. |

### Hooks

| Plite | Plate | Notes |
| --- | --- | --- |
| `useEditorSelector(selector, options)` / `useEditorSelector(editor, selector, options)` | The same overloads | Both packages take `dependsOn` and `equalityFn`. Context mode follows the editor of the root that holds the caret. |
| `useModelEditor()` | `useModelEditor()` | Returns Plate's React `Editor` for the complete document owned by the nearest `EditorRoot`. |
| `useEditorSelection`, `useEditorFocused`, `useEditorComposing`, `useEditorReadOnly` | The same names | The calls are the same. Plate reads the selected editing area. |
| `useStateFieldValue(field, options)`, `useSetStateField(field)` | The same names | Rebound to Plate's `useEditor()`, including passive `EditorProvider` targets. |
| `useEditorHistory(options)` | `useEditorHistory(options)` | The options are the same. |
| `useElement<MyElement>()` | `useElement(MyPlugin)` | `useElement()` without arguments still returns the nearest element, and throws outside an element component. |
| `useOptionalElement()` | None | Call `useElement()` inside an element plugin's component. |
| `useNodeSelector(selector)` | `useElementSelector(selector)` inside an element component | The selector receives the element. Plate has no hook that selects a node by key. |
| `useTextSelector(selector)` | None | A text plugin component receives its `text` in props. |
| `useEditorEditableElement(editor)` | `useEditorEditableElement(editor)` | Re-exported identically by `platejs/react`. Plate also offers `useEditableRef()` (returns a ref without rerendering on mount) and `useEditorMounted()`. |
| `useRootEditor(root, options)` | `useRootEditor(root, options)` | Returns Plate's React `Editor` for the root. |

| Plite | Plate | Notes |
| --- | --- | --- |
| `EditorContentProps`, `PagedEditorContentProps`, `VirtualizedEditorContentProps` | The same names | Plate's versions omit Plite's render props and type handler `context.editor` as Plate's React `Editor`. |
| `RenderElementProps`, `RenderLeafProps`, `RenderTextProps`, `RenderTextHostProps`, `RenderTextPieceProps` | The same names from `platejs/react` | Root `platejs` does not export render prop types. Import `StaticRenderLeafProps` and `RenderStaticNodeWrapper*` from `platejs/static`. |

| `CreateEditorOptions` | `CreateEditorOptions` from `platejs` or `platejs/react` | Takes Plate plugins and options; `platejs/react`'s adds `clipboardFormatKey`. |
| `EditorRootProps`, `CommitContext`, `SelectionChangeContext`, `ValueChangeContext` | The same names | `CommitContext`, `SelectionChangeContext`, and `ValueChangeContext` type `editor` as Plate's `Editor`. |
| `Editor`, `Plugin`, `DefinitionOf`, `PluginPortal`, `PluginReference`, `BlockInsertOptions` | The same names | Plate's take Plate's plugin and editor type parameters; a Plite state field or raw Plite plugin works in `createEditor({ plugins })` even though it does not satisfy Plate's own `PluginReference` or `PluginPortal`. |
| `TransferPlugin` type | `typeof TransferPlugin` | Plate's `TransferPlugin` is the core plugin value. |
| `ReactPlugin` | `RuntimeReactPlugin` | |
| `CommandDispatcher`, `CommandFocusPolicy`, `UseCommandOptions`, `EditorNodeSelectorContext`, `EditorTextSelectorContext`, `EditorRuntimeSelectorOptions`, `EditorReadOnlyProviderProps`, `DOMTextSyncRendererCapabilityContext` | None | Companion types of dropped `useCommand`, `useNodeSelector`, `useTextSelector`, `EditorReadOnlyProvider`, and `setDOMTextSyncRendererCapability`. |

### DOM

`platejs/dom` keeps `ariaKeyShortcuts`, `dataTransferFormats`, `domCommands`,
`DOMResolutionError`, `isHotkey`, `usesAppleDOMHotkeys`,
`writeDataTransferFragment`, and the drag and geometry types used by `DOMApi`
and `useDropIndicator`. Both packages use `editor.api.dom.*` for DOM queries,
focus, and clipboard calls. The other `plitejs/dom` exports map as follows.

| Plite | Plate | Notes |
| --- | --- | --- |
| `getEditorDOMRoot(editor)` | `editor.api.dom.root()` | |
| `dom`, `DOMEditorOptions`, `DOMPlugin`, `DOMPluginTypes` | None | Plate installs its core DOM plugin automatically; configure `clipboardFormatKey` on `platejs/react`'s `createEditor` or `useCreateEditor`. |
| `getDOMClipboardFormatKey`, `writeDOMFragmentData`, `writeDOMRangeData`, `cleanDOMClipboardContents`, `DOMClipboardInsertDataHandler`, `DOMEditorClipboardCapability`, `DOMFragmentDataHtml`, `DOMFragmentDataPayload` | `editor.api.dom.clipboard` and a plugin's `dataTransferFormats` | |
| `Hotkeys` | `Hotkeys` from `platejs` | Plate's set has other members. |
| `createCompiledHotkeyMatcher`, `Key` | `isHotkey`, or a plugin's `shortcuts` | |
| `readDOMSelectionRange`, `writeDOMSelection`, `DOMSelectionPoints` | None | `EditorContent` reads and writes the DOM selection. |
| `isEditor`, `isElement`, `isLeaf`, `isNode`, `isString`, `isText`, `isVoid`, `getElements`, `getNodeDataAttributeKeys`, `keyToDataAttribute` | None | They read Plite's DOM data attributes. `isEditor` from `platejs` is a different function that checks an editor object. |
| `getSelection`, `getActiveElement`, `getDefaultView`, `isDOMNode`, `isDOMElement`, `isDOMText`, `isDOMSelection`, `hasShadowRoot`, `closestShadowAware`, `containsShadowAware`, `isAfter`, `isBefore`, `normalizeDOMPoint`, `isPlainTextOnlyPaste`, `CAN_USE_DOM`, `isGeckoDOMHost`, `TRIPLE_CLICK` | None | Use the DOM API. |
| `DOMCoverage`, `DOMCoverageBoundary`, `DOMCoverageBoundaryAnchor`, `DOMCoverageBoundaryEdge`, `DOMCoverageBoundaryState`, `DOMCoverageCopyPolicy`, `DOMCoverageMaterializeHandler`, `DOMCoverageMaterializeRangeRole`, `DOMCoverageMaterializeReason`, `DOMCoverageMaterializeResult`, `DOMCoveragePathRange`, `DOMCoveragePointResult`, `DOMCoverageReason`, `DOMCoverageRuntimeRange`, `DOMCoverageSelectionPolicy`, `DOMCoverageSession`, `isTrackedMutation`, `applyStringDiff`, `mergeStringDiffs`, `normalizeStringDiff`, `normalizePoint`, `normalizeRange`, `targetRange`, `verifyDiffState`, `StringDiff`, `TextDiff` | None | `EditorContent` owns DOM coverage, mutation tracking and Android input diffs. |

### History

`platejs/history` re-exports `History` and the history data types by identity.
Plate installs `HistoryPlugin` by default, so `platejs/history` drops the raw
Plite plugin factory and its plugin-only types.

| Plite | Plate | Notes |
| --- | --- | --- |
| `history(options)` from `plitejs/history` | `HistoryPlugin.configure({ initialState: { maxDepth, newBatchDelay } })` from `platejs` | Disable history with `HistoryPlugin.configure({ enabled: false })`. Turning history off uninstalls it at runtime while keeping `api.history` in the editor types. |
| `HistoryOptions` | `HistoryPluginState` from `platejs` | Passed through `HistoryPlugin.configure({ initialState })`. |
| `HistoryPlugin`, `HistoryPluginTypes`, `HistoryPluginTypeProvider` from `plitejs/history` | `typeof HistoryPlugin` from `platejs` | Plate's `HistoryPlugin` is a core plugin descriptor. |

### Review And Annotations

| Plite | Plate | Notes |
| --- | --- | --- |
| `authored({ authorId })` from `plitejs/authored` | `AuthoredPlugin` from `platejs/authored` in `plugins` | The author is the editor's `userId`, or the `authorId` of a view from `createEditorView`. |
| `authoredRecords` | None | `AuthoredPlugin` installs it. |
| `createAuthoredPlugin`, `AuthoredTestOptions` | None | Plite's test helper with fixed ids and clock, plus its options type. |
| `AuthoredPlugin` type | `typeof AuthoredPlugin` | Plate's `AuthoredPlugin` is the plugin value. |
