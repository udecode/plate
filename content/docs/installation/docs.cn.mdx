---
title: 本地文档
description: 让编码 agent 读取随已安装版本发布的 Plate 文档，或把文档复制到项目中。
---

每个 `platejs` 版本都在 `node_modules/platejs/dist/docs/` 中附带 Markdown
格式的文档。这些文件与已安装的版本一致，编码 agent 读到的是应用实际使用的
API，而不是它记忆中的 API。

## 让 agent 读取文档

把下面这段内容加入应用的 `AGENTS.md`，或你的编码工具读取的规则文件：

```md
This app uses Plate (`platejs`), whose API differs from older versions you
may remember. Before you write editor code, read
`node_modules/platejs/dist/docs/llms.txt` and the pages it lists. They match
the installed version.
```

`llms.txt` 写明已安装的版本，并列出每个页面及其描述。页面中的
`/docs/<path>` 链接在 `llms.txt` 列出该页面时，对应
`node_modules/platejs/dist/docs/` 中的 `<path>.md` 文件。在 monorepo 中，
请让这段内容指向应用解析 `platejs` 时使用的 `node_modules` 文件夹。

## 把文档复制到项目中

从 `@plate` 注册表复制文档 MDX，用于审阅、定制，或与其他库的文档放在同一个
站点中。注册表提供最新的文档，可能与已安装的版本不同。

### 方式一：文档应用

此方式使用 Fumadocs 设置完整的文档站点，提供可搜索、可导航的界面。

<Steps>

#### 创建 Fumadocs 应用

设置 Fumadocs 应用，它为您的文档站点提供基于 Next.js 的框架：

```bash
pnpm create fumadocs-app
```

设置过程中：

- **名称：** 提示时输入 `docs`
- **选择您偏好的选项**（默认选项即可）
- 向导将创建包含所有必要文件的 `docs` 目录

进入新创建的 `docs` 目录：

```bash
cd docs
```

详细的 Fumadocs 设置，请参阅 [Fumadocs UI 文档](https://fumadocs.dev/docs/ui)。

#### 创建 `components.json`

在 docs 目录中创建 `components.json`：

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "base-nova",
  "rsc": true,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "app/global.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  },
  "iconLibrary": "lucide",
  "registries": {
    "@plate": "https://platejs.org/r/{style}/{name}.json"
  }
}
```

#### 添加 Plate 文档

现在，从 `@plate` 注册表获取 Plate 文档文件和必要的 MDX 组件。

```bash
npx shadcn@latest add @plate/fumadocs
```

<Callout type="warning" title="特定版本文档">
  上述命令会从实时注册表安装当前 Plate 文档。对于旧版 Plate，只有不声明
  `registryDependencies` 的叶子注册表项目才适合使用 GitHub 原始 URL。

不要从 GitHub 原始 tag 安装 `fumadocs.json` 或 `docs.json` 这类聚合项目：
它们的传递注册表依赖可能会解析到实时注册表。要获取完整的特定版本文档，
请阅读上文的包内文档，或从匹配的 Plate checkout 生成或提供注册表，确保每个
传递项目都来自同一版本。

</Callout>

#### 运行 Fumadocs 应用

启动开发服务器：

```bash
pnpm run dev
```

您的文档站点将在以下地址可用：

- Plate 文档：`http://localhost:3000/docs/plate`

#### 自定义

使用 [Fumadocs 功能](https://fumadocs.dev/docs/ui#writing-content)增强您的文档。

</Steps>

### 方式二：仅 MDX 文件

如果您只想要文档文件而不设置完整站点，可以直接将它们添加到现有项目中：

```bash
# 从项目根目录运行（您想要放置文档的位置）
npx shadcn@latest add @plate/docs
```

这将：

- 在您的项目中安装 MDX 文档文件（通常在 `docs/` 或类似目录中）
- 完全跳过 Fumadocs 设置
- 为您提供原始 MDX 文件，您可以按需使用

使用场景：

- 直接在代码库中引用文档
- 与现有文档设置集成
- 使文档对 AI 工具可用以获得更好的上下文

## 高级集成

### MCP 集成

通过 `.cursor/mcp.json` 或编码工具对应的配置文件连接 shadcn MCP 服务器。

```json
{
  "mcpServers": {
    "shadcn": {
      "description": "Shadcn and EditorRoot MCP",
      "command": "npx",
      "args": ["shadcn@latest", "mcp"]
    }
  }
}
```

您的 AI 工具随后可以：

- 访问文档上下文以获得更好的代码辅助
- 帮助管理和更新文档
- 使用正确的导入和配置生成代码
- 协助编辑器设置和功能集成

更多详情请参阅 [MCP 指南](/docs/installation/mcp)。

<Callout>
配置完成后，尝试询问您的 AI：

- "帮我理解 Plate AI 插件是如何工作的"
- "如何创建自定义插件？"
- "最新版本的 Plate 有什么新功能？"
</Callout>

### 集中管理多个文档

您的 `content/docs/` 目录可以托管多个库的文档。复制 Plate 的流程来添加其他内部或外部工具的文档：

```plaintext
content/
└── docs/
    ├── plate/         # EditorRoot 文档
    │   └── ...
    ├── other-library/ # 其他库的文档
    │   └── ...
    └── index.mdx      # 所有文档的主页
```

这为您的项目技术栈创建了一个统一的、版本控制的知识库。
