Use direct, diagnosed HTML, Markdown, and DOCX conversion contracts.

Feature plugins declare schema-bound node mappings with `formats` and `defineFormats`. HTML uses one parse5-owned safety and admission path for direct parsing and paste. HTML and Markdown expose detached `parse*` and `serialize*` functions plus installed editor methods, with explicit document, slice, diagnostics, projection, and loss-policy results. Editor methods type documents with the editor's value; standalone functions accept any plugin list and type documents as `Value`, like `createEditor({ plugins })`. Fragment parsing preserves slice boundaries and refuses silent inline truncation. Markdown serialization drops and reports a node that no configured remark plugin writes, such as a table without `remark-gfm`. A Markdown copy writes any slice its mappings can write, such as a dragged column. DOCX import captures a detached target before asynchronous work and reports schema repairs and mapping loss under its `lossPolicy`. Markup the HTML sanitizer removes takes the sanitizer's impact, and any other element a mapping loses follows the policy. A lost attribute or style, or a refused link destination that could not run script, is a `property-dropped` warning under every policy. Every `unsupported-content` diagnostic declares `impact`. Import finds header, footer and notes parts by Word's default names and reports such a part when it holds content. A header or footer part that is not XML counts as content. It leaves note markers and note text out of the body and comment bodies only for the notes it reports. It keeps the text of a text box the converter reads, and reports the box of a checkbox that no installed mapping decodes as lost. Import keeps a run's direct underline, yellow highlight, text color and background color, and a paragraph's direct center, right, end or justified alignment. It reports each other direct format it drops, such as a font size, line spacing, a background that is not the run's own, or a mark no installed plugin reads, as a `property-dropped` warning with its count. A light text color imports only on the run's own background or highlight, and otherwise counts as dropped. When any part of the file holds a character reference longer than four characters that is not a decimal or hex number, such as `&#example;`, import keeps no text or background color and reports each color it drops. Import ignores a style map stored in the file and returns a `style-map` warning when the map holds a rule. A `Quote` paragraph that no installed plugin reads returns a lossy `unsupported-content` diagnostic. DOCX export uses `exportDocx` with explicit native-state attachment. Export writes what a `stylesheet` adds to a run as a Word character style. Direct run formatting then holds only the run's own marks and style, and import does not turn the stylesheet's look, such as a heading's bold, into marks. Each paragraph in a quote exports as a Word `Quote` paragraph, and inline code and keyboard text export as the `HTML Code` and `HTML Keyboard` character styles. Import reads all three back. Any other block in a quote exports outside it, and a quote inside a quote merges into the outer one. Two quotes in a row come back as one when the first ends and the second starts with a paragraph that is not a list item. Each case reports a `quote-structure` warning under both policies.

**Migration:** Replace `codecs` and `defineCodecs` with `formats` and `defineFormats`. Replace legacy HTML and Markdown deserializers with the direct format entrypoints. Call `importDocx(source, { plugins, ...options })` without an editor instance, and replace `exportToDocx` with `exportDocx`.
