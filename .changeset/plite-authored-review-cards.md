- Read review cards with `read.authored.groups({ at })`. A card groups one author's adjacent pending changes, such as changes on either side of a pending line break or neighboring lines added or struck as separate changes, and its summary holds `id`, `authorId`, `createdAt`, `changeCount` and `revision`. A card's id is its oldest change, so every peer and every reload gives it the same id. `read.authored.groupOf(changeId)` returns the card that holds a change
- Page pending changes in document order with `read.authored.changes({ at, authorId, group, cursor, limit })`, 50 at a time by default and at most 200
- `at` names a place of the document the view shows. On a preview, `at` takes the key or path of a node the preview shows, and the read returns the cards and changes of the stored content that node shows. A point or a range throws `AuthoredPlaceError` from `plitejs/authored`. A block never reads the change of an element around it that the view still shows. A change's `ranges` and its details stay places of the stored document
- Decide changes or cards as they were read with `update.authored.decide({ action, changes })` or `{ action, groups }`, and pass several decisions to decide them together. A decision returns `applied`, `unchanged`, `stale`, `invalid`, or `blocked` with the changes it needs in `with`
- A change's `revision` ignores where it sits, except a split or join inside a top-level block, so an edit before it keeps it. A join, split, wrap or unwrap's revision ignores the text and leaves inside it
- `api.authored.subscribeChanges` passes one frozen `{ blocks, changed, groups, removed }` delta for each commit that changes the review, and `api.authored.subscribeRefusals` reports each proposal write or view switch the editor refused. `blocks` names the view's top-level blocks whose reads may differ, including a block a change left; a change to a card's summary alone names no block
- Refuse a `propose` write that review marks cannot show yet with an `authoredVeto` contribution. A veto gets the element's properties and how the write touches it: `'content'` when it changes only what the element holds, and `'element'` when it inserts, removes, splits, joins or changes the properties of the element. A refused write applies nothing and reaches `subscribeRefusals` with the veto's reason
- A view is `{ intent: 'edit' | 'propose' }`, or a `{ preview: 'accepted' | 'proposed' }`
- Typing or pasting inside struck text lands after it, as in a plain editor. An IME composition inside struck text splits the pending deletion around the composed text. A `propose` view records the new text as an insertion, and Enter or a pasted line break inside or right beside your own pending insertion becomes part of it, as does a second Enter on the empty line the first one made
- Pending review marks live in each node's `authored` property and review records in the document's `records`. Every loaded value and commit passes admission, which compacts and checks them, so saving `read.value()` keeps the review
