- Keep each block of a pasted or parsed HTML list item, such as a second paragraph, a code block or an image, as its own block one indent level under the item, as Plate's own HTML and Markdown write it, instead of joining the item's blocks into one line of text. A style that the `<li>` or a wrapper sets, such as bold, does not reach the content that moves out of that element, and the parse warns once with an `html-unsupported-content` diagnostic that names the first such style. That includes `white-space`, so a line break that `pre-wrap` kept becomes a space. A `<div>`, `<section>` or custom element without `data-` attributes around an item's blocks no longer drops the item's list properties, an item's `margin-left` sets the level of its blocks too, and line breaks between an item's blocks add no space to its text
- Read custom and namespaced HTML elements, such as GitHub's `<g-emoji>` and `<relative-time>`, and `<ruby>`, `<noscript>`, `<slot>` and `<datalist>` as inline, as browsers lay them out, and keep the spaces around them
- Parse a Markdown list item whose block cannot hold a list property, such as `indent` on a code block when `IndentPlugin` does not target code blocks: the block keeps its type, drops that property and reports a `markdown-unsupported-node` warning under every `lossPolicy`. These lists used to fail the whole parse with `markdown-schema-invalid`
- Keep the type of a Markdown list item's first block, such as a heading, when `ListPlugin` targets it. When it does not, a heading or code block that opens the item becomes the item's paragraph, and a first block that is not a line of text, such as a rule or a quote, keeps its type and leaves the list. Either change reports a `markdown-unsupported-node` diagnostic, so `lossPolicy: 'reject'` refuses the parse
- Keep an image inside a Markdown list item's text, and the text after it, under that item instead of making them list items of their own, and give a Markdown item that opens with a nested list an empty first block, as HTML does
- Add `property` to `PluginFormatSchemaView`, the `schema` a format mapping reads, which is the editor schema's `property({ key, placement, type })` read
